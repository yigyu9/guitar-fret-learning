# 1. 운지 결정 — 탭을 왼손 동작으로 바꾸기

> **현재 범위 — 2026-09-07:** 구현된 v0 finger mapping의 역할 설명이다. 현재 Full event의
> sounding target은 `mapping/fingering.json`의 note를 정본으로 사용한다. 바레·특수 주법과
> finger가 없는 fretted note는 지원되는 것으로 추정하지 않고 compiler에서 fail-closed 한다.

## 이 단계가 하는 일

탭은 어느 줄의 몇 프렛을 연주할지는 알려주지만, **어느 손가락으로 누를지**는 알려주지 않는다. 이 단계는 각 음에 손가락을 배정하고 손의 포지션, 바레, 누름·해제 시각을 결정한다.

```text
입력: 음표의 줄·프렛·시작·끝 + 코드 구간
출력: finger, position, barre, t_press, t_release
```

최종 `presses` 배열이 물리 제어 단계에 전달되는 왼손 목표다.

## 사람이 운지를 정하는 방식을 어떻게 옮겼나

1. 코드라면 먼저 익숙한 코드 폼을 찾는다.
2. 멜로디라면 현재 포지션 안에서 해결한다.
3. 다음 음과 코드를 미리 보고 손가락 이동을 줄인다.
4. 교차, 과도한 벌림, 한 손가락의 두 프렛 동시 압현처럼 불가능한 후보를 제거한다.
5. 아직 울려야 하는 음의 손가락은 유지한다.

후보가 여러 개면 빔 서치가 전체 구간의 이동 비용을 비교한다. 이 때문에 현재 음만 보고 검지를 쓰는 대신, 뒤의 음까지 고려해 소지→중지→검지처럼 선행 준비하는 운지가 나올 수 있다.

## 핵심 개념

| 개념 | 뜻 |
|---|---|
| 포지션 `P` | 검지가 담당하는 기준 프렛 |
| 앵커 핑거 | 코드가 바뀌어도 같은 줄·프렛에 유지하는 손가락 |
| 바레 | 검지 하나로 같은 프렛의 여러 줄을 누르는 동작 |
| planted | 음이 울리는 동안 떼면 안 되는 손가락 상태 |
| `t_cut` | 충돌을 피하려고 앞 음을 조금 일찍 끊은 시각 |
| `presses` | 실제 왼손 모터용 누름 타임라인 |

## 누름 시각은 음 시작보다 빠르다

- 기본 선행 누름: 타현 0.12초 전
- 앞 음이 이동을 막으면 최대 80ms 일찍 릴리즈
- 같은 손가락·줄·프렛의 재타현은 조건이 맞으면 1.5초 간격까지 하나의 누름으로 병합
- 최소 울림 50ms는 보존

## 현재 확인된 결과

- 교본 오픈 C와 F 바레 운지 재현
- Am→C에서 검지·중지 앵커 유지
- rock3 218개 음 전부 배정, 생체역학 위반 0
- rock3 타현 218회를 실제 누름 이벤트 103개로 축소

## 아직 부족한 부분

- 반복 프레이즈의 운지를 강제로 통일하는 모티프 일관성
- 손가락을 완전히 들지 않고 줄 가까이에 두는 lazy lift 후처리
- 손가락 쌍별 실제 벌림 한계
- 20곡 통계에 기반한 비용 가중치 튜닝
- `t_cut`과 배정 실패를 탭 전사 교정에 되돌리는 피드백
