# 논문 작성 원칙

이 디렉토리의 논문을 작성·수정할 때 아래 기준을 적용한다.

작성 원칙 갱신일: **2026-10-27**. 이 날짜는 원고나 실험 자료의 기준일을 변경하지 않는다.

## 작업 범위와 문서 역할

- 수정할 절과 확인할 근거를 먼저 정하고, 요청한 범위에 필요한 부분만 바꾼다. 제목·구성·핵심 주장에 영향을 주는 변경은 그 이유와 영향을 먼저 설명한다.
- 지속적으로 적용할 작성 규칙은 이 파일에, 원고 구성과 자료 기준일은 [README](README.md)에, 남은 작성·검증 과제는 [작성 메모](writing_notes.md)에 기록한다. 주장별 직접 근거와 해석 범위는 [근거 색인](evidence_index.md)에서 관리한다.

## 독자와 설명 수준

- 기타 연주, 물리 시뮬레이션, 강화학습의 세부 분야를 모르는 독자도 연구 문제와 방법의 필요성, 결과의 의미를 따라갈 수 있게 쓴다.
- 각 방법은 해결할 문제 → 필요한 이유 → 작동 원리 → 수식·구현 세부 순서로 설명한다. 문단만 읽어도 논리의 흐름이 이어져야 한다.
- 전문 용어와 약어는 처음 사용할 때 쉬운 설명과 함께 정의한다. 부록의 용어표는 본문의 첫 설명을 대신하지 않는다.
- 같은 대상의 용어와 기호를 일관되게 사용한다. 한국어·영어 명칭의 대응을 처음에 정하고, 예를 들어 자유 기타·비고정 기타 또는 기준 목표·nominal을 사용할 때 같은 개념인지 분명히 한다.
- 수식의 기호와 연산의 물리적 의미를 설명하고, 필요하면 짧은 예시를 사용한다. 가상 예시는 실제 실험 결과와 명확히 구분한다.
- 실험은 무엇을 확인하려는지, 지표는 무엇을 재는지, 결과는 어떤 결론을 뒷받침하는지 연결한다. 낮거나 높은 수치의 의미를 독자가 추측하게 하지 않는다.
- 쉬운 표현을 위해 제약·판정 조건·불확실성을 생략하지 않는다. 교과서식 배경 나열과 같은 설명의 반복은 피한다.
- 파일명·내부 구현 명칭보다 연구에서의 역할을 먼저 설명한다. 재현에 필요한 식별자와 세부 설정은 표·부록·근거 링크에서 보존한다.

## 근거와 범위

- 현재 논문 제목은 **From Audio to Full-Body Guitar Performance with a Freely Moving Instrument**이다. 논문 관련 문서에서는 이 표기를 사용한다.
- 사용자가 정한 제목과 Abstract → Introduction → Related Work → Methodology → Experiment → Result → 부록의 순서를 유지한다. 초록은 본문 앞에 둔다.
- 원고의 자료 기준일과 실제 실험 조건을 보존한다. 프로젝트의 최신 구현, 실행일, 원고에 반영한 자료 기준일을 구분한다. 새 코드·설정이나 문서의 수정 날짜만으로 기존 결과가 갱신된 것으로 서술하지 않는다.
- 새로운 실험 결과를 반영할 때는 사용한 코드·설정·모델과 직접 결과를 확인하고, 방법·실험·결과·초록·근거 색인에서 관련 설명을 함께 맞춘다. 자료 기준일은 실제 반영한 근거 범위에 맞게 갱신한다.
- 음악 수행·악기 지지·사람과의 동작 유사성·지각적 자연스러움은 서로 다른 평가 대상이다. 검증한 범위에서 주장한다.
- 구현 완료, 정적 검사·단위 테스트 통과, 물리 시뮬레이터 실행, 학습 업데이트, 저장 모델의 별도 평가, 성능 향상을 구분한다. 앞 단계의 확인만으로 뒤 단계를 달성했다고 쓰지 않는다.

## 연구 질문과 논리 구성

- 서론의 각 기여는 방법·실험·결과의 근거와 연결한다. 아직 검증하지 않은 목표는 달성한 기여와 구분한다.
- 본문은 연구 질문과 독자의 이해 순서에 따라 구성한다. 개발 순서나 시행착오를 그대로 나열하지 않는다. 실패 실험은 어떤 질문에 답하며 무엇을 보여주는지 설명하고 포함한다.
- 설계 의도, 관측 사실, 원인에 대한 해석을 구분한다. 예를 들어 안정성을 높이기 위한 선택, 실제 이탈 감소, 지지 접촉이 원인이라는 추정은 서로 다른 수준의 주장이다. 통제된 비교 없이 상관관계를 인과관계로 단정하지 않는다.

## 설계 선택과 실험의 일관성

- 초기 자세, 고정한 신체 부위, 스트랩, 보상 계수 등 결과에 영향을 주는 선택은 선정 이유와 적용 조건을 설명한다. 수동 설정은 수동으로 정했다고 밝히고, 실제 시험한 범위와 재현에 필요한 조건을 기록한다.
- 초기 자세의 정적 유지와 연주 동작 중의 지지 유지를 구분한다. 자세 선정에 사용한 기준과 그 자세에서 별도로 평가한 결과를 명시한다.
- 하나의 실험 설정에 속하는 방법·제어 방식·평가 기준을 일관되게 설명한다. 개발 과정의 서로 다른 버전을 하나의 방법처럼 섞지 않는다. 다른 버전의 결과를 함께 제시할 때는 변경된 조건과 비교 가능한 범위를 밝힌다.
- CPU·GPU 물리 경로, 자산·접촉 모델, 관측·행동·보상·성공 판정이 달라지면 별도 조건으로 식별한다. 같은 이름의 지표라도 정의가 다르면 수치를 그대로 합치거나 직접 비교하지 않는다.
- 모델의 전체 관절·입력 채널, 실제 가동범위가 있는 축, 정책이 출력하는 축, 별도 유지 제어를 받는 축을 구분한다. ‘전신’이라는 표현에는 Root 고정 여부와 실제 정책 제어 범위를 함께 설명한다.
- XML 선언값, 시뮬레이터가 불러온 값, 실행에 실제 적용한 값을 구분한다. 시각 형상과 충돌 형상, 기준점과 질량중심, 접촉 후보·몸체 합력과 실제 현 압력·음향을 같은 측정으로 해석하지 않는다.

## 정량 결과와 재현

- 결과마다 곡·목표 수, 초기 조건, 평가 시간 구간, 성공 기준과 시간 허용오차, 사용 모델을 식별할 수 있게 기록한다. 임계값의 값·단위와 적용 시점을 설명하고, 누적 유지와 연속 유지처럼 결과에 영향을 주는 정의를 생략하지 않는다.
- 성공률에는 성공 수와 전체 평가 수를 함께 적고, 분모가 음·에피소드·곡·환경 중 무엇인지 밝힌다. 부분 수집·중도 종료·실패 사례의 포함 또는 제외 기준을 명시한다. 안전한 시간축 완주와 음악 과제 성공은 별도로 보고한다.
- 학습 중 수집한 결과와 저장 모델의 별도 평가를 구분한다. 학습 전·후 비교에는 모델 선택 기준과 평가 조건을 밝히고, 가장 좋은 중간 모델을 보고할 때 최종 모델의 결과와 구별한다.
- 병렬 환경 수, 반복 에피소드 수, 독립 학습 seed 수를 구분한다. 반복이 부족하면 관측한 횟수와 조건을 그대로 보고하며, 통계적 유의성이나 일반화를 단정하지 않는다. 변동성·신뢰구간은 계산할 수 있는 원자료와 방법이 있을 때 제시한다.
- 성공이 관측되지 않은 결과와 실패 사례도 연구 질문에 맞게 보고한다. 관측된 성공 0회를 과제의 불가능성으로 해석하지 않는다. 수행하지 않은 비교 실험은 후속 과제로 표시한다.

## 인용과 근거 자료 관리

- 선행 연구의 서지 정보·방법·수치는 원 논문이나 저자·출판사의 공식 자료로 확인한다. 확인하지 못한 인용·수치·링크를 만들어 채우지 않고 작성 메모에 확인 과제로 남긴다.
- 연구 결과를 뒷받침하는 직접 원자료와 코드·설정·모델의 위치를 근거 색인에 연결한다. 코드만으로 실행 성과를 증명하거나, 요약 문서의 설명만으로 원자료에 없는 결론을 추가하지 않는다.
- 오래된 자료도 현재 모델의 출처·형상·물성 설명에 사용되면 측정 조건과 용도를 명시해 유지한다. 과거 설정의 사본을 현재 설정의 근거로 인용하지 않는다.
- 불필요한 근거 사본을 정리할 때는 논문 밖의 그림 생성 도구를 포함해 참조·의존 관계를 확인한다. 복사본 목록·파일 해시·검증 기록이 있으면 함께 갱신하고, 필요한 참조는 보존된 원본으로 연결한다. 원본 실험 기록의 삭제는 사본 정리와 별도 범위로 다룬다.

## 선행 연구 비교와 시각 자료

- 선행 연구는 입력, 제어 대상, 악기 고정 여부, 사용하는 데이터, 성공 판정 조건을 구분하여 비교한다. 우리와 다른 문제를 다룬다는 사실만으로 그 연구의 한계나 우리 방법의 우월성을 주장하지 않는다.
- 그림과 표는 본문 없이도 핵심 조건을 이해할 수 있도록 캡션·표 머리글에 필요한 비교 대상, 단위, 측정 구간과 성공 기준을 명시한다. 정지 화면의 외관과 연속 연주 성공을 구별한다.
- 개념도·재구성 영상·시뮬레이터 원본 화면을 구분해 표시한다. 보기 좋은 대표 장면의 선정만으로 정량 결과나 전체 수행의 성공을 대신하지 않는다.

## 작성 후 점검

- [ ] 독자가 필요한 용어·기호를 처음 등장할 때 이해하고, 문제·방법·평가의 논리 연결을 따라갈 수 있는가?
- [ ] 각 주장과 수치가 직접 근거, 자료 기준일, 해당 실행의 조건·판정 정의에 맞는가?
- [ ] 초록·기여·방법·실험·결과·부록의 설명과 단위·분모·그림·표가 서로 일관되는가?
- [ ] 변경한 인용·파일 링크가 유효하며, 근거 파일 정리로 도구의 입력이나 재현 경로가 끊기지 않았는가?
- [ ] 관측 사실·해석·미검증 가설·후속 과제를 구분했으며, 변경 범위에 맞는 별도 검수에서 지적된 사항을 확인했는가?
