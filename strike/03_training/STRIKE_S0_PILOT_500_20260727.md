# Strike S0 500-iteration pilot — 2026-07-27

> **보존 범위:** 2026-07-27 재설계 결정에 따라 이 실험의 checkpoint, plot, evaluation,
> manifest는 제거했다. 정량 근거인 로그와 remembered/current 결과 영상만 보존한다.

## 판정

500회 학습 실행과 결과 저장 배관은 정상 동작했다. 그러나 정책은 한 번도 RELEASE를
만들지 못했으므로 strike primitive 학습은 실패다. 기존 checkpoint는 제거되어 재사용할 수 없다.

## 실행 범위

- 환경: Isaac Gym GPU PhysX, RTX 4070 Ti
- 병렬 환경: 512
- PPO iteration: 500
- 환경 sample: 8,192,000
- 경과 시간: 1,037.4초
- curriculum: `single_release` 300회, `alternate_pair` 200회
- 출력: `strike/training/runs/strike_s0_pilot_500_20260727`

500회는 전체 A0~A7 curriculum이 아니다. 현 설정의 iteration 기반 4단계 중 첫 300회와
두 번째 단계의 200회만 실행한 진단 pilot이다.

## 실행 중 발견하고 수정한 학습기 결함

첫 실행은 `policy_loss=value_loss=entropy=0`, `ppo_updates=0`이었다. 원인은 Isaac Gym task가
같은 `obs_buf`를 매 step 덮어쓰는데 rollout 수집기가 그 참조를 그대로 저장한 것이었다.
과거 행동을 모두 마지막 프레임 관측으로 재평가해 첫 KL gate에서 갱신이 차단됐다.

`PPOTrainer.collect()`가 `env.step()` 전에 정책 관측을 clone하도록 수정했다. 같은 관측
버퍼를 재사용하는 CPU stub 회귀 검사를 추가했고, 512-env·1-iteration GPU probe에서 유한한
policy/value loss와 `ppo_updates > 0`을 확인한 뒤 500회를 처음부터 재실행했다.

중단된 진단 실행은 비교 증거로
`strike/training/runs/strike_s0_pilot_500_20260727_aborted_no_updates`에 보존했다.

## 다음 실행 전 필수 과제

1. **A0 dynamic-ready를 실제 단계로 구현**한다. pick marker가 strike ribbon entry gate에
   도달하고 rest gap을 유지하는 문제만 먼저 학습하며 RELEASE goal은 아직 주지 않는다.
2. **성능 기반 승급**으로 바꾼다. release가 0인데 iteration 301에서 `alternate_pair`로
   넘어가는 현재 방식은 금지하고, A0 reach gate와 A1 release recall gate를 통과해야 승급한다.
3. **거리 진단을 로그에 추가**한다. pick→allowed ribbon 최소 거리, entry-gate 거리,
   기타 local `(x,y,z)`, corridor progress, action saturation을 iteration/evaluation에 저장한다.
4. **scripted 6줄×양방향 GPU kinematic probe**를 완료한다. detector가 정상 궤적에서는
   release를 만들고 현재 정책 궤적에서만 0인지 분리한다.
5. **초기화/탐색 ablation**을 한다. entry gate 근처의 reset pose 또는 scripted approach
   warm start와 현재 pose를 비교하고, 초기 표준편차·action EMA·actor learning rate는
   reach 및 안전 분포를 보면서 조정한다.
6. 위 과제 뒤 `A0 → A1 one-string` 순으로 짧은 gate run을 수행한다. A1 단현 release가
   나오기 전에는 alternate-pair나 full-song 500회를 다시 실행하지 않는다.
