# 코드 트랙 구축 — 탭→규칙(1차) + ACE 게이팅(2차) 구현·평가 리포트 (2026-07-15)

> 역사적 실험 보고서. 최종 갱신: 2026-08-03. 재현·운영 진입점은 상위
> [`../SETUP.md`](../SETUP.md)와 [`../pipeline.py`](../pipeline.py)이며, 이 문서의 수치는 당시
> moum/rock3 평가 결과다.

## 왜 이렇게 시도했나

07-15 ACE 단독 평가(`tabtrans/ace_eval/REPORT.md`)에서 consonance-ACE가 게이트를 통과하지
못했다(고립 코드 top-1 0.65, 실패 모드 = 감쇠 시 3도 소실). 반면 탭→규칙 디코딩은 같은
도메인에서 0.937(07-13 실측)이었다. 이에 코드 트랙의 아키텍처를 다음으로 재설계했다:

- **1차 증인 = 탭→규칙**: v1 탭의 프레임별 울림 pcset → `match_pcset`(legacy 재사용).
  코드는 탭의 결정론적 함수라는 07-13 발견의 제품화.
- **① 시간 필터 (정보 불변)**: 프레임 판정의 깜빡임은 ACE가 아니라 순수 필터로 잡는다 —
  mode 필터(9프레임≈105ms) → 같은 코드 사이 짧은 N 틈 메움(≤0.35s, 스트럼 사이 감쇠)
  → 최소지속 병합(<0.25s). "평활화에 ACE는 필요 없다"의 검증.
- **② ACE 융합 게이팅 (정보 추가)**: ACE는 탭과 오류가 무상관인 독립 증인. 역할 3개 —
  (a) 합의/불일치 → 신뢰도 채널(conf), (b) 탭 N 구간 구제(단, ACE 세그먼트의 탭
  시간-합집합 pcset이 그 코드 구성음의 부분집합일 때만 — 환각 채택 방지 게이트),
  (c) 불일치 플래그 = 전사 오류 의심 신호.

## 과정

- 구현: `chordtrack/core.py`(규칙 디코딩·필터 체인·융합, 순수 함수),
  `eval_moum.py`(4변형 비교 하니스), `build_track.py`(오디오→코드 트랙 JSON CLI,
  ACE는 .lab 산출물로만 소비 — ACE 의존성 없음).
- 평가: ace_eval과 동일 조건(moum 코드 88 + 단음 156, 파일명 GT, 37클래스).
  ACE는 완화 파라미터(τ0.3, minDur 0.25s) 고정.
- 데모: rock3 comp(Bb 록 반주 32.8s, 연속 컴핑)로 실전 융합 확인.

- **탭→규칙만으로 두 게이트 모두 통과** (top-1 88/88, 오탐 0). 단음 파일에서 pcset<2 → N이
  구조적으로 보장되는 것이 오탐 0의 이유(ACE는 5.9~6.6% 오탐).
- 시간 필터가 시간가중 정확도 +5.1%p (감쇠로 끊긴 코드 지속을 이어붙임) — ACE 없이 달성.
- ACE 융합의 순기여는 +0.5%p(구제 프레임 0.5%): 이 코퍼스(고립 코드)에서는 탭이 이미 다
  잡아서 여지가 작음. 멜로디 쪽 구제 오염 0 — pcset 검증 게이트가 환각 채택을 전부 차단.

## 결과 2 — rock3 연속 컴핑 데모 (융합의 실전 가치)

`build_track.py + rock3_comp_relaxed.lab`, 2827프레임: **합의(conf=3) 68.2%** /
불일치(conf=1) 19.6% / **구제 2.7%** / N 9.5%.

- 진행 골격(A#–F–Gm/G5–Dm–D#–…)에서 두 증인이 일치 — 코드 코어는 고신뢰로 확정됨.
- 불일치의 전형 = **"X:5 vs X:maj/min"**: 어택·감쇠 순간 탭에 3도가 안 잡혀 파워코드로
  붕괴한 구간에서 ACE는 3화음을 주장. 흥미롭게도 **finger mapping 관점에서는 탭 우선이
  여전히 옳다** — 사전 매칭은 어차피 탭 발자국과 대조하므로, 실제로 루트+5도만 눌렸다면
  파워코드 그립이 맞는 운지다. ACE의 3화음 주장은 라벨 명명·구간 병합 힌트로만 쓰면 된다.
- 구제 사례: 탭이 순간적으로 N인 스트럼 사이를 ACE 세그먼트가 이어붙임(76프레임).

## 판정·해석

1. **아키텍처 확정 근거 확보**: 1차 = 탭→규칙 + 자체 시간 필터(여기까지로 게이트 통과),
   2차 = ACE 게이팅(신뢰도 채널·N 구제·불일치 플래그). ACE는 "평활화 도구"가 아니라
   "독립 증인"으로만 가치가 있음이 수치로 분리됨(①의 +5.1%p vs ②의 +0.5%p).
2. conf 채널의 finger mapping 접속(설계 §A): conf=3 → 고신뢰 CHORD(사전 조회),
   conf=1 → 사전 조회하되 진단 플래그, conf=0/N → MELODY.
3. disagree 프레임(전 코퍼스 1,231 + rock3 554)은 전사 오류 의심 채널로 축적 가능.

## 정직한 주의사항

- moum 코드 파일은 **고립 블록 코드 = 탭→규칙의 최적 조건**이고, v1이 이 코퍼스 음원을
  학습에서 봤을 가능성(legacy README 리스크 노트)이 있어 1.000은 낙관 상한이다.
  실전(빠른 패시지·전사 오류·아르페지오)은 rock3처럼 불일치 ~20%가 정상 — conf 채널이
  그 불확실성의 운반자다.
- 아르페지오 전용 평가는 아직 없음(moum은 블록 코드 위주) — dataset3(릭·코드 혼재)나
  실곡에서 ARPEGGIO 분류·구제 경로 검증이 다음 항목.
