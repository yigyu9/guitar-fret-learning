# 평가 중단 원인과 재개 방법

학습 100회는 정상 완료되어 보존되어 있다. 두 번의 평가는 각각 16개 에피소드를 마쳤으나, 평가 중 별도 오른손 연구 파일이 변경되어 종료 SHA 검사를 통과하지 못했다. 물리 장면 정리와 생명주기 검사는 두 번 모두 성공했고 failure는 null이다. 이 평가는 과학적 성공/실패 결과로 채택하지 않는다.

첫 평가에서 right_strike_environment.py와 그 테스트, 두 번째 평가에서 right_strike/native_probe.py와 그 테스트가 변경되었다. 현재 학습 입력 555개와 driver 핀 10,257개는 모두 일치하며, CPU에서 frozen learning.read_checkpoint(final.pt)의 strict 검증도 성공했다. checkpoint는 updates100과 actor/value optimizer, 난수 상태, sampler, 누적 노출 원장을 포함한다.

## 안전한 재개

1. 활성 소스 편집을 중지하고 GPU를 단독 확보한다. RH21 변경은 별도 새 연구로 분리한다.
2. root가 현재 상태를 별도 보관하고 완료 task의 artifact/dependency SHA를 다시 검사한다.
3. 실패 task 평균_u000100 엔트리는 원문을 별도 보관한 새 상태 revision에서 새 재시도 묶음으로 분리한다. 기존 attempt01/02 디렉토리와 report/log는 수정하지 않는다. 단순 driver 재실행은 history 두 번 제한으로 즉시 같은 지점에서 멈춘다.
4. 같은 frozen driver를 재시작하면 완료 학습100을 재사용하고 새 attempt03 평가를 만든다. 이 평가가 검증되면 동일 final.pt로 추가100회씩 엄격 재개하여 목표800회까지 이어간다.
5. 기존 학습시간/전체7시간 제한은 유지한다. 시간이 부족하면 완료 모델을 보존하고 추가 계획을 분리한다.

원본 checkpoint의 노출 일정은 planned_transitions=3,276,800, full_song_after=819,200으로 이미 완료되어 있다. 후속 추가학습은 이 기존 일정을 복원하며, 총800회 예산에 맞추어 조용히 재설정하지 않는다. 유효한100회를800회로 잘못 표시하거나 실패 평가의 completed 값을 바꾸면 안 된다.

이 진단은 읽기 전용이며 상태·학습·평가·모델·봉인 파일을 변경하지 않았다. 원문 SHA와 상세 항목은 진단.json에 저장했다.
