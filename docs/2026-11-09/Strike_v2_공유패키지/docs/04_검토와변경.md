# 검토 결과와 원본 대비 변경

이 패키지는 원본을 그대로 복제한 봉인본이 아니라 **원본을 보존한 공유용 개선 사본**이다. 비교 기준은 `archive/strike_v2_20261104`, 그 출처는 `archive/legacy_guitar_20261019/tab2body`다. 실제 파일별 출처·해시·차이는 [provenance.json](../verification/provenance.json)에 기록한다.

## 정리한 범위

- 압현 환경·보상·모델·커리큘럼과 양손 결합 전용 코드18개를 공유본에서 제외했다.
- 연결된 lazy export3곳을 타현 중심으로 좁히고, `train.py`의 기본값과 선택지를 strike로 한정했다. `train.py`는 tooling 지문에 포함되므로 파일 자체를 제거하지 않았다.
- 현재 프로젝트의 다른 절대 경로를 가리키던 과거 README/TRAINING은 제외하고 이 패키지 내부 문서로 대체했다.
- 공용 checkpoint 모듈의 문서 첫 줄을 실제 지원 범위인 fret·strike로 바로잡았다. 그 모듈의 검증 로직은 변경하지 않았다.
- 공유 코드에 남아 있는 공용 helper와 과거 관측 호환 경로는 추가 삭제하지 않았다. 삭제 이득보다 실행·checkpoint 계약에 미칠 영향이 커, 핵심 학습 코드를 대폭 재구성하지 않았다.

회귀는 [타이밍 경계 검사](../tab2body/tests/test_strike_timing_boundary.py)와 [목표 계획 검사](../tab2body/tests/test_strike_plan_validation.py)에 있다. 시간창을 실질적으로 확대하거나 보상 계수·관절 제어·물리를 변경한 것은 아니다. 수치 경계 오류는 극히 작은 정밀도 차이이므로 이 발견으로 과거 학습 결과 전체를 다시 해석하지 않는다.

## 남은 한계와 개선 제안

**회복 진행 보상 재지급:** `StrikeTask`는 추가 교차 후 같은 사건의 회복 최고 진행량까지 초기화하며, `StrikeReward`의 회복 진행 보상에는 clean-event gate가 없다. 다른 입력을 고정한 CPU 보상식에서 S0의 `오타현 −.50 + 회복 11/12 × .60 = +.05`가 재현됐다. 이는 해당 항목의 재지급 가능성이고, 실제 정책의 반복 악용·물리 실현·전체 에피소드 이득을 확인한 결과는 아니다.

개선안은 사건별로 이미 지급한 회복 진행 상한을 보존하고, 회복 상태 재시작과 보상 지급 이력을 분리하는 것이다. 보상 의미가 달라지므로 이 공유 정리에서는 적용하지 않았다. 적용 시 잘못된 교차 뒤에도 정상 회복을 유도할 수 있는지, 보상 반복 지급이 사라지는지, 별도 새 학습에서 비교해야 한다.

**원시 입력 출처:** `metadata.source`가 없는 컴퓨터에서는 raw SHA 확인이 생략될 수 있다. 공유·재현 시 raw를 동봉하고 plan을 재생성한다. 장기 개선은 휴대 가능한 상대 출처 경로와 출처 미검증 상태를 명시하는 것이다. 이 작업에서는 기존 검사를 우회하거나 성공으로 위장하지 않았다.

**연구 검증 범위:** CPU 검사는 로직·모델 입출력 검증이다. 자산이 포함되지 않아 native rollout, PPO 학습 수렴, 과거 checkpoint 재개, 실제 영상, 줄 힘·음향은 미검증이다. 문자열·기하 기반 성공과 실제 악기 연주를 구분한다.

**활성 판정과 과거 helper:** `strike_false_positive_count`, 구형 `strike_recovery_to_approach` 같은 함수는 보존되어 있으나 현재 `StrikeTask`의 활성 판정 경로와 다르다. 함수 이름만으로 현행 성공 기준을 설명하지 말고 task의 실제 호출 연결을 확인한다.

기준 모음에서 별도의 LICENSE/COPYING/NOTICE 파일은 발견되지 않았다. 이 문서는 새로운 이용 허락 조건을 추가하지 않는다.
