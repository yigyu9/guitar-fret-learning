# 구조·입력·출력·신경망

## 처리 흐름

```text
raw 줄별 목표 → 목표 compiler → strike_plan.v4 → StrikeGoalSequence
                                                    ↓
실제 관절·가상 피크 상태 → StrikeTask 관측 조립 → actor → 30축 행동
                           ↑                         ↓
               교차 검출·사건 판정 ← Isaac Gym 물리 제어
                           ↓
                  보상·종료·통계 → PPO / critic
```

[train_strike.py](../tab2body/train_strike.py)가 입력 검증, 환경·모델 생성, 학습·평가·저장을 묶는다. [task_strike.py](../tab2body/env/tasks/task_strike.py)는 실제 시뮬레이션 상태를 관측으로 만들고 준비·접근·회복 및 사건별 달성을 관리한다. [base.py](../tab2body/env/base.py)는 자산 로딩과 관절 제어를 담당한다.

## 상태와 목표 입력

현재 압현 구조처럼 상태 전체와 목표 전체에 각각 하나씩 인코더를 쓰는 형태가 아니다. 과거 Strike-v2는 상태와 목표를 아래 **11개 의미 블록**으로 나누어 각각 인코딩한다. 기준은 [관측 계약](../tab2body/strike_v2_contract.py)과 `StrikeTask.compute_observations()`다.

| 블록 | 입력 | 내용 | 인코딩 출력 |
| --- | ---: | --- | ---: |
| proprio | 60 | 제어 관절 위치30·속도30 | 96 |
| arm_anchor | 18 | 오른쪽 흉곽의 기타 상대 위치3·회전6·선속도3·각속도3·중력3 | 48 |
| hand_geometry | 30 | 손바닥·피크 각각 기타 상대 위치3·회전6·선속도3·각속도3 | 64 |
| grip_safety | 7 | 파지 품질3·관통 여유4 | 16 |
| current_event | 32 | 유효성·주법·통과/발음줄·줄별 시각 offset·방향·시간창 | 64 |
| target_geometry | 25 | ready/entry/exit/active 벡터12·lane 오차1·현재/다음 줄12 | 48 |
| lookahead | 52 | 다음 두 이벤트 각각26 | 64 |
| phase_detector | 29 | 단계3·준비 누적1·해결1·줄별 완료/armed/rearm/release 각6 | 48 |
| recovery | 18 | 회복 모드·진행·남은 시간·분리 여유·목표 벡터·방향 | 48 |
| synchronizer | 2 | 교차 허용·타이밍 offset | 8 |
| history | 30 | 이전 실행 행동 | 48 |
| 합계 | **303** |  | **552** |

`synchronizer` 슬롯은 외부 동기화와의 인터페이스를 위해 남아 있다. 슬롯이 존재한다는 것만으로 왼손 압현이나 전신 정책이 함께 학습된다는 뜻은 아니다.

## 목표 파일

raw 입력의 최소 예시는 `{"time": 0.5, "frame": 30, "string": 0}`이며 시계는 60Hz다. 런타임 줄 번호는 **0=1번 줄(high-e), 5=6번 줄(low-E)**이다. [합성 입력](../tab2body/tests/fixtures/strike/strum_6_string.json)처럼 같은 시점의 여러 줄은 compiler가 하나의 스트럼 이벤트로 묶는다.

[compiler](../tab2body/env/strike_goal_compiler.py)는 single_pick·strum·alternate_restrike를 구분하고, 음악적 발음줄·피크가 실제 통과할 연속 줄 범위·보호줄·운동 방향·줄별 offset·sweep 시간 및 전환에 필요한 여유를 만든다. raw 목표의 frame은 시각과 반 프레임 이내여야 하며, 컴파일된 이벤트의 중심 frame은 compiler의 반올림 규칙을 따른다.

실제 학습 진입점은 **`tab2body.strike_plan.v4`**를 요구한다. loader가 raw 입력을 읽을 수 있어도 raw fixture를 그대로 학습 `--goal`에 넣는 것은 지원 경로가 아니다. `alternate_restrike`는 표현·진단은 가능하지만 이 학습 경로에서는 거부한다. 제공된 `single_dense.json`은 이 거부 동작을 확인하기 위한 입력이다.

## 신경망과 출력

[StrikeV2ActorCritic](../tab2body/learning/strike_v2_model.py)은 블록마다 `Linear → ELU`를 적용한 뒤 합친다.

```text
actor:  관측303 → 독립 블록 인코더 → 552 → 512 → 256 → 평균30
critic: 관측303 → 독립 블록 인코더 → 552 → 512 → 256 → 가치1
```

actor와 critic은 인코더도 따로 가지며 관측 정규화 통계만 공통으로 사용한다. 순환망은 없다. 학습 가능한 행동별 표준편차의 Gaussian을 tanh로 제한하고, 결정적 평가에서는 `tanh(mean)`을 사용한다. 모델 생성자 기본 std는 `.02`이지만 **실제 Strike 실행 설정은 `.04`**를 전달한다.

30축은 **오른쪽 어깨3 + 팔꿈치3 + 손목3 + 손21**이다. 오른손21축은 파지 기준각 주변 residual로 제한하며 기본 허용폭은 pinch `.08rad`, 나머지 `.22rad`다. 행동에는 EMA `.5`를 적용하고 기존 관절 제어기에 연결한다. 이 값은 현재 프로젝트의 27축 정책 정의와 혼용하지 않는다.

## 실제 Strike 기본 PPO 설정

기준은 공용 PPO 클래스의 기본값이 아니라 [strike_cfg.py](../tab2body/strike_cfg.py)의 `STRIKE['ppo']`다.

| 항목 | 값 |
| --- | --- |
| 환경 수 / 전체 iteration / seed | 512 / 50,000 / 42 |
| rollout horizon / update epoch / minibatch | 32 / 5 / 2,048 |
| actor 학습률 / critic 학습률 | 3e-6 / 3e-4 |
| 할인율 / GAE λ | .95 / .95 |
| PPO clip / value 계수 / entropy 계수 | .2 / 1 / .001 |
| gradient clip / target KL | 1 / .03 |
| 팔·손목 행동 포화 정규화 | 계수 .002, 임계 .90 |

[ppo.py](../tab2body/learning/ppo.py)에서 Adam의 actor/critic parameter group을 분리하고 PPO update 후 관측 통계를 갱신한다. 위 수치는 과거 기본 설정이며 이번 공유 작업에서 학습 성능을 다시 검증한 수치는 아니다.
