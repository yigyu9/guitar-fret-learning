# 실행과 검증

## CPU 검증

명령은 패키지 루트에서 실행한다. [requirements-cpu.txt](../requirements-cpu.txt)는 CPU 검사에 필요한 직접 의존성을 적은 목록이며 과거 물리 학습 환경의 잠금 파일이 아니다.

```bash
python -m pip install -r requirements-cpu.txt
python -B tools/verify_cpu.py
```

[검증 도구](../tools/verify_cpu.py)는 각 검사를 새 Python 프로세스로 실행하고 GPU를 숨기며 CPU 스레드를1개로 제한한다. `assert` 최적화를 차단하고 완료 표시·종료 코드·시간 초과를 확인한다. 결과는 [cpu_report.json](../verification/cpu_report.json), 세부 출력은 `verification/cpu_logs/`에 남는다. 실제 검사 수와 버전은 이 보고서가 기준이다.

최종 검사 환경은 Python3.8.20, Torch2.4.1+cu121, NumPy1.23.5, Pillow10.4.0, Matplotlib3.7.5다. CUDA 지원 Torch가 설치되어 있지만 본 검사는 GPU 장치를 숨기고 CPU만 사용했다. 다른 설치 조합의 호환성을 검증한 것은 아니다.

기존 전체 검사22개, goal_quality의 합성 검사6함수, 공유본에 추가한 회귀 스크립트2개를 대상으로 한다. `unittest discover`의 검출 개수는 이 검사의 실행 수가 아니다. 다음 검사는 필요한 외부 입력이 빠져 있어 제외하며 통과로 세지 않는다.

2026-11-04 최종 실행에서 **25개 프로세스 모두 통과**했다. 이는 전체 스크립트24개와 선택한6함수 실행1묶음의 합계다.

| 제외 대상 | 사유 |
| --- | --- |
| test_strike_training_runtime.py | 실제 곡별 strike_plan 필요 |
| test_strike_reward_staging.py | 원래 pick-grip-reference 필요 |
| test_strike_preflight_layout.py | mock 진입 전 기본 곡·파지 파일 확인이 수행됨 |
| goal_quality의 실제 곡1함수 | 원시곡·계획·검토된 override 필요 |

첫 검사에서 확인한 preflight 외부 입력 누락은 [초기 보고서](../verification/cpu_initial_report.json)에 보존했다. 합성 입력 검증·정책 shape·판정 로직·파일 계약 검사와 실제 Isaac Gym/PPO 학습은 구분한다.

## 목표 컴파일 예제

아래 명령은 동봉한6줄 입력을 학습 계획 형식으로 변환할 뿐 물리를 실행하지 않는다. 출력 경로는 예시다.

```bash
python -B -m tab2body.tools.build_strike_plan \
  tab2body/tests/fixtures/strike/strum_6_string.json \
  --out /tmp/strike_v2_example_plan.json
python -B -m tab2body.train --help
```

raw 입력을 수정하면 plan을 다시 만든다. `metadata.source`가 실제로 존재할 때 loader는 raw SHA를 검사한다. **선언한 원시 파일이 없으면 해당 SHA 검사를 생략하는 기존 동작**이 있으므로, 다른 컴퓨터에 전달할 때는 raw도 함께 전달하고 받는 위치에서 plan을 재생성해야 출처를 확인할 수 있다. plan 생성 성공을 물리적 수행 가능성으로 해석하지 않는다.

## 실제 물리 실행에 별도로 필요한 것

| 위치·항목 | 용도 |
| --- | --- |
| tab2body/assets/smpl_mpl_hands_body.xml 및 참조 mesh | 인체 모델 |
| tab2body/assets/guitar_asset.xml 및 참조 mesh | 기타 모델 |
| tab2body/assets/seated_pose.json | 초기 자세 |
| tab2body/_gen/mjcf_gains.json | 기존 관절 PD·힘 설정 |
| pick-grip-reference.json | 오른손21축 파지 기준·그룹·보상 척도 |
| 곡의 raw 입력 및 strike_plan.json | 검증할 고정 목표와 출처 |
| 호환되는 Isaac Gym·Torch 환경과 GPU | native 물리 실행 |

원래 자산·입력의 동일성을 확인한 뒤 배치한다. 자산 경로는 패키지 내부 고정 구조이며 별도 asset-root CLI가 없다. goal과 grip 경로는 CLI로 지정할 수 있지만 기본 경로의 파일은 이 패키지에 없다. run 관리가 `fcntl`·`/proc`에 의존하므로 native 실행은 Linux/POSIX 환경을 전제로 한다. 영상 생성에는 ffmpeg도 필요하다.

환경과 입력을 갖춘 뒤의 **미실행 참고 명령**이다. `/path/to/...`는 실제 보유 파일로 대체한다.

```bash
python -B -m tab2body.train_strike \
  --goal /path/to/strike_plan.json \
  --grip-reference /path/to/pick-grip-reference.json \
  --device cuda:0 --smoke --no-auto-video --no-auto-artifacts \
  --out /path/to/new_strike_smoke
```

smoke도 실제 GPU 물리와 PPO update를 실행한다. 이번 공유본 검토에서는 실행하지 않았다. 먼저 자산·입력·모델 계약 확인과 smoke를 완료하고, 이어 별도 새 실행으로 학습 및 seed별 평가·영상을 확인해야 한다.

## 무결성과 과거 모델

파일 변경 확인은 패키지 루트에서 `sha256sum -c FILES.sha256`로 할 수 있다. 이 목록은 배포 시점 기준이므로 검증 도구를 재실행해 보고서·로그를 갱신하면 해당 파일들의 해시가 달라진다.

공유본의 판정·입력 검증·initializer 변경으로 코드 지문은 과거 원본과 달라진다. **과거 checkpoint의 재개·평가 호환성을 보장하지 않는다.** runtime·tooling·입력·asset SHA와 identity 검사는 그대로 유지했으며 검사를 끄거나 과거 모델 지문을 새 값으로 덮어쓰지 않았다. 원본 결과를 정확히 재현할 때는 해당 원본 소스와 일치하는 입력·자산을 사용해야 한다.
