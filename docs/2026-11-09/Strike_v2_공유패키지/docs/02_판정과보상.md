# 판정·보상·학습 단계

## 물리 환경과 성공의 의미

[base.py](../tab2body/env/base.py)는 기타 root 고정·기타 중력 OFF, 인체 root 고정 조건이다. 하체는 고정용 관절 제한·관성 설정에 더해 매 제어 스텝 초기 상태로 유지된다. 제어 주기는 60Hz, PhysX 내부 substep은 4다. detector가 240Hz의 독립적인 피크 관측을 받는다는 뜻은 아니다.

피크는 물리 충돌 형상이 없는 가상 피크 끝점이고, 현은 고정된 유한 선분 6개다. 따라서 여기서의 성공은 **피크의 기하학적 교차·주법·방향·시각·구역·회복 조건을 만족한 사건**이다. 실제 줄 변형, 줄에 가한 힘, 음압이나 음색 성공을 측정하지 않는다.

## 판정 계층

| 계층 | 역할 | 주요 코드 |
| --- | --- | --- |
| 교차 검출 | 이전/현재 피크 궤적으로 줄 통과·깊이·속도·교차 시각을 계산 | [strike_detector.py](../tab2body/env/strike_detector.py) |
| 줄별 재타현 상태 | armed/rearm, 분리 거리·유지 프레임으로 중복 교차 제한 | 같은 detector |
| 사건 대응 | 목표 줄·방향·순서·중복·보호줄·허용 시간창 판정 | [strike_events.py](../tab2body/env/strike_events.py) |
| 준비·완료·회복 | 준비 자격, 전체 통과, 끝줄 이후 이탈, 다음 사건 인계 | [task_strike.py](../tab2body/env/tasks/task_strike.py) |
| 평가 | 오타현·누락·시간 오차·회복·안전 및 단계 승급 | [strike_evaluation.py](../tab2body/learning/strike_evaluation.py), [strike_curriculum.py](../tab2body/learning/strike_curriculum.py) |

detector의 `valid`만으로 목표 성공이 되는 것은 아니다. 기본 최소 깊이는 1mm, 횡방향 속도는 .05m/s, rearm 분리 거리는 3mm이며 최소2프레임을 요구한다. 준비 유지 기본값은6프레임, 회복은12프레임이다. **준비 획득 자격은 에피소드에서 유지되는 latch**이며 목표마다 처음부터6프레임 준비를 다시 요구하는 구조는 아니다.

스트럼은 한 줄 교차로 전체 성공을 선언하지 않는다. 통과줄의 누적·방향·순서와 끝줄 이후 이탈을 처리하며, 발음줄과 통과줄을 별도 표현한다. 사건 오타현 기록은 보상·clean 판정과 함께 유지한다.

## 보상

계수는 [strike_cfg.py](../tab2body/strike_cfg.py)의 `reward`, 계산은 [StrikeReward.compute](../tab2body/env/rewards/strike.py), 실제 전달값은 `StrikeTask.step()`을 함께 확인한다. 다음은 전체 구조이며 단계별 상세 계수는 설정 파일이 기준이다.

| 항목 | 실제 계산 의도 |
| --- | --- |
| 파지 | A0는 품질을 보상, 이후는 파지 품질 저하를 벌점 처리 |
| 접근 | 목표까지의 potential 변화량에 reach·단계별 approach 계수를 적용 |
| 준비 | A1은 준비 품질, 이후 준비 미획득 손실과 획득 pulse |
| 유효 교차 | 준비된 target_hit에 기본 +1 |
| 스트럼 진행 | 누적 통과와 시간 품질을 포함한 potential의 종료 처리를 포함한 차분 |
| 끝줄 이탈·물리 완료 | clean·준비 조건에서 terminal progress와 완료 pulse |
| 시간 | accepted 줄별 시간 품질, 대기 품질, 스트럼 RMS·sweep 길이 품질 |
| 구역 | timed 단계의 구역 품질과 시도 여부 |
| 회복 | 회복 진행 증가량·완료 pulse; 과도한 회복 속도는 벌점 |
| 오타현·누락 | wrong 교차 개수·miss pulse·준비 전/이른 교차 벌점 |
| 관절 범위 | task에서 관절 한계 사용률 .95 초과의 제곱 평균에 −.01 |
| 실패 종료 | 해당 스텝 보상 전체를 기본 −10으로 **교체** |

`reward_strum_progress`에 실제로 들어가는 값은 단순 신규 통과줄 비율이 아니다. `task_strike.py`의 `strum_progress_potential → strike_terminal_potential_delta → strum_progress_shaping` 연결을 따라야 한다. 신규 통과줄 비율은 별도 진단 값으로 남아 있다. timed 단계의 시간 품질은 `1 / (1 + (error/core)^2)` 형태이며 기본 timing core는20ms, duration core는15ms다. 단계 프로필이 이 core와 허용창을 바꿀 수 있다.

예를 들어 S0의 오타현 계수는 −.50, 회복 진행 계수는 +.60이다. 이 계수만으로 전체 보상식이나 성공 여부를 판단하면 안 된다. 추가 교차 뒤 회복 진행 보상의 재지급 가능성은 [검토 문서](04_검토와변경.md)에 별도로 기록했다.

## 학습 단계

| 단계 | 목적 |
| --- | --- |
| A0_PICK_GRIP | 파지 유지 |
| A1_TIP_READY | 피크 준비 위치 획득 |
| A2_SINGLE_CROSSING | 단일 줄 교차 |
| A3_TIMED_SINGLE | 시간에 맞춘 단일 줄 교차 |
| A4_STRUM_CONTEXT_RECOVERY | 스트럼 맥락에서 완료·회복 |
| S0_TWO_STRING_STRUM | 두 줄 스트럼 |
| S1_STRUM_SPAN | 통과줄 범위 확대 |
| S2_TIMED_STRUM | 시간·sweep 길이를 맞춘 스트럼 |
| S3_SONG_INTEGRATION | 곡 안의 사건 전환 및 원곡 시각으로 확장 |

스트럼 없는 곡은 A0→A1→A2→A3→S3 경로를 사용한다. S3는 회복 여유를 둔 easy timeline에서 원곡 시각까지 tempo λ를 높인다. 스트럼 곡의 기본 adaptive 경로는 최대6줄 span 입력을 요구하므로 2줄 과제 하나를 그대로 전체 경로에 넣으면 사전 검증에서 거부될 수 있다. 단계별 학습 결과와 곡 전체 평가를 구분해야 한다.
