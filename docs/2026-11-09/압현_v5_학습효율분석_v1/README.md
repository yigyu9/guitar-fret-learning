# 압현 v5 학습이 더딘 이유와 개선 우선순위

작성: 2026-11-04. 저장 위치의 2026-11-09는 사용자가 지정한 실험 정리 기준이다.

**현재 근거로 가장 먼저 개선할 대상은 성공에 가까운 경험을 만드는 과정이다.** 준비 구간의 접근 신호, 목표별 학습 기회, 탐색 명령이 실제 움직임으로 이어지는 방식을 우선 비교할 필요가 있다. 계산 측면에서는 경험 수집이 대부분의 시간을 차지한다. 학습률이나 신경망 크기 하나로 두 문제를 함께 해결할 근거는 없다.

진행 중인 C1 학습은 변경하지 않았다. 이 문서는 실행 사본의 코드, 최초 100회 로그, 과거 실험 원시 자료, CPU 계산을 대조한 진단과 후속 실험 제안이다. **현재 C1의 최종 실패 판정이나 개선안의 효과 검증 결과가 아니다.**

## 1. 조사 범위와 판단 기준

- 현재 실행: large·1024환경·H32·2000업데이트·seed7·corrected. 팔12축과 엄지5축 초기 std 0.15, 나머지 손가락16축 초기 std 0.35.
- 기준 코드: [봉인된 실행 사본](/home/ajou/yigyu/3/docs/2026-11-09/압현_v5_C1_장기학습_v1/작업자료/runtime). 다른 창에서 바뀌는 작업 소스와 구분했다.
- 현재 v5 입력 계약은 상태 464·목표 26×8이다. 과거 설계안이나 이전 613차원 실험을 같은 구현으로 취급하지 않았다.
- C1은 검지 7음·중지 13음, 총 20음이다. 정책 시간은 준비·끝 여유를 포함해 47.25초다. 약지·소지 수행 능력을 평가하는 과제는 아니다.
- 로그 범위: 1~100회, 3,276,800개 제어 전이. 집계 시각은 2026-11-04 14:13:43 KST. 실제 학습은 이후에도 계속 진행된다.
- 이번에 새 GPU 학습·평가·프로파일러를 실행하지 않았다. 학습 원문, 모델, 입력과 검증 계약도 변경하지 않았다.

여기서 속도는 두 가지로 나눈다. **계산 효율**은 초당 경험을 얼마나 생성하는가이고, **학습 효율**은 같은 경험량에서 원하는 연주를 얼마나 빨리 배우는가다. 환경 수가 증가하면 전자가 좋아질 수 있지만, 다음 목표를 한 번도 누르지 못하는 경험만 많아지면 후자는 개선되지 않을 수 있다.

## 2. 현재 로그에서 확인한 사실

### 2.1 계산 시간은 경험 수집에 집중돼 있다

| 최초 100회 측정 | 결과 |
|---|---:|
| 한 업데이트의 경험 | 1024×32 = 32,768 전이 |
| 경험 수집 시간 합 | 1,594.78초 |
| PPO 최적화 시간 합 | 34.04초 |
| 두 시간 합에서 수집 비중 | **97.91%** |
| 업데이트당 수집 / 최적화 중앙값 | 15.79초 / 0.340초 |
| 수집+최적화 기준 처리량 | 약 2,012 전이/초 |
| 실제 PPO epoch / minibatch | 2 / 4096 |
| actor LR / value LR | 0.00003 / 0.0003 |
| 이 구간의 LR 감소 / KL 재시도 | 없음 / 0회 |

수집에는 물리 시뮬레이션뿐 아니라 정책 추론, 제어, 접촉·목표 판정, 초기화, 진단 기록이 포함된다. 따라서 97.91%를 전부 PhysX 비용이라고 해석하면 안 된다. 최적화 시간만 없애도 줄일 수 있는 시간은 이 측정 합의 약 2.09%다. 신경망 축소가 수집 중 추론에 주는 효과는 별도 측정이 필요하다.

14:08:36~14:09:14 KST의 약 38초 자원 표본에서는 GPU 이용률 평균 47.75%(10~85%), 최대 VRAM 4,479MiB/12,282MiB, 관련 프로세스 CPU 합 평균 85.72%였다. CPU 100%는 논리 코어 하나 기준이다. 이 짧은 표본은 GPU 자원 여유를 시사하지만, 정확히 어느 함수가 병목인지 또는 환경 수를 두 배로 늘리면 얼마나 빨라지는지는 증명하지 않는다.

소스에는 매 제어 tick의 4개 물리 substep, native/Torch 사이의 동기화, GPU 결과의 Python bool 확인, 진단값의 CPU 변환이 있다. **후속 시간 측정 대상**이며, 동기화나 유한값 검사를 검증 없이 제거할 대상은 아니다.

### 2.2 안정성 학습과 음악 수행 학습의 진전이 다르다

| 지표 | 1~20회 | 81~100회 |
|---|---:|---:|
| 완료된 학습 episode | 1,564 | 1,045 |
| 그중 물리 실패 종료 | 1,211 (77.43%) | 82 (7.85%) |
| 제어 전이당 평균 비용 | 0.04346 | 0.002068 |
| 완료 episode당 기존 음 달성 평균 | 0 | 0 |
| 보상 가치망 설명력 EV 중앙값 | 0.23849 | 0.000347 |
| 비용 가치망 설명력 EV 중앙값 | 0.64686 | 0.00000260 |

두 구간은 각각 655,360 전이를 사용했다. 물리 실패 비율의 분모는 **그 구간에 끝난 episode**다. 초기화 횟수·episode 길이·노출 분포가 달라질 수 있어 고정 조건 성공률은 아니다. 그래도 전이당 비용도 크게 감소하므로, 안전한 상태를 유지하는 쪽의 진전은 확인된다.

100회 전체에서는 종료 episode 5,898개 중 2개에서 기존 기준 음 달성이 하나씩 기록됐다. 모두 2~6음 구절 학습이다. 이 숫자는 20음 C1 전체 성공률이 아니다. 시간 끝까지 도달했다는 timeline_complete도 음악 수행 성공을 뜻하지 않는다.

### 2.3 같은 C1 안에서도 목표별 접촉 경험 차이가 크다

| C1 P3의 목표 | 포함된 종료 episode | 실제 노출된 episode | 한 번이라도 하중 접촉 후보 | 누적 clean 시간 합 |
|---|---:|---:|---:|---:|
| 중지·4번줄·6프렛, 원본 4번째 음 | 1,773 | 1,463 | **746** | 182.21초 |
| 중지·4번줄·8프렛, 원본 5번째 음 | 1,937 | 1,576 | **1** | **0초** |

줄은 사용자 기준 1부터 표기했다. 소스와 runtime의 줄 인덱스 방향이 반대여서 변환을 확인했다. 실제 노출은 원장의 exposure_time>0, 즉 [press−2초, end] 구간을 한 번이라도 거쳤다는 뜻이다. 준비 창만 잠깐 본 경우도 포함하므로 발음 시각까지 도달했다는 뜻은 아니다. 하중 접촉 후보는 패드 기하·방향·하중으로 계산한 후보이며 유효 압현 성공과 다르다. 위 두 행은 여러 구절에서의 포함·노출을 합친 것으로, 모두 같은 episode에서 실제 6→8 전환을 시도한 쌍은 아니다.

8프렛은 단순히 학습 대상으로 적게 선택된 것이 아니다. 준비 창을 거친 episode도 많지만 실제 접촉 사례가 거의 없다. 노출된 시간의 길이와 발음 창 도달 여부는 추가로 나눠야 한다. 목표 위치, 출발 상태, 같은 손가락 전환, 준비 시간 중 어느 요인이 원인인지는 아직 분리되지 않았다.

## 3. 구조에서 발견한 개선 후보

### 3.1 목표는 보여도 접근 학습 신호가 늦게 켜진다 — 첫 비교 권장

현재 목표 선택기는 압현 시작 2초 전부터 목표를 보여준다. 그러나 corrected의 접근 잠재함수에는 1−대기 gate가 곱해진다. 긴 쉼 뒤에는 gate가 압현 시작 0.45초 전까지 1이고, 이후 0.1초 동안 줄어든다. 이때 접근 잠재함수는 0이다. 선택된 첫 압현 묶음에는 별도 보호가 있지만 이후 모든 준비 구간에 적용되는 것은 아니다.

공식 C1 전곡 시계의 예시: 중지 6프렛의 press는 10.38초이고 목표는 8.38초부터 보인다. 8.90·9.00·9.50·9.93초에는 접근 배율이 0, 10.03초에는 1이다. 즉, **미리 보는 시간과 이동을 배울 수 있는 접근 신호의 시간이 다르다.** 구절의 첫 압현 묶음에는 위 보호 예외가 있으므로, 이 예시가 초반 모든 episode에 그대로 적용되거나 모든 접촉 실패를 설명하는 것은 아니다.

개선 방향은 대기 권고를 유지하면서도 준비 목표를 향한 약한 접근 신호를 더 일찍 제공하는 것이다. 이미 구현된 preparation 프로필은 배율을 1−0.90×gate로 바꿔, 대기 중에도 접근 품질의 10%를 남긴다. corrected와 이 한 조건을 먼저 비교할 수 있다. 계속 누르고 있어야 하는 이전 목표를 일찍 버리지 않는지도 함께 평가해야 한다.

현재 단계는 손목 도달을 확인한 뒤 다음 제어기를 여는 세 개의 순차 정책이 아니다. 하나의 33축 정책 안에서 목표별 준비 품질이 press 직전 0.20초 동안 접촉 품질로 부드럽게 바뀐다. 손가락별 시간은 분리돼 있지만 실제 준비 완료 여부가 이 시간 전환의 필요조건은 아니다. 별도 강제 단계기를 추가하기 전에 위 신호 지연부터 비교하는 편이 변경 범위가 작다.

### 3.2 성공 경험을 만드는 초기 상태와 난도 일정이 약하다

현재는 처음부터 35개 구절을 섞는다. 2음 9개, 3음 7개, 4음 7개, 5음 7개, 6음 5개이며, 독립 단일음 구절은 없다. 모든 구절은 동일한 물리 초기 자세에서 시작하고 악보 시각과 목표 mask만 바뀐다.

표본기는 손가락 bucket을 균형 있게 고르는 방식이다. 각 음이나 P1~P9 유형을 똑같이 학습시키는 방식은 아니다. 완료된 episode에서 목표별 선택 기회는 421~2,012회였다. 조기 종료까지 고려하면 실제 노출과 성공 경험은 더 달라진다.

또 16,384,000 전이, 현재 기준 500회가 지나면 다음 reset부터 전곡으로 바뀐다. 실제 준비·압현 능력을 확인하는 조건은 없다. 아직 어려운 목표에 접촉하지 못한 채 전체 과제로 넘어갈 수 있다.

개선은 다음 요소를 하나씩 비교한다.

1. **도달 가능성과 전환을 분리**: 같은 물리 출발 상태에서 어려운 B만 누르기와 A→B 전환을 비교한다. B 단독도 안 되면 준비·도달·접촉부터, B 단독은 되는데 전환이 안 되면 유지 중 다음 목표 준비와 해제를 점검한다.
2. **유효한 시작 상태의 혼합**: 원래 시작을 유지하되 일부 episode를 검증된 목표 근처 준비 상태에서 시작해 첫 접촉 경험을 늘린다. 관통·이미 압현 상태를 성공으로 인정하거나 episode 중 손을 이동시키지 않는다. 최종 평가는 항상 원래 C1 시작으로 한다.
3. **능력에 맞는 난도 확대**: 단일음→두 음→동시·전환 구절→전체 C1로 확대한다. 목표별 노출 수와 유지·해제 성능을 이용하고, 최대 체류 예산도 정해 쉬운 구간에 영구히 남지 않게 한다. 초기 상태 혼합과 동시에 바꾸면 원인을 분리할 수 없으므로 별도 비교한다.

참고로 DeepMimic은 후반 동작을 초반 성공에만 의존시키지 않기 위해 참조 동작의 여러 상태에서 시작한다. Reverse Curriculum은 유효한 성공 근처 상태에서 시작 범위를 확장한다. 우리에게는 그대로 쓸 참조 동작이 없으므로, 검증된 시뮬레이터 준비 상태를 먼저 확보해야 한다. 이 연구들을 근거로 현재 과제의 개선 배수를 예상할 수는 없다. [DeepMimic §6.1](https://xbpeng.github.io/projects/DeepMimic/DeepMimic_2018.pdf), [Reverse Curriculum Generation](https://arxiv.org/abs/1707.05300).

### 3.3 탐색의 크기와 실제로 지속되는 움직임이 다르다

정책은 60Hz마다 독립적인 Gaussian 탐색을 새로 뽑는다. 손가락은 절대 목표각을 요청하지만 적용 목표각에는 4rad/s 제한이 있어, 한 tick의 최대 변화는 약 3.82도다. 다음 tick에서 반대 방향을 요청하면 직전 탐색을 이어가지 못할 수 있다.

실제 최초 env0의 600제어 tick·검지~소지16축, 총 9,600표본을 보면:

- 요청 목표와 적용 목표의 차이가 0.0001rad를 넘는 표본: **77.54%**
- 요청−적용 목표 RMS 차이: **13.91도**
- 적용 목표−실제 관절 RMS 차이: **4.40도**

이는 시작 직후 한 환경의 기록이다. 최종 정책이나 모든 환경이 같은 비율로 제한된다고 일반화하지 않는다. 손가락이 전혀 움직이지 않는다는 뜻도 아니다.

실제 관절 범위를 사용한 CPU 제어식 모사에서는 std 0.35를 유지해도 탐색의 시간 상관을 바꾸면 0.5초 목표 이동 RMS가 6.2도에서 14.1도로 달라졌다. **물리 성공 실험이 아니라 명령 생성 방식의 차이를 보여주는 계산**이다.

따라서 다음 후보는 std를 더 크게 하는 것보다 **일정 시간 일관된 방향을 탐색하는 정책 분포**다. gSDE 같은 시간적으로 부드러운 탐색을 참고할 수 있다. 단순히 기존 행동을 AR 필터로 후처리하면 PPO의 확률 계산과 불일치할 수 있으므로, 결정 길이·조건부 확률·logprob를 함께 정의해야 한다. [Smooth Exploration for Robotic Reinforcement Learning](https://arxiv.org/abs/2005.05719).

목표각 속도 제한을 없애는 것은 이번 근거에서 바로 권장하지 않는다. 불규칙한 큰 명령이 실제로 전달되면 접촉과 안정성을 함께 해칠 수 있다.

### 3.4 수초의 행동 결과를 전달할 때 가치망 의존도가 높다

현재 H32는 제어 시간 0.533초다. 보상 할인 γ=0.99, GAE λ=0.98을 매 제어 tick에 적용한다.

| 결과까지 시간 | 보상 할인 계수 | GAE 전달 계수 |
|---|---:|---:|
| 0.5초 | 0.740 | 0.403 |
| 1초 | 0.547 | 0.163 |
| 2초 | 0.299 | 0.0265 |
| 4초 | 0.0896 | 0.000703 |

수집창 밖의 결과는 마지막 상태의 가치 예측으로 이어진다. 따라서 H32가 장기 목표를 보지 못한다는 말은 틀리다. 다만 가치망이 미래 결과를 구분하지 못하는 구간에서는 긴 준비·전환의 결과가 앞선 행동에 전달되는 데 시간이 걸릴 수 있다. GAE 자체도 편향과 분산 사이의 절충이다. [GAE 논문](https://arxiv.org/abs/1506.02438).

81~100회의 보상 가치 출력 표준편차 중앙값은 0.00142, 반환 목표의 표준편차는 0.252였다. 비용 쪽은 0.000162 대 0.788이었다. 초반 1~20회에는 EV가 더 높았기 때문에, 가치망이 처음부터 학습되지 않았다고 할 수 없다.

코드와 CPU 역전파에서는 가치망의 실제 입력·optimizer 연결·gradient가 확인됐다. 로그도 유효한 32,768표본 전체를 평가하고 padding을 제외한다. 단순 연결 누락이나 마지막 minibatch만 평가하는 오류는 확인되지 않았다. 입력 활성값 포화, 목표별 반환의 혼합, 학습량 부족, 확률적인 접촉 결과 중 무엇이 설명력을 낮추는지는 추가 진단 대상이다.

![시간에 따른 할인과 H32 범위](/home/ajou/yigyu/3/docs/2026-11-09/압현_v5_학습효율분석_v1/그림/시간할인과수집창.png)

비교 후보는 H32→H128 또는 PPO epoch 2→4다. H를 바꾸면 배치 크기와 정책 갱신 빈도도 달라지고, epoch를 바꾸면 같은 자료를 더 많이 재사용한다. 서로 다른 실험으로 해야 한다. 지금처럼 수집 비용이 높다면 추가 epoch의 시간 부담은 상대적으로 작을 수 있지만, KL 증가와 과적합을 확인해야 한다. 현재 구현은 이미 표본을 epoch당 한 번씩 모두 사용한다. 표본 대부분을 버리는 오류 때문에 느린 것은 아니다. [PPO 논문](https://arxiv.org/abs/1707.06347).

### 3.5 안전 비용과 음악 보상의 학습 신호도 분리해서 봐야 한다

현재 actor는 보상 advantage에서 비용 advantage×1을 뺀 뒤 전체를 정규화한다. 81~100회의 비용 advantage 표준편차는 보상 쪽의 약 3.12배였다. 그러나 이 비율만으로 비용이 정책 gradient를 지배한다고 단정할 수 없다. 행동과의 관계 및 두 advantage의 상관도 중요하다.

안전 비용을 즉시 줄이면 성공률이 오르는 대신 자세 붕괴가 다시 늘 수 있다. 먼저 목표·단계별 가치 오차, 두 신호의 상관, actor gradient 기여를 진단하는 편이 낫다. 두 advantage를 각각 정규화하는 것도 사실상 목적의 상대 가중치를 바꾸므로 단순 수치 안정화로 취급하면 안 된다.

가치 목표의 규모 차이가 학습을 방해한다는 증거가 모이면, 예측 출력을 보존하는 가치 목표 정규화를 별도 비교할 수 있다. PopArt는 이런 구분에 참고할 연구다. 지금 반환값을 임의로 잘라내거나 비용의 의미를 바꾸자는 제안은 아니다. [Learning values across many orders of magnitude](https://arxiv.org/abs/1602.07714).

### 3.6 학습의 달성 기준과 최종 연주 완성 기준이 다르다

corrected의 기존 달성은 음 길이의 40% 연속 clean을 기준으로 한다. 1.5초 음이면 0.6초다. 그 뒤에도 유지 보상은 계속 받을 수 있지만, 달성 보너스는 이미 발생한다. v5 완성 평가는 전체 음 길이의 연속 유지, 필요한 동시 압현, 해제까지 요구한다.

또 해제는 음 끝부터 0.1초 안에 하중 후보가 사라졌는지 별도 평가하지만, 명시적인 해제 보상은 없다. 대기 권고는 약한 간접 신호다. 그래서 예전의 달성률이 높아도 실제 연주 시각을 만족하지 못할 수 있다.

이미 있는 full_hold 프로필로 유지 기준 차이를 단독 비교할 수 있다. 해제 개선은 한 번도 접촉하지 못한 missed와 실제 눌렀지만 늦게 뗀 경우를 먼저 나눠야 한다. 접촉이 거의 없는 현재 초반에는 이 변경만으로 첫 성공이 빨라질 것이라고 기대하기 어렵다.

접근 보상 평균이 음수라는 이유만으로 해당 항이 잘못됐다고 판단하지도 않는다. 현재는 γ×다음 잠재함수−현재 잠재함수이며, 대기 gate·목표 mask·시각도 포함된다. 같은 자세라도 값이 바뀔 수 있고 실제 episode 끝의 다음 잠재함수는 0이다. 동일 할인율의 완전 궤적에서 이 항은 망원합된다. 이 성질과 근사 가치망에서의 학습 효과는 구분해야 한다. [Potential-based reward shaping](https://ai.stanford.edu/~ang/papers/shaping-icml99.pdf).

## 5. 다음 비교 실험의 우선순위

아래는 **미실행 제안**이다. 현재 C1을 끝까지 기준 실행으로 남기고, 고정 전곡 평가와 아래 초기 진단이 얼마나 일치하는지 먼저 확인한다.

| 순서 | 하나씩 바꿀 대상 | 비교 | 우선 확인할 값 |
|---|---|---|---|
| 1 | 준비 접근 배율 | corrected 대 preparation, 대기 중 0%→10% | 목표 노출 후 거리 감소, 첫 후보·첫 clean까지 경험량, 이전 음 조기 해제 |
| 2 | 어려운 목표의 도달과 전환 | 같은 초기 자세에서 B 단독 대 A→B | B 단독 성공 여부, A 유지 중 다음 목표 준비, 해제·재접촉 시각 |
| 3 | 초기 상태 또는 구절 난도 중 하나 | 원래 reset 대 검증된 준비 상태 일부 혼합; 난도 일정은 별도 비교 | 원래 시작의 고정 평가에서도 향상되는지, 목표별 실제 노출 |
| 4 | 경험 재사용 | epoch 2 대 4, LR·H·minibatch 고정 | 경험량당 strict 성능, 가치 EV, KL·clip 비율, 실제 소요 시간 |
| 5 | 시간 범위 | H32 대 H128, γ·λ 고정 | 긴 준비·전환 성능, 가치 오차, 갱신 빈도 영향 |
| 6 | 탐색의 지속성 | 독립 탐색 대 확률 계약이 일치하는 지속 탐색 | 실제 관절 이동·속도 제한 비율, 후보→clean 전환, 물리 실패 |
| 7 | 완성 기준 | corrected 대 full_hold; 해제 신호는 별도 | 전체 길이 유지와 해제, 기존 달성 대비 strict 완성률 |

2번은 과제 난도를 분리하는 진단이며 같은 과제에서의 알고리즘 우열 비교는 아니다. 3번은 한 번에 초기 상태·표본 균형·난도 조건을 모두 바꾸지 않는다. 4번에서 현행 공용 epoch를 바꾸면 actor와 critic 모두 갱신 횟수가 늘어난다. critic만 추가 학습하는 조건을 만들 경우 별도 조건으로 명시한다.

### 비교 예산과 공정성

- 첫 선별은 조건당 **16,384,000 전이**, 현재 1024·H32의 500회와 같은 경험량을 제안한다. 현재 처리량 단순 환산은 약 2.26시간이며 평가·준비 시간을 제외한 값이다. 명백히 악화되는 안전 지표는 중간에 확인하되, 100회에서 달성 0이라는 이유만으로 수렴 불가능을 선언하지 않는다.
- 250·500회 상당의 경험량에서 학습 곡선과 누적 비용을 비교한다. 현재 실행이 끝난 뒤 실제 저장된 250·500회 체크포인트를 입력·identity 검증을 거쳐 동일한 전체 C1 조건으로 평가하고, 후속 조건도 같은 경험량에서 평가한다. 학습 중 확률 정책의 통계와 고정 평가를 구분한다.
- **짧게 비교하려고 계획 업데이트를 500으로 줄이면 전곡 전환도 125회로 앞당겨진다.** 최초 계획 예산 65,536,000과 구절 종료 문턱 16,384,000전이를 명시적으로 같게 보존해야 한다. 학습 중단 예산과 curriculum 계획 예산을 분리하는 후속 실행 도구가 필요하다.
- 500회 예산은 구절 단계의 선별이다. 전환 경계에서 실제 episode 범위는 reset 기록으로 확인한다. 전곡 학습 결과까지 주장하려면 유망 조건을 최소 32,768,000 전이, H32의 1000회 상당으로 연장하고, 별도 seed 11·23에서도 확인한다. 최종 판단은 원래 초기 자세의 20음 평가로 한다.
- H32/1024와 H128/1024는 배치 32,768 대 131,072로, 같은 경험 예산에서 업데이트 횟수가 4배 다르다. epoch·minibatch를 유지하면 경험당 재사용 횟수는 같지만 정책 갱신 빈도는 다르다. 이를 시간 범위만의 순수 인과 효과라고 부르지 않는다. 효과가 있으면 환경 수 256/1024와 H32/H128의 추가 비교로 분리할 수 있다.
- 우수 조건의 기준은 보상 합 자체가 아니라 **같은 경험량·같은 실제 시간에서의 정시 압현·연속 유지·해제 성능**, 첫 유효 접촉까지 걸린 경험량, 물리 실패다. 보상이 달라지는 조건의 총점을 직접 순위화하지 않는다.

### 계산 효율 작업은 별도 경로로 진행

현행 실행이 끝난 뒤 고정 정책·고정 입력으로 수집 시간을 정책 추론, 제어·기하, 물리 simulate/fetch, 초기화, 진단 변환, 파일 기록으로 나눠 측정한다. CPU 기록이 유의미한 비중이면 통계의 GPU 집계와 묶음 CPU 전송부터 검토한다. 물리 substep과 접촉 판정 의미를 유지하고, 같은 입력에서 보상·종료·관절 궤적이 허용 오차 안에 일치하는지 확인한다.

GPU 메모리 여유만으로 2048·4096환경을 바로 채택하지 않는다. 짧은 동일 전이 예산으로 처리량과 수렴 영향을 별도 측정한다. Isaac Gym의 GPU 상주 구조와 대규모 병렬 제어 연구는 참고가 되지만, Python 진단·동기화가 많은 이 구현의 가속률을 대신 보장하지 않는다. [Isaac Gym](https://arxiv.org/abs/2108.10470), [Learning to Walk in Minutes](https://arxiv.org/abs/2109.11978).

## 6. 먼저 유지할 것과 추가할 진단

현재 8개 목표 슬롯은 C1에서 부족하지 않다. 공식 시계를 240Hz로 검사했을 때 손가락당 준비 창 안 목표가 최대 2개였기 때문이다. 네트워크 대형화, 목표 차원 확대, 새 강화학습 알고리즘 전체 재작성은 지금 근거에서 우선순위가 낮다.

추가 진단은 큰 관절 trace를 모든 환경에서 저장하기보다 다음을 목표·단계별 요약 통계로 남기는 편이 낫다.

| 진단 | 구분할 문제 |
|---|---|
| 선택 → 실제 노출 → 접근 활성 → 정렬 → 후보 → clean → 전길이 유지 → 해제의 수·시간 | 어느 단계에서 성공 경험이 끊기는가 |
| 요청·적용 목표 차이, 실제 관절 이동, 이동 방향의 연속성 | std는 큰데 유효 탐색 움직임은 작은가 |
| 미래 목표 노출부터 거리 감소·준비 완료까지 시간 | 준비 신호가 늦거나 이전 음 유지와 충돌하는가 |
| 목표·단계별 가치 EV·오차, 입력 활성 포화, 보상/비용 advantage 상관 | 가치망이 서로 다른 미래를 구분하는가 |
| 각 수집 구성요소의 시간과 기록량 | 경험 생성이 느린 실제 위치는 어디인가 |

이 중 목표 노출·후보·clean·관절 요청/적용 차이는 이미 일부 기록돼 있다. 기존 통계를 재사용하고, 필요한 교차 집계만 추가하는 것이 적절하다.
