## 최초 Warning — 보완 후 해소

README.md의 2.3절에 있는 “실제 노출된 episode”와 “선택·노출은 충분히 많다”는 표현은 노출 길이와 발음 창 도달을 구별해 읽어야 한다.

근거: 초반로그분석.py의 목표별 `exposed` 집계는 원장의 `exposure_time>0`이다. 동결 `guitar_learning/gpu/environment.py:1197–1207`의 exposure_time은 선택된 목표의 `[max(press-2,0),end]`와 실제 진행 구간의 겹침 시간이다. 따라서 준비 창을 한 tick만 거친 episode도 exposed 한 건이 된다. 음 시작까지 도달하거나 압현할 충분한 시간을 확보했다는 뜻은 아니다. C1에서는 슬롯 용량 초과가 없어 일반 준비 창과 슬롯 노출의 큰 충돌은 확인되지 않았으나, 최초 목표의 reset부터 추가 노출과 이 원장 창은 완전히 같지는 않다.

권고: “실제 노출”을 “2초 준비 창부터 음 끝 사이에서 exposure_time이 양수인 종료 episode”로 한 번 정의한다. “선택·노출은 충분히 많다”는 “단순 선택 빈도가 낮은 것만으로 설명되지는 않지만, 노출 길이와 발음 창 도달 여부는 추가 구분이 필요하다” 정도로 완화한다. 이 보완은 8프렛 목표의 하중 후보가 1건, clean 합이 0초라는 확인 사실을 바꾸지 않는다.

## README 보완 재확인

- README.md:64–66에서 exposure_time>0은 준비 창만 잠깐 거친 경우도 포함하며 발음 시각 도달을 뜻하지 않는다고 명시했다. “충분한 노출” 주장은 완화했고, 노출 길이·발음 창 도달 여부를 추가 구분하도록 했다. 최초 Warning이 해소됐다.
- README.md:78은 gate 예시가 전곡 시계 기준임을 명시했고, 구절 첫 압현 묶음의 보호 예외 때문에 초반 모든 episode에 그대로 적용하거나 모든 접촉 실패의 원인으로 해석할 수 없다고 보완했다. 동결 코드와 일치한다.
- README.md:188–191은 선별 예산을 실제 저장 모델과 맞는 500회 상당, 16,384,000전이로 바꿨다. 기록된 처리량 2,011.77196전이/초를 이용하면 약 2.2623시간이므로 약 2.26시간 표기가 맞다. 이는 평가·준비를 제외한 단순 환산이며 실측 완료 시간 예측으로 확정하지 않았다.
- 250·500회 저장 모델의 동일 C1 평가를 비교하고, 최초 계획을 500회로 바꾸면 전곡 문턱도 125회로 바뀐다는 교란을 명시했다. 최초 계획 65,536,000전이와 문턱 16,384,000전이를 고정해야 한다는 요구가 유지됐다.
- 500회 상당은 전환 경계이므로 실제 episode 범위는 reset 기록으로 확인한다고 보완했다. 전곡 학습 결과까지 주장하려면 별도 연장이 필요하다는 제한도 유지됐다.

## 확인한 내용

- 원본 learning_metrics.jsonl의 분석 prefix 713,343bytes와 episodes.jsonl의 분석 prefix 260,621,754bytes를 스트리밍으로 다시 해시했다. 둘 다 초반100회_분석.json의 SHA와 일치한다. 커지는 원문 전체를 고정 파일로 오인하지 않았다.
- 최초 100회는 3,276,800전이, 종료 episode 5,898개다. 첫·마지막 20회는 각각 655,360전이다. 종료 episode의 분모와 고정 평가 성공률은 분리되어 있다. 음 달성 평균은 episode 수로 가중되며, 수집·갱신 시간 비율은 합의 비율이다.
- JSON의 수집 1,594.777817초, 갱신 34.035026초, 수집 비중 97.91044%, 처리량 2,011.77196전이/초가 README 반올림 수치와 일치한다. 수집 시간을 모두 PhysX 비용으로 해석하지 않은 점도 적절하다.
- P3 source_index3/4의 선택·노출·하중 후보·clean 합이 JSON과 표에서 일치한다. runtime string index3은 사용자 기준 4번줄이다. 원본 string과 runtime string을 반대로 취급하지 않았다.
- 35개 구절의 2~6음 구성, 500회 이후 다음 reset부터 전곡 전환, 고정 물리 초기 자세와 악보 offset의 분리는 목표와보상근거.md 및 동결 코드와 일치한다. 목표 포함 횟수와 실제 수행·성공을 같은 것으로 취급하지 않았다.
- corrected의 준비 gate와 접근 잠재함수 배율, 기존 preparation 프로필의 10% floor 설명이 동결 구현과 일치한다. 손목 도달 여부가 시간 blend를 여는 필수 조건이라고 주장하지 않았다.
- 접근 항을 gamma×다음Phi−현재Phi로 설명하고 시간·mask 경계와 terminal Phi0, 완전 궤적의 망원합을 구분했다. 접근 항의 부호만으로 실제 접근·후퇴나 보상 오류를 단정하지 않았다.
- 400회로 최초 계획을 줄이면 전곡 문턱도 100회로 바뀌는 문제를 명시했다. 최초 계획 전이 예산과 실제 중단 예산을 분리해야 한다는 제안은 타당하다. 아직 그 후속 실행 도구가 구현됐다고 주장하지 않았다.
- H32→H128은 배치 크기와 같은 경험량에서의 정책 갱신 빈도도 바꾼다고 명시했다. 순수 시간 범위 효과로 단정하지 않았다. epoch 증가는 actor와 critic 모두에 적용되는 별도 조건임을 구분했다.
- 초기 trace의 600제어 tick×16축=9,600표본 및 rad→degree 반올림은 JSON과 일치한다. 단일 env0 초기 trace를 전체 환경·최종 정책 성능으로 일반화하지 않았다.
- RMS 재집계는 episode별 RMS를 제곱하고 completed_physics_samples로 가중한 후 제곱근을 취한다. 동결 episode_diagnostics.py:858–882의 원 RMS 분모와 일치한다.
- 현재 K1 계약에서는 제어 tick당 decision이 하나여서 metrics mean_reward/mean_cost를 전이 수로 가중한 현재 집계가 성립한다. 가변 hold 길이를 가진 다른 실험에 이 함수를 그대로 재사용한다면 별도 분모 검사가 필요하다.

## 검수 범위의 한계

모든 과거 연구 원문과 외부 논문을 다시 조사하지 않았다. 이번 검수는 소유한 목표·보상 원문 조사와 현재 JSON 수치, 집계 코드의 의심 지점에 집중했다. 과거 실험의 사실 확인은 별도 담당의 과거실험근거 자료를 전제로 한다. 현재 C1 최종 평가 또는 제안된 개선의 효과를 검증한 것은 아니다.
