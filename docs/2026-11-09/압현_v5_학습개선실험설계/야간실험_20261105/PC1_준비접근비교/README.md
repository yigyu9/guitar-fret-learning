# PC1 준비 접근 비교 실행

2026-11-05 08:00 KST까지, 기존 C1의 학습·평가·분석·영상과 감독 종료 뒤 B corrected와 P preparation을 새로 비교한다. 이 폴더 밖의 원래 C1/H 소스·입력·감독·진행 상태는 읽기 전용이다.

공통 C1·1024환경·H32·512업데이트·seed7·large·epochs2·minibatch4096·std0.15/0.35이며 P의 준비 접근 배율만 다르다. 계획16,777,216전이, 전곡 전환4,194,304전이,128업데이트마다 저장한다. 나머지 계약은 실제 설정 검사와 저장본의 strict 검증을 따른다.

도구는 다음 세 파일이다.

- 도구/run.py: 독립 사본 준비·봉인·기존 C1 완료 대기·시간 진입 판정·순차 학습/평가/영상 감독.
- 도구/inspect_inputs.py: 별도 CPU 프로세스에서 입력·시각·모델 SHA·정책/PPO identity·RNG/Adam·원래 노출 예산 검사.
- 도구/analyze.py: 확정 전이만 분석하고 전체20음 분모의 유지+해제·구간·보상·LR·탐색·시간 비교를 기록.

진행상황은 진행상황.json, 시작/명령/감독 로그는 작업자료/, 결과는 분석/REPORT.md·비교표.csv·그래프와 동영상/에 둔다. native 원시 출력과 모델은 작업자료/source_snapshot/study_outputs/ 안에 있다. 동영상/에는 조건당 손확대·전신 두 비디오만 둔다.

정확한 초기 후보·clean 시각과 조기 해제율은 현행 원장에 없으므로 없는 지표로 표시한다. 누적 접촉·clean으로 대체 시각을 꾸며내지 않는다. 첫 접촉·legacy40% 달성을 전체 유지·해제 완료와 구분한다.

07:00까지의 학습과08:00까지의 후처리가20% 여유를 두고 들어갈 때만 새 B/P 쌍을 시작한다. --max-wall-seconds 상한은 운영 제한이며 설정 차이로 따로 기록한다. 최종 B/P를 먼저 평가해 결과를 확보하고 공통0/128/256/384의 학습 곡선을 추가한다. 마감상 평가 일부를 못 하면 부분 완료로 보고한다.

복구는 명확한 일시 장애일 때만1회, 공통128회 경계 모델에서 수행한다. 입력 오류·비유한 값·반복 오류의 검사를 완화하지 않는다. 기존 장기 학습의 결과는 새 B 대조군으로 쓰지 않는다.

검증 후 실행 도구를 봉인하면 실행 중 파일은 편집하지 않는다. 재시작·오류 분석도 원래 로그를 보존하며 새 경로에서 수행한다. 준비/실행/성과의 상태는 진행상황.json의 실제 기록을 기준으로 판단한다.
