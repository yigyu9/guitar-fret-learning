# PC2에 전달할 야간 실행 프롬프트

현재 PC의 H 비교를 마친 뒤 2026-11-05 오전08:00 KST까지 추가 연장 실험을 진행해줘. 이 파일과 같은 폴더의 계획.md를 먼저 읽고, 현재 실행 기록을 다시 확인해 순서대로 질문 없이 진행해줘. 이 지시는 기존 실험의 조건을 바꾸는 것이 아니라 완료 후의 새 후속 작업이야.

1. 기존 H 비교를 먼저 끝내줘.

현재 H32/H64/H128 비교의 학습·15시점 평가·분석·대표 영상6개·최종 소스/공유 SHA 검증을 먼저 모두 완료해줘. 실행 중 감독·finisher·소스·자산·설계·모델·원시 로그를 바꾸거나 종료하지 마. 기존 H 진행상황.json과 완료 보고서는 후속 연구 상태로 덮어쓰지 마. 오류나 미완료가 있으면 그것을 보존하고 분석한 뒤 새 작업 가능 여부를 판단해줘.

2. 새 후속 작업의 위치를 분리해줘.

소유 경로는 docs/2026-11-09/H실험/야간연장_20261105/야. 그 안에 계획/설정·진행상황.json·검증·분석·동영상·감독 도구를 두고 공유에도 동일 위치로 전달해줘. native 실행은 기존에 검증된 PC 로컬 source_snapshot과 로컬 cache를 그대로 사용하고, native 출력만 그 사본의 study_outputs/야간연장_20261105/ 아래 새 경로로 지정해줘. 실행 중인 PC1 자료와 공유 활성 guitar_learning 코드는 수정하지 마.

3. 동일 예산으로 연장할 H를 골라줘.

H32를 기준으로 두고, H64/128 중 **최종16,777,216전이**의 원본 C1 평가에서 전체 유지+필요 해제 완료율→물리/손목 실패가 적음→clean 시간이 좋은 하나를 골라줘. 모두 동률/불명확하면 H64를 선택해줘. 중간 최고 모델의 점수로 최종 모델의 연장 대상을 고르지 마. 선택 이유와 모든 후보 수치를 기록하고 탐색적 선택이라는 한계를 밝혀줘.

출발 모델은 각 조건의 원래 J/final.pt야. checkpoint_manifest SHA와 strict reader·input·identity·clock을 통과한 뒤 --resume으로만 이어가줘. 다른 H·다른 profile·원래 PC1 C1의 모델로 대체하지 마.

4. H32→후보 H 순서로 각각8,388,608전이를 추가해줘.

H32: 원래global512에서 추가 --updates256, --checkpoint-every128, 목표global768.
H64가 후보면: 원래global256에서 추가 --updates128, --checkpoint-every64, 목표global384.
H128이 후보면: 원래global128에서 추가 --updates64, --checkpoint-every32, 목표global192.

최종 실적은 조건당25,165,824전이야. 원래 planned_transitions16,777,216·full_song_after4,194,304를 바꾸지 마. 재개에서는 --updates가 추가량임을 확인해줘. H·N1024·seed7·corrected·std·LR·PPO·보상·직접 제어·관측·목표·종료는 유지해줘. Adam·RNG·sampler·노출을 복원하지만 물리 episode는 준비 상태로 새로 reset되는 원래 계약을 기록해줘. 중단 없는 학습과 궤적이 같다고 주장하지 마.

원래 final의16,777,216평가를 기준으로 재사용하고, 추가 중간20,971,520·최종25,165,824를 full_song·원래 초기 자세·평균 정책·32환경에서 각각 평가해줘. 연장 initial.pt의 같은 global update를 원래 final과 이중 집계하지 마. 원래 모델과 새 모델은 각자의 소스·저장 계약으로 엄격하게 검사해줘.

5. 마감에 맞춰 범위를 판단해줘.

기존 후처리가 완료된 실제 시각과 최근 처리량으로 두 조건의 학습이07:00까지, 평가·분석·영상이08:00까지 들어갈지 판단해줘. 학습 예상에20% 여유를 더하고, 새 평가 속도가 없으면 후처리에 최소60분을 임시 확보한 뒤 실제 측정으로 보정해줘. 현재 속도라면 두 연장 학습 합계 약2시간15분~2시간30분이지만 보장값은 아니야.

두 조건이 안 들어가도 H32 한 조건과 후처리는 들어가면 H32만 연장해 길이 효과를 확인해줘. 이 경우 H 간 추가 예산 비교는 미완료라고 밝혀줘. 한 조건도 안 들어가면 기존 자료의 실패 구간·LR·std·목표별 접촉 분석을 보강하고 새 GPU 학습은 시작하지 마.

두 연장이 끝난 뒤에도 둘 다 들어갈 시간이 충분하면 각각8,388,608전이를 한 번 더 연장할 수 있어. 총33,554,432전이, H32global1024/H64global512/H128global256을 목표로 하고 두 조건을 같은 최종 예산에서 평가해줘. 여유가 부족하면1차 연장 결과로 마무리해줘. 새로운 seed나 보상 변경 실험은 추가하지 마.

추가 native 학습에는 --max-wall-seconds로07:00까지 남은 시간에서120초를 뺀 상한을 전달하고 settings 차이로 기록해줘. 정확한 시각의 즉시 중단은 rollout 단위 검사라 보장되지 않으므로 여유를 두고,07:00 이후 새 학습을 시작하지 마. wall_budget으로 멈추면 전체 예산 완료로 표시하지 마.08:00까지 공유와 보고를 끝내는 것을 목표로 해줘.

진행상황은 최대60초 간격으로 실제 PID·단계·global update·commit·저장 SHA·속도·ETA·오류·다음 작업을 기록하고 터미널 종료에 견디는 감독을 사용해줘. 실패는 같은 조건으로1회만 복구하되 계획.md의 저장 공통 경계와 입력/SHA 검증을 지켜줘. 원래 공통 경계 이후 tail을 버리면 성과에 포함하지 마. NaN·identity 실패·반복 오류는 중단 근거로 남겨줘. 저장공간8GiB 미만 또는 예상 출력 여유가 부족하면 추가 학습을 시작하지 마.

6. 결과를 분석하고 대표 영상을 모아줘.

분석/REPORT.md·비교표.csv에 원래16,777,216→20,971,520→25,165,824의 목표별 전체 유지+해제, P1~P9, 첫 접촉·clean·해제·물리/손목 실패, LR·KL·실제 checkpoint std·자원/시간을 비교해줘. 조기 종료한 뒤쪽 음도 전체20음 분모에 남겨줘. 준비 노출과 발음 창 도달 여부는 별도 분모로 표시하고 없는 로그는 추정치로 채우지 마.

각 H 안에서 추가 경험량으로 좋아졌는지와, 동일 추가 예산의 H 비교를 분리해 결론 내줘. 기존 평가에서 후보를 골랐고 seed7만 연장한다는 한계도 써줘. 아직 전체 유지가0이면 그 사실을 숨기지 말고 후보→clean→유지→해제 중 어디서 막혔는지 원장으로 분석해줘.

조건당 대표 손확대1개·전신1개만 새 동영상/에 두고 기존 H 영상은 보존해줘. 모델 선택 근거·SHA·렌더 입력/장면 종료/인코딩 검증과 실제 재생을 확인해줘. native 원문·중간 파일은 study_outputs 안에 두고 공유본 전달 SHA를 검사해줘.

08:00까지 완료/부분 완료/실패/시간 부족, 최종 설정·추가 전이, 보고서와 대표 영상의 정확한 경로, 다음 단독 실험 추천을 알려줘. 독립 검수는 GPU를 중복 실행하지 않는 범위에서 진행해줘.
