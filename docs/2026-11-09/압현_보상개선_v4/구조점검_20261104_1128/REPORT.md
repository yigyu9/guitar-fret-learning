# 압현 v4 보상·관측·학습 구조 점검

점검일: 2026-11-04. 사용자가 지정한 연구 분류 경로인 docs/2026-11-09 아래에 저장했다. 현재 별도 실행 경로인 compact press v4 combined를 중심으로, 상속한 v3/J 코드와 기존 v2 장기 학습 기록을 구분해 확인했다.

## 판단

**실행 연결은 정상이나, 그대로 장기 학습을 시작하기 전에 맞춰야 할 설정과 관측 문제가 있다.** 전체 신경망이나 물리를 새로 작성해야 한다는 근거는 없다. 먼저 탐색 초기값, 보상에 쓰이는 대기 맥락, 관측 예산의 정규화를 보정하고, 준비 보상과 최종 평가 기준을 독립 비교하는 것이 적절하다.

현재 소스의 관련 CPU 회귀 검사 **188개가 모두 통과**했다. 목표 인코더에서 행동 출력으로 가는 경로, 마스크, H32 경계의 에피소드 지속, 저장·엄격 복원, 보상 예산과 실패 정산에서 연결 오류를 발견하지 못했다. 별도의 CPU 재현으로 아래 정보 손실과 설정 차이를 확인했다.

이번 작업은 점검이다. 활성 학습 소스, 원문 로그, 체크포인트, 봉인 파일은 수정하지 않았고 새 GPU 학습도 실행하지 않았다. 이전 v4의 6회 갱신 결과는 작동 검사이며, 이번에 발견한 사항이 v4의 성능 실패를 일으켰다고 주장할 수는 없다.

## 실제 학습 구조

```text
상태 452개 → 상태 인코더 256 → 256
목표당 26차원 × 8슬롯 → 공통 목표 인코더 64 → 64 → 512개 특징
256 + 512 = 768개 특징 → 행동망 512 → 256 → 왼손 33축
독립적인 가치 인코더와 결합망 → 음악 보상 가치와 실패 비용 가치
행동 샘플링 → 관절 목표각과 속도 제한 → 물리 240Hz → 보상·관측
정책 60Hz, H32 자료 수집 → PPO 갱신 → 진행 중인 에피소드 계속
```

원래 합의한 상태443·목표16에 v3가 상태9·목표10을 추가했고 v4가 이를 상속한다. 골반 관측을 추가하면 상태461이다. 추가 상태는 지지 접촉 상실 시간, 남은 에피소드 시간·음 비용 예산, 동시 압현 상태다. 추가 목표는 최초 접촉·유지·달성·수행 부족의 이력과 정규화 기준이다.

행동망과 가치망의 인코더는 서로 독립이다. 두 가치 출력은 하나의 가치 인코더를 공유한다. large를 지정해도 compact 경로의 층 폭은 위 고정값이다. 현 경로는 왼손33축만 학습하고, 전달 형식의 오른손6축은0, 전신은 기존 유한 지지 제어를 쓴다. 압현·타현·전신의 세 정책을 함께 학습하는 실행은 아니다.

현재의 상태·목표 슬롯 연결이나 768→512→256→33 구조가 손가락 학습을 원천적으로 막는다는 증거는 없다. 목표당26차원 벡터를64차원 특징으로 인코딩하는 크기를 곧바로 늘리거나 손가락별 출력부로 나누는 변경은 우선순위가 낮다.

## 먼저 보정할 확인 사항

### 탐색 초기값이 이전 장기 실험과 다르다

현재 v4 최초 체크포인트는 팔·엄지·검지부터 소지까지 모두 표준편차 **0.049787**이다. 이전 7시간 v2는 팔과 엄지 **0.15**, 검지부터 소지 **0.35**였다. 각 저장본의 manifest SHA를 확인한 뒤 실제 가중치를 읽어 확인했다.

손가락의 초기 탐색은 약7.03배, 팔·엄지는 약3.01배 작다. 과거 연구 전용 실행기가 별도 초기화한 값을 신규 v4 공용 경로가 상속하지 않은 것이 원인이다. 설정의 공통 initial_std만 읽으면 과거의 실제0.35도 놓칠 수 있다.

이 차이는 보상 비교의 혼입 요인이며, 현재 v4를 그대로 장기 실행하면 사용자가 예상한0.35로 시작하지 않는다. 높은 탐색이 반드시 우월하다는 뜻은 아니다. 우선 팔·엄지와 나머지 손가락의 초기 표준편차를 명시적인 실행 설정으로 두고, 저장된 최초 모델까지 일치하는지 검사해야 한다. 보상 조건별 비교에서는 탐색을 동일하게 고정한다.

근거: [실행 감사와 체크포인트 대조](training/training_audit.md), [정량·SHA](training/audit.json).

### 정책이 모르는 정보로 대기 보상이 달라진다

구간 학습은 선택한 음 외에 손가락별 첫 후속 음을 회복 경계로 추가한다. 이 경계는 대기 보상 계산에 쓰이지만 목표 슬롯에는 들어가지 않는다. 상태 벡터에도 최종 대기 가중치가 없다.

실제 구간 선택 CPU 환경에서 중지의 tracking 목표가 비어 있는 상태를 확인했다. 현재2.90초,2.95초,3.00초에서 대기 가중치는 각각0.541,0.041,0이었다. 숨은 후속 경계만 소거하면 가중치가1로 바뀌는데 **상태452개·목표26×8·마스크가 모두 동일**했다.

이 대조는 입력에 보상 맥락이 명시되지 않는다는 확인이다. 두 상태가 실제 물리 궤적에서 모두 도달하거나 이 누락이 학습 실패의 주원인이라는 증명은 아니다. 전곡에서는 미선택 후속 경계라는 특정 문제가 없어지지만, 이전 음 종료 후 회복 이력을 모두 제공하는 것도 아니다.

보정 방향은 실제 대기 가중치4개를 상태에 포함하고, 필요하면 다음 준비 시작까지 시간4개를 함께 제공하는 것이다. 또는 구간 밖 목표를 보상 경계에만 쓰는 규칙을 바꿀 수 있다. 관측과 보상의 목표 범위가 일치하도록 한 가지 계약을 선택해야 한다.

근거: [관측 감사](observation/observation_audit.md), [동일 입력 대조](observation/results.json).

### 남은 음의 비용 예산이 입력에서 잘린다

v3가 추가한 remaining_negative_note_budget은 척도1로 나눈 뒤 전체 상태의±10 제한을 받는다. 기본67음 전곡의 초기 값은 **16.750000916**인데 정책 입력은 **10.0**이다. 실제 실패 비용은 원래 값을 사용하므로 비용 계산이10으로 줄어드는 것은 아니다.

비용 예측을 돕기 위해 넣은 정보가 큰 값에서 구분되지 않는다. 현재 곡의 최대 예산을 표현할 수 있는 고정 척도로 정규화해야 한다. 에피소드마다 다른 분모를 숨겨 쓰면 실제 비용이 다른데 같은 입력이 되는 문제가 다시 생기므로 척도를 계약에 고정한다.

근거: [예산 포화 재현](observation/results.json).

## 보상과 학습 목표에서 비교가 필요한 사항

### 미래 목표가 보여도 준비 접근 신호가 없을 수 있다

v4 timing과 combined는 접근 잠재값에 1−실제 대기 가중치를 곱한다. 대기 가중치가1이면 해당 목표의 접근 잠재값 전체가0이다. 손가락의 B 대기와 접근 보상이 충돌하지 않게 하려는 선택이지만, 팔을 미리 이동시키는 준비에도 영향을 준다.

CPU 재현에서는 음 시작1.95초 전 이미 노출된 목표의 거리를10cm에서8cm로 줄였다. baseline의 잠재값 증가는0.033809였지만 timing과 combined에서는0이었다. 즉 그 시점의 접근 개선이 즉시 점수로 구분되지 않는다. 미래 보상으로 준비를 배울 가능성까지 사라지는 것은 아니다.

일반적인 긴 간격에서 대기 보상은 다음 압현0.45초 전부터 줄고0.35초 전에0이 된다. 먼 손목 이동, 정렬, 굽힘이 필요한 경우 이보다 일찍 준비할 필요가 있다. 관측2초와 보상 활성 시간의 관계를 같은 시간축으로 확인해야 한다.

다음 비교는 동일한 탐색·입력에서 timing 단독을 baseline과 대조하는 것이 우선이다. 그다음 하나의 접근 항 안에서 대기 중 준비 영역에 대한 약한 접근 신호를 유지할지, 팔 이동과 손가락 대기를 어떻게 양립시킬지 비교한다. 중복 접근 항이나 강제 단계 잠금을 바로 추가하지 않는다.

근거: [보상 재현](reward/results.json), [보상 감사](reward/reward_audit.md).

### 보상 달성과 최종 성공의 기준이 다르다

달성 보너스는 기본적으로 음 길이40퍼센트의 연속 유지에서 지급한다. 수행 부족의 연속 유지 부분도 같은 기준을 사용한다. 반면 v3/v4 strict 성공은 음 전체와 모든 동시 구간 전체의 연속 유지 및 안전 완주를 요구한다.

가중치1인1초 음을0.4초 올바르게 누르고0.6초 누락한 계약상 예에서는 최초 접촉0.25, 유지0.40, 달성0.25, 수행 부족−0.06으로 합계 **0.84**다. 전체를 누르면 **1.50**이다. 이 합계는 접근·대기·엄지·행동 변화·실패 비용을 제외한 해당 음의 과제 항이다.

부분 수행이 최적이라는 뜻은 아니다. 이후에도 유지 보상이 늘고 누락 감점이 줄어든다. 다만 달성 음 수가 늘었다고 전체 음을 유지했다고 해석하면 안 된다. 최장 연속 유지/D, 동시 유지 비율, strict 음 성공 수를 함께 봐야 한다. 보너스와 부족률을 최종 목표에 맞출지는 이러한 지표의 정체 구간을 보고 단계적으로 비교한다.

또한 현재 strict 성공 함수는 해제 이력을 요구하지 않는다. 합성 완료 원장에서 두 음 모두 released=False여도 전체 유지·안전 완주 조건을 만족하면 strict 성공이었다. 이는 현재 full-hold 계약을 어긴 오류는 아니지만 정확한 해제까지 포함한 완전 연주 성공이라는 의미로 사용할 수 없다. 전환 실험에서는 필요한 음의 해제 시점과 이전 음의 잔류 접촉을 별도 기준으로 정하고, 같은 위치의 이어지는 음은 해제 필요 여부를 구분해야 한다.

근거: [정산과 해제 판정 재현](reward/reward_audit.md).

## 학습 시간 범위·탐색·비용

현재 H32는 환경당0.533초다. 많은 환경 수는 표본 수를 늘리지만 환경 하나의 직접 시간 범위를 늘리지는 않는다. 그 뒤 보상은 critic의 가치 예측으로 연결한다. gamma0.99에서2초 뒤 보상의 할인은0.299이고, gamma×lambda의2초 뒤 잔차 가중치는0.0265다. 실제 H32에서는 그 미래 잔차를 직접 계산하지 않고 수집 끝의 가치 예측에 의존한다.

따라서 준비 신호가 꺼진 구간과 짧은 수집 구간이 함께 있을 때 초기 준비를 배우기 어려울 가능성이 있다. H32/H128처럼 수집 길이를 따로 비교하되 총 전이 수와 PPO 갱신 횟수 차이를 보고해야 한다. gamma까지 바꾸는 비교에서는 접근 잠재함수의 gamma도 동일하게 바꿔야 한다. H32가 장기 학습을 불가능하게 한다는 뜻은 아니다.

이전 v2의 실제1427회 로그에서는 KL 재시도가 한 번 있었고,574회에 actor LR이3e-5에서7.5e-6으로 줄어 이후 유지됐다. 복구 하한은 없지만 업데이트가 완전히 멈춘 것은 아니며 손가락 탐색도0.35 부근을 유지했다. 이전 실패를 단순한 학습률·탐색 붕괴로 설명할 근거는 없다.

같은 과거 실험의 마지막100회에서는 stochastic 완결1843개 중 물리 실패304개,16.49퍼센트였다. 평균 행동을 쓰는 최종 평가의 물리 실패0과 구분해야 한다. 비용 우위의 표준편차 평균은1.1993으로 음악 보상 우위0.2179의약5.50배였다. 비용과 보상을 결합하는 정책 갱신이 안전 신호에 상대적으로 강하게 영향을 받을 가능성은 있으나, 표준편차만으로 실제 정책 gradient의 방향이나 실패 원인을 확정할 수는 없다.

현재 공용 학습기는 평가 성능으로 best 모델을 자동 선택하지 않는다. 중간 저장본의 deterministic 평가와 학습 중 stochastic 성능을 함께 기록하고, 목표별 유지·동시 유지·실패율을 기준으로 대표 모델을 선정할 필요가 있다.

근거: [PPO·실제 로그 감사](training/training_audit.md).

## 제어 연결에서 확인한 탐색의 실제 의미

탐색 표준편차는 tanh 이전 행동 분포의 값이다. 손가락은 목표각을 직접 요청하지만 한 제어 주기에 적용 목표가 이동할 수 있는 최대치는4/60rad, 약3.82도다. 요청 표준편차가7배 커져도 실제 적용 목표각의 퍼짐이 그대로7배가 되는 것은 아니다.

실제 BatchedController.targets를 이용한 CPU 진단에서 평균 행동0,8192개 표본,60회 독립 샘플을 사용했다. 발 IK는 손가락 채널에 관여하지 않아 생략했고 물리·PD·학습은 실행하지 않았다.

| --- | ---: | ---: | ---: | ---: |
| 현재 v4의0.0498 | 약2.31도 | 약1.95도 | 약1.90도 | 20.34퍼센트 |
| 과거의0.35 | 약14.70도 | 약3.35도 | 약5.80도 | 78.00퍼센트 |

각 값은 관절별 표준편차의 평균이며 물리 손가락 변위가 아니다. 이 결과는 제어가 고장 났다는 뜻이 아니라, 탐색을 평가할 때 요청 행동뿐 아니라 적용 목표각과 실제각을 함께 봐야 한다는 근거다. 속도 제한을 바로 제거하거나 움직임 비용을 추가할 근거로 쓰지 않는다.

근거: [실제 제어 함수 CPU 진단](control_probe.py), [수치](control_probe.json), [출력](control_probe.log).

## 추가 명세·입력 확인 사항

- 목표의 속도3개는 실제 기타 기준 패드 표면점 속도의 음수다. 인덱스 연결 오류는 없지만 문서에는 접근 부호용 표현임을 명시해야 한다. 최근접점 변화까지 포함한 정확한 오차 미분과도 다르다.
- 프렛을14로 나누는 것은 범위 검사와 다르다. CPU에서는15프렛 목표도 수용했다. 기본 곡은4~12프렛이므로 현재 곡의 실패 원인은 아니지만,1~14만 허용하려는 새 실험에는 입력 검사가 필요하다.
- 무효 목표 마스크는 관측 슬롯을 비우는 기능이다. 해당 손가락의 행동을 고정하거나 B 자세로 자동 복귀시키는 기능은 아니다.
- 엄지 기하 보상은 접촉 전에도 받을 수 있다. 양의 엄지 보상만으로 후면 접촉이나 실제 악기 지지가 확인되는 것은 아니다. 도달성·접촉 후보·하중을 별도로 봐야 한다.
- 기본 상태452는 골반 중력 방향과 속도9개를 포함하지 않는다. 현재 고정Root 범위에서는 곧바로 오류가 아니지만 자유Root 전환 시 옵션과 상태 계약을 다시 확인해야 한다.

## 권장 작업 순서

1. 탐색 초기화를 팔·엄지/손가락별로 명시하고 이전 비교 기준과 일치시킨다. 최초 체크포인트의 실제 std까지 검사한다.
2. 보상에 쓰이는 실제 대기 맥락을 입력에 제공하고, 남은 음 비용 예산의 clip을 없애는 정규화를 적용한다. 입력 계약을 새 버전으로 고정한다.
3. 같은 입력과 탐색에서 baseline과 timing을 비교한다. 먼 이동에서 준비 접근 신호가 없어지는 영향을 확인한 뒤 대기와 접근의 관계를 조정한다.
4. 부분 유지·전체 유지·동시 유지·필요한 해제를 분리해 평가하고, 달성 보너스와 부족률을 어느 기준에 맞출지 결정한다.
5. 이후 수집 길이, 학습률 회복, 비용 신호 균형을 각각 독립 비교한다. 신경망 확대·손가락별 출력부·새 물리 제어는 그 결과 뒤에 검토한다.

이번 점검에서 가장 먼저 고칠 대상은 보상 계수를 일괄 늘리는 것이 아니라 **실제 실행 조건과 정책에 전달되는 정보의 정합성**이다. 설계 위험의 효과는 입력과 탐색을 맞춘 실험으로 확인해야 한다.
