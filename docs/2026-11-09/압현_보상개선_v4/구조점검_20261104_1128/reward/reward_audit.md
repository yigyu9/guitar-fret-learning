# 압현 v4 보상·종료·성공 판정 구조 감사

기준일: 2026-11-04. 활성 소스, 기존 검사와 원문 결과는 변경하지 않았다. 이 폴더의 CPU 재현만 실행했다. 학습·GPU 실행 및 실제 도달성 검증은 하지 않았다.

## 판정

**실행 오류나 예산 중복 지급으로 확정할 문제는 발견하지 못했다. 다만 학습 신호와 최종 평가의 관계에서 세 가지 설계 위험이 있다.** 아래 수치는 함수 수준의 재현이며 실패 원인을 확정하는 실험이 아니다. v2 장기 학습 결과를 v4 성능으로 해석하지 않는다.

## 1. 미래 목표를 관측하지만 즉시 접근 신호는 차단되는 구간

분류: **확인된 동작 / 학습 효율의 설계 위험**. 요청한 상보 가중치대로 동작하며 구현 실수라고 판정하지 않는다.

근거:

- `guitar_learning/gpu/compact_press_v4.py:143`의 timing 조건은 첫 목표 묶음 외에는 기존 score gate를 대기에 사용한다.
- 같은 파일 `:226`은 접근 잠재값에 `1-standby_reward_gate`를 곱한다.
- `guitar_learning/gpu/finger_reward.py:47`의 준비 목표 노출은 압현 시각보다 2초 먼저 시작할 수 있다.

CPU에서는 두 목표 A/B를 만들고 현재 3.05초, B의 압현 시각 4.9초·발음 시각 5초로 설정했다. B는 정책 목표로 이미 노출되지만 대기 gate는 1이다. 실제 환경의 `_surface_potential()`을 호출하며 다른 측정은 고정하고 B의 준비 거리만 10cm에서 8cm로 변경했다.

| 조건 | B 대기 gate | 전체 잠재값의 변화 |
|---|---:|---:|
| baseline | 0 | +0.03380946 |
| timing | 1 | 0 |
| combined | 1 | 0 |

이는 **그 시점의 B 접근 개선이 즉시 접근 보상으로 구분되지 않는다**는 뜻이다. 미래 보상으로 조기 이동을 배울 가능성까지 없다는 뜻은 아니다. 특히 큰 팔 이동과 손가락 대기가 함께 필요한 경우, 손가락 대기 여부로 목표 전체의 접근 가중치를 끄는 선택이 준비 학습을 어렵게 할 수 있다. 실제 영향은 timing 단독 비교에서 확인해야 한다.

다음 비교에서는 입력·신경망·목표·전이 수를 고정하고, B의 목표 노출 시간과 접근 활성 시간을 함께 기록하는 것이 우선이다. 팔의 원거리 이동과 손가락의 B 대기를 모두 상보 관계로 묶어야 하는지는 별도 설계 질문이다. 이번 감사에서는 변경하지 않았다.

## 2. 40% 달성과 전곡 strict 성공의 간격

분류: **의도된 기준 차이 / 평가와 보상 해석의 위험**. v4에서 새로 생긴 회귀가 아니다.

근거:

- `guitar_learning/gpu/environment.py:333`: 기존 달성 기준은 `min(D,max(0.05,0.4D))`다.
- 같은 파일 `:1075`: 이 기준 최초 통과 시 달성을 latch한다.
- `guitar_learning/gpu/finger_skill_environment.py:30`: 수행 부족은 `max(missing/D,1-best_streak/required)`를 사용하며 required는 위 40% 기준이다.
- `guitar_learning/gpu/compact_press_v3.py:157`: strict 음 성공은 최장 연속 유지가 D 전체를 채워야 한다. 동시 구간 전체 및 안전 완주도 요구한다.

단일 음 D=1초, b=1, 오압현 없음이라는 계약상 예에서 실제 `performance_settlement()`로 정산했다. 접촉·유지·달성 계수는 활성 계약을 대입했다. 경계 샘플 오차나 실제 물리 궤적을 재생한 결과는 아니다.

| 올바른 연속 유지 | 누락 | 최초 접촉 | 유지 | 달성 | 수행 부족 | 합계 | strict 음 성공 |
|---|---|---:|---:|---:|---:|---:|---|
| 0초 | 1초 | 0 | 0 | 0 | -0.10 | -0.10 | 실패 |
| 0.4초 | 0.6초 | 0.25 | 0.40 | 0.25 | -0.06 | 0.84 | 실패 |
| 1초 | 0초 | 0.25 | 1.00 | 0.25 | 0 | 1.50 | 성공 |

40%에서 학습 보상이 완전히 멈추는 것은 아니다. 이후에도 유지 보상이 늘고 누락 감점은 줄어든다. 따라서 부분 압현이 전역 최적이라고 주장할 수 없다. 다만 최초 접촉·달성의 이산 보너스는 이미 받은 상태라, **평균 달성 음 수가 높아지는 것과 strict 전곡 성공으로 접근하는 것은 같은 지표가 아니다.** 67음 전체·동시 구간이 모두 완벽해야 하는 최종 이진 성공만으로 학습 진행을 보면 개선을 놓칠 수도 있다.

달성 수와 함께 목표별 최장 연속 유지/D, 동시 구간 clean 비율, strict 음·구간 성공 수를 분리해야 한다. 보상 기준을 강화할지는 이 중 어느 구간에서 학습이 정체되는지 확인한 뒤 결정하는 것이 맞다.

## 3. strict 성공은 해제 시각까지 검사하지 않는다

분류: **확인된 판정 범위 / 연주 성공 정의의 누락 위험**. 현 계약은 strict를 전체 유지로 정의하므로 계약 위반인 구현 버그라고 선언하지 않는다.

`compact_press_v3.py:157–171`은 음 전체 연속 유지, 동시 구간 전체 연속 유지, 안전 완주로 strict 성공을 만든다. `environment.py:1071`에서 따로 기록하는 해제 이력은 이 조건에 사용하지 않는다. v4도 같은 판정을 상속한다. 해제 자체의 별도 보상·감점도 현재 9항에는 없고, 이후 목표 간섭이나 대기 보상 등이 간접적으로 영향을 줄 수 있다.

CPU에서 두 목표 환경의 합성 원장을 전체 유지 완료로 설정하되 `released`를 모두 False로 두고 실제 `_episode()` 판정 함수를 호출했다.

- 해제 완료 수: **0**
- strict 음 성공 수: **2**
- strict 전체 성공: **True**

이 검사는 판정 함수가 무엇을 요구하는지만 확인한다. 실제로 해제 없이 해당 연주를 할 수 있다는 물리 실험이나 학습 성공 데이터가 아니다. 현재 성공을 **엄격한 압현 유지 성공**이라고 설명하면 정확하다. 악보의 종료 시각에서 손을 풀거나 소리를 끝내는 것까지 완전 연주 성공으로 주장하려면 별도의 해제 기준이 필요하다. 정당한 같은 줄 재타격·연속 유지·legato 등을 함께 정의해야 하므로 즉시 일괄 해제 벌점을 추가하라는 제안은 아니다.

## 4. 오류로 판단하지 않은 경로

- **접촉 반복 예산:** 최고 연속 접촉 진행률의 증가분만 지급한다. 0.01→0.03→0.05→0→0.02→0.05초 예시의 총예산은 0.25b다. 재접촉마다 0.25b를 추가하지 않는다. 재현 도구에서는 해당 계산식을 검산했으며, 기존 환경 검사가 실제 접촉 업데이트 경로를 담당한다.
- **동시 유지 예산:** v3는 원래 개별 유지에서 일부 목표만 clean인 동시 구간의 절반을 차감한다. 전원이 clean이면 기존 예산을 유지하며 별도 총예산을 더하지 않는다. `compact_press_v3.py:104`와 최종 `finger_skill_environment.py:507`의 0.5 계수를 함께 읽어야 한다.
- **수행 부족 정산:** 누락 비율은 단조 증가하고 종료 때 연속 유지 부족과 max로 정산하므로 두 감점을 독립 합산하지 않는다. 오압현과 수행 부족은 서로 다른 실패를 다루므로 동시에 발생할 수 있다. 이것을 코드상 중복 지급 오류로 분류하지 않는다.
- **PBRS 종료:** `environment.py:1253`에서 실패 또는 실제 끝일 때 nextPhi=0이다. H32 경계는 이 조건이 아니다. 시작 Phi=0.7인 서로 다른 96스텝 경로의 `Σgamma^t(gamma*Phi_next-Phi)`는 둘 다 -0.7이다. 이론 검산과 실제 호출 경로를 대조했으며, 원시 접근 보상 음수 합계로 보상 지배를 판정하면 안 된다.
- **실패 처리:** 9항 보상과 실패 cost는 별도다. 실패 cost는 기본 5+2×남은 시간+미정산 음의 남은 감점 예산이며 한 번 청구한다. 실패 tick의 양의 항은 억제하고 terminal 잠재 차분은 유지한다. 손목 일반 이탈은 초기 3초 유예, 심한 이탈은 초기에도 검사한다.
- **대기 진단:** v4는 실제 지급 gate와 legacy gate를 분리해 기록한다. 기회·품질 적분과 실패 억제를 거친 지급액은 다르며 현재 계약이 이를 구분한다.
- **엄지·이상 자세:** 엄지 보상은 접촉 전 기하 품질에도 존재하므로 양의 보상만으로 접촉 성공이라 할 수 없다. 신규 기하 자세 flag는 진단이며 압현 중 자세 비용으로 사용되지 않는다. 그 상태가 잘못됐다는 수치적 발산 증거와 구분한다.
