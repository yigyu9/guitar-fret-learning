# 단일 압현 준비·패드 추종 개선 v1

기존336조합 검사의 준비90·압현12실패를 줄이기 위한 별도 진단 도구다. 기존 봉인된 실험 소스·결과와 현재 학습 코드를 변경하지 않는다. 이 도구는 정책을 학습하지 않으며, 진단용 목표각 생성기가 작동하는지 검사한다.

## 다섯 조건을 각각 비교한다

| 조건 | 기존 방식에서 바꾸는 부분 |
| --- | --- |
| baseline | 기존 팔 운반·담당 손가락 고정 목표각 램프 유지, 계측만 추가 |
| joint_prepare | 팔12축과 담당 손가락4축을 함께 준비 정렬. 비담당 관절은 공통 자세 유지 |
| safe_route | 기존 끝 자세를 유지하고 경로의 간격 검사와 경유점 탐색만 추가 |
| robust_candidate | 같은 압현 기하 후보 중 접촉 영역·관절 한계의 여유가 큰 후보 선택 |
| pad_feedback | 기존 램프가 끝나는2.5초부터 실측 FK·3D Jacobian 기반 패드 추종 보정 |

안전 경로의 시작 계약은 별도로 명시한다. 공통 초기 자세의 양수 간격이2mm보다 작은 형상쌍은 그 간격에서 출발해 경로 진행20% 이내에 요구 여유를2mm까지 늘린다. 다른 쌍은2mm를 유지하며 초기 음수 간격은 허용하지 않는다. 이는 초기 근접 형상에 대한 정적 경로 규칙이고, native 안전 판정이나 압현 기준을 완화한 것이 아니다. 정적 검사 범위는 손·손목 대 기타이며, 손가락끼리의 충돌과 전체 몸 충돌 인증은 아니다.

조건을 섞지 않는다. 생성 입력의 문서·목표 행·실행 옵션이 일치해야 하며, 새 파일의 입력 SHA를 검증한다. baseline은 기존결과를 복사하는 것이 아니라 새로 native 실행한다.

## 구현

- `도구/build_inputs.py`: 원본 geometry JSON을 검증하고 한 조건의 새 준비 입력 생성
- `도구/geometry.py`: 공동 준비 정렬, 경로 검사, 접촉·관절 여유, 실제 자세 기반 패드 Jacobian
- `도구/native_check.py`: 실제 준비·압현·240Hz 기록과 제한된 패드 추종 실행
- `도구/test_improvements.py`: CPU 검사
- `설계/대표비교.json`: 성공 대조군과 실패 유형 대표7조합·기본seed7/17/27, 총60회 native 비교 설계

`copy_origin.json`은 독립 복사의 출처다. 과거 실험 Python을 실행 중에 import하지 않는다. 현재 패키지 공용 물리·제어·접촉 API는 그대로 사용한다.

## 새로 남기는 진단

준비에는 높이·접선거리·방향·손목속도 각각의 통과 여부와 실측/목표 손목 위치·회전·관절 추종 오차가 남는다. 준비의 무압현·안전 조건은 그대로다.

압현의 `substeps240.jsonl`에는 실제240Hz 패드 기하·방향·하중·candidate·wrong, 기타/끝마디 자세와 관절각·요청각이 남는다. `trace.jsonl`은 기존60Hz 끝점 기록이며 `report.json`은 별도의240Hz 겹침 시간 집계도 제공한다. 성공의 기준은 기존240Hz 음별 원장이다.

GPU `selected_patch_sample`은 원래 전체 패드 배열의 전역번호이고, 기하 후보 `selected_sample`은 해당 손가락의 유효 표본 부분집합 번호다. 두 번호를 직접 동일시하지 않는다. net rigid body load는 접촉 상대·현 압력·소리를 식별하지 못한다.

패드 피드백은 실제 위치와3×4 Jacobian을 사용하며 총보정±0.12rad, 보정 변화율0.5rad/s, 전체 요청속도4rad/s와native한계를 지킨다. 오압현 중에는 추가 압현을 진행하지 않는다. 무하중이고 원래 목표1.5mm 이내이며 방향이 적합할 때만 원래−0.5mm 기하 목표에서 고정0.3mm 안쪽(−0.8mm)을 시도한다. 편향은 누적하지 않으며 실제 하중 획득을 보장하지 않는다. 이미 성공한 접촉만 유지하는 제어가 아니며, 램프 이후의 늦은 접촉 획득에도 영향을 줄 수 있다. 이 진단용 보정의 성과를 정책 학습 성공으로 합산하지 않는다.

## 실행 예시

프로젝트 루트의Isaac Gym용Python을 사용한다. `RUN`은 매번 새 출력 디렉토리를 지정한다. 다른 학습이나 오류복구가GPU를 사용하는 동안 동시에 실행하지 않는다.

```bash
python docs/2026-11-09/단일압현_준비와유지개선_v1/도구/build_inputs.py \
  --case index_s3_f6 --condition joint_prepare \
  --out docs/2026-11-09/단일압현_준비와유지개선_v1/입력/index_s3_f6_joint

python scripts/tab2body.py run \
  docs/2026-11-09/단일압현_준비와유지개선_v1/도구/native_check.py \
  --geometry docs/2026-11-09/단일압현_준비와유지개선_v1/입력/index_s3_f6_joint/geometry.json \
  --case index_s3_f6 --condition joint_prepare --seed 7 \
  --out docs/2026-11-09/단일압현_준비와유지개선_v1/로그/index_s3_f6_joint_seed7
```

준비 또는 압현 실패는 전체 시작 분모에 남긴다. `safe_route_unresolved`는 CPU 경로 조건 미해결로 GPU 실행을 하지 않은 경우이며, 압현 물리 실패나 GPU 실행 완료로 계산하지 않는다. 경로 후보가 성립하지 않으면 성공 경로인 것처럼 실행하지 않는다.

## 적용 범위

현재 운영 학습에 자동 적용하지 않았다. 원래 성공 조건이나 물리·손목 종료 문턱을 낮추지 않는다. 단일음 준비의 접촉 금지 규칙을 지속 음이 있는 다중 압현·전환에 그대로 적용하지 않는다. 다음 확장에서는 현재 유지 중인 음을 우선 제약으로 두는 공유 손목 계획이 필요하다.

검증 상태는 `검증/결과.md`를 따른다. GPU 실행 전에는 실제 성공률 향상이나 장기 학습 효과를 주장하지 않는다.
