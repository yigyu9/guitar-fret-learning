# 중지 3번줄 6→8프렛: 실제 이동 분석

결론은 **평균 정책이 6프렛 압현을 해제하고 8프렛으로 옮기는 동작을 충분히 학습하지 못했다**는 것이다. 완전히 정지한 것은 아니다. 팔 탐색을 높이면 이동은 증가했지만 방향과 크기가 목표 패드 접근으로 이어지지 않았고, 새 음 구간에도 6프렛 접촉이 남았다. 같은 입력·제어·시계의 native 재생은 두 음 모두 성공했으므로 이 목표의 물리 불가능으로 해석할 근거는 없다. 아래는 기존 자료만 읽은 분석이다.

## 자료와 범위

A0의 팔 초기 std 0.049787/0.10/0.15, 각 50·100·200회 평가와 대표 렌더를 대조했다. 각 평가의 전체 16환경 성적과 env0 첫 에피소드의 실제 240Hz 손가락 원장을 구분했다. 손목·팔 이동은 대표 env0 렌더의 60Hz poses에서 직접 계산했다. native 재생은 실제 240Hz 원장과 성공 기록을 사용했다. 원문, 코드, 체크포인트를 변경하지 않았고 새 GPU 작업도 실행하지 않았다.

수치·원문 SHA는 같은 폴더의 [이동분석.json](이동분석.json)에 있다.

## 확인된 사실

### 1. B 목표와 시각은 들어왔고 대기 자세가 목표 손가락을 막지 않았다

컴파일된 목표는 중지·3번줄·6프렛 3~4.5초, 중지·3번줄·8프렛 5.5~7초다. 휴지·전환 시간은 1초다. 실제 손가락 priority 원장은 4.5초에 target_index 0에서 1로 바뀐다. 이후 전환과 B 구간 모두 목표 B의 `observation_exposed=true`가 기록되며 중지 `standby_weight=0`이다. 5.5초에는 B의 audible도 참으로 바뀐다.

이는 손가락별 선택 목표·준비 상태가 B로 바뀌었다는 증거다. 정책이 전체 미래 악보 token을 실제로 활용했다는 증거까지는 아니다. priority 원장만으로 미래 token의 정확한 최초 노출 시점을 확정하지 않았다.

### 2. 손목은 조금 움직였지만 B 패드까지 약 25mm가 남았다

다음은 대표 영상의 전환 구간 실제 손목 이동과 200회 평가 env0의 B 패드 거리다. 이동량은 구간 시작·끝 사이 순변위이며 누적 경로 길이와 다르다.

| 팔 초기 std | 전환 4.5~5.5초 손목 순변위 mm | B 5.5~7초 손목 순변위 mm | B 평균 패드 거리 mm | B 평균 패드 방향 cos | B clean / wrong 초 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 0.049787 | 4.67 | 1.40 | 25.29 | 0.240 | 0.0 / 1.5 |
| 0.10 | 8.45 | 1.81 | 25.89 | 0.235 | 0.0 / 1.5 |
| 0.15 | 9.51 | 1.69 | 25.61 | 0.239 | 0.0 / 1.5 |

전환 중 손목의 프렛 방향 Gy 이동은 각각 약 −2.52/−5.35/−6.19mm다. 팔 std를 높여도 전환 후 패드 거리는 줄지 않았다. 50·100회에서도 B 평균 패드 거리는 약 22.93~25.56mm이고 후속음 달성은 없었다. 더 오래 학습한 200회에서도 B 패드 거리는 약 25.29~25.89mm로 남았다.

원본의 독립 단음 준비 도착 snapshot A/B 손목 위치 차이는 약 45.61mm, 그중 Gy는 −45.54mm다. 이것은 서로 다른 단독 native 성공 검사에서 기록된 실제 끝점 두 개이며, A0 native 전환의 실제 손목 궤적과 동일한 자료가 아니다. 두 프렛 이동의 공간 규모를 보여주는 참고값이지 유일한 정답 손목 변위는 아니다.

### 3. 6프렛 잔류 접촉이 B 구간의 오압현으로 기록됐다

세 대표 영상은 모두 A clean 1.5초, B clean 0초, B wrong 1.5초다. B 원장의 원인 몸체는 `human/LH:middle3`이며 `own_wrong_fret`와 `own_wrong_string` 두 원인이 각각 1.5초다. 출처 프렛의 최솟값·최댓값은 모두 6이다.

따라서 B 때 중지 패드의 일부가 같은 3번줄의 6프렛에 남았고, 다른 패드 표본의 다른 줄 접촉도 조건을 만족했다. 다른 줄의 정확한 번호는 이 집계 원장에 없으므로 특정하지 않는다. 두 원인은 겹칠 수 있으므로 1.5+1.5=3초로 합산하면 안 된다. 전체 유효 오압현 시간은 1.5초다.

대표 영상에서 A의 해제 시각은 관측되지 않았다. B 패드에 대해서는 body loaded가 참이어도 geometry가 거짓이었다. 즉 몸체가 하중을 받고 있다는 사실만으로 8프렛에 닿았다고 볼 수 없다. 남은 프렛 방향 excess는 약 24.7mm다.

### 4. 요청각이 속도 제한에서 전부 막힌 현상은 아니다

B의 실제 240Hz 중지 4축 원장에서 요청각−적용각 RMS는 세 std·50/100/200회 모두 0이다. B 구간에서 손가락 요청이 rate 제한에 막혀 적용되지 않은 상태는 아니다.

대표 영상의 전환 구간 팔 요청→적용 RMS 차이는 약 0.00198/0.00367/0.00398rad다. 요청된 팔 12축의 최대 변화는 0.02725/0.05177/0.05543rad, 실제 최대 변화는 0.01871/0.03938/0.04251rad다. 팔 요청과 실제 동작 모두 변했으므로 “손가락·팔이 아예 잠겨 있다”는 설명은 맞지 않는다.

적용각−실제각 차이는 남는다. B에서 팔 12축 RMS는 약 0.0265/0.0357/0.0365rad, 중지 4축 RMS는 약 0.0182/0.0208/0.0215rad다. 유한 PD·접촉에 따른 추종 오차가 전혀 없다고 주장할 수는 없다. 다만 요청→적용의 대규모 차단이 없고 같은 제어기에서 native 재생이 성공했다는 점은 **목표에 맞는 명령의 조합을 정책이 충분히 내지 못한 문제**를 더 강하게 지지한다. 이 오차만으로 실패 원인의 기여율을 확정하지는 않는다.

팔 요청각은 저장된 39축 행동과 봉인된 비대칭 직접 목표각 변환식으로 재구성했다. 손가락 요청각은 원시 240Hz 로그를 그대로 사용했다.

### 5. 손목 안내는 두 프렛 사이의 이동을 강제하는 지점 목표가 아니다

목표 프렛은 6/8이지만 hand anchor는 검지 기준 5/7이다. A의 allowed fret range는 4~9, B는 6~11이다. 실제 손목 허용 박스의 Gy 범위는 A 약 [−18.88,101.12]mm, B 약 [−67.54,52.46]mm다. 두 박스는 약 71.34mm 겹친다.

대표 영상의 기존 Gy 위치는 두 박스 안에 남고 B 구간의 Gy/Gz는 세 조건 모두 100% 허용 범위 안이다. Gx는 약간 벗어나는 시점이 있다. B에서 Gx 최대 이탈은 팔 std 순서대로 약 1.96/0.00/0.00mm이며, 실제 원장의 손목 종료 active는 모두 거짓이고 평가 16환경 모두 손목 실패 0이다. “모든 축이 항상 박스 안”이라는 뜻과 “종료 조건에 해당하지 않음”을 구분해야 한다. 따라서 손목 안내·종료 범위를 통과하는 것만으로 8프렛 압현 위치에 도달했다고 볼 수 없다. 프렛 방향 이동은 결국 목표 패드 거리·음 수행 조건을 통해 학습해야 한다. 세 std 평가 모두 물리·손목 종료는 없었다.

### 6. 같은 과제는 현재 물리에서 실행됐다

native A0 재생은 A clean 1.5초, B clean 약 1.4125초, 두 음 모두 달성, B wrong 0초이며 `native_reference_pass=true`다. 실제 A 해제 지연은 약 20.83ms, B 최초 clean 지연은 약 83.33ms였다.

native B의 평균 패드 거리는 약 0.146mm, 방향 cos 약 0.991, geometry 비율 100%, 담당 말단 body loaded 비율 약 94.44%다. 평균 정책의 B 거리 약 25mm·geometry 실패와 차이가 크다. 같은 목표·초기 입력·시계·제어에서 성공한 물리 재생이 있으므로, 현재 평균 정책 실패를 두 프렛 목표 자체의 물리 불가능이나 1초 전환 시간의 절대적 부족으로 설명할 수 없다.

native 재생에는 손목/q105 전체 궤적이 저장되지 않았다. 따라서 실제 native 손목 이동량을 요청 waypoint나 정적 FK 결과로 대체하지 않았다. native 비교에서 실제로 확인한 것은 손가락 실제각·패드·부하·압현 원장이다.

## 미검증 가설과 다음 구분

가장 일관된 가설은 “첫 음의 압현을 유지하는 국소 정책이 생겼고, 해제→이동→재압현 전환을 정책이 충분히 찾아내지 못했다”는 것이다. 팔 std 증가는 움직임을 늘렸지만 목표 접근을 개선하지 못했다. 단순히 전역 탐색 크기만 더 올리면 해결된다고 볼 근거는 부족하다.

보상 항목 간 상대 이득, 미래 목표를 쓰는 방식, 전환 구간의 학습 노출량 중 무엇이 주원인인지는 이 이동 분석만으로 확정하지 않는다. 기존 성공 재생에서 압현각을 학습 정답으로 주입하지 않는 조건을 유지하면서, 해제와 프렛 방향 진행의 보상·관측·노출을 한 가지씩 분리해서 비교해야 한다. native 제어 추종 오차의 기여도는 동일 요청의 실제 손목/팔 궤적과 접촉 부하까지 남기는 후속 진단이 필요하다.
