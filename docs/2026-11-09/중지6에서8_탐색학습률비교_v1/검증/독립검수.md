## LR 복구·KL 안전·엄격 재개

`learning.py:427`의 ExperimentTrainer는 update 진입에서만 actor optimizer LR을 max(current,1.5e-5)로 올린 후 원본 `super().update()`를 호출한다. 복구는 원본 update snapshot을 만들기 직전에 적용된다. 따라서 실패 rollback은 복구한 update 시작 상태로 돌아가며, update 내부에 다시 floor를 강제하지 않는다. value optimizer LR은 변경하지 않는다.

KL retry 함수는 원본 DecisionPPOTrainer와 동일한 함수다. 원본의 policy/actor Adam rollback, 일시 LR 감소, retry 한도, 전체 update 실패 시 policy/actor·value optimizer/RNG/update count 복원을 유지한다. 예산 소진 KLGuardError는 다시 발생시키며 diagnostic에 복구 정보를 추가할 뿐 수용하지 않는다. 표본·우도·활성 축·분산 clamp·9보상·접촉 원장·물리 제어는 기존 코드와 같은 경로다.

독립 실행한 CPU12개 검사는 모두 통과했다. 특히 다음을 확인했다.

- existing 모드와 원본 PPO의 update 결과·policy tensor·actor/value Adam·RNG 수치 동일.
- 7.5e-6 진입 → 1.5e-5 복구 → 첫 KL 거절 후 3.75e-6 수용 가능 → 다음 update에서 1.5e-5 복구.
- KL 예산 소진 시 policy/Adam/RNG/update count rollback 및 예외 유지.
- 새 trainer/policy/resume identity, std 또는 LR 모드가 다른 저장본 거부, context의 class factory 예외 복원.
