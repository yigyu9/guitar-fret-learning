# C1 동시 압현 재생 원인 분석

원문 재생은 정상 종료했지만 동시 압현에는 실패했다. 확인된 오압현 원인은 약지 마지막 마디 `human/LH:ring3`이다. 이 몸체가 **3번 줄 7프렛**에 해당하는 조건을 만족하여 중지의 **3번 줄 6프렛**을 막는다. 약지의 지정 목표는 2번 줄 7프렛이다.

## 확인된 원시 수치

| 항목 | 중지 3번 줄 6프렛 | 약지 2번 줄 7프렛 |
|---|---:|---:|
| clean / 최장 연속 | 0 / 0초 | 1.295833 / 1.295833초 |
| 오압현 시간 | 1.304167초 | 0초 |
| 기하 조건 충족 시간 | 1.487500초 | 1.479167초 |
| 담당 말단 하중 조건 시간 | 0초 | 1.304167초 |
| 최초 접촉 완료 / 압현 달성 | 실패 / 실패 | 성공 / 성공 |

`episode.json → left_note_ledger.wrong_press_sources`에서 중지 목표의 유일한 비영 원인은 `body_names[7]=human/LH:ring3`, `other_higher`, 프렛 최솟값=최댓값=7이다. 다른 손가락과 own_wrong_fret/string 원인은 모두 0이다. 오압현과 약지 candidate의 240Hz 끝점 표본은 최초 3.145833초, 마지막 4.466667초이며 313개다. 원장 시간은 발음구간 양 끝점 적분이므로 표본 수를 단순히 나눈 값과 혼동하지 않는다.

## 정확히 어느 표면 표본인가

**원시 로그만으로 오압현 원인 표본 번호는 특정할 수 없다.** 오압현 원장은 몸체·줄·프렛·원인별 시간만 보존하고, 해당 전체 표면 표본 번호와 위치를 저장하지 않는다.

`finger_control_trace`의 약지 `sample_index=370`은 지정 목표를 위한 최근접 패드 표본이다. 오압현은 별도의 전체 손가락 표면 집합으로 계산되므로 370번이 3번 줄을 막았다고 결론 내릴 수 없다. 이 로그의 중지 지정 패드 표본은 183/242번이다. 전체 표면 집합에서 ring3는 유효 표본 68개를 가지지만, 정확한 기여 표본을 재구성할 native 몸체 궤적은 저장되지 않았다.

현재 코드에서 다른 손가락의 고프렛 방해는 원래 줄 구간 기준 최근접 줄, 횡방향 3mm 이내, 높이 절댓값 3mm 이내, 프렛 내부 2mm 여유, 몸체 하중 조건으로 판정한다. 지정 패드의 압현 평면·방향 조건과 동일한 검사가 아니다. 따라서 지정 약지 패드가 2번 줄에 적합하더라도 약지의 다른 표면은 인접 3번 줄의 높은 프렛에 해당할 수 있다.

## 오압현 외의 별도 문제

중지는 발음구간 `[3,4.5)`의 실제 240Hz 표본 360개 전부에서 `assigned_body_loaded=false`다. 기하와 방향은 약 1.4875초 충족하지만 담당 말단 하중 조건은 0초다. 따라서 약지의 방해만 제거해도 중지가 발음한다는 보장은 없다. 이것은 몸체 순하중 대용 판정이며 실제 줄의 압력·접촉 상대가 확인되었다는 뜻은 아니다.

또한 C1 참조는 2.8~3.0초에 압현각으로 이동하고 4.45~4.55초에 복귀한다. B1은 0.5~2.5초에 준비를 완료하고 4.5초까지 유지한다. C1 약지 최초 clean은 3.175초여서 시작 지연 0.175초이며, 끝나기 전 해제도 포함된다. 이 시각 차이가 있어 B1/C1 관절 오차의 전체 구간 평균을 순수한 동시 압현 영향으로 해석할 수 없다.

C1 동시 clean 비율은 0, 시각 통과 0/1이다. 약지 단독 clean도 1.5초의 90%인 1.35초에 못 미친다. 최종 해제 지연 0이라는 값은 음 끝 이후 첫 검사에서 이미 해제되었다는 뜻이며, 4.5초 이전 해제가 없었다는 인증이 아니다.

## 다음 후보에서 확인할 조건

1. 약지 지정 패드뿐 아니라 약지 전체 표면의 인접 3번 줄 고프렛 방해 조건을 검사한다. 원래 줄 구간과 실제 판정식을 사용해야 한다.
2. 중지 말단 하중과 두 목표의 clean을 같은 native 재생에서 확인한다. 기하 후보 성공만으로 동시 압현을 인증하지 않는다.
3. 준비를 음 시작 전에 끝내고 해제는 음 끝 이후로 옮기는 시각 보정을 기하 변경과 분리해서 기록한다.

원본 코드·입력·모델은 수정하지 않았고 새 GPU 실행도 하지 않았다. 재생 보고서는 `completed=true`, `failure=null`, `lifecycle_verified=true`, 입력 변경·정리 오류 없음이다. 원문 경로와 SHA256은 같은 이름 JSON에 기록했다. 분석 완료는 물리 과제 성공을 뜻하지 않는다.
