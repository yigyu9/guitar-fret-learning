# H32·H64·H128 비교

다른 PC에서 V5 C1의 경험 수집 길이 H를 비교한다. 현재 PC에서는 CPU 환경 준비와 설정 검증만 수행한다. 결과가 아직 없으며, H가 길수록 더 잘 학습한다는 결론을 전제하지 않는다.

## 비교 조건

| 조건 | 한 환경에서 수집하는 시간 | 한 PPO 업데이트의 전이 수 | 총 업데이트 | 저장 간격(업데이트) |
| --- | ---: | ---: | ---: | ---: |
| H32 | 0.533초 | 32,768 | 512 | 128 |
| H64 | 1.067초 | 65,536 | 256 | 64 |
| H128 | 2.133초 | 131,072 | 128 | 32 |

환경 수1,024, 정책60Hz·물리240Hz, 조건당16,777,216 전이, seed7이다. 세 조건은 각각 새 정책으로 시작한다. H는 에피소드 길이가 아니다. 수집이 끝나도 끝나지 않은 환경·목표 시계·원장은 이어진다.

공통: C1 원본 압현 시각, V5 `corrected`, 골반 관측 미포함, 상태464·목표26×8, Actor768→512→256→33, 독립 Critic, 팔·엄지 초기 탐색0.15/나머지 손가락0.35, Actor LR0.00003·Critic LR0.0003, PPO epoch2·minibatch4096·gamma0.99·lambda0.98, 기존 KL 제한과 보상·종료·직접 목표각 제어를 유지한다. `large`는 기록용이며 V5 폭은 고정이다. 초기 탐색값은 학습 중 고정값이 아니다.

노출 일정도 공통 경험량으로 맞춘다. 4,194,304 전이를 commit한 뒤 새로 reset되는 환경부터 전곡으로 전환한다. 초기·4,194,304·8,388,608·12,582,912·16,777,216 전이의 정책을 원본 C1 전곡으로 평가한다. 진행 중인 별도 C1 장기 학습의 노출 일정과 다르므로 그 결과를 H32 대조군으로 대체하지 않는다.

이 비교에서 H와 함께 배치 크기와 업데이트 빈도가 바뀐다. 이를 통합한 실제 실행 설정의 효율 비교이며, 순수한 시간 신용 할당 효과를 분리한 실험은 아니다. seed 하나의 결과는 1차 선별이다. 동일 초기 상태의 평가32환경을 독립 학습 seed32개로 해석하지 않는다.

## 준비된 도구

프로젝트 루트에서 Python3.8 학습 환경을 활성화한 뒤 사용한다.

```bash
python docs/2026-11-09/H실험/도구/study.py check
python docs/2026-11-09/H실험/도구/study.py commands
```

`prepare`는 최초1회 소스·자산·C1·Isaac Gym 패키지를 내부 사본으로 복사하고 봉인한다. 이미 준비된 사본은 덮어쓰지 않는다. `check`는 봉인 사본과 설계의 무결성을 검사하고, 활성 프로젝트의 변경은 별도로 보고한다. `commands`는 실제 학습·동일 경험량 평가·최종 모델 영상의 명령을 JSON argv 배열로 출력한다. 실행하지 않는다. 다른 PC 경로로 이동한 뒤에는 그 PC에서 명령을 다시 생성한다.

사본은 `작업자료/source_snapshot/`이다. 해당 디렉토리는 Git의 소스 사본 제외 규칙에 걸리므로 Git 전송만으로 전달되지 않는다. **다른 PC에는 이 연구 폴더 전체의 봉인 사본도 함께 복사해야 한다.** 소스 사본이 없고 활성 코드가 이미 달라졌다면 임의로 재봉인하지 말고 원본 사본을 전달받는다. `기준봉인.json`과 `설계.json`도 함께 보존한다. Conda 환경은 복사하지 않고 PC마다 설치한다.

다른 PC의 Linux·Python3.8·NVIDIA 드라이버·컴파일러·Torch 등은 [실행 환경 안내](../../../scripts/README.md)와 프로젝트의 `scripts/environment.rl38.yml`을 따른다. native 실행은 사본의 `scripts/tab2body.py`를 사용한다. Isaac Gym보다 먼저 Torch를 import하는 별도 실행기를 만들지 않는다. 동영상에는 ffmpeg와 렌더링 환경이 필요하다.

실행 전에 H128·1024환경으로 업데이트1회의 별도 메모리 검사를 수행한다. 그 출력은 `study_outputs/사전검사/`에 두고 본 비교에서 제외한다. 이 검사의 1회 예산에 따른 노출 일정도 본 실험과 다르다. 각 본 학습은 반드시 표의 전체 업데이트 예산을 처음부터 지정한다. 블록별로 작은 예산을 지정해 새 학습하면 노출 일정이 달라진다.

메모리 부족이면 조건별 환경 수를 다르게 하거나 무리하게 진행하지 않는다. 세 조건 모두 같은 환경 수를 쓰는 별도 설계를 먼저 확정하고 새 연구 사본에서 시작한다. 이 준비본은1024환경 기준이다.

## 저장 위치

모든 결과의 상위 디렉토리는 이 `H실험/`이다.

```text
H실험/
    README.md                     설계·실행 기준
    다른PC_실행프롬프트.md         다른 PC에 전달할 지시
    설계.json                     공통 예산과 조건
    기준봉인.json                 실행 소스·입력 SHA와 설계 SHA
    진행상황.json                 다른 PC가 갱신할 단계·시간·진척·오류
    분석/                         비교표·그래프·최종 보고서
    동영상/                       조건별 대표 손확대·전신 영상만
    검증/                         CPU 검증과 독립 검수
    도구/study.py                 준비·봉인 검사·명령 생성
    작업자료/source_snapshot/     독립 실행 소스·입력
        .runtime/cache/           PC 로컬 native 캐시
        study_outputs/
            사전검사/             메모리 검사; 성과 비교 제외
            학습/H32_seed7/attempt01/J/
            학습/H64_seed7/attempt01/J/
            학습/H128_seed7/attempt01/J/
            평가/H32_seed7/T000000000/ ...
            동영상/               렌더 원본과 검증 보고서
```

모델은 `J/initial.pt`·전이25/50/75%의주기별 checkpoint·`final.pt`를 남긴다. 정상 완료 시 조건당5개이다. 전체 진행 상태는 다른 PC가 작성하며, 체크포인트 저장 SHA와 `report.completed`·무결성·장면 정리 결과를 대조한다. 실행 완료와 압현 성공은 별개다.

실패 후에는 덮어쓰기 대신 `attempt02`를 사용한다. 검증된 같은 조건 checkpoint로 Adam·RNG·노출·sampler를 복구하며 `--updates`는 전체 목표에서 저장된 업데이트를 뺀 추가량이다. 원래 계획 예산을 재설정하지 않는다. 저장에 포함되지 않은 로그 꼬리는 성과로 합산하지 않는다. H가 다른 모델을 이어 학습하지 않는다.

## 판정과 산출물

다른 PC에서 세 조건을 같은 GPU로 순차 실행한다. 경쟁 GPU 작업을 겹치지 않고, GPU/VRAM·RAM·전이/초·수집/최적화 시간과 총 시간을 기록한다. 약2,000전이/초라면 순수 학습은 조건당 약2시간20분, 세 조건 약7시간이다. 실제 예상 종료는 사전검사와 첫 학습의 측정 속도로 갱신한다.

주 지표는 전체 길이의 올바른 유지와 필요한 해제를 만족하는 음·구간의 완료다. 첫 접촉, legacy 달성, 평균 보상만으로 성공을 선언하지 않는다. C1 P1~P9 중 단일 압현·동시 압현·같은 손가락 이동·손가락 교대·유지하며 전환 등의 차이를 분석한다. 노출되지 않은 목표와 실제 노출됐지만 실패한 목표를 구분하고 분모를 표시한다.

`learning_metrics.jsonl`의 항목별 보상, KL·clip·재시도·LR·탐색·Critic 진단도 비교한다. 누적 전이와 실제 경과 시간 두 축의 그래프를 만든다. 압축 에피소드는 사본의 `training_log_io.iter_episode_rows()`로 복원한다. raw journal은 필요한 실패 사례를 추적할 때만 읽는다.

각 H에서 사전 정의한 전체 유지·해제 완료율, 안전성, clean 시간 순으로 모델을 선택한다. 중간 저장본이 좋으면 그 모델을, 차이가 불명확하면 최종 모델을 대표로 남기고 SHA·선택 이유를 기록한다. 평가에 사용한 C1에서 고른 모델의 수치는 별도 검증셋 성과가 아니다. 대표 영상은 조건별 손확대1개·전신1개, 총6개까지만 `동영상/`에 복사하고 출처를 분석 보고서에 기록한다.
