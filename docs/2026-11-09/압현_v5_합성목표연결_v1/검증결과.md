# v5 합성 목표 연결 검증

검증일: 2026-11-04. 입력 연결의 정확성과 실제 실행·저장·재개의 작동 검증이다. 장기 학습의 수렴이나20개 목표의 물리적 달성을 판정하는 실험은 아니다.

## CPU 검사

기존 v5 환경·실행기·곡 시간축29개 검사는 모두 통과했다. [검사 로그](기존회귀검사.txt)를 보관한다.

추가로 실행한 과거 `test_song_wrist_guide` 검사는 준비 단계에서 구 실험 자료 `docs/2026-10-12/stability_adapter_2/results/free_guitar_fretting_v1/native_probe_v1/prepared.json`을 읽다가 I/O 오류가 발생했다. 해당 검사는 실행되지 않았으며 통과 수에 포함하지 않는다. [원래 오류 로그](기존회귀검사_과거fixture오류.txt)를 보존했다. 이번 C번들의 손목 track은 새 번들 검사와 GPU 실행에서 별도로 확인한다. 과거 fixture나 기존 검증 코드는 수정하지 않는다.

신규 입력8개·실행기13개, 총21개 검사를 통과했다. 기존29개와 합쳐50개다. [신규 검사 로그](신규검사.txt), [6개 목표 검사 결과](목표검사.json)를 보관한다.

- 6개 조합 모두20개 목표의 줄·프렛·손가락·압현·음 시작·해제를 원본과 대조했다.
- P1~P9 구간, P7 연속 유지, P9 별도 재압현,43.75초 원본과47.25초 정책 길이를 확인했다.
- 공식 계획에서±3.5ms 이동한 동시음10개를 각 조합의 원본 시각으로 복원했다. 타현 계획 자체는 수정하지 않았다.
- 원본18개 사본과SHA, 새 번들의 모든 파일이 학습 입력 봉인 목록에 들어가는 것을 확인했다.
- 번들을 임시 위치에 복사하고 원본 docs 경로 없이 검사했다.
- 다른 목표로 재개, 입력 변조, 원본 누락, 시계 계약이 없는 저장본, 직접 `--song` 선택을 전용 실행기가 거부한다.
- 실제 v5 설정→환경→구간 목록·손가락별 진행 상태에 같은20개 목표가 전달됨을 확인했다.
- 학습·평가·렌더 명령 전달, Isaac 선행 import, 예외 시 시간축 주입 복구를 검사했다.

독립 검수에서도 신규21개 검사를 다시 실행해 통과했다. [독립 검수 기록](독립검수.md)에 코드 검수 범위와 한계를 남겼다.

## GPU 실행

RTX4070Ti12GB, `large` 표기·고정 v5 신경망, C1 검지·중지 조합, `corrected`, H32, seed7 조건이다. [실행 명령](실행명령.txt)과 원래 출력 파일을 보관한다.

| 실행 | 환경 | 갱신 | 수집 전이 | 측정된 학습 구간 시간 | 결과 |
|---|---:|---:|---:|---:|---|
| [새 학습](GPU검증/C1_학습/report.json) | 8 | 4 | 1,024 | 26.60초 | 완료 |
| [재개](GPU검증/C1_재개/report.json) | 8 | 추가2, 누적6 | 추가512, 누적1,536 | 14.64초 | 완료 |
| [전체 목표 평가](GPU검증/C1_전체평가/report.json) | 2 | 결정적 평균 행동 | 환경당2,835tick | 전체 평가430.03초 | 두 환경 완주 |

학습·재개 시간은 각 `J/report.json.wall_s`이며 실행기 시작과 일부 입력 준비 시간을 모두 포함하는 전체 벽시계 시간이 아니다. 평가 시간은 평가 `report.json.wall_s`다. 이 짧은 실행으로 장기 학습 속도를 추정하지 않는다.

새 학습에서 구간894·전체 목표130전이를 수집했다. 재개는 전체 목표512전이를 추가했다. 최초 계획 예산1,024전이의25% 문턱256은 재개에서 변경되지 않았다. 진행 중 구간을 갱신 경계에서 끊지 않는 기존 일정을 확인했다.

종료된 에피소드 기록은 새 학습5개, 재개1개였으며 모두 `guitar_displacement`로 종료됐다. 초기 탐색에서 발생한 물리 실패이고, 표본이 적으며 아직 끝나지 않은 에피소드도 있어 이 수를 전체 환경의 장기 실패율로 해석하지 않는다. 압현 달성은 이 기록들에서0이다. 유효 압현 성능을 확인하기 위한 충분한 학습 예산은 아니었다.

입력 변경·누락된 import pin·정리 오류는 모두0이며 실행 종료 검증도 통과했다. 시작·최종 모델4개의 SHA와 크기가 manifest에 일치한다. 재개 시작 가중치는 이전 최종 가중치와 모든 텐서에서 완전히 일치했다. 최초 탐색은 팔·엄지17축0.15, 나머지 손가락16축0.35로 확인했다. [저장본 검사](학습저장본검사.json)에 근거 수치를 저장했다.

전체20개 목표의 결정적 평가2회는 모두47.25초,2,835tick을 완주했다. 물리 실패0·손목 실패0, 평균 압현 달성0/20, 전체 유지·해제·완료 성공은 모두false였다. 학습6회짜리 저장본의 실행 검사이므로 유효한 연주 정책을 얻었다는 결과가 아니다.

평가의 실제 `training_contract.task.provenance.song.schedule`에서20개 note index와 줄·프렛·손가락·원본 onset+3초를 다시 대조했다. 입력 변경·누락된 import pin·정리 오류0, 종료 검증 통과였다. [전체 수치 요약](검증요약.json)과 [학습 수치 검사](학습수치검사.json)에 기록했다. 영상 경로는 명령 전달·검증 계약을 CPU에서 검사했으며 이번 작업에서 새 영상은 렌더하지 않았다.

## 원본 보존

작업 전 기록한 기존 Python366개와 C입력18개, 총384개 파일의 SHA가 모두 동일했다. [기준 SHA](작업전_SHA.json)와 [보존 검사](원본보존검사.json)를 보관한다. 원래 v5·공용 소스·원본 입력은 유지했고, 새 실행 도구·새 검사·신규 번들과 README 안내만 추가 또는 수정했다.

신규 구현2개·검사2개와 번들66개 파일, 총70개의 [최종 SHA](신규파일_SHA.json)를 기록했다. 이70개 파일은 Git의 무시 대상이 아니다. 이번 작업에서 commit·push는 수행하지 않았다. 관련 안내 문서8개의 [로컬 링크 검사](문서링크검사.json)에서도 끊어진 링크가 없었다.

## 해석 범위

공식 타현 계획 검사 통과와 압현 원본 시각 검사는 서로 다른 사실이다. 전자는 기존 계획의 정합성을 검증하고, 후자는 검증된 음 ID와 배정을 유지하면서 동시 압현을 원래 목표 시각에 배치했는지 확인한다. 무음 입력이나 기하 접촉 판정으로 실제 음향 성공을 주장하지 않는다.
