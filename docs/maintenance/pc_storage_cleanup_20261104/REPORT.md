# PC 저장 공간 후보 정리 결과 — 2026-11-04

실행 가능한 후보를 정리해 **관측상 약3.66GiB**를 추가 확보했다. 완료 시점 주 디스크 여유는 **약45.96GiB(`df -h`:46G)**다. 관리자 인증이 필요한 약5.36GiB와 실행 중인 앱의 캐시는 보류했다.

할당량·엔진 추정 합계는 약3.70GiB이고 디스크 여유의 실제 변화는 약3.66GiB다. 다른 작업의 동시 쓰기와 측정 방식 차이를 반영해 실제 관측값을 확보량으로 보고한다. 디렉터리나 심볼릭 링크는 삭제하지 않아 구버전 경로에 빈 폴더·링크가 남을 수 있다.

## 관리자 항목의 실행 방법

[관리자 정리 실행파일](admin_cleanup.py)을 준비하고 정적 검수를 마쳤다. 기본 실행은 읽기 전용이며 `--apply`를 지정하고 관리자 인증을 해야 변경한다. **아래 작업은 아직 수행되지 않았다.** 프로젝트 루트에서 다음 명령으로 실행할 수 있다.

```bash
sudo /usr/bin/python3 -I docs/maintenance/pc_storage_cleanup_20261104/admin_cleanup.py --apply
```

실행 범위는 다음 세 항목으로 고정돼 있다.

1. `/var/cache/apt/archives/chatgpt_26.1027.51404_amd64.deb` 한 파일: 설치 버전·SHA256·파일 식별자와 APT/dpkg 잠금을 재확인한다.
2. journal: 과거 기록에1GiB 한도를 적용하며 활성 기록을 강제로 회전하거나 영구 설정을 변경하지 않는다.
3. XRDP: 모든 쓰기 파일의 추가 기록 방식(`O_APPEND`)을 관리자 권한으로 확인한 경우에만 실행한다. 최근16MiB를 `/var/log/xrdp-cleanup-20261104-tail.log`에 관리자 전용 권한으로 보존·동기화·체크섬 검증하고 원본 로그를 축소한다. 서비스 중단·재시작은 하지 않는다.

XRDP는 일반적인 copytruncate 방식처럼 복사와 축소 사이에 새로 들어오는 일부 로그가 유실될 수 있다. 쓰기 방식을 확인할 수 없거나 파일 식별자가 바뀌었거나 보존 파일이 이미 있으면 해당 단계는 보류한다. 단계별 결과와 보류 이유를 출력한다. 자동 재시도와 보존 파일 덮어쓰기는 없다. 이 실행파일은 현재 PC의 점검 결과에 맞춰져 있으며 다른 PC에 그대로 적용하는 용도가 아니다.

## 검증

- 실행된7,293개 삭제 경로는 모두 승인된 준비 목록에 포함되고 보호 경로와 겹치지 않는다.
- 삭제 경로의 잔존0, 보호 경로 누락0, 보호 경로의 식별자·현재 버전 링크 변경0.
- 준비에서231건을 제외했고 실행 직전 재검사에서 추가 생략은0이었다. 231건은 파일과 전체 캐시 경로가 섞인 제외 항목 수다.
- 프로세스의 실행파일·열린 파일·메모리 매핑을 실제 호스트에서 확인하고 삭제 후보 경로별로 재점검했다. 알려진 시스템 보조 프로세스8개는 일부 조회 제한이 있으며, 그 외 알 수 없는 접근 제한은 실행을 중단하도록 했다.
- 보호 검증은 경로의 존재·객체 식별자·현재 버전 링크 대상에 대한 확인이다. 사용 중인 앱 데이터 전체가 바이트 단위로 불변이었다고 주장하지 않는다.
- helper 문법과 변경 파일·심볼릭 링크·Docker 참조 차단 조건을 검사했다. 관리자 단계는 실제 실행하지 않았으며 XRDP 쓰기 검증은 관리자 실행 시점에 필요하다.
