# V5 기준 프로젝트 정리

2026-11-04 작업. 새 압현의 기준을 V5로 통합하고 이전 실행 구현·전용 도구·중복 안내를 제거했다. 보상 개선 실험은 이번 작업에 섞지 않았다.

## 변경 결과

| 항목 | 정리 전 | 정리 후 |
|---|---:|---:|
| 활성 Python 전체, archive 제외 | 379 | 344 |
| 그중 tests 이외 구현·보조 | 220 | 200 |
| 압현 GPU compact 구현 파일 | 4 | V5 1개 |

| compact 압현 실행기 | 4 | V5 1개 |

Python 37개를 제거하고 필요한 손목 수학·V5 정책 검사 2개를 추가했다. 제거된 Python은 구현·도구 21개와 검사 16개다. 실제 계산을 유지하는 데 필요한 공통 기능은 이관했으며, 기존 검사의 유효한 부분도 V5와 공용 검사에 합쳤다.

- GPU의 base→v3→v4→v5 상속을 단일 V5 환경으로 통합했다.
- 상태·목표 인코더와 33축 분포를 V5 정책이 직접 소유한다. 이전 FingerSkillPolicy와 16필드 목표 생성자는 제거했다.
- 공용 MLP·목표 결합을 training/policy.py로 모아 V5·타현·전신이 사용한다. 타현·전신의 구조와 수식은 바꾸지 않았다.
- 기본 train, 평가와 영상 명령을 V5 strict 실행기로 연결했다. C1~C6 입력은 원본 압현 시계를 사용하고 저장본의 목표·경로·시계를 검증한다.
- 이전 compact CLI, ablation·natural_press·song_finger_progress·short_finger_learning과 구형 왼손 접촉 비교·평가 CLI를 제거했다. legacy 학습 CLI는 기존 오른손 진단만 허용한다.
- 공통 왼손 설정·CPU 측정 API, 그래픽/영상 helper, 목표각 역변환과 손목 Jacobian 수학은 현재 소비가 있어 유지했다.

관측 464/473, 목표26×8, 상태256·목표64 인코더, 결합768, Actor512→256→33, 독립 Critic256→256과 보상·비용 출력은 유지했다. 네 가지 V5 프로필, 목표각 직접 제어, 접촉·유지·해제·종료·노출 일정도 유지했다. 일부 로그 계약의 v3/v4 명칭은 진단 식별자이며 이전 실행 구현을 남긴 것이 아니다.

활성 소스의 재생성 가능한 bytecode·pytest 캐시 263개, 3,788,152바이트를 제거했다. 실행 중 runtime·native 빌드 캐시·archive·assets와 외장 링크는 이 정리에서 제외했다. 대형 모델·영상·원시 로그를 추가 삭제해 용량을 확보한 작업은 아니다.

## 검증

- 변경 전 실행 사본과 4프로필×골반 관측 여부, 총 8조건의 CPU fixture를 대조했다. 계약·관측·보상/비용·오압현·raw 하중 후보·해제·부분 reset·정책 architecture/state_dict/출력이 정확히 일치했다. 144,609는 컨테이너와 텐서를 포함한 중첩 비교 항목 수이며 물리 표본 수가 아니다.
- 공용 함수 이동 전후 타현·전신도 같은 seed에서 architecture·state_dict·행동 출력이 정확히 일치했다.
- 관련 26개 모듈의 **CPU 회귀검사 191개 통과**. V5 학습/저장/엄격 재개, 두 루트 사이 실제 V5 모델·입력 계약 이식, C1~C6·시계·변조 거부, 타현·전신·제어·로그·손목 수학을 포함한다.
- 독립 검수의 CPU 검사 **83개 통과**, 미해결 지적 없음. 위 191개와 중복될 수 있으므로 합산하지 않는다.
- 활성 344개 Python의 구문과 내부 모듈·이름 import를 검사해 누락이 없었다.
- 대표 문서 12개의 로컬 링크 167개에 누락이 없었으며 이후 매뉴얼·보고서 링크도 다시 확인했다.
- 별도 복구 감독기의 prefix·분모·episode 참조·잠금 검사 9개 및 독립 검수를 통과했다.

이번 변경의 새 GPU 학습 smoke는 실행하지 않았다. 기존 실행 사본과의 CPU 동등성 및 공용 회귀를 확인했고 GPU 자원은 원래 C1 학습에 사용한다.

확장된 구형 CPU 시작 경로 검사에서는 기존 역사 fixture가 없는 7개 실패도 확인됐다. initial_values·과거 준비 기록·role-layout 원문을 요구하는 검사이며 이번 V5 검증을 대신하지 않는다. 자료나 판정을 임의로 대체해 통과시키지 않았다. 이 7개와 기존 다른 작업의 CSV/논문 문서 공백 문제를 프로젝트 전체 검사 통과로 표현하지 않는다.

## C1 재부팅 중단과 복구

정리 중 기존 C1의 진행 기록이 멈춘 것을 발견했다. 마지막 기록은 14:52:43 KST의 256회이며 현재 PC 부팅 시각은 14:53:10이다. 학습·감독 프로세스가 함께 사라졌고 traceback이나 정상 종료 기록은 없다. 이 정황은 PC 재부팅에 의한 중단과 일치한다.

원래 runtime·감독 도구·입력의 봉인 3,185개는 모두 일치했다. 원본 run.py/analyze.py나 attempt01의 로그·모델을 수정하지 않았다.

별도 복구 감독기를 만들고 checkpoint250의 manifest SHA·입력·identity·목표 시계·원래 노출 계획을 확인했다. 250회에서 추가 1,750회만 재개해 원래 총 2,000회·65,536,000전이를 완료하고, 기존 initial/1000/final의 32환경 평가·분석·대표 손/전신 영상 계획을 이어간다.

checkpoint에 반영되지 않은 attempt01의 251~256회는 보존하되 최종 확정 학습량에서는 제외한다. 원본 1~250회와 새 attempt02의 251~2000회만 분석한다. 원래 상태는 reboot_previous_state.json으로 보존하고 새 상태는 기존 연구의 진행상황.json에 갱신한다. 복구 후 실제 optimizer 진행을 확인했다.

복구는 원래 V5 실행 사본에서 수행한다. 정리한 활성 트리로 이전 저장본의 SHA 검사를 우회하거나 암묵 변환하지 않는다.

## 사용과 보존 범위

새 실행은 [학습 안내](../../../guitar_learning/README.md)를 따른다. C1~C6는 [목표 실행 안내](../../2026-11-09/압현_v5_합성목표연결_v1/README.md), 구현은 [코드 지도](../../../guitar_learning/docs/CODE_STRUCTURE.md)에서 읽는다.

보존한 자료는 필수 자산/CAS·초기 자세, 곡·합성 목표, 타현·전신·전처리·논문 작업, 현재/과거 모델과 고유 결과, 봉인된 실행 사본, PC2 공유·별도 보존 진단이다. 기존 archive와 역사 자료는 현행 구현에서 import하지 않는다. 날짜별 연구 원문을 새 결과처럼 고치거나 대량 삭제하지 않았다.

원래 코드·문서를 가리키는 역사 기록은 당시의 소스와 함께 읽는다. 현재 실행 안내의 링크는 검증했지만 날짜별 원문 전체를 현재 V5 설명으로 바꾼 것은 아니다.
