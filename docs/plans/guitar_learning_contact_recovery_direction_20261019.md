## 1. 평가와 초기화의 기준을 먼저 고정

- [ ] 각 실험의 검증된 소스·입력을 전용 경로에 동결해 다른 채팅의 코드 정리와 실행을 분리한다. 현재 내부화된 native/assets/score 코드와 실제 설정을 고정하고, checkpoint32를 명목 행동의 참조로 다시 확인한다. 과거 격리 실행 성공을 현행 코드의 새 성공으로 상속하지 않는다. 원본·archive를 현행 코드에서 import하지 않는다.
- [ ] checkpoint strict load 후 명시적인 평가 seed를 적용한다. 초기·최종 모델에 같은 seed 목록을 쓰고 실제 seed를 기록한다. 현재 load가 저장 RNG로 settings seed를 덮어쓰는 제약을 해소한다.
- [ ] 평가에서만 새 프로세스의 첫 에피소드와 같은 장면의 반복 reset을 따로 측정한다. 초기 관절 위치/속도·기타 위치/속도·접촉·제어기/행동 이력을 비교한다. 숨은 PhysX solver cache가 원인이라고 확정하지 않는다. 평상시 학습은 persistent 환경을 유지한다.
- [ ] 명목 결정론적 실행과 탐색을 넣은 실행을 별도 평가한다. 명목 실행도 실패하면 초기화 차이와 정책의 접촉 민감도를 먼저 분리한다. 준비시간을 늘리는 것은 상태 차이와 접촉 정착 기록을 근거로 결정한다.

개발 중에는 소수 반복으로 연결을 확인하고, 기준 모델 선택과 단계 종료 시에 고정된20개 평가 조건을 사용한다. 매 PPO 업데이트마다 무거운 native 검증을 반복하지 않는다. 과정과 성능 기준을 먼저 정하고 결과를 보고 기준을 바꾸지 않는다.

## 2. 실제 회복 성공 자료를 확보

- [ ] 기존 transition/contact_teacher.py의 측정 상태 기반 보정 기능을 재사용한다. 이미 교사 피드백이 있으므로 새 기하 제어기를 처음부터 만들지 않는다.
- [ ] 명목 성공 경로 주변에서 작은 왼손 제어 목표 편차를 유한 제어로 부여한다. 처음에는 손목/해당 손가락에 제한하고, 강도는 원 행동 범위와 짧은 native 안전 검사로 정한 뒤 고정한다. 기타 직접 힘·상태 덮어쓰기를 사용하지 않는다.
- [ ] 접촉 직전, 처음 접촉한 상태, 부분 접촉, 놓친 뒤 돌아오는 상태에서 교사가 실제로 성공하는지 확인하고 전체 관측·행동을 수집한다. 기하 IK 수렴은 후보일 뿐 성공 증거가 아니다.
- [ ] native clean 접촉·오압현/미압현·안전으로 확인한 성공 자료를 학습에 사용한다. 교사가 회복하지 못한 상태도 실패 자료로 보존한다. 현재 시점 행동을 명목 궤적의 같은 시각 행동으로 일괄 라벨링하지 않는다.
- [ ] 교사는 성공 자료 수집에만 사용하고 최종 정책 단독 평가는 교사 보정 없이 수행한다. 교사 보조 실행은 별도로 표기한다.
- [ ] 학습에 쓰지 않는 편차·seed 조건을 평가용으로 분리한다. 시연 개수와 seed·초기 상태 다양성을 구분한다.

## 3. 단음 과제를 획득 → 유지·회복 → 시간 조건으로 분리

| 단계 | 학습 목표 | 제안하는 개발 진행 기준 |
|---|---|---|
| 획득 | 현재 기타 좌표계의 목표에 접근해 올바른 접촉 확보 | 고정20조건 중18회 이상에서2초 내 획득 후0.3초 clean 유지, 물리 실패0 |

| 음악 타이밍 | 원래 음 시작·유지·해제 일정 수행 | 새로운 고정20조건 중18회 이상에서 원래0.5초 유지90%·해제90%·안전 동시 충족 |

첫 두 단계의 성공은 완화된 기술 단계의 성공이다. 원 음악 목표의 성공으로 바꾸어 보고하지 않는다. 각 단계와 남은 시간/진행 상태가 정책에 관측되어야 하며, 숨은 내부 단계에 따라 정답 행동이 달라지도록 만들지 않는다. 회복0.5초는 초기 기술 단계 기준이며 향후 음악의 짧은 전환을 만족한다는 뜻이 아니다.

보상 변경은 다음 두 가지를 작은 대조 실험으로 분리한다.

- [ ] R1: 현재 마지막0.2초에만 주는 실제 접촉 준비 보상을 획득 단계의 허용 준비 구간으로 넓힌다. 접촉 획득·지속을 측정하고 필요하면 최초 획득 보너스는 목표당 한 번만 지급한다. 거리 potential은 접근 보조로만 남기며 압현 성공 판정을 대체하지 않는다.
- [ ] R2: 실제 접촉 획득 이력이 있는 목표에만 해제 보상을 지급한다. dense release_absent와 한 번의 release_success 모두에 같은 자격을 적용해 never-contact의0.75 전체를 제한한다. 획득 이력의 초기 제안은 허용 압현 구간에서 안전한 연속50ms native clean 접촉이며, 구현·검증 시 명시적으로 고정한다. raw 접촉 부재/해제 진단은 그대로 기록하고 보상 자격만 구분한다. 이50ms는 보상 자격의 개발 제안이며 최종90% 유지 성공을 완화하지 않는다.

현재 가중치에서 아무 접촉이 없어도 해제 구간0.5초의 부재 보상0.25와 해제 성공 보너스0.5를 받을 수 있다. 이것이 학습 실패의 원인으로 입증된 것은 아니다. 실제로 수행한 기술과 보상 자격을 맞추기 위한 보완이다. 해제 구간에 실제 접촉이 남은 경우의 실패 판정은 완화하지 않는다.

## 4. 학습 구조와 비교 실험

- [ ] 새 보상/목표 계약이면 strict resume를 우회하지 않는다. 현재 초기화는 원 BC 전용이므로 checkpoint32의 PPO Actor를 바로 넣을 수 있다고 가정하지 않는다. 새 명시적 Actor migration을 작성해 입력·행동·물리·목표 대응과 원 checkpoint를 검증하고, 실제 native 재평가를 통과한 초기화만 사용한다. Critic/Adam은 새 계약에 맞게 시작한다. 원래 성공 자료와 실패 모델은 보존한다.
- [ ] 우선 회복 성공 자료로 BC를 학습하고 native에서 검증한 다음, 같은 단계에서 PPO를 짧게 수행한다. 시연 관측의 MSE만으로 성공을 판정하지 않는다.
- [ ] Actor와 Critic의 갱신 횟수를 분리한다. 현재 full-batch Actor1회는 유지해 KL 누적과 LR 고갈을 피하고, Critic 추가 갱신은 작은 별도 대조로 value fit과 실제 성공에 미치는 효과를 확인한다.
- [ ] 한 번에 보상·탐색·BC 가중·학습률을 모두 바꾸지 않는다. 자료만 보완한 기준, R1 추가, 필요할 때 R2 추가를 같은 평가 목록과 비슷한 반영 전이 예산으로 비교한다. 목적은 개별 변경의 효과를 확인하는 것이다.
- [ ] 학습 성공률·독립 평가·반복 reset 평가·결정론적/탐색 평가를 분리한다. 최초 접촉 시각, 준비 접촉 시간, 접촉 상실/회복 시간, wrong/missing, 유지율, 해제 보상 자격,240Hz 안전을 기록한다.
- [ ] 성능 기준으로 모델을 고르고 마지막 checkpoint도 별도 보존한다. BC와PPO gradient를 측정하기 전에는 BC 가중100이 원인이라고 단정하지 않는다. 탐색을 줄여 얻은 성공률만으로 회복 능력 향상을 주장하지 않는다.

## 5. 목표 B와 두 음 전환

- [ ] A에서 획득·유지·회복·원 음악 조건을 통과한 뒤 B도 같은 방식으로 개별 도달 가능성을 확인한다. 교사의 기하 후보와 실제 native 성공을 구분한다.
- [ ] A와B가 각각 성공하면 A→B의 느린 전환부터 학습하고 원래 곡의 간격으로 좁힌다. 같은 현의 높은 프렛 소유권·낮은 프렛 준비·오압현 구분은 유지한다.
- [ ] 오른손 결합과 전곡은 두 목표 전환이 안정적으로 수행된 뒤 진행한다. 현재 왼손 개선을 오른손·전곡 성공으로 설명하지 않는다.

## 유지할 조건과 작업 범위

Root만 고정,105/97/8 구분, 하체 유한 제어, 자유 기타·중력ON·스트랩OFF, 원 관절 제한·gain·속도·기타 이탈/회전·접지 안전을 유지한다. 가슴 접촉 지속은 강제하지 않는다. 기타 고정·부착·직접 보조 힘·실행 중 상태 덮어쓰기를 해법으로 사용하지 않는다.
