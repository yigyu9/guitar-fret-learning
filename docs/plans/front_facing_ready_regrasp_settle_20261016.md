# 재접촉 후 실제 손가락 정착 구간의 분리

## 관측과 가설

원 native_regrasp_v6는42초10080step 정상완료했으나, 기존37..42초1201표본에서 실제 neck–finger 양성1040개(86.59450458%)로95% 기준에 실패했다. 기타·발·목표소유권·닫힘11축·손목2cm는 기존기준을 통과했다. 원실험/판정/입력/소비코드/leaf는 불변이다.

담당자 초기 원자료 관측에서는 미접촉161개가37.000..37.666667초에 모여 있고 실제손가락의 닫힘 추종 지연이 보인다. 최종 readonly 진단으로 raw와lambda0/실제각·목표를 대조한 뒤 아래 후보를 확정한다. 이 가설은 접촉 위치 오류가 없다는 증명이나 새성공 결과가 아니다.

## 최소 후보와 사전 검증

- [ ] readonly diagnose_regrasp_contact_v1 동결 및 원자료 불변 확인.
- [ ] 원 목표·gain·cap·초기모델·G/Root/cube·모든 제어수학은 유지한다. 손가락 유지 힘을 올리거나 손목을 임의로 더 깊게 넣지 않는다.
- [ ] 새protocol3 절대일정: regrasp는 close36..37 그대로, 별도 settle37..38, 측정dwell38..43의 연속5초. 전체43초다. settle은 준비구간이며 삭제하지 않고 별도로 기록한다.
- [ ] continuous는 기존 close48..49 뒤 settle49..50, dwell50..55, 후속타현55..59. 앞의 타현16/20/24/33/37/41 및 release28..31/free31..46/approach46..48은 그대로다. 전체59초다.
- [ ] baseline/repeat/release/free_strike 시간과 동작은 원v2 그대로다. 새case의clock/step은 실제 절대시각이며 시간을 되감거나 offset으로 원성공을 만들지 않는다.
- [ ] 기존 Motion1은 close 이후 regrasp_hold에서 같은 closed 목표를 계속 유지한다. settle은 제어단계 조작이 아니라 물리적 정착을 측정에서 분리하는 명시적 준비구간이다. 새일정 wrapper/분석만 필요하다는 점을 CPU로 확인한다.
- [ ] 원42초 replay의 states/contacts 0..10080, efforts0..10079, targets0..10076 전체row exact를 새43초실행에서 비교한다. 원37..42 접촉률FAIL은 그대로 재계산·보존하며 새38..43만 별도5초로 검사한다.
- [ ] 문법/실제constructor global binding 복원/일정/경계/모든gaincap불변/분석시간창/원42prefix 조건 CPU와 독립검수·Root ACK 뒤 새입력/out에서 실제43초를 실행한다.
- [ ] 원5초 구간의 95%·동일축실제닫힘·손목2cm·지원/접지/형상/건강 기준을 완화하지 않는다. 새43 실패시59 연속실험으로 진행하지 않는다.

## 후속과 남은 과제

43초가 통과해야 새59초 전체연속시험을 진행한다. 기존58초/조건부76초 설계는 아직 미실행인 과거계획으로 보존한다. 이후 재파지후LH하중비의존을 확인할 추가완전해제15초와fresh restart1회의 정확한 새일정은59초 통과 후 새별도계획으로 정한다. 원 design_post_regrasp_release_v1은 이변경의 실제구현으로 간주하지 않는다.

관절제한 잔차의 solver진단/추가건강예산, 모든60Hz source평면 형상, RHS21파지고정, 기타몸통상대변화, 실제압현준비와비물리현marker 한계도 별도확인한다. 새PPO는 시작하지 않는다.

소유권: Root는 계획/입력보존·실행·최종기록, impl은 명시brief 이후 새일정/runtime/runner만, analysis는 요청한새분석/추가감사, reviewer는 독립검수다. 다른담당파일이나기존소비파일은 수정하지 않는다.
