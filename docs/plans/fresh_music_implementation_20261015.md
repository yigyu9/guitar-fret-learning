# 음악 조건 공동 정책 구현 계획

2026-10-15 사용자 요청: 정해진 입력·출력·작업에 맞춰 구현을 계속하고, 사용자 판단이 필요한 사항은 하나의 문서에 모은다. 기존 정책 가중치를 폐기한 결정과 새 Stage A 결과는 유지한다. 별도 답변 없이 진행 가능한 구현·검증을 수행한다.

## 구현 계약

입력은 기존 오디오 처리로 생성한 실제 song bundle의 줄·프렛·운지·타현 시각과 현재 native 물리 상태다. 정책이 raw waveform에서 모션을 직접 예측한다고 설명하지 않는다. 하나의 score clock과 현재 기타 좌표계를 사용한다. 출력은 명시된54개 관절의 목표이며, 최종 목표의 소유권과 PD 적용 경로는 하나다. root·하체 고정, 자유 기타, 내부 충돌, 스트랩 OFF 조건을 유지한다.

이번 확장은 새 `fresh_music_v1`에 구현한다. 소비된 Stage A 소스와 checkpoint·실험은 수정하지 않는다. 관측과 과제가 달라지므로 새 음악 정책을 난수 초기화하고 Stage A 가중치를 암묵적으로 이식하지 않는다. 기존 PPO 갱신 구현은 재사용할 수 있다.

B는 실제 단음의 접근·압현 후보·유지·해제, C는 시간 조건이 있는 양손 동작, D는 연속 구절을 입력으로 받는다. 실제 줄 변형·음향을 모델링하지 않는 조건에서 기하/접촉 기반 후보 판정과 실제 음향 성공을 구분한다. 네트워크 관측, 성공 판정, 보상, 종료 조건을 문서와 실행 metadata에 남긴다. 곡 전체 또는 학습 성공을 구현 완료와 혼동하지 않는다.

## native 실행에서 확인한 보완

기준 실행v1은245제어/4.0833초를 완료했으나 목표 프렛까지 약154mm여서 기존25mm 거리 보상이 사실상0이었다. 목표 프렛의 native 위치와 XML의 nut/fret1 중간 위치가 일치함을 확인했다. 환경v2는 exp(-거리/150mm)의 연속 접근 보상과 실제 누른 이력 뒤의 해제 보상으로 바꾸었으며 물리·검사는 유지했다.

v2 첫 학습은153번째 명령의 physics611에서 속도/Jacobian 검사로 중단했다. 정상152전이는 전부 제외되고 optimizer 갱신은0이다. 같은 상태에서 현재 Jacobian의 전체 COM 최대잔차는0.000779m/s로0.01m/s 기준을 통과하고, 직전 Jacobian의 최대잔차0.010419m/s만 실패했다. 항상 직전 시점을 요구하던 가정을 재검토한다.

새v3는 전체 body와 지지점에서 일관된 현재 시점 후보가 통과하면 이를 사용하고, 실패 시 정확히1스텝 전 후보 전체가 통과할 때만 호환성을 인정한다. 부위별로 서로 다른 시점을 섞어 통과시키지 않는다. 둘 다 실패하면 즉시 중단하며0.01m/s 기준·현재 Jacobian의 실제 힘 계산·native 보호 조건은 유지한다. 이 검사는 속도 표본의 시점 호환성으로 한정하고 solver 원인 규명이나 물리 안전성의 증명으로 설명하지 않는다. 원153개 명령 재생과 B/C/D 전체 에피소드 검증을 통과한 후 새 scratch 파일럿을 실행한다. 원본과 오류 결과는 보존한다.

v3의 독립±0.8 행동 스트레스는 양 후보가 실패하여 중단했다. 검사를 느슨하게 바꾸지 않고, v4에서는 난수 초기 정책의 잠재 탐색 표준편차만 exp(-3)으로 시작한다. 표준편차는 학습 가능하고 행동 권한은 유지한다. 별도 qualificationv2의 원153명령 재생(이전152개 상태 완전 일치),0행동 B/C/D,±0.2 행동 B/C/D의7개 검사가 모두 통과했고 입력 SHA 변경은0개다. 이는 해당 유한 실행의 시점 호환성 검증이며 학습 정책의 안전성이나 음악 성공을 보장하지 않는다.

qualificationv1 실행 중 진단 스크립트의 완료 판정이 바뀐 사건(조건3줄 추가·completed1줄 변경)은 원래 실패한 입력 봉인 결과와 함께 보존했다. 원문을 복원하고 변경본을 별도v2로 만들어 다시 실행했다. 사후 복원으로 이전 검사를 성공으로 바꾸지 않는다. 세부 근거는 결과의 `guard_source_change_record.json`과 `review_v3.md`에 남긴다.
