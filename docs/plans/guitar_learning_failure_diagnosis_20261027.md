# 왼손 학습 실패 원인 진단 및 개선 구현 계획

작성일: 2026-10-27
상태: 단계0~1 완료. 단계2 정산·정적 부정 사례·실제 짧은 접촉/해제 검증 완료, loaded back-facing 미확인. 단계3 seed7 두 제어 비교 실패·seed17 재현 중. 단계4 독립 변경 준비. 최종 학습 개선 완료 보고는 아니다.

## 목적과 기본 판단

최신 large/1024/H32/1478회 학습은 동일 전곡 평가에서 평균 달성 음이 1.58594→1.19531/67로 감소했다. 보상만 조절하기 전에 관절 명령 전달, 실제 압현의 도달 가능성, 판정의 타당성, 학습 과제의 난도를 차례로 분리한다.

순서는 **① 제어 진단 → ② 접촉·보상 판정 진단 → ③ 짧은 과제 학습 → ④ 보상·비용·전곡 전환 개선**이다. 앞 단계의 문제가 남으면 그 원인을 수정·재검증한 뒤 다음 단계로 간다. 현재는 누적 제어의 한계 체류와 과제 난도 전환이 유력한 가설이며 물리 엔진 오류나 특정 보상항을 원인으로 확정하지 않는다.

유지할 요구: 손가락 전체 native 가동범위, LH21 움직임 비용0, 압현을 방해하지 않는 약한 B 권고, 엄지 안내, GPU 실제 물리. 최종 학습은 자유 기타·중력 ON·스트랩 OFF·기존 Root/하체 유한 제어를 유지한다. 기타 고정은 원인을 분리하는 진단 조건으로만 사용한다. 진단 중의 보조 제어·고정·선택 과제 조건을 최종 학습 성과로 보고하지 않는다.

## 0. 기준 실행과 재현 자료 보존

### 작업

- 기준 실행은 `docs/2026-10-27/guitar_learning_large_until0900_v1/run_01/J`이다. 기존 평가·보상 그래프를 재사용하고, 같은 통계를 얻기 위한 장시간 학습·전체 로그 재처리는 반복하지 않는다.
- 코드 변경 전에 초기·최종 checkpoint의 필요한 상세 추적을 완료한다. 사전 지정 env0와 소규모 고정 환경 묶음의 첫 에피소드에서 새 진단 신호가 필요한 경우만 추가 촬영·수집한다. 초기/최종/종료실패 사례를 선택한 기준을 기록한다.
- 첫 진단 도구는 결과 디렉토리의 `support/`에 두어, 활성 패키지 Python 파일 추가만으로 이전 checkpoint의 소스 봉인이 달라지지 않도록 한다.
- 패키지 수정 전 변경 전 소스·관련 테스트·계약과 SHA manifest를 `guitar_learning/archive/20261027_before_failure_diagnosis/`에 보존한다. 실제 변경 파일과 전체 실행 소스 인덱스를 기록하고 필요한 원문을 보관한다. archive를 활성 코드에서 import하지 않는다.
- 구버전 checkpoint의 소스/정책 계약 검사를 완화하거나 신규 관측·제어 계약에 그대로 재개하지 않는다. 추가 구버전 재현이 필요하면 동일 소스·입력 계약을 만족하는 별도 재현 checkout에서 수행한다. 원래 실행·보상·checkpoint 원본은 수정하지 않는다.

### 산출물과 검증

- 결과 루트: `docs/2026-10-27/guitar_learning_failure_diagnosis_v1/`
- `baseline/`: 설정·입력 SHA·사전 지정 사례·상세 추적·영상. 같은 정책을 새 장면에서 실행한 결과가 과거 배치와 완전히 같다고 가정하지 않는다.
- 각 실행은 새 출력 디렉토리, 계약/입력 SHA, 장면 종료 결과, 실패 포함 분모를 남긴다.

## 1. 명령 → 목표각 → 실제각 진단

### 가설

현재 incremental 제어는 `target_next=clamp(target_old+action*4/60, native limits)`이며 행동0은 기존 목표각 유지다. 작은 출력 편향이 누적될 수 있고 한계에 도달한 뒤에도 같은 방향 명령을 낼 수 있다. 이것이 실제 움직임 부재의 원인인지, PD/충돌/접촉 부하에 의해 목표를 따라가지 못한 것인지 분리한다.

### 구현

- 기존 `tool/validation/hand_contact_probe.py`, `gpu/control.py`의 두 제어 모드, 관절별 기존 진단을 재사용한다. 공용 기능만 필요할 때 추출하고 같은 시뮬레이터/제어기를 새로 작성하지 않는다.
- LH21을 관절 이름으로 지정한다. 엄지5축, 나머지 손가락16축을 관절별로 검사하고 마지막에는 손가락별 동시 굽힘·펴짐을 검사한다. 부호를 해부학적 굽힘이라고 미리 가정하지 않고 실제 native 축과 영상으로 대응시킨다.
- 정책 없이 ①0 유지 ②작은 양/음 명령 ③방향 반전 ④0 유지 ⑤B 목표로 유한 속도 이동·유지 프로토콜을 수행한다. B는 검지~소지에만 적용하고 엄지에는 별도 넥 후면 목표를 사용한다.
- 먼저 접촉이 없는 구간에서 단일 관절을 검사하고, 이어 넥 근처·손가락 간 충돌이 있는 상태에서 검사한다. 몸을 순간 이동시켜 접촉 상태를 만들지 않는다. 필요한 진단 자세는 에피소드 초기화 후 기존 유한 제어로 접근한다.
- 누적 제어와 이미 구현된 position 제어를 비교한다. 동일 행동값을 넣으면 목표각 의미가 다르므로, **같은 물리적 목표각 궤적을 요청하는 비교**와 **작은 지속 출력 편향에 대한 비교**를 구분한다. position의0 기준은035/v14 준비 자세이며 B가 아님을 명시한다.

### 기록

- 60Hz: 정책 평균/표본 행동(정책 실행 시), 클램프 전 요청, 클램프 후 목표각, 실제각·속도, 목표-실제 오차, native 상·하한, 바깥 방향 명령, 반전 지연.
- 240Hz: 실제각/속도 극값, 가능한 제어 effort·상한 체류, 손가락/넥 근접·접촉 후보. 몸체 순힘을 접촉 상대나 실제 압력으로 해석하지 않는다.
- 기존 한계 점유에 더해 **한계에서 연속 체류한 길이**와 **동일 방향 출력 누적량**을 남긴다. 초기 준비·압현·유지·본인 idle을 구분한다.
- 손가락별 명령/목표/실제각 겹침 그래프, B 각도 오차, 손 확대·전신 영상. 본격 실험은 원시 전체 시계열 대신 요약+사전 지정 소수 환경만 상세 저장한다.

### 판정과 분기

- 코드 차원 필수: 명명/부호/배치 대응 정확, 4rad/s 목표 속도 상한 준수, native 범위 준수, 반전 요청 시 다음 정책 tick부터 목표가 안쪽으로 이동, 부분 reset이 다른 환경에 영향0.
- 무접촉·한계에서 떨어진 명령에 대한 실제각 추종은 정착 뒤 오차 p95≤10°를 우선 진단 기준으로 사용한다. 이를 만족하지 못하면 PD·축 대응·effort 상한·충돌/관성부터 조사한다. 접촉 부하 조건에는 같은 오차 기준을 기계적으로 적용하지 않는다.
- B는 완전 도달 가능한지 먼저 확인한다. 무접촉 유지 마지막0.5초에 손가락별 RMS≤10°·최대오차≤20°를 진단 목표로 두되, 실패를 숨기기 위해 B나 한계를 즉시 바꾸지 않는다.
- 목표는 움직이는데 실제각이 안 움직임 → 구동/접촉 문제를 우선 수정한다.
- 목표·실제각이 함께 한계에 머무르고 바깥 명령 지속 → 누적 편향/정책 출력 문제를 우선 검증한다.
- position에서만 개선 → 누적 제어가 기여한 증거지만, 같은 짧은 학습 과제 비교 전 기본 제어를 교체하지 않는다.

## 2. 도달 가능성과 접촉·보상 판정 진단

### 가설

기하·손가락 배정·부하 gate·방향 조건 때문에 가능한 압현이 실패 처리되거나, 불필요한 접촉이 성공 처리될 수 있다. 보상 수식 단위검사가 통과해도 실제 물리의 대표 자세에서 판정이 맞는지는 별도 문제다.

### 구현

- 현재 곡의 실제 목표에서 손가락별 최대6개(줄·프렛 범위를 분산, 가능한 경우 총24개)를 먼저 선정한다. 선정 목표와 제외 사유는 실행 전에 저장한다. 성공하는 쉬운 음만 사후 선택하지 않는다.
- `GpuScene(diagnostic_guitar_mode='fixed'/'free')`의 기존 기능을 재사용한다. 동일한 초기·목표에서 기타 고정/자유 조건을 분리하며 다른 충돌·재질·solver·손가락 판정은 유지한다.
- 유한 관절 제어로 접근→접촉→유지→해제하는 목표 궤적을 만든다. 기존035/v14 초기 상태에서 출발하고, 필요하면 팔/손목도 유한 제어로 이동한다. 도달 실패와 판정 실패를 구분한다. 정답 자세를 관절 상태에 매 tick 덮어써 성공을 만들지 않는다.
- 합성 기하 단위검사와 실제 GPU 물리 검사를 분리한다. 합성 positive가 통과했다고 실제로 그 자세를 만들 수 있다고 보고하지 않는다.
- 부정 사례: 목표에서 떨어짐, 잘못된 줄/프렛, 잘못된 손가락만 접촉, 타 손가락 높은 프렛 간섭, 잘못된 표면/방향, 짧은 접촉, 접촉 해제. 부정 사례도 물리 도달 여부를 기록한다.
- 각 사례에서 거리→패드 방향→cell/줄/프렛→부하→candidate→clean→연속시간→보상지급의 실패 gate를 한 줄 타임라인으로 표시한다.

### 검증

- 접촉 보상은 최대0.25b·반복 지급 없음, 유지 최대1b, 달성0.25b 한 번, 오압현 최대−0.15b, 부족 최대−0.10b 및 중복 정산 없음을 실제 계수 적용 후 검산한다.
- PBRS는 할인 가중 합의 telescoping 관계와 종료 Φ=0 정산을 검증한다. 원시 비할인 누적값을 접근 품질 지표로 사용하지 않는다.
- 임계값 충분히 안/밖에 있는 합성 사례는 기대 분류100% 일치를 요구한다. 경계값은 별도 수치 허용오차 테스트로 다룬다.
- 실제 물리에서는 각 손가락에 최소1개의 재현 가능한 positive 유지 사례와 대응 negative 사례를 확보한다. 연속 clean 기준 달성뿐 아니라 해당 음 전체의 clean 비율을 기록한다.
- 물리적으로 도달하지 못하면 해당 목표는 미해결이며 판정 통과로 처리하지 않는다. 한 손가락이라도 재현 가능한 positive가 없으면 그 손가락의 RL 장기 학습을 시작하지 않는다.
- 판정/좌표/할당 오류를 발견하면 그 부분만 수정한다. 성공을 만들기 위해 거리·부하 문턱을 일괄 완화하지 않는다. 실제 현 압력·음향 인증이라고 표현하지 않는다.

## 3. 짧은 과제에서 실제 학습 가능성 검증

### 목적

정책이 ‘손가락 굽힘→목표 접촉→깨끗한 유지→해제’를 배울 수 있는지 확인한다. 이 단계는 최종 곡 단위 학습을 단음 학습으로 바꾸자는 의미가 아니라 원인을 분리하는 시험이다.

### 과제 순서

1. 기타 고정·손가락별1목표·다른 손가락 B 권고: 단계2에서 도달 가능성을 확인한 목표만 사용한다. 팔/손목은 검증한 기준을 기존 유한 제어로 유지한다. support를 무작정 행동0으로 고정해 목표가 닿지 않는 실험을 만들지 않는다.
2. 기타 고정·같은 손가락의 접근/유지/해제 반복, 이후2~4음 전환. 성공 이후 손가락을 해제하지 않는 해법도 검출한다.
3. 같은 짧은 악구에서 기타 자유·팔/손목 공동 제어로 복구한다. 고정 기타의 보조 조건과 자유 기타 성능을 구분한다.

### 비교 설계

- 첫 비교는 incremental 대 기존 position이다. 보상·음 계획·관절 범위·물리·PPO는 같게 두고 제어 방식만 비교한다. 특정 모드가 단계1에서 부적합하면 먼저 원인을 해결한 뒤 학습 비교한다.
- large·128환경·H32를 시작안으로 하고, 한 조건당300회(1,228,800전이)를 1차 예산으로 사용한다. seed7/17로 선별 후 seed27에서 확인한다. 과제별 예산과 중간 평가 간격50회는 시작 전에 고정한다. 속도 측정 없이 완료 시간을 약속하지 않는다.
- 행동0/스크립트 정책·학습 전 무작위 모델을 분리해 기준선을 둔다. 임의의 초기 정책이 우연히 압현하는 점수를 학습 성과로 세지 않는다.
- 제어 모드 간 초기 탐색은 같은 행동 표준편차만 복사하지 않는다. 목표각 변동·실제각 움직임을 함께 기록하고 물리적 탐색 크기를 가능한 한 맞춘다. 정책 구조·다른 학습 설정은 유지한다.
- 새 과제/제어 계약은 fresh 모델로 비교한다. 이후 단계로 actor를 이전할 때는 명시적 transfer로 기록하며 optimizer/critic/성과를 자동 상속하지 않는다.

### 통과 목표(실험 전에 고정)

- 고정 평가에서 손가락별 압현 달성률≥80%, 목표별 평균 clean 유지 비율≥70%, audible 오압현 비율≤10%, 물리 실패율≤5%를 연속2회 평가에서 확인한다. 실패를 분모에서 빼지 않는다.
- 해제는 실제 pad 이격·candidate 종료·유지 보상 중단으로 확인한다. B는 권고 상태로 별도 점유율을 보고하고 단기 압현 성공의 필수조건으로 삼지 않는다.
- 목표/실제각이 계속 한계에 고정된 채 팔 이동만으로 성공하는지, 관절 변형과 support 상대운동 분해를 함께 확인한다. 손가락을 많이 움직이는 것 자체에는 새 보상을 주지 않는다.
- 위 수치는 채택용 공학 기준이며 사전 입증된 성능이 아니다. 미달이면 예산만 늘리거나 기준을 낮추지 않고 학습곡선·gate·명령 추적을 근거로 원인을 재분류한다.

## 4. 보상·비용·전곡 전환 개선

단계1~3 결과에 따라 필요한 변경만 수행한다. 아래 후보를 동시에 적용하지 않는다.

### 4-A. 성공 지표와 보상 목적 정렬

- 가중 보상과 무가중 원곡 달성 수를 나란히 기록한다. 손가락 균형계수 때문에 보상이 증가하고 달성 수는 감소한 현상을 분리한다.
- 같은 성공/오압현 궤적에 대한 기대 점수표를 만든다. 순수 clean, 짧은 접촉 반복, 다른 손가락 오압현 동반, 무행동, 초기 접촉 후 한계 고정이 어떤 순서로 평가되는지 확인한다.
- 동일 목표의 clean 성공이 명확히 나쁜 수행보다 낮게 평가되는 재현 사례가 있을 때 계수/정산을 수정한다. PBRS의 큰 음수 누적값만으로 항목을 제거하지 않는다.

### 4-B. 보상 시간척도와 실패 비용

- 60Hz의 gamma=.99는5초 후 가중치 약.049이고 비용 gamma=1이다. 이 비대칭을 명시한다. H32는0.533초 수집 경계이며 bootstrap이 있으므로 ‘그 이후 보상을 전혀 보지 못한다’고 해석하지 않는다.
- 먼저 시간척도만 비교한다. 후보는 물리시간 τ=30초에 대응하는 `gamma=exp(-1/(60*30))≈.9994446`; 접근 PBRS gamma도 동일하게 맞추고 계약·검사를 갱신한다. 비용 계수/종료 문턱/GAE lambda는 이 비교에서 고정한다.
- 다음에 필요하면 실패 비용의 크기/남은 시간 기울기를 별도 비교한다. 실제 물리·손목 실패 조건을 없애 성공률을 높이지 않는다. cost/reward advantage 분산과 가능한 정책 gradient 진단을 함께 보되 분산비를 인과 기여율로 보고하지 않는다.
- 무행동·조기 탈출·정상 미달성·성공 궤적의 할인된 보상과 비용을 계산해 조기 실패가 유리해지는지 확인한다.

### 4-C. 대기·엄지와 극단 자세

- 먼저 목표각/실제각이 따라갈 수 있는지 확인한 뒤 B 회복·엄지 안내를 개선한다. B는 본인 준비/압현을 보호하고 손가락별 권고로 유지한다.
- 엄지는 목표 후면 영역 도달 가능성, 방향, 거리, 접촉 후보, 한계 충돌을 각각 확인한다. 다른 손가락 압현을 방해하는 엄지 고정이나 지속적인 상태 덮어쓰기를 넣지 않는다.
- 움직임 비용·native 범위 축소·강제 관절 결합을 기본 해법으로 추가하지 않는다. 한계 체류가 제어 방식에서 해결되는지 먼저 확인한다. 보상 강화가 필요하면 작은 독립 비교로 압현 성능 저하 여부를 확인한다.

### 4-D. 악구 → 전곡 전환

- 고정 예산25% 전환 대신 손가락별 수행과 실패율에 근거한 전환을 검토한다. 검지/중지 실패를 약지 성공 평균으로 가리지 않는다.
- 짧은 악구→다양한 악구→전곡 순서로 길이/목표 다양성을 늘린다. 초기에는 검사한 대표 목표를 쓰되 최종 목표에서 어려운 음을 제거하지 않는다.
- 전환 판단은 종료 에피소드만의 편향을 피하도록 별도 고정 평가 배치로 한다. 반복된 학습용 평가와 최종 비교용 holdout을 구분한다.
- 자유 기타의 악구 평가가 기준을 통과한 뒤 원곡67음·128환경·여러 seed 평가와 전신/손 영상을 제공한다. 최종 채택은 총보상이 아니라 손가락별/전체 달성, clean 유지, 오압현, 실패, 관절/엄지 진단으로 결정한다.
