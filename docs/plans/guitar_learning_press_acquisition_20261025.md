## 범위와 순서

첫 착수 범위는1단계 진단 도구다. 결과 확인 뒤2단계 접촉 보상 변경을 진행한다. 구간 학습·손가락별 단계·제어 비교는 후속 단계이며 첫 변경에 함께 넣지 않는다.

| 순서 | 구현 | 완료 판단 |
| --- | --- | --- |
| 0 | 현재 원문·입력·기준 결과 보관 | 경로/SHA와 변경 범위 고정 |
| 1 | 손가락별 압현 도달성 및 같은 조건의 고정/자유 기타 진단 | 목표별 실패 지점을 위치→방향→하중→wrong→유지로 구분 |
| 2 | 기존 최초접촉 보너스를 최장 연속접촉 증가에 따라 분할 지급 | 총량·시간창·완료 기준 보존, 반복 접촉 재지급 없음 |
| 3 | 작은GPU 실행과 보상 전후 대조 | 실제 접촉 획득률·손가락 편중·안전·제어 악화 여부 판정 |
| 4 | 필요시 균형 있는 곡 구간 학습과 손가락별 단계 | 전체 곡 평가의 약한 손가락 향상 및 약지 성과 보존 |
| 5 | 필요시 누적/절대 목표 제어 대조 | 같은 조건에서 유지·한계 체류·반전·기타 안정성 비교 |

기본 학습은 자유 기타·중력ON·스트랩OFF다. 고정은 진단 전용이다. 손가락 움직임 비용0·전체 가동범위·네이티브 힘/PD·물리 안전 기준·B v18·기존 clean 유지/음 달성/오압현 기준은 첫 변경에서 유지한다.

## 1단계: 실제 압현 가능성 진단

### 1.1 목표·입력

기존67음에서 손가락별4개의 서로 다른 `(현, 프렛, 손가락)` 목표를 선정한다. 목표 종류는 검지9·중지7·약지6·소지8개가 있어 각4개 선택이 가능하다. 빈도 높은 목표와 낮은/높은 작업 위치를 포함하고 선정 목록을 실행 전에 고정한다.

- 기본 출발은 현재035/v14 준비 상태다. 과거 고정 기타의 성공 관절각을 그대로 주입하지 않는다.
- 기존v17 NPZ 기록은 자세·명령 분석이나 유한 목표 궤적 재생 입력으로만 사용한다. 현재 계약에 구형 정책을 강제로 load하지 않는다.
- CPU 기하 단계에서는 현재 source 메시/관절 한계로 실제 지정 패드가 목표 프렛 셀 안에 들어오는 후보 자세를 찾는다. 원래 최적화의 목적은 실제 패드 위치와 방향이며 손목 영역 만족만으로 성공 처리하지 않는다.
- 기하 후보는 실제 물리 재생 전에는 '도달 후보'로만 표시한다. 탐색 실패는 도달 불가능의 증명이 아니다.

### 1.2 고정/자유 대조

현재 단일 강체 기타 자산·89개 실제 충돌 형상·마찰·접촉 설정·제어·관절 범위·초기 자세를 유지한다. 고정 조건만 루트의 운동을 제한하고 자유 조건은 현행 그대로 둔다.

주의: `GpuScene`의 기존 자산 선택은 `fixed_base`와 결합되어 있다. 고정 표시 때문에 원래 다중 몸체 자산으로 돌아가지 않도록 단일 강체 자산 경로와 고정 여부를 분리한다. 자산/충돌 fingerprint와 몸체 수를 양쪽에서 확인한다.

- 진단 진입점만 고정 모드를 선택할 수 있게 한다. 일반 `guitar_learning.train`에는 고정 학습 옵션을 추가하지 않는다.
- 진단 실행 계약·출력은 학습 계약과 별도 표시한다. 현행 학습 검증을 느슨하게 만들어 고정 실행을 정상 자유 학습으로 인증하지 않는다.
- q/몸체 상태를 매 tick 덮어써 고정하지 않는다. 시작 reset 이후 실제 물리와 유한 제어만 사용한다.
- 기하 후보 자세로는 제한된 속도의 목표 궤적을 만든 뒤 기존39차원 행동 경로를 통해 실제 이동한다. LH21은 현재 누적 목표에서 다음 목표까지의 차이를 기존 증분식의 역변환으로 행동값에 바꾸고, 나머지는 기존 절대 목표 변환을 사용한다. 실제 제어기의 범위·속도 제한을 거친 목표를 읽어 다음 행동을 계산하며 제어 목표 메모리나 실제 관절 상태를 직접 덮어쓰지 않는다. 관절 한계·안전 종료를 지킨다.
- 동일 목표 궤적 재생은 물리 차이 확인용이다. 자유 기타를 추종하지 않는 open-loop 궤적이 실패했다는 사실만으로 정책/제어 결함을 확정하지 않는다. 필요시 같은 기타 상대 목표를 추종하는 폐루프 진단도 구분해 수행한다.
- 시작은16목표의 소규모GPU 실행으로 하고, 대규모1024환경은 재현·메모리 확인에 필요한 경우에만 확대한다. 복제 환경을 독립 seed로 세지 않는다.

### 1.3 기록과 판정

물리240Hz에서 목표별 다음을 누적한다.

1. 지정 패드의 목표까지 거리와 축별 오차.
2. 프렛 셀·옆방향·부호 있는 표면 높이 조건 통과.
3. 같은 패드 샘플점의 법선 조건 통과.
4. 해당 끝마디 몸체 하중 조건 통과.
5. wrong veto 후 정상 candidate 및 원인.
6. 연속 접촉 최장시간·50ms 최초접촉·100ms 진단 유지·실제 q와 목표 차이·관절 한계 체류.
7. 기타 변위/회전·안전 종료 원인.

하중은 끝마디 몸체의 순합력이며 그 점의 현 접촉력·압력 인증이 아니다. 원인별 조건은 겹칠 수 있어 단순 합산하지 않는다. 곡의 음 달성 기준과 별도100ms 진단 지표를 섞지 않는다.

모든 목표의 요약은JSON으로 저장하고 원시240Hz trace와60Hz 자세는 사전에 지정한 소수 대표 환경에 한정한다. 성공·실패 예시 손 확대 영상, 필요시 전신 영상을 남긴다. 새 실행 폴더에만 저장한다.

## 2단계: 최초접촉 보상 분할 지급

1단계에서 의미 있는 접촉 가능 사례를 확인한 뒤 적용한다. 현재 최초접촉은 `press..end`에서 연속 `tau=min(.05,end−press)`를 채워야 보너스가 처음 지급된다. 이 보너스의 지급 시점만 부드럽게 바꾼다.

```text
current_streak = 기존과 동일한 정상 candidate 연속시간
best_streak_new = max(best_streak_old, current_streak)
p_old = min(best_streak_old / tau, 1)
p_new = min(best_streak_new / tau, 1)
원시 최초접촉 보상 증가 = .5 × 기존 손가락 가중치 × (p_new − p_old)
```

- 정상 접촉의 두 실제240Hz 끝점과 `press..end` 교집합을 기존과 동일하게 사용한다.
- 현재 streak는 접촉이 끊기거나 창 밖이면0으로 한다. best는 같은 음 안에서만 유지한다.
- tau=50ms이면20ms에서 누적 .2b,40ms에서 .4b,50ms에서 .5b다.20ms 접촉을 반복해도 추가 지급하지 않는다.
- 기존 .5b 일괄 지급은 제거한다. 분할 지급과 완료 보너스를 중복해서 주지 않는다.
- `contact_done`은 현재 연속시간이 기존 tau에 도달할 때만 참이다. 부분 보상이 곧 최초접촉 완료·음 달성은 아니다.
- 원시 보너스 총량은 음마다 .5b 이하이며 기존 단계 가중치·실패 tick 양성 억제를 그대로 적용한다. 단계 비중이 시간에 따라 달라질 수 있어 최종 가중 후 합계가 과거 일괄 지급값과 항상 같다는 주장은 하지 않는다.
- best/progress는 H32 경계에서 유지하고, 종료 환경의 reset 때만 지운다. 새 음마다 독립된 예산을 쓴다.
- 최초접촉 완료 전 부분 보상으로 행동이 정체될 가능성도 비교한다. 보상 합계 증가만을 성능 향상으로 해석하지 않는다.

계획상 새 보상 버전은v19다. 원장에는 `best_contact_streak`와 지급 진행도를 추가하고 원장 버전도 구분한다. 숨은 예산 상태를 만들지 않도록 GPU 왼손의 일반/우선 음 토큰에 각 음의 현재 접촉과 소진한 원시 보상 예산 진행도를 모두 제공한다. 실패 tick은 예산이 진행해도 실제 양성 보상이 억제되므로 실제 수령액과 구분한다. 기존 선택 음 하나의 focus 상태506만으로 중첩 목표를 표현하지 않는다.

관측 크기는 유지하고 다음처럼 의미를 명시적으로 바꾼다. 인덱스는0부터 센다.

| 음 토큰 열 | 기존 | 변경 |
| --- | --- | --- |
| 11 | 현재 audible clean 연속시간 | 유지 |
| 12 | 누적 clean 시간 | 현재 최초접촉 streak/tau, 0~1 |
| 13 | 누적 clean/음 길이 | 최장 최초접촉 streak/tau, 0~1 |

누적 clean 관측 두 열을 접촉 상태로 교체하는 선택이며, 누적 clean 계산·보상·원장·보고는 유지한다. 정책과 critic이 같은 새 토큰을 받도록 연결을 검증한다. 상태544·토큰24·우선8개 크기는 유지하지만 의미가 바뀌므로 `left_surface_events.v5` 등 관측 계약을 명시적으로 새 버전으로 구분하고 관련 검사·문서를 함께 갱신한다. CPU/오른손의 토큰 의미는 바꾸지 않는다.

v18 이하 strict resume는 허용하지 않는다. 기존 정책의 Actor를 새 보상에 이전하는 실험이 필요하면 출처·동일성 검사·critic/optimizer 초기화를 명시한 별도 경로로 계획하며 자동 이전하지 않는다.

## 3단계: 검사와 학습 대조

### CPU 및 독립 검수

- 같은 최장시간의 접촉을 반복하면 재지급0.
- 더 긴 streak의 증가분만 지급되고 음별 총량 상한 유지.
- 창 시작/끝·짧은 음·겹치는 음·경계50ms·H32 경계·선택 reset 검증.
- wrong/invalid 접촉·실패 tick에서 양성 보상 억제 유지.
- 기하·힘·관측/목표·기존 clean/성공/오압현 로직의 의도치 않은 변경 없음.
- 같은 새 계약은 model/양 optimizer/RNG/curriculum 정확 복원, 이전 계약은 상태 변경 없이 거부.
- 별도 change-reviewer가 변경·진단 결과를 검수한다.

기존 확장 검사의 CPU512/GPU544 기본값 가정 오류1건은 v18 보고서에 남아 있다. 이번 계획의 회귀와 구분하며 성공한 검사 개수만 골라 전체 통과라고 표시하지 않는다.

### 실제 GPU

1. 소규모 구동·기록 검증. 실제 종료 에피소드가 생기는 길이로 실행하고 원장/지급량을 대조한다.
2. large/1024환경의 짧은 구동·메모리·저장/재개 검사.
3. 기준v18과 변경판을 같은 학습 예산·초기화·목표·평가 조건으로 비교한다. 첫 비교는200업데이트, 개선 신호가 있을 때500회로 확장하는 예산을 제안한다. 신호 부족만으로 즉시2,000회를 반복하지 않는다.
4. 평가는 원속도67음 전체·1024환경의 첫 종료곡을 사용하고 실패도 분모에 포함한다. 단일 seed의 초기 비교임을 표시한다.

선정 지표: 손가락별 near·최초접촉·달성·최장 streak 분포·오압현/누락·안전 완주·관절 한계 체류. 최고 모델은 고정 평가로 선택하고 마지막 모델도 보존한다. 학습 총보상만으로 선택하지 않는다.

추가 계산/메모리·변경 전후 소스SHA·로그CRC·checkpoint 해시를 기록한다. 저장은 현재compact 형식·기본250회 간격을 유지하며 원시 trace는 소수 진단 행에만 남긴다.

## 4~5단계: 후속 조건부 변경

첫 변경의 결과를 보기 전에는 구현하지 않는다.

### 곡 구간 학습·손가락별 단계

- 곡의 연속4~8음 구간을 사용하고 앞뒤 손가락 전환을 포함한다. 검지/중지/약지/소지 중심 구간을 균등하게 선택한다.
- 초기 제안은75%구간/25%전체 곡이다. 검증 후 전체 곡 비중을 늘린다. 단음만으로 전체 학습을 대체하지 않는다.
- 초기 자세는 유지하고 준비 시간을 제공한다. 환경별 구간 시계·활성 목표·종료·남은 시간 실패 비용·보고 분모를 함께 설계한다. 단순히 목표 몇 개를 숨기지 않는다.
- 구간 성공과 전곡67음 성공을 분리한다. 최종 평가는 원속도 전체 곡이다.
- 단계는 손가락별로 진행하고 관측/로그/checkpoint에 저장한다. 초기 기준은 기존 near20%/contact20%를 손가락별로 적용하되 이것이 최적값이라고 주장하지 않는다.
- 손가락별 단계만 분리해 약지 보상만 더 키우지 않도록 균형 있는 경험 구성과 함께 검증한다.

### 제어 방식 대조

진단에서 지속적인 목표 편향·관절 한계 체류가 주요 원인으로 확인될 때 누적 목표와 절대 목표 제어를 같은 목표/예산으로 비교한다. 전체 가동범위·움직임 비용0·PD·힘 한계는 유지한다. 접촉 유지·반전 복귀·기타 움직임·손 모양을 함께 본 뒤 기본값을 결정한다. 현재 누적 제어를 결과 없이 먼저 폐기하지 않는다.
