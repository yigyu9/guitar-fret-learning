## 입력·출력·신경망

- 상태 **450차원**: 기존 설계440 + 지지 접촉 소실시간3 + 남은 시간/이벤트 진행/완료·clean·누락·오류·미준비 이력7. 105축 각도는 준비 기준각을 빼서 표현한다.
- 목표 **79차원 × 2슬롯**: 현재 이벤트(회복 포함), 다음 이벤트. 일반 이벤트 배열은 비우고 빈 우선 슬롯은 mask로 구분한다.
- 목표79 = 기존16 + 스트럼 여부/스윕 길이2 + 줄별 통과·발음·순서·offset·승인·실제 시각오차36 + 준비/단계/진행/오류/해결/완료/회복 이력15 + 회복 조건4 + 회복 경로줄6.
- Actor: 상태450→256→256, 목표79→64→64(두 슬롯 공유), 결합384→512→256→27.
- Critic: 별도 상태/목표 인코더, 결합384→256→256, 보상 가치와 안전 비용 가치 각각1.
- 오른손27 = 손가락21 + 팔꿈치3 + 손목3. 기존39칸 전달 형식의 첫12칸은0이며 확률·우도·엔트로피는27축만 계산한다.
- 기존 `Right27Controller`를 그대로 사용한다. 손가락 직접 목표각, native 범위,4rad/s 제한, 나머지 PD·힘·지지 제어는 유지한다. 물리 상태 재주입은 에피소드 reset에만 존재한다.
- 기존 `DecisionPPOTrainer`와 K1(매60Hz 새 행동)을 사용한다. Actor 학습률3e-5, Critic3e-4, epochs2, 보상할인.99, GAE.98, 비용 가중치1. 초기 표준편차는 exp(-3)≈.0498. `--size`는 기록용이며 위 폭은 고정이다.

## 과거 보상 유지와 현재 환경에 대한 적용

과거 최종 S3 계수를 사용하며 과거 고정 기타·하체 상태 덮어쓰기·그립 행동 제한·9단계 커리큘럼은 가져오지 않았다.

| 항 | 값/조건 |
| --- | --- |
| 그립 | −.02(1−Qg), 준비 기준 RH21과의 각도 오차, 엄지/검지와 나머지 손가락 구분 |
| 준비 | 거리 품질 부족 −.02(1−Qr), 에피소드 최초0.1초 준비 완료 +.25 |
| 접근 | .40 × clamp(.95Φ후−Φ전,−1,1), 목표/단계 변경 순간 제외 |
| 타이밍 대기 | 준비 완료 후 접근 시작 전 +.01Qr |
| 정상 목표 | 준비·시각·순서·오류 없는 전체 이벤트 +1 |
| 미준비/누락 | 미준비 완료 −1, 시각 실패 또는 deadline 누락 −1.5, 각각 한 번 |
| 오타현 | 비계획·역방향·순서 위반·중복·재무장 전 재통과마다 −.35 |
| 시각/타현 영역 | 타이밍 +.75, 영역 +.20, 미세시각 핵심폭20ms |
| 스트럼 | 준비된 새 승인현/통과현 수 +1, 끝줄→exit 진행 증가 +.75, 물리 완주 +.40, 시각/스윕 오차 +.25 |
| 회복 | 최고 진행 증가 +.30, 최초 완료 +.30, 과속 −.10; clean 이벤트만 보상 |
| 조기/관절한계 | 조기 타현 −1 및 연속 조기 시각 감점, 관절95% 초과 −.01 |
| 물리 실패 | 해당60Hz tick 전체 보상을 **−10으로 대체** |

기존 자유 기타의 연속 안전 비용과 실패 비용5는 별도 비용 가치 학습에 유지한다. 보상 로그의 `failure_override`를 포함한 모든 성분 합은 실제 최종 보상과 같다.

현재 좌표계에서 준비 지점은 첫 통과 줄의 y=−.320m, 줄 아래8mm, 접근 쪽8mm다. 최초 준비는 거리10mm와 그립 품질0.75를60Hz에서6회 연속 만족해야 한다. 과거 S3처럼 최초 준비 완료는 에피소드 동안 유지하고, 이후 이벤트에 준비0.1초를 다시 강제하거나 준비 완료 보너스를 재지급하지 않는다. 이후 각 이벤트의 실제 교차·순서·시각·회복은 새로 검사한다. 예정 첫 통과70ms 전부터 순서상 다음 줄의 반대편8mm를 안내한다. 해당 지점의 실제 관절 도달성은 아직 물리 검사하지 않았다.

실제 승인 기하는 현행 그대로: 유한 XY 선분 교차, 법선 속도≥.05m/s, 깊이1–15mm, y=−.385..−.255m. native 재무장은 실제240Hz 두 단계 경과와3mm 분리를 요구한다. 재무장 전 동일한 기하 통과는 새 이벤트의 오류로 기록하고 성공을 취소한다. 승인 조건을 완화하지 않는다.

완전 회복은0.2초, 다음 목표까지 시간이 짧으면 일정에 맞춘 handoff를 사용한다(최소2/60초). 경로 clearance4mm와 필요한 재무장을 확인한다. 추가 통과가 있으면 연속 회복시간을 다시 측정하며 이미 소비한 진행 보상을 재지급하지 않는다. 목표 전환과 PPO 수집 경계는 서로 다르며 후자에서 시계·원장을 reset하지 않는다.

## 성공·지원 범위

스트럼은 발음할 줄뿐 아니라 계획상 보호줄을 포함한 **전체 traversal**을 정해진 방향·순서로 통과해야 한다. 각 줄의 예정 시각±50ms, 준비 완료, 오타현 없음, 회복 완료를 검사한다. 전체 성공은 모든 이벤트의 clean 완료와 회복, 오타현0, 안전한 전체 시간축 종료를 모두 요구한다. 개별 줄 승인·부분 스트럼·기하 완주·시간 준수·clean 완료는 별도 원장에 남는다.

실제 반주 입력 `00_SS1-68-E_comp`의104개 이벤트/43개 스트럼을 읽을 수 있다. `single_pick`과 `strum`을 지원한다. `alternate_restrike` 및 미지원 주법은 명시적으로 거부하며 생략하지 않는다. 원래 기본 solo곡은 alternate_restrike가 있어 이 새 경로의 기본곡으로 쓰지 않는다. 계획 traversal 시간이 실제로 겹치는 서로 다른 이벤트도 지원하지 않는다. 단순히±50ms 허용창이 겹치는 것은 허용한다.

보호줄은 오른손의 허용 통과 경로일 뿐, 실제 왼손 뮤트·압현이나 음향을 인증하지 않는다. 현재 피크는 검지 자식 marker이며 독립적인 동적 파지 물체가 아니다. 관절각 그립 품질·기하 타현과 실제 피크 접촉력·현 진동·음향 성공은 구분한다.

## 검증 및 다음 실행

CPU 검사75개가 통과했다(신규63개, 재사용 제어/정책/결정 수집12개). 합성 snapshot 검사, PPO 작은 update/저장·복원, strict 입력 오염 거부, 27축 행동 전달, 준비·스트럼 순서·회복·이동 기타 상대속도·실패 보상을 검사했다. 별도 검수에서 재무장 전 재통과, 회복 연속시간, 빠른 목표의 최초 준비 latch, tick 안에서 목표가 바뀌는 경우의 보상 귀속을 수정하고 회귀 검사를 추가했다. 최종 독립 판정은 남은 Critical/Warning 없음이다. Python3.8 문법12파일, CLI help, 기존538개 소스 SHA 보존과 정리.txt 원문 보존도 확인했다. 상세는 `검증.json`과 `CPU검증.log`에 기록한다. native GPU 장면·카메라·장기 학습은 미실행이다.

GPU를 기존 작업과 공유하지 않는 조건에서, 프로젝트 루트에서 먼저 작은 학습 실행을 한다. 새 출력 경로를 사용한다.

```bash
python scripts/tab2body.py run -m guitar_learning.tool.experiments.compact_strike train \
  --song 00_SS1-68-E_comp --num-envs 4 --horizon 32 --updates 2 \
  --out docs/2026-11-04/타현학습/로그/smoke_v1
```

실제 native lifecycle·finite 로그·관절 추종을 확인한 뒤128환경 등으로 확대한다. 처리속도를 측정하기 전 장기 학습시간과 성능을 예측하지 않는다.

```bash
python scripts/tab2body.py run -m guitar_learning.tool.experiments.compact_strike evaluate \
  docs/2026-11-04/타현학습/로그/smoke_v1/final.pt \
  --out docs/2026-11-04/타현학습/로그/eval_v1
python scripts/tab2body.py run -m guitar_learning.tool.experiments.compact_strike render \
  docs/2026-11-04/타현학습/로그/smoke_v1/final.pt \
  --out docs/2026-11-04/타현학습/로그/render_v1
```

재개는 `train --resume <checkpoint> --updates <추가 업데이트 수> --out <새경로>`다. 입력·소스·자산 SHA, 관측 순서/정규화, 신경망·행동·PPO identity가 일치해야 하며 옛 압현/right6/right27 checkpoint의 암묵 전환은 거부한다. 재개 시 물리 장면은 새 준비 에피소드에서 시작한다.
