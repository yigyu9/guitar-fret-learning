# 손가락 추종 오차 원인 확인과 최소 개선

사용자의 '추가적으로 개선할 부분이 있다면 개선을 진행해줘'를 진단으로 확인한 문제의 구현·검증 승인으로 따른다. 임의 gain·탐색폭·보상을 동시에 조정하지 않고, 기존435소스/두 봉인 결과를 보존한다.

- [x] 기존 약지/소지 probe의 소지기저 오차를 native PD·source joint·힘·관측/제어 흐름에 대조해 원인을 좁힌다. 정책 한방향 출력은 다른 문제와 구분한다.
- [x] 필요한 실제 작은 GPU 대조로 원인 가설을 확인한다. 설정 변경은 새 별도진단/명시적계약에서만 적용하고, 원래 source·모델·물리성과를 재분류하지 않는다.
- [x] 근거가 확인된 최소 수정 전에 해당 소스/검사/문서를 archive에 보관한다. 수정 범위·checkpoint 호환성을 명시하고 의미있는 CPU 검사·독립 리뷰를 수행한다.
- [x] 동일 pulse/hold/return로 실제GPU 기본/반복16 추종·복귀·접촉·안전 비교,새정량그림/문서·최종입력SHA 검증. 개선효과가 없는 후보를 현행에 적용하지 않는다. 물리/동작을 바꾸지 않은 진단 보강이므로 기존 반전 영상을 보존하고 새 정책 영상을 만들지 않는다.

일차 성공 기준은 같은 허용0.2rad 목표에서 준비자세 소지1_z의 정지끝 |q−target|≈0.09922rad를 줄이면서, 원래 관절 범위·힘 상한과 반전/접촉 해제·안전을 유지하는 것이다. 원인불명 상태에서 stiffness를 올리거나 충돌/한계를 없애지 않는다. 정책 drift·곡 달성 개선이나 장기수렴은 별도 증거 없으면 주장하지 않는다.

실제 N6 기본 대조는525tick/2100물리표본·6환경 모두 정상 완료했다. 무접촉 소지는 x=0일 때 +0.1rad 명령에 실제+0.09982rad, x=1.56일 때+0.05070rad였다. 실제 PD K12/D1.5·effort20·friction0도 확인했다. qx/z는 실제 상대회전 log의 두 성분과 맞지만 생략된 y 성분이 생기며, zero-y 목표 대비 local SO(3) 오차는 x/z가 거의0이고 y가 남는다. gain을 올리는 해법은 근거가 부족하다. 내부 PhysX 버전·임포터 구현 전체 원인은 확정하지 않는다.

추가 개선 범위를 실제 자세 진단으로 구체화한다. 기존 `left_finger_motion`에4개 기저 관절의 실제 palm 상대 회전 y·zero-y 명령 대비 전체/국소xz 회전오차 RMS/최대를60Hz로 기록한다. 관측512·보상·제어·PPO는 유지하고, q−target만으로 전체 자세 추종을 판단하지 않도록 한다. 원래6개 관련 파일은 `archive/20261022_before_finger_pose_diagnostics_v1/`에 보관했다. solver16 대조 효과가 없으면 해당 설정을 기본값으로 승격하지 않고 미해결 제어 오차를 명시한다. 관절 수/모드/몸체 구조를 바꾸는 큰 수정은 이번 작은 개선에 섞지 않는다.

기본/반복16은 모두 정상525tick/2100물리tick·조기종료0. 소지x=1.56 유지오차−.049162→−.049318rad로 개선하지 못해 기본4를 유지했다. 목표 오차 감소라는 일차 제어 성공 기준은 충족하지 못했다. 별도 최소 개선인 자세 진단을 구현했고 CPU73개·독립 검수를 통과했으며 실제6×525개 자세의CPU/CUDA 재생으로 수식의 정합을 확인했다. 제어 문제를 해결한 것으로 표시하지 않는다.
