## 짧은 예산과 중단

먼저 기존 대표 4목표를 같은 초기·제어 조건의 새 독립 실행에서 재현하여 25/50/75/100회 모델을 각각 평가한다. 과거 모델 재개나 과거 소스 수정은 하지 않는다. 보상·탐색·학습률·PD·종료 조건은 한 조건 안에서 고정하고, 원래 학습 일정이 재개 때마다 초기화되지 않는지 검사한다.

빠른 선별은 seed7 하나로 시작한다. 평가에는 잡음 없는 고정 정책을 사용한다. 각 경계에서 첫16개 에피소드를 검사하고, 연속 달성≥15/16·평균 clean 비율≥90%·물리/손목 실패0·평균 오압현≤.05초면 첫 후보로 표시한다. 다음 25회 경계에서도 같으면 첫32개 에피소드로 확인한다. 확인은 달성≥31/32·평균 clean 비율≥90%·물리/손목 실패0·평균 오압현≤.05초다. 이는 빠른 선별 기준이며 기존 128회 반복 검증을 대신하는 최종 인증이 아니다. 같은 초기 상태의 반복을 독립 학습 seed로 세지 않는다.

25회에서 우수하면 50회 확인 후 중단 가능하다. 100회에서 처음 통과하면 새로 더 학습하지 않고 같은 모델을 독립 평가 프로세스의 첫32개 에피소드로 재확인하고 위32개 기준을 적용한다. 어느 경우든 실제 소비한 학습 수와 평가 횟수를 기록한다. 100회 미통과는 예산 내 미해결이며 수렴 불가능이나 물리적 불가능 판정이 아니다. 25회 첫 평가의 낮은 성과만으로 중단하지 않는다. 비유한값·입력 불일치·실행 오류·반복 물리 붕괴는 성능 미달과 분리해 즉시 기술 점검한다.

대표 4목표에서 실제 경계를 찾은 뒤 72조합(4손가락×6줄×1·12·22프렛)에 적용한다. 대표 중앙 프렛의 성공 예산이 최고 프렛에도 충분하다고 보장하지 않는다. 각 조합의 목표별 초기 정렬이 준비되었는지 먼저 확인한다. 정렬 미확보와 학습 실패를 구분한다. 이번 빠른 검사는 손목지원 조건부터 수행하며 공통 초기 자세의 팔 도달 학습과 별도 표로 남긴다. 어려운 조합만 후속 원인 분석·두 번째 seed·연장 후보로 보낸다. 전체 평균으로 실패 조합을 숨기지 않는다.

## 자원 사용

기존 100회 실행 시간의 약96%는 수집, 약3%는 PPO였다. 환경 수를 1024로 키우는 것만으로 성공까지 빨라진다고 단정할 수 없다. 환경 수를 늘리면 한 번의 갱신당 경험과 에피소드 수가 바뀌기 때문이다. 64환경 100회를 1024환경 6회로 치환하지 않는다.

자원 검증은 대표 목표에서 64환경 기준을 확보한 뒤 128/256환경의 성공 도달 시간·평가·메모리·물리 실패를 비교한다. 같은 경험량 비교와 같은 갱신 수 비교를 구분한다. 성공 기준을 만족하는 데 가장 짧게 걸리는 설정을 선택한다. 초기 조건·보상·학습률을 동시에 바꾸지 않는다.

독립 조합 2개 병행도 후보지만 먼저 단독 실행과 작은 병행 시험의 소요 시간·GPU 메모리·오류·성능을 비교한다. 실제 총 처리량이 늘고 여유 메모리가 유지될 때만 채택한다. 다중 프로세스의 GPU 물리 버퍼·렌더 충돌 가능성을 시험하지 않고 4~16개를 한꺼번에 실행하지 않는다. 현재 병행 효율은 미측정이다. 영상 렌더는 학습과 겹치지 않게 후처리한다.

## 시간과 산출물

기존 속도에서 25회 수집·갱신은 약2.1분, 50회는 약4.2분, 100회는 약8.3분이다. 프로세스 시작·저장·재개·평가는 추가다. 과거 평가 프로세스는 대략1분이었다. 25회마다 평가하면 빠른 성공을 찾는 대신 평가 비용이 늘어난다.

72개 모두100회면 학습만 약10시간이다. 경계별 평가·최종 확인을 더하면 약14~17시간을 첫 순차 예산으로 잡는다. 다수가50회에 통과하면 약8~11시간으로 줄어들 여지가 있다. 목표별 초기 정렬 준비·실패 진단·영상 시간은 별도다. 병행 속도 향상은 실측 전 시간표에 반영하지 않는다. 4대표 파일럿 뒤 실제 성공 경계와 자원 처리량으로 남은 예상 시간을 갱신한다.

각 조합마다 첫 접촉·연속 달성·clean 비율·오압현·물리/손목 종료·패드 거리·학습 수·경험량·실행 시간·checkpoint/입력 SHA를 한 행으로 남긴다. 72행 전체를 제공하고 영상은 기존 보관 원칙대로 손가락별 대표 성공 및 주요 실패 유형만 남긴다. 모델은 초기·선택·최종 위주로 남기되 선택/탈락 근거와 원시 수치는 보존한다.
