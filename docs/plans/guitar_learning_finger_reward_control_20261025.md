# 손가락 보상·제어 개선 계획

상태: 사용자 승인으로 v20 A 구현·검증을 완료했고, large/1024/H32/seed7의 새500회 학습·각3회고정평가·영상·분석을 완료했다. A는음악성과와복귀채택기준미달로3,000회연장하지않았다. 후속평가·분석·영상과3,000회후보판정은 [실행계획](/home/ajou/yigyu/3/docs/plans/guitar_learning_v20_A500_20261025.md)을 따른다.

[독립 기술 검수](guitar_learning_finger_reward_control_20261025_review.json)는 문제없음으로 완료했다. 이는 계획의 수식·검증 설계에 대한 판정이며 실제 개선 효과를 검증한 결과가 아니다.

근거: [기존1024평가와 실제240Hz 진단](/home/ajou/yigyu/3/docs/2026-10-25/guitar_learning_finger_diagnosis_v1/README.md). 검지는 충분히 긴 대기에서도 PIP≈0°/DIP≈90°를 유지했고, 정책의 한계 방향 명령을 관절이 약0.8°오차로 따라갔다. 대기 시간 확대·PD 변경부터 시작할 근거는 부족하다.

## 1. 목표와 유지할 조건

개선 목표는 두 개다.

1. **본인 압현과 무관한 긴 대기에서는 B 범위로 돌아오기.** 한 점을 반드시 거치게 하지 않으며 B±15° 안의 자세는 동등하게 취급한다.
2. **압현에서는 끝관절 하나에 과도하게 역할을 몰지 않기.** 특정 관절 비율·고정 궤적·손가락 간 동시 굽힘을 강제하지 않는다. 달성음·실제 접촉 유지가 우선이다.

유지: GPU PhysX·자유 기타·중력ON·스트랩OFF·035/v14 초기 자세·전체native가동범위·손가락 움직임/행동변화 비용0·현재PD/힘상한·4rad/s최대목표속도·60/240Hz·음악성공/안전종료 기준. 엄지·벌림각·손목·하체는 이번 B/분담 개선 대상이 아니다. 기존 wrong/missing/clean/contact 보상과 PPO/H32도 첫 실험에서 유지한다.

보상과 제어를 동시에 바꿔 효과를 뭉뚱그리지 않는다. **A: 대기 관측·보상 → B: 압현 분담 선호 → C: 필요할 때만 대기 제어 보조** 순서다.

## 2. A단계: 실제 대기 신호와 B 복귀 보상

### 2.1 정책의 대기 입력을 실제 보상과 일치

- 현재544상태의 손가락별 기존 `idle_weight` 4열을 새 계약에서는 `standby_gate` 4열로 바꾼다. **차원544, 손가락head20개직접입력과 우선토큰8개 구조는 유지**한다.
- 값은 그 시점의 실제 B gate다. 본인 press−0.35..end 차단,0.15초fade, 본인 관련목표에 대한4cm근접/접촉 제외를 그대로 반영한다.
- 2초 준비창은 추종 목표 선택·음 토큰용으로 유지한다. 실제 B 자격과 이름·의미를 섞지 않는다.
- 보상과 관측이 하나의 순수 gate 계산을 공유한다. 관측은 최신60Hz끝점의 gate, 보상은 기존대로 모든240Hz끝점에서 적분한다. 관측용 계산 때문에 이전candidate·원장·타이머가 갱신되면 안 된다.
- reset 시에도 같은 계산을 사용하며, H32 경계에서 gate·곡 시계·관절 목표를 초기화하지 않는다.

실제 gate와 관측의 불일치 시간이 짧았으므로 이것만으로 성과가 좋아진다고 주장하지 않는다. 새 보상 의미를 정책에 명확히 전달하기 위한 정리다.

### 2.2 지수 품질을 완만한 양성 권고로 교체

손가락 f의 실제 기하 MCP/PIP/DIP 각도를 θ, 기존 B 기준각을 B라 한다. 도 단위로:

```text
e[f,j] = max(abs(θ[f,j] − B[f,j]) − 15°, 0) / 30°
s[f]   = sum_j e[f,j]²
Q_B[f] = 1 / (1 + s[f])
rate_B = 0.02 × mean_4(actual_gate[f] × Q_B[f])  /초
```

- B 기준각·±15° 평탄대역은 유지한다. 대역 안에서는 모든 자세 Q=1이며, 특정 각도에 더 가까워져도 추가 이득은 없다.
- 기존 `exp(−s)`를 `1/(1+s)`로 바꿔 극단 자세에서 작은 개선의 보상 차이가 급격히 사라지는 현상을 줄인다.
- 첫 실험의 최대치는 손 전체0.02/초·손가락당0.005/초로, 기존0.01/초의2배다. 통과 후보가 복귀를 거의 학습하지 못하면 **별도 비교군**으로0.04/초를 평가한다. 검증된 최적 계수라는 뜻은 아니다.
- 예: 검지0°/0°/90°에서 Q는 약0.00690→0.167이다. 해당 손가락 보상률은 약0.0000172→0.000837/초다. 이것은 현재 자세의 지급액이지 B로 돌아갈 총이득/정책효과를 뜻하지 않는다.
- 실제 gate가 0인 압현 준비·근접·접촉 구간에는 직접 적용하지 않는다. 무효 각도·빈 곡은 보상 0을 유지한다. 전체 4손가락 분모도 유지한다.
- `−gate×B오차` 감점으로 단순 교체하지 않는다. 현재 gate는 거리에 따라 꺼지므로, 벌점을 피하려고4cm안으로 이동하거나 불필요한 접촉을 만들어 gate를 끄는 유인을 만들 수 있다.
- 양성 권고도 먼 곳에 머물러 gate를 유지하거나 준비를 늦추는 유인이 생길 수 있다. 본인 press에 대한 준비 지연·접촉 누락·목표에서 먼 체류가 늘면 B품질이 좋아져도 통과시키지 않는다.
- 별도 개선량 보너스·일회성 복귀 보너스는 첫 버전에 넣지 않는다. gate전환/H32/음전환에서 보상이 중복될 여지를 줄인다.

### 2.3 A단계 통과 기준

운영상의 목표값이며 해부학적 정상범위 인증이나 효과 보장은 아니다.

- 악보만으로 고정한 **본인 press−2..end 밖의 먼 대기 구간**을 기준 실행과 후보에 동일하게 사용한다.1초이상 구간에서 B대역 점유율을 **20%p 이상** 높이는 것을 우선 지표로 삼는다. 실제full gate가1초이상 연속인 구간의 점유율도 보조 지표로 함께 보고한다.
- 본인 마지막 음 이후의5초 이상 대기에서는, 시작 시 대역 밖인 손가락의 **70% 이상이3초 이내** B±15° 안에 들어와0.2초 이상 유지하는 것을 목표로 한다. 시작부터 대역 안이면 별도 유지율로 센다.
- 초기 본인 추종0·full gate1 구간에서 B품질이 오히려 떨어지는 비율, 관절 한계 밖 명령 비율이 줄어야 한다.
- 정책이 gate를 꺼서 분모를 줄이는 착시를 막기 위해, 고정 시간창의 개수·길이·도달률과 실제 gate 구간의 개수·길이·커버리지를 함께 보고한다. 물리 실패로 고정창을 끝까지 관찰하지 못하면 복귀 성공으로 세지 않고 실패·미관찰로 따로 기록한다. 해당 창이 없으면 평가 불가이며 자동 통과시키지 않는다.
- 음 달성·접촉·오압현·안전 성능은 아래 공통 기준을 만족해야 한다. 못 만족하면 계수나 gate를 무작정 늘리지 않고 A단계 원인을 재검토한다.

## 3. B단계: 압현 중 극단적 끝관절 편중을 별도 개선

A가 좋아져도 압현 중 PIP0°/DIP90°는 남을 수 있다. B는 A와 분리한 비교군으로 추가한다.

```text
z[f]        = max(DIP[f] − PIP[f] − 50°, 0) / 30°
Q_shape[f]  = 1 / (1 + z[f]²)
rate_shape = 0.004 × mean_4(tracking_active[f] × Q_shape[f]) /초
```

- 현재 곡에 존재하는4손가락 고정분모, 손 전체 최대0.004/초·손가락당0.001/초부터 시험한다. 새 항이므로 계수50°/30°와 함께 실험값으로 기록한다.
- tracking_active는 기존 손가락별 추종 선택기의 유효 tracking목표가 있는 경우다. 새로운 목표 선택기를 만들지 않는다.
- DIP−PIP가50°이하이면 전부 같은 점수다. 둘을 같은 각도로 만들거나 MCP를 특정 각도에 고정하지 않는다. 자연스럽게 필요한 큰 굽힘·펴짐은 여전히 가능하다.
- 이 항은 움직임 크기/속도/행동의 비용이 아니다. 실제 각도의 극단적 차이에 대한 약한 선호다. thumb·spread·MCP에는 추가 항을 걸지 않는다.
- 최초 작은 계수로 **candidate/clean 접촉 중에도 적용하는 비교군**을 시험한다. 여기까지 꺼버리면 실제 압현 중 끝관절 편중을 고칠 신호도 사라진다. 이 선택의 압현 간섭 위험을 숨기지 않는다.
- 압현 중 작용하는 비영(0이 아닌) 보상이 압현에 전혀 영향을 주지 않는다고 보장할 수는 없다. 달성음/접촉이 공통 기준보다 나빠지면 이 항을 채택하지 않는다. 대기 개선 A만 유지할 수 있다.
- 관절 편중 진단 임계값(PIP≤10°·DIP≥60°)과 보상식의50°대역은 서로 다른 목적임을 로그에 명시한다. 임계값 바로 아래에 몰리는지도 실제 연속 각도 분포로 확인한다.

B의 목표: 압현 중 말단 편중 점유율을 기존 대비 절반 이하로 낮추되, 접촉·음 달성의 저하를 동반한 모양 개선은 채택하지 않는다. 어느 손가락도 이전보다 안정적으로 잘못 펴지게 만들지 않았는지 MCP/PIP/DIP 전체 분포를 확인한다.

## 4. 제어 개선 C: 필요할 때만 시험하는 대기 보조

**A/B의 첫 실험에서는 누적 제어·PD·최대속도를 바꾸지 않는다.** 현재 제어가 명령을 잘 따라가므로 여기부터 바꾸면 문제를 숨길 수 있다.

A의 보상 신호를 개선해도 긴 실제 대기에서 복귀가 계속 실패할 때, 다음 보조를 A기반의 별도 비교군 C로 시험한다. A+B+C를 처음부터 한꺼번에 넣지 않는다.

### 4.1 적용 범위

- 검지~소지의MCP굽힘/PIP/DIP12축만 대상이다. 엄지5축·벌림4축·팔/손목은 기존 제어를 쓴다.
- **본인 관련목표가 press−2..end에 하나라도 있으면 보조0**이다. 보상보다 더 보수적인 먼 대기에서만 작동한다.
- 본인 접촉/하중이 있거나, 센서/기하각이 무효이면 보조0이다. 기타를 지지하는 손가락을 강제로 움직이지 않는다. 부하 판정은 기존0.01N진단 기준에서 시작하고 대상 몸체를 명시한다.
- B±15° 안에서는 보조0이다. 악보 시간으로 정해지는 먼 대기 경계에는0.15초fade를 사용하고 준비/접촉/부하 진입 시에는 즉시0이다. 별도의‘접촉이 풀린 뒤 몇초’누적타이머는 추가하지 않는다. 마지막 기타/손가락 상태를 덮어쓰지 않는다.

### 4.2 속도 결합과 정책 우선권

보조속도 v_B의 초기 최대치는 **0.35rad/초(약20°/초)**다. 예를 들어DIP90°에서B상한27°까지 보조만으로는 최소약3.14초가 필요하다. 너무 작은 보조를 넣어 수초 내 복귀를 기대하는 모순을 피한다.

정책 명령 a∈[−1,1]에 대해:

```text
v = v_B + (4 − v_B)×a    if a >= 0
v = v_B + (4 + v_B)×a    if a < 0
target_next = clamp_native(target_previous + v/60)
```

- a=+1/−1은 언제나+4/−4rad/초다. 단순`4a+v_B`후clamp와 달리 보조 반대쪽 최대속도를 줄이지 않는다.
- 정책은 보조를 상쇄하거나 반대로 움직일 수 있다. 움직임 비용0도 유지한다.
- a=0은 먼 대기에서 ‘유지’가 아니라 ‘약한 복귀’가 된다. **명시적인 새 제어 계약**이며 기존checkpoint를 같은 행동 의미로 재개하지 않는다.
- 순간 B각도로 target을 바꾸지 않고 기존target에서 속도만 적분한다. 최대목표변화4/60rad·한계클램프·reset/H32 연속성을 유지한다.
- 실제 기하MCP각과native좌표는 같지 않다. B대역과nativeB후보의 변환을 소스기구학과 실제 각도 readback으로 먼저 검증한다. 기하각 차이를native MCP축에 그대로 더하지 않는다. 변환이 검증되지 않으면MCP보조를 켜지 않고 그 제한을 보고한다.
- 정책이 자신에게 더해지는 보조를 알 수 있도록 현재 끝점에서 계산한 **다음 제어 tick 적용 예정 v_B 12열**을 관측에 추가한다. 그 tick의 실제 적용값과도 대조한다. 이 후보는 상태 556·손가락 head마다 직접 입력 23개의 별도 계약이다. 보조는 현재 관측·명령 목표·악보 시간·현재 접촉에서 결정되는 함수로 제한하고, 별도의 숨은 전환 상태는 추가하지 않는다.

이 보조는 B를 단순 보상 권고에서 일부 제어 보조로 바꾸는 선택이다. 기본안으로 조용히 넣지 않으며, 복귀율·압현 성능·자유로운 반대 명령을 모두 검증한 뒤 채택 여부를 정한다.

## 5. 로그와 검증

### 5.1 필요한 진단

매240Hz 기록은 짧은 진단의 사전지정8환경에만 사용하고, 일반 학습은 고정크기 episode 집계만 저장한다.

- 실제 gate>0와gate=1의 연속 길이·전체 가능 시간·fade가중 시간, 각0.5/1/3초이상 구간 비중.
- B대역 진입 지연·0.2초유지 여부·긴 구간 점유율. 초기부터 대역 안인 경우와 실제 복귀 성공을 구분한다.
- 초기무추종/압현/전환/마지막음후대기별 MCP/PIP/DIP, 실제/목표오차, 한계 밖 명령 시간.
- B/shape/추종/contact/clean/wrong/missing의 실제 지급과 원시값. 실패 마지막tick의양성억제를 같은 규칙으로 적용한다.
- Bgate를 끄는 접근/접촉이 늘었는지, candidate없이 보상만 얻는 체류가 늘었는지, 다른 손가락으로 문제가 옮겨갔는지.

## 6. 실험 순서와 공통 채택 기준

1. **변경 전 기준 확보:** v19의 저장된 500회·3,000회 체크포인트를 같은 1,024환경으로 고정 평가한다. 기존의 안전 완주 887/908회·env0 달성 26/30음은 반복 차이의 근거로 보존한다. 새 후보의 성능과 섞지 않으며, 기준 자료는 코드 변경 전에 보관한다.
2. **A 구현·구동:** CPU 검사 → 16환경의 짧은 GPU 실행·저장/재개 검증 → large·1024환경·H32에서 fresh 500회 순서로 진행한다. 짧은 구동 검사를 학습 성능 검증으로 부르지 않는다.
3. **A 비교:** v19 500회와 A 500회를 동일한 곡·초기화·예산으로 고정 평가한다. 가능하면 초기 actor 가중치가 바이트 단위로 같은지 검사한다. 상태 544·망 구조를 유지해 불필요한 초기화 차이를 줄인다. 계수 0.02가 복귀에 무효한 경우에만 0.04를 별도 500회로 비교한다.
4. **B 또는 C 분리:** A가 대기를 해결했지만 압현 편중이 남으면 A+B, A에서도 긴 대기 복귀가 실패하면 A+C를 선택한다. 동시에 추가하지 않고 같은 예산의 A와 비교한다.
5. **최종 후보:** 통과한 후보 하나를 fresh 3,000회로 학습하고 v19 3,000회와 평가한다. 500회 결과만으로 장기 개선을 판정하지 않는다. 첫 seed 7이 통과하면 seed 17/27의 별도 학습으로 재현성을 확인하는 후속 단계를 둔다.

GPU 반복 궤적 차이가 있으므로 각 선정 checkpoint는 최소 3회 고정 평가한다. 같은 seed의 반복 평가는 독립 학습 seed 검증이 아니다. 원래/새 실행과 전체/안전 완주의 분모를 분리한다.

500회는 비교 후보를 가리는 초기 예산이다. 500회에서 복귀가 부족하다는 사실만으로 A가 학습 불가능하거나 제어가 고장 났다고 판정하지 않는다. 개선 추세가 남아 있으면 같은 후보의 학습을 더 확인하고, 제어 C가 필요하다는 결론과 구분한다.

운영상 채택 기준이며, 수치는 초기 제안이다.

- 전체 1024환경 평균 달성음: 같은 예산의 기준보다 감소가 **1.0음 이내**(전체 67음 대비 1.49%p).
- 안전 완주율: 반복 평가 평균의 하락이 **2%p 이내**. 반복 변동과 구별이 안 되면 보류하고 추가 반복한다.
- 손가락별 달성률과 contact_done율: 어느 손가락도 **5%p 초과 하락 없음**. clean/wrong/missing 시간도 함께 판단하며 최고 한 장면으로 통과시키지 않는다.
- 자세 개선: A의 복귀 기준, B의 압현 편중 감소 기준을 충족해야 한다. 음악 성능만 유지하고 자세가 그대로면 해당 수정의 목표는 미달이다.
- 오압현/누락의 audible 시간 정규화 비율이 **5%p 초과 악화 없음**. 실패로 일찍 끝나 관측 노출이 줄어든 착시를 막기 위해 완주/실패를 분리한다.
- 위 값은 통계적 비열등성 인증이 아니라 실험 중단/채택 기준이다. 불확실하면 개선으로 인증하지 않는다.

처음에는 고정 기타·단음 훈련으로 대체하지 않고 현재 전곡 67음·자유 기타를 유지한다. 필요한 짧은 재현 검사는 별도 진단으로만 두며 전곡 성과와 섞지 않는다.

## 7. 구현 범위·버전·산출물

예상 수정은 `gpu/finger_reward.py`(B/shape), `gpu/environment.py`(공유 gate·보상/관측/계약), `skills/specialist_policy.py`(새 필드·버전 검사), `gpu/episode_diagnostics.py`(고정 크기 복귀 진단), 관련 tests·보상 구조·학습 흐름 문서다. C를 시험할 때만 `gpu/control.py`와 제어 계약·556관측을 추가 수정한다. 다른 학습 패키지는 정리하지 않는다.

변경 전 v19 원문·필요 검사·문서·SHA를 보관한다. A는 새 보상·관측 계약 v20 후보로 구분하고, B/C의 선택 기능·계수·codec도 전체 계약에 기록한다. 구 v19를 암묵적으로 이어받지 않고 fresh로 시작하며, 명시적 actor 이전이 필요하면 별도 실험으로 다룬다. 기존 영상·checkpoint·평가 pin은 고치지 않는다.

산출물은 구현·CPU/GPU/재개 검증, 설정·입력 SHA·버전, 비교표, 손가락별 복귀·분담 진단, 최종·선정 정책의 전신/왼손 60fps 영상이다. 전이 원시 기록은 기존 compact/보관 정책을 따르고, 매 프레임 대용량 진단을 전체 학습에 상시 추가하지 않는다.
