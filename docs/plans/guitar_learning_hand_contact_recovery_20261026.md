# 왼손 접촉·대기 복귀·충돌·극단 관절 개선 계획

작성일: 2026-10-26. 사용자가 요청한 네 작업의 실행 계획이며, 이 문서 작성은 구현·새 학습의 시작이 아니다.

## 목표와 순서

사용자 작업 번호:

1. 엄지를 넥 뒷면에 접촉시키고 보조 지지로 사용
2. 압현 사이에도 B 대기 자세로 복귀
3. 손가락 사이의 선별적인 충돌 적용
4. 극단적인 관절 조합의 원인 탐색과 개선

실행 순서: **④ 원인 분리 → ③ 충돌 적용 → ④ 원인별 개선 → ② 대기 복귀 확대 → ① 엄지 뒷면 접촉 → 통합 검증**.

④는 먼저 진단하고 물리 조건 정리 후 개선한다. 충돌만 켜면 기존의 한 방향 누적 명령이 큰 접촉 부하로 바뀔 수 있다. ②는 실제로 도달 가능한 손 모양과 제어를 바탕으로 적용하고, ①은 손가락을 통과해 넥에 접근하는 경로를 막은 다음 적용한다.

## 이미 확인한 사실과 아직 확인할 것

| 확인된 사실 | 아직 분리해야 하는 원인 |
|---|---|
| A500 소지 목표·실제 굽힘90/90/−5도, 검지·엄지도 극단 목표를 요청함 | 정책이 시간·목표·대기 입력을 충분히 활용하지 않는 이유와 보상 간 경쟁 |
| 손가락 사이90개 마디 조합의 충돌이 공통 filter128로 억제됨 | 준비 자세·B·압현에서 안전하게 활성화할 충돌 쌍과 필요한 연결부 예외 |
| 기존 누적 제어의 행동0은 현재 목표 유지이며 B 자동 복귀가 아님 | 제어 codec·관절축 해석 오류인지, 적절한 제어에 대한 정책의 지속 편향인지 |
| 일부 벌림 축에 큰 목표–실제 잔차가 있음 | 접촉 부하·축 표현·native 제약·실제 제어 응답의 기여 |
| 직접 목표 시험에서 B 굽힘 대역 도달 가능 | 충돌 적용 후의 동적 도달, 검지 약20N 부하 및 벌림 잔차의 개선 가능성 |
| B는 약한 굽힘 권고, 엄지 뒷면 전용 보상은 없음 | 음 사이 복귀와 엄지 접촉을 추가했을 때 압현 품질에 주는 영향 |

기존 A500 영상·저장 자세·240Hz 진단을 기준 자료로 재사용한다. 이미 확인한 전체 평가를 이유 없이 반복하지 않고 부족한 측정만 추가한다.

## 공통 유지 조건

- 선택한 B 굽힘 중심과 ±15도 대역을 기본으로 유지한다. 압현 중 특정 관절각이나 관절 비율을 강제하지 않는다.
- LH21의 움직임·속도·행동 비용0과 전체 native 가동범위를 유지한다. 손가락이 빠르게 굽히고 펴지는 능력을 줄여 해결하지 않는다.
- 기존035/v14 초기 상태, root 고정, 유한한 하체·팔 유지 제어, 자유 기타·중력ON·스트랩OFF를 유지한다.
- 기타에 보조 힘을 주거나 엄지를 붙잡아 두지 않고, 실제 상태를 매 프레임 덮어쓰지 않는다.
- 음별 달성·clean·오압현 판정은 이번 자세 개선과 별도 유지한다. 달성 플래그가 켜져도 음 끝 전에 손가락을 떼도록 하지 않는다.
- 물리·보상·관측 계약이 바뀌면 새 버전으로 기록한다. A500 checkpoint의 strict resume를 완화하지 않는다. 과거 성과를 새 물리의 성과로 상속하지 않는다.

## 단계 A — ④의 원인 분리와 측정 기준

### 할 일

1. 검지·소지·엄지의 마지막 자세를 만드는 요청 행동, 누적 목표, 실제 native 각도, 실제 몸체 상대 회전을 같은 시계로 정리한다.
2. 단일 GPU 환경에서 현재 물리로 다음 제어 시험을 수행한다.
   - 준비 자세 유지와 B 직접 목표 이동.
   - 손가락별 작은 굽힘·펴짐 및 벌림·오므림 요청.
   - 일정한 작은 행동 유지 후 반전: 목표가 계속 누적되는지, 한계에서 정상적으로 반전하는지 확인.
   - 접촉이 적은 자세와 접촉이 있는 자세에서 같은 요청을 비교.
3. 특히 MCP 벌림은 q/target 숫자뿐 아니라 palm 상대 전체 회전으로 확인한다. source 관절축·native 좌표·몸체 회전이 어떻게 대응하는지 확인한 후 제어 오류 여부를 판단한다. 진단용 SO(3) 오차를 실제 drive torque 인증으로 사용하지 않는다.
4. H32 경계와 에피소드 reset 전후를 확인한다. 현재 코드의 한계 clamp에 문제가 있다고 가정하지 않고 재현되는 경우에만 수정한다.

### 원인별 분기

| 측정 결과 | 다음 조치 |
|---|---|
| 목표가 극단적이고 실제도 잘 따라감 | 정책 명령 편향·보상 경쟁·대기 복귀 학습을 개선 |
| 목표는 적절하지만 실제가 지속적으로 다름 | 축 표현·관절 제약·PD 응답·접촉 부하를 분리 검증 |
| 접촉이 생길 때만 추종이 크게 나빠짐 | 충돌 쌍·초기 교차·접촉 위치를 우선 점검 |
| 목표와 기하 굽힘의 차이가 좌표 표현에서 발생 | 측정과 제어 좌표를 바로잡고 보상 계수 조정은 보류 |

### 산출물과 통과 기준

- 같은 명령의 목표·실제·부하 시계열, 정면/사선 영상, 원인 분류표.
- codec의 누적·한계·반전·reset 동작과 실제 축 대응을 확인해야 다음 단계로 진행한다.
- 원인 미확정 잔차는 별도 항목으로 남긴다. 손가락별 원인이 같다고 가정하지 않는다.

## 단계 B — ③ 손가락 사이 충돌 적용

### 할 일

1. 왼손 실제 충돌 shape와 기존 필터를 표로 만든다. 비물리 tip/pad proxy는 별도로 유지한다.
2. 다른 손가락끼리와 엄지–다른 손가락 사이를 우선 활성화한다. 같은 손가락의 연속 마디·손바닥 연결부는 구조상 필요한 예외를 유지한다.
3. 모든 필터를0으로 바꾸지 않는다. 실제 허용/차단 쌍을 명시하고 native readback으로 검사한다. 기타·오른손·팔·의자와의 기존 필터 효과도 함께 대조한다.
4. 새 필터를 켜기 전에 준비 자세·B·압현 예시의 원본 형상 교차를 확인한다. 초기부터 충돌 메시가 겹쳐 반발하는 쌍은 연결부 형상/근사 문제와 잘못된 자세를 구분한다. 초기 상태 변경이나 광범위한 충돌 해제를 우회책으로 사용하지 않는다.
5. 충돌 적용 후 1환경 →16환경 →1024환경의 짧은 실제 GPU 시험으로 확대한다. 기존 solver·PD·마찰은 우선 유지해 효과를 분리한다.

### 시험

- 다른 접촉의 영향을 분리할 수 있는 손가락 쌍 시험에서 기존의 교차 명령을 비교한다.
- 준비 자세 유지, B 이동/유지, 손가락별 압현·해제·전환을 검사한다.
- 새 필터에서 기존 명령 테이프를 재생할 수 있으나, 이는 물리 비교 진단으로만 표기한다. 새 계약의 정책 성능 평가나 strict resume로 취급하지 않는다.

### 통과 기준

- 의도한 충돌 쌍과 실제 필터 readback이 일치한다.
- 초기 반발·비유한 값·과도한 관절 속도나 기타 이탈이 새로 증가하지 않는다.
- 충돌을 피하면서 B와 필요한 압현 자세에 도달할 수 있다.
- 원본 convex 교차 지표만으로 실제 cooked 메시의 무관통을 인증하지 않는다. 가능하면 실제 접촉 정보와 동적 반응을 함께 확인하고 API 한계는 보고한다.

## 단계 C — ④의 원인별 개선

### 할 일

- 재현된 codec/축/상태 전환 오류가 있으면 그 부분만 수정한다. 오류가 없으면 제어 방식을 전면 교체하거나 PD를 임의로 낮추지 않는다.
- 정책이 극단 목표를 내는 문제에는 실제 MCP/PIP/DIP 조합, 벌림, native 한계 부근의 지속 요청, task-space 접근의 개선 여부를 함께 사용한다.
- 현재 선택형 shape 항은 DIP−PIP>50도만 보기 때문에 소지90/90/−5도와 검지−42/90/90도를 충분히 구별하지 못한다. 이 사례를 진단·회귀 검사에 포함한다.
- 압현에 도움이 되는 큰 굽힘 자체를 벌하지 않는다. B 권고가 적용되는 휴지 구간과 실제 압현 구간의 모양 평가를 구분한다.
- 상시의 더 강한 자세 보상이 꼭 필요한지는 분리 비교로 결정한다. 필요하다면 극단 조합에 대한 약한 선호부터 적용하고, 동일한 패드 도달·clean 유지가 가능한지 확인한다.
- 관측에는 기존 q/target·실제 굽힘·B gate·다음 음 정보가 이미 있으므로 중복 입력을 무조건 추가하지 않는다. 실제 측정에 비해 빠진 정보만 보완한다.

### 통과 기준

- 적절한 목표에 대한 실제 응답이 정상이며, 지속적인 한 방향 명령·한계 체류·극단 조합 시간이 줄어든다.
- 손가락 가동범위·필요한 굽힘 속도·압현 도달 능력을 줄여 얻은 개선이 아니다.
- 충돌을 더 세게 누르며 겹침만 막는 형태로 바뀌지 않았는지 부하를 확인한다.

## 단계 D — ② 압현 사이 B 진입 확대

### 시간과 보상 설계

1. 손가락별로 압현 유지·해제·대기 복귀·다음 압현 준비를 구분한다. 다른 손가락의 작업으로 자신의 B 권고를 끄지 않는다. 같은 손가락의 겹친 음은 유지 구간의 합집합으로 보호한다.
2. 음 끝 뒤 약50ms부터 복귀 권고를 부드럽게 켜는 것을 첫 후보로 삼는다. 실제 해제 응답과 다음 음까지 필요한 이동 시간을 단계 A/C에서 측정해 조정한다.
3. 초기 간격 분류 후보는 아래와 같다. 검증된 최적 시간이나 모든 자세의 도달 보장이 아니다.

| 같은 손가락의 압현 사이 간격 | B 적용 후보 |
|---|---|
| 0.25초 이하 | 다음 음으로 직접 전환, 완전한 B 왕복을 요구하지 않음 |
| 0.25–0.6초 | 약한 부분 복귀 |
| 0.6초 이상 | B 대역 복귀를 충분히 권고 |

4. 줄/목표4cm 이내라는 이유로 복귀 전체를 끄는 조건을 완화한다. 유지해야 하는 유효 압현은 보호하되, 음이 끝난 잔류 접촉이나 오압현이 복귀를 계속 차단하지 않게 한다. 비유한 측정은 여전히 무효로 처리한다.
5. 손가락 추종과 B의 가중치를 같은 작업 단계에서 전환한다. 손목·팔의2초 선행 이동은 유지하되, 아직 먼 미래 음을 향한 손가락 추종이 B 복귀와 계속 경쟁하지 않도록 한다. 다음 압현 준비가 시작되면 추종을 우선한다.
6. B 굽힘 중심·±15도 대역은 유지한다. 벌림은 특정값 고정보다 넓은 비간섭 영역의 선호로 검토한다. 직접 B 시험의 검지20N 부하를 재현하지 않도록 접촉·벌림·손목 관계를 확인한다.
7. 우선 보상 계수는 현재0.02/초를 유지해 시간 설계 효과를 확인하고, 이후0.04/초를 별도 비교한다. B로 가까워지는 진척 신호를 추가할 필요가 있으면 별도 변형으로 시험하고, gate 전환·H32·reset·종료에서 가짜 보상을 만들지 않는지 검증한다.

### 필수 검사와 지표

- 같은 손가락의 연속 음, 손가락 교대, 동시 음, 짧은 간격, 곡 시작/끝, 한동안 쓰이지 않는 손가락을 검사한다.
- B 최초 진입, 복귀 지연, 대역 점유율, 다음 압현 준비 시작/도착 시각을 손가락별로 기록한다.
- 평가 분모는 악보로 정한 고정 구간도 함께 사용한다. 정책이 gate를 꺼서 점유율이 좋아 보이게 하지 않는다.
- 학습의 첫 통과 목표안은 고정된 **복귀 평가구간**에서 B 점유율80% 이상이다. 평가구간은 `음 끝+해제 여유+복귀 여유`부터 `다음 압현 시각−준비 여유`까지로 정한다. 각 여유는 단계 A/C의 제어 시험으로 사전에 확정하고 모든 비교군에 동일하게 사용하며 정책의 실제 행동에 따라 분모를 줄이지 않는다. 다음 음이 없으면 곡 종료를 오른쪽 경계로 쓴다. 평가구간이0.5초 이상 남는 긴 간격에 이 기준을 적용하고, 짧거나 빈 구간은 완전 B 유지 평가에서 제외한 뒤 다음 음 전환 지표로 평가한다. 초기 도달 시간을 확인한 뒤80% 기준의 타당성을 확정한다.
- 짧은 간격에서는 B 도달률보다 다음 음 도착·clean 유지·불필요한 왕복 감소를 우선한다.

## 단계 E — ① 엄지 넥 뒷면 접촉과 보조 지지

### 역할과 위치

엄지는 압현의 반작용과 넥 흔들림을 받아 주는 보조 지지로 정의한다. 기타 전체 무게를 엄지로 떠받치거나 강하게 감싸 쥐게 하지 않는다.

| 항목 | 첫 설계 후보 |
|---|---|
| 목표 면 | 실제 넥 뒷면의 유한 표면, 옆면·지판 앞면 제외 |
| 폭 방향 | 중앙50% |
| 길이 방향 | 현재 작업 프렛 묶음 중심±4cm, 기존 손목 안내와 일관되게 부드럽게 이동 |
| 엄지 표면 | 끝마디의 굽힘 안쪽 패드 후보를 우선, 가운데 마디는 별도 보조 후보로 검증 |
| 근접 품질 | 표면 간격0–3mm에서 최대, 멀어질수록 부드럽게 감소 |
| 방향 | 엄지의 해당 면이 넥 뒷면을 향할수록 좋은 품질; 손등/손톱 쪽으로 대체하지 않음 |
| 초기 보상 상한 | 엄지 전체0.02/초부터,0.05/초는 후속 별도 비교 후보 |
| 힘 | 클수록 보상하지 않음. 원하는 힘의 수치는 실제 응답 확인 전 고정하지 않음 |

위 범위는 기존 정지 시각화의 제안과 일치시키되, 저장된 정지 예시의 관절각이나 초기 상태를 그대로 강제하지 않는다. 새 충돌 조건의 실제 native 동적 도달을 다시 확인한다.

### 구현과 관측

- 위치·방향·간격은 같은 엄지 표면 표본과 실제 기타 상대 좌표로 측정한다. 부호 있는 간격으로 뒷면 바깥과 깊은 침투를 구분한다.
- 근접 품질이 높은 동일 표본의 위치와 법선을 함께 사용한다. 엉뚱한 점의 거리와 다른 점의 방향을 조합하지 않는다.
- 측정 helper를 관측·보상·진단에서 공유한다. 현재 관측에 없는 패드 간격·영역 초과·방향·접촉 근접 이력 등 필수 정보만 추가하고 관측 계약을 갱신한다.
- 0–3mm 근접 보상과 실제 접촉/부하 지표를 분리한다. 현재 GPU의 net force만으로 엄지–넥 접촉쌍이나 정확한 압력을 인증하지 않는다.
- 프렛 이동 중 짧은 이탈과 넥을 따른 이동을 허용한다. 잠깐 떨어졌다는 이유로 실패 처리하거나 강제로 붙이지 않는다.
- 뒷면 기하 품질 외에도 실제 압현 방해·깊은 침투·다른 손가락과의 교차를 따로 검사한다. 교차는 원본 기하 지표, 과부하는 native 결과력으로 각각 기록하며, 실제 접촉쌍 정보가 가능한 경우에만 상대를 특정한다. 결과력 하나로 엄지–다른 손가락 충돌을 판정하지 않는다. 이 비교에서 간섭이 확인되는 목표·보상은 채택하지 않는다.

### 지지 효과 검증

1. 기존 초기 상태에서 엄지만 목표 영역으로 이동하고 유지하는 실제 Isaac Gym 영상을 촬영한다. thumb 관절 목표와 실제, 뒤쪽 표면 위치·방향·부하를 확인한다.
2. 같은 B/압현·해제 명령에서 엄지 유도 유무를 비교한다. 다른 유지 제어는 동일하게 둔다.
3. 뒤쪽 근접 지속시간뿐 아니라 기타 변위·회전, 다른 지지 부위의 부하, 압현 도달·clean 유지·오압현을 비교한다.
4. 가까워졌지만 과도하게 쥐거나 손가락 도달이 나빠지면 지지 개선으로 채택하지 않는다. 기존 오른손·가슴 지지 때문에 기타가 안정적일 수도 있으므로 안정성 하나만으로 엄지 효과를 주장하지 않는다.

## 단계 F — 통합 시험과 학습 비교

### 규모와 비교 순서

- 제어·충돌·엄지 도달: 1환경 native 영상 →16환경 반복 시험.
- 통합 구동: large/1024/H32의 짧은 실행과 실제 저장·재개 검사. 작은 환경 통과를1024환경 안정성으로 확대하지 않는다.
- 이후 같은 곡·초기화·예산의 짧은 비교 학습을 진행한다. 필요 시100–200업데이트를 진단 예산으로 사용하되 구동 성공을 학습 개선으로 표현하지 않는다.
- 비교군은 충돌만 반영한 기준 → 확인된 제어/모양 개선 → B 복귀 확대 → 엄지 유도 추가로 구분한다. 단계 A에서 제어 오류가 없으면 불필요한 제어 수정 비교군은 만들지 않는다.
- 학습 비교 시 관측 구조를 맞춘 공통 새 초기 모델로 분기해, 보상 추가와 초기화 차이가 섞이지 않게 한다. 기존 A500은 과거 참고 결과로 남긴다.
- 통합판에서 지표와 영상을 확인한 뒤 장기 학습 예산을 정한다. 이전3000회 요청을 이 새 계약의 자동 장기 실행 승인으로 해석하지 않는다.

### 채택 기준

| 구분 | 확인할 내용 |
|---|---|
| 물리 | 의도한 손가락 충돌, 새 초기 반발·비유한 값·부하 급증 여부 |
| 관절 | 한 방향 요청·한계 체류·극단 조합 감소, 가동범위와 필요한 움직임 유지 |
| B | 고정 휴지창의 복귀 지연·점유율 개선, 다음 음 준비 지연 없음 |
| 엄지 | 뒤쪽 영역 근접·방향·지속 개선, 부하·관통·다른 손가락 방해의 악화 없음 |
| 연주 | 평균 달성음, clean 유지, 손가락별 성과, wrong/missing, 안전 완주 |

반복 GPU 평가의 편차를 넘는 연주 성능 회귀가 있으면 전체 평균 보상만 높아졌다는 이유로 장기 학습에 확대하지 않는다. 반복 native 실행과 독립 학습 seed를 구분한다.
