## 1. 목표와 현재 근거

목표는 합의한 준비 상태에서 시작해, 손목이 연주 위치를 안내하고 손가락이 목표에 맞게 접근·압현·유지·해제·다음 음 전환을 배우게 하는 것이다. 움직임 자체를 늘리는 것이 목표는 아니다. 같은 위치 반복이나 이미 올바르게 누르고 있는 경우에는 적게 움직여도 된다.

확인된 근거:

- v23의 같은 초기 네트워크/large128/H32/seed7/각100회 비교에서 기존 incremental은 5.6875/67음·안전114/128, position은0.078125/67음·안전124/128이었다. 위치 제어의 기본 채택은 보류했다.
- 위치 영상의 사전 지정env0은 달성음0·B회복창 체류0이었다. B를 유지하며 정상 압현한 성공 예제가 아니다. 비엄지 목표각 변화는 전곡 최대약0.61도였다.
- 현재 B 보상은 손가락별 압현 준비/음 구간에서0이며, 꺼진 뒤 다음 동작을 자동 실행하는 장치는 없다. 손가락별 출력부·직접 관측·음 개수 균형계수는 이미 존재한다.
- 확인한 현상은 목표각 출력의 정체와 기존 누적 제어의 높은 목표 한계 체류다. 탐색·보상·공유 학습 신호의 개별 기여와 정체의 원인은 아직 분리하지 않았다.

- 035/v14 준비 상태를 에피소드 경계에서 복원한다. 기타는 자유·중력ON·스트랩OFF이고 Root/의자·하체 유한 제어·native48POSITION/57EFFORT·105/97/8을 유지한다.

- 기본 기준군은 incremental이다. position은 명시 실험 옵션으로 남기며 재채택하지 않는다.

- 하나의 새 학습 진입점에서 준비→손가락→공동조정을 자동 진행하게 한다. 외부 전문가 모델·수동 B 자세 적용·별도 BC를 사용자 선행조건으로 요구하지 않는다.

## 3. 단계 A: 진단과 학습 구간을 먼저 만든다

### A1. 팔 이동과 손가락 움직임을 분리해 기록

지정 패드의 동일한 material point를 추적하고, 한 물리 구간에서 다음 두 변위를 계산한다.

1. 이전 손바닥 상대 좌표를 유지했을 때의 패드 위치 변화: 손바닥/기타 상대 이동 성분.
2. 실제 패드 위치와1의 차이: 손가락 내부 관절 운동 성분.

두 벡터 합이 실제 패드 변위와 일치하는지 검사한다. 최근접 표본 교체를 손가락 움직임으로 세지 않는다. 변위 벡터의 길이는 단순 가산되지 않으므로 이를 압현 힘의 기여율이나 성공 원인의 백분율로 표현하지 않는다.

이 진단을 준비/압현/유지/해제/idle로 나눠 기록한다. 초기에는 진단만 추가하고 새 보상으로 쓰지 않는다. 손바닥 좌표계로 목표를 바꾸는 것만으로 팔의 보상 기여가 제거되는 것도 아니다.

### A2. 원곡의 짧은 연속 구간을 학습용으로 선택

새 `song/finger_phrases.py`에서 원본 전체 task를 읽고 구간 카탈로그를 만든다. 목표 길이는2~6개 음으로 시작하되, 동시음·유지음과 경계가 겹치면 구간을 확장한다. 정확히6개에 맞추려고 진행 중인 음을 자르지 않는다. 어떤 음도 정상 구간에 넣을 수 없으면 사유를 기록하고 전체 원곡 평가에서 없애지 않는다.

현재67음에서 [press,end]의 겹침/맞닿음을 합치면20개 묶음이며 크기는 `3,2,1,1,6,3,1,6,10,1,1,1,15,2,1,2,4,5,1,1`이다. 이 닫힌 묶음을 기본 단위로 하고 인접 묶음을 합친 짧은 연속 구간을 추가한다. 10음·15음 묶음도 카탈로그에 남긴다. 짧은 구간에서 긴 구간으로 확장하는 노출 순서를 명시하고, 전체 카탈로그의 ID 합집합이67음을 정확히 덮는지 검사한다.

카탈로그에는 원본67음의 SHA·원본target ID·선택된target ID·source press/onset/end·구간 시작/끝·담당 손가락·회복 가능한 실제 gap을 저장한다. 구간 내부의 중간 음을 골라 빼지 않는다.

GPU 환경은 원본 일정[M]과 환경별 focus_mask[N,M], 시작 오프셋[N], 종료 시각[N]을 가진 학습용 view를 사용한다. 구간 선택은 해당 환경 reset에서만 바꾸며 H32 경계에서는 바꾸지 않는다.

- 로컬 시계는 물리 경과·실패 grace·종료·남은 실패 비용에 쓴다.
- 악보 시계는 로컬 시계+구간 오프셋으로 계산하고 목표/토큰/악보 gap에 쓴다.
- 원오디오 기준 첫 선택 press를 t0, 로컬 경과를 τ, 준비 시간을 P=3초로 두면 source_time=τ−P+t0이며 선택 음의 local_press/onset/end=source_press/onset/end−t0+P다. 기존 SongTask의 준비3초가 붙은 시각을 쓸 때에는 이 차이를 한 번만 보정한다.
- 정책 준비3초를 확보하며 초기 손목 안내는 첫 선택 목표의 안내 영역으로 둔다. 실제 구간에서는 해당 source시점의 안내를 쓴다. 시작 전/끝 뒤의 비선택 음 때문에 안내가 다른 구간으로 넘어가지 않게 한다.
- 학습에서 선택하지 않은 음은 보상·missing·missed·추종 선택기·음별 분모에 끼어들지 않는다. B도 선택된 과제를 기준으로 계산하되 다음 항목의 경계 보호를 예외로 둔다. 원문 일정/ID는 보존하고 로그에 선택 범위를 명시한다.
- 끝 tail을 원곡의 다음 압현 시각까지 제한하고, B의 보호 구간에는 손가락별 다음 원본 음의 준비 시각도 반영한다. 비선택 음에 새 보상을 주려는 것이 아니라 구간을 잘랐다는 이유로 가짜 휴식 보상을 만들지 않기 위한 경계 보호다. 원곡의 회복창과 새 에피소드의 준비3초 체류는 별도 지표로 둔다.
- 종료는 기존 60Hz 경계에서 수행한다. 마지막 음의 end 이후이면서 다음 원본 press를 넘지 않는 종료 tick이 있는지 카탈로그 생성 때 검사한다. 없으면 다음 묶음까지 확장한다. 음을 일찍 자르거나 종료를 올림한 결과 다음 압현을 넘긴 시간을 휴식으로 보상하지 않는다. 이 확장까지 반영해 최종 구간 크기와 67음 포함 여부를 다시 검사한다.
- wrong의 실제 비목표 현/프렛/할당 오류 측정은 유지한다. 비선택 악보를 덜 채웠다는 이유로 감점하는 것과 실제 오압현을 구분한다.
- 구간학습의 달성률과 stage를 전곡67음 달성률/기존256전곡 curriculum에 넣지 않는다. 학습 범위에 맞는 별도 상태를 저장한다.

검지·중지·약지·소지별 구간 bucket을 만들고 환경 reset 횟수에 따라 균등 순환한다. 하나의 구간에 여러 손가락이 있으면 모두 원래 역할대로 평가한다. 실제 선택 순서·노트 기회 수·중복 노출을 기록한다. 특정 손가락이 성공했다는 이유로 다른 손가락의 기회를 없애지 않는다.

검증: 원본 ID/음 길이/동시음 보존, boundary누락/중복0, 선택mask가 측정·보상·분모 전부에 일관되게 적용됨, source/로컬 시계 일치, 부분reset 타환경 불변, 기본 full-song67음/1969tick 불변.

환경 연결에서는 물리 tick과 악보 시각을 별도 함수로 조회하게 한다. native 표본의 `physics_step == local_clock + 1` 검사는 로컬 시계 그대로 유지한다. 손목 안내·표면 potential·이벤트/추종 선택·B·관측·음별 원장·종료/남은 비용의 시간과 범위 사용처를 하나씩 점검한다. 기존 환경 전체를 복제하지 않고 필요한 공용 조회 지점만 분리하며, 기본 경로의 오프셋0/전체 선택은 기존 결과와 일치해야 한다.

## 4. 단계 B: 팔/엄지와 네 손가락의 학습을 실제로 분리

새 정책은 support17(팔·손목12+엄지5)과 finger16(비엄지각4)의 인코더·이벤트 인코더·출력부를 분리한다. 네 손가락의 현재/다음 목표 출력부는 기존 설계를 재사용한다. action벡터39의 실제 관절 순서는 유지한다. 공유 인코더를 그대로 두고 출력부만 동결하는 방법은 사용하지 않는다.

support는 손목 영역·기타 자세·자기 관절·엄지 기하·거친 악보 목표를 본다. 비엄지의 개별 자세/패드 오차/음악 성과 이력을 보고 압현을 대신 해결하지 않도록 입력 필드 목록을 명시적으로 나눈다. finger와critic은 손 전체와 목표 정보를 본다. 같은 거친 장면에서 손가락 전용 관측값만 바꿨을 때 support 출력이 바뀌지 않는 검사를 추가한다.

| 단계 | 학습하는 정책 | 나머지 정책 | 물리 |
| --- | --- | --- | --- |
| R: 손목/지지 준비 | support17 | finger16은 결정론적 초기 명령 | 전부 기존 물리대로 움직임 |
| F: 손가락 획득 | finger16 | R의support17을 동결하고 매60Hz 결정론적으로 재계산 | 기타/팔/손가락 강체 고정 없음 |
| J: 공동 조정 | support17+finger16 | 비활성 오른손 정책0 | 전곡·기존 유한 제어 |

R은 새 준비 상태에서 시작한다. 손목 영역과 지지가 이미 충분하면 긴 사전학습을 의무화하지 않는다. 필요한 경우에만 짧은 안내 학습을 한다. 이는 외부 전문가 준비 절차가 아니라 같은 실행 안의 초기 단계다. R의 압현 성과를 F의 학습 성과로 보고하지 않는다.

R의 최적화 목적은 기존 손목 영역 항·엄지 안내·비손가락 행동 변화·물리 안전이다. 음악 성과는 진단으로 남기되 아직 학습하지 않는 손가락의 missing/missed를 R의 팔 최적화에 섞지 않는다. F/J는 기존 음악 항과 B를 사용한다. 엄지 접촉이나 B 도달을 F 진입의 필수조건으로 추가하지 않는다. 이는 phase별 목적 변경이므로 보상 계수만 같다고 동일 보상이라고 주장하지 않는다.

F에서는 팔이 보상 때문에 더 움직이는 학습을 멈추고, 담당 손가락이 접촉을 만드는 학습에 집중한다. 동결된 팔 정책은 관측에 반응할 수 있으므로 팔의 물리적 정지를 보장하는 단계라고 설명하지 않는다. 손목/손가락 상대 운동 진단으로 실제 동작을 확인한다.

동결은 requires_grad/optimizer대상에서 처리하고 기존 Adam momentum으로 동결 값이 변하지 않게 한다. support/finger의 표준편차도 별도 파라미터로 나눠 필요한 쪽만 학습한다. 동결 파라미터의 gradient를0으로 만드는 것만으로 처리하지 않는다.

확률 계산의 활성 축도 단계별로 명시한다. R은 support17, F는 finger16, J는 왼손33축만 샘플링하고 log_prob·entropy·KL에 포함한다. 동결된 결정론적 출력과 비활성 오른손6축은 이 합에서 제외한다. 물리에 전달하는 전체39축의 순서는 바꾸지 않는다.

critic은 전체 장면·선택 목표·학습 phase·계획한 행동 지속시간·남은 구간 시간을 본다. support 입력에서 phase/탐색 기간처럼 F에서만 바뀌는 제어용 열은 제외하거나 고정 마스킹한다. 관측 목록을 먼저 확정하고 새 차원/scale/순서를 계약에 봉인한다. 기존552 모델이라고 가장해 재개하지 않는다.

먼저 K=1(기존60Hz)·대각 Gaussian·기존 보상으로 A와 B만 비교한다. 정책 분리·부분곡만으로 개선되는지 확인하기 전 탐색 변경을 결합하지 않는다.

## 5. 단계 C: 공통 굽힘을 탐색하되 독립 제어는 남긴다

새 제어 목표를 강제로 섞는 대신, 우선 탐색 분포만 바꾼다. 정책 평균은 기존 실제 관절 latent공간에 둔다. MCP/PIP/DIP3축의 Gaussian 표본을 다음 직교 기저로 구성한다.

```text
공통 굽힘       (1, 1, 1) / sqrt(3)
근위·중간 차이  (1,-1, 0) / sqrt(2)
말단 분담 차이  (1, 1,-2) / sqrt(6)
```

초기 표준편차는 공통축=sqrt(2)σ, 차이축2개=σ/sqrt(2)로 둔다. 그러면 각 실제 관절의 초기 주변분산은 기존σ²와 같고 상관계수는0.5다. 탐색 크기 증가와 협응 효과를 첫 비교부터 혼합하지 않는다. 이 관계는 초기화 조건이며 이후 기저별 표준편차를 독립 학습한다는 점을 계약에 기록한다.

기저가 full rank이고 차이축 분산도 양수이므로 관절을 고정 비율로 묶지 않는다. 벌림/엄지/팔의 분포는 이 비교에서 바꾸지 않는다. 기존 tanh·native범위·4rad/s를 유지한다. 평가에서는 잡음을 제거하므로 공통 굽힘 명령을 자동 삽입하지 않는다.

log_prob는 실제 latent와 정책 평균을 모두 역기저로 변환한 Gaussian 밀도와 실제 관절 latent의 tanh 보정으로 계산한다. KL도 역기저의 평균 차이를 사용해야 하며 기존 실제 관절 대각분산 KL을 그대로 사용하지 않는다. 직교 행렬·양의분산·역변환·독립 다변량 Gaussian 계산과 대조한다.

초기 준비 자세가 이미 일부 native한계에 있으므로 공통 굽힘도 특정 마디에서 막힐 수 있다. 실제 관절별 탐색 범위·포화·패드 운동을 검사하며, 끝관절만 더 움직이면 이 탐색안을 채택하지 않는다.

## 6. 단계 D: 손가락 전용 단계에서 시간적으로 이어지는 탐색

이 단계는 C와 별도 비교한다. F에서만 정책 결정을 최대3tick(50ms) 유지하는 조건부터 시작하고6tick(100ms)은 후속 비교로 둔다. 결정 시 선택한16축 명령을 실제로 유지하며 저수준 목표/PD/물리는60/240Hz로 계속 계산한다. 동결된 support정책은 매60Hz 새 관측으로 결정론적 출력을 계산한다.

R과 최초 J는 K=1을 유지한다. 학습 중인 팔은 매tick 새로 샘플링하면서 손가락만 유지하는 복합 확률 구조는 첫 버전에 넣지 않는다.

정책 결정에는 계획한 지속시간을 관측으로 제공한다. 가까운 선택 음의 press/onset/end 및 학습 수집 경계가 오면 결정을 짧게 끝내고 다시 샘플링한다. 짧은 음을 건너뛰거나 이전 음의 행동을 다음 음까지 무조건 유지하지 않는다. 정확한 물리 접촉 판정은 계속240Hz다.

현재 곡의 최단 audible 길이는 약0.0232초다. 목표 이벤트에 대응하던 원래60Hz 제어 경계보다 늦게 새 결정을 하지 않도록 구간을 나눈다. 이벤트를 지나친 뒤의 ceil 경계까지 기다리는 방식은 쓰지 않는다. dense 구간에서는 결과적으로 K=1이 될 수 있다.

### 결정 단위 수집/PPO 계약

기존처럼 매tick 같은 행동의 log_prob를 반복 계산하지 않는다. 하나의 결정에는 시작 관측·한번 샘플링한 latent/분포·실제 지속 d·마지막 reset전 관측을 저장한다.

```text
R       = sum(i=0..d-1, gamma^i * reward_i)
C       = sum(i=0..d-1, cost_gamma^i * cost_i)
delta   = R + gamma^d * bootstrap_mask * V_next - V_start
GAE연결 = (gamma * lambda)^d * continuation_mask
```

비용은 별도 cost_gamma를 사용한다. terminated에서는 bootstrap을0으로 하고, truncated에서는 해당 계약에 맞는 reset 전 최종 관측으로 bootstrap한다. 두 경우 모두 에피소드 간 GAE 연결은 끊는다. 유한 구간의 자연 종료는 새 task의 terminal로 정의하고, 외부 time-limit truncation 및 수집 경계와 구분한다. 기존 full-song의 reason/음악 집계 정의와 별개로 기록하며 이 계산을 기존 v22와 동일하다고 설명하지 않는다.

시작 가치 V_start에는 그 결정의 계획 지속시간을 넣는다. V_next에는 다음 결정에 대해 이벤트/수집 경계를 반영해 미리 계산한 계획 지속시간을 넣는다. 실제 d는 할인 지수에 쓰며, 실패 때문에 짧아진 d나 이전 결정의 계획 길이를 다음 가치 입력으로 재사용하지 않는다. H32 경계의 bootstrap도 다음 rollout에서 시작할 결정의 계획 길이를 기준으로 계산한다. true terminal에는 다음 가치가 없다.

한 환경이 결정 중간에 실패하면 해당 길이 d로 전이를 확정하고 그 환경만 기존 경계 reset을 수행한다. 다른 환경의 결정은 이어간다. H32 끝에서는 진행 중 결정을 짧게 확정하고 bootstrap하되 장면·곡·원장은 유지한다. PPO업데이트 뒤에는 반드시 새 행동을 선택한다. 이전 정책의 유지 명령을 다음 업데이트 수집으로 넘기지 않는다.

현재 PPO/collector의[T,N] 완전 격자를 새 결정 버퍼로 재사용하지 않는다. 유효mask가 있는[decision,N] 또는 동등한 비정형 저장 구조를 별도 모듈에 구현하고 GAE·정규화·loss·KL·critic·진단 전부에서 padding을 제외한다.

기존60Hz raw journal은 계속 남기고, decision journal에는 시작/끝 control tick·episode ID·정책 버전·계획 길이와 실제 d·discounted합계·종료 종류·원시행 참조를 기록한다. 결정1개를 기존 control 전이1개로 세지 않는다.

검증: 수동 계산한 d=1/2/3/6의 보상·cost·GAE, 중간 실패·자연 종료·H32 cut·부분 reset·padding·노트 경계·저장/재개를 검사한다. K=1에서는 같은 새 family의1tick 기준 계산과 일치해야 한다.

## 7. 보상은 어디까지 바꾸는가

초기 F/J 비교에서는 보상v22의 접촉·clean·wrong/missing/missed·엄지와B 계수를 유지한다. 구간/phase의 범위 마스크는 새 계약으로 구분하고, 계수 변경을 섞지 않는다. R의 안내 학습 목적과 F/J의 음악 목적을 로그/계약에 분리한다.

R/F/J는 기존 음악 stage0/1/2의 이름을 바꾼 것이 아니다. 첫 A~E 구조 비교에서는 모두 v22의 초기 음악 그룹 비중(wrist .2, contact .5, timing .5, approach 1)을 고정하고 기존 256곡 기반 자동 진급을 적용하지 않는다. 이 비교의 계약과 기준군에 함께 기록한다. 손가락 균형식도 선택된 과제의 `M_focus / (presentF_focus * n_f_focus)`로 계산하며 원곡67을 부분곡 분자에 남겨 보상을 부풀리지 않는다. 전곡 평가의 분모는 계속67이다.

- B는 본인 idle에서만 약한 선호이며 압현 준비·음 구간에서는0이다. 준비 자세와 B를 혼동하지 않는다.
- 손가락이 움직였다는 이유만으로 보상을 주지 않는다. 충분한 접촉 뒤에는 움직임이 적어도 clean 유지·달성 보상을 받는다.
- 팔/기타 상대 이동과 손가락 운동의 기여는 우선 진단한다. 관절을 일정 각도 이상 움직여야 음 성공으로 인정하는 새 조건을 넣지 않는다.
- 협응/탐색을 고쳐도 자세 문제가 남는 경우에만 idle의 벌림·극단 조합·B 복귀 개선을 별도 비교한다. 압현 중 고정 비율 prior나 추가 움직임 비용을 넣지 않는다.
- 최초 접촉 과정에 추가 보상을 검토한다면 목표 교체/phase 경계/왕복 동작에서 중복 지급되지 않는 예산 또는 potential 계약부터 정의한다. 이번 기본 계획에는 새 ‘움직임 보너스’를 포함하지 않는다.

## 8. 학습 단계 전환과 평가

자동 단계 전환의 초기 후보 기준은 아래와 같다. 실제 도달성과 비교 자료로 조정해야 하는 잠정값이며 정상 압현의 정의가 아니다.

1. R→F: 고정 구간 평가에서 안전완주90%·실제 손목 안내 영역 체류80%. 준비 상태가 이미 충족하면 R을 길게 학습하지 않는다.
2. F→J: 네 손가락 각각 평가 기회64음 이상·연속 clean 달성20% 이상·안전 완주90%. 한 손가락의 높은 성과로 다른 손가락을 통과시키지 않는다. 이는 중간 진입 기준이며 숙련 완료가 아니다.
3. 단계별 전이 예산을 둔다. 예산 소진 때 기준을 몰래 낮추거나 무조건 진급시키지 않고, 해당 단계의 정체/진단을 결과로 남긴다. 사용자에게 수동 전문가 준비를 요구하는 gate로 만들지 않는다.
4. J에서는 원래67음 전체로 학습·평가한다. 부분곡 성과를 전곡 성과로 합산하지 않는다.

### 단계 전환과 재개 경계

전환은 진행 중 결정을 확정하고 이전 단계의 PPO 업데이트/기록 commit을 마친 공통 경계에서만 한다. 이전 단계의 버퍼를 다음 단계의 정책/목적으로 재사용하지 않는다. 단계 말 checkpoint와 원장을 보관한 뒤 해당 실행을 종료하고, 같은 자동 실행 관리자가 다음 단계를 새 준비 에피소드로 시작한다. 전곡을 연주하던 도중 새 단계라고 이름만 바꾸거나 장면을 덮어쓰지 않는다.

F→J에서는 모든 환경의 focus를 전체67음으로 바꾸고 원곡 시작/종료 범위를 복원한다. 끝내지 못한 이전 단계 에피소드는 중도 관측 자료로 남기며 완주/성공으로 세지 않는다. 전환 기준은 별도 고정 평가의 완결 에피소드로 판단한다. 마지막 수집의 bootstrap은 해당 이전 단계의 계속 상태 가치이며 다음 단계의 가치와 섞지 않는다.

이 내부 전환은 명시적인 phase_transfer다. 정책 가중치를 넘기되 단계별 목적/학습 대상이 바뀌므로 actor/critic optimizer는 새로 만들고 critic 가중치도 새로 초기화한다. 옮긴 정책·동결 대상·초기화한 상태·단계별 RNG seed를 기록한다. 반면 같은 단계의 strict resume는 모델·optimizer·RNG·구간 sampler·계약을 그대로 복원하는 기존 엄격 재개이며, 두 작업을 같은 것으로 설명하지 않는다.

예비 비교는 large/128환경·같은 원곡·같은 초기 상태·물리 조건으로 진행한다. 새 family 안에서 네트워크 초기화와 support 준비 상태를 맞춘다. 기존 v23 결과는 참고군이며 새 아키텍처와의 차이를 탐색만의 인과 효과로 설명하지 않는다.

| 비교 | 바꾸는 요소 | 고정하는 요소 |
| --- | --- | --- |
| A | 새 family 기준: 전곡·공동 학습·K1·독립 탐색 | native/보상 계수/성공 정의 |
| B | 연속 구간 균등 학습만 | 같은 새 family·K1·독립 탐색 |
| C | R/F/J 정책 학습 분리 | B의 구간·K1·독립 탐색 |
| D | 공통 굽힘 상관 탐색 | C·초기 관절 주변분산·K1 |
| E | F의3tick 지속, 필요시6tick | D·R/J는 K1 |

각 단계는 먼저 같은 실제60Hz 전이 예산 약100만개로 선별하고 유망 조건은3seed로 확인한다. 결정 수/optimizer step 수/전체 표본 pass 수/벽시계 시간도 기록한다. K가 달라지면 모든 계산량을 동시에 같게 만들 수 없으므로 반복 횟수만 같게 두고 동량이라 부르지 않는다.

전체 pipeline 예산에는 R/F/J 학습과 정책 준비 시간을 모두 포함하고, 전환 평가의 전이는 별도로 공개한다. 중도 마감한 에피소드의 실제 사용 전이도 제외하지 않는다. D/E의 F 탐색 비교에서는 seed별로 같은 R checkpoint를 복제하고 공통 준비 비용을 공개한다. R 유무·보상 목적이 다른 A/B/C를 탐색 하나만의 인과 비교라고 설명하지 않는다.

최종 지표는 전곡 평균/손가락별 달성·연속 clean·wrong/missing·안전·실제 각 관절 운동·목표 한계 체류·곡에 실제로 존재하는 B 회복창 체류·팔/손가락 변위 성분·엄지 후보이다. 실패/미관측 꼬리를 고정 곡 분모에서 빼지 않는다. 원래67음 전체 고정 평가와 사전 지정 env0의 손/전신 영상, 각 손가락 대표 목표의 가까운 영상을 저장한다. 한 seed의 총달성만 늘고 다른 손가락이0이면 해결로 채택하지 않는다.

고정 평가·렌더도 새 policy family를 명시적으로 선택하고 동일한 결정/제어 계약으로 실행한다. 구형 SpecialistPolicy만 가정하는 로더를 암묵적으로 재사용하거나 checkpoint 검증을 완화하지 않는다. J의 평가는 원곡 시각·67음·기존 clean/실패 기준으로 하며 학습 구간의 분모를 가져오지 않는다.
