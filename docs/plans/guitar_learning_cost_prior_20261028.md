# 다음 단일 원인분리: 비용 예측기의 초기값

V4와 V5는 같은 초기 가중치·seed7·PPO300으로 비교했으나, 둘 다 마지막 A음 달성이 0회였다. V5의 실제 실패 비용은 300회 모두 0이었다. 반면 150회 비용 advantage 표준편차는 약 0.09868, 비용 target 평균은 약 −0.17288이었다. 이는 실제 실패 비용과 다른 예측·부트스트랩 신호이며, 후반 퇴행의 단독 원인이라고 확정하지 않는다.

사용자가 승인한 학습 실패 진단·보상과 전환 개선의 후속 비교다. 기존 원자료와 봉인된 소스는 보존하고 새 진단 버전에서 진행한다.

1. **비용 critic 마지막 층의 초기값만 변경한다.** 마지막 Linear의 가중치와 편향 2개를 fresh 생성 직후 0으로 둔다. 원래 생성 난수는 그대로 소비한다. 다른 69개 텐서, fit 자료와 1000회 예산, PPO 설정, seed, 128환경/H32/300회, 선택 4축, 물리·범위·PD, 보상 9개와 A 정산은 유지한다. 실패 비용 계산·종료·`cost_weight=1`도 유지한다.
2. **CPU에서 변경 범위와 학습 가능성을 검증한다.** 실제 Python3.8에서 2개 텐서만 다르고 나머지는 같은지, 초기 비용 예측과 비용 관측 0의 GAE 신호가 0인지 검사한다. 양의 비용이 주어지면 critic이 학습할 수 있는지도 확인한다. 현재 체크포인트 검증을 완화하지 않고 새 계약의 fresh 모델을 만든다. 독립 검수 후 입력을 봉인한다.
3. **초기 모델과 실제 동작을 대조한다.** fresh와 fit 모델의 나머지 69개 텐서가 같은지 확인한다. 초기 고정·확률 평가를 각각 128시도 실행해 동작과 음별 수행이 동일한지 검증한다. 비용 가치 변경을 정책 평균·분산 변경과 구분한다.
4. **같은 학습·평가 예산으로 비교한다.** PPO300, 50회 간격 고정 평가 6개, 마지막 확률 평가를 수행한다. 실제 비용과 cost advantage, value·target, KL 재시도와 실제 학습률, 9개 보상, A 연속 압현·해제·동시 성공을 비교한다. KL 재시도와 실제 학습률의 후속 차이는 개입의 결과로 기록한다. 마지막 모델 영상도 남긴다.
5. **원래 전환 범위를 유지한다.** 수용 기준 통과 전에는 J33·다른 손가락·자유 기타·67음의 성공으로 확대하지 않는다. 개선이 있으면 다른 seed로 재현하고 원계획의 전환을 평가한다. 개선이 없다면 실제 관측·동작과 보상별 정책 기울기를 이용해 전환과 제어 간섭을 분리한다.

이 비교는 실패 비용을 유지하는 초기값 실험이다. 동일300회 비교와 후속7평가를 완료했다. 비용 신호는 전구간0이지만 첫 음 달성은100회 모델부터0이고 마지막에는 오압현이1.0이다. 이 변경만으로 퇴행을 해결하지 못했으며 생산 코드에 채택하지 않았다. 마지막300의 손/전신 영상과 실제 학습·평가·분석·영상 독립 검수를 완료했다. 입력 불변·동작/원장 동일성과 영상 규격은 PASS이며 음악 수용 기준은 미달이다.
