# 자원 활용 장기 학습

사용자 요청: 현재 방법으로 컴퓨팅 자원을 최대한 활용하는 설정을 정하고 이전 연결 검사보다 길게 실제 학습한다.

전제: 최신 musical_quality563 손별 경로와 보상·물리 조건을 유지한다. CPU PhysX가 병목인 현재 구조에서 GPU 사용률 수치보다 유효 전이 처리량과 안정적인 메모리 여유를 기준으로 선택한다. 우선 총 약2시간의 실행 예산(업데이트 경계의 soft 제한)을 사용하며 최신 손별563 정책에서 strict resume하는 것을 우선한다. 사용자가 시간을 지정하면 반영한다.

- [x] 실제 호스트 자원과 최신 checkpoint/optimizer 상태를 읽는다.
- [x] 현재 코드에서 N8/N16 짧은 처리량·메모리 비교를 수행한다. 필요하면 두 손 N8 동시 실행을 비교한다. 과거16환경의 메모리 문제를 무시하지 않는다.
- [x] 유효 처리량과 메모리 여유에 따라 총 worker 수·rollout·동시/순차 배치를 선택한다. 설정·원본 모델·소스를 봉인한다.
- [x] 제한된 장기 학습을 실제로 시작하고 초기 업데이트의 음악 품질·KL·비용·자원을 확인한다. 실행은 터미널/채팅 수명에 의존하지 않게 관리한다.
- [x] 실행 경로·중단/재개 방법·선택 근거·실제 경과를 문서에 남기고 검수한다. 정상 종료 또는 실패 시 모델·실행 결과를 보존한다.

코드 변경은 필요한 문제가 확인된 경우에만 새 보관 버전을 만든 뒤 수행한다. 기존 실행·실패·모델은 덮어쓰지 않는다. 자원 부족 보호를 끄거나 임의의 다른 프로세스를 종료하지 않는다.
