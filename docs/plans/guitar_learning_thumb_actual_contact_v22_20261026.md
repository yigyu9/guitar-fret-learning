# v22 엄지 실제 접촉 후보 보완

사용자의 추가 필요 작업 자율 진행 지시에 따른 보완이다. 기존 v21 실행 자료·원문은 그대로 보존한다.

## 발견한 문제

v21의 세 조건100회 비교에서 통합판은 평균5.1484/67·안전128/128였지만, 엄지3 native 결과력 평균·최대가0이었다. 기하 근접0~3mm에서 최대 .02/s를 주므로 실제 접촉 없이 떠 있어도 최대 보상이 가능했다. B 고정창 점유율도 네 손가락 모두0으로 남았다. v21의 B .04/s 비교와 직접 B복귀 시험은 별도로 완료해 원인을 분리한다.

## 구현과 검증 순서

1. 기존 v21 비교를 끝내고 변경 원문·소스 SHA를 보관한다. 활성 소스는 실행 입력 pin이 끝날 때까지 변경하지 않는다.
2. 엄지의 동일 패드점 기하 안내 최대 .01/s와 접촉 후보 추가 최대 .01/s로 나눈다. 후보는 gap[-1,.5]mm·유한 후면 영역·방향과 엄지3 기타 좌표계 합력의 후면 법선 성분≥.01N을 함께 요구한다. 큰 힘에 더 많은 점수를 주지 않는다. 결과력은 접촉 상대나 정확한 압력 인증이 아니므로 표현은 접촉 후보로 제한한다.
3. helper의 실제 candidate1열을 기존551에 추가해552상태·reward.v22·thumb_support.v2·diagnostics.v5로 기록한다. 기존 valid와 B/손가락 자유도·비용0·물리·초기 상태는 유지한다. v21 이하 strict resume는 거부한다.
4. 정지 근접 유지와 작은 엄지 목표 조절의 native GPU 대조로 접촉 후보 도달·유지·해제·재접근, 몸체 결과력·기타 이동·소스 형상 간섭을 확인한다. 목표 조절은 진단 명령이며 생산 제어를 바꾸지 않는다. 상태 주입·강제 부착·기타 보조 힘은 없다.
5. 관련 CPU검사·독립검수를 거쳐1024 저장/재개, 새 v22의100회 짧은128환경 학습과 고정 평가·영상을 확인한다. 새 관측으로 초기화가 달라지므로 v21과의 성과 차이를 보상 단독 인과 효과로 해석하지 않는다.
6. B .04 비교와 native 복귀 시간의 결과를 반영하되, 성과가 개선되지 않은 계수를 기본으로 올리지 않는다. B80%는 미충족을 숨기지 않고 실제 상태와 채택 범위를 문서화한다.
