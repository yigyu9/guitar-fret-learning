# 음악 조건 공동 제어 모델 파이프라인 설계

## 관절 역할과 하체 자세 유지 학습의 설계 기준

[관절별 역할과 제어 원칙](/home/ajou/yigyu/3/docs/2026-10-12/stability_adapter_2/results/joint_role_design_v1/README.md)에 주 역할·보조 역할, 관측·보상·목표 소유권, 학습 단계와 평가를 상세히 정리했다. 접촉 분담은 유연하게 허용하고, 왼손 압현 반력과 기타 무게 지지를 구분하며, 자세 유지와 기타 안정성을 따로 평가한다.

현재 구현은39정책/66기준 목표의105채널 CPU 계약이다. 하체의 가동16축을 추가하는55정책/50기준 목표는 권고 시작 설계이며 아직 구현·학습하지 않았다. 역할을 부여한 것만으로 몸통·오른쪽 근위부15개의 목표 변경 권한이 추가되지는 않는다. 이번 갱신은 문서화이며 native 환경·코드·체크포인트는 변경하지 않았다.

## 최신 방향 변경 전신 관절 제어와 root 고정

사용자는 최종적으로 root를 제외한 전신 관절을 사용하며 초기 자세 유지도 제어 역할에 포함하기로 했다. 새 음악 환경은 하체 관절이 제거된 fixed-lower 대신 하체를 포함한 관절 feedback 제어를 목표로 한다. 연주 정책 출력39개와 기준 자세 유지66개를 합친105채널 목표·유한 PD 명령의 CPU 계약을 `music_pipeline_v3`에 구현하고5개 테스트를 통과했다. 원본 관절 한계가0인8축은 유지하므로105채널과97개의 비영 가동 범위를 구분한다.

현재 초기 자세 연구와 아래81채널 native 실행은 기존 조건으로 보존한다. 새로운105차원 초기 배치·물리 관측·native 제어 연결은 초기 자세 연구와 함께 후속 구현한다. 이번 결과를 이미 전신 native 제어·연주를 달성한 것으로 설명하지 않는다. 신경망이 모든 관절 목표를 학습한다는 주장과도 구분한다. [구현·검증과 논문 표현 범위](/home/ajou/yigyu/3/docs/2026-10-12/stability_adapter_2/results/wholebody_control_v1/README.md).

2026-10-15 개선안. 현재 설계는 **음악 시각과 사람–기타 상호작용을 함께 관측하는 공동 정책**이다. 기존 코드·파일럿·선택 곡과 관련 연구를 검토하여 입력, 과제 판정, 학습 목적과 갱신 절차를 보완했다. 세부 근거와 수식·비교 실험은 [상세 설계 검토](/home/ajou/yigyu/3/docs/2026-10-12/stability_adapter_2/results/pipeline_learning_design_v2/README.md)에 있다.

초기 자세 연구와 독립적으로 모델·학습 구조의 CPU 구현을 진행했다. 사용자 지지 자세 조건을 반영한39행동 정책·음악 기록·PPO와26개 테스트를 완료했다. 세부 native 환경 연결과 재학습은 초기 자세 확정 후 수행한다. [구현과 검증](/home/ajou/yigyu/3/docs/2026-10-12/stability_adapter_2/results/music_pipeline_v2/README.md). 우선 곡은 `05_BN2-131-B_solo`, 최종 타이밍 주 지표는 ±50ms, ±100ms는 진단이다.

## 왜 개선하는가

기존 파일럿은 첫 단음 접근이 거의 개선되지 않았고 접촉·유지에 실패했다. 조사 결과 정책이 사용하지 못하는 과제 이력, 일부 짧은 음에 불가능한 유지 조건, 첫 PPO step부터 큰 정책 변화가 확인됐다. 이러한 문제를 먼저 해결해야 모델 구조를 공정하게 비교할 수 있다. 단순히 네트워크를 크게 만드는 것을 우선하지 않는다.

## 개선된 정보 흐름

```mermaid
flowchart LR
    A[오디오와 기존 탭 운지 처리] --> B[음악 이벤트와 고정 시계]
    B --> C[현재 목표와 시간 창 안의 미래 목표]
    D[사람 기타 상태와 접촉 및 과제 진행] --> E[상대 기하와 안정성 여유]
    C --> F[음악 및 물리 특징 결합]
    E --> F
    F --> G[공동 actor]
    G --> H[겹치지 않는 관절 목표 출력]
    H --> P[유지 목표66과 합성한 전신 관절 제어]
    P --> I[물리 환경]
    I --> D
```

## 입력과 출력의 결정

- **목표:** 현재 유지 중인 음과 다음 음의 준비를 별도 표현한다. 미래 창은 초 단위로 비교하며, 용량 초과를 조용히 잘라내지 않는다.
- **물리 상태:** 기존 상대 위치·속도에 할당 손가락–목표점 오차, pick–줄 관계와 부위별 접촉 후보를 명시적으로 제공한다. world 중력·기타 허용 범위 정보도 유지한다.
- **과제 진행:** 연속 dwell·누적 hold·owner·이미 매칭한 이벤트·해제 상태와 남은 시간을 입력에 포함한다. 필요 정보가 관측 가능한지 먼저 확인하고 메모리 네트워크는 이후 비교한다.
- **공동 행동:** 왼팔·왼손33과 오른쪽 팔꿈치·손목6을 하나의 공동 actor가 결정한다. 가슴·상완 지지부15, 오른손 피크 그립21, 목·머리6과 하체24의 목표는 외부 초기 기준을 유지한다. 새 계약은 하체를 포함한105채널이며 실제 각도·속도에 따른 유한 feedback을 계산한다. 원본 range=0인8축은 비영 가동 자유도로 세지 않는다. 왼손에 필수 악기 지지 역할을 부과하지 않는다.
- **행동 의미:** 새 reset 계약의 기준 목표에 대한 제한된 오프셋을 기본 후보로 둔다. 기준 목표·직전 최종 목표·제어 범위를 관측한다. 39행동/105목표와 전신 PD 명령 계약을 구현했고 action scale과 실제 물리 관측 ABI는 새 환경에서 확정한다.

## 네트워크의 시작점

먼저 위 입력을 모두 제공하는 flat MLP를 유효한 기준 모델로 둔다. 개선 구조는 물리 상태 encoder와 이벤트별 encoder를 나누고, 현재 상태를 query로 하는 작은 attention pooling으로 미래 목표를 요약한다. 현재 목표와 가장 가까운 deadline은 별도 경로로 보존한다. 공동 actor의 출력은 역할별로 구분해 기록하되 단순 선형 head 분할 자체를 협력 기여로 주장하지 않는다.

actor와 value의 encoder는 파라미터를 분리하는 구성을 권고한다. 음악 value와 안정성 cost value는 각각의 반환값 단위를 유지한다. 고정 비용 가중치 기준군과 안정성 budget을 사용하는 목적을 비교한다. 별도 motion generator·world model·큰 Transformer는 첫 구조에 포함하지 않는다. 작은 pooling 구조도 성능 향상이 입증된 선택이 아니라 비교할 후보다.

## 과제와 학습의 보완

1. **달성 가능한 판정:** 유지 성공은 실제 음 길이에 대한 유효 유지율로 정의한다. 접촉 준비와 onset 정확도를 따로 측정한다. 100ms보다 짧은 음에 100ms 유지를 요구하지 않는다.
2. **평가 일관성:** ±50ms와 ±100ms 매칭 기록을 독립적으로 관리한다. 준비가 늦어도 음악 시계나 원래 onset을 이동하지 않는다.
3. **공동 목적:** 음악 성과를 최대화하면서 명시된 안정성 비용 budget을 만족시키는 목적을 설계한다. 기대 비용 제약을 모든 순간의 안전 보장으로 설명하지 않는다.
4. **학습 신호:** 접근을 돕는 보조 신호와 실제 연주 성공을 분리한다. potential-based shaping을 후보로 두고 시간·이벤트 상태·terminal 처리를 일관되게 만든다.
5. **갱신 제한:** 첫 actor minibatch부터 KL을 검사한다. 과도한 갱신을 복원할 때 weight와 optimizer state를 함께 복원한다. 탐색 분산과 학습률을 같이 보정한다.
6. **종료 의미:** 구절의 진짜 끝은 terminal, 계속되는 과제의 수집 예산 cut만 truncation으로 구분한다. cost critic과 budget의 할인·분모 정의를 일치시킨다.
7. **단계적 학습:** 자유 기타 조건을 유지하며 지지+이동→한 음 cycle→전환→짧은 구절로 진행하고 이전 과제를 일부 혼합한다. 승급은 실제 음악·안정성 지표로 판정한다.

## 다음 구현 전에 받을 환경 계약

안정적인 reset 상태와 허용 변동, 실제 제어 관절·접촉 surface·목표 도달 가능성, 물리 실패와 simulator 오류의 구분, 안정성 budget·유지율·debounce 기준을 초기 자세 연구와 새 환경 구현에서 결정한다. 기존 fret·strike 환경은 참고하되 고정 기타를 전제한 목표·접촉·보상·종료 가정은 재검토한다. 기존 가중치는 이식하지 않는다.

현재 곡은 지원 이벤트65개 중6개가100ms 미만이고, 첫 같은 줄 전환의 여유가0초다. 따라서 단음과 전환 과제를 구분해서 구현해야 한다. 미지원 `event-000042`는 동일 줄의 빠른 재타현에 관한 계약 제한이다. 전체 곡 지원을 완료한 것으로 간주하지 않는다.
