# v5 합성 목표 연결과 실행 안내 정돈

사용자 승인: v5 학습 구조를 정돈하고 새 곡이 아닌 목표 C1~C6를 사용할 수 있게 준비.

## 범위와 판단

- 원본은 docs/2026-11-09/압현_연속목표_손가락조합_v1/입력의 6개 조합이다. 각각43.75초·20음·20누름·P1~P9 연속 시간축이다.
- 기존 v5 신경망·관측·보상·제어·노출 일정과 봉인 소스는 유지한다. 역할별 파일 안내와 목표 선택 실행 경로를 정리한다.
- 조합별 등록 ID는 press_sequence_c1_v1부터 press_sequence_c6_v1까지로 한다. 한 실행에서 한 조합을 선택하며 여섯 조합 혼합 학습은 이번 범위에 추가하지 않는다.
- 학습용 파생 번들에서 원본의 줄·프렛·손가락·시각·해제·P7 연속 유지·P9 재압현을 보존한다. 기존 compiler의 strum 시간차 때문에 동시 목표가 이동하지 않는지 실제 최종 task와 대조한다.
- 원본 CSV/JSON·생성 근거를 번들 안에 보존하고 파생파일과 함께 SHA를 검사한다. 무음 파일이 형식상 필요하면 합성 시간축 운반용이라고 명시하며 실제 음악/타현 성공으로 해석하지 않는다.
- 학습 전 기존3초 준비와 말미0.5초는 유지한다. 원본 시각에 준비3초가 더해지고 전체47.25초가 되는지 검사한다.
- 새 목표를 연결하기 위한 생성·검사 도구와 얇은 v5 실행 도구만 추가한다. 기존 설정/학습 루프/정책을 복제하지 않는다. 기존 checkpoint 검증을 우회하지 않는다.

### 확정한 시간 연결

공식 타현 계획은 동시 두 음에 ±3.5ms 순차 타현 간격을 넣는다. 이를0으로 바꾸거나 동시single events를 넣으면 기존 물리 계획 검사를 통과하지 못한다. 따라서 타현 계획은 그대로 검증하고, 새 C 전용 runtime에서만 원본 압현 clock을 적용한다. 공식 make_task를 먼저 실행한 뒤 원본의 mapping_note_index로20개를 대조하고 onset/source_onset만 원본값으로 되돌린다. target ID·누름·해제·줄·프렛·손가락과47.25초 길이는 보존하며 provenance에 보정 전후 시각과 압현 전용 의미를 기록한다. 기존v5/공용Python을 수정하지 않고 새 context가 필요한 task factory를 주입·복구한다. 타현 정책에서 이 adapter를 사용하지 않는다.
