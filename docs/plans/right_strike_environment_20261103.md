# 타현 환경 구성 실행 계획

사용자 승인: 기존 물리·학습 기반을 재사용해 피크 타현 준비→통과→회복을 먼저 검증한다. 실행 코드는 guitar_learning, 목표 입력은 data, 모델·원시 기록은 runs, docs에는 문서·분석·대표 영상만 둔다. 기존 봉인 소스·입력·모델·원장은 수정하지 않는다.

1. [x] 오른손 단일 목표 입력·설정 생성 → 검증: standard3번줄/runtime2, down+1, actual onset3초, episode5초·300tick, SHA·오염 거부.
2. [x] RightStrikeEnvironment 추가 → 검증: 기존 판정/보상/물리 상속, 준비2관측·타현1회·이후 회복2관측·안전·오타현/중복 회귀 검사.
3. [x] CLI·기존 GPU/PPO 연결·엄격 모델 평가·native 제어 진단 구현 → 검증: 원 input/identity 검증 유지, 오른손6축만 행동, 시작 중간 상태 재주입 금지, 실제 원시 기록·카메라 출력.
4. [x] 독립 change-reviewer 검토·CPU 검사 후 명세 봉인. GPU 유휴 확인 후에만 1환경 실제 진단 실행. 다른 사용자/실험 프로세스를 중단하지 않는다.
5. [x] 결과·한계·현재 상태·다음 명령 기록. 실제 목표 경로 미확보는 물리적 불가능으로 해석하지 않으며 장시간 학습의 성공으로 대체하지 않는다.

초기 범위는 피크그립 유지/오른팔꿈치·손목6축이다. canonical곡 입력 형식의 명목6프렛은 오른손 줄/방향/시각을 표현하기 위한 기존 입력 호환이며 왼손 압현·음고 성공 조건은 아니다. 타현 성공은 원래 깊이·속도·구간·재무장 조건의 피크표식 현 통과이며 실제 현 압력·진동·음향과 구분한다.

예상: CPU 구현·검증20~40분, native1환경5초경로 각1~3분(최대3개사전명시조건). GPU 점유 중이면CPU에서설계/검증후유휴대기. 장시간PPO는실제진단후별도조건으로진행하며현재승인범위를정적한과제로한정한다.

## 실제 완료와 제한

입력·환경·실행기·학습연결·엄격평가·진단·GPUguard 구현 및 독립검토 완료. 신규39개 CPU 검사 통과. 실제검사1회는도착상태저장검사오류,후속정상2조건은안전완주하나속도0.04065/0.04446m/s가원하한0.05미달. 타현성공/PPO학습성공을선언하지않는다. 실제성공진단없어PPOgate로학습보류. 원시runs보존·docs결과보고서/대표영상/재현명령기록완료.
