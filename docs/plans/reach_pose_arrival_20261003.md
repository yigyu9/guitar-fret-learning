# 기타 넥 접근과 손바닥 자세 정렬 구현 계획

작성일: 2026년 10월 3일. 상태: 사용자 구현 승인 후 구현 및 연결 검증 중.

이 계획은 왼손이 기타 넥 뒤쪽의 목표에 원하는 방향으로 도달하고, 기타를 과도하게 밀지 않으면서 정지하도록 REACH를 개선하는 작업을 정의한다. 먼저 실제 손 형상으로 목표 자세의 가능성을 확인하고, 관절 목표 누적을 제한한 다음, 넥에 닿기 전에 정렬하는 접근 과정을 학습한다. 보상 가중치를 추가로 조정하는 작업부터 시작하지 않는다.

사용자는 이번 작업에서 **먼저 구현 계획 문서를 작성**하도록 요청했다. 이후 사용자가 “이제 구현을 진행해줘”라고 승인하여 코드 구현과 짧은 연결 검증을 진행한다. 장기 학습 성능 비교는 별도 실행 범위다.

## 현재 구현과 확인된 결과

계획 작성 시 환경의 큰 단계는 WAIT, REACH, GRIP, TRANSPORT이며 policy 관측은 177차원, action은 왼쪽 흉곽·어깨·팔꿈치·손목·손가락의 33개 관절이다. 자유 기타, 중력, routed strap과 오른손 유지 자세를 사용한다.

손 쪽 거리 기준은 손바닥 뼈에 고정한 로컬 점 `(-7.325, -31.218, -23.256)mm`다. 목표는 넥의 충돌 형상 아래쪽에서 10mm 떨어진 점이다. 이 두 점의 직선거리는 손 전체와 기타 사이의 최소 간격이나 접촉력을 나타내지 않는다.

REACH의 목표 방향은 손바닥 법선이 기타 로컬 +z를 향하고 손의 길이 방향이 넥 축을 따르는 것이다. 다만 heading 보상·gate에는 내적의 절댓값을 사용하므로 넥 축의 양방향을 허용하고, 관측의 목표 회전은 +y 방향 하나를 사용한다. 이 차이는 아래 목표 자세 검증에서 먼저 정리한다.

| 검증 | 기존 318회 정책 | 방향 보상 변경 후 30회 학습 |
|---|---:|---:|
| noisy16 평균 최소 거리 | 1.44cm | 2.11cm |
| 5cm 이내 구간의 평균 법선 오차 | 36.3도 | 40.1도 |
| 같은 구간의 평균 heading 오차 | 37.7도 | 48.1도 |
| 기타 중심 최대 이동량의 환경별 평균 | 14.8cm | 22.3cm |
| GRIP 진입률 | 0% | 0% |

근거리 오차는 각 환경의 근거리 평균을 다시 평균 낸 값이다. 기타 이동량에는 중력·스트랩과 모든 접촉의 영향이 포함되므로 이를 손이 밀어낸 양이라고 단정하지 않는다. 비교는 한 학습 seed와 32환경·30update·61,689sample의 짧은 실험이다. 새 critic·optimizer의 적응과 보상 변경의 영향을 분리하지 못했다. 이 결과는 변경 정책의 회귀를 보여주지만, 충분히 학습된 최종 설계의 성능을 판단하는 근거는 아니다.

현재 action은 이전 관절 목표에 매 control step 최대 0.5도를 더한다. 관절 토크는 목표와 실제 관절각의 차이에 비례하며 토크 한계로 제한한다. action이 0이어도 누적 목표는 유지되므로 접촉에 막힌 관절에 잔여 힘을 계속 줄 수 있다. 이 구조가 실제 밀림의 주원인인지는 새 진단으로 검증한다.

## 목표 자세와 접근 준비 위치

목표를 제어점 하나가 아니라 위치·회전·전체 손의 간격을 함께 만족하는 자세로 정의한다. 넥 뒤쪽의 실제 충돌 표면에서 목표점, 표면 법선, 넥 길이 축을 구하고 손바닥 기준 프레임에 대응시킨다. 기존 기타 +z와 실제 면 법선의 차이를 확인한 뒤 어느 기준을 사용할지 확정한다.

최종 목표 자세에서 손바닥뿐 아니라 모든 손가락, 손목, 전완의 충돌 형상을 확인한다. 표면 접촉 허용 범위에는 PhysX의 접촉 skin을 반영한다. 화면상 겹침이나 단일 점의 거리만으로 관통을 판정하지 않는다. 목표에서 필요한 접촉과 허용하지 않을 접촉을 구분한다.

접근 준비 위치는 최종 위치보다 넥 뒤쪽으로 더 떨어진 곳에 둔다. 거리는 우선 5~8cm 범위를 후보로 검토하되, 전체 손의 회전 공간과 도달 가능성을 측정한 뒤 정한다. 이 범위는 확정된 제어 파라미터가 아니다. 준비 위치부터 최종 위치까지의 회전·이동 경로도 충돌이 없는지 검사한다.

가능성 확인에는 진단용 역기구학을 사용할 수 있다. 이는 관절 한계 안에서 원하는 자세가 존재하는지 확인하기 위한 도구이며, PPO 실행 시 손을 자동으로 움직이는 teacher나 servo로 연결하지 않는다. 기하 검증 이후에는 자유 기타·중력·스트랩을 유지한 실제 물리 실행으로 확인한다. 기타를 고정한 진단 결과를 최종 성공으로 인정하지 않는다.

**단계 통과 조건:** 충돌 형상으로 허용되는 목표 자세와 접근 경로가 적어도 하나 존재하고, 관절 한계·목표 법선·heading 방향의 정의가 일치한다. 통과하지 못하면 목표점 또는 손의 초기 형상을 먼저 수정한다.

## 관절 목표 누적과 접촉 압력 제한

REACH에서 목표와 실제 관절각의 차이를 관절별로 제한한다. 누적 목표가 실제 동작보다 계속 앞서가는 것을 막는 방식이다. 제한값은 관절 gain, 토크 한계와 물리 측정으로 정하며 모든 관절에 같은 각도를 임의로 적용하지 않는다.

접촉 중 목표 차이가 커지는 경우에는 접촉을 더 강하게 누르는 방향의 추가 누적을 제한한다. 접촉 정보만으로 각 관절의 위험 방향을 단정하지 않고, 실제 관절 추종 오차·토크·손의 속도·접촉력 변화를 함께 측정한다. 접촉했다고 전체 관절 action을 0으로 만들지는 않는다. 뒤로 빠지거나 회전해 정렬하는 움직임은 가능해야 한다.

action 0에서 이미 쌓인 목표가 남는 경우를 별도로 검증한다. 목표를 매번 실제 관절각으로 덮어쓰면 유지 토크가 사라질 수 있으므로, 기존 유지 제어를 보존하면서 과도한 차이만 줄이는 방식을 선택한다. 현재 환경은 작은 손 관절의 명시적 속도 감쇠가 불안정하다고 기록하고 있으므로, 새 감쇠 토크를 검증 없이 추가하지 않는다.

**단계 통과 조건:** 반복적인 밀기 명령에서도 목표 차이가 한계 내에 있고, 명령을 중립으로 바꾼 뒤 과도한 잔여 접촉력이 줄어든다. 이탈 동작, 자유공간 추종, 부분 reset과 기존 WAIT·GRIP·TRANSPORT 제어가 깨지지 않는다.

## REACH 내부의 정렬 접근 유지 과정

큰 단계 순서는 유지하고 REACH 내부를 세 과정으로 구분한다. 단순히 가까워지면 손 전체를 강제로 고정하는 방식은 사용하지 않는다. 관절 움직임은 위치와 회전에 함께 영향을 주므로 방향을 맞추는 동안 필요한 위치 보정도 허용한다.

| 내부 과정 | 위치 목표 | 학습 목표 | 다음 과정 조건 |
|---|---|---|---|
| 정렬 | 접근 준비 위치 | 손바닥 법선과 heading을 맞추면서 넥 뒤쪽으로 접근 | 준비 위치·방향·안전 조건을 일정 시간 만족 |
| 접근 | 준비 위치에서 최종 위치로 연속 이동 | 정렬을 유지하며 작은 속도로 접근 | 최종 위치 근방에 진입 |
| 유지 | 최종 목표 위치 | 위치·방향·상대 속도·접촉 압력을 함께 유지 | 기존 여섯 조건을 8step 연속 만족하면 GRIP |

접근 중 방향이 크게 틀어지면 최종 목표까지의 진행을 늦추거나 준비 위치 쪽으로 부드럽게 되돌린다. 같은 경계에서 과정이 반복 전환되지 않도록 진입·이탈 조건을 구분한다. 임계값과 유지 시간은 도달 가능성 및 runtime 측정 이후 확정한다.

내부 과정과 목표 진행이 이전 상태에 의존한다면 policy가 그 상태를 알 수 있어야 한다. 현재 177차원 관측에 숨겨진 내부 상태를 추가하지 않는다. 세 과정의 one-hot만으로 이동·지연·복귀 중인 목표를 구분할 수 없으므로, 현재 접근 목표의 위치 오차 3개, 목표 진행률 1개, 정렬 조건의 연속 충족 카운터 1개도 명시적으로 추가하는 안을 사용한다. 기존 177개에 8개를 더한 185차원 제안이며 policy·계약·checkpoint schema·검사 코드를 함께 갱신한다. 기존 최종 목표 오차와 ready 카운터는 그대로 두고 다른 의미로 재사용하지 않는다. 내부 전환의 이력 상태가 관측에 모두 드러나는지 테스트한 뒤 차원을 확정한다. 이 관측 변경은 구현 승인 범위에 명시한다.

REACH 총 시간 제한 300step은 첫 연결 검증에서 유지한다. 세 과정에 시간이 충분한지 측정하고, 실패를 가리기 위해 먼저 timeout이나 성공 임계값을 완화하지 않는다.

## 보상과 진단 기록

위치 보상은 준비 또는 최종 목표의 허용 범위 안에서 포화하도록 한다. 법선과 heading은 별도 항목으로 기록하며 속도 오차에 희석하지 않는다. 유지 과정에서는 계속 더 밀어 넣는 것보다 위치·방향·속도·허용 접촉을 동시에 유지하는 것이 유리하도록 설계한다. 어떤 상태가 성공인지와 policy가 보고 있는 회전 목표가 일치해야 한다.

밀림 억제는 기타 중심 이동량 하나만으로 보상하지 않는다. 기타는 원래 중력과 스트랩 때문에 움직이므로, 손과 기타의 실제 contact pair에서 계산한 힘과 접촉 시점, 기타 선속도·각속도 변화를 함께 사용한다. 무접촉 기준 실행과 비교해 접촉 전후의 추가 움직임을 진단하되 정확한 인과 분리로 표현하지 않는다. 접촉력 벌점은 무조건 접촉을 회피하는 정책을 만들 수 있으므로 필요한 접촉을 허용하는 범위를 측정한 뒤 적용한다.

frame별 진단에는 내부 과정, 위치 목표, 위치·회전 오차, 여섯 조건 통과 여부, 연속 충족 시간, raw/applied action, 실제/목표 관절각, 누적 제한 작동 여부, 토크, 손과 기타의 속도·접촉력을 저장한다. 확대 영상에는 손바닥 법선, 목표 법선, 두 기준점과 내부 과정을 표시한 진단 버전을 별도로 만든다. 기존 무자막 전체 영상도 보존한다.

## 학습 순서와 실험 비교

먼저 충돌이 없는 가까운 초기 자세에서 정렬과 유지를 학습한다. 시작 상태를 관절 공간에서 실제로 가능한 자세로 구성하고, 손만 임의 위치로 이동시켜 관절·접촉 상태가 불일치하는 reset은 사용하지 않는다. 준비 위치까지의 접근을 추가한 뒤 authored WAIT 시작의 먼 거리 접근으로 확장한다. 기타 자유도·중력·스트랩은 최종 평가에서 항상 원래 조건을 사용한다.

초기 자세 curriculum은 학습 모드임을 config에 기록한다. 초기 위치 범위와 자세·속도·기타 노이즈는 하나씩 늘린다. 쉬운 reset에서 성공했더라도 현재 프로젝트의 WAIT 시작 noisy 평가를 통과하기 전에는 개선 모델로 채택하지 않는다.

보상 변경 후 기존 actor를 초기값으로 사용한다면 critic은 새 보상으로 먼저 적응시키고 초기 policy 변화량을 제한한다. 새 관측 차원을 도입할 경우 기본은 새 policy 학습이며, 명시적 변환 설계·검사 없이 기존 actor를 부분 로드하지 않는다. 이전 reward나 관측의 critic·optimizer를 자동 resume하지 않는다.

실험은 동일 학습 조건에서 기준 구현, 누적 제한만 적용, 정렬 과정만 적용, 두 변경 결합을 비교한다. 가능한 변경을 한 번에 모두 적용하고 원인을 추정하는 대신, 각 단계의 효과를 확인한 뒤 결합한다. 하나의 seed와 짧은 smoke는 연결 검증이며 성능 확인에는 여러 학습 seed와 고정 noisy 평가를 사용한다. 학습량은 실제 처리량과 곡선 추세로 정하고 30update를 충분한 학습으로 간주하지 않는다.

구현은 위 파일 전체를 한 번에 수정하지 않는다. 준비 위치를 사용하더라도 평가지표는 최종 목표까지의 거리로 기록하고 준비 목표 오차와 구분한다. 평가와 영상은 checkpoint에 저장된 정확한 계약을 선택하거나 불일치로 거부한다. 차원이 같다는 이유로 이전 제어를 새 제어로 해석하지 않는다. 기존 checkpoint와 실패 실험은 근거로 보존한다.

## 완료 기준과 단계별 체크리스트

CPU 검사 통과, GPU 연결 성공, 학습 성능 개선을 별도 결과로 보고한다. 최종 완료 기준은 원래 WAIT 시작 평가에서 기존 위치 2cm·간격 3mm·법선과 heading 20도·상대 선속도 0.1m/s·각속도 0.5rad/s를 8step 연속 충족해 GRIP에 진입하는 것이다. 접촉력을 측정한 안전 범위 내로 유지하고, 성공 직전 기타 움직임과 관통 진단도 함께 확인한다. 평균 최소 거리나 보상 개선만으로 완료 처리하지 않는다.

- [ ] 목표점·법선·heading 일치와 손 전체 충돌 형상으로 가능한 자세 확인
- [x] 기존 정책의 접촉력·누적 목표 차이·기타 움직임 기준 기록
- [x] REACH 누적 제한 구현 후 경계·중립·이탈·부분 reset 검사
- [x] 준비 위치와 정렬 접근 유지 과정 구현 후 관측·checkpoint 계약 검사
- [x] 가까운 자세 초기화와 원래 WAIT 시작 평가의 설정 분리 검증 (학습 성능 미검증)
- [ ] 충분한 학습량의 단계별 비교와 여러 seed 결과 확인
- [ ] 최종 목표 동시 충족률·유지 시간·접촉력·GRIP 진입 및 전후 영상 비교
- [x] change-reviewer의 독립 검수와 문서·체크리스트 갱신 (물리 진단 도구 종료 처리 수정 반영)

첫 구현 묶음은 **목표 자세 가능성 진단과 기존 정책의 frame별 기록**이다. 그 결과로 준비 위치와 누적 제한 수치를 정한 뒤, 다음 묶음에서 누적 제한만 구현한다. 장기 학습은 이 진단과 제어 검증 이후 별도 실행 범위로 정한다.

## 구현 결과 기록

- 185차원 관측과 새 schema, guitar-local 준비 목표·정렬/접근/유지, 방향 이탈 시 목표 후퇴를 연결했다.
- 법선 +z와 directed heading +y를 목표 회전과 일치시켰다. 원래 최종 조건과 active 목표 오차를 구분한다.
- curriculum align/hold 초기 자세와 원래 WAIT 평가를 분리하고 초기 파일 SHA256까지 resume에 확인한다.
- 형상 진단: FK 위치 오차 0.000325mm, 회전 0.00662도. 5/6.5/8cm 준비점에서 최종 목표까지 샘플 IK 경로는 충돌 없음. 연속 경로와 자유 물리 성공 판정은 남아 있다.
- 제한 단독 ablation: 최소 거리 1.492cm→0.596cm, 최대 접촉력 6.872N→26.51N, 기타 중심 최대 이동 12.55cm→13.72cm. 제한은 기본 비활성으로 유지한다.
- 기준 trace/ablation: `docs/2026-10-12/회의/results/reach_pose_arrival_20261003/`. 형상 결과: `docs/2026-10-12/회의/results/reach_pose_diagnostics_20261003/`.

- CPU 108개 테스트 통과. GPU 4환경·2update·512개 유효 sample 학습, checkpoint 저장, 64환경 독립 평가 및 best/final 영상 생성이 완료됐다. 새 policy는 초기 학습 연결 검증용이며 GRIP·전체 성공률은 0이다. `docs/2026-10-12/runs/pose_arrival_integration_20261003/analysis.md` 참조.

- 자유 물리 추가 진단에서 WAIT 이후 snapshot 기타에 맞춘 IK 자세를 authored 기타 reset과 조합하면 WAIT 첫 단계에서 안전 종료됐다. 준비 자세 평균 접촉력 최대 704N, 최종 자세 182.5N(각각 substep 최대 2679N, 730N). 따라서 해당 snapshot 후보는 curriculum 초기값으로 채택하지 않는다. 이 결과는 샘플 형상 경로 통과가 초기화·물리 실행 성공을 보장하지 않음을 확인한다. partial reset은 다른 환경 상태를 유지했고, 종료 기하는 생략하여 NaN 없는 JSON을 저장한다.

- authored 기타 reset에 맞춰 IK를 다시 계산하면 손·기타의 형상 충돌과 접촉력은 0이지만, 흉곽 IK가 strap 경로를 바꿔 extension ratio 1.080993%가 기존 1% 안전 한계를 넘었다. 이 초기값도 채택하지 않는다. 안전 한계나 strap 법칙을 변경하지 않고 흉곽 고정 후보를 따로 확인한다.

- 최종 흉곽 고정 후보는 형상 오차 0.000365mm/0.000641도, 손·기타 충돌 없음이며 실제 constructor·WAIT180·중립120step에서 안전하게 동작했다. 185차원 관측 유한성과 부분 reset 독립성도 확인했다. 다만 자유 기타가 reset에서 23.48cm 움직여 WAIT 후 최단 목표 거리가 27.54cm다. 따라서 가까운 자세 curriculum으로 채택하지 않는다. 안전한 초기 자세와 WAIT 후 실제 근접 자세는 다른 조건이며, 다음 학습 실험에는 WAIT 종료 상태에 맞춘 안전한 단계별 초기화가 필요하다. 안전 기준·strap 경로 법칙은 변경하지 않았다.
