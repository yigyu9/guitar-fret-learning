# V5 기준 구현·프로젝트 정리

사용자 승인 범위: 압현 V5를 이후 개발의 원본으로 삼고, 이전 버전은 간단한 기록을 남겨 활성 구현에서 제거한다. 프로젝트 전체의 불필요·중복 파일도 실제 참조를 확인해 정리한다.

## 기준과 보호 범위

- 현재 실행 중인 C1의 동결 runtime, 감독·분석 도구, 모델·원시 로그·입력은 변경하지 않는다. 원본 작업 트리의 정리와 실행 사본을 구분한다.
- 새 타현·전신·운지 전처리·논문 작업과 기존 사용자/다른 작업자의 변경은 보존한다.
- V5의 보상·관측·33축 행동·PPO·초기 자세·물리를 바꾸지 않는다. 구버전에서 재사용한 기능은 V5 또는 공용 기반으로 옮겨 상속 사슬을 정리한다.
- 과거 checkpoint를 바뀐 소스로 암묵 재개하지 않는다. 기존 모델은 기존 실행 사본에서 검증하며 새 코드는 새 소스 identity를 사용한다.
- 보호 요청된 PC2 공유·실패 진단 원문·실험 근거와 필수 자산은 단순히 오래됐다는 이유로 삭제하지 않는다. 외장 링크는 따라가거나 삭제하지 않는다.
- 삭제 전 경로·크기·SHA·이유와 대체 경로를 기록한다. 동일 경로를 요구하는 필수 입력은 내용 중복만으로 삭제하지 않는다.

   검증: 활성 import 폐쇄, 진입점 도움말·C1~C6 준비·checkpoint 거부 조건·타현/전신 공용 회귀를 확인한다.

5. [x] 독립 검수와 최종 검증 후 실제 감소량·새 실행 경로·남겨둔 이유를 보고한다.
