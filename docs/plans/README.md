# 계획을 찾는 방법

실제로 다음에 할 작업은 [CURRENT_STATUS](../../CURRENT_STATUS.md)에서 확인한다. 이 디렉토리에 남아 있다는 사실이나 미완료 체크만으로 실행 중인 계획으로 판단하지 않는다.

| 구분 | 확인 위치 |
| --- | --- |
| 이번 정리 작업 | [역할별 정리 계획](../maintenance/organization_20261031/PLAN.md) · [완료·검증 결과](../maintenance/organization_20261031/REPORT.md) |
| 최근 압현 준비·구조 계획 | [자연 준비](natural_press_preparation_v3_20261031.md), [구조 개선](press_learning_structure_v2_20261031.md), [탐색·학습률 비교](press_exploration_lr_sequence_20261030.md) |
| 위 계획의 실제 완료 결과 | [실험별 결과 목록](../2026-11-02/압현성공/experiments/README.md) |
| 참조 없는 완료 계획 | [history/plans](../history/plans/README.md) |
| 참조 때문에 원래 위치에 둔 계획 | [계획 분류표](../maintenance/organization_20261031/plan_catalog.json) |

최근 계획의 체크 표기가 실험의 실제 완료 여부를 대체하지 않는다. 실행 상태·조건·성공 수치는 해당 실험 report와 결과 문서를 우선한다. 이번 정리에서354개 중 참조 없는 로컬 완료 계획94개를 `history/plans/`로 옮겼으며,260개는 참조·원문·외장 링크·미완료/미분류 상태를 보존해 원래 위치에 두었다. 이 수는 README를 제외한 Markdown 경로 수다.

과거 정리 목록은 실행 의존이 아니므로 이동을 막는 이유로 삼지 않았다. 실제 코드·manifest·입력 SHA·문서에서 참조한 계획과 상대 링크를 검증하기 어려운 계획은 그대로 유지했다. 외장 링크는 읽거나 옮기지 않았다.
