# 2026-09-12 기타 프로젝트 설명 문서 작성 계획

## 목적

- 프로젝트가 최종적으로 무엇을 만들려고 하는가?
- 오디오와 곡 데이터가 어떻게 왼손·오른손 제어 목표가 되는가?
- Fret, Strike, Synchronizer, StabilityAdapter, FullBodyPlayer는 각각 무엇을 소유하는가?
- 각 파트의 입력·출력·좌표계·시간축·관절 action은 무엇인가?
- 현재 구현·검증된 범위와 아직 구현되지 않은 범위는 어디까지인가?

## 작성 범위

- Stage1: 오디오 → tablature/코드/왼손 운지
- 곡별 정본 입력: `data/song_bundles/<song_id>/`
- Fret-v2 왼손 압현 skill
- Strike-v2 오른손 pick/strum skill
- Isaac Gym 공통 환경, action/PD/EMA, PPO 학습 및 산출물
- G0 Canonical PlayEvent·rule Synchronizer·105-slot action bridge (97 movable DOF)
- 자유 기타·strap·StabilityAdapter 실험과 G1/G2로의 확장 계획
- 처음 프로젝트를 설명 듣는 사람이 실제 코드와 첫 작업을 찾아갈 수 있는 파일 지도와 체크리스트

## 정확성 기준

- 숫자와 차원은 가능한 한 현재 코드의 contract 상수와 설정에서 확인한다.
- 오래된 설계·prototype·과거 checkpoint는 현재 구현과 분리해 표시한다.
- “코드가 존재함”과 “GPU 물리 성능이 검증됨”을 같은 의미로 쓰지 않는다.
- raw audio는 runtime policy에 직접 들어가지 않는다는 경계를 유지한다.
- string convention, score time/physics time, normalized action/PD target을 명시한다.
- 문서의 모든 내부 링크와 코드 경로를 작성 후 확인한다.
