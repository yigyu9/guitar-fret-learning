# 90. 용어집

문서에서 자주 쓰는 용어를 주제별로 모았습니다. 차원·필드 순서처럼 실행에 영향을 주는 내용은 용어 설명만 믿지 말고 연결된 contract도 확인하세요.

## 음악 데이터와 event

| 용어 | 뜻 |
|---|---|
| Stage 1 | 음원에서 음표·tablature·코드·핑거링 후보를 만드는 오프라인 전처리 |
| TablatureSong | note의 시간·pitch·string·fret 등을 담는 음악 표현 |
| song bundle | 검토된 곡별 정식 입력 디렉터리 |
| FretEvent | 왼손이 누르고 유지할 목표 사건 |
| StrikeEvent | 오른손 pick/strum이 처리할 목표 사건 |
| Canonical PlayEvent | Fret과 Strike 정보를 공통 score 시간축으로 묶은 runtime event |
| traversal mask | pick이 물리적으로 통과해야 하는 줄의 표시 |
| audible mask | 해당 event에서 실제로 소리가 나야 하는 줄의 표시 |
| source event ID | 원본 mapping/strike plan과 runtime event를 연결하는 식별자 |
| fail-closed | 모호하거나 지원되지 않는 입력을 추측해 실행하지 않고 실패/미지원으로 표시하는 방식 |

## 정책 입력과 학습

| 용어 | 뜻 |
|---|---|
| observation | policy가 현재 상태·목표·문맥을 읽는 숫자 벡터 |
| action | policy가 제안하는 관절 제어 벡터 |
| block contract | observation block의 이름·순서·크기 약속 |
| proprioception | 관절 위치·속도 등 자기 몸의 상태 정보 |
| geometry | 손가락·pick·줄·프렛 사이의 위치·방향 관계 |
| skill prior | 상위 시스템이 재사용하는 사전 학습된 동작 정책 |
| source policy | 상위 결합에서 frozen 상태로 재사용하는 Fret 또는 Strike policy |
| frozen | 해당 단계에서 정책 parameter를 업데이트하지 않는 상태 |
| PPO | rollout과 advantage를 이용해 policy와 critic을 업데이트하는 강화학습 알고리즘 |
| rollout | 현재 policy로 환경을 실행해 모은 연속 상태·행동·보상 데이터 |
| curriculum | 쉬운 목표에서 어려운 목표와 전체 곡으로 난이도를 올리는 학습 절차 |
| smoke run | 성능이 아닌 학습 경로·shape·reset·checkpoint 연결을 빠르게 확인하는 짧은 실행 |

## 물리 판정과 시간

| 용어 | 뜻 |
|---|---|
| readiness | 목표 동작을 실행해도 되는 준비 상태 |
| dwell | readiness가 정해진 frame 동안 연속해서 유지되는지 확인하는 조건 |
| sounding fret | 한 줄에서 실제 음높이를 결정하는 유효한 가장 높은 press |
| sustain | 음을 내는 동안 압현을 유지하는 것 |
| swept crossing | 한 step 동안 움직인 pick 궤적이 줄 segment를 통과했는지 판정하는 것 |
| rearm | 이전 crossing 뒤 다음 crossing을 새로 인정하기 위한 복귀 조건 |
| phase | 접근·준비·실행·회복 등 event 진행 상태 |
| ScoreClock | 공통 음악 시간과 score frame을 관리하는 시계 |
| event cursor | 현재 처리할 Canonical event 위치 |
| pre-roll | score frame 0 전에 정책과 몸이 준비하는 구간 |
| safe delay | 준비가 늦었을 때 deadline 범위 안에서 허용하는 짧은 event 지연 |
| Synchronizer | readiness·timing·stability를 바탕으로 실행/대기/skip을 감독하는 규칙 계층 |

## 제어와 action 구조

| 용어 | 뜻 |
|---|---|
| named action ABI | 관절 이름과 full action slot mapping으로 정의한 제어 인터페이스 |
| full action vector | 이름 있는 105개 slot으로 구성된 ABI 벡터. zero-range 고정축 8개도 포함 |
| effective movable DOF | full action의 zero-range 고정축 8개를 제외한 실제 이동 가능 축 수. 현재 97개 |
| hold | 해당 모듈이 소유하지 않는 관절을 초기 pose 또는 현재 pose에 유지하는 값 |
| residual | 기존 source action에 더해지는 보정 action |
| EMA | 연속 action을 부드럽게 하는 exponential moving average |
| PD | 관절 목표와 현재 상태를 이용해 제어 torque를 계산하는 방식 |
| PhysX | Isaac Gym 환경에서 동작하는 물리 엔진 |
| manifest | schema·hash·asset·설정·mapping 등의 계약 정보를 기록하는 메타데이터 |
| fingerprint | 입력 asset·물리 조건·데이터가 무엇인지 식별하는 값 |
| checkpoint migration | contract나 physics 조건 변경에 맞춰 checkpoint를 명시적으로 변환·검증하는 절차 |

## 좌표계와 진행 단계

| 용어 | 뜻 |
|---|---|
| G frame | 기타 기준 좌표계. 줄·프렛·pick geometry에 사용 |
| B frame | pelvis 기준 몸 좌표계. 몸에 대한 기타 배치와 시작 pose에 사용 |
| W frame | world 기준 좌표계. 중력·낙하·세계 위치에 사용 |
| G0 | 기타를 고정하고 Fret·Strike·event 결합을 검증하는 단계 |
| G1 | 자유 기타·중력·스트랩·안정화 계층을 추가하는 단계 |
| G2 | 인공 도움을 줄이고 짧은 구절에서 전곡으로 확장하는 단계 |
| Stability Adapter | source 연주를 보존하면서 몸·하체·지지 동작을 보정하는 계층 |
| pre-play stability | 음악 event를 시작하기 전에 기타와 몸의 시작 상태를 안정화하는 절차 |
| CPU integration probe | simulator 없이 source loading·event·action bridge 계약을 확인하는 검사 |

### 빠르게 기억할 구분

- **Observation은 정책이 읽는 값**, **action은 정책이 제안하는 값**입니다.
- **Action 제안은 물리 성공이 아닙니다**. press와 crossing은 simulator 결과로 판정합니다.
- **traversal은 pick이 지나는 줄**, **audible은 실제 소리가 필요한 줄**입니다.
- **Full action은 105-slot ABI**, **실제 이동 가능한 축은 97개**입니다.
- **G0는 고정 기타 결합 검증**, **G1/G2는 자유 기타 안정화와 확장**입니다.
