# GPU 기타 접촉 회귀: 원인 분리와 완화 수정

2026-10-21. 원래 CPU 구현과 비교해 GPU에서 기타가 튀는 현상을 조사하고, GPU 기타를 단일 자유 강체로 표현하도록 현행 코드를 수정했다. **큰 수치 폭발은 크게 줄었지만 느린 기타 이탈은 남아 있다. 완전한 안정화나1024환경 장기 학습 인증이 아니다.**

## 확인한 문제 범위

기존 기타는39개 몸체와38개 고정 관절, 관절 자유도0으로 들어왔다. 줄 표식 일부의 질량은1e-7kg이고 프렛의 관성 성분은 약1e-9kg·m²다. 물리적으로 변형하지 않는 기타를 이런 고정 연결 구조로 풀 때 GPU 다중 환경 접촉에서 큰 차이가 증폭됐다. 같은 형상을 단일 강체로 바꾸면 큰 폭발이 사라지고 유지 성능이 크게 개선됐다. 정확한 PhysX 내부 결함이나 특정 solver 코드 한 줄을 확정한 것은 아니다.

앞선 조사와 실제 영상은 [원본 비교](../../2026-10-20/guitar_learning_gpu_original_comparison_v1/README.md), [무행동 영상](../../2026-10-20/guitar_learning_gpu_failure_video_v1/README.md)을 따른다. 이번 추가 조사에서는 다음을 확인했다.

- 자기접촉을 보존하고 인체↔기타 접촉만 제거하면GPU1/1024환경의env0가128단계 동안 비트 단위로 같았다. 왼손↔기타 접촉만 제거한 시험도 같았다. 오른손 접촉 제거·기타 몸통 접촉 제거에서는 차이가 남았다. 접촉 제거 시험은 지지가 사라져 안전 실패도 생기는 **진단**이며 해결책으로 채택하지 않았다.
- 원래CPU의 실제 유지 제어를480단계 기록했다. 이CPU가 제출한 목표·힘의128단계 prefix를 새CPU 물리 장면에 재생하면1환경과1024환경 모두 안전 초과0이었다. 동일CPU 명령을GPU에 재생하면1환경은128단계째1개,1024환경은972개가 안전 한계를 넘었다. 새 정책·보상 계산이 없는 재현이다. CPU 배치도 궤적 자체는 완전히 같지 않으므로 **배열의 차이만으로 버그를 판정하지 않는다.** 차이의 크기와 실제 안전 실패를 함께 본다.
- 원본의 기타 생성filter2, 원본의 기타 관성 재설정 방식, GPU articulation 강제 옵션, solver 변경·반복 횟수·세부 시간 간격·환경 간격·마찰 분리만으로는 해결되지 않았다.

`case_summary.json`은35개 동일 힘 변형의 완료 여부·한계 초과·명령 일치를 요약한다. 별도 compound/폐루프/현행 실행은 각 결과 디렉토리의report를 따른다. 동일 힘 시험의 초과 수는 **서로 다른 환경 수**이며 학습 에피소드 수가 아니다. unsafe 이후에도 재생을 계속한 진단을 정상 학습처럼 해석하지 않는다.

두proxy는 원래filter에서도 모든 인체·기타와의 충돌이 막혀 있었지만filter0인 의자·지면과의 접촉 가능성은 남았다. 이를 완전히 제외한 것은 **명시적인 새GPU 물리 계약**이다. 원래CPU2초 기록에서는 두proxy가 의자와 최소21.1/27.8cm 이상 떨어져 실제 지지에 참여하지 않았다. 이후 임의 자세까지 충돌 동등성을 주장하지 않는다. 근거는`proxy_clearance_cpu_reference_v1.json`이다. 실제 손가락·엄지의 충돌 형상과 유연 제어 gain을 제거한 것이 아니다.

원래91개 형상의 순서를 마찰 태그로 검증하려 했으나 SDK가 body 첫 geom의 마찰을 공유해 그 검사 방법으로는 식별할 수 없었다. `native_shape_order_v1`의 실패는 **원래 형상 순서가 틀렸다는 증거가 아니다.** 남은89개는native에서 모두 같은filter4096·friction1·contact offset0.0001m이고 다른 shape 속성도 동일하게 설정·검증한다. 따라서 속성을 어느 형상에 잘못 붙이는 순서 문제를 없앴다. native cooked mesh가 비트 단위로 동일하다고 인증한 것은 아니다.

기존CPU 경로·초기035/v14자세·기타 중력·스트랩OFF·손가락 유연 제어·힘 상한·안전 종료 기준을 유지한다. 기타 직접 힘·부착·진행 중 상태 주입을 추가하지 않았다. 물리240Hz/정책60Hz, solver4/2·substeps1과 환경 간격도 유지한다.

현행1024의 앞선 반복에서는6회/6환경, 최종 반복에서는8회/8환경이었다. 결과를 고르지 않고 둘 다 보존했다. 최종8건은 기타 이동7건·회전1건이며 큰 관절 속도/비유한 응답으로 종료된 실행은 아니다. 이2초 결과만으로 장기 안정성을 인증하지 않는다.

PPO 두 실행은 전곡보다 짧다. 완료 에피소드0이며 전곡 성공·곡 학습 수렴을 확인한 시험이 아니다. 재개는 모델·optimizer·RNG·curriculum을 복원하고 물리는 새로운 준비 자세 에피소드에서 시작한다. `checkpoint_verification.json`은 재개 경계의 실제 payload 일치와 구버전 거부를 기록한다.

처음 재개 스크립트는 존재하지 않는`checkpoint.pt`를 지정해 물리 생성 전에 종료됐다(`resume128_final/`, 로그 보존). 실제 저장 파일`final.pt`로 고쳐`resume128_final_v2/`에서 재검증했다. 이 실행 스크립트 오류를 물리 실패로 집계하지 않는다.

최종 모델은`train128_final/final.pt`, 재개 모델은`resume128_final_v2/final.pt`다. 학습 커맨드는 기존`python -m guitar_learning.train`을 그대로 사용한다. GPU 설정/실행 계약은v2이며 XML과manifest의SHA를 checkpoint 계약과 실행 입력에 포함한다. CPU나구GPU v1 모델을 암묵적으로 재개하지 않는다.

## 남아 있는 문제와 채택하지 않은 후보

정상 접촉을 유지한89형상 진단의128환경10초 시험에서는6개 환경이 약8초 이후 서서히 이탈했다.1024환경2초 진단에서도2개가 일시적으로 안전 한계를 넘었다. 이는최종 현행2초 캡처와 별도 실행이며도중reset하지 않은 진단이다. 큰 폭발을 완화한 것과 오래 안정적으로 지지하는 것은 구분한다. **현재128은설정 기본값이며안정 학습 권장 수가 아니다.1024장기 학습도 권장하지 않는다.**

- 환경 간격 축소:1024/2초 실패12·16개로 개선되지 않아 채택하지 않았다.
- position iteration8:11개, substeps2:32개로 개선되지 않아 원래값을 유지했다.
- 실제CUDA 질량행렬은[envs,105,105]로 제공된다. 기존의 “GPU mass matrix API가 없다”는 설명은 잘못됐다. 실제 물리 후 하체16×16과 기하 행렬의 최대 차이는 약8.5e-6/2.94e-5kg·m²였다. native행렬로 바꿔도128/10초17개·1024/2초13개로 개선되지 않아 기존 기하 경로를 유지했다. reset 직후 stale native행렬은 제어에 사용하지 않았고 숨은 물리 대기tick도 추가하지 않았다.

이후 조사 대상은 남은 느린 접촉 미끄러짐과 지지 제어의 민감도다. 보상·압현 성공 기준이나 안전 한계를 완화해 문제를 숨기지 않는다.

## 원문 보존과 재현 자료

변경 전 활성Python421개와README/AGENTS는`guitar_learning/archive/20261021_before_gpu_contact_fix_v1/`에보존했다. protected3파일과native 원문·기존 자산은 수정하지 않았다. 실험은각각 새출력에기록하고실패·SIGSEGV·비유한 응답·초기화 거부도 보존했다.

과거 동적변형 도구는 당시활성GpuScene에 patch를 적용한 진단이다. 과거 결과를 재현할 때는 각시험의정확한scene source와변경전 원문을 함께 확인한다. 현행v2에과거명령을 실행한 결과를원래v1재현으로해석하지 않는다. 현행검증은`run_final_checks.sh`의물리/학습부분과`run_resume_final.sh`의수정된재개명령을 따른다.

`source_manifest.json`·`verification.json`·`artifact_sha256.json`은 최종 소스·입력 검증과 결과파일을 식별한다. 독립change-reviewer가 물리/논리COM분리·checkpoint·실제native실행·검사결과를 확인했다. 이번 CPU 검사는 수정에 관련된GPU검사36개이며, 전체 회귀검사는 다시 실행하지 않았다. 원본CPU의 과거 전체 검사결과를 새 실행처럼 재사용하지 않는다.
