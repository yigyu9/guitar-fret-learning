# 1000회 중간 해석

**중지 접촉은 안전 완주곡에서도 나타났지만 안정적인 음 달성은 아직0이다.** 가까워지는 지표와 물리 안전은 좋아지는 반면 전체 음 달성은 낮아지는 변화가 함께 관찰된다. 이는 학습 중 변동 정책의 수집 결과이며 고정 체크포인트 평가나 수렴 판정이 아니다.

범위는 저장300+150+350과 현재200회, 총1,000업데이트·32,768,000 committed 전이다. 원본 미저장63회는 제외했다. CPU로 종료 기록을 읽었으며 GPU·GL·동결 코드·기존 결과는 변경하지 않았다. ## 손가락별 접근 증가가 압현 유지로 이어지지는 않는다

아래 비율은 **안전곡만** 대상으로 각 손가락 배정 음 수(25/18/12/12)에 대한 곡별 비율을 평균했다. 800~999는 단계1 비중이 일정해, 이전0→1 보상 비중 변화가 이 구간 차이를 설명하지 않는다.

| 손가락 | 접근800~899→900~999 | 접촉800~899→900~999 | 음 달성800~899→900~999 |
| --- | ---: | ---: | ---: |
| 검지 | 64.147→66.810% | 15.563→10.735% | 8.644→4.675% |
| 중지 | 59.162→63.849% | 0.006→0.016% | 0.000→0.000% |
| 약지 | 82.083→83.009% | 6.014→8.921% | 1.607→1.945% |
| 새끼 | 36.995→42.760% | 3.297→3.149% | 1.234→0.946% |

전체 달성 감소는 특히 검지 음 달성8.64→4.67%와 접촉15.56→10.74% 감소가 크다. 약지 접촉·달성은 늘었지만 이를 메우지 못했다. 새끼는 접근이 늘었어도 접촉·음 달성은 소폭 낮아졌다. 중지는 표면 최소거리 평균11.36→9.56mm, 허용 기하 시간은 음당37.26→72.49ms로 가까워졌다. 그러나 목표 위치에서 하중을 동반한 시간 평균은0.0127→0.0519ms에 그친다.

새800~999의 안전3,033곡에는 중지 배정 음 기회가54,594개다. 그중 near_done34,009개, 기하 시간 양성12,700개, 목표 하중 시간 양성63개, contact_done7개, 음 달성0개다. 각 조건의 시간·거리 기준이 달라 엄밀히 중첩된 확률 깔때기는 아니지만, 접근보다 유효 하중·유지 단계가 훨씬 드물다는 것은 명확하다. 이 접촉 합력·유한 표면 후보를 보정된 현 압력이나 음향으로 해석하지 않는다.

## 중지의 안전 접촉7개가 음 달성으로 이어지지 않은 이유

7개 접촉은 서로 다른 안전곡5개·목표 ID5개에서 발생했다. contact_done은 `press..end`의 후보 누적50ms(짧은 창은 그 길이)를 요구한다. 음 달성은 **실제 onset..end의 clean 누적40%, 최소50ms**를 요구한다. 따라서 접촉50ms 자체가 음 달성은 아니다.

5개는 실음 clean54~83ms가 필요79~119ms에 못 미쳤다. 나머지2개(note47·note61)는 준비 구간에서만 접촉해 실음 clean이0이다. 같은 현·프렛의 앞 음과 준비 시작을 공유해 이른 접촉이 뒤 음의 contact_done에도 기록된 사례이며, 서로 독립적인7번 압현 동작으로 해석하면 안 된다.

실패 양상도 한 가지는 아니다. env842/note65는 낮은 프렛 쪽 접촉 원인225ms와 wrong125ms가 함께 있었고, env512/note44·env966/note60 등은 높은 프렛 원인도 기록됐다. env751/note65는 기하 허용시간418ms인데 목표 하중은60ms에 불과해 clean54ms·missing240ms로 남았다. 즉 기하 접근만으로 부족하며 하중과 올바른 위치·타이밍을 동시에 충분히 유지해야 한다. 이 원인 시간은 겹칠 수 있어 합산 확률이 아니고, 어느 관절이 원인인지까지 확정하지 않는다.

750~999 전체에서는 실패곡에도 중지contact3개·음 달성1개가 기록됐다. 이전과 달리 안전곡의 접촉 자체가 관측됐으므로 완전한 접촉 불가능을 주장할 근거는 없지만, 안전한 지속 압현 학습은 여전히 부족하다.

## 단계1 유지와 PPO·자원

1,000회 최근 접근은 검지66.94·중지61.18·약지83.01·새끼44.27%다. 하지만 접촉은12.59·0.043·10.84·1.37%로 **모든 손가락20%**라는1→2 승급 조건에 네 손가락 모두 못 미친다. 안전100%여도 접촉 gate가 충족되지 않으므로 진행도1.0 유지가 현 계약과 맞다.

optimizer916(0-based update915)에서 attempted KL0.02199가 목표0.02를 넘었고 재시도1회 뒤 accepted KL0.01964, actor LR7.5e−6→1.875e−6가 기록됐다. 이 자동 조정은 소스 수정이 아니다. 이후900~999 평균 accepted KL0.00574이며 action 포화·보고된 nonfinite는0이다. 표의 KL은 각 update에 기록된 마지막 accepted KL의 구간평균이며 모든 minibatch의 표본가중평균과는 구분한다.

| update 평균 | 800~899 | 900~999 |
| --- | ---: | ---: |
| transition reward | -0.0407979 | -0.0374138 |
| transition cost | 0.00589762 | 0.00357894 |
| accepted KL | 0.00800905 | 0.00573893 |
| actor gradient (pre-clip) | 8.60934 | 8.56133 |
| value gradient (pre-clip) | 14.1227 | 7.22032 |
| latent std | 0.0496108 | 0.0495975 |

안전·가까운 움직임과 오압현·비용 감소가 유효 clean 유지보다 잘 최적화되고 있을 가능성이 있으나 인과 결론은 아니다. 같은 단계에서도 평균 reward는 덜 음수가 되는데 음 달성은 낮아져, reward 하나를 성능 점수로 쓸 수 없다. 접근 potential 평균의 부호 역시 거리 증가를 직접 뜻하지 않는다. 학습률 감소가 이후 변화를 늦추는지도 별도 비교 없이는 단정할 수 없다.

현재 실행200회 post-cache GPU free는 최저7.669GiB·마지막7.946GiB, RAM 가용 최저14.577GiB다. 비Torch 잔차 추정은34MiB 범위이며 증가를 확인하지 못했다. 현재 prefix에 OOM·새 SIGFPE·비유한 PPO는 기록되지 않았지만, 근본 x87 문제 해결이나 전체2,000회 정상완료 보장은 아니다. 전체 CPU831검사 통과는 실행·연주 성능 검증과 별개다.

다음 구간에서도 초기환경별 곡 순서의 안전·음 달성, 중지의 유효 하중·clean 유지, 검지 달성 저하를 함께 추적해야 한다. 현재 결과는 진행 중인 학습수집 분석이며 최종 고정정책 평가와 합치지 않는다.
