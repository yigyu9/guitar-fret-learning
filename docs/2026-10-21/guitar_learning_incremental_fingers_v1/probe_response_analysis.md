# 손가락 누적 제어 실측 응답 분석

완료된 `probe_n4_retry02`의21축×4명령, **84개 원본 NPZ**를 독립 CPU 수식으로 다시 검산했다. 명령 반복식·정지·반전·한계 clamp가 기록과 일치하고, 물리 종료는0개다. 목표 움직임과 실제 관절 움직임을 분리한다.

## 명령과 실제 움직임

총1470 control tick·5880 native physics step 후 실제 GPU 장면이 정상 종료됐다. 각 시험은 전진30tick(0.5초), 행동0의 목표 유지10tick(0.167초), 반전30tick(0.5초)이며 매 시험 준비 자세로 reset한다. 각 NPZ는 준비 t0+70 endpoint의71프레임이다. 모든21축 목표는 독립식 `clip(이전 목표+행동×4/60,native하한,상한)`과4e−6rad 이내로 일치했다. 다른20축의 명령 목표도 같은 식으로 함께 검사했다.

목표가 전진한80/84개에서 실제 q의 전진 순변위 방향도 모두 명령과 일치했다. 반전30tick의 실제 순변위는84/84개 모두 새 방향이다. 전체 실제 범위가1e−4rad보다 큰 시험은84/84개다. 이 마지막 수에는 전진이 clamp된 뒤 반전에서 움직인 시험도 포함된다.

전진 목표가0인4개는 `LH:thumb1_x`, `LH:ring3` 각각−0.1/−0.2 명령이다. 이들은 이미 native 하한에 있고 더 바깥으로 지시했으므로 목표가 유지되는 것이 정상이다. 실제 전진 순변위도 약1.7e−7~2.1e−6rad에 그쳤고 반전에서는 움직였다. 이를 손가락 전체가 움직이지 않는 결함으로 세지 않는다.

반전 첫60Hz endpoint에서 실제 q가 새 방향으로 움직인 것은23/84개다. 나머지61개는 목표가 이미 바뀌어도 잠시 기존 방향으로 움직였다. 실제 반전 검출은 반전 시작 후 0.017~0.050초의 endpoint에서 나타났다(관절 증분1e−6rad 문턱). 이는60Hz 검출 시각이며 연속 물리의 정확한 반전 시각이나 원인 분해가 아니다. **행동0은 목표 유지, 반전은 다음 명령 목표의 반전이며 실제 자세의 즉시 정지·반전이 아니다.**

행동0의10tick에서 목표 변화는84개 모두0이었다. 그러나 실제 q는 목표를 추종하며 더 움직였고, 각 시험의 hold 시작점 대비 최대 이동량 평균은0.034293rad(1.965°), 전체 최대는0.076837rad(4.402°)였다. 따라서 이 제어를 실제 자세의 즉각 정지/고정으로 설명하면 안 된다.

## 손가락별 범위·추종

| 손가락 | 축/시험 수 | 실제 범위 최대(rad/도) | 시험별 RMS 평균(rad) | 시험 RMS 최대(rad) | no-windup 관측 |
| --- | ---: | ---: | ---: | ---: | ---: |
| thumb | 5/20 | 0.366624/21.006° | 0.065206 | 0.130297 | 4 |
| index | 4/16 | 0.378321/21.676° | 0.058815 | 0.113801 | 2 |
| middle | 4/16 | 0.378391/21.680° | 0.055700 | 0.101552 | 4 |
| ring | 4/16 | 0.378372/21.679° | 0.050944 | 0.084888 | 6 |
| pinky | 4/16 | 0.378372/21.679° | 0.059609 | 0.145051 | 6 |

범위는 t0 포함71개 실제 q의 max−min이고, 추종 RMS는 t0를 제외한70개 `실제q−명령목표` 오차다. RMS가 가장 큰 시험은 `LH:pinky1_z`/행동+0.2의0.145051rad다. native K/D·힘·중력·안전 기준을 변경한 결과가 아니며, 이 오차만으로 특정 gain 변경을 정당화하지 않는다.

no-windup을 실제 관측한 시험은22/84개다. 같은 한계에서2개 이상 전진 endpoint가 포화되고 첫 반전 목표가 즉시 안쪽으로 이동했을 때만 관측으로 센다. 나머지62개는 같은 native 한계 포화 상황을 충분히 만들지 않아 **미검증**이며 성공으로 채우지 않는다. 실제 q의 즉시 반전과 다른 명령 상태의 검사다.

## 이전 실패와 데이터 범위

`probe_n4`는 Ninja 의존성 문제로 GPU 생성 전0tick에서 실패했다. `probe_n4_retry01`은 첫70tick·4NPZ를 남기고 NumPy int64의 도구 JSON 직렬화 오류로 중단됐으며 report는 불완전 JSON이다. 보존된 native 최종 감사는 closed=true/280physics step이고 남은4NPZ의 시계·목표 반복식·실제 q도 별도로 CPU 재검산했다. 이를 완료된84시험으로 세지 않는다. 두 실패는 실제 물리 종료·native SIGFPE와 구분해 원본 그대로 보존했다.

현재84NPZ의 모든 배열, 총588개 배열을 표준 builtin JSON으로 왕복하고 원래 dtype/shape/바이트로 복원해 일치를 확인했다. 보고서 원래 수치와 독립 수치·집계도 대조했고 모든 사용 파일 SHA가 분석 전후 같았다. 새 분석 결과 역시 builtin JSON 왕복을 통과했다.

좌표 부호는 native 일반화좌표이며 해부학적 굽힘/폄과 동일시하지 않는다. 이 표는60Hz endpoint이고240Hz 최대각·속도는 아니다. 4환경의84명령은 단일 제어 검증이며 학습 정책, 현 압력·음향·곡 성공·독립 seed 일반화의 증거가 아니다. 실제 영상의 시각 점검과 후속 학습·고정 정책 평가는 별도로 진행한다.
