# 원래 CPU 구현과 GPU 배치 구현 비교

사용자 요청에 따라 원본 CPU 코드와 새 GPU 구현을 비교했다. **현재 현상은 새 GPU 전환 경로의 물리 회귀로 다뤄야 한다. 단순히 CPU와 GPU가 달라서 생기는 정상 현상이나 새 정책의 탐색 행동으로 설명할 근거가 없다.** 정확한 잘못된 코드 한 줄이나 최종 해결책은 아직 확정하지 못했다.

## 가장 강한 재현 증거

이전 실제 영상·상태 기록은 `../guitar_learning_gpu_failure_video_v1/`, 동일 힘 재생 기준은 `../guitar_learning_gpu_force_replay_v1/`에 보존했다. 원래 CPU의 무행동 1환경은 2초 동안 실패하지 않았고, 새 GPU 1024환경은 무행동에서도 실패했다. 그러므로 정책 학습만의 문제가 아니다.

이번에는 안정적인 GPU 1환경에서 기록한 **똑같은 float32 관절 목표·힘 명령**을 1환경과 1024환경에 재생했다. 새 정책·피드백·보상·압현 판정을 다시 계산하지 않으며, 도중 reset도 없다. 아래는 두 실행의 **env0** 몸체 상태·관절 위치·속도 배열 비교다. 240Hz 128단계, 초기 상태 포함 129개 표본이다.

| 접촉 구성 | 1환경과 1024환경의 env0 비교 |
| --- | --- |
| 정상 접촉 | 기존 동일 힘 재생에서 크게 달라짐. 1024개 중 995개 환경이 안전 한계를 넘음 |
| 모든 접촉 제거 | 128단계 전체 비트 단위 동일 |
| 지면만 제거, 나머지 접촉 유지 | 19단계부터 달라짐 |
| 지면 접촉만 유지 | 128단계 전체 비트 단위 동일. 별도 반복도 동일 |

지면 접촉만 유지한 반복에서는 실제 접촉력도 기록했다. env0 마지막 표본의 최대 접촉력 성분은 두 실행 모두 43.2183N이다. 접촉을 실수로 전부 끈 결과가 아니다. 세부 배열·검증은 `comparison.json`, `verify_comparison.py`, `ground_only_force_n*/`를 따른다.

**이 재현에서는 지면 이외 접촉을 허용한 구성에서 배치 차이가 나타난다.** 진단의 공유 shape filter는 인체·기타·의자 사이 접촉과 자기접촉을 함께 막는다. 따라서 특정 인체↔기타 접촉쌍, collision cooking, 접촉 캐시, solver 내부 중 어느 것이 직접 원인인지는 아직 구분하지 못했다. 초기 접촉 기록 8단계에서 환경 간 잘못된 접촉은 발견하지 못했지만, 이후까지 배제한 것은 아니다.

접촉 제거 시험에서는 기타 지지가 사라지고 자유 낙하하므로 안전 한계도 넘는다. 이 시험은 **배치 차이를 분리하는 진단**이며 안정화 수정이나 학습 성공이 아니다. env0의 일치를 모든 환경의 전체 궤적 일치로 확대하지 않는다.

## 원본과 실제로 달라진 구현

| 항목 | 원래 CPU | 새 GPU | 조사 결과 |
| --- | --- | --- | --- |
| 물리 장면 | worker별 simulator 1개·env 1개 | simulator 1개에 다수 env | 접촉이 있는 배치 구성에서 회귀가 재현되는 핵심 경계 |
| 상태/명령 전달 | actor별 CPU API | 전체 tensor 및 indexed reset | 모든 actor·DOF·body native index 오류 0. canonical state descriptor와 indexed 명령 변형도 해결하지 못함 |
| 인체 질량·COM·관성 | 가져온 원본 속성 유지 | 저장 속성을 다시 설정 | 해당 재설정을 생략해도 회귀가 남음 |
| 기타 복원 | 모든 rigid-body 상태 복원 | free actor root 상태 복원 | 기타 고정 링크의 상대 자세는 유지됨. 단독 원인으로 확정할 증거 없음 |
| 하체/가슴/오른팔 유지 제어 | NumPy/SciPy·native 기반 | CUDA tensor·기하 Jacobian/질량·반복 IK | 공유 상태에서 제어 수식 차이는 작지만 native 폐루프 동등성을 증명한 것은 아님 |
| shape rest offset | 명시적으로 0 설정 | 명시적 복사 생략 | 실제 읽은 값은 전부 0이며 환경별 속성도 동일. 현재 값 불일치는 발견하지 못함 |

원문 위치: `guitar_learning/native/environment.py`, `runtime/headless_session.py`, `runtime/prepared_reset_v1.py`, `gpu/scene.py`, `gpu/control.py`. GPU 전환 전 원본은 `guitar_learning/archive/20261020_before_gpu_batch_v1/`에 보존되어 있다.

## 배제하거나 약해진 가설

- **정책·새 보상/접촉 판정이 기타를 날린다:** 무행동 및 동일 힘 재생에서도 재현한다. 이번 재생에는 새 보상·정책 피드백이 없다.
- **CUDA tensor 연결만 잘못됐다:** GPU PhysX를 유지하고 CPU tensor pipeline으로 바꿔도 1024환경 중 995개가 한계를 넘었다.
- **인덱스가 섞이거나 rest offset이 다르다:** 실제 native 전체 인덱스 오류 0. 1024환경 shape rest offset 150,528개 값은 모두 0이고 같은 종류의 shape 속성은 환경별 동일하다.
- **먼 월드 좌표만의 정밀도 문제다:** 빈 환경 1023개 뒤 [93,93,0]에 단일 실제 환경을 만든 시험은 동일 힘 128단계 동안 한계를 넘지 않았다. 위치·배치와 접촉의 상호작용까지 배제한 것은 아니다.
- **제어 수식이 처음부터 크게 다르다:** 같은 준비 상태·기하 Jacobian·질량행렬을 제공한 원래 CPU 수식과 새 float32 수식의 힘 차이는 최대 0.000087738Nm, 발 목표 차이는 0.0000050164rad다. 원래 CPU native Jacobian/질량행렬, 실행 중 전체 궤적을 비교한 것은 아니다. GPU 발 IK의 기준/초깃값이 원래 q_ref와 다른 작은 포팅 차이는 남아 있지만, 동일 힘 배치 차이를 설명하지는 못한다.

수식 비교 원문과 출력은 `compare_gpu_cpu_foot*.py`, `compare_gpu_cpu_foot*.out`에 사본을 보존했다. 이 비교는 실제 GPU/native 물리 동등성 검사로 인용하지 않는다.

## 해결로 채택하지 않은 진단

`comparison.json`은 완료 여부·실제 물리 flag·명령 일치·native index·환경별 첫 한계 초과를 기록한다. 한계 초과 수는 **서로 다른 환경 수**이며 학습의 에피소드 종료 수가 아니다. 실제 학습과 달리 원인 분리를 위해 한계 이후에도 재생을 계속했다.

- 상태 tensor 형태 정규화: 128단계 완료, 983환경 한계 초과.
- 인체 속성 재설정 생략: 128단계 완료, 1008환경 한계 초과.
- prepare_sim 이전 DOF 설정: 유효 57단계 뒤 비유한 물리 응답.
- indexed 목표·힘 제출: 유효 116단계 뒤 비유한 응답.
- PhysX thread 1: 유효 29단계 뒤 비유한 응답.
- iteration 16/8: 유효 6단계 뒤 비유한 응답.
- subscene 1: native SIGSEGV(-11), 보고서 생성 전 실패. 프로세스 결과·로그 보존.
- 새 장면을 CPU PhysX로 실행: 1환경도 GPU 기록 힘으로 128단계째 한계 초과했다. 이 GPU용 open-loop 명령은 원래 CPU의 폐루프 제어를 대신하지 않으므로 CPU 1024환경의 842개 초과를 원래 CPU도 같은 버그라는 증거로 사용하지 않는다.

## 현재 판단과 다음 수정 범위

우선 조사·수정할 곳은 **`gpu/scene.py`의 다중 환경 장면 생성·초기 복원과 지면 이외 접촉이 물리에 들어가는 경로**다. 다음 단계에서는 정상 지지 접촉을 보존하면서 접촉쌍/충돌 형상/초기 복원 조건을 더 분리하고, 동일 힘 재현에서 개선된 뒤 원래 CPU와 무행동·폐루프 궤적을 비교해야 한다. 접촉 제거·기타 부착·기타 직접 보조 힘·실행 중 상태 덮어쓰기를 수정으로 채택하지 않았다.

현 단계에서 안정적인 GPU 학습 환경 수를 다시 추천할 근거는 부족하다. 기존 128 권장은 유보하며, GPU 대규모 학습을 안정화 완료로 설명하지 않는다.

## 보존과 검증

실행 소스는 파일을 고치는 대신 메모리에서 한 조건씩 바꿨고, 각 시험에 정확한 `scene_variant.py.txt`와 입력 SHA를 남겼다. 실패·비유한 응답·충돌 로그도 삭제하지 않았다. 시점별 진단 helper는 `variant_probe_*group.py.txt`, `variant_probe_ground_split.py.txt`에 보존했다.

`verify_comparison.py` 실행 결과: 활성 Python 421개 원문 SHA 유지, 21개 진단 케이스의 기존 보고서/예외 확인, 저장 명령이 기준 tape의 prefix와 일치, native 전체 인덱스 오류 0, 접촉 분리 배열 비교 통과, 진단 Python 문법 통과. 독립 change-reviewer도 접촉 분리 결과와 해석 범위를 확인했다. 생산 Python 변경이 없어 전체 학습 테스트는 다시 실행하지 않았다.
