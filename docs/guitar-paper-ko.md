## 초록

양손의 높은 **시간적 정밀도** 협응이 필요한 과제(기타 연주)를 위한 물리 기반 정교한 모션 합성 방법을 제안한다. 두 손을 하나의 에이전트로 묶어 관절 정책(joint policy)을 직접 학습하는 대신, **협력 학습(cooperative learning)** 관점에서 각 손을 개별 에이전트로 취급한다:

1. 왼손(프렛 압현)·오른손(스트링 피킹) 정책을 **각각 분산 환경에서 먼저 학습**
2. 사전학습된 두 정책을 **잠금(lock)** 상태로 중앙집중 환경에 넣고, **잠재공간 조작(latent space manipulation)** 을 하는 **동기화기(synchronizer)** 만 학습해 양손 관절 정책으로 빠르게 결합

이렇게 하면 두 손을 합친 고차원 상태-행동 공간에서의 직접 학습을 피해 학습 효율이 크게 오른다. 학습된 가상 기타리스트는 **특정 곡 트래킹이 아닌 일반 연습 동작의 비정형(unstructured) 참조 데이터**로부터 모션을 합성하며, 참조에 없는 새로운 코드 프레싱·피킹 패턴을 입력 기타 탭에 맞춰 정확히 연주한다. 전문 기타리스트에게서 수집한 모캡 데이터도 함께 공개한다.

## 1. 서론

- VR/AR·가상 라이브 음악의 부상으로 악기를 연주하는 시뮬레이션 캐릭터 수요가 있으나, 제어 정밀도 요구가 높아 어렵다. 모캡 재생은 사실적이지만 비용이 크고 새로운 곡/리듬에 일반화되지 않는다.
- 기타 연주의 난점: 코드 프레팅(여러 줄 동시 압현), 스트러밍, 정교한 핑거피킹. 왼손은 리듬에 맞춰 신속히 압현/해제하고, 오른손은 줄이 올바른 눌림 상태가 된 **바로 그 시점**에 튕겨야 한다. 내추럴 하모닉스처럼 "오른손 직후 왼손 해제" 같은 기법도 있다 — 즉 **시간 동기화가 본질**.
- 기존 프렛팅 연구는 운지 배치를 휴리스틱 규칙으로 풀며 시간적 맥락에서의 실제 손 동역학을 무시. 본 연구는 **데이터 구동 + 물리 기반**으로 자연스러운 프렛팅을 만들고, 여기에 **양손 제어**를 도입해 프렛팅과 스트러밍이 같은 시간축 위에서 한 곡을 연주하게 한다 (소리는 양손 동역학 기반 후처리로 생성).
- 양손을 단일 에이전트로 학습하면 상태-행동 공간이 지수적으로 커지고, 중앙집중 환경 시뮬레이션 비용도 크다 → **분리 학습 후 동기화**.
- 참조 모션: 전문 기타리스트 약 1시간 모캡(특정 곡이 아닌 일반 주법 연습). 실제 모방학습에는 **스케일 연습(~40초, 양손)과 스트러밍(~3초, 오른손) 두 클립만** 사용 — 그럼에도 참조에 없는 운지·피킹 패턴을 자동 탐색으로 합성.

## 2. 관련 연구

- 물리 기반 제어: 궤적 최적화/휴리스틱 → 모캡 모방학습 → 최근 RL 기반 모방학습(DeepMimic, AMP, ASE, ICCGAN 계열)이 주류. 본 연구는 RL 기반 정교 양손 제어.
- **2.1 시뮬레이션 손의 정교 제어**: 파지/재배치, 손안 조작 연구가 다수지만 **높은 시간 정밀도가 필요 없고 대부분 한 손**. 악기 연주 모션 생성은 피아노 중심(RoboPianist 등). 초기 기타 연구 ElKoura & Singh 2003(Handrix)은 왼손 프렛팅만, 운동학 기반이라 시간 맥락의 손가락 전환 제약과 손가락-지판 충돌/접촉을 무시. 본 연구는 휴리스틱 운지 규칙 없이 **정책 스스로 운지를 탐색**하게 하고, 모방학습+RL로 비정형 참조에서 모션을 합성.
- **2.2 손 모션 데이터셋**: 파지/조작 위주이고 악기 연주는 바이올린·피아노 정도. 고품질 기타 연주 모캡의 공백을 본 연구의 ~1시간 데이터셋 공개로 채움.

## 3. 개요 (그림 2)

2단계 학습 체계:

1. **분산(single-hand) 학습**: 왼손 프렛 압현 정책 π_L(a^L|o^L), 오른손 피킹 정책 π_R(a^R|o^R)을 각각 학습. 멀티 목적 RL 프레임워크(Composite Motion Learning, Xu et al. 2023a)로 **모션 모방 목적 + 태스크 목적**을 함께 최적화. 왼손은 실제 곡에서 추출한 노트로, 오른손은 절차적으로 생성한 패턴으로 **범용(general-purpose)** 학습.
2. **동기화(synchronization)**: 사전학습 정책의 파라미터를 전부 잠그고, **synchronizer**가 양손 관측을 받아 두 정책의 잠재 벡터 z^L, z^R에 오프셋을 더해 행동을 조율 → 특정 목표 곡에 대한 양손 관절 정책 π(a^L, a^R | o^L, o^R) 완성. AdaptNet(Xu et al. 2023b)의 정책 적응 전략을 확장.

## 4. 정책 동기화

- 2-에이전트 협력 과제: max E[Σ_t γ^{t-1} R_t], 궤적 τ = {o^L_t, o^R_t, a^L_t, a^R_t}. 관절 정책은 단일 손 학습과 같은 방식(RL)으로 최적화 가능.
- 사람의 협력 학습 방식에서 착안한 2단계: 개별 기본기 먼저(분산 학습) → 협력 행동 적응(중앙집중). 기본기 없는 상태에서의 협력 학습을 피해서 효율 확보.
- **synchronizer 설계**: 사전학습 정책 네트워크를 직접 파인튜닝하지 않고, 양쪽 관측을 입력받아 **잠재 오프셋**을 출력:

```
z^L_t = E_φL(o^L_t) + Δz^L_t ,   z^R_t = E_φR(o^R_t) + Δz^R_t          (식 1)
Δz^L_t, Δz^R_t = S_θ( Concat( E^L_θ(o^L_t), E^R_θ(o^R_t) ) )           (식 2)
```

- S_θ는 MLP인데 **마지막 FC 레이어를 0으로 초기화** → 동기화 시작 시점에 개별 정책의 행동이 전혀 변하지 않음. 탐색이 무작위가 아니라 **사전학습 궤적에서 출발**하므로 효율적.
- synchronizer의 상태 인코더 E^L_θ, E^R_θ는 사전학습 정책의 인코더(E_φL, E_φR)를 **복제**해 초기화. 학습되는 것은 θ뿐.

`[역주]` 코드 대응: `models.py`의 `AdaptNet` 클래스 + `main.py` L456-529(TwoHands일 때 좌/우 체크포인트에서 Actor 재구성 후 `model.actor = AdaptNet(model, left_policy, right_policy)`). 보상 가중치를 ×2 하는 조정(main.py L525-528)은 단일 손 학습과의 일관성용이며 grad clipping 덕에 사소하다고 주석에 명시.

## 5. 기타 연주 태스크 설계

**셋업(그림 3)**: 6줄·24프렛 기타(스케일 길이 24.5인치 ≈ 0.62m), 픽 사용. 손 모델은 16링크·**27 DoF**(손목 6, MCP 2 — 엄지 MCP만 3, 나머지 관절 1). 코드 조합은 이론상 약 **90만 개**(줄당 프렛 4범위 + 개방 + 뮤트) — 전부 마스터하기 어려운 규모. 손만 제어하며 **기타는 3D 공간에 고정**. (기타 모델은 왼손잡이용이고, 오른손잡이 연주는 미러링으로 획득.)

### 5.1 왼손 정책 — 프렛 압현

- **goal**: 탭 형식 그대로 — 줄마다 목표 프렛 번호, **-1 = 개방현(눌러선 안 됨... 정확히는 피킹 전 누르지 않아야 함), 0 = 뮤트현**. 미래 5개 노트 + 노트별 남은 지속시간 타이머(시뮬레이션 프레임 수) → **g^L ∈ R^{5×7}**.
- **상태**: 기타 기준 상대좌표로 표현한 각 링크의 위치·방향·선/각속도, 2프레임 히스토리 → **s ∈ R^{2×16×13}**.
- **운지 비지정**: 운지 배치는 코드 패턴·생체역학(가동 제약, 에너지)에 얽힌 복잡한 문제지만, 명시적 운지 추론을 제공하지 않고 **정책이 스스로 탐색**하게 함. (GPS·Handrix와의 근본 차이)
- **멀티 목적 구성**: 줄마다 압현 조건이 다르므로 **6개 줄 각각을 하나의 목적(objective)** 으로 취급:

```
r_i = { r_i^k   (줄 i를 프렛 k에서 눌러야 할 때)
      { r_i^0   (개방현 — 누르면 안 될 때)                         (식 3)
      { r_i^-1  (뮤트현)
```

- **압현 보상** (식 4): `r_i^k = 0.8·exp(−1000·d²) + 0.2·exp(−30·d²)`
  - d = 줄 i의 프렛 k 중앙선과, **available한 손가락 파트**(원기둥) 최근접점 사이 최소 거리.
  - 손가락은 MCP–PIP, PIP–DIP, 끝마디의 3파트 원기둥 — 엄지 제외 4손가락 × 3 = **12파트**가 프렛팅에 사용 가능.
  - 지판 길이 ~0.45m, 프렛 폭 0.01~0.035m → 지수 2개 혼합 이유: **−1000 항은 d≈0.01m에서 민감**, −30 항은 d≈0.45m에서도 그라디언트가 죽지 않게(포화 방지).
- **available 판정(그림 4)**: 강한 압현은 손끝만이 아니라 마디로 눕혀 누르기도 하므로, MCP–PIP·PIP–DIP 파트는 **지판면과의 각도 < 5°일 때만** 압현에 사용. 여러 프렛 동시 압현 시 한 손가락이 프렛을 가로질러 누르거나 다른 손가락을 타 넘지 않도록, **손가락 순서 ↔ 목표 프렛 순서의 불일치로 파트 가용성을 결정**: 한 프렛에 여러 손가락 허용, 손가락 교차(cross-over) 불허. r_i^k는 available 파트만 대상으로 계산.
- **개방현 보상** (식 5): `r_i^0 = min{ (d_i/0.007)², 1 }` — 줄 i와 12개 손가락 파트 전체의 최단거리 d_i. 손가락 반경 ~0.006m이므로 0.007로 정규화, ≥1이면 안 닿은 것.
- **뮤트현 보상** (식 6): `r_i^-1 = 0.9 + 0.1·r_i^0` — 뮤트현은 피킹되지 않으므로 엄격히 제약하지 않음(느슨한 제약). 이론상으론 진동을 죽이러 살짝 대는 게 맞지만 강제하지 않음.
- **줄별 최종 보상** (식 7): `r^L_{t,i} = 0.8·r_i + 0.2·r^L_correct − 0.05·r^L_energy`
  - r_correct = **모든 줄이 동시에 정답 상태**일 때 1 (전역 정합 보너스)
  - r_energy (식 8): `exp(−(‖v_w‖ + 0.1·Σ_f ‖v_f‖)²)` — 손목 전역 속도 v_w + 손목 기준 손끝 국소 속도 v_f.
  - `[역주]` 식 7·8을 문자 그대로 읽으면 "느릴수록 벌점"이 되어 본문 의도("빠른 움직임을 벌점")와 부호가 안 맞는다. 코드는 `env.py` L1684-1686에서 **+0.05·exp(−50·fps·(Δwrist+0.1·Δfinger)²)** 즉 "느린 움직임 보너스"로 구현 — 의도(부드러움 유도)는 동일하며 논문 수식의 부호 표기가 어색한 것으로 보임.
- **모방(imitation) 목적 2개**: Composite Motion Learning을 따라 왼손 모션을 ① **기타 기준 손목+엄지** 모션, ② **손목 기준 나머지 4손가락 국소** 모션으로 분해하고 ICCGAN(GAN류 판별자)으로 모방. 손목·엄지 자세가 참조로 잡히니 기타를 자연스럽게 "쥐고", 4손가락은 기타 자세에서 자유로워 새로운 운지 탐색 가능.
  - `[역주]` cfg의 discriminator 정의와 정확히 일치: `LH/wrist`(key=wrist+thumb, parent=guitar), `LH/fingers`(key=4손가락, parent=LH:wrist).
- **최적화** (식 9): `max E[ Σ_κ w_κ · Ã^L_{t,κ} · log π_L(a^L|o^L) ]` — 목적별 표준화 어드밴티지 Ã의 가중합. **w = 0.15 × 6(프렛팅) + 0.05 × 2(모방)**. 백본은 DPPO(actor-critic PPO).

### 5.2 오른손 정책 — 스트링 피킹

- **goal**: 피킹 여부만 필요하므로 **이진 벡터**(프렛 정보 없음). 한 노트 동안 목표 줄은 **정확히 1회** 피킹; 이미 피킹된 줄은 그 노트의 남은 프레임에서 goal 표기를 0으로 되돌림(재피킹 방지).
- **크리틱 확장 관측**: 현재 노트에서 각 줄이 잘못 다뤄졌는지의 이진 벡터를 추가한 **g^{R+} ∈ R^{5×7+6}** 를 크리틱에만 입력 — 가치 추정 정확도에 결정적(효율적 학습의 핵심).
- **통합 목적**: 왼손과 달리 줄별 목적으로 나누지 않음. 여러 줄 피킹은 **일관된 방향(위→아래 또는 아래→위)의 빠른 연속 동작**이어야 하므로 하나의 통합 목적:

```
r_pick = { r^+   (이번 스텝에 어떤 줄이든 피킹됨)
         { r^−   (이번 노트에 남은 목표 줄이 없음)                  (식 10)
         { r^×   (그 외 — 목표가 남았고 피킹 없음)
```

- **오처리(wrongly tackled) 정의**: ① 비목표 줄 피킹, ② 위→아래 진행 중 목표 줄을 건너뛰고 아래 줄 피킹, ③ 아래→위 진행 중 건너뛰고 위 줄 피킹.
- (식 11) `r^+ = min_i r_{d_i}`(오처리 발생 시; d_i는 픽 끝→오처리 줄 거리) 아니면 `r_succ = 1`. (식 12) `r_{d_i} = 0.175·exp(−10000·d_i²) + 0.025·exp(−2000·d_i²)` — 잘못 건드린 줄에서 **멀어지도록** 유도 (거리 스케일 mm~dm).
- (식 13) `r^− = 0.4·min{min_i d_i/0.003, 1} + 0.1·Σ_i r_i + 0.5·Π_i r_i` — 남은 목표가 없으면 **모든 줄에서 0.003m 이상 떨어져 대기**; r_i = 줄 i가 올바로 처리됐으면 1. Π 항은 6줄 전부 정답일 때만 발동.
- (식 14) `r^× = 0.2 + 2·min{r_{d_top}, r_{d_bottom}}` — 최상단/최하단 목표 줄 중 가까운 쪽으로 픽을 이동시킴. 항상 `1 = r_succ > r^× ≥ 0.2` 라서 "끝 줄부터 순서대로 피킹"이 우선순위를 가짐.
- **오른손 총 보상** (식 15): `r^R_t = r_pick + 0.05·r_contact + 0.05·(r^R_energy + r^pick_energy)`
  - r_contact = 엄지와 검지가 올바로 맞닿아 **픽을 쥔 상태**면 1.
  - r^pick_energy (식 16): `exp(−20‖v_pick‖² − 14‖0.05·a_pick‖⁴)` — 픽의 속도·가속도를 억제해 안정적 픽 움직임 유도.
- **모방 목적 1개**: 오른손은 손 전체를 한 그룹으로 모방(픽 스트럼은 손목 스윕에 손가락이 순응하는 미묘한 동역학). 총 2목적(goal 1 + imitation 1), **가중치 각 0.5**.

### 5.3 양손 동기화

- 4절의 방식으로 특정 목표 곡에 대해 관절 정책을 최적화하되 **θ(synchronizer)만 갱신**.
- 왼손: 6 goal + 2 imitation 목적 유지 (새 코드 패턴 앞에서 자연스러운 자세 유지에 참조가 여전히 필요).
- 오른손: **모방 목적 제거**, goal 목적만 — 피킹 패턴 수가 제한적이라 이미 마스터됨.
- **협력 조건**: 오른손의 r_pick 계산 시, **모든 줄이 기대 압현 상태가 아니면 목표가 없는 것(r^× 케이스)으로 간주** — 왼손이 준비될 때까지 오른손이 기다리는 구조.
  - `[역주]` 코드 대응: `ICCGANTwoHands.reward()`(env.py L2185-2201)의 `ready` 마스크 — `pressed`(왼손 정답) 또는 `timer`(노트 잔여 ≤3틱 or 경과 ≥5틱)면 발동. 타이머 예외는 논문에 없는 구현 디테일.

## 6. 실험

**셋업**: IsaacGym, 손 모델은 Modular Prosthetic Limb(MPL, Kumar & Todorov 2015) 수정판. 관절은 모터+PD 제어, 행동 공간 **a^L, a^R ∈ R^27**. **물리 240Hz, 제어 60Hz**. 줄 동역학은 시뮬레이션하지 않고 **가상 판정**: 손가락 파트가 줄에서 **0.006m 이내**(≈손가락 반경)면 "눌림", 픽 끝이 줄의 가상 위치를 **줄 아래 궤적으로 한쪽에서 반대쪽으로 통과**하면 "피킹".

**학습 데이터**: 왼손 범용 학습은 **500개 곡 트랙**에서 추출한 노트(다양한 리듬·템포) + 온라인 증강(코드 패턴 유지한 채 지판 위 랜덤 시프트, 템포 ±20BPM 확률 조정). 오른손은 절차적 스트러밍 패턴. 동기화 단계에서 특정 곡으로 파인튜닝. 모방 참조는 스케일 연습 ~40초(양손) + 스트러밍 ~3초(오른손) 두 클립뿐 — **트래킹이 아닌 신규 모션 합성**.

### 6.1 정량 결과

- **지표**: 노트 수준 F1. TP = 노트 지속시간 동안 올바로 눌리거나/피킹된 줄. 왼손: 노트 지속시간의 **≥2/3 동안 연속으로** 목표 프렛에 눌려야 정답. 오른손: 목표 줄이 일관된 순서로 **정확히 1회** 피킹돼야 정답. 양손 관절: ① 올바른 피킹 ② 피킹 시점에 올바른 압현 ③ 피킹 후에도 지속시간 2/3까지 압현 유지 — 세 조건 동시 만족.
  - `[역주]` 코드의 왼손 통계(env.py L1584, `goal_orig_t2 = 0.5·노트길이`)는 ½ 기준으로 구현되어 논문 서술(2/3)과 미세하게 다름.
- **단일 손 평가** (테스트 50트랙, 반복 제거 후 4859노트): 왼손 전체 F1 ≈ **0.8**. 단선율(한 줄) 노트는 **150BPM에서도 거의 100%**. 코드(chord) 노트는 약 40%의 코드에서 F1 > 0.8; **약 20%의 코드는 F1 < 0.5**(그림 5) — 500트랙으로도 코드 조합 공간을 다 못 덮음(학습셋에 거의 안 나온 코드가 병목). 오른손은 피킹 패턴이 제한적이라 **전 노트 평균 F1 > 0.9**로 일관.
- **동기화 평가** (25트랙, 그림 6): 동기화 전후 F1 — **최대 657% 개선, 평균 +193%**. 두 손 협응 요구 때문에 동기화 전 양손 F1은 단일 손 평가보다 낮다(≈0.2~0.7). **동기화 후 대부분 곡에서 거의 100% 정확도**. 흥미로운 점: 전체 네트워크 파인튜닝이 아니라 **잠재 조작만으로**, 오른손은 모방학습도 없이 이만큼 개선 — 사전학습 정책이 필요한 자세를 이미 갖추고 있었고, 개선은 파인튜닝 효과 + 동기화된 협응 양쪽에서 옴.

### 6.2 정성 결과

- 왼손: **11프렛(~0.3m) 원거리 점프 압현**(그림 7; 최소 프렛 폭 0.01m의 공간 정밀도), 참조에 없는 다양한 신규 코드(그림 8) — 손가락 대스트레치, 한 손가락 다줄(바레류), 같은 프렛 다손가락(2·3번줄 약지 + 6번줄 소지) 등. **모방 없이 태스크 보상만으로 학습하면 부자연스러운 자세**(그림 11)와 대비.
- 오른손: Hotel California 피킹(그림 9) — 방향 지시 없이도 위→아래→위 일관 리듬을 에너지 효율적으로 유지. 빠른 스트러밍(그림 10).
- **아르페지오**(그림 13): 오른손이 개별 줄을 차례로 피킹하는 동안 왼손이 코드 자세를 유지 — 단, **왼손 goal에만 코드(Dm6)를 명시적으로 공급**하고 synchronizer·오른손은 개별 피킹 줄만 받음. 실제 악보에 코드 심볼을 병기하는 것과 같은 조치 (한계 D 참고).
- 시간 정밀도가 높아 **여러 대의 기타 합주(ensemble)** 도 가능.

## 7. 결론

분산 학습으로 기본기를 만들고 중앙집중 환경에서 synchronizer로 결합하는 물리 기반 양손 제어. 시간적·공간적 고정밀 협응이 필요한 기타 연주에서 유효성을 입증. 비정형 참조 데이터에서 정확하고 자연스러운 모션을 합성하며, 데이터 전부 공개.

## 부록 A: 기타 연주 모션 데이터셋

- NOKOV 모캡, 적외선 카메라 18대(9MP×7 + 4MP×11), **손마다 마커 19개 + 기타에 4개, 120FPS**.
- 총 ~1시간: 12개 장조 스케일, 반음계 스케일, 다양한 코드, 아르페지오, 스트러밍·피킹, 벤딩, 슬라이드, 비브라토, 팜 뮤트, 내추럴/아티피셜 하모닉스, 해머온/풀오프.
- 모든 노트는 1/8음표, 대부분 100BPM. 악기: Fender American Deluxe Stratocaster (6줄 22프렛, 스케일 25.5인치).
- `[역주]` `guitar/dataset/`에 동봉된 그 데이터. `dataset/doc/guitar.pdf`는 이 기타의 시리얼 스펙 문서.

## 부록 B: 구현 상세

- PPO + Adam. 판별자 학습 샘플의 절반은 시뮬레이션, 절반은 참조 모션.
- **표 S1 하이퍼파라미터**:

| 파라미터 | 값 |
|---|---|
| policy lr | 5×10⁻⁶ |
| critic lr | 1×10⁻⁴ |
| discriminator lr | 1×10⁻⁵ |
| discount γ | 0.95 |
| GAE λ | 0.95 |
| surrogate clip ε | 0.2 |
| gradient penalty 계수 | 10 |
| PPO workers (환경 수) | 512 |
| PPO replay buffer | 4096 |
| PPO batch | 256 |
| PPO opt epochs | 5 |
| disc replay buffer | 8192 |
| disc batch | 512 |

- **네트워크(그림 S2)**: 상태 인코더 = 포즈용 **GRU(hidden 256)** + goal용 2층 MLP, 두 인코딩을 **덧셈**으로 결합해 잠재(z)로 사용 (이 z가 동기화 조작 지점). 정책 FC(1024-1024-512) → μ, logσ. 가치망은 같은 구조에 다중 출력 — **왼손 8개(goal 6 + imitation 2), 오른손 2개, 관절 정책 9개**. 양손 학습 시 s = {s^L, s^R}, g = {g^L, g^{R+}}.
- 정규화: 왼손 프렛 표현은 [−1,1] 정규화, 오른손은 이진. 상태에 이동평균 정규화, 가치 출력은 **PopArt**.
- **비용**: Nvidia V100 1대. 개별 정책 학습 **3–4일, ~8×10⁸ 샘플**. 동기화는 **1.5–12시간, 1×10⁷–8×10⁷ 샘플**(곡 난이도 — 코드 패턴·템포에 좌우).

## 부록 C: 어블레이션

- 비교 3종: **GSync**(범용 왼손 정책을 동기화) vs **SSync**(곡 전용으로 학습한 왼손 정책을 동기화) vs **Joint**(양손을 처음부터 단일 에이전트로 합동 학습). 오른손은 전 경우 공용(범용으로 충분).
- 곡 전용 왼손 정책: 통상 ~2×10⁷ 샘플, 어려운 곡(170BPM Flight of the Bumblebee, 아르페지오 많은 Prelude No.1)은 3.5–8×10⁷. 단독 F1 0.98–1.0에 도달하지만 **오른손과 합치면 비동기화로 ~20% 하락** → 동기화가 이를 회복.
- 범용 왼손 정책은 곡 전용보다 낮지만(특히 코드 많은 Corcovado) 대부분 곡 F1 > 0.8이고 **재사용 가능**, 동기화 후 곡 전용과 비슷한 최종 성능 도달.
- **Joint(처음부터 합동)**: 학습이 매우 느림 — 초기에 협응 구축이 아니라 기본기 무작위 탐색에 소모. 게다가 **양손 시뮬레이션은 단손 대비 ~40% 느림** → 같은 샘플 수를 모으는 데 훨씬 오래 걸림. 충분히 오래 학습하면 결국 더 좋아질 수도 있으나, 제안 방식이 중앙집중 환경에서의 학습량을 줄여 훨씬 효율적.

## 부록 D: 한계

1. **에너지 항 ↔ 반응성 트레이드오프**: 식 8은 빠른 움직임을 단순 벌점 처리. 숙련 기타리스트의 에너지 효율적 모션 계획과 달리, 짧은 노트에도 반응하려면 가중치를 작게/리듬별로 튜닝해야 하고, 빠른 곡에서는 부자연스럽게 급한 움직임을 완전히 못 없앰.
2. **5노트 미리보기의 한계**: 사람처럼 긴 지평의 운지 계획(손가락 기민성, 근피로 고려)이 없음. 아르페지오에서 왼손이 코드 패턴을 스스로 감지하지 못해 **코드 노트를 왼손 goal에 별도 공급**해야 했음(그림 13). 탭에 코드 심볼을 병기하는 것과 유사하나, 사람 수준의 모션 계획 지능은 향후 과제.
3. **줄 동역학 미시뮬레이션**: 눌림/피킹 판정이 휴리스틱이고 소리는 후처리 — 비브라토, 핑거스타일처럼 줄과의 복잡한 상호작용 기법 도입 불가. 강체 손 모델이라 미세한 손 모양 변화도 생략.
4. **고정 60Hz 제어의 시간 해상도 한계**: 최단 노트가 정수 프레임이 되도록 템포를 반올림(예: 1/16음표 기준 100–105BPM → 100). 임의 시간 해상도의 정밀 제어는 향후 과제.
5. **분산 환경 셋업 요구**: 개별 정책용 분산 환경 구성이 항상 쉬운 것은 아님. 기타 유사 악기(베이스, 우쿨렐레)엔 적용 기대, 하프·바이올린처럼 복잡한 줄 동역학 악기엔 일반화 어려움.
