## 1. 기초 용어 — 기타를 모르는 사람을 위한 최소 지식

- **줄(string) 6개**: 굵은 줄일수록 낮은 음. 아무것도 안 누르고 튕기면 각 줄의 기본음(**개방현**, open)이 난다.
- **프렛(fret)**: 지판에 박힌 금속 칸막이. "3프렛을 누른다" = 3번째 칸 안쪽을 눌러 줄의 유효 길이를 줄인다. 프렛이 1 올라갈 때마다 음이 반음씩 높아진다. 즉 **(줄, 프렛) 한 쌍이 음 하나를 결정**한다. 프렛 0 = 개방현(누르는 손가락 없음).
- **탭(tablature)**: 오선 악보와 달리 "몇 번 줄의 몇 프렛"을 직접 지시하는 기보법. 같은 높이의 음이 여러 (줄, 프렛) 조합으로 존재하는 것이 기타의 특징인데, **탭은 그 선택을 이미 끝낸 표기**다.
- **왼손가락 번호**: 1=검지, 2=중지, 3=약지, 4=소지. 엄지는 넥 뒤를 받치는 용도라 운지에 쓰지 않는다. 오른손은 줄을 튕기는 손 — 이 문서 범위 밖.
- **소노리티(sonority)**: 같은 순간(±30~50ms)에 시작되는 음들의 묶음. 한 음이면 크기 1.
- **포지션 P**: 검지가 담당하는 프렛 번호. 기본 규칙 "1프렛 1손가락" — 검지=P, 중지=P+1, 약지=P+2, 소지=P+3. 손 전체를 옮기는 것이 **포지션 시프트**.
- **코드(chord)/그립(grip)/폼(form)**: 여러 줄을 동시에 눌러 화음을 내는 손 모양. 관용 손 모양들이 **코드 차트**에 손가락 번호까지 문서화되어 있다.
  - 표기 예: C 코드 = `x32010` — 6번줄(가장 굵은 줄)부터 순서대로 [안 침(x), 3프렛, 2프렛, 개방(0), 1프렛, 개방(0)]. 관례 운지는 3프렛=약지(3), 2프렛=중지(2), 1프렛=검지(1).
- **바레(barre)**: 검지를 막대처럼 눕혀 **같은 프렛의 여러 줄**을 한 번에 누르는 기술 — 프렛은 하나, 줄이 여러 개다(한 손가락으로 여러 *프렛*을 누르는 것은 물리적으로 불가능 — 규칙 4의 "1손가락 1프렛"이 그 사실의 코드화). F 코드가 대표: 검지가 1프렛에서 6줄 전부(프렛 음 6개, 손가락은 1개) + 나머지 손가락이 E폼. 일부 줄만 걸치면 부분(하프) 바레. 부수 제약 = **바레 그늘**: 바레가 걸린 줄들에서는 바레 프렛보다 낮은 음(개방현 포함)을 낼 수 없다 — 검지가 이미 그 위를 막고 있으므로.
- **앵커 핑거(anchor finger)**: 코드를 바꿀 때 두 코드에 공통인 (줄, 프렛)을 누르던 손가락을 떼지 않고 유지하는 것. 예: Am(`x02210`, 검지=2번줄1프렛·중지=4번줄2프렛·약지=3번줄2프렛) ↔ C(`x32010`, 검지=2번줄1프렛·중지=4번줄2프렛·약지=5번줄3프렛) — 검지·중지는 그대로 두고 약지만 움직인다. 교본 운지가 그렇게 정해진 이유.
- **CAGED**: 오픈 코드 5가지(C·A·G·E·D) 폼을 바레와 함께 지판 위로 평행이동하면 모든 루트의 코드를 만들 수 있다는 체계. 이동 가능한 폼 사전의 이론적 근거. (moum 데이터 파일명 `E1-Major 05` = E폼을 5프렛 이동 — 같은 원리.)

## 2. 문제 정의

**입력**
1. 노트 리스트: v1 CSV `(string, start, end, pitch)` → `fret = pitch − 개방현pitch[string]`로 (줄, 프렛, 시작, 끝) 사건 목록을 만든다.
2. 코드 구간 리스트: consonance-ACE `.lab` `(t0, t1, Harte라벨)` → root+quality로 정규화, 실제 오디오 길이로 클립(zero-pad 꼬리 N 제거).

**출력**
- 노트별: 손가락 ∈ {0(개방·손가락 없음), 1, 2, 3, 4}, 바레 소속 여부.
- 시간별 손 상태 트랙: 포지션 P, 바레 {프렛, 줄 범위}, 그립 id(코드 구간).
- 진단 리스트: 어떤 규칙으로도 실현 불가한 소노리티(전사 오류 후보).

**스코핑(중요)**: 고전 운지 연구는 "음높이 → (줄, 프렛, 손가락)"을 한꺼번에 풀지만, 우리는 탭이 (줄, 프렛)을 이미 고정했으므로 **"어느 손가락으로, 손을 어디에 두고"만 결정**하는 축소 문제다. 훨씬 잘 정의되고 탐색 공간이 작다. (탭 자체를 교정하는 확장은 §11 진단 피드백과 chord-module-design의 경로 C로 연결.)

⚠️ **줄 번호 관례 함정**: CSV는 0=low-E, note JSON은 frets[5]=low-E (PROJECT_CONTEXT §7). 매퍼 내부 관례를 CSV 관례(0=low-E) 하나로 고정하고 입출력 경계에서만 변환한다.

## 3. 설계 원리 — 규칙 5개의 역할 분담

사용자 규칙 1~5는 성격이 두 부류다:

| 부류 | 규칙 | 역할 |
|---|---|---|
| **정책(policy)** | 1 코드 사전, 2 포지션, 3 선행 문맥 | 어떤 후보를 먼저/좋게 볼 것인가 (사람의 사고 순서) |
| **제약(constraint)** | 4 생체역학, 5 울림 유지 | 물리적으로 불가능한 후보의 즉시 탈락 (항상 켜져 있음) |

"1번부터 순서대로 적용"의 정확한 의미: **규칙 1→2는 후보 생성의 우선순위 캐스케이드**(코드면 사전에서, 아니면 포지션 규칙으로), **규칙 3은 후보들 사이의 선택 기준**(비용 함수 + 미래 내다보기), **규칙 4·5는 모든 단계에서 상시 필터**다. 상위 규칙의 1순위 후보가 4·5에 걸리면 같은 단계의 차순위 후보로, 그것도 안 되면 다음 단계로 폴백한다.

또한 규칙 3이 "다음에 올 것"을 요구하므로 알고리즘은 노트 하나씩의 탐욕(greedy) 결정이 아니라 **구간 단위 최적화**여야 한다 — 구현은 빔 서치(beam search).

## 4. 파이프라인 개요

```
A. 시간 분할     탭+코드트랙 → 소노리티 묶기 → 구간을 CHORD / ARPEGGIO / MELODY로 분류
B. 후보 생성     CHORD·ARPEGGIO → 규칙1(사전 조회, 폴백 포함)
                MELODY        → 규칙2(포지션 후보)
                모든 후보에 규칙4·5 마스크
C. 시퀀스 결정   규칙3 — 전이 비용 함수 + 빔 서치로 구간 전체 최소비용 경로
D. 후처리       모티프 일관성, 게으른 손떼기, 진단(전사 오류 후보) 출력
```

## 5. 단계 A — 시간 분할

**A-1 소노리티 묶기**: onset이 30~50ms 이내로 모인 노트를 하나의 소노리티로. 이후 모든 결정의 단위.

**A-2 구간 분류 (ACE × 탭 교차검증)**: ACE의 각 코드 구간에 대해 그 구간 탭의 피치클래스 집합(pcset)과 동시성을 검사한다.
- 탭 pcset ⊆ 코드 pcset **이고** 3줄 이상 동시 onset → **BLOCK_CHORD** (블록 코드)
- 탭 pcset ⊆ 코드 pcset **이고** 순차 발음 + 발자국(눌리는 (줄,프렛) 집합)이 정적 → **ARPEGGIO** (분산화음: 코드 폼을 잡은 채 한 줄씩 튕김)
- 불일치 → **MELODY**. **탭 우선 원칙**: 07-13 실측에서 탭→규칙 디코딩(acc 0.937)이 학습 코드 헤드보다 신뢰 가능했다. ACE의 기여는 라벨 명명·경계 시각·탭이 틀렸을 때의 2차 의견이다. 둘이 일치하면 고신뢰 코드 구간, 불일치하면 멜로디로 보수적 처리.
- 회색지대(멜로디+반주 혼재): CHORD로 두고 초과 멜로디 음은 자유 손가락으로 처리(§6, 규칙 5가 자연스럽게 조율).

**A-3 경계 스냅**: ACE 경계(내부 43fps, ±수십 ms 오차)를 가장 가까운 소노리티 onset으로 스냅.

## 6. 단계 B-1 — 규칙 1: 코드 사전 조회

**사전 구조**: `(root, quality)` → 그립 목록(관용도 순). 그립 = 발자국 {(줄, 프렛옵셋)} + 손가락 템플릿 + 바레 스펙 + 기준프렛. 내용물:
- 오픈 폼: C, A, G, E, D, Am, Em, Dm, (E7, A7, D7 …)
- 이동 폼(CAGED): E폼 바레(루트=6번줄), A폼 바레(루트=5번줄) 중심, 필요시 C·G·D폼
- 파워코드(5): 루트+5도 2~3줄 폼 (검지+약지 또는 검지+약지+소지)
- 부분 폼: 상위 3~4줄만 잡는 축약형

**매칭 절차** (그립을 root에 맞게 평행이동한 뒤 탭 발자국과 비교):
1. **완전 일치** → 즉시 채택, 손가락 번호를 사전 그대로 스탬프.
2. **탭 ⊂ 그립** (부분 스트럼 — 사람은 폼 전체를 잡고 일부만 튕긴다) → 그립 전체를 잡는 것으로 채택. (모션 최소화를 원하면 눌린 줄만 잡는 옵션 — 파라미터로.)
3. **탭 ⊃ 그립** (코드 위 멜로디 음) → 그립 + 초과 음은 남는 손가락으로(규칙 4·5 검사).
4. **어느 그립도 불일치** (희귀 보이싱) → 일반 솔버 폴백: 소노리티의 최저 프렛에 2줄 이상 있으면 검지 바레 후보 생성, 나머지 음을 프렛 오름차순으로 낮은 손가락부터 배정, 규칙 4 통과 조합만 후보로.

**ARPEGGIO 처리**: 그립을 구간 전체에 **플랜트**(전 손가락 유지). 규칙 5(울림 유지)가 자동 만족되고, 사람의 실제 연주 방식과 같다.

**복수 그립의 선택은 여기서 끝내지 않는다**: 같은 C:maj라도 오픈 C와 3프렛 A폼 바레 C가 모두 후보로 살아남아 §8의 문맥 비용이 결정한다(직전·직후 포지션이 3프렛 부근이면 바레 C가 이길 수 있음 — 규칙 3의 소관).

## 7. 단계 B-2 — 규칙 2: 포지션 기반 멜로디 후보

- 기본 배정: 포지션 P에서 프렛 f의 음 → 손가락 `k = f − P + 1` (1..4로 클램프). f=0(개방) → 손가락 0, 왼손은 자유.
- 후보 P의 범위: 현재 윈도(소노리티 몇 개 앞까지)의 프렛 min/max에서 유도 — 모든 음이 [P, P+3]에 들어가는 P들.
- 포지션을 벗어나는 음의 두 가지 해법(모두 후보로 생성):
  - **스트레치**: 검지를 P−1로, 소지를 P+4로 벌림 (벌점, 규칙 4의 스팬 한계 내에서만)
  - **시프트**: P′로 손 전체 이동 (큰 비용). 시프트 타이밍은 쉼표나 개방현 발음 중이 우선 — 개방현은 왼손이 놀고 있는 자유 시간이다.
- 산출: 소노리티마다 {P 유지, P 스트레치, P′ 시프트} × 손가락 배정의 후보 목록.

## 8. 단계 C — 규칙 3: 문맥 최적화 (알고리즘의 심장)

**상태**: (포지션 P, 손가락→(줄,프렛) 배치, 바레 상태, 손가락별 플랜트 종료시각).

**전이 비용** (소노리티 i−1의 상태 → i의 후보):
| 항목 | 방향 | 근거 |
|---|---|---|
| 포지션 시프트 \|ΔP\| | 벌점 (초선형: 큰 도약일수록 가중) | 규칙 2 — 시프트는 비싸다 |
| 시프트가 쉼표·개방현 중 | 벌점 할인 | 자유 시간 활용 |
| 손가락 뗌+누름 횟수 | 벌점 | 모션 최소화 |
| 손가락 이동 거리 합 | 벌점 | 〃 |
| 스트레치·바레·소지 과사용 | 벌점 | 규칙 4의 소프트 영역 |
| **앵커 유지** — 같은 (줄,프렛,손가락) 지속 | **보너스(음의 비용)** | 규칙 3 — Am↔C의 검지·중지가 자동 재현되는 메커니즘 |

**탐색**: 빔 서치. 각 소노리티에서 (이전 빔의 상태 × 현재 후보) 조합의 누적 비용을 계산해 상위 K(≈10~50)개만 유지. **지평(lookahead)** = 다음 코드 경계까지 또는 고정 k 소노리티.

**"선행 준비"가 별도 규칙이 아니라 창발하는 이유**: 지평 안에 다음 코드가 들어오면, 그 코드의 그립과 연결 비용이 낮은 경로(필요한 손가락을 미리 비워두고, 앵커를 유지하는 경로)가 누적 비용 최소가 되어 자동으로 선택된다. 두 논문(GPS·Xu)이 공통 한계로 꼽은 "선행적 운지 계획 부재"를 정확히 이 지평이 메운다.

**동률 판정**: 낮은 포지션 우선(저프렛 편향 — 20곡 통계에서 1~12프렛이 91.8%), 강한 손가락 우선(검지>중지>약지>소지).

## 9. 규칙 4 — 생체역학 마스크 (상시 필터)

동시에 눌려 있는 배치 전체에 대해:
1. **교차 금지**: 손가락 번호 i<j이면 fret(i) ≤ fret(j). 같은 프렛은 허용(다른 줄에 손가락을 세로로 쌓는 것은 정상).
2. **스팬 한계**: 눌린 프렛 max−min ≤ 4는 허용, 5는 스트레치 벌점부 허용, 6+ 하드 탈락. 손가락 쌍별 세분(3-4 사이가 가장 좁음, 1-2가 가장 넓음)은 파라미터.
3. **한 손가락 = 한 프렛**: 같은 손가락이 서로 다른 프렛을 동시에 못 누른다. 예외 = 바레(사실상 검지 전용, 같은 프렛의 연속 줄).
4. **바레 그늘**: 바레 중에는 바레 프렛보다 낮은 프렛의 음을 그 줄들에서 낼 수 없다.
5. (소프트) 인접 손가락이 멀리 떨어진 줄로 도약하는 배치 벌점.

Xu의 availability 마스킹(교차 금지·마디 각도)과 동형 — 후보 생성 직후의 필터로 구현한다.

## 10. 규칙 5 — 울림 유지 (상시 필터)

- 노트가 [t_on, t_off) 동안 울려야 하면 그 손가락은 그 시간 동안 **플랜트**(고정) — 겹치는 새 음에 쓸 수 없다. GPS `arrangeFinger`의 last-usage-time 체크와 동형.
- 바레는 그 위에서 울리는 모든 음이 끝나야 해제 가능.
- 개방현의 울림과 손 이동의 간섭(이동 중 스치면 뮤트됨)은 v0에서 무시 — 소프트 벌점 후보로 예약.

## 11. 단계 D — 후처리

1. **모티프 일관성**: 동일한 (줄,프렛,리듬) n-gram이 반복되면(리프·후렴) 동일 운지를 강제(가장 많이 선택된 배정으로 통일). 사람은 프레이즈 단위로 운지를 암기하며, RL 학습 데이터로서도 일관성이 안정성을 높인다.
2. **게으른 손떼기(lazy lift)**: 뗀 손가락을 다음 사용 위치로 바로 보내지 않고 현 위치 위에 호버 유지 — 모션이 자연스러워지고 이동량이 준다. 제어 모델에 "뗌 vs 압력 해제" 릴리즈 의미론과 함께 전달.
3. **진단 출력**: 어떤 후보로도 규칙 4·5를 만족 못 하는 소노리티 = **전사 오류 가능성 높음**(note F1 0.596). 플래그를 남겨 (a) 사람 검수 (b) 향후 탭 교정 피드백 루프(chord-module-design 경로 C: 그립 후보로 탭 재채점)의 입력으로 쓴다. **운지 불가능성은 공짜로 얻는 전사 오류 검출기다.**

## 12. 추가 제안 규칙 (6~10)

6. **개방현 활용**: 개방현 발음 순간·직전은 왼손의 자유 시간 — 시프트와 다음 폼 준비를 여기에 배치(§7·§8 비용 할인으로 구현).
7. **주법 어포던스**: 같은 줄에서 1~2프렛 차 연속음은 슬라이드/해머온/풀오프로 잇는 게 자연스러움 → 같은 손가락 유지 선호. v0 범위 밖(전사가 주법을 출력하지 않음), 비용 항 자리만 예약.
8. **모티프 일관성**: §11-1 (반복 구절 = 동일 운지).
9. **에너지 최소화 + 손가락 강도 서열**: 동률 판정자 — 총 이동량·뗌/누름 횟수 최소, 오래 누르는 음·벤딩은 강한 손가락에.
10. **릴리즈 의미론**: 노트 끝 = 완전 뗌이 아니라 압력 해제(손가락은 줄 위) — 제어 모델 인터페이스에 명시해 불필요한 큰 모션 방지.

## 14. 검증 계획

- **하드 제약 위반율 = 0**: 출력 전 자동 전수 검사 (규칙 4·5 위반 없어야 함 — 구성상 보장되지만 회귀 테스트로).
- **코드 구간**: 사전 커버리지(20곡 + moum에서 사전 매칭 성공률)와 코드 차트 일치율.
- **멜로디 구간**: 20곡 큐레이션 탭에서 이동 비용 통계, 탐욕 vs 빔 서치 ablation, 시프트 횟수 분포의 상식성.
- **질적 검증**: 교본 운지(코드 차트·스케일 포지션 연습)와 표본 대조, 지판 시각화 위 육안 검토.
- 근본 한계: **GT 운지 데이터셋이 없다** — 프록시 지표 + 사례 검토로 갈음. (GuitarSet도 줄/프렛까지만 제공.)

## 15. 구현 단계 제안

- **M1**: 입력 파서(CSV+lab) + 소노리티 + 구간 분류 + 규칙4·5 검사기 — 진단 리포트만 내는 골격.
- **M2**: 코드 사전 + 매칭 + 멜로디 탐욕(포지션 유지·시프트만) → end-to-end 첫 출력, rock3로 스모크.
- **M3**: 빔 서치 + 비용 함수 + 앵커 보너스 (규칙 3 완성) — M2 대비 이동 비용 개선을 수치로.
- **M4**: 후처리(모티프·lazy lift) + 진단 피드백 + note JSON 병합 + 데모 곡 파이프라인 통합.

## 16. 관련 연구 (맥락)

- Sayegh 1989 "optimum path paradigm" — 운지=그래프 최단경로 관점의 원조. 이후 Radicioni & Lombardo(제약/그래프), Hori & Sagayama(HMM 기타 운지·탭), Tuohy & Potter(GA) 등이 같은 골격.
- 본 설계의 차별점: ①탭이 (줄,프렛)을 고정한 축소 문제 ②**코드 사전(규칙 1)을 1급 경로로** — 기존 연구는 음 단위 최적화만 하고 관용 폼 사전이 없음 ③ACE×탭 교차검증 분할 ④운지 불가능성→전사 오류 피드백.
- GPS hold-position P·`arrangeFinger`(last-usage), Xu availability 마스킹 — 각각 규칙 2·5·4의 선행 수식화로, 본 설계는 이들을 한 프레임워크(후보 생성+빔 서치)에 통합.
