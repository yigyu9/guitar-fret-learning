# 새 기타 연주 학습 확인 사항

2026-10-15 요청에 따라, 답변이 필요한 연구 선택을 이 문서 한 곳에 모은다. 구현 중 해결할 수 있는 코드·좌표·데이터 문제는 직접 확인하며 사용자에게 넘기지 않는다. 답변 전에도 현재 합의된 조건의 구현과 검증은 계속한다.

## 그대로 적용하는 결정

- 기존 Fret·Strike·잔차 정책의 가중치는 새 학습에 사용하지 않는다. 과거 파일은 재현용으로 보존한다.
- 오디오에서 생성한 연주 계획과 현재 물리 상태를 입력받아 humanoid 관절 목표를 출력한다. 기타는 고정하지 않는다.
- 현재 실험은 root·하체 고정, 내부 충돌 ON, 스트랩 OFF다. 이 조건의 결과를 동적 하체 제어 성과로 설명하지 않는다.
- 사람 동작의 유사성보다 음악 시간 조건, 목표 줄·프렛, 악기 지지를 분리해 평가한다.
- 실제 줄 진동·음향 합성이 없는 조건에서 기하/접촉 기반 연주 판정을 실제 음향 재현으로 표현하지 않는다.

## 답변할 항목

현재 구현을 멈춰야 할 미확정 입력은 없다. 아래 두 항목은 이후 실험 우선순위와 최종 평가 기준에 관한 선택이며, 답변 전에는 명시한 기본값으로 진행한다.

### Q1 최종 연주 평가의 시간 허용오차

기존 Strike 계약은 50ms를 기준으로 삼고, 이번 첫 음악 학습의 타현 후보 검사는 100ms의 넓은 창을 사용한다. **최종 결과는 50ms 기준을 주 지표로 두고 100ms 결과를 초기 학습 진단으로만 병기하는 방향**을 제안한다. 기존 기준과의 비교를 유지하면서 초기 학습의 진행도도 볼 수 있다.

답변: 기존50ms 기준 유지 / 다른 기준과 이유. 답변 전에는100ms 후보 판정만으로 최종 음악 성공을 주장하지 않는다.

### Q2 우선 완성할 시연 구간

현재는 입력 파일이 갖춰진 `00_SS1-68-E_comp`의 첫 단음→두 이벤트→첫8개 이벤트를 연결한다. **이 구간을 우선 완성한 뒤 다른 곡으로 확대하는 방향**으로 진행한다. 먼저 보고 싶은 다른 곡·구간이 있으면 지정해 주면 된다.

답변: 현재 구간 우선 / 다른 곡과 구간. 현재 구현은 곡 bundle을 바꿔 실행할 수 있도록 하되, 서로 다른 곡의 기존 정책을 가져오지는 않는다.

## 구현 결과

음악 이벤트 입력 → 현재 기타 좌표계의 목표 → 공동 정책의 54개 관절 목표 → native 물리 실행 → 실제 모션·연주 후보 평가를 연결했다. 과거 정책과 Stage A 가중치를 가져오지 않고 새 정책을 초기화해 16회 갱신·4,096개 전이를 학습했다. 이번 실행의 오류와 제외 전이는 0개다. 단음·두 이벤트·8개 이벤트의 입력 시간축도 실제 환경에서 검증했다.

**연주 성공은 아직 아니다.** 첫 단음의 발음 구간에서 손가락 marker와 목표 프렛의 평균 거리는 초기 154.19mm → 학습 후 154.10mm로 사실상 그대로다. 접촉·기하 조건을 함께 만족한 유지 시간은 0초다. 입력·출력과 학습 경로가 작동함을 확인한 첫 파일럿이며, 8개 이벤트 정책을 학습하거나 곡 연주를 완성한 결과는 아니다.

현재 초기 손 위치에서 첫 목표까지 약 15cm를 접근하는 문제가 남았다. 다음 구현 판단은 사용자가 자세를 하나씩 골라주는 방식으로 넘기지 않고, 현재 행동 범위에서의 도달 가능성 확인과 접근→접촉→유지의 학습 단계를 근거로 결정해야 한다. 짧은 파일럿의 정책 변화량도 크게 나타났으므로 학습 안정성 진단이 필요하다. 이 기술적 후속 사항은 위 두 연구 선택과 별개다.

실제 관절·기타 궤적과 전신·양손 영상은 [구현 및 실행 결과](/home/ajou/yigyu/3/docs/2026-10-12/stability_adapter_2/results/fresh_music_v1/README.md)에 모았다. 현재 root·하체 고정이라는 한계, 데이터 한 곡의 계획 파일 누락, 과거 실패와 재현성 사고도 해당 문서에 명시했다.
