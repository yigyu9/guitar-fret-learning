# 독립 최종 검수

판정: **문제없음 — 명시한 작은 행동 범위의 native 수집·PPO 연결 검증으로 한정해 완료 가능.**

검수자는 구현 파일을 수정하거나 물리 실행·전체 테스트를 반복하지 않았다. `native_v1` 원자료, 저장된 rollout/전후 체크포인트, 실제 실행 로그, `native_audit.json`, 결과 README와 `guitar_learning/TRAINING.md`를 읽고 CPU에서 원자료를 재계산했다.

## 확인한 근거

- 원자료 96개 전이의 네 물리 표본, 총 384개를 모두 확인했다. 첫 에피소드의 학습 물리 step은 481–832, 재시작 후 481–512로 연속적이다. 두 reset 모두 준비 완료 step480에서 음악 시간0으로 시작한다. 두 번의 준비를 포함한 실제 물리 시간은 5.6초다.
- rollout의 terminal은 0-based index87 한 곳이고 truncation은 없다. 해당 전이의 reward/cost bootstrap은 모두0이다. index88은 두 번째 에피소드의 첫 관측으로 이어진다. 마지막 index95는 비종료 경계이며 bootstrap은 각각 0.04638150334358215, 0.024875693023204803이다. 초기 체크포인트와 마지막 실제 관측으로 실행과 동일한 CPU 1-thread 설정에서 다시 계산한 두 값이 저장 tensor와 정확히 일치했다.
- 첫 88개 전이의 보상 합 −0.48391121647387214, 비용 합 2.7220652327819455e−6은 에피소드 및 실행 보고와 일치한다. 실제 목표는 현2/프렛7/약지, onset1.12초/end1.3522초이며 strict/lenient 매칭0, strict 미스1, 목표 유지0초다. 시간표 완료를 음악 성공으로 표현하지 않는다.
- 체크포인트 identity는 동일하고 updates는0→1이다. 배우, 가치 인코더, reward/cost head가 실제 변경됐다. 전체 state-dict 변화 L2 재계산은 약0.378099237이며 실행 보고 약0.378099231과 부동소수점 합산 정밀도 범위에서 일치한다. medium/state468의 파라미터 수1,931,600도 독립 계산했다.
- 원자료의 failure reasons와 최종 forbidden calls는 비어 있다. `report.json`은 completed=true, failure=null, import 핀 누락/원본 parity 오류/변경 입력 모두 빈 목록이다. 검수 시점에 입력1,564개의 현재 SHA를 직접 재계산해 모두 동일함을 확인했다.
- CPU84개 PASS 로그를 확인했다. 실제 실행 로그는 PhysX CPU, GPU pipeline disabled이며 정책도 CPU다. 기존 visual geom 경고를 시각 형상 검증 성공으로 해석하지 않는다는 문서 범위가 적절하다.

## 사전 발견 및 수정 확인

1. 음악 token이 목표 종료 직후 사라져 해제 보상 창을 관측하지 못하던 문제: 종료+0.1초까지 유지하도록 수정했고 경계 회귀검사를 추가했다.
2. 새 `fresh_music_v1` CPU wrapper를 과거 물리 실행의 원본 SHA map에 잘못 대조하던 문제: 학습 실행기의 initial/final 분류를 함께 수정하고 새 의존성의 전후 입력 핀은 유지했다.
3. 문서의 “실제 접촉 소실” 표현은 코드보다 강하므로 “지정 목표의 압현 접촉 후보 소실”로 한정했다. 다른 현/프렛으로 이동한 접촉과 왼손 전체 비접촉을 구분한다.

현재 남은 Critical/Warning finding은 없다. 검증 범위는 행동 반범위0.002rad의 짧은 연결 시험과 PPO 업데이트1회다. 기본0.25–0.5rad 탐색 안정성, 연주 학습 수렴, 전체 곡의 미지원 복합 재타현, 완전 비접촉/현 압력/음향, 하체 정책 학습 또는 기존V3 전체 검증을 승인하는 결과는 아니다.
