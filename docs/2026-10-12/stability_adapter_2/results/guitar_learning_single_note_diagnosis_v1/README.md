기준은 2026-10-19 **01:18:06 KST**의 실행 중 고정 prefix다. 손별21업데이트·40,320전이·96회 완료이며 최종2시간 결과가 아니다. 원 실행·설정·모델과 후속 진급 watcher는 수정하지 않았다. 각16환경과 반복 episode는 같은 시작·목표를 공유하므로 독립된96개 실험으로 해석하지 않는다.

## 2. 원인 판단: 관측과 가설을 구분

### 관측된 것

- **학습은 실제로 진행된다.** 21개 update의 KL은 양수이고 retry는0이다. 오른손 오차 변화와20업데이트 전후 모델 변화도 있다.
- **변화는 기존 행동 근처에서 작다.** 상속한 실제 Actor LR은 선언값의 LH1/64·RH1/16이며 고정됐다. std는 약0.02이고 별도 entropy 증가 항은 없다. 현재 long 중 계속 LR이 줄었다는 뜻은 아니다.
- 같은 저장 관측에 initial과20업데이트 모델을 넣은 제한적 CPU probe에서 평균 정규화 행동 변화는 LH0.000585·RH0.001307이다. LH4개/RH9개 관측만 사용했으며 실제 새 궤적 평가가 아니다.
- LH 접촉 직후 probe의5축이 tanh |a|≥0.98이었고 initial도 같았다. 포화 부근에서는 같은 latent std라도 실제 행동 잡음이 작다. 하지만 이 표본에는 음 종료 후 관측이 없으므로 해제 구간의 포화를 확정하지 않는다.
- **해제 정보와 벌점이 빠진 것은 아니다.** 종료 시간·접촉/해제 이력이 관측에 있고, 남은 접촉에는 지연 벌점이 적용된다. LH post-note hold 보상 상쇄도 작동한다. 다만 명시적인 손가락 표면 이탈 방향·검증된 해제 목표 경로는 없다.
- **행동 범위에 제약이 있다.** 현재 reference와 ±offset/native limit 아래에서 일부 손가락은 완전히 펴는0rad까지 가지 못한다. 팔/손목 이동 권한은 남아 있어 해제가 불가능하다는 결론은 아니다. 과거 초기 자세의 손 해제 성공을 현재39행동 범위의 성공으로 상속하지 않는다.
- **H120은 reset 오류가 아니다.** 상태가 다음 업데이트로 이어지고 올바른 bootstrap을 사용한다. 다만 짧은 GAE 직접 전파와 value 의존성은 별도 후보다.

### 현재 가장 설득력 있는 가설

기존 정책은 누르기/타현 동작을 이미 갖고 있지만, 좁은 탐색으로부터 **새로운 해제·타현 후 동작을 충분히 발견하지 못한다**는 설명이 현재 자료와 맞는다. 오른손은 first-hit/precision/guide 수익이 개선되면서 extra/wrong은 남을 수 있다. 왼손은 해제 보너스가 한 번도 발생하지 않아 성공 행동의 양성 경험이 없다. 양의 총보상 자체가 실패 정책이 최적임을 증명하는 것은 아니다.

낮은 LR, 포화/상태 독립 잡음, 목표 방향 부족, 보상 정렬·시간 신호가 원인 후보이며 각각의 인과 효과는 아직 검증하지 않았다. **안정성 보상이 주원인이라는 증거도 없다.** 비용을 제거하거나 기타 지지를 완화하는 것부터 시작하지 않는다.

## 3. 개선 순서

### 1순위 — 현재 행동 범위 안에서 두 실패 동작이 실제로 가능한지 확인

현재 학습 종료 후 이미 연결한 결정적 평가의 전체 기록을 먼저 사용한다. 고정 prefix에서는 raw가 첫 tick/분류 변경 중심이라 LH 해제 구간의 실제 목표·관절 상태가 부족하다. 예정 평가에는 전체 관측·행동·4개 물리 substep이 있어 이 구간을 자세히 확인할 수 있다.

그 다음 별도 새 버전의 짧은 native 확인에서:

- **LH:** 현재 정책으로 음을 누른 뒤, 기존 범위 안에서 작은 손가락/손목/팔 이동으로 목표현의 모든 적격 손가락 접촉을50ms 이상 없앨 수 있는지 확인한다. 지정 손가락 candidate만False인 것을 해제로 간주하지 않는다. 관절별 행동→요청목표→최종목표→실제각과 native limit, 기타/발 안정성을 함께 기록한다.
- **RH:** 첫 정상 통과 후240Hz 피크 궤적을 보고 extra와반대방향/잘못된 통과의 위치를 구분한다. 출구 쪽에서 유지하거나 허용 깊이 밖으로 빠져 재통과 없이 회복하는 경로가 기존6축 안에서 가능한지 확인한다. 아직 검증된 해법은 아니다.
- 같은 조건의 현재 정책과 zero-action 기준선도 함께 측정한다. 코드상의 조건부 보상 계산을 무행동의 실제 결과로 대신하지 않는다.

**판단:** 경로가 가능하면 학습 경험/목표 설계로 넘어간다. 불가능하면 포화한 관절의 reference·허용 범위 또는 목표 정의를 최소 수정하는 새 계약을 먼저 검증한다. 기타 강제 부착·직접 보조 힘·매 step 상태 덮어쓰기로 통과시키지 않는다.

### 2순위 — 실패 구간을 직접 가르친 뒤 단음 전체로 다시 연결

- LH는 `접근→압현 유지→해제` 중 **해제 구간**을 분리한다. 성공한 안전 경로가 확보되면 그 짧은 구간을 교사 예제/초기화에 포함하고, 이미 되는 압현을 보존하며 전체7초로 연결한다.
- RH는 `준비→정상 통과→재통과 없는 회복/유지`를 분리한다. 회복 보너스만 크게 하기보다 오류 없는 통과 후 동작과 최종 품질 달성을 보상에 연결하는 비교를 우선한다.
- 명시적인 phase·clearance 목표 또는 단계별 residual/head는 필요할 경우의 구현 후보다. 시간/이력은 이미 입력되므로 입력 flag만 추가하면 해결된다고 가정하지 않는다. 시작은 현재 medium 망을 재사용하는 최소 변경이 적절하다.
- 교사/스크립트 경로를 사용하면 그 역할을 기록하고, 순수 PPO가 스스로 발견한 성공으로 설명하지 않는다. 판정과 안전 문턱은 유지한다.

### 3순위 — optimizer·탐색·시간 설정은 통제 비교

안전한 성공 경로를 확보한 뒤 같은 checkpoint에서 제한된 새 실험을 비교한다.

|실험|한 번에 검증할 변경|핵심 판정|
|---|---|---|
|A 기준선|현 방식 유지|release/extra/quality와 기존 능력 보존|
|B 국소 동작 학습|해제 또는 타현 후 안전 경로 예제/구간 학습|새 성공 행동의 발생·반복, 전체7초 품질|
|C optimizer 또는 탐색|LR 후보 하나 또는 시간적으로 일관된 작은 행동 탐색 중 하나|수락/시도 KL·retry·실제 목표/관절 변화·안전/품질|
|D 시간 전달|H120 대 H420 또는 gamma/λ 중 하나|동일 전이 수의 품질·critic/advantage·update 수|

B가 가장 직접적인 개선안이다. C/D는 진단에 따라 하나씩 진행한다. 처음부터 모든 조합을 대규모로 돌리거나 LR/std/보상을 동시에 바꾸지 않는다. 64회 정도의 완료 episode를 초기 비교 단위로 사용하고(독립성/통계 검정 주장은 하지 않음), 신규 해제/오류 없는회복 사례가 생기는지와 기존 압현/첫 타현의 손실을 본다. 유효 신호 없이0성공이 반복되면 같은 조건의 시간만 추가하지 않고 직전 가설을 재검토한다.

현재 strict resume JSON의 LR·gamma·보상만 바꿔 이어 붙이지 않는다. 새 실험은 출발 모델 SHA·허용 변경·정책/critic/Adam/RNG의 이전 범위를 명시한다. LR만 비교하려면 가능한 한 같은 optimizer 상태도 맞춘 **명시적 실험 fork**가 필요하다. Actor-only fresh 초기화를 택하면 critic/Adam 재시작까지 함께 달라지는 한계를 기록한다. H420은 reset을 고치는 것이 아니라 데이터 구성 비교이며, 그 자체로 lambda의 짧은 직접 전파가 해결되는 것은 아니다.

## 4. 현재 실행과 확장 계획에 적용할 결정

1. 원2시간 단음 실행은 설정을 유지하고 기준선으로 완료한다. 마지막까지 품질이 개선될 가능성을 배제하지 않는다.
2. 현 진급 watcher의 최근64회90%·안전0·결정적4/4 조건을 유지한다. 통과한 손만 기존 [0,2] pool로 넘어간다.
3. 종료까지 미달이면 목표 수/성공 범위/허용오류를 늘려 통과시키지 않는다. **다음 작업은 새 음이 아니라 위1순위 native 해제/타현 후 경로 확인과 국소 동작 학습**으로 정한다.
4. 큰 네트워크, 전곡/화음, 양손 결합, 안정성 보상 일괄 축소는 후순위다. 현재 증거는 용량 부족을 보여주지 않는다.

이번 요청에서는 분석과 방향을 정했다. 보상·네트워크·환경 소스·현재 학습 설정·watcher는 변경하지 않았으며, 표의 새 실험도 아직 실행하지 않았다. 자동 후속 실행이 해 주는 것은 기존 단음의 평가/진급 및 통과 시 두 단음 학습까지다. 진급 실패 후 B/C/D 개선 실험을 자동 시작하도록 연결한 상태는 아니다.
