# StabilityAdapter 2: 기타 고정 해제 후 초기 위치·회전 유지 계획

작성일: 2026-10-06 (Asia/Seoul). 메인 계획·구현·설정은 `stability_adapter_2/`에 둔다.
결과·분석·로그·영상과 산출물 정리는 `docs/2026-10-12/stability_adapter_2/`에 둔다.
상태: **소스 비교·CPU 자산 로드 감사 완료 / P1a CPU 환경·초기화·native 계약 검사 완료 /
초기 장면 렌더·접촉 품질·자세 유지 성능 미검증**.

## 1. 범위와 현재 증거

**가장 중요한 작업은 humanoid 초기 자세와 strap 초기 설정을 함께 조정하여 시작 직후
기타의 이동·회전을 줄이고, 이후 제어로 초기 기타 위치·회전에서 벗어난 오차를 보정·유지하는 것이다.**
안정화하기 쉬운 다른 기타 배치를 먼저 선정하는 것이 현재 목적이 아니다.
기준 기타 pose는 공용 시작 pose로 유지하고 양손 배치·제어 및 스트랩 조건을 비교한다.
WAIT → REACH → GRIP → TRANSPORT를 선행 상태기로 만들지 않는다.
정착 관찰 시간은 측정 구간이며 연주를 잠그는 WAIT gate가 아니다.
기타 고정·손 부착·목표로 끄는 별도 힘·지속적인 pose/관절 상태 덮어쓰기를 쓰지 않는다.

작업은 다음 두 축으로 진행한다.

1. **초기 상태 선정:** 같은 기타 p/q에서 humanoid 초기 관절각·양손/전완 지지 배치와
   스트랩 초기 rest length/장력을 조합해 첫 자유 step부터의 이동·회전을 줄인다.
   root는 고정하고, 우선 Torso/Spine/Chest 기준 목표를 유지하며 Thorax 이하 양쪽 66관절을 조절한다.
   스트랩은 원본 버튼·guide·물리 수식을 유지하고 초기 길이/그에 따른 preload부터 비교한다.
2. **오차 보정·유지:** 선정한 같은 초기 조건에서 feedback OFF/ON을 비교하여,
   기타가 초기 p/q에서 벗어나면 허용된 관절 목표를 보정하고 다시 유지하도록 한다.
   떨어져 정착한 pose를 새 목표로 삼지 않는다. 실행 중 스트랩 구동은 별도 확인할 후보다.

두 축은 설계·검증 순서이며 연주 전에 필수 WAIT를 두는 실행 단계가 아니다.
현재 CPU v3는 공용 humanoid H0·S0 초기 조건의 진단 기준선일 뿐이다.
초기 상태 조합 선정과 기타 오차 feedback은 아직 구현·검증하지 않았으며 다음 작업의 중심이다.

이전 P0에서는 계획·README만 수정했다. 이번 P1a에서는 별도 CPU 기본 환경·제어 목표·
스트랩·실행 감사·테스트와 설정을 추가하고, 계획·README와 결과 정리를 갱신한다.
정책·학습·장면 렌더 코드는 아직 없다. 기존 결과 그래프 생성 코드는 추가했다.
초기 길이 선택과 고정 해제 후 동적 길이 조절을 구별한다. 동적 조절은 후보로 설계하되
사용 여부·구동 제한은 구현 전에 확인한다. 지금 정책의 실시간 길이 action을 확정하지 않는다.
`stability_adapter/`, 기존 계획·결과, 공용 자산과 fret/strike 코드는 수정하지 않는다.
기존 작업 트리의 수정·삭제도 복구하거나 정리하지 않는다.
사용자가 제공한 AGENTS 지침, 루트 README, `PROJECT_CONTEXT.md`,
`stability_adapter_2/README.md`, 공용 env/assets README를 읽었다.
루트·상위 경로에서 별도 AGENTS.md를 찾지 못했으며 프로젝트의 `.Codex/skills`도 발견되지 않았다.
루트 README·PROJECT_CONTEXT의 기존 StabilityAdapter 상태 설명보다 이번 요청과 새 README를 우선한다.

증거 파일:

- [자산 로드 감사](../docs/2026-10-12/stability_adapter_2/analysis/asset_import_audit.json): Isaac Gym CPU PhysX 로더 readback. simulate/상태 쓰기 없음.
- [소스 비교 snapshot](../docs/2026-10-12/stability_adapter_2/analysis/source_comparison.json): 이전 비교 시점의 원본 스트랩·좌표·출처 SHA-256 snapshot.
  새 README의 hash는 이번 문서 수정으로 달라지며 해당 snapshot을 소급 수정하지 않는다.
- [자산 로드 원문 로그](../docs/2026-10-12/stability_adapter_2/logs/asset_import_audit.log): 자산 로드 원문 로그.

감사는 `rl38`의 Python으로 human fixed-root, guitar free-root를 로드했다.
기타는 기본 옵션과 `override_com=True, override_inertia=True` 두 경우를 비교했다.
GPU 장치를 찾지 못했다는 메시지와 visual geom 로드 오류가 로그에 있다.
배치 렌더·GPU 자유 기타 동역학·접촉 품질은 **미검증**이다. 양의 질량·관성이 안정성을 증명하지 않는다.
양손의 실제 world 위치·접촉 간격도 아직 native FK/렌더로 측정하지 않았다.

### 2.1 질량·관성·충돌·관절 한계 감사

- human: 66 bodies, 55 collision shapes, 105 hinge slots, 질량 합 **73.316412kg**.
- guitar: 39 bodies, 28 collision shapes, 내부 DOF 0, 질량 합 **4.648716kg**, 무게 **45.6039N**.
- `G:body`: box half-size `(0.15, 0.17, 0.02)m`, 질량 **4.080000kg**.
  로컬 관성 대각 `(0.0398480, 0.0311440, 0.0699040) kg·m²`.
- 기타 root: 질량 **0.421014kg**, 관성 대각
  `(0.00903235, 0.000100977, 0.00910998) kg·m²` (body frame 대각; 주관성 값과 구별).
- `G:pluck_range`: half-size `(0.028, 0.086, 0.0075)m`, 질량 **0.144480kg**.
  충돌을 끄는 것과 질량을 제거하는 것은 다른 변경이다. 초기 비교에서는 질량을 보존한다.
- 두 로드 옵션에서 전체 질량과 관성은 같았다. 현 marker 12개의 COM만 다르다
  (기본 로드에서는 marker 위치 값, 재계산에서는 local zero). 전체 readback을 JSON에 기록했다.
  marker 질량 약 `1e-7kg`, 관성 대각 약 `1e-9 kg·m²`로 양수였다.
  따라서 XML의 질량 0 주석만 보고 임의 repair하지 않는다. GPU 재감사 후 판단한다.
- 사람 initial pose가 XML hard range를 조금 넘는 관절은 `LH:thumb1_x/y/z` 3개다.
  최대 **0.000228807rad ≈ 0.01311°**. reset 시 보정량을 남기고 clamp하는 안을 권장한다.
- authored zero-width 8개는 양쪽 Knee/Toe y/z. 105 named slots 중 실질 가동 97개와 구분한다.
- 현재 사람·기타 로더 shape friction은 모두 **1.0**. `condim=1` 주석만으로 무마찰이라 하지 않는다.
  이 값은 태스크 필터·contact offset 적용 전 로더 값이며 실제 유효 마찰은 동역학에서 재확인한다.
- 기본 human=1, guitar=2; 두 filter 비트 AND가 0이면 서로 충돌한다.
  자기충돌 OFF, 접촉 offset `1e-4m`은 공용 비교 조건이다. 몸통·팔·양손의 기타 충돌을 감사한다.

기존 stability의 상체 hold gain 6배는 복사하지 않는다. 공용 기본 hybrid PD
(명시적 stiffness torque + solver 내부 damping)를 비교 기준으로 하고 q 오차·속도·토크 포화를 기록한다.
첫 CPU native 진단에서는 같은 kp/kd/effort cap으로 **native POS solver PD**를 사용한다.
native POS 모드가 별도 effort 입력을 무시하는 것을 실제 응답 비교로 확인했기 때문이다.
이는 공용 tensor hybrid PD와 다른 수치적 제어 조건이다. CPU/GPU 결과를 동일 조건으로
합치지 않고, 최종 actuator·학습 구조는 뒤에 결정한다. 현재 실제 토크·포화는 측정하지 않았다.
좌식 하체는 limit pinch/armature 후보만 먼저 검토한다. 매 스텝 관절 상태 재주입은 새 코드에 넣지 않는다.
하체 이탈 때문에 문제가 생기면 기록하고 별도 변경을 합의한다.

## 3. 기타와 양손 초기 자세 후보

### 3.1 좌표와 기타 배치

단위 m/rad, world up `+Z`. Guitar local `+Y`는 넥/너트 방향, `+Z`는 지판·현 앞쪽.
JSON source quat는 **wxyz**, Isaac tensor는 **xyzw**이다.
현재 실제 computed pose는 다음과 같다 (단순 회전 변환으로 교차 확인).

- guitar root world pos `(-0.19678993, 0.11876893, 0.82380560)`.
- quat wxyz `(0.44954730, -0.34126009, 0.58164588, 0.58577884)`.
- body box center world `(0.170000, 0.065000, 0.672000)`.
- 너트 world `(-0.395370, 0.147431, 0.905930)`.
- fret5 center world `(-0.251528, 0.133828, 0.847449)`.
- pluck-zone center world `(0.106945, 0.098489, 0.701505)`.
- neck elevation **22°**, source parameter: audience 방향 회전 5°, soundboard tilt 8°.

XML 헤더의 root `(0,0,0.89)`·넥 26.5°는 역사적 O4 값이며 현재 배치가 아니다.

이 pose를 `p_target`, `q_target`으로 봉인한다. 이후 기타가 떨어지거나 정착해도
목표를 새 pose로 갱신하지 않는다. 이전 제안의 neck 28°/몸쪽·아래 10mm 이동 후보는
현재 계획의 탐색 대상에서 제외한다. 기준 기타 pose 변경은 별도 사용자 결정이다.

### 3.2 고정 해제의 정확한 의미와 목표 상태

시각 기준은 초기 고정 기타와 같은 배치다. 실제 시험은 `fix_base_link=False`, 중력 ON인
자유 기타 actor를 **처음부터** 만든다. fixed actor를 런타임 flag로 해제할 수 있다고 가정하지 않는다.
초기 상태를 한 번 설정한 뒤 첫 자유 physics step을 고정 해제 시점 `t=0`으로 정의한다.
physics를 진행하며 기타를 붙잡아 두는 준비 구간은 넣지 않는다.
별도의 고정 기준 이미지를 사용할 경우 시각 자료일 뿐 자유 동역학 성공 증거로 쓰지 않는다.

- 첫 step **직전** source/reset root pose를 목표로 저장한다. root 선속도·각속도는 0으로 초기화한다.
- env origin을 반영한 동일 world frame에서 목표와 상태를 비교한다. quat는 정규화한다.
- 양손 native FK와 스트랩 명목 경로 길이는 초기 상태에서 구한다.
  refresh 때문에 한 physics step이 필요하면 그 step도 과도 응답에 포함하며 목표를 재설정하지 않는다.
- 손 초기 위치는 고정 해제 전 지지가 가능한 후보로 한 번 배치할 수 있다.
  실제 지지력은 그 뒤 관절 PD와 접촉에서 발생해야 한다.
- 양손 initial q, joint target, 스트랩 길이, 활성 제어 그룹, 시작 시각을 run manifest에 저장한다.

### 3.3 Humanoid 초기 자세·손 지지 후보와 출처

우선 **H0: 공용 좌식 양손 그대로**를 기준선으로, **H1: 넥을 지지하는 왼손 + 기타 body
쪽을 지지하는 오른손/전완**을 후보로 시각화한다. 기타 목표 pose는 두 경우 동일하다.
공용 시작 자세나 피크 자세가 이미 지지를 달성했다고 가정하지 않는다.
공용 humanoid 관절각은 비교 기준이지 최종 reset 자세의 고정 조건이 아니다.
기타 초기 p/q와 root 조건을 유지하면서 허용된 관절의 초기 q를 후보별로 한 번 설정한다.
초기 자세가 바뀌면 손 접촉·몸 주변 strap 경로·초기 장력도 함께 재계산해 조합을 비교한다.
오른손 pick prior는 연주 호환 비교 후보로 남기되, 이번 목표를 위해 오른손·팔 접촉 제어도 검토한다.

현재 `joints_isaac` 팔 각도 (degrees, 축 슬롯 순서 x/y/z; 통상 Euler 각과 다름):

| 그룹 | 왼쪽 | 오른쪽 |
|---|---|---|
| Thorax | `(1.92, 0.62, -14.14)` | `(-1.81, 18.86, 3.58)` |
| Shoulder | `(19.40, -43.40, 62.90)` | `(-1.87, 26.37, -31.79)` |

### 4.1 고정 해제 후 동적 길이 조절 후보

이번 요청의 길이 조절을 초기 값 탐색에만 제한하지 않는다. 다만 동적 조절은 **능동적으로
스트랩을 감거나 푸는 구동 장치**를 가정한 별도 후보이며, 수동 스트랩의 효과로 보고하지 않는다.
공용 모델에 실제 구동 장치가 있다고 가정하지 않고, 최초 시험은 등가 rest-length 조절 모델이다.
사용자가 정적 길이 조정만 원하면 아래 동적 시험을 제외한다.

- action은 길이 변화율 `u_L [m/s]` 후보로 두고,
  `L_rest_next = clamp(L_rest + u_L·dt, L_min, L_max)`로 갱신한다.
  길이 범위·속도·가속도/변화율 제한을 명시하며 즉각적인 길이 점프를 허용하지 않는다.
- 초기 진단 후보는 명목 `L_start` 주위 ±5mm, 속도 상한 **1mm/s** 정도다.
  이는 승인 전 탐색값이며 실제 장력·안정성 결과에 따라 조정한다. `L_start`는 이미 선택한 초기 길이다.
- 우선 원본의 `k(L-L_rest)+c·Ldot` 장력 law를 명시적으로 유지한다.
  `L_rest_dot`을 damping에 넣는 별도 motor/damper 모델로 조용히 바꾸지 않는다.
  기존 damping 의미와 등가 길이 구동을 구분하고 실제 구동기 모델은 필요 시 별도 설계한다.
- 양 버튼 힘·body guide 반작용·COM 모멘트는 원본 경로에서 계산한다.
  길이 action으로 기타 root pose를 직접 이동시키지 않는다.
- 장력 cap, 연신, 길이 범위 도달, 토크 포화, 접촉 과힘을 기록한다.
  기준을 넘거나 cap에 지속 의존하면 길이 조절 제한/중단과 실패 상태를 기록한다.
- 길이 단축은 외부 actuator가 일을 하는 동작이다. 등가 구동의 기계 출력 proxy
  `P_reel = -T·L_rest_dot`와 누적 양/음의 일을 기록한다. 장치 효율·전기 소비·실제 motor 성능을 뜻하지 않는다.
- 길이 하나는 연결점 힘과 모멘트를 함께 바꾼다. 그것만으로 임의의 6D 기타 pose를
  독립 제어할 수 있다고 가정하지 않는다. 위치 오차를 줄이면서 회전을 악화시키는지 반드시 비교한다.

구동 제한과 damping 모델은 동적 후보 구현 전 확인한다. 이 단계에서도 학습 정책이
길이를 출력할지, 결정론적 제어기가 맡을지는 아직 확정하지 않는다.

## 5. 현재 유지 제어와 이후 연주 제어권

현재 단계에서는 음악 사건을 실행하지 않고 **기타 초기 6D pose 유지**를 시험한다.
손 위치를 초기 상태에 PD로 유지하는 기준선과, 기타 오차를 보고 손·팔 목표를 바꾸는
능동 피드백 제어를 구별한다. 제어기가 기타 pose를 쓰는 것이 아니라 **관절 목표각**을 쓴다.

### 5.1 최소 제어 설계

1. 기타 position/orientation 오차와 선속도·각속도, 양손 접촉·관절 상태를 관측한다.
2. 먼저 작은 관절 목표 변화로 지지 접촉과 기타의 위치·회전 응답을 측정한다.
   왼손 넥 지지, 오른손/전완 body 지지가 만드는 힘·모멘트 방향을 확인한다.
3. 고정 길이에서 왼손만, 오른손만, 양손 제어를 비교한다. 비교하지 않는 쪽의
   손은 동일 초기 PD target을 유지하므로 그 손의 **수동 접촉 지지는 남아 있을 수 있다**.
4. 접촉 응답이 확인된 그룹에만 제한된 목표각 보정을 적용하는 작은 결정론적
   제어기부터 시험한다. 접촉 상황에서 부호·효과를 확인하지 않은 6D 오차→joint 매핑을 쓰지 않는다.
5. 필요 시 동적 길이 단독/양손·길이 공동 제어를 같은 시작 길이에서 비교한다.
   손과 스트랩이 서로 반대 보정을 키우면 보정 크기·속도·제어 주기를 조정하고 실패 원인을 기록한다.

기본 제어 주기 60Hz·물리 240Hz는 비교 출발값이며 PhysX import/접촉 이후 검증한다.
학습 보상·네트워크를 먼저 정하지 않는다. 초기 손 배치와 gain 변화가 오차를 줄인 경우도
피드백 제어의 효과와 분리한다. gain만 키워 유지하거나 과힘을 만드는 해법은 채택하지 않는다.

비교 정의:

  원본 초기 slack +5mm는 C1의 S+5 대조 조건으로 분리한다. 자동 길이 단축·기타 위치 교정 없음.
- C1: feedback 없이 **humanoid 초기 자세와 스트랩 초기 길이**를 비교한다.
  H0+기준 길이, H1+기준 길이 자세 변경, H0+선택 길이 길이 변경, H1+선택 길이 조합 변경을 구별한다.
  기준 길이는 C0/H0의 명목 L_A(S0)이며 선택 길이도 이 기준에서 정한 절대 값이다.
  두 절대 rest length는 H0/H1에 동일하게 적용하며 H1의 경로 길이에 맞춰 자동 재설정하지 않는다.
  길이는 S-5부터 검토하고 필요할 때 S+5/S-10을 추가한다. 각 trial에서는 초기 길이를 고정한다.
  기타 p/q·초기 속도·gain은 같게 두고 초기 상태 개선 효과를 평가한다.

  H1 비교에서는 H1의 피드백 OFF trial도 함께 저장한다.
- C5: 같은 초기 조건에서 관절은 initial PD hold, 스트랩 길이 피드백만 활성.
- C6: C4와 같은 관절 제어에 길이 피드백만 추가. 최선 초기 조건을 서로 다르게 골라 효과를 과장하지 않는다.
- 모든 후보를 한 번에 구현하지 않는다. 기준선에서 확인한 원인에 필요한 다음 제어만 추가한다.

### 6.1 초기 pose 오차와 성공 기준

목표는 첫 step 이전의 `(p_target,q_target)`이며 전체 trial 동안 불변이다.
실제 pose `(p(t),q(t))`에 대해 아래 지표를 저장한다.

- 위치 오차 `e_p(t)=p(t)-p_target`, 축별 오차·norm [m], 전체 구간 max/RMS/평균.
- 회전 오차 `theta(t)=2 acos(clamp(|dot(q(t),q_target)|,0,1))` [rad/deg].
  quaternion을 정규화하고 필요 시 회전 벡터도 기록한다. Euler wrap 차이를 오차로 사용하지 않는다.
- 목표 기준에서 벗어난 시간·연속 이탈 길이, 끝 위치/회전 오차, 후반 drift 추세.
- 선속도·각속도, 기타 COM·neck/bridge 위치, 지상 최저 높이.
- 손 q/qd/target/torque·포화, 접촉 위치/힘·관통, strap L/L_rest/Ldot/T/버튼·guide force/torque.
- 동적 시험은 길이 변화율·제한 도달 횟수, 등가 구동 일과 초기/최종 L_rest도 저장한다.

기타 root 위치 오차와 COM 이동은 구별한다. net contact force만으로 접촉 상대 body를
특정하지 않고 가능한 접촉 쌍 정보·표면 간격과 함께 판정한다.

기본 trial 10초: 해제 직후부터 첫 2초와 이후 8초를 나누어 보고하되 **전체 10초 오차**도
반드시 제공한다. 처음 크게 떨어진 뒤 정지한 결과가 후반 속도만 낮다고 통과하지 않는다.
2초에 정착했다는 가정을 두지 않는다. t=0, 첫 step, t=2/5/10의 동일 카메라 이미지를 제공한다.

성공 목표는 위치와 회전 오차를 **함께** 줄이는 것이다. 단위가 다른 두 값을 임의 가중합한
점수 하나로 숨기지 않는다. 최종 gate 전에는 baseline 대비 개선량과 오차 tradeoff를 보고한다.
수치 허용치(m/deg, 속도, 접촉·토크·장력)는 최초 장면·측정 분포를 보고 합의한다.
허용치 합의 후 위치와 회전 gate를 모두 만족하고, 낙하·관통·지속 진동·과힘 없이 유지해야 한다.
시작 자세를 유지한 것과 연주 가능한 손 자유도를 확보한 것은 별도 결과다.

### 6.2 작은 움직임과 연주 호환 시험

우선 0.5Hz, 3주기. finger flex **3° → 5°**, wrist **±2°**, elbow/shoulder **±2°**,
몸통 **±1°**는 첫 후보이며 hard limit과 지지 상태를 확인해 진폭을 정한다.
단방향 제한 관절은 무조건 대칭 진폭을 주지 않는다. trial별 reset 후 동일 기타 목표로 비교한다.

왼손 운지 손가락 개폐·엄지 지지 완화, 오른손/전완의 타현 움직임·free fingers 운동,
양팔 순차/동시 운동·몸통 변화를 한 그룹씩 넣는다. scripted movement 목표와 안정화
보정이 충돌하면 수정한 움직임·거부된 보정·기타 오차를 모두 기록한다.
연주 목표를 계속 취소해 기타를 붙잡는 방법은 호환 성공으로 보고하지 않는다.
피드백 OFF와 ON에서 같은 scripted movement를 비교하고 오차·재안정화 시간을 기록한다.
시험 통과는 실제 곡의 압현·타현·음악 타이밍 검증을 뜻하지 않는다.

### 6.3 학습 구조 결정 조건

먼저 초기 접촉·관통·충돌 필터·경로·관성·gain 문제를 해결하고,
양손과 스트랩이 낼 수 있는 지지 힘·모멘트가 목표 유지에 충분한지 확인한다.
결정론적 제어·초기 길이 선택으로 충분하면 우선 그 구조를 유지한다.
능동 스트랩 없이는 유지하지 못하면 그것을 전제로 한 결과라고 명시한다.

학습이 필요할 때만 제어 그룹·q/L action·구동 한계·연주 task 보호·목표 오차 gate를 정한 뒤,
관측·네트워크·보상·종료/timeout·단기 pilot을 설계한다.
현재 pose 오차 지표는 평가 계약 제안이며 확정된 RL reward가 아니다.
기존 단계 보상·PPO·33-action checkpoint를 복사하거나 지금 장기 학습을 시작하지 않는다.
