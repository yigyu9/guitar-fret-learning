# 성공 궤적 초기화·손별 PPO 실제 결과 독립 검수

판정: **현재 기록과 제한된 손별 성공 후보의 보존에 차단 문제 없음. 전체 초기 자세 요구나 양손 음악 수행 완료를 승인하는 검수는 아니다.**

BC 실제 평가, 닫힌 양손 PPO 기록, 마지막 `final.pt`의 실제 결정적 평가가 모두 나온 뒤 확인했다. 검수자는 새 native 실행·학습·모델 변경 없이 원자료를 읽고 CPU에서 재집계했다. 이 검수 파일 외에는 수정하지 않았다. 앞서 검수자가 작성한 BC 분석의 요약만을 근거로 삼지 않고, 실제 결과·240Hz 표본과 PPO 전이·저장 모델을 다시 읽었다.

## 확인 범위

- 양손 capture/BC 보고서·초기화 모델·실패한 BC 평가 v1·완료된 BC 평가 v2.
- `initialization_audit_v1.json/.md`, 실제 PPO `initial.pt`와 BC의 활성 Actor/std 텐서.
- 양손 PPO `report.json`, 24개 업데이트, 닫힌 `transitions.jsonl.gz`, `persistent_audit.json`, `final.pt`.
- `left_ppo_eval_v1`, `right_ppo_eval_v1`의 실제 결과·평가 입력 pin·저장240Hz 측정.
- phase README, `policy_candidates_v1.json`, BC/PPO native 분석, PPO 집계 문서·그래프, 실행 계획, 현행 `guitar_learning/README.md`·`IMITATION_TRAINING.md`, 메인 문서4개의 최신 추가 기록.
- capture/BC/PPO/평가의 입력 SHA, 기존87개 및 계약수정 이전5개 보관본, 실패 로그.

## 실제 학습과 저장 모델

두 PPO 모두 `completed=true`, `failure=null`, `stopped=updates_complete`다. 각각24업데이트·11,520전이·48완료 에피소드이며 실제 벡터 전이 로그를 펼쳐 같은 개수를 확인했다. 원자료 재집계에서 양손 모두48/48 손별 기술 성공, 물리 실패0, 음악50ms 매칭0이다. 실행·worker·입력·물리 guard·정리 오류 배열은 비어 있고 재사용 수명 감사는 완료됐다. 학습 중 안정성 접촉률은60Hz 끝점이고, 이 비율을 모든240Hz 물리 순간의 비율로 설명하지 않았다.

실제 `initial.pt`는 업데이트0·빈 Actor/Value optimizer state다. BC와 활성 Actor의17개 텐서 및 해당 log_std가 정확히 같음을 재확인했다. 마지막 모델은 업데이트24·유한 텐서이며 비활성 손의 Actor는 초기와 같다. 활성 Actor는 실제로 변경됐다. Critic·상대 Actor를 복사하지 않는다는 근거는 봉인된 로더 구현과 초기화 감사의 범위 제한을 따른다. 저장 결과만으로 복사하지 않았다는 사실까지 역추론하지 않았다.

| 모델 | 확인한 SHA256 |

| LH BC | `89eb4f3dc5296147b881441e3d7d291f8fd93a35de9287810e1a42b783a3cb8f` |
| RH BC | `5b07074dc6c3f0c6f2a79de122aba45b86366134432fb7784868ff8d0c931db2` |
| LH PPO final | `204d672b152bc9647b321a50fc4d8fdc5763908774e4ef2cf1d155ebf864be4b` |

최종 평가의 `inputs_before.json`은 위 실제 `final.pt` SHA와 정확히 일치했다. 평가한 파일과 문서에서 제공하는 최종 모델이 같다. 후보 목록의 `best_model_selected=false`, `joint_training_ready=false`와 초기 BC·마지막 PPO의 동시 보존은 근거에 맞다. 마지막 업데이트라는 이유만으로 최적 모델을 선정하지 않았다.

## 실제 결정적 수행과 안정성

BC 및 마지막 PPO 각각 양손2회씩 평가가 완료됐으며 모든 에피소드가 `valid=true`, `stage_success=true`, `reason=timeline_complete`, 입력 불변이다. 마지막 PPO의 각 실행은240제어 tick×4물리 표본=960개이고 physics step481–1440의 연속성을 직접 확인했다. 아래는 최종 평가 원자료240Hz 재집계다. 편차 기준은 각 실행의 실제 준비2초가 끝난 후 상태이며 준비 구간은 분모에 넣지 않았다.

## 개선 여부·BC fit·KL의 해석

- BC는각2000step에서 LH MSE `2.480236253e−5`, RH `5.431588943e−5`이고, 목표 `1e−6`에 대해 `converged=false`다. 실제 native2/2 성공을 별도 진입 조건으로 사용한 사실과 수치 목표 미달을 함께 기록했다. BC의 업데이트0과 이후 PPO24를 합쳐 학습 업데이트라고 세지 않았다.
- LH BC의 최장 유지는2.875/2.870833초다. 마지막 PPO의3.0625/2.6125초와 비교하면 일률적인 향상이 아니다. RH BC의 첫 목표 방향 단계 성공2.079167초보다 마지막 PPO2.329167초가 늦고 기타·발 편차도 모두 줄어든 것이 아니다. 문서는 기능 유지와 개선·수렴을 구분한다.
- 현재 profile에서 BC 초기화가 있는 제한 학습의 손별 성공을 확인했지만, 다른 초기화·보상·상태 조건을 통제한 무작위 대조 실험은 아니다. 과거 무성공 결과와의 차이를 BC의 단독 인과 효과로 확정하지 않았다.
- 초기 actor lr는양손 `1e−5`다. 첫 업데이트의 KL guard 재시도는LH2회/RH1회이며 실제 이후 lr는LH `6.25e−7`/RH `2.5e−6`다. 저장 optimizer와 업데이트 기록이 일치한다. 수용 KL 최대는LH0.007025726/RH0.017898221이고, 거절 시도 포함 최대는0.754528522/0.064133123이다. 거절 시도의 큰 KL까지 모두0.02 미만이었다고 설명하지 않았다.
- 학습 그래프는24업데이트 원자료를 표시하며 기타 편차를 끝점 최대값, KL을수용값, 성공을학습중 손별 기술로 명시했다. 그래프가 최종 checkpoint 평가나 음악 매칭 성공을 대신하지 않는다.

## 보존·기록·남은 범위

확인한 capture/BC/PPO/평가 입력 manifest의고유1637개 경로는 SHA 충돌0·현재 bytes 변경0이었다. `archive/20261018_before_imitation`의87개와 `archive/20261018_before_imitation_contract_v2`의5개 보관본 모두 manifest SHA와 일치했다. BC 평가v1 두 실행은 계약 비교 `ValueError` 실패 로그와 초기화 전 자료가 남아 있고, v2의 정책 성공으로 과거 실패를 덮어쓰지 않았다. main 문서 이전 사본의 위치도 manifest로 남아 있다. CPU207개 통과 로그와 별도 구현 검수도 확인했으며 본 검수자가 전체 시험을 다시 실행한 것은 아니다.

계획·현행 안내·phase README는 첫 단음·동일 준비 시작, 손별 독립 수행, root 고정·하체 유한 제어·자유 기타·중력ON·스트랩OFF, 기존 제어/물리 제한의 범위를 유지한다. 양손 동시 협응·음악 타이밍·음향·다른 곡/시작 자세 일반화·사람 동작 유사성·왼손 하중 비의존은 완료로 설명하지 않는다. PPO 수렴과 전체 연구 목표 완료도 주장하지 않는다.

검수 중 발견한 lr 유지 표현과 BC std 전달 표현은 담당자에게 전달했고 최종 문서에서 초기/실효 lr 및 BC 최적화/PPO 전달 범위로 수정됐음을 확인했다. 현재 결과의 기록·후보 보존을 막는 미해결 오류는 발견하지 못했다. **LH 지지 저하는 실제 남은 과제이며, 손별 기술 성공만으로 양손 결합이나 원초기 자세 요구 완료로 승격하면 안 된다.**

최종 보존 봉인(`final_verification_v1.json`)은 이 검수 이후 Root가 수행할 단계다. 이 문서는 아직 실행되지 않은 최종 봉인 자체를 통과했다고 주장하지 않는다.
