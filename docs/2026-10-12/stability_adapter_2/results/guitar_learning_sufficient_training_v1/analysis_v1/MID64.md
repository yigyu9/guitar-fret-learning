# 추가 64업데이트 시점 — 중간 집계

**학습은 계속 진행 중이며 최종 성능·감사 결론은 보류한다.** `training_long_v1`의 완료된 update index 0–63을 먼저 목록으로 정한 뒤 복사했고, episode/resource의 index 63까지 완료된 줄만 고정했다. 이후 데이터는 포함하지 않았다. 목록·SHA·수집 시각은 `mid64_snapshot_manifest.json`, 고정 원자료는 `mid64_input_snapshot/`, 수치는 `mid64_summary.json`이다. 기준은 B32, 이번 추가 64회 저장본은 optimizer 누적 96회다. 과거 C의 처음 14회가 정확히 재현된 관계와 smoke 결과를 별도 표본으로 합산하지 않는다.

122,880전이가 sampled/logged/durable/committed 모두 같고 discarded는 0이다. 종료 에피소드 512개 중 성공 247회(48.2422%), 물리 실패 0, 목표 접촉 해제 통과 512/512다. 평균 유지율 55.2409%, 준비 clean 시간 65.544ms, 오압현 57.560ms, 미압현 165.617ms다. 이것은 한 정책이 변하며 수집한 같은 조건의 학습 기록이고, 독립 평가 성공률이 아니다.

## 실패의 대부분은 준비 접촉을 확보하지 못한다

실패 265회 중 준비 clean 시간이 0인 것은 261회(98.49%)다. 음 구간 유지율 0은 199회이며, episode 전체에서 first clean 자체가 관측되지 않은 것은 180회다. 이 둘은 서로 다른 진단으로, 음 구간 밖의 짧은 접촉을 음악 유지 성공으로 세지 않는다.

준비 clean 시간이 양수였지만 유지에 실패한 4회는 다음과 같다. 여기서 양수 준비 접촉은 누적 접촉 측정이지, 아직 적용하지 않은 R1/R2의 50ms 지속 획득 latch가 아니다.

| update index(0부터) | worker | 준비 clean 시간 | 음 구간 유지율 |
|---|---:|---:|---:|
| 30 | 1 | 83.333ms | 88.3333% |
| 34 | 5 | 50.000ms | 70.8333% |
| 49 | 0 | 25.000ms | 12.5000% |
| 58 | 3 | 66.667ms | 50.0000% |

첫/뒤 32회 실패는 각각 130/135회, 준비 clean 0은 129/132회다. 획득 실패가 여전히 중심이며, 이미 접촉한 뒤 충분히 유지하지 못하는 사례도 존재한다. 해제 100%는 지정 손가락 목표 접촉이 해제 창에 없다는 조건으로, 실패 전에 접촉을 잘 획득했다는 뜻이 아니다. 보상 R1/R2와 회복 학습은 이 실행에 적용되지 않았다.

## Critic은 개선되지만 음악 수행 상승으로 연결되지 않는다

| 최적화 기록 평균 | 첫 32회 | 뒤 32회 |
|---|---:|---:|
| Actor LR | 1e-7 | 1e-7 |
| KL retry | 0 | 0 |
| accepted KL | 1.02101e-4 | 1.19775e-4 |
| latent std 평균 | 0.00300261 | 0.00300515 |
| BC MSE | 3.38920e-8 | 2.61285e-8 |
| reward value loss | 0.073298 | 0.063372 |
| reward explained variance | 0.60861 | 0.70325 |
| cost value loss | 0.00010877 | 0.00002472 |
| cost explained variance | 0.68908 | 0.86684 |
| weighted cost / reward advantage std | 3.4809% | 1.9866% |

LR 붕괴나 KL 복원 반복은 없으며, accepted KL 전체 범위는 약 3.59e-5–3.00e-4로 기준 0.005보다 작다. 평균 latent std는 첫 업데이트 0.003000585에서 64번째 0.003006075로 약 0.18% 증가해 거의 유지된다. 고정 시연에 대한 BC MSE는 뒤 구간에서 줄었다. 이는 측정한 시연 행동에 더 가까워진 방향이지만, 그것이 성공 정체를 만들었다는 인과 증거는 아니다.

두 Critic은 평균 loss와 설명력이 함께 좋아졌다. 그럼에도 학습 중 접촉 성공은 상승하지 않는다. 따라서 “학습이 전혀 적용되지 않는다”보다 “예측·작은 정책 수정은 진행되지만 접촉 획득 성공으로 충분히 연결되지 않는다”는 설명이 현재 기록에 더 가깝다. 실제 가중치·고정 BC 관측의 출력이 변한다는 확인은 추가 32회 모델의 `PARAMETER_MID32.md`, `ACTOR_OUTPUT_MID32.md`에 있으며, 그 결과를 이번 64회 모델의 출력 측정으로 상속하지 않는다.

cost weight는 모든 64회에서 1.0이다. weighted cost advantage 표준편차가 reward보다 훨씬 작고 뒤 구간에서는 더 작아, 현재 진단으로는 안전 비용이 음악 학습을 압도한다고 보기 어렵다. 이 비율은 실제 gradient 기여도를 직접 분해한 값이 아니며 안전 조건 완화의 근거도 아니다. 보상·BC 상태 범위·정책 변화·접촉 민감성 중 주원인을 분리하려면 조건을 나눈 후속 비교가 필요하다.

## 수집·자원·최종 확인 범위

수집은 첫/뒤 32회 평균 79.62/80.74초이고 PPO는 0.073/0.069초다. 분석 시점의 resource prefix는 약 5,158초까지이며, 다른 평가가 함께 실행된 시간도 섞여 있다. 최저 가용 RAM은 약 12.10GiB, parent RSS 최고 약 1.38GiB다. 마지막 checkpoint가 저장됐다고 전체 실행의 정리·worker 종료·runtime/core 최종 검사가 완료된 것은 아니다. 아직 최종 CUDA peak나 모든 worker peak를 갖춘 종료 보고서가 없어 그 부분은 보류한다.

현재 128회 목표 학습이 진행 중이며, 별도 fresh-process 평가도 아직 여기서 집계하지 않았다. 학습곡선은 `mid64_learning_curve.png`다. 동일 준비 자세의 왼손 단음·단일 학습 계보 결과이며, 전곡·양손·접촉 회복·초기 자세 일반화·통계적 독립성을 주장하지 않는다.
