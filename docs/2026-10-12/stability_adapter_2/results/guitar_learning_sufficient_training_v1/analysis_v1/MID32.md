# 추가 32업데이트 시점 — 중간 집계

**본 학습은 진행 중이며 최종 평가·감사 전 잠정 결과다.** `training_long_v1`의 완료된 update index 0–31, 종료 에피소드 256개만 `mid32_input_snapshot/`에 고정했다. 파일 목록·SHA·수집 시각은 `mid32_snapshot_manifest.json`, 수치는 `mid32_summary.json`, 곡선은 `mid32_learning_curve.png`에 있다. 이후 업데이트와 기록 중이던 줄은 제외했다. B32에서 추가 32회, optimizer 누적 64회이며, smoke·과거 C 표본을 합산하지 않는다. 처음 14회가 과거 C와 정확히 재현되는 관계는 `mid16_old_C_comparison.json`에 이미 확인했다.

61,440전이가 sampled/logged/durable/committed 모두 일치하고 discarded는 0이다. 성공은 126/256(49.2188%), 물리 실패 0, 목표 접촉 해제 통과 256/256이다. 초기와 비교해 성공률이 지속적으로 개선된다는 근거는 아직 없다.

## 최적화는 진행되지만 접촉 성공으로 이어지지 않는다

| 기록된 최적화 진단 평균 | 첫 16회 | 뒤 16회 |
|---|---:|---:|
| Actor LR | 1e-7 | 1e-7 |
| KL retry | 0 | 0 |
| accepted KL | 1.30795e-4 | 7.34069e-5 |
| latent action std | 0.00300157 | 0.00300365 |
| BC MSE | 3.41637e-8 | 3.36204e-8 |
| reward value loss | 0.078276 | 0.068320 |
| cost value loss | 0.00015286 | 0.00006468 |
| reward explained variance | 0.59577 | 0.62145 |
| cost explained variance | 0.72058 | 0.65758 |
| weighted cost / reward advantage std | 4.0431% | 2.9187% |

Actor LR가 유지되고 KL 복원이 한 번도 없어, 기존 실행의 LR 붕괴 문제는 이 구간에 재발하지 않았다. 평균 std는 첫 업데이트 0.003000585에서 마지막 0.003004238로 약 0.12%만 증가했다. BC MSE 역시 작은 범위에 머물러 시연 주변 행동을 조금씩 수정하는 상태다. reward Critic의 loss/설명력은 평균적으로 개선되지만, 행동 성공률은 함께 개선되지 않는다. cost Critic의 loss 감소와 설명력 감소가 동시에 나타나므로 loss만 보고 모든 예측력이 좋아졌다고 표현하지 않는다.

weighted cost advantage의 변동은 reward advantage의 약 1–7% 범위이고 뒤 구간에서 더 작아졌다. 현재 지표에서는 안전 비용 때문에 음악 학습이 압도된다고 볼 근거가 부족하다. 다만 이 비율은 실제 Actor gradient의 기여도 측정이 아니므로 비용을 없애도 된다는 결론으로 연결하지 않는다.

현재 가장 좁게 말할 수 있는 결론은 **최적화·Critic 적합 자체는 돌아가지만, 탐색 중 안정적인 준비 접촉과 충분한 유지 성공은 약 50% 부근에서 정체되어 있다**는 것이다. 보상, 작은 행동 변화, 시연의 상태 범위, 접촉 민감성 중 무엇이 주원인인지는 마지막 고정 조건 평가와 실패 원자료를 더 보아야 한다. 학습 중 성공률은 같은 고정 seed 20회 평가와 분모·행동 궤적이 다르므로 직접 개선 수치로 비교하지 않는다.

수집 시간은 첫/뒤 구간 평균 88.62→70.61초, PPO 업데이트는 0.080→0.067초다. 앞 구간에는 별도 baseline 평가가 함께 실행되어 시간 차이에 부하 영향이 섞여 있다. 최저 가용 RAM은 약 12.10GiB, parent RSS 최고는 약 1.38GiB다. 병목은 여전히 native 수집이며, 이 기록만으로 GPU를 더 쓰면 학습 효율이나 성공률이 개선된다고 보지는 않는다. 최종 CUDA/worker peak와 전체 runtime/core 감사는 종료 후 확인한다.

R1/R2 보상·접촉 회복 학습은 적용하지 않았다. 동일 준비 자세의 왼손 단음 결과이며 전곡·양손·회복 성공·초기 자세 다양성 일반화를 주장하지 않는다.
