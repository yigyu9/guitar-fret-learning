# B32 → 최종 모델의 파라미터 변화

추가 128회가 끝난 `training_long_v1/final.pt`(optimizer 누적 160회)를 B32와 CPU로 비교했다. 결과는 `parameter_final.json`, 재현 도우미는 `parameter_final.py`다. 중간 32회 파일은 수정하지 않았다. Torch CPU·연산/interop 각 1스레드를 사용하고 native·GPU·학습·forward는 실행하지 않았다.

원 B32(`ed4408…`)와 본 실행에 사용된 봉인 이전본(`8bedd8…`)의 모든 model tensor가 정확히 같음을 다시 확인했다. 비교한 최종 파일 SHA는 `ae9770470cdbd7141bf47c277a4a81757a753841beab18419c60de31f2e9a7e6`다. 기준/최종의 identity·이름/shape/dtype schema가 같고, 읽은 세 checkpoint의 분석 전후 SHA도 같다. 정확한 경로와 전체 SHA는 JSON에 있다.

RMS는 scalar 변화량 제곱 평균의 제곱근, 상대 L2는 `||최종−기준||₂ / ||기준||₂`이며 표에는 백분율로 적었다. 왼손 Actor scalar 약 95.40%가 바뀌었고 17개 tensor 중 16개에 변화가 있어, 업데이트가 전혀 반영되지 않았다는 설명은 맞지 않는다. Actor 가중치의 상대 이동은 작으며 Value/Critic은 더 크게 바뀌었다. 오른손 파라미터가 그대로인 것은 현재 왼손 역할과 맞는다.

활성 축 `exp(log_std)` 평균은 0.003000501→0.003006227(약 0.1908% 증가), 범위는 0.002963385–0.003037399→0.002938818–0.003088433이다. log_std 자체의 상대 변화율과 실제 표준편차의 변화율은 같은 값이 아니다.

이 결과는 실제 업데이트 여부와 가중치 거리의 측정이다. 파라미터 상대 거리를 곧바로 행동·관절각·접촉 성공 차이로 해석하지 않는다. 작은 Actor 변화가 낮은 LR·BC·clipping 때문에 발생했는지, 그것이 수행 한계를 만들었는지는 이 비교로 확정할 수 없다. 고정 BC 관측에 대한 실제 출력 비교는 `ACTOR_OUTPUT_FINAL.md`, 최종 native 수행은 별도 평가 결과로 판단한다.
