# 왼손 단일 목표의 추가 128회 학습과 전후 평가

**학습은 정상 완료됐고 후반에 완만한 개선이 나타났다. 하지만 탐색 중 준비 접촉을 안정적으로 확보하는 문제는 해결되지 않았다.** 같은 설정으로 시간을 더 주는 것만을 다음 단계의 최우선으로 삼기에는 이득이 작다.

## 실제 수행량

검증된 B32에서 model·Critic·optimizer·RNG를 그대로 이어 추가 128 PPO 업데이트를 수행했다. 최종 누적 업데이트는 160회다. 8환경·240 control tick에서 245,760전이가 sampled/logged/durable/committed 모두 일치했고 폐기·미해결 전이는 0이다. 학습 에피소드 1,024회 중 목표 성공은 529회(51.66%), 물리 실패는 0, 목표 접촉 해제 통과는 1,024회다.

학습 내부 시간은 9,654.14초(약 2시간 41분, 선행 입력 감사 제외)다. 수집 9,611.77초, PPO 갱신 8.72초로 이번 실행의 시간 대부분은 시뮬레이션·수집에 사용됐다. 각 worker는 장면을 한 번 만들고 재사용했으며 정상 종료했다. 129개 reset 기록은 128회 완료 뒤 다음 에피소드를 준비한 reset까지 포함한 수다.

별도 smoke 8회와 기준·중간·최종 평가 132회는 위 학습량에 더하지 않았다. 이번 처음 14회는 과거 C 실행의 처음 14회를 정확히 재현하므로 새로운 독립 표본으로 합산하지 않는다.

## 학습 구간의 변화

| 지표 | 첫 64회 | 뒤 64회 |
|---|---:|---:|
| 목표 성공 | 247/512 (48.24%) | 282/512 (55.08%) |
| 음 구간 목표 접촉 유지율 평균 | 55.24% | 60.88% |
| 마지막 200ms 준비 창 clean 접촉 평균 | 65.54ms | 74.26ms |
| 미압현 평균 | 165.62ms | 136.49ms |
| 물리 실패 | 0 | 0 |

각 32회 구간 성공은 126, 121, 137, 145회/256이다. 급격한 성공 전환보다 후반의 점진적 상승이다. 학습 중 변화와 최종 정책의 고정 조건 평가를 구분한다.

## 기준·중간·최종 정책 평가

| 실행 조건 | 기준 B32 | 중간 누적64(추가32회) | 최종 누적160 |
|---|---:|---:|---:|
| 탐색 없음·반복 초기화 | 20/20 | 20/20 | 20/20 |
| 탐색 있음·반복 초기화 | 8/20 | 11/20 | 11/20 |
| 탐색 있음·매 case 새 프로세스 | 3/6 | 미실행 | 4/6 |

세 모델의 20조건은 같은 정책 RNG seed 순서로 실행했다. 반복 초기화의 저장 자세·속도·목표가 같더라도 contact history는 달라질 수 있어 완전히 같은 초기 상태의 독립 비교로 설명하지 않는다. 새 프로세스 6조건은 최종 모델 생성 전에 고정한 별도 진단이다. 두 시험을 합산하거나 작은 차이를 통계적 우월성·초기 자세 일반화로 확대하지 않는다.

최종 탐색 유지율 평균은 57.46%로 기준 45.71%보다 높지만 중간 67.92%보다 낮다. 최종 미압현 평균은 187.40ms로 기준 145.83ms와 중간 133.23ms보다 높았다. 중간→최종의 성공 수는 같아도 10/20조건에서 판정이 바뀌었다. 탐색 없는 최종 평가는 20/20 성공을 유지했지만 평균 유지율은 100%→98.5%, 준비 clean은 176.67→160ms로 전면 개선은 아니다.

새 프로세스 12개 실행의 관측 가능한 초기 상태는 접촉 이력까지 정확히 같았다. 기준의 성공101/103/107은 유지됐고109가 새로 성공했으며113/127은 실패를 유지했다. 이 관측 상태 동등성을 숨은 PhysX cache 동등성으로 설명하지 않는다.

`final.pt`는 마지막 저장 모델이며 최우수 모델이라는 선언이 아니다. 중간 평가 모델은 `training_long_v1/checkpoint_000031.pt`(이번 추가32회·누적64회)로 보존했다. `analysis_v1/MID64.md`는 추가64회(누적96회)의 학습 구간 분석이므로 이 중간 정책 평가와 시점이 다르다.

## 실패와 해석

실패 495회 중 487회(98.38%)는 **마지막 200ms 준비 창**의 clean 접촉 시간이 0이었다. 음 구간 유지율 0은 371회, 에피소드 전체 first clean 미관측은 337회다. 준비 접촉이 양수였지만 유지에 실패한 경우도 8회 있다. 양수 누적 접촉은 미구현 R2의 50ms 연속 획득 latch와 다른 정의다.

실패한 495회 모두 해제 보상 0.75를 받았다. 충분히 누르지 못했어도 접촉이 없으면 해제 보상을 받을 수 있는 현 설계의 특징이다. 이것만으로 정체의 원인을 확정할 수는 없지만 후속 보상 비교에서 확인해야 한다.

Actor LR은 1e-7로 유지됐고 KL retry는 0회였다. Critic의 loss·설명력은 개선됐으며 Actor와 고정 관측의 출력도 실제로 변했다. 안전 비용의 변동이 음악 reward advantage를 압도한다는 근거는 없었다. 다만 이 비교는 Actor gradient의 인과 분해가 아니며, LR·BC 가중치·접촉 민감성의 개별 원인은 별도 실험이 필요하다.

다음 우선순위는 준비 구간 전체의 접촉 획득 신호(R1), 실제 접촉 상실·회복이 확인된 시연 자료, 획득 이력을 관측에도 제공하는 해제 보상 설계(R2)를 분리해서 검증하는 것이다. R1/R2·회복 BC/PPO는 이번에 적용한 실험이 아니다. Actor LR·BC 가중치 비교도 각각 별도 계약과 실행으로 진행해야 한다.

## 범위와 보존

이번 결과는 같은 준비 자세에서 수행한 왼손 단일 목표·4초 에피소드·단일 학습 계보다. Root 고정·하체 유한 제어·105/97/8·자유 기타·중력 ON·스트랩 OFF와 기존 gain·제한·충돌 정책을 유지했다. 오른손 정책 출력은 비활성이고, 비정책 관절의 유지 제어를 새 전신 정책 학습으로 설명하지 않는다. 목표 접촉 해제는 왼손 전체 하중 해제의 검증이 아니다.

두 음 전환·전곡·양손 동시 수행·일반화·실제 현 압력·진동·음향·Root 자유 균형·엄밀 EPS0 원인 규명의 성공으로 확대하지 않는다. 기타 직접 보조 힘·부착·실행 중 상태 덮어쓰기를 추가하지 않았다.

실행 소스·외부 입력은 `frozen_execution_view_v2/manifest.json`의 2,398개 pin으로 고정했고 독립 검수에서 불일치 0이었다. 현재 host의 다른 작업과 동결 실행 view를 구분한다. B32의 과거 평가용 이관 manifest는 보존하고 이번 학습 사용 결정은 `training_use_decision_v1.json`에 별도로 기록했다. 실행 준비의 캐시 오류와 첫 검증 호출의 import 오류 등 실패 자료도 그대로 보존했다. 이번 작업에서 생산 학습 코드를 수정하지 않았다.
