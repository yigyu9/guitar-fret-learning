## 실제 전송과 입력 변화의 구분

원본505 Actor가 기존 성공 입력과 새 실패 입력에서 각각 저장된 실제 첫 행동을 최대3.66e−7/5.97e−8 이내로 재현했다. 536차원으로 재구성한 Actor의 기존505열과 나머지 활성 가중치는 원본과 완전히 같고 새31열은 정확히0이다. 새31개 이력을0으로 바꿔도 출력은 변하지 않았다. 실패 실행의 모든 tick 행동 역시 원본505 Actor에 새505 prefix를 넣으면 수치 허용오차 안에서 재현된다.

실제 native 평가 직후536 모델 텐서는 별도 checkpoint로 저장되지 않았다. 따라서 런타임 텐서를 직접 읽었다는 주장은 하지 않는다. 이는 실제 전달 기록과 일치하는 전송을 CPU에서 재구성하고 저장된 native 행동을 대조한 근거다.

## 실제 물리와 실패

행동 codec·관절 목표 계약·안전 조건·준비 목표105개는 기존 성공 실행과 같다. 감사 대상 native 제어·자산·준비 입력의 SHA도 기존/새 실행 pin과 같다. 초기 정책의 물리 관측도 같지만, 기존 평가에는 full native body/solver 상태가 없어 숨은 solver/contact 상태의 완전 동일성을 주장하지 않는다.

정규화 행동 범위 안에서도 처음부터 큰 팔 명령이 생겼고 실제 관절·접촉·기타 상태가 달라져 안전 종료에 이르렀다. 새 시간 조건 아래에서 기존 Actor를 바로 실행하는 방식은 이번 왼손 초기 평가에서 안전하지 않았다.
