# 단음 성공 확인 후 두 단음으로 확장

사용자 요청에 따라 기존 첫 단음 장기 학습은 그대로 유지하고, **그 실행이 끝난 뒤 실제 평가와 진급 판정**을 수행하는 별도 후속 실행을 구성했다. 이 문서는 조건부 실행의 설명이다. 확장 시작 여부는 `watch_v1/status.json`의 hands별 advanced와 reason, 최종 결과는 `watch_v1/result.json`을 확인한다. 학습이 잘 될 것이라는 예상으로 확장을 시작하지 않는다.

## 진급 기준

왼손과 오른손을 독립 판단한다. 통과한 손만 확장하고 다른 손의 실패를 상속하지 않는다.

1. 원 단음 trainer가 물리·입력·소스 검수를 포함해 정상 완료해야 한다.
2. 최근64개 종료 학습 episode에서 역할별 품질 성공률90% 이상이어야 한다. 이64개에는 invalid/물리실패 terminal도 포함하고, 미완료 prefix는 분모에 넣지 않는다. 안전한7초 완료 이외의 종료는0개여야 한다. 즉64개 중 최소58개 품질 성공이 필요하다.
3. 종료 모델로 정책 평균을 사용하는 결정적 평가4회 모두7초를 안전하게 완료하고 해당 손의 품질 목표도 통과해야 한다. 이는 같은 준비 초기상태의 반복 평가이며 새로운 곡·초기상태에 대한 일반화 검증이 아니다.
4. 새 pool에서 두 목표를 각1회 실제로 reset·실행하는 사전 검사를 통과해야 한다. 이때 새 목표의 음악 성공은 요구하지 않지만, 두 목표의 실제 선택 기록·7초 안전 완료·입력 불변은 요구한다. 사전 검사가 실패하면 확장 학습을 시작하지 않는다.

왼손의 품질 성공에는 음 구간 clean 접촉과 이후 목표현 접촉 해제가 필요하다. 오른손에는 준비 후 목표 통과와 회복, 추가·준비 전·잘못된 타현이 없는 조건이 필요하다. timing-only 성공과 품질 성공은 구분한다. 현행 성공·보상·안전 문턱을 낮춰 진급하지 않는다.

## 첫 확장 대상과 의미

곡 `05_BN2-131-B_solo`의 source event **[0,2]**를 명시적으로 선택한다.

|원 이벤트|현(1기준)|프렛|손가락|방향|
|---|---:|---:|---:|---|
|0: 기존 목표|2|7|3|down|
|2: 추가 목표|3|7|3|down|

기존 목표와 같은 프렛·손가락·방향을 유지하며 인접 현 하나만 추가한다. 매 episode는 여전히 **한 음**이다. 두 음을 한 episode에서 순서대로 연주하는 프레이즈나 화음은 아니다. 각 worker가 seed+worker_id로 순서를 섞고, 각 두 episode 묶음 안에서 두 목표를 한 번씩 선택한다. 기존 음도 절반 유지하여 새 목표만 학습하며 잊는 상황을 줄인다. 손별/목표별 결과를 함께 기록해야 한다.

상태563·행동39·medium·native정착0초/정책7초·기존 timing stage1(±0.5초)·기타 상대 관측·기존 지지 제어와 물리 기준을 유지한다. 새 환경은 매 reset에 원 task·+3초 실행 task와 측정/음악/skill/timing/quality ledger를 모두 새로 구성한다. 실제 선택은 episode_task로 기록하고, 정책/worker 계약은 전체 후보를 담은 고정 pool 계약으로 유지한다.

## 정책 이전과 예산

확장은 단음에서 학습한 **563 Actor와 탐색 표준편차**를 명시적으로 이전한다. 입력의 순서/정규화·동작·보상·타이밍·안전이 같고 허용된 task 선택 차이만 있는지 검사한다. 목표 분포가 달라지므로 critic·Adam·RNG·update counter는 새로 시작한다. 이는 전체 옵티마이저 재개와 구분한 warm-start다. 새 pool 내부의 재개는 기존 strict PPO 계약을 그대로 사용한다. 기존 단음 성공을 새 음의 성공으로 상속하지 않는다.

통과한 손별16환경, 최대2시간/256업데이트다. 둘 다 통과하면 총32환경으로 동시에 실행하고, 한 손만 통과하면16환경이다. 새 평가/사전 검사는 원 장기 실행 종료 후 순차 수행해32개 학습 worker와 겹치지 않는다. 평가4회·pool검사2회는 별도 시간이며 학습2시간은 업데이트 경계 soft 제한이다. 기존6GiB 메모리 보호와5업데이트 간격 체크포인트를 유지하고, 새 native 단계 시작 전8GiB 여유를 요구한다.

이번 후속 실행은 두 단음 pool까지로 제한한다. 원 단음 품질이 미달이면 확장을 보류하고 해당 사유와 평가·모델·로그를 남긴다. 실행 오류와 순수 품질 미달을 상태/종료코드에서 구분한다. 무제한 재학습이나 다음 화음·전곡 승급은 연결하지 않는다.

## 파일과 상태

- `progression_plan_v1.json`: 원 실행·진급 조건·예산·목표 선택과 후속 경로.
- `pool_left_settings_v1.json`, `pool_right_settings_v1.json`: 두 목표 설정. actor_initialization은 원 실행의 미래 final.pt를 가리키므로 원 실행 종료 후에 검증한다.
- `watch_and_expand_v1.py`: 원 supervisor 종료 대기→양손 평가→진급→새 pool 검증→후속 학습을 관리하는 실험 실행기. 대기 중 native 환경을 추가하지 않는다.
- `execution_pins_v1.json`: 실행 전 새 소스·설정·실행기를 봉인한다. 원169 source pin과 원실행6 pin도 검증한다. 변경되면 기존 모델 계약을 우회하지 않고 오류로 멈춘다.
- `watch_v1/status.json`: 실제 watcher PID·대기/평가/진급/학습 단계와 소유한 자식 PID/종료코드.
- `watch_v1/single_{left,right}_evaluation_v1/`: 원 단음 종료모델의 실제 평가.
- `watch_v1/single_{left,right}_gate_v1.json`: 최근 학습 구간과 결정적 평가의 판정 근거. 마지막 진행 여부/사유는 status/result를 본다.
- `watch_v1/pool_{left,right}_preflight_v1/`: 통과한 손의 두 목표 실제 사전 검증.
- `pool_{left,right}_train_v1/`: 진급한 경우에만 생성되는 확장 모델·원전이·목표별 episode·학습 로그.
- `watch_v1/*.log`: 단계별 터미널 로그.
- `watch_v1/result.json`: 후속 실행 종료 상태. execution_ok는 실행 정상 여부이며 음악 학습 성공을 의미하지 않는다.

현행 소스는 수정하지 않고 `guitar_learning/curriculum/`의 새 모듈과 새 테스트만 추가했다. 원 모델·실패·봉인 자료는 보존한다. watcher는 채팅과 분리해 실행하며 원 학습을 종료하거나 새롭게 재시작하지 않는다. 취소가 필요하면 신원을 확인한 watcher PID에 SIGINT를 보내며, watcher는 자신이 시작한 평가/확장 자식만 정리한다. 원 장기 실행은 watcher의 자식이 아니다.

실제 native pool 검사는 진급 조건이 만족되어 해당 단계가 실행된 뒤의 결과만 근거로 삼는다. CPU 검사를 통과했다는 이유로 새 목표에서의 안전·성공을 미리 주장하지 않는다.

실제 watcher 시작 정보는 `launch_v1.json`, CPU 검사·입력 봉인·초기 대기 상태 확인은 `validation_v1.md`, 최종 독립 검수는 `review_v2.md`에 기록한다.
