# B 준비 자세의 약한 권고 보상 v14

사용자가 선택한 B를 손이 쉬는 구간의 느슨한 자세 선호로 사용한다. 압현 준비·접촉 중에 자세 점수가 경쟁하지 않도록 차단한다. 강제 경유 자세, 관절 목표 또는 음 달성 조건으로 사용하지 않는다. 초기035/v14는 그대로이며 이번에는 실제 학습을 실행하지 않았다.

## 보상과 차단

- B의 실제 source 기하 굽힘을 중심으로 MCP/PIP/DIP 각각 ±15° 안이면 같은 최대 품질이다. 바깥에서는 `exp(-sum(excess_angle²)/(30°)²)`로 완만하게 감소하고 네 손가락을 평균한다. MCP는 그림과 같은 `Exp([x,0,z])` 입력을 실제 forward-vector 굽힘으로 변환한다.
- 최대 보상은 손 전체 **0.01/초**다. 활성 추종 상한2/초의0.5%이며 기존 approach 단계 가중치로 적분한다. 음 길이나 쉬는 구간을 늘려주는 기능은 없다.
- 어느 손가락이라도 배정 음의 **press−2~end**이면 손 전체 자세 보상은0이다. 창 바깥 양쪽0.25초는 선형 fade한다. 여러 음과 손가락이 겹치면 가장 바쁜 상태를 따른다.
- 비엄지 손가락의 어느 마디라도 net contact load가0.01N 이상이거나, 이전/현재 접촉후보·오압현이 있으면 전체0이다. 이 load는 접촉 상대를 인증하지 않으므로 보수적인 차단에만 쓴다.
- 어떤 곡 목표와의 지정 패드 거리가4cm 이하이면 시간창 밖에서도 전체0이다. 유효하지 않은 거리도 차단한다. 빈 곡은0이다.
- 기존의 상시 관절 분담 보상은 활성 경로에서0이다. `song_finger_coordination` 로그 열은0으로 유지하고 새 권고 보상은 기존 `song_finger_standby` 열에 기록한다. 벌림·엄지에 자세 보상을 주지 않는다.

이 구현은 압현 구간의 직접적인 자세 보상 경쟁을 없앤다. 약한 보상도 정책 학습에는 간접 영향을 줄 수 있으므로 압현 성능 저하가 전혀 없다는 보장은 실제 학습 없이 할 수 없다.

기본67음의 시간표만 보면 전체 시간의 약86.8%는 준비/유지 차단 구간이다. 초기 정적 상태의 가장 가까운 지정 패드는 목표에서 약2.0mm로 근접 차단도 켜진다. 따라서 초기 상태에서 B를 향해 움직이도록 보상하지 않으며, 연주 내내 B를 거치지 않아도 된다. 이 수치는 [고정 입력 진단](default_song_gate_diagnostic.json)이고 실제 학습 궤적의 통계가 아니다.

## 유지한 동작과 계약

손가락 움직임 비용0·제어/KD/관절 한계·물리·PPO·초기 자세를 유지한다. v13 추종v7과 v11 최초접촉·v12 연속clean달성, 유지보상·오압현·손목영역·안전 비용도 그대로다. 기존 `finger_posture_reward` 함수는 관측과 legacy 직접호출에 남아 있다. 새 활성 함수는 같은 측정을 재사용하되 기존 자세율은 누적하지 않는다.

전체 보상 `gpu_tensor_song_reward.v14`, 활성 자세 `gpu_finger_preparation_rate.v1`이다. 상태544/event24/priority8/커리큘럼3331을 유지하며 이전v13 이하 checkpoint의 strict resume는 거부한다. 같은v14 전체 계약끼리 복원한다.
