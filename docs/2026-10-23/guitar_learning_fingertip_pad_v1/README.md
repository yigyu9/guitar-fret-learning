# GPU 왼손 끝마디 압현면 v10

실제 끝마디 메시에서 굴곡 안쪽과 둥근 끝 아래쪽을 압현 허용면으로 지정했다. 접근 안내와 정상 접촉 후보가 같은 허용면·지판 기준면을 사용한다. 손등·중간마디가 가까워진 것만으로 정상 압현 보상을 받던 경로를 분리했다.

## 적용 규칙

- 검지·중지·약지·소지 각각 실제 메시 삼각형을 경계에서 자른 뒤 면적에 비례해 128점을 배치한다. 각 점의 원본 삼각형·barycentric 좌표·바깥 법선과 입력 SHA를 기록한다.
- 소스의 끝 방향은 −y, +x 굴곡은 −z 방향이다. `u=(ymax-y)/(ymax-ymin)`일 때 `z≤0, u≥0.25`이고, `normal_z≤−0.25` 또는 둥근 끝의 `u≥0.75, normal_y≤−0.4, normal_z≤0`인 면을 사용한다. 소스에 피부·손톱 라벨이 없으므로 모델 굴곡 방향을 근거로 정한 공학적 영역이다.
- 접근 거리는 지정 손가락의 허용면에서 지판면으로 투영한 목표현의 유한 프렛 셀 안쪽까지 계산한다. 프렛 경계에서 2mm 안으로 줄이며, 하중·방향과 무관하게 유한한 안내를 제공한다.
- 정상 접촉 후보는 **동일 표면점**의 현 옆방향 거리≤3mm, 셀 안쪽 위치, 지판면 부호 거리 −1~+3mm, 바깥 법선과 지판을 향하는 방향의 내적≥0.1을 모두 요구한다. 지정 끝마디의 순접촉력도 0.01N 이상이어야 한다. 이는 접촉 상대·실제 현 압력·음향의 인증은 아니다.
- 추종 보상은 목표 2cm 안에서만 방향에 따라 최대20% 약하게 줄인다. 거리 기반 접근 potential은 방향 때문에 사라지지 않는다. 손가락 움직임 비용은0이며 물리 메시·관절 범위·PD·누적 제어를 바꾸지 않았다.
- 잘못된 프렛·손가락 검사는 엄지를 포함한 기존 중간/끝마디 전체 표면으로 유지한다. 허용면 밖의 모든 접촉에 새 벌점을 일괄 부과하지 않는다.

## 관측·기록·재개

보상은 `gpu_tensor_song_reward.v10`, 관측 의미는 `left_surface_events.v3`, 음별 원장은 `surface_note_ledger.v3`다. 상태544·event24·priority8·커리큘럼3331값은 유지한다. event22/23은 중복된 엄격 타이밍 잔여시간 대신 최근접 허용점의 법선 내적·지판면 부호 거리를 담는다(scale1/0.03m). 다른 타이밍 정보와 strict50/100ms 진단은 유지한다.

원장에는 위치 조건 시간·방향 조건 시간·끝마디 하중 시간과 함께 기존 전체 표면 기준의 중간/끝마디 목표 접촉 및 새 허용면 판정에서 거부된 시간을 기록한다. 이 시간들은 겹칠 수 있다. `rejected_target_time`은 옛 기준의 하중 목표 후보가 새 기준을 충족하지 못한 시간이며, 실제 손등 접촉의 확정값은 아니다.

v9 이하 checkpoint는 strict resume하지 않는다. 새 학습으로 시작하고 동일 v10 전체 계약의 checkpoint만 재개한다. 기존 손목 허용 영역과 CPU 왼손·오른손 경로는 유지한다.

## 검증

관련 CPU21모듈 **202개 검사 통과**. 허용면의 원본 삼각형 복원·법선·분포, 같은점의 위치/방향 조건, 손등/중간마디 제외, 접근 신호 유지, 기존 오압현·부분reset·안전·보상 적분·PPO·v9 거부/v10 복원을 포함한다. 독립 change-reviewer 검수에서도68개 검사와 별도 NumPy 수식의 무작위77개 환경·목표 대조가 통과했다. 최종 로그·저장본·그림·보고서 검수도 통과했으며 남은 지적은 없다.

최종444개 Python 소스를 보존하고 RTX4070Ti에서 **large·1024환경·H32·seed7**로 실행했다.

| 실행 | PPO 업데이트 | 반영 전이 | CRC/EOF 원시 행 | 결과 |
|---|---:|---:|---:|---|
| `gpu_fresh` |새2회|65,536|64|정상 종료|
| `gpu_resume` |누적2→3회|32,768|32|정상 종료|
| `gpu_active` |누적3→11회|262,144|256|정상 종료·목표 음 구간 진입|

합계360,448전이를 반영했다. 각 실행의 입력589/590/590개 SHA와 원시 gzip CRC/EOF를 확인했다. fresh→resume와 resume→active 양쪽 경계에서 모델·Actor Adam·Value Adam·3331이력·업데이트 수·cost weight·Python/NumPy/Torch/CUDA RNG가 정확히 일치했다. 모델과 두 optimizer tensor는 모두 유한하며 장면·로그가 정상 close됐다. 관측 GPU 여유 최저는 약6.56GiB다.

처음 두 실행은 준비구간 안에서 끝나 손가락 추종 보상이0이었다. 이를 구분하기 위해 `gpu_active`를 초기 자세에서 정책시각4.267초까지 추가 실행했다. update2부터 거리 접근·손가락 추종 보상이 가동됐으며 update6부터 새 패드 기준 최초 접촉·유지 보상도 발생했다. 마지막 update의 전이당 평균은 추종0.0174082, 최초 접촉0.0050048, 유지0.0079223이다. 업데이트마다 시간창·노출 음이 달라지므로 이 값의 증가를 학습 향상으로 해석하지 않는다.

이 짧은 실행의 전체 곡 완료는0개다. 종료된11개 에피소드는 모두 물리 실패였고 기타변위11건·회전1건(중복)이다. 그 종료행의 달성 음 합계는0이며 살아 있는 부분 곡을 완주로 계산하지 않았다. 종료 원장의 새 `facing/middle_target/distal_target/rejected_target` 시간도 기록됐다. 실제 GPU에서 정상 후보와 거부 진단이 작동한다는 연결 검증이고, 새 기준의 성공률·기존 정책 대비 성능은 아직 평가하지 않았다. 재개 시 PPO 상태는 복원하지만 물리 장면·곡은 초기 자세에서 다시 시작한다.

이번 범위는 구현 연결 확인이며 장기 학습 성능이나 자연스러운 압현 자세의 입증이 아니다. 기존 native visual geometry 로드 경고는 남아 있으며 GPU 영상 렌더 검증은 수행하지 않았다. 기존 별도 `test_left_curriculum_runtime`의 GPU544/옛512 기대 불일치는 [v9 원문 보고](/home/ajou/yigyu/3/docs/2026-10-23/guitar_learning_wrist_region_v1/README.md)에 보존했고 이번 검사 수에 포함하지 않았다.
