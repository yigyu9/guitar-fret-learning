# 팔·손목 행동 변화 감점 v16

GPU 왼손의 작은 명령 변화에는 감점하지 않고, 왼손목3축의 계수를 팔의1/4로 낮췄다. 엄지를 포함한 손가락21축은 계속 직접 비용0이다. 사용자 승인에 따른 초기 설계값이며 실제 학습 성능이나 자연스러움 개선은 이번에 측정하지 않았다.

## 계산

~~~text
Δa_j = action_now_j − action_previous_j
e_j = max(abs(Δa_j) − 0.05, 0)
c_j = 0       : LH21(엄지 포함)
      0.0025  : L_Wrist_x/y/z
      0.01    : 나머지 축
R_action_change = −sum(c_j × e_j²) / 39 / 60
~~~

0.05는 정규화된 정책 명령 차이이며 각도·속도 또는 힘의 문턱이 아니다. 절댓값0.05까지0이고 바깥에서도 초과분만 제곱해 경계에서 점수가 뛰지 않는다.39분모를 유지해 팔의 기존 축당 계수0.01을 보존한다. 같은 명령 변화에서는 손목 감점이 팔의1/4다. 같은 명령을 반복하면0이고, LH21은 최대 크기 명령과 반전에도 직접 비용0이다.

예를 들어 한 팔 축의 명령이0→0.25로 바뀌면 e=0.20, 해당60Hz tick 감점은 약−1.7094e−7이다. 손목 한 축은 약−4.2735e−8이다. 이 항은 실제 관절이 움직인 양이나 속도·가속도의 측정값이 아니다.

첫tick은 기존처럼 previous_action=0을 기준으로 계산한다. H32 수집 경계에서는 이전 명령을 유지하고 에피소드 reset은 해당 행만0으로 만든다. 단계 가중치는 곱하지 않는다. GPU 오른손과 CPU 경로는 기존식을 유지한다. 비활성 오른손6축의 정책 명령은 기존 마스크로0이다.

## 유지한 범위와 계약

제어기·평활화·속도제한·실제 힘·관절 한계·초기035/v14·물리 실패/안전 cost를 바꾸지 않았다. v15 오압현/누락 정규화·최장clean 기반 미달성 감점·원인 진단, 기존 압현/유지/달성·B 약한 권고·손목영역·PPO도 그대로다.

전체 보상v16, 행동변화 계약 `gpu_action_change.v2`다. 관절별39개 계수와 순서·무감점 대역을 계약에 기록한다. surface_frettingv7/ledger6/event4와544상태/24열event/8우선slot/3331커리큘럼을 유지한다. 이전v15 이하 checkpoint는 strict resume를 거부하며 같은v16 전체 계약끼리 복원한다.
