# Learning to Play Guitar with Robotic Hands — 국문 상세 정리본

> **원문**: Chaoyi Luo, Pengbin Tang, Yuqi Ma, Dongjin Huang, *Computer Graphics Forum* 43(8), SCA 2024. DOI: 10.1111/cgf.15166
> **코드**: https://github.com/MRXuanL/GPS-GuitarPlaySimulation (로컬: `GPS/`)
> **문서 성격**: 저작권 관계로 축어역(문장 대 문장 전문 번역)이 아닌, 전 절의 기술 내용·수식·파라미터·실험 수치를 빠짐없이 담은 상세 정리본. `[역주]`는 우리 프로젝트/로컬 코드와의 대조 메모.

## 초록

기타 연주는 손가락 위치의 정밀성과 양손 협응 때문에 그래픽스·로보틱스 양쪽에서 어려운 과제다. 기존 방법은 모캡 데이터에 의존해 특정 연주 구간을 재현하는 수준이라 표현 범위가 제한되고 후처리가 번거롭다. 이 논문은 **모캡 데이터 없이, 입력 타블라처(tablature)만으로** 로봇 손이 기타를 연주하게 하는 강화학습 모델을 제안한다. 과제를 3단계로 분할한다:

- **(a) 운지 생성**: 입력 탭에 대해 사람의 연주 습관에 맞는 운지(fingering)를 생성
- **(b) 프레팅 제어**: 생성된 운지를 가이드로 왼손 손가락을 제어하는 신경망을 심층강화학습으로 훈련
- **(c) 탄현 모션**: 탭에 맞춰 오른손의 탄현(plucking) 동작을 역기구학(IK)으로 생성

평가는 precision / recall / F1 정량 지표와 사용자 연구(시각·청각 효과)로 수행했다. 중간 난이도 이하의 곡 대부분에서 거의 모든 노트를 정확히 연주했다.

## 1. 서론

- 사람 수준의 다지(多指) 손 기민성을 로봇 손으로 재현하는 것은 과제 이해→의사결정→정밀 실행 전 과정에 걸친 난제다. 물체 재파지, 손안 조작, 피아노 연주 등은 연구가 있었지만 기타 연주 시뮬레이션 연구는 극소수다.
- 전통적 접근은 실제 기타리스트의 모캡을 가상 캐릭터에 매핑하는 방식인데, 일반화가 안 되고 후처리가 많이 든다.
- 저자들은 **강화학습 + 역기구학** 기반의 새 모델을 제안하며, "타블라처 입력만으로 기타를 연주하는 로봇 손 제어"는 자신들이 아는 한 최초라고 주장한다 (외부 모션 데이터 불필요).
- 실황 연주 구성: **왼손**은 넥 위 줄을 눌러 음높이를 바꾸고, **오른손**은 줄을 튕겨 소리를 낸다. 해결할 과제 3가지: ① 각 노트에 올바른 손가락 배정, ② 배정된 손가락이 지정 프렛을 사람 수준 정밀도로 누르기, ③ 오른손 탄현을 탭과 정확히 동기화.
- 방법 요약: 목표 프렛에 가장 가까운 손가락을 고르는 **브루트포스 탐색**으로 운지 생성(복수 손가락이 필요하면 손 안쪽 손가락이 저음현, 바깥쪽 손가락이 고음현을 담당하도록 보정), 왼손 제어 정책은 **DroQ**(Dropout Q-Functions) 알고리즘으로 학습, 오른손은 손끝 궤적을 설계한 뒤 IK로 관절각 계산. 소리는 눌린 프렛·탄현 정보로 **Karplus-Strong** 알고리즘 합성. 평가는 precision/recall/F1 + 사용자 연구.

## 2. 관련 연구

### 2.1 인간 기민성 스킬 시뮬레이션

- **2.1.1 전통적 방법**: 모캡 기반 재현은 특정 구간에 묶여 유연성이 없다. 궤적 최적화는 고차원 공간에서 계산량이 커 실시간에 부적합. IK는 실시간성은 좋으나 자연스러움이 떨어진다.
- **2.1.2 모캡 기반 학습**: 모방학습으로 테니스(비디오 기반), 축구 저글링, 가구 상호작용(SAMP), 대규모 사전학습(ASE) 후 복잡 과제 적용, VAE 기반 다양한 행동 학습 등. 공통 한계는 데이터셋 범위 밖 일반화 부족.
- **2.1.3 데이터 독립적 방법**: 모캡의 근본 한계는 데이터 희소성. 사전 정의된 기준에 맞는 행동에 보상을 주는 RL로 로코모션, 젓가락 사용 등을 학습. 고난도 스킬은 **커리큘럼/다단계 학습**으로 해결(예: 바닥에서 일어나기의 3단계 RL). **기타 연주 데이터셋이 희소하므로 본 논문도 데이터 독립적 RL + 다단계 분할 학습을 채택**.

### 2.2 악기 연주 시뮬레이션

- 소리 합성 쪽 연구가 다수(가산/감산/FM 합성, 딥러닝 기반). 본 논문은 기타 음원으로 Karplus-Strong 사용.
- 모션 쪽은 피아노가 중심: IK로 손가락 궤적 계획, 피아노 전용 RL 환경(RoboPianist 계열) 등.
- 기타 모션은 기계 장치 연주, 모캡/IK 재현 정도. 대표 선행 연구 **Handrix (ElKoura & Singh, 2003)**: 손 모션 데이터셋 + K-최근접 이웃으로 손 자세를 재구성(IK의 부자연스러움 회피). 단, 데이터셋 보간 기반이라 데이터 밖 모션이 어렵고, 동역학 없이 운동학적으로만 손가락을 목표 위치로 이끈다.
- 본 논문은 (저자 주장으로는 최초로) **탭을 읽고, 학습 후, 사전 데이터셋 없이** 사실적이고 자연스러운 기타 연주를 하는 RL 모델.

## 3. 시스템 개요

입력 탭 → 자동 제어 전략 생성. 3개 컴포넌트(그림 1):

1. **운지 생성 (Fingering generation)**: 탭의 모든 노트에 손가락을 충돌 없이 배정. 한 손가락이 동시에 두 노트를 담당할 수 없음(바레 코드 제외). 단순하면서 사람 습관에 맞는 운지 지향.
2. **프레팅 제어 (Fretting control)**: 운지 확정 후, 왼손이 해당 프렛에 빠르고 정확하게 도달·압현하도록 RL로 제어.
3. **탄현 모션 계획 (Plucking motion planning)**: 오른손 손끝의 탄현 궤적을 먼저 설계하고, 궤적을 따라가는 관절각을 IK로 계산.

## 4. 운지 생성

해결할 3가지 문제: (1) 한 손가락이 동시에 두 노트를 연주할 수 없음, (2) 에너지 최소화 — 손가락이 목표 프렛까지 이동하는 거리 최소화, (3) 사람의 연주 습관에 부합.

**알고리즘**:
- 노트를 시작 시각 순으로 정렬 후 순차 배정. 각 손가락은 "마지막 사용 시각"을 가지며, 노트 시작 시각이 어떤 손가락의 마지막 사용 시각보다 이르면 그 손가락은 아직 점유 중 → 다른 손가락 선택. 배정되면 마지막 사용 시각을 `노트 시작 + 지속시간`으로 갱신.
- **파지 포지션(hold position) P**를 실시간 추적: 왼손 **검지가 놓인 지판 위치**. 검지·중지·약지·소지(i=1,2,3,4)의 기준 위치를 각각 P, P+1, P+2, P+3으로 두고, 목표 프렛 P_t에 대해 **argmin_i |P_i − P_t|** 로 가장 가까운 손가락을 브루트포스 선택.
- **사람 습관 보정**: 같은 프렛에 여러 노트가 동시에 오면(그림 2의 G 코드·A 코드 예), 저음현(6번 줄 쪽)에는 앞 손가락, 고음현(1번 줄 쪽)에는 뒷 손가락을 배정. 예: G 코드에서 6번 줄 3프렛=약지, 1번 줄 3프렛=소지 (반대로 하지 않음); A 코드에서 4·3·2번 줄=검지·중지·약지. 가용 손가락을 정렬한 뒤 이 선호에 따라 배정.
- 이렇게 배정된 운지가 RL 학습의 훈련 데이터(목표)가 된다.

`[역주]` 로컬 코드 `GPS/guitarplay/music/tablature.py`의 `arrangeFinger()`가 이 절의 구현. 손가락 부족 시 노트를 버리고 `arrange.txt`에 기록하는 처리는 논문에 없는 구현 디테일.

## 5. 프레팅 제어

운지로 손가락의 목표 위치는 알지만, 관절 회전·왼손 이동을 포함한 실제 손가락 움직임의 조율이 문제 → RL로 프레팅 전략 학습.

**환경 설정**: 모든 줄의 모든 프렛에 **터치 센서** 부착(그림 3). 센서 힘이 임계값을 넘으면 그 프렛은 "눌림" 상태로 판정.

**보상 함수** — 3개 항으로 구성:

**(1) Finger reward** — 손가락을 목표 프렛으로 유도:

```
r_finger = (r_x + r_y + r_z) / 3                     (식 1)
  r_x = g(|f_x − k_x|, 0.5·L_key, 0.1)
  r_y = g(|f_y − k_y|, 0.001, 0.1)
  r_z = g(|f_z − k_z|, 0.001, 0.1)
```

- (f_x, f_y, f_z) = 손끝 위치, (k_x, k_y, k_z) = 프렛 중심 위치, L_key = 목표 프렛의 길이.
- g(x, bound, margin)은 dm_control의 매핑 함수(그림 4): x ∈ [0, bound]에서 최대(1), x = bound+margin에서 0.1로 감소.
- **유클리드 거리를 쓰지 않고 축별로 분해**한 이유: 프렛에는 지정 압현 영역이 있어 그 영역 안이면 어디든 성공이므로, 프렛 길이 방향(x)은 0.5·L_key까지 관대하게, 수직 방향(y·z)은 0.001로 엄격하게 → 목표 프렛을 더 효율적으로 찾음.

**(2) Key reward** — 올바른 프렛의 압력 유지 + 오누름 벌점:

```
r_key = 0.5·( (1/K) Σᵢᴷ g(|ksᵢ − 1|, 0, 1) ) + 0.5·(1 − 𝟙{false positive})     (식 2)
```

- K = 현재 눌러야 할 프렛 수, ks = 프렛에 가해진 정규화된 힘, 𝟙{false positive} = 금지된 프렛이 하나라도 눌리면 1.
- 소리는 오른손이 튕겨야만 나므로, **튕기지 않는 줄의 프렛은 눌러도 무방**하다는 점을 명시.

**(3) Energy reward** — 불필요한 토크·이동 억제:

```
r_energy = −k · |τ_joints|ᵀ |v_joints|                (식 3)
```

- τ_joints = 관절 토크 벡터, v_joints = 관절 속도 벡터, |·| = 원소별 절댓값, k = 0.0025.
- 왼손이 누를 프렛이 없는 구간에는 k를 0.005로 올림 (오른손이 개방현만 튕길 때 왼손이 쓸데없이 움직이는 것을 방지, 더 안정적인 압현 유도).

**최종 보상**:

```
r = 0.5·r_key + 0.5·r_finger + r_energy              (식 4)
```

## 6. 탄현 모션 계획

- 양손 협응: 왼손이 누르고 오른손이 튕긴다. 전형적 주법에 따라 **엄지 → 4·5·6번 줄, 검지·중지·약지 → 3·2·1번 줄** 배정.
- 실제 기타리스트 관찰: 검지·중지·약지의 손끝 탄현 궤적은 **타원**에 가깝고, 엄지는 **직선**에 가까움 → 탄현 모션이 비교적 일정하므로 정밀 궤적 계획 채택.
- 엄지: 현재 엄지 끝 위치에서 목표 탄현점까지 직선 궤적.
- 나머지 손가락: 원점 기준 타원 궤적 **p = (0, a·cosθ, b·sinθ)**, 계수 a = 0.005, b = 0.0025. 강체 변환 **p′ = T + R·p** 로 목표 줄의 탄현점 site_i를 지나도록 배치하며, 다른 줄과의 충돌을 피하도록 손을 적절히 기울임(그림 5):
  - T = site_i + (0, 4.33×10⁻³, −2.5×10⁻³)
  - R = R_z(−π/2) · R_y(−π/9) · R_x(π/9)
- 궤적 확정 후 **IK로 각 손가락 관절각 계산**.

`[역주]` 로컬 코드에서는 `_create_trajactory()`가 이 절의 구현이며, 학습이 아니라 테스트 시에만 구동된다. 오른손은 RL이 아님.

## 7. 실험 설정과 결과

### 7.1 실험 설정

**타블라처 데이터셋**: 노트(지속시간, 시작 시각, 프렛 위치, 사용 손가락)의 리스트로 구성된 'Tablature' 클래스. 8곡으로 평가:
- 다성(polyphonic) 스킬 검증: *Chord Transition*
- 단선율(monophonic) 연습: *Scales Practice*
- 중간 난이도 단선율: *Twinkle Twinkle Little Star*, *Für Elise*, *Long Long Ago*
- 다성 곡: *Farewell*, *Happy Birthday*, *Red River Valley*

- **String state**는 현재 목표뿐 아니라 **앞으로 n틱의 목표까지 포함**(lookahead). n은 `n_step_lookahead` 파라미터로, 로봇 손이 미리 대비하게 하는 장치.
- String state는 두 형태 제공: 키별 0/1 (120차원) vs **줄별 목표 프렛만 표시하는 단순화 버전(6차원)**.

- 행동은 MuJoCo의 **position servo**로 관절 목표각을 실시간 제어.

`[역주]` 표 1의 obs 직전 행동 크기 24는 state의 20과 불일치 — 로컬 gym 래퍼 코드는 action(20)+reward(1)를 `last_state`로 사용한다. 실제 학습에 쓰인 관측 조합은 `guitar_gym_env.py`의 `sequece` = goal + last_state + 기타 키 상태 + 왼손 관절각.

**환경 래핑과 학습**: gymnasium 표준으로 래핑. 알고리즘은 **sbx**(JAX 기반 stable-baselines3) 라이브러리의 **DroQ** — SAC의 개선판으로 샘플링 효율이 높음.

**사운드 생성**: 줄마다 PyAudio 스트림을 바인딩. 오른손 손끝이 탄현점에 접근하면, 해당 줄에서 **눌린 최고 프렛**으로 음높이를 결정(실제 기타 발음 원리)하고 Karplus-Strong으로 합성해 재생.

**평가 지표**: precision(누른 프렛 중 정답 비율), recall(눌러야 할 프렛 중 실제로 누른 비율), F1 = 2·P·R/(P+R). **피아노와 달리, 튕기지 않는 줄의 프렛을 잘못 눌러도 연주에는 영향이 없으므로 recall이 높을수록 실제 연주 품질이 좋다고 볼 수 있음**.

**freedom 파라미터** (중요 강조 항목): 기타 음향 원리상 소리는 **그 줄에서 가장 높은 눌린 프렛**에만 의존하고, 더 낮은(너트 쪽) 프렛이 같이 눌려 있어도 무관하다.
- `False`: 지정된 프렛만 누를 수 있음(피아노식). precision↑, recall↓ 가능.
- `True`: 목표보다 낮은 프렛은 눌러도 허용, 높은 프렛만 금지(key reward의 금지 프렛 벌점으로 구현). 손의 자유도↑, recall↑, precision은 다소 하락 가능. 그림 6이 G 코드 기준 허용(초록)/금지(빨강) 영역 시각화.

## 8. 어블레이션과 비교

- **매핑 함수** (그림 13): 보상 매핑으로 gaussian 대신 **reciprocal**을 선택. 기타는 미세한 손가락 이동으로도 프렛을 놓치므로 **목표 근방에서 보상 변화에 민감한** reciprocal이 유리 — *Little Star* 학습에서 수렴 속도와 최종 성능 모두 우위.
- **Finger reward 설계** (그림 14): 유클리드 거리 기반 보상은 F1이 0.6에 정체되고 수렴이 매우 느림. 5절의 **축별 분해 + 프렛 내부 어디서든 만점** 방식(프렛 중심 강제 X)으로 바꾸면 수렴 속도·성능 모두 크게 개선.
- **Freedom** (그림 15, *Für Elise*, buffer 1e7): `True`로 하면 **recall이 크게 상승**(≈0.58 → ≈0.9)해 곡의 완성도(음 누락 감소)가 크게 개선. precision은 하락(≈0.93 → ≈0.5)하지만, 소리는 최고 프렛에만 의존하므로 **청감상 영향은 미미**.
- **프레임률** (그림 16, 10/20/30fps): 높을수록 제어 기회가 많아져 성능 향상. 단, 과도하게 높이면 학습 불안정이 나타날 수 있음.
- **Discount** (그림 17, *Happy Birthday*, γ ∈ {0.84, 0.90, 0.96, 0.99}): 처음엔 0.99를 썼으나 **0.84로 낮추자 뚜렷한 개선** — 기존 실험 곡 거의 전부 recall 0.85 이상 달성, 수렴도 빨라짐. 해석: 손 움직임은 **현재 노트의 보상에 지배**되고 후속 노트에 미치는 영향이 작아, 높은 discount가 불필요.
- **다곡 검증** (그림 18): 온라인에서 수집한 MusicXML 곡들을 γ=0.84로 학습. **대부분의 곡이 recall 0.7 이상** = 청중이 곡을 알아들을 수 있는 수준. (수록곡: Little Star, Red River Valley, Long Long Ago, Für Elise, Scale Practice, Happy Birthday, Chord Transition, Big Fish, Town, Auld Lang Syne, the Rebel Army, Fantastic, Moon River, Melody of Life, Answer, Farewell, Secret Base, Wind Song, Castle in the Sky, to Zanarkand — recall 상위부터 정렬, 최저는 to Zanarkand ≈0.45)

## 9. 결론 및 논의

**요약**: 탭 입력만으로 ① 브루트포스 운지 생성 → ② 보상 설계 기반 RL로 왼손 프레팅 학습 → ③ 경로 계획 + IK로 오른손 탄현 생성. 단순 단선율·다성 곡에서 우수한 성능, 복잡한 곡 대부분도 recall 0.7 이상으로 청중이 인식 가능.

**한계와 향후 과제**:

1. **선행적 운지 전략 부재**: 사람은 연주 중 다음 노트를 예측해 미리 프렛 위치를 준비하지만 모델은 이를 재현하지 못함.
2. **왼손 엄지 미모델링**: 사람은 넥 뒤를 엄지로 받쳐 기타 밀림을 방지하지만, 시뮬레이션의 기타는 공간에 고정돼 있어 엄지의 역할이 없음. 학습 방해(충돌)를 피하려고 엄지를 부동 상태로 고정.
3. **관절 가동범위와 행동 공간의 트레이드오프**: 가동범위를 늘리면 더 다양한 손 모양과 도달 불가능하던 프렛 커버가 가능해지지만 행동 공간이 커져 학습이 어려워짐 — 반복 조정으로 최적 범위를 찾았고, 이 균형이 중요.
4. **단일 곡 학습**: 현재는 곡마다 학습하며 비슷한 템포의 곡에만 전이됨. 다양한 장르의 대규모 곡 데이터셋 구축이 향후 과제.
5. **초보자 주법 한정**: 왼손은 기본 프레팅만 (바레 코드, 해머온, 풀오프, 슬라이드 미지원), 오른손은 엄지=6·5·4번 줄, 검지·중지·약지=3·2·1번 줄의 고정 배정 (하모닉스, 태핑, 뮤팅, 스트러밍 미지원).
6. 다양한 주법의 진정한 재현에는 **보상 함수만으로는 부족** — 특수 주법의 모캡 수집 + 모방학습 결합이 향후 방향.
7. 운지 생성·프레팅 제어는 기타 특화지만, **기저 보상 프레임워크는 다른 손가락 제어 과제로 일반화 가능**.

## 부록 A: 기타 연주 용어

- **발음 원리**: 기타는 줄의 진동으로 소리를 낸다. 왼손이 지판 위 줄을 누르는 위치가 **프렛**이며, 누르면 진동하는 줄 길이가 짧아져 음높이가 올라간다. 오른손이 줄을 튕기거나(pluck) 긁어(strum) 진동을 일으킨다.
- **단선율(monophonic) 곡**: 한 번에 한 노트(왼손이 프렛 하나만 누름). 멜로디/솔로 라인.
- **다성(polyphonic) 곡**: 여러 노트 동시 연주(왼손이 여러 프렛을 동시에 누름). 화성을 만들며 리듬 기타의 기본. 단선율보다 훨씬 어렵다.
