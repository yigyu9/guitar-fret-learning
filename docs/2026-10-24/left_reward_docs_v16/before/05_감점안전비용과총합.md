## 5.1 잘못 누름·누락·놓친 음

GPU왼손v15는진단초단위시간을보존하면서보상만음길이와손가락으로정규화한다. D=end−onset>0, b=M/(등장손가락수×해당손가락음수)이며3장의양성계수와같다.

~~~text
wrong_dt = audible_dt × .5 × (wrong_previous + wrong_now)
missing_dt = audible_dt × .5 × (
    (NOT candidate_previous AND NOT wrong_previous)
  + (NOT candidate_now AND NOT wrong_now))
best_clean_streak = max(previous_best, current_audible_clean_streak)
deficit = 1 − min(best_clean_streak/required_clean, 1)

song_wrong_press   += −sum(b * wrong_dt / D)
song_missing_press += −.5 * sum(b * missing_dt / D)
song_left_missed   += −.5 * sum(new_missed * b * deficit)
~~~

missing은각끝점에서후보도wrong도아닌상태다. wrong과missing은각끝점에서배타적이지만clean은두끝점AND로적분하므로세시간합이항상정확한분할은아니다. wrong/missing진단은기존처럼**초**로누적하고벌점만D로나눈다. 준비창의wrong/missing감점은추가하지않는다.

`best_clean_streak`는onset~end의최장연속clean시간으로끊겨도최고값을남긴다. 누적clean이아니다. missed는음이끝나고left가한번도참이되지않았을때한번발생하지만감점크기는부족률deficit에비례한다. 이진 `left_missed`음수・left달성문턱・보너스의한번지급은그대로다. 달성이후떨어져도wrong/missing은남는다.

예를들어required400ms에서최장399ms면deficit=.0025,원시미달성은−.00125b다. 최장0이면−.5b,문턱을채웠으면left가참이므로missed를지급하지않는다. 200ms→끊김→199ms는누적399ms여도best200ms로deficit.5・원시−.25b다.

## 5.2 감점계수는기존표를유지하고단위만바꾼다

세감점은 LegacyCurriculumState.weights에서같은progress의계수표만재사용한다. GPU에CPU8곡단계전환기를적용하는것은아니다.

| 감점 | 그룹 | progress0 | progress1 | progress2 |
| --- | --- | ---: | ---: | ---: |
| wrong_press | contact | .15 | 1 | 1 |
| missing_press | timing | .10 | .35 | 1 |
| left_missed | timing | .10 | .35 | 1 |

다음은**b=1인한음전체**의예이며초당값이아니다. 길이0.1초음과1초음이각각전체wrong이면같은총감점을받고음중일부wrong이면wrong시간/D비율로계산한다.

| 경우 | 단계0 | 단계1 | 단계2 |
| --- | ---: | ---: | ---: |
| 한음전체wrong | −.15 | −1 | −1 |
| 한음전체missing | −.05 | −.175 | −.5 |
| best0인미달성음1개 | −.05 | −.175 | −.5 |
| required400ms중best399ms미달성 | −.000125 | −.0004375 | −.00125 |

손가락b가다르면위값에b를곱하고중간progress는기존선형보간한다. 각손가락의전체음에대한b합은같으므로음수항에도기회균형을적용하지만실제성과균형이나향상을보장하지않는다. 원인・몸체별진단시간은겹칠수있어합쳐벌점을주지않으며기존target별wrong한번에만b/D를적용한다.

## 5.3 행동 변화: action_change.v2

GPU왼손v16만다음식을사용한다. a는정규화된정책명령이며실제관절각/속도가아니다.

~~~text
Δa_j = a_now,j − a_previous,j
e_j = max(abs(Δa_j) − .05, 0)
c_j = 0       : 엄지포함LH21
      .0025/s : L_Wrist_xyz
      .01/s   : 나머지비손가락축
R_action = −sum_39(c_j * e_j²) / 39 / 60
~~~

**|Δa|≤.05는경계포함무감점**이다. .05는각도/속도문턱・action자체의크기제한・제어deadzone이아니다. 초과분만제곱하므로경계에서감점이연속으로시작하며같은초과변화의손목계수는팔의1/4이다. 손가락LH21은변화크기와관계없이직접계수0이다. 큰명령을일정하게유지할때도Δa=0이면이항은0이며안전종료・접촉/연주보상은별도로남는다.

기존팔의.01/초계수와39분모를유지한다. 60Hz경계에서한번계산하고단계가중치를곱하지않는다. 비활성오른손6축은0이지만39분모에남는다. **첫tick도previous_action=0으로계산**하며H32경계에서previous를지우지않고종료환경선택reset행만0으로복원한다.

실제motion・힘・제어기평활화/속도제한・035/v14초기화・PPO는변경하지않는다. GPU오른손/CPU는기존식을유지하며v16무감점대역과손목계수를자동상속하지않는다. 손가락추종의요청명령/실제속도비용0도유지한다. 이번GPU/native・학습및감점유무비교학습은수행하지않았으므로성능・자연스러움효과는미확인이다.

## 5.4 물리 실패 tick의 보상

한 tick의 물리 4표본 중 실패 사유가 하나라도 잡히면 failed=True다.

- 기본 연주 항은 해당 tick의 양수 부분을 0으로 제한한다. 음수 접근 potential·wrong/missing/missed는 남는다.
- 손가락 추종·관절 분담·대기 자세의 양성 항은 0으로 한다.
- 행동 변화 감점은 계산한다.
- terminal_failure로 −2를 한 번 더한다.
- 안전 cost도 별도로 더한다.

정상적인 곡 종료에는 −2 실패 감점을 적용하지 않는다. 곡이 끝났다는 이유로 새 전곡 성공 보너스를 별도 추가하는 코드도 없다. 종료 자체와 음별 달성 보상을 구분한다.

## 5.5 안전 cost는 별도 신호다

매 240Hz 표본에서 초기 기준에 대한 이동·회전과 지지 상태로 비음수 rate를 계산한다.

~~~text
g_d = 기타 위치 변위 크기
g_a = 기타 회전 오차 크기
f_L, f_R = 양 발 위치 변위 크기
S = 기타 근처 Chest/R_Shoulder/R_Hip 중 하중이 확인된 지지 존재
G_L, G_R = 양쪽 발/발목 계열 하중 플래그

cost_rate =
    (g_d/0.02)²
  + (g_a/0.15)²
  + mean((f_L/0.02)², (f_R/0.02)²)
  + [NOT S]
  + mean([NOT G_L], [NOT G_R])
cost_running += cost_rate / 240
~~~

지지 플래그도 몸체 하중 기반 근사다. 기타 지지는 몸체가 기타 원점 0.5m 이내인지 추가 확인하지만 접촉 상대쌍을 인증하지는 않는다. 가슴 접촉만을 필수로 요구하는 규칙은 아니다.

cost의 의미는 “이미 reward에서 뺀 값”이 아니다. 환경은 reward와 cost를 따로 반환한다. PPO가 두 advantage를 결합하는 방식은 7장에 설명한다.

## 5.6 물리 실패 조건과 일회성 cost

| 사유 | 문턱 |
| --- | --- |
| 기타 이동 | 8cm 초과 |
| 기타 회전 | 0.35rad 초과 |
| 발 위치 변위 | 어느 한 발 4cm 초과 |
| 기타 지지 상실 | 0.25초 초과 |
| 발/발목 하중 상실 | 어느 쪽 0.25초 초과 |
| 관절 속도 | 어느 축 절댓값 50rad/s 초과 |
| support_control_invalid | 유한하게 확인된 지지 기하에서 제어 방향을 정의할 수 없는 경우 |

실패 시 running cost 외에 다음을 한 번 추가한다.

~~~text
C_fail = 5 + 5 × max(곡 길이 − 실제 실패 tick 종료 시각, 0)
~~~

예를 들어 곡 길이 32.8167초이고 tick 종료가 10초라면 추가 cost는 약 119.0833이다. 같은 tick에 reward −2도 따로 있다.

남은 시간의 초당 5는 측정한 미래 비용의 정답이 아니라 고정률 absorbing-failure 모델이다. 빨리 실패해 이후 위험 노출을 피하는 경향을 줄이려는 설계다. 단계 가중치로 낮추지 않는다. 현재 성능에서 이 크기가 적절한지는 별도 비교가 필요하다.

## 5.7 v16 왼손 총 reward: 13슬롯, coordination상시0

| 항 이름 | 원시 항 | 최종 그룹 |
| --- | --- | --- |
| song_wrist_position | 영역 안0·밖 음수 rate를 전240Hz 적분 | GPU wrist |
| song_left_approach | γΦ_next−Φ_now | GPU approach |
| song_left_contact | 연속 min(50ms,e−p) 최초충족0.5b/음 | GPU contact |
| song_clean_hold | 2b×clean 증가/음 길이 | GPU timing |
| song_left_success | 연속clean문턱 최초달성0.5b/음 | GPU timing |
| song_finger_tracking | 손가락 추종 rate 적분 | GPU approach |
| song_finger_coordination | 항상0(로그슬롯유지) | GPU approach |
| song_finger_standby | 준비/접촉/4cm근접제외B권고≤.01/s적분 | GPU approach |
| song_wrong_press | −sum(b*wrong_dt/D) | 기존 contact |
| song_missing_press | −.5sum(b*missing_dt/D) | 기존 timing |
| song_left_missed | −.5sum(new_missed*b*최장streak부족률) | 기존 timing |
| action_change | −sum(c*relu(abs(Δa)−.05)²)/39/60・LH21 0/손목.0025/기타.01 | 가중치 없이 |
| terminal_failure | 실패 시 −2 | 가중치 없이 |

~~~text
R =
  w_wrist × R_wrist
+ w_approach × (R_potential + R_tracking + R_coordination + R_standby)
+ w_contact × R_first_contact
+ w_timing × (R_hold + R_achievement)
+ l_contact × R_wrong
+ l_timing × (R_missing + R_missed)
+ R_action + R_terminal
~~~

w는 GPU 그룹 계수 표(손목 항은 음수/0), l은 기존 감점 표의 같은 progress 계수다. w_approach는 항상 1이다. 별도 cost는 이 합에 포함되지 않는다.

공용 환경은 오른손 타현 사건도 측정하고 song_right_success 등의 항을 만들지만, 왼손 최종 reward 합산표에는 넣지 않는다. 오른손 진단이 존재한다는 이유로 양손 보상을 동시에 학습한다고 설명하면 부정확하다.

실제 reward_components와 reward_component_means 딕셔너리에는 공용 LEFT_TERMS의 **18개 키**가 있다. 왼손 합산에서 제외한 오른손용 5개 키(song_right_success, song_right_missed, song_wrong_crossing, song_repeat_crossing, song_right_progress)는 이 component 로그에서 0으로 남는다. 최종합산13슬롯중coordination은상시0이고,공용로그18키와구분한다.
