# 6. 학습 단계와 가중치

[전체 목차](/home/ajou/yigyu/3/docs/2026-10-26/왼손보상구조/README.md)

## 6.1 단계는 다른 환경으로 바꾸는 스위치가 아니다

progress는 0~2의 값이다. 단계 0부터 같은 곡의 67음과 같은 물리 조건을 진행한다. 음 길이·성공 문턱·제어·관절 가동범위를 단계마다 바꾸지 않는다.

바뀌는 것은 주로 보상 그룹의 비중과 기존 감점의 보간 계수다. 관측에도 progress와 일부 가중치가 들어간다. “접근이 끝날 때까지 압현을 시도할 수 없다”거나 “접촉 단계에서는 곡의 뒷부분을 실행하지 않는다”는 구조는 아니다.

## 6.2 GPU 그룹 가중치 표

| 그룹 | progress 0 | progress 1 | progress 2 |
| --- | ---: | ---: | ---: |
| wrist | 0.20 | 0.10 | 0.05 |
| contact | 0.50 | 1.00 | 1.00 |
| timing | 0.50 | 1.00 | 2.00 |
| approach | 1.00 | 1.00 | 1.00 |

progress 0.5이면 wrist=0.15, contact=0.75, timing=0.75다. progress 1.5이면 wrist=0.075, contact=1, timing=1.5다.

단계 이름은 0≤progress<1에서 surface_approach, 1≤progress<2에서 contact, progress=2에서 hold_transition이다. 이름은 설명용이며 항의 on/off를 뜻하지 않는다.

## 6.3 단계 0: 표면 접근을 확보하는 동안

손목 영역 감점은 안·경계0, 밖에서 초당 −0.2에 점근하며, 표면 potential과 추종·자세는 가중치 1, 최초 접촉은 원시값의 절반, 유지·음별 달성도 원시값의 절반이다. 감점은 기존 표의 contact=0.15, timing=0.10이다.

접촉·유지·성공을 막지는 않지만, 추종이나허용대기구간의B권고처럼연속률로얻는항과 사건 보상의 상대적 크기가 이후 단계와 다르다. 어떤 보상이 실제 수집에서 주도하는지는 항별 누적 로그가 필요하다.

## 6.4 0→1 진급 조건

최근 **256개 종료 에피소드**를 보관한다. 충분히 쌓인 후:

1. 최근 안전한 전체 시간축 완주 비율이 90% 이상이다.
2. 곡에 등장하는 **모든 손가락 각각**의 near_fraction 평균이 20% 이상이다.
3. 이번 committed PPO 수집에서 새 안전 완주가 하나 이상 들어왔다.

조건을 만족하면 한 번의 observe에서 progress를 최대 0.1만 올리고 1을 넘기지 않는다. 256곡이 들어왔다고 곧바로 0→1로 뛰는 것은 아니다.

near_fraction은 해당 손가락의 음 중 near_done인 비율이다. near_done은 해당 음의 준비~끝 창에서 10mm 이내 누적 100ms를 채운 상태다. 손목 ready 비율이나 전체 음 평균 20%가 아니다.

중지·소지 중 하나라도 문턱 미달이면 다른 손가락이 높아도 진급하지 않는다. 이전 v8 2,000회 전체에서 progress는 0이었다. 최고 1,500회 고정 평가의 검지 near 0%, 중지 near 약 0.056%로 진급 조건을 충족하지 못했다. 단계 0에서도 압현 보상은 작동한다.

## 6.5 단계 1과 1→2 진급

progress가 1이 되면 같은 256개 종료곡 창에서 **손가락별 contact_fraction 평균 20%**를 사용한다. 안전 90%와 새 안전 완주 조건은 유지한다. contact_fraction은 각 손가락에 배정된 음의 contact_done 비율이다.

코드에서 1 이상이면 gate 지표가 near에서 contact로 바뀐다. near≥20%를 동시에 다시 요구하는 AND 조건은 없다. contact 문턱을 만족하면 최대 0.1씩 2까지 올린다.

contact_done은 v11에서 press~end의 연속최초접촉 충족이므로, 1→2는 “모든 손가락이 audible clean 40%를 달성했다”는 증명이 아니다. success_fraction도 저장하지만 현재 진급 gate에는 사용하지 않는다.

## 6.6 단계 2: 유지·전환 비중

timing 가중치는 2로 올라가고 wrist는 0.05로 내려간다. contact는 1, approach와 추종·자세는 1이다. 따라서 손목 영역 밖 벌점은 약해지고 실제 audible 유지와 음별 달성의 상대적 비중은 커진다.

현재 v16에서 “전환”은 다음 음의 준비·접촉·유지 보상과 기존 입력을 통해 간접적으로 학습되는 부분을 포함한다. 이전 음의 명시 해제시각에 직접 연결된 별도 해제 비용은 없다. 그 비용은 별도 v7 실험에만 있으며 현재 v16에 통합되지 않았다.

## 6.7 실패곡과 부분 수집의 취급

안전 완주하지 못한 종료곡은 접근·접촉·성공률을 모두 0으로 저장한다. 종료 전 일부 음을 잘 수행했어도 gate 창에는 0행이다. 실패곡을 분모에서 제거하지 않는다.

H32 중간에 아직 끝나지 않은 곡은 gate 창에 들어가지 않는다. 독립 환경 1024개가 비슷한 상태에서 함께 끝나면 종료곡 창은 빠르게 채워질 수 있다. 256개는 독립 seed 256개나 서로 다른 곡 256개를 뜻하지 않는다.

progress는 조건이 나빠져도 감소하지 않는다. 매번 조건을 확인해 상승을 멈출 수는 있지만 강등 로직은 없다. 성능 보존을 보장하는 별도 손가락별 회상 학습 장치라고 해석하면 안 된다.

## 6.8 언제 가중치를 갱신하는가

수집 → PPO 갱신 성공 → journal 반영 확정 → curriculum.advance 순서다. 실패한 PPO 반영을 진급의 근거로 삼지 않는다.

가중치가 바뀌면 현재 살아 있는 환경의 다음 관측을 다시 만든다. 곡 중간이라도 다음 수집부터 새 progress를 사용할 수 있고, 물리 장면·곡 시계를 새로 시작하지 않는다. 따라서 한 에피소드의 reward_components에는 여러 progress에서 받은 값이 섞일 수 있다.

단계 이력은 progress/count/cursor 3개 + 256×13행 = 3331개의 값으로 checkpoint에 보관한다. CPU의 8곡/27값 이력과 다르다.
