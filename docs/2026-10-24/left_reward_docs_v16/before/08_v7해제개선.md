## 8.2 왜 v6 released를 그대로 보상하지 않았는가

v6 released는 음 끝 뒤 후보가 참→거짓으로 바뀌었는지다. 후보가 거짓이 되는 이유에는 손가락 이동뿐 아니라 하중 소실·다른 높은 프렛 접촉 등이 있다. 따라서 이 기록에 바로 보너스를 주면 실제 이전 위치에서 벗어나지 않아도 점수를 얻을 수 있다.

또 end는 sustain과 명시 release 중 이른 값이다. 무조건 end부터 손을 들도록 요구하면 원래 계획된 유지·반복과 상충할 수 있다.

v7은 **명시 release 시각과 필요 전환**을 별도 일정으로 만들고, 하중·wrong 배제 이전의 지정 손가락 기하가 남았는지를 본다.

## 8.3 어떤 음에만 적용하는가

아래 조건을 만족하는 경우에만 release 창을 만든다.

1. 원자료에 유한한 명시 source_release_s가 있다.
2. 같은 손가락의 다음으로 늦은 onset 묶음이 하나의 명확한 후속 목표다.
3. 후속 목표의 현·프렛이 이전과 다르다.
4. 서로 다른 운지의 sustain이 겹치지 않는다.
5. 같은 위치를 유지해야 할 다른 목표의 press~end와 해제 창이 겹치지 않는다.
6. 해제 창 시작 전에 후속 음이 이미 끝나지 않았다.
7. 현재 음의 동시 동일 손가락 배정이나 동시 후속 목표 묶음처럼 선택이 모호한 경우가 아니다.

해제 정보 누락은 end로 추정해 채우지 않고 적용 제외한다. 음 끝보다 앞선 명시 해제 등 잘못된 시간은 입력 오류로 거부한다. 같은 위치 반복·후속음 없는 마지막 음은 제외한다.

## 8.4 비용 공식

~~~text
r = 명시 source_release_s + 정책 pre-roll
deadline = min(r + 0.1초, 후속 음 end)
engaged = 그 음의 audible clean 누적시간 > 0
geometry = 원래 현/프렛 위치에 지정 손가락의 기하가 아직 있음

delay_dt = 실제 물리 구간과 [r,deadline]의 겹친 초 × engaged × geometry
song_release_delay += −0.5 × Σ delay_dt
~~~

같은 손가락에 창이 여러 개 겹치면 활성 창 중 가장 이른 마감 하나만 고른다. 후보 무효화나 하중 소실만으로 geometry를 거짓으로 바꾸지 않는다. endpoint의 기하로 해당 짧은 구간의 잔류를 평가한다.

한 번도 audible clean을 얻지 못한 음은 이 추가 비용의 대상이 아니다. 손가락이 벗어났다고 일회성 양성 보너스를 지급하지 않는다. 명시 해제 이전에는 비용이 없다. 에피소드 안에서 음 하나당 최대 비용은 0.05다. **에피소드 전체 비용의 최대가 0.05라는 뜻은 아니다.**

이 항은 curriculum 계수로 약화하지 않는 **음수 reward component**다. 별도 safety cost를 늘리는 방식이 아니다. 실패 tick에도 음수 항은 유지한다.

## 8.5 입력도 함께 바뀐다

기존 상태 544의 끝에 손가락별 6개, 총 24열을 덧붙인다.

| 필드 | 의미 |
| --- | --- |
| string | 해제 대상 현, 0은 무효 |
| fret | 해제 대상 프렛 |
| until_release_s | 명시 해제 시작까지 남은 시간 |
| until_deadline_s | 창 끝까지 남은 시간 |
| engaged_in_note | 원래 audible clean을 얻은 적이 있는가 |
| old_geometry_now | 이전 위치의 지정 손가락 기하가 남았는가 |

이미 활성화된 창을 우선하고, 없으면 2초 이내 시작할 창을 제공한다. 대상이 없으면 모두 0이다. 기존 544열과 8×24 우선 토큰은 보존하지만 전체 상태는 568이다.

보상 v7·관측 568은 기존 v6·544 checkpoint로 strict resume할 수 없다. 자동 Actor 이전도 하지 않는다. 관측과 보상을 함께 바꾸었으므로 향후 차이를 “비용 항 하나만의 효과”로 단정할 수 없다.

## 8.6 확인된 범위와 남은 불확실성

기본 67음의 정적 일정에서는 36개에 적용 가능하고 같은 위치 반복 27개·후속음 없음 4개는 제외된다. 적용 가능 수는 검지 13/25, 중지 8/18, 약지 6/12, 소지 9/12다. 실제 이 음들이 잔류했다거나 비용을 받았다는 관측 결과는 아니다.

별도 구현의 CPU 검사 107개와 독립 검수 기록이 있다. 모의 물리 입력으로 실제 tensor 환경·정책·CPU PPO 연결을 검사했다. GPU/IsaacGym/렌더링·장기 학습·실제 성능 비교는 하지 않았다. CPU adapter의 경로 격리 검사가 실제 native GPU 런타임 이식을 완료했다는 뜻도 아니다.

기하에서 벗어났다는 것은 실제 현 압력·접촉쌍·음향 해제 인증이 아니다. 실제 비교에서는 다음을 함께 확인해야 한다.

- 원래 음의 clean 유지시간과 달성률이 보존되는가
- 해제 기하 잔류시간·비용이 줄어드는가
- 같은 손가락 다음 음의 준비·접촉·적시 달성이 개선되는가
- 과도하게 들기·조기 해제·안전 비용이 늘지 않는가
- 실제 GPU 연산 시간·메모리 영향이 허용 가능한가

현재 v6에서 해제 지연이 주요 병목이라고 확정한 것은 아니다. 선택한 가설을 작은 별도 버전으로 평가할 수 있도록 만든 구현이다.
