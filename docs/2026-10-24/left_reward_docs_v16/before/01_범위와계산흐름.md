## 1.1 어떤 왼손을 설명하는가

기본 진입점 guitar_learning.train의 GPU 왼손이다. 보상 계약은 guitar_learning.gpu_tensor_song_reward.v16, 표면 관측은 left_surface_events.v4다. v16은v15음감점/원인진단과B권고/추종/접촉/달성을유지하고행동변화.05무감점대역・왼손목계수1/4만적용했으며 이전 v8 장기 실행의 동결 소스와 현재 소스를 구분한다. 경로와 보존·검증 범위는 9장을 따른다.

기준 파일은 [GPU 환경](/home/ajou/yigyu/3/guitar_learning/gpu/environment.py), [손가락 보상](/home/ajou/yigyu/3/guitar_learning/gpu/finger_reward.py), [기본 실행 설정](/home/ajou/yigyu/3/guitar_learning/training/start.py)이다.

왼손 정책은 왼팔·손목 12축과 손가락 21축을 합한 33축을 학습한다. 전체 행동 벡터는 39개지만 나머지 오른팔꿈치·손목 6축은 왼손 실행에서 0이어야 한다. 오른손 움직임이 물리적으로 고정된다는 뜻은 아니다. 지지 제어와 물리 상호작용은 계속 존재한다.

검지·중지·약지·소지의 음별 보상과 엄지의 역할도 구분해야 한다. 엄지는 왼손 21축 행동에 포함되지만, 네 손가락의 음별 추종·관절 분담·대기 자세 보상에는 포함되지 않는다. 엄지를 직접 특정 자세로 보상하는 새 항은 본문 코드에 없다.

## 1.2 곡 하나의 시간

확인한 기본곡은 05_BN2-131-B_solo, 목표 67개다. 정책 준비 3초 + 오디오 약 29.3064초 + 말미 0.5초를 정책 60Hz 경계로 올려 1969tick, 약 32.8167초로 만든다. native에서 별도 무행동 대기하는 시간이 아니다. 정책은 처음부터 움직일 수 있고 안전 비용도 처음부터 수집한다.

학습의 수집 길이 H32는 약 0.5333초다. H32가 끝나도 곡 시계·손가락 누적 목표·음별 원장은 유지된다. 곡이 끝나거나 물리 실패한 환경만 새 에피소드로 돌아간다.

## 1.3 한 음에 있는 세 시각

| 기호 | 코드 | 의미 |
| --- | --- | --- |
| p | press_s | 압현 준비·접촉을 시작하도록 계획한 시각 |
| o | onset_s | 그 음이 시작되어야 하는 시각 |
| e | end_s | 유지해야 하는 음 구간의 끝 |
| r | source_release_s + pre-roll | 원자료의 명시 해제 시각. e와 같다고 가정할 수 없음 |

onset·press·end는 원곡 기준 시간에 정책 준비 3초를 더한다. end는 원래 sustain 끝과 명시 release 중 이른 시각이다. 따라서 음의 끝 e가 항상 실제 명시 해제 r인 것은 아니다. source_release가 없을 수도 있다.

근거: [시간표 생성](/home/ajou/yigyu/3/guitar_learning/song/task.py).

## 1.4 음의 시간축과 항의 활성 구간

~~~text
max(0,p−2)                 p                  o                  e
    ├──── 접근 준비 ────────┼── 사전 접촉 ──────┼──── audible ──────┤
    │  potential·추종은 이 넓은 구간에서 기회가 생김               │
                           ├─ contact_time누적 / contact_streak연속 ─────┤
                                              ├─ clean/held누적·clean_streak연속 ────┤
                                              ├─ wrong/missing ┤
                                                                  missed 1회
~~~

potential과 추종은 공통 선택기의 손가락별 현재 목표 하나씩, 최대 4개를 사용한다. 다음 목표 토큰에는 별도 두 번째 보상을 주지 않는다. 손목 영역 감점은 음의 창과 무관하게 정책 준비3초부터 곡 말미까지 모든240Hz 표본에서 한 번만 적분한다. 과거 reach window gate는 쓰지 않는다.

v14의활성관절분담항은항상0이다. B대기권고는네손가락idle의min을써서어느손가락이라도press−2..end에있으면손전체0이며양쪽바깥.25초fade한다. 비엄지finger1/2/3하중・이전/현재candidate/wrong・어떤곡목표거리4cm이하중하나면손전체0이다. 빈곡도0이며B필수경유는없다.

## 1.5 물리 4표본과 정책 1tick

한 정책 행동은 1/60초 동안 적용되고, 환경은 실제 물리 표본 4개를 1/240초 간격으로 읽는다.

1. tick 시작 시 현재 접근 potential과 이번 행동을 저장한다.
2. 각 물리 표본에서 표면·속도·하중·candidate·wrong을 계산한다.
3. 실제 시간 구간과 음의 구간이 겹치는 초를 적분한다. 음 경계를 넘었다고 표본 전체를 audible 시간으로 세지 않는다.
4. 최초 접촉은 연속streak 문턱 최초충족 때, 달성·놓친 음은 기존 사건 규칙대로 기록한다.
5. 물리 표본마다 추종·자세·손목 보상과 안전 비용을 더한다.
6. 네 표본이 끝나면 potential 차이와 행동 변화 감점·실패 처리를 계산한다.
7. 단계별 계수를 적용한 reward와 별도 cost를 반환한다.

연속률 보상은 대체로 rate/240으로 더한다. 최초 접촉·달성·놓친 음은 한 번 지급하는 사건이다. 접근 potential은 tick 경계의 차이이므로 다시 1/60이나 1/240을 곱하지 않는다.

## 1.6 보상이 제어를 대신하는가

보상은 움직임을 평가하는 숫자다. 손가락을 자동으로 굽히거나 관절끼리 강제 결합하지 않는다. GPU 왼손 손가락은 현재 목표에 행동×4/60rad를 더하는 누적 제어다. 행동 0은 목표 유지, 반대 행동은 다음 tick부터 반대 방향의 목표 변화다. 실제 관절이 즉시 같은 움직임을 한다는 보장은 없다.

따라서 다음 셋을 나누어 봐야 한다.

- 정책의 요청 행동
- 요청으로 갱신한 관절 목표
- 물리에서 실제로 움직인 관절·몸체·손끝

현재추종보상은지정finger3패드거리와2cm이내약한법선품질만사용하며candidate접촉배율은1이다. 실제 속도·요청 행동은 이 점수를 줄이지 않는다. B대기권고의각도는실제몸체회전을사용하며 엄지를 포함한 LH21은 행동 변화 비용에서도 제외한다.
