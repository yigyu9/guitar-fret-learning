# 100회 중간 학습 수집 분석

**100회까지 기술 검산은 통과했지만, 음 달성은 낮고 네 손가락의 표적 수행이 불균형하다.** 전체 종료1,381회 중 안전722/물리실패659, 평균 달성0.9790/67음이고 안전곡만으로도1.0831/67음이다. 안전하게 끝난 곡에서도 표면 접근→올바른 하중 후보→충분한 clean 지속으로 이어지지 않는 병목이 남는다. 이는 다른 정책들이 학습 도중 만든 **확률적 수집 episode의 혼합 집계**이며, optimizer100의 고정 정책 평가나 최종 성능이 아니다. 낮은 성과만으로 요청한2000회 학습을 중단하지 않는다.

## 검증 범위

[원분석](../analysis_prefix100/analysis.json)의 SHA는 `2ed2bc97bb08482614b61736ac719be33ca1e6949775fec6f9746b24e95af842`다. update0..99, 완료 CRC member 안의3,200 raw행/3,276,800 committed전이, source436·581 pins·세 경로의 종료 episode 일치, 진단v2/base6,3331 curriculum 재생 오차0을 확인했다. 모델56/actor optimizer54/value optimizer57개 tensor가 유한하다. checkpoint100은 `checkpoint_000099.pt`, SHA `a23de4bbf0e9f2472c26ecea1b3dd2026836a5b038995552deeb03425ba95322`다.

실행은 계속되고 있으므로 전체 gzip EOF, 최종 native close,2000회 완료를 확인했다는 뜻이 아니다. prefix100 이후 학습 내용은 이 통계에 섞지 않았다. 분석 JSON/PNG·원로그·모델·동결 도구를 수정하지 않고 이 보고서만 새로 작성했다.

## 움직임·지속 명령·새 자세 진단

손가락이 전혀 움직이지 않는 양상은 아니다. 안전곡에서 각 손가락4축의 평균 실제 범위는 검지0.678/중지0.641/약지0.439/소지1.203rad이고, scalar target−q RMS의 episode·축 평균은0.0224/0.00905/0.0239/0.0301rad다. 단, 큰 운동 범위가 목표음으로 가는 운동이라는 뜻은 아니다.

안전곡의 손가락별 인접 action 반전율은47.38/48.88/47.39/47.55%다. 현재는 std≈0.05의 확률적 수집으로, 과거 별도 deterministic 정책의 '같은 부호 지속 출력' 검사와 같지 않다. 평균 |action|은 약0.04이고 action±1 포화율은0이다. 따라서 이 자료에서 모든 손가락이 한 방향으로만 고정 출력된다고 말할 수 없다. 동시에 누적 목표에서는 작은 부호 편향도 큰 이동을 만들 수 있으며, clipped action 포화0과 목표 한계 명령은 별개다.

예를 들어 안전곡 `LH:ring1_z`는 음수 명령66.51%, mean action−0.02247, 목표 한계 밖 방향 요청25.70%다. `LH:thumb2`도 음수69.17%/한계 밖 방향24.03%다. 이는 명령 목표가 한계에 있을 때 같은 바깥 방향 명령을 요청한 비율이며, 실제 관절이 물리적으로 끼였다는 판정은 아니다. 손가락 평균만으로 각 축의 서로 다른 편향을 상쇄해 해석하지 않는다.

새 base_rotation 지표는 scalar q오차가 놓치는 실제 기저 회전을 드러낸다. 다음은 안전722곡의 **각 episode RMS를 동일 가중한 평균**이며, 전체 프레임을 합쳐 재계산한 pooled RMS나240Hz 최대가 아니다.

|---|---:|---:|---:|
| 검지1 |0.2243rad|0.2279rad|0.06393rad|
| 중지1 |0.04967rad|0.05240rad|0.01003rad|
| 약지1 |0.1800rad|0.1874rad|0.01635rad|
| 소지1 |0.2321rad|0.2388rad|0.04468rad|

명령의 두 좌표를 작은 scalar 오차로 추종하는 것과 실제 전체 상대회전이 일치하는 것은 다르다. 이 지표는 source body frame과 `Exp([target_x,0,target_z])`라는 진단 참조모형을 쓰며 SDK 내부 drive error/토크·추가 자유도·현재 낮은 성과의 단독 원인을 인증하지 않는다. 기존 N6에서 검증되지 않은 gain 증가/경험식 목표 증폭을 이번 학습에 넣지 않은 이유도 유지한다. 실제 표면 event는 실제 body pose에서 계산되므로 정책이 이 회전 영향을 전혀 받지 못한다는 주장도 하지 않는다.

## 보상·PPO·단계

100회 동안 progress0/surface_approach 단계다. update99의 최근256 safe12.89%는 승급 조건90%에 못 미치고, 각 near도 검지1.00/중지0.8898/약지6.1849/소지0%로 모두20%에 못 미친다. 네 손가락 gate이므로 한 손가락 일부 음의 달성만으로 올라가지 않는다. 지금 단계 정체는 기록된 승급 규칙과 일치한다.

100-update 평균 per-transition reward−0.0124634/cost0.0303027이다. 항별로 approach−0.014236이 크고 wrist+0.001943/finger tracking+0.001572/clean hold+0.000715가 있다. approach는 `gamma*Phi(next)−Phi(current)`의 할인/종료 구조이므로 음의 평균만으로 매번 목표에서 멀어졌다고 해석하지 않는다. 안전 episode 평균 reward와 update 전이평균도 서로 다른 분모다.

PPO는 update index23에서1회 KL retry가 있었고 actor LR이3e−5→7.5e−6으로 낮아진 뒤 유지됐다. attempted KL 최대0.020841, 각 update 마지막 accepted analytic KL의 구간평균0.008403이다. cost weight1.0, latent std 평균≈0.049788을 유지한다. accepted minibatch 가중 preclip gradient 평균은 actor3.79/value95.73이며 clip0.5 전 수치다. 이것만으로 수치 폭주를 단정하지 않고, 실제 비유한값0/체크포인트 유한성과 구분한다. LR 감소와 낮은 음 달성 사이 인과도 이 자료만으로 확정하지 않는다.

## 자원·남은 예산

100개 optimizer 경계에서 cache 반환 후 GPU free 최저7.8037GiB, index99 free8.0439GiB다. Torch allocated는0.14572→0.14619GiB이고 free+reserved residual 증가 추정은0.03320GiB다. 이 잔차로 native leak 소유권을 확정할 수 없지만 현재 자료에 과거 OOM 양상의 큰 증가 증거는 없다. host MemAvailable 최저16.2003GiB다.

prefix에 포함된 외부 디스크 관측의 마지막은 optimizer99/wall1124.65초로 가용12.5390GiB였다. 이는 checkpoint100 직전의 관측이므로 저장 직후 실측이라고 부르지 않는다. 처음100회에 귀속되는 파일 크기를 별도로 합치면 다음과 같다.

- raw의 update99 committed compressed prefix:72,541,996bytes.
- update0..99 JSON 합41,640,410bytes, metrics100행도41,640,410bytes, 종료 episode1,381행40,947,897bytes.
- 이 네 로그의 합196,770,713bytes를20배 하면3,935,414,260bytes다. 현재 크기의 큰 checkpoint20개(중간19+final)와 작은 fresh initial을 합한1,427,045,184bytes를 더하면 **본학습 약4.99GiB**의 단순 외삽이다. 추가 monitor/GDB/메타데이터·분석·고정 평가5개·영상은 별도다.

처음100회는 initial censoring과 이후 실패/음별 원장 수의 변화가 있어 이 외삽은 상한 보장이 아니다. 종료가 짧아져 episode 원장이 늘면 증가량이 커질 수 있다. 실제 관측으로 주기 재산정하고 root의3GiB soft warning/2GiB technical floor를 유지한다. 기존 봉인 삭제나 기록 생략으로 공간을 맞추지 않는다.

평균 collect8.907초/PPO2.274초이며 최근 RAM 관측 wall1133.45초까지 약18분53초다.100회 단순20배는2000회 약6.3시간 추정으로, 현재 기술적으로 실행 가능한 예산이다. 낮은 성공률만을 이유로 조기 종료하지 않고 같은 source/보상/안전/계약으로 계속 수집한다. 뒤의1000/2000회와 별도 고정 평가에서 손가락별 병목과 실제 개선 여부를 다시 판단한다.
