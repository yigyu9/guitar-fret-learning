# v6 장기 학습 로그에서 확인한 변화

2000회에 반영된 학습 수집은 완료됐지만, 성과는 꾸준히 상승하지 않았다. 안전곡 평균 달성은 1400–1499회에 **6.9814/67음**, 마지막1900–1999회에 **1.8553/67음**이다. 초기에는 약지·중지의 성공도 있었으나 후반에는 검지에 집중됐다. 이것은 **학습 중 바뀌는 정책의 확률적 수집 결과**이며, 고정 checkpoint 성능이나 망각의 원인을 확정하는 결과가 아니다. 별도 5개 checkpoint 고정 평가는 이 문서 작성 시 완료 결과를 반영하지 않았다. 실제 자세의 자연스러움도 이 로그만으로 판정하지 않는다.

근거는 [완료 분석](analysis_final/analysis.json), [복구 전체 검산](recovery_verification.json), [학습 곡선](analysis_final/training.png), [PPO 곡선](analysis_final/ppo.png), [자세 credit 곡선](analysis_final/finger_posture_reward.png)이다. 아래400–499/1400–1499/1900–1999의 안전곡 원장 수치는 실제 해당 `update_*.json`의67음 ledger를 다시 읽어 확인했다.

## 어느 학습 경로를 집계했는가

- 저장된 원실행 local0–1299의 **1300회/42,598,400전이**와 새 `train_resume700_restart1` local0–699/global1300–1999의 **700회/22,937,600전이**만 합쳤다. 합계는 **2000회/65,536,000전이/64,000 raw행**이다.
- 초기 디스크 중단13회, 원실행 checkpoint 이후62회, 첫700재개에서 중단된5회는 별도 분기로 보존했다. 별도 분기의 업데이트·파일 수 합계는 **80**이고, 업데이트당32,768을 곱한 **명목 예산은2,621,440전이**다. 특히 원실행 후속62개 파일의 raw 완전성·commit은 이번1300 prefix proof가 인증하지 않는다. 이 분기와 별도의 부분 수집은 최종 정책 경로·평균에 합산하지 않는다. 이는 journal의 공식 discarded 필드를 재분류하거나 원자료를 삭제했다는 뜻이 아니다.
- 원본은 NTFS/FUSE EIO 뒤 SHA가 같은 로컬 복사로 읽었다. [최종 위치 이전 manifest](recovery_copy_relocated_manifest.json)는 원복사 manifest의 부모 SHA와 파일 증거를 보존한다. 원래 입력 pin은 고치지 않고 manifest로 입증한 경로 이전만 허용했다.
- 1300 checkpoint→새 initial1300의 모델·양 optimizer·모든 RNG·3331 커리큘럼은 metadata 외 **정확 복원**됐다. 진행 중이던 물리 episode는 잇지 않고035/v14의 새 장면에서 시작했다. 따라서1300 직후 종료곡 수·시계 분포는 정책 변화뿐 아니라 새 episode 시작의 영향도 받을 수 있다.
- 원실행은1300 prefix의 CRC가 완료된41,600행만 인증하며 전체 EOF·native 정상 종료를 주장하지 않는다. 마지막700은22,400행의 전체 gzip CRC/EOF·정상 GPU close를 인증한다. 이 마지막 프로세스는 wall **8175.3926초(약2시간16분15초)**에 정상 완료됐다. 연속2000회 단일 프로세스나 중단 시간을 제외한 통합 wall을 만들지 않는다.
- 두 구간에서 source436, 실제 입력 pin581/582개, model56·actor optimizer54·value optimizer57 tensor 유한성, 보상/비용 성분합, 세 로그의 episode 연결과3331 재생이 통과했다. 커리큘럼 재생 최대 오차는 양쪽 모두0이다. 소스·모델 구조·PPO 설정·물리 설정을 실행 중 수정하지 않았다.

## PPO는 유한하게 갱신됐지만 성과 보존은 별개다

실제 KL retry는 global index18과832에서 각각1회였다. 시도 KL은.02099025/.02026569로 target.02를 넘었고, 해당 시도 복원 후 최종 accepted KL은.00455077/.00329580이었다. 설정된 retry factor.25로 actor LR은3e−5→7.5e−6→1.875e−6이 됐고 이후 끝까지 유지됐다. value LR은3e−4다. cost weight는 전체1.0이고 episode-cost budget은None이라 예산 기반 자동 lambda 갱신은 작동하지 않는 설정이었다.

행별 KL은 마지막 accepted 시도의 값이고 minibatch 전체 KL 평균이 아니다. gradient는 accepted actor/value minibatch의 sample-weighted preclip norm을 update별 평균한 값이며, 실제 optimizer에는 max norm.5 clipping이 적용됐다. 초기 std.0497871→final 모델의 active33 평균.0497131로 큰 std 붕괴는 관찰되지 않았다. 수집 action saturation 지표는 전체0이었다. 이는 **tanh action이±1에 붙지 않았다는 기록**이며, 누적 target이 native 관절 한계에 닿지 않았다는 뜻은 아니다. 유한 gradient/허용 KL/비슷한 std만으로 음악 기능이 보존됨을 보장하지 않는다. LR 감소가 후반 성과 소실의 원인인지도 이 한 실행으로 판별할 수 없다.

## 요청과 실제 움직임의 증거 범위

LH21 action은4rad/s 배율의 **누적 목표 변화 요청**이다. controller가 적분·clamp한 target은 절대 관절 목표이고 q는 실제 상태다. 다른18 absolute codec 채널을 LH21과 같은 속도 action으로 해석하면 안 된다. 이 episode 진단의 상세 운동 통계는 LH21 대상이다.

마지막 안전곡1714개의 아래 값은 **곡별·축별 통계의 평균**이다. thumb는5축, 나머지는각4축 평균이며 전체 프레임을 모은 pooled RMS·240Hz 극값이 아니다.

추가 base 진단에서 마지막 안전곡의 실제 palm-relative rotvec-y RMS 평균은 검지/중지/약지/소지 .286752/.272715/.116166/.078257rad, zero-y command 대비 local-xz 오차 RMS는 .028756/.089360/.028666/.015479rad다. 이 때문에 q 두 축의 RMS만으로 실제3D 기저 자세가 충분히 설명된다고 볼 수 없다. 그러나 zero-y는 진단 참조이고 SDK 내부 drive 오차·힘·자유축 버그 인증은 아니다. MCP/PIP/DIP의 자연스러운 분담·비사용 손가락 대기 자세·급꺾임 여부는 별도 실제 pose capture와 시간축을 확인해야 한다. 여기서는 그 결론을 내리지 않는다.
