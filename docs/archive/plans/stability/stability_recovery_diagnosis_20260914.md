# 무탐색 평가와 복원 실패 진단

사용자의1·2번 구현 및 근거 있는 개선 반영 요청에 따라 진행한다.
기존 평가기는 이미 deterministic 행동을 사용한다. 이를 명시적으로 표시하고 동일 조건의
탐색 행동 비교, 복원 조건별 실패·가장 가까운 상태·유지 시간·명령 변화 진단을 확장한다.

- [x] 조건별 복원 진단을 독립 모듈과 CPU 회귀 검사로 구현한다.
- [x] 평가·영상·비교 도구에 연결해 기존 v6 checkpoint를 엄격한 계약 아래 평가한다.
- [x] 실제 결과를 분석하고 근거가 있는 개선을 적용한다.
- [x] 새 학습 로그에 진단을 연결하고 GPU/PPO·checkpoint 경계를 검증한다.
- [x] 변경 검수, 사용법·평가 결과·한계 문서를 갱신한다.

기존 학습을 중단하지 않는다. 평가 전에는 기존 checkpoint의 물리·정책 지문 대상 파일을
변경하지 않는다. 관측·제어 권한·성공 기준을 임의로 완화하지 않는다. 가장 가까운 상태는
한 frame의 위치·회전·속도를 함께 기록하고 WAIT/전환/reset을 RECOVER 성과에 포함하지 않는다.

결과: CPU 25개와 공통 dispatcher/checkpoint 검사 통과. 1500 모델의 무탐색
seed 1 반복은 2/3 성공, 탐색 반복은 0/3 성공이었다. 무탐색 정기 평가를 기본 연결했으며
보상·물리·성공 조건은 유지한다. 새 wrapper/실행기 포함 변경 검수에서 actionable 결함 없음.
GPU 8환경·48 rollout의 기존 지표는 이전 v6 smoke와 모두 일치했다. 정기 평가 자동 실행과
strict 재로딩을 통과했다. 기존 1500 모델의 새 실행기 resume·1504 저장·optimizer 갱신 및
원본 계약 보존도 확인했다. [결과·사용법](../../../2026-09-14/archive/STABILITY_RECOVERY_DIAGNOSIS.md).
