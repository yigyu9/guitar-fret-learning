Fret 학습 실제 구조

이 문서는 왼손 Fret 정책이 실제로 어떤 입력을 받고,
어떤 상태를 관측하며, 그 상태를 어떤 신경망에 넣고,
30차원 action을 어떻게 물리 시뮬레이션으로 바꾸는지 설명

Strike 문서와 마찬가지로, 오디오 자체가 Isaac Gym 안으로 들어가는
구조는 아니다. 오디오와 tablature에서 미리 만든 운지 결과가
60Hz의 압현 목표로 가공되어 있고, Fret은 그 목표를 달성하는
왼손 관절 제어 정책을 학습

전체 흐름
    오디오/tablature/finger mapping
        → fret_training.json
        → hand_position_targets.json
        → FretGoalSequence
        → 현재 기타·손·손가락·엄지·압현 상태
        → 420D Fret-v2 observation
        → Fret-v2 Actor
        → 30D 정책 action
        → curriculum action mask와 인접 손가락 보정
        → EMA + PD target + torque
        → Isaac Gym PhysX 1스텝
        → 손끝/프렛/줄의 기하학적 압현 판정
        → press, wrong press, sustain, safety reward
        → goal frame 전진
        → PPO update

정책이 직접 학습하는 것은 "현재 상태에서 왼손 관절을 어느 방향으로
움직일지"이다. 다음 정보는 정책이 학습해서 만들어내는 것이 아니다.

    - 어떤 줄의 어떤 프렛을 눌러야 하는지
    - 어떤 손가락이 그 목표를 담당하는지
    - 지금 누르지 말아야 하는 줄인지
    - 실제 손끝이 목표 프렛 셀 안에 들어왔는지
    - 압현 성공으로 인정할지
    - curriculum을 다음 단계로 올릴지

이런 부분은 goal 파일, 기하학 계산, reward, curriculum 코드가
규칙으로 정의한다.


1. 학습을 시작하는 실제 실행 경로

1.1 외부 명령

가장 간단한 Fret 학습 명령은 다음과 같다.

    python -m tab2body.train \
        --task fret \
        --song 02_Jazz1-200-B_solo \
        --num-envs 1024 \
        --iterations 5000

`tab2body/train.py`는 먼저 `--task fret`만 해석하고,
`tab2body.train_fret`로 실행을 넘긴다. Fret 환경을 공용 진입점에서
직접 import하지 않는 이유는 Strike만 학습할 때 Fret Isaac 환경이
먼저 초기화되지 않도록 하기 위해서다.

실제 호출 관계는 다음과 같다.

    tab2body/train.py
        → task 이름으로 runner 선택
    tab2body/train_fret.py
        → 인자 파싱
        → goal/hand target 경로 결정
        → FretTask 생성
        → Fret-v2 ActorCritic 생성
        → PPOTrainer 생성
        → checkpoint contract 생성
        → curriculum 적용
        → rollout 수집과 PPO update
        → 평가, 영상, 로그, checkpoint 저장

`--song`을 지정하면 `tab2body/song_bundles.py`의
`fret_goal_path(song_id)`가 다음 파일을 선택한다.

    data/song_bundles/<song_id>/training/fret_training.json

손목 soft target은 같은 bundle의 다음 파일을 자동으로 찾는다.

    data/song_bundles/<song_id>/training/hand_position_targets.json

따라서 일반 실행에서는 `--goal`과 `--hand-targets`를 직접 입력할
필요가 없다. 다른 파일을 실험할 때만 이 두 인자를 사용한다.

1.2 기본값

`tab2body/cfg.py`의 `FRET` 설정에서 신규 실행의 기본값이 결정된다.

    observation_contract = fret.observation.v2
    num_envs            = 1024
    device               = cuda:0
    iterations           = 5000
    action_scale         = 1.0
    action_alpha         = 0.5
    reset_noise          = 0.0
    preparation_frames   = 60  (1초)
    human_hard_limits    = enabled

따라서 `--observation-contract`를 생략해도 기본적으로 420D
Fret-v2가 사용된다. Fret-v1은 호환성 검사용 legacy 계약이며,
현재 새 학습의 기본 구조가 아니다.

1.3 smoke와 평가

전체 학습 전에 배관만 확인하려면 다음처럼 실행한다.

    python -m tab2body.train \
        --task fret \
        --song 02_Jazz1-200-B_solo \
        --smoke

`--smoke`는 환경 수를 최대 8개, rollout horizon을 4, PPO epoch를
1로 줄여 짧게 실행한다. 이것은 압현 성능을 검증하는 실행이 아니라
Isaac Gym 생성, observation, action, reward, PPO, checkpoint 저장이
서로 연결되는지만 확인하는 용도다.

checkpoint를 deterministic하게 평가할 때는 다음 형태를 사용한다.

    python -m tab2body.train \
        --task fret \
        --checkpoint <path/to/fret_XXXXXX.pt> \
        --eval

평가에서는 환경 수가 1개로 줄고 random start가 꺼진다. 이때 정책은
확률분포에서 action을 sampling하지 않고 평균 action을 사용한다.


2. Fret 학습 입력 데이터

2.1 Song Bundle 구조

예를 들어 `02_Jazz1-200-B_solo` bundle은 다음처럼 구성된다.

    data/song_bundles/02_Jazz1-200-B_solo/
        source/audio.wav
        source/annotation.jams
        mapping/fingering.json
        mapping/tablature.notes.csv
        preview/fingering.png
        training/fret_training.json
        training/hand_position_targets.json
        training/strike_training.json
        training/strike_plan.json
        manifest.json

각 파일의 역할은 서로 다르다.

    source/audio.wav
        사람이 듣는 원본 오디오. Fret runtime에는 직접 입력되지 않는다.

    source/annotation.jams
        원본 note annotation. 학습 goal을 다시 만들 때 사용하는 원자료다.

    mapping/tablature.notes.csv
        줄, 시작/종료 시각, pitch 등의 tablature 형태 입력이다.

    mapping/fingering.json
        어떤 note를 어떤 줄/프렛/손가락으로 연주할지 검수한 결과다.
        Fret 학습의 직접적인 의미론적 출발점이다.

    training/fret_training.json
        fingering을 60Hz 프레임별 압현 goal로 rasterize한 runtime 입력이다.

    training/hand_position_targets.json
        각 프레임의 기타 좌표계 wrist soft target과 허용 반경이다.

    manifest.json
        bundle 파일의 존재 여부, SHA-256, mapping validation 결과를 기록한다.

현재 runtime은 오디오를 다시 분석하거나 fingering을 매 step 생성하지
않는다. 이미 검수·생성된 `fret_training.json`을 읽는다.

2.2 fingering.json의 의미

`mapping/fingering.json`은 대략 다음 필드를 가진다.

    {
      "convention": "string 0 = low-E (CSV/모델 관례)",
      "notes": [
        {
          "t_on": 0.0231,
          "t_off": 0.2437,
          "string": 3,
          "fret": 6,
          "midi": 61,
          "finger": 3,
          "barre": false
        }
      ],
      "presses": [ ... ],
      "hand": [ ... ],
      "diagnostics": [ ... ],
      "violations": [ ... ]
    }

여기서 source string 번호는 다음과 같다.

    0 = low-E
    1 = A
    2 = D
    3 = G
    4 = B
    5 = high-e

각 `notes[]`는 note의 소리 구간이고, `presses[]`는 왼손이 실제로
압현을 유지해야 하는 구간이다. `hand[]`의 `P` 값은 손의 대략적인
위치(anchor fret)를 표현한다.

Fret runtime의 Isaac goal 배열은 줄 순서를 반대로 저장한다.

    goal index 0 = high-e
    goal index 1 = B
    goal index 2 = G
    goal index 3 = D
    goal index 4 = A
    goal index 5 = low-E

이 변환은 `tab2body/tools/build_fret_training_data.py`의
`rasterize()`에서 `goal_idx = 5 - event["string"]`으로 수행된다.
이 규칙을 혼동하면 올바른 프렛 번호를 사용해도 다른 줄을 누르는
정책이 된다.

2.3 fret_training.json 생성

학습용 파일 생성 코드는 다음이다.

    tab2body/tools/build_fret_training_data.py

이 도구는 reviewed fingering 또는 JAMS를 읽고 다음 과정을 수행한다.

    reviewed notes/fingering
        → press event와 release window 정리
        → hand anchor와 allowed fret range 보간
        → 60Hz 프레임 rasterization
        → fret_training.json
        → hand_position_targets.json

동일 줄에서 이전 프렛을 떼고 다음 프렛을 누르는 실제 gap은
`NO_PRESS`로 만든다. 마지막 event 이후에는 더 이상 특정 release를
강제하지 않으므로 `DONT_CARE`가 된다.

2.4 fret_training.json의 schema

파일의 핵심 구조는 다음과 같다.

    {
      "schema": "tab2body.fret_training.v1",
      "metadata": {
        "fps": 60,
        "asset_max_fret": 22,
        "allow_barre": false,
        "string_convention_events": "0=low-E, 5=high-e",
        "string_convention_frame_goals":
            "index 0=high-e, 5=low-E (Isaac goal order)",
        "fret_encoding":
            "0=don't-care, -1=must-not-press/open, >=1=press fret",
        "finger_encoding":
            "0=none, 1=index, 2=middle, 3=ring, 4=pinky"
      },
      "events": [ ... ],
      "hand_positions": [ ... ],
      "frames": [ ... ],
      "validation": { ... }
    }

실제 `frames[]` 한 개는 다음 의미를 가진다.

    {
      "frame": 0,
      "t": 0.0,
      "fret_goal":   [0, 0, 6, 0, 0, 0],
      "finger_goal": [0, 0, 3, 0, 0, 0],
      "barre_goal":  [false, false, false, false, false, false],
      "hand_anchor_fret": 4.0,
      "hand_anchor_norm": 0.142857,
      "hand_allowed_fret_range": [3, 8]
    }

위 예는 Isaac 순서의 세 번째 줄, 즉 G string의 6번 프렛을
약지(`finger=3`)로 누르라는 뜻이다.

`FretGoalSequence`는 파일을 읽을 때 다음을 검증한다.

    - schema가 tab2body.fret_training.v1인지
    - fps가 60인지
    - frame index가 0부터 연속인지
    - t가 frame / 60과 일치하는지
    - 각 goal 배열이 정확히 6개인지
    - fret이 -1..22 범위인지
    - fret>0이면 finger가 1..4인지
    - fret<=0이면 finger가 0인지
    - barre가 허용되지 않은 현재 계약에서 false인지
    - hand anchor와 allowed range가 1..22 안에 있는지

2.5 goal 값 세 가지

각 줄의 `fret_goal`은 단순한 프렛 번호가 아니라 평가 규칙을
선택하는 값이다.

    fret > 0
        해당 프렛을 눌러야 한다.
        finger_goal이 지정한 왼손 손가락의 압현을 평가한다.

    fret == -1
        이 프레임에는 해당 줄에 압현이 없어야 한다.
        실제 다른 프렛을 누르고 있으면 wrong press가 된다.

    fret == 0
        이 줄은 현재 frame에서 평가하지 않는다.
        누르고 있어도 성공/실패의 직접 대상이 아니다.

이 세 가지를 구분하는 이유는 음악적으로 "소리가 나지 않아야 하는
구간"과 "현재 목표에서 관심이 없는 구간"이 다르기 때문이다.

2.6 hand_position_targets.json

손목 target 파일은 다음 계약을 가진다.

    schema          = tab2body.hand_position_targets.v1
    coordinate_frame = guitar local
    frames[].t       = goal frame time
    anchor_fret      = 손의 중심이 되는 대략적인 프렛
    allowed_fret_range = 손목이 허용되는 넓은 fret band
    wrist_pos_guitar = 기타 좌표계 wrist soft target [x,y,z]
    allowed_radius_m = 허용 반경

이 target은 wrist를 정확히 한 점에 고정하는 hard trajectory가 아니다.
왼손 손가락이 목표 프렛에 도달하도록 손 전체를 안내하는 soft reward와
observation 문맥이다. 현재 02_Jazz1 파일의 첫 target은 대략 다음과 같다.

    anchor_fret       = 4
    allowed_fret_range = [3, 8]
    wrist_pos_guitar   = [0.075, 0.112313, -0.0227]
    allowed_radius_m   = 0.04 m


3. Isaac Gym Fret 환경

3.1 FretTask와 GuitarEnvBase

`tab2body/env/tasks/task_fret.py`의 `FretTask`는
`tab2body/env/base.py`의 `GuitarEnvBase`를 상속한다.

환경의 기본 조건은 다음과 같다.

    - Isaac Gym PhysX
    - control frequency 60Hz
    - PhysX substeps 4
    - net contact force collection: 마지막 substep만 사용
    - max depenetration velocity: 10.0 m/s
    - GPU pipeline / GPU PhysX
    - seated humanoid
    - fixed guitar G0
    - chair actor
    - Hip/Knee/Ankle/Toe 하체 DOF 잠금
    - 왼쪽 어깨·팔꿈치·손목·손가락 제어

기타는 `guitar_asset.xml`, humanoid는
`smpl_mpl_hands_body.xml`에서 읽는다. G0에서는 기타 root가 고정되어
있으므로 손과 기타의 상대 위치가 매 episode 동일한 기준을 가진다.

3.2 제어하는 관절 30D

`FRET_CONTROL_PREFIXES`는 다음 prefix를 사용한다.

    ("L_Shoulder", "L_Elbow", "L_Wrist",
     "LH:thumb", "LH:index", "LH:middle", "LH:ring", "LH:pinky")

실제 checkpoint의 관절 순서는 prefix 이름의 단순한 의미가 아니라
`controlled_dof_names`에 봉인된 정확한 이름 순서다.

    L_Shoulder_x/y/z       3D
    L_Elbow_x/y/z          3D
    L_Wrist_x/y/z          3D
    LH:thumb1_x/y/z        3D
    LH:thumb2, thumb3      2D
    LH:index                4D
    LH:middle               4D
    LH:ring                 4D
    LH:pinky                4D
    --------------------------------
    total                  30D

손가락 4D는 각 손가락의 base/lateral/flexion 관련 관절을 포함한다.
정확한 문자열은 checkpoint contract와
`tab2body/tests/test_full_postprocessing.py`의 `_fret_names()`에서
확인할 수 있다.

3.3 기타 안의 기하학

`tab2body/assets/guitar_asset.xml`은 다음 기타 요소를 제공한다.

    G:fret1 ... G:fret22
        프렛 위치 marker/box
    G:string1 ... G:string6
        줄의 nut 쪽 marker
    G:string1_end ... G:string6_end
        줄의 body 쪽 marker
    G:thumb_support_proxy
        엄지 후면 지지를 위한 전용 proxy
    G:body, G:pluck_range
        기타 body와 타현 주변 geometry

실제 줄 marker는 줄의 양 끝점을 제공하는 geometry-less body이고,
Fret reward는 이를 이용해 string/fret cell과 손끝의 상대 위치를
계산한다. 줄을 손끝이 누르는 현상을 단순히 PhysX 접촉 하나로
판정하는 구조는 아니다.

엄지에는 예외적으로 실제 충돌쌍이 있다.

    LH:thumb_pad ↔ G:thumb_support_proxy

`FretTask.__init__()`에서 `enable_thumb_support_collision()`을 호출해
이 쌍만 기타-손 충돌로 활성화한다. 엄지의 접촉력, 압축 깊이,
후면 정렬은 reward와 observation에 사용된다.

3.4 기타 좌표계

`GuitarEnvBase.to_guitar_frame()`과
`body_pose_twist_in_guitar_frame()`이 world state를 기타 local frame으로
변환한다.

    world body state
        → guitar root pose를 기준으로 평행이동
        → guitar root 회전의 inverse 적용
        → position_G / velocity_G / rotation6d_G

G0에서는 기타가 움직이지 않지만, 이 변환 경로를 사용하는 이유는
나중에 G1/G2에서 기타가 움직여도 손의 관측을 기타 기준으로 유지하기
위해서다. 단, 현재 Fret checkpoint는 G0 fixed guitar에서 학습된다.
4. Fret이 관리하는 상태

4.1 신체와 관절 상태

Fret policy가 직접 받는 proprioception은 제어 관절의 상태다.

    q
        왼쪽 어깨·팔꿈치·손목·엄지·네 손가락의 30개 관절 각도

    qdot
        같은 30개 관절의 각속도

`q`와 `qdot`은 기타 좌표계의 위치가 아니라 관절 공간 값이다.
손목, 손끝, 엄지의 위치·자세·속도는 별도로 기타 좌표계로 변환된다.

4.2 observation에 쓰는 rigid body

Fret-v2는 다음 rigid body의 기타 상대 상태를 사용한다.

    L_Thorax
        왼팔의 기준 anchor. position, rotation6d, 선속도,
        각속도, 투영 중력을 사용한다.

    L_Wrist
        손목 위치/자세/선속도/각속도와 wrist target 오차를 계산한다.

    LH:palm
        손바닥의 위치와 움직임을 관측한다.

    LH:index_top, LH:middle_top,
    LH:ring_top, LH:pinky_top
        네 손가락 끝에 가까운 body. 프렛 접근, lateral error,
        압현 깊이와 손가락 이동을 계산한다.

    LH:thumb3, LH:thumb_top
        엄지 후면 support geometry와 thumb observation을 계산한다.

4.3 goal cursor와 시간 상태

`FretGoalSequence`는 각 병렬 environment마다 별도의 cursor를 가진다.

    frame_idx
        현재 60Hz goal frame index

    preparation_remaining
        첫 목표를 보여주면서 song clock을 멈추는 준비 프레임 수
        기본값은 60 frame = 1초

    curriculum_stage
        현재 연습 단계

    practice_remaining
        정적 손가락/코드 연습에서 남은 연습 프레임

    practice_string
        단일 줄 압현 단계에서 연습하는 줄

    sustain_event_id / sustain_eligible
        같은 압현을 계속 유지하는 sustain 구간 식별자와 평가 가능 여부

    finger_event
        각 손가락의 다음 목표, 남은 시간, keep/move/rest 관계

full_song 또는 chronological stage에서는 `frame_idx`가 한 control step마다
전진한다. `coarse_reach`, `fine_reach`, `isolated_press` 같은 정적
연습 단계에서는 source song의 특정 frame을 여러 step 반복하고,
`practice_remaining`이 줄어든다.

4.4 현재 목표의 의미

`goals.current()`가 현재 frame의 목표를 다음 tensor 묶음으로 반환한다.

    fret
        [N,6] 프렛 목표
    finger
        [N,6] 손가락 번호 0..4
    barre
        [N,6] 바레 여부
    anchor / allowed
        손 위치 목표
    wrist / wrist_radius
        기타 좌표계 wrist soft target
    sustain_event_id / sustain_eligible
        sustain 평가 상태
    finger_event
        손가락별 다음 목표 문맥

여기서 N은 병렬 환경 수다. 같은 정책이 N개의 서로 다른 현재
frame/초기 자세를 동시에 경험한다.

4.5 압현 측정 내부 상태

`FretReward`는 손끝이 각 string/fret cell에 들어갔는지 추적하기 위해
다음 내부 상태를 유지한다.

    _press_distal[N,6,4,22]
        손끝 distal sample의 압현 hysteresis 상태

    _press_anyseg[N,6,4,22]
        finger chain의 어느 segment라도 cell을 누르는지

    _latest_depth_by_finger_fret
        최근 기하학적 압현 깊이

    _press_hold_streak
        동일 goal을 올바르게 누른 연속 frame 수

    _press_hold_acquired
        최소 hold 조건을 이미 달성했는지

    _press_hold_previous_fret/finger
        이전 frame과 현재 target이 같은지 확인하는 latch 기준

이 상태는 actor observation을 만들 때 반복해서 읽힐 수 있지만,
observation 생성 자체가 hold streak를 추가로 증가시키면 안 된다.
실제 hold state 갱신은 reward 계산 경로에서 한 번만 수행한다.

4.6 safety 상태

FretTask는 성능 외에 다음 safety monitor도 관리한다.

    WristSafetyBoxMonitor
        wrist가 기타 기준 안전 box를 벗어나는지

    FingerBackLimitMonitor
        손가락이 neck 뒤쪽 평면을 과도하게 통과하는지

    GuitarPenetrationMonitor
        손/팔 chain이 기타 geometry를 관통하는지

    FingerSelfIntersectionMonitor
        손가락 capsule proxy가 서로 과도하게 겹치는지

    ContactLoadMonitor
        엄지 support 및 기타 접촉 하중을 진단

    palm_down termination
        손바닥 방향이 비정상적으로 바닥을 향한 상태가 지속되는지

일부 monitor는 현재 reward/diagnostic만 제공하고, 일부는 3 frame
연속 위반 시 episode를 종료한다. 평가 시에는 성공률과 safety 종료를
분리해 기록한다.


5. 420D Fret-v2 observation

5.1 observation 계약의 출처

최종 observation 순서는 다음 파일들이 공동으로 결정한다.

    tab2body/fret_v2_contract.py
        block 크기, field 이름, field 순서, slice

    tab2body/env/tasks/task_fret.py
        현재 PhysX와 goal에서 실제 block tensor 생성

    tab2body/learning/fret_v2_model.py
        block별 encoder width

`fret_v2_block_manifest(controlled_dof_names)`가 이름 기반 manifest를
만들고, `pack_fret_v2_blocks()`가 정해진 순서로 이어 붙인다.
이 때문에 단순히 tensor shape가 420으로 같다는 것만으로는 checkpoint
호환을 보장하지 않는다. 관절 이름 순서와 각 field 이름도 같아야 한다.

5.2 전체 block 표

    block                   raw dim   encoder output
    -------------------------------------------------
    O_proprio                  60          96
    O_arm_anchor               18          48
    O_hand_geometry            60          96
    O_current_event            45          64
    O_target_geometry          24          48
    O_finger_transition        52          64
    O_lookahead                72          72
    O_readiness_contact        45          64
    O_phase                    12          32
    O_synchronizer              2           8
    O_history                  30          48
    -------------------------------------------------
    total                      420         640

각 raw block을 별도 Linear+ELU encoder로 처리한 뒤 640D를 fusion MLP에
넣는다. 아래 각 설명의 `→` 오른쪽 숫자는 encoder 출력 차원이다.

5.3 O_proprio: 60D → 96D

    30D controlled joint position q
    30D controlled joint velocity qdot

이 block에는 하체나 기타 root의 모든 DOF가 들어가지 않는다. Fret 정책이
직접 제어하는 30개 관절만 사용한다.

5.4 O_arm_anchor: 18D → 48D

`L_Thorax`를 왼팔의 기준점으로 삼는다.

    position_G             3D
    rotation6d_G            6D
    linear_velocity_G       3D
    angular_velocity_G      3D
    projected_gravity       3D

quaternion 전체 대신 rotation6d를 사용하는 이유는 quaternion 부호
불연속을 피하면서 방향을 표현하기 위해서다.

5.5 O_hand_geometry: 60D → 96D

다음 body의 기타 좌표계 geometry를 연결한다.

    L_Wrist
        position 3 + rotation6d 6 + linear velocity 3 + angular velocity 3
    LH:palm
        position 3 + rotation6d 6 + linear velocity 3 + angular velocity 3
    index_top, middle_top, ring_top, pinky_top
        각 position 3 + linear velocity 3 = 6 × 4
    thumb_top
        position 3 + linear velocity 3 = 6

합계는 15 + 15 + 24 + 6 = 60D다. 손가락 끝의 속도를 포함하는
이유는 단순히 현재 위치뿐 아니라 목표 프렛으로 접근하고 있는지,
이미 지나쳤는지를 구분하기 위해서다.

5.6 O_current_event: 45D → 64D

현재 frame에서 요구하는 손가락/줄/프렛 의미를 표현한다.

    event valid                     1D
    finger 1..4 active              4D
    finger 1..4 × string mask      24D
    finger 1..4 fret normalized      4D
    finger 1..4 barre                4D
    no_press mask                    6D
    chord size                       1D
    atomic chord flag                1D
    ------------------------------------
    total                           45D

여기서 fret은 22로 나누어 정규화한다. 손가락 번호와 줄 mask가
동시에 들어가므로, 같은 프렛이라도 어느 손가락이 어느 줄을 담당하는지
구별할 수 있다.

5.7 O_target_geometry: 24D → 48D

각 손가락의 목표 위치와 압현 상태를 표현한다.

    finger 1..4 target vector_G       12D
    finger 1..4 signed press depth     4D
    finger 1..4 string lateral error   4D
    wrist target vector_G               3D
    wrist radius margin                 1D
    ---------------------------------------
    total                              24D

활성 target finger의 목표 vector를 손끝 position에서 뺀 값이다.
비활성 손가락은 해당 target vector가 0으로 채워진다.

5.8 O_finger_transition: 52D → 64D

네 손가락 각각에 대해 13D next-goal event를 넣는다.

    next string mask       6D
    next fret               1D
    time to next goal       1D
    next valid              1D
    time to current change  1D
    relation.keep           1D
    relation.move           1D
    relation.rest           1D
    --------------------------------
    finger one              13D
    four fingers             52D

`keep`은 현재 압현을 유지할 손가락, `move`는 다음 위치로 이동해야
하는 손가락, `rest`는 현재 목표가 없는 손가락이다. preparation 동안에는
남은 준비 시간을 반영해 time field가 보정된다.

5.9 O_lookahead: 72D → 72D

현재 distinct fret event 이후의 두 개 event를 본다. 각 lookahead는
다음 field를 가진다.

    valid                         1D
    delta_s                       1D
    finger 1..4 × string mask   24D
    finger 1..4 fret              4D
    no_press mask                 6D
    --------------------------------
    one event                    36D
    two events                   72D

긴 sustain 구간의 매 frame을 별도 event처럼 보지 않고,
`canonical_event_lookahead()`가 실제 상태가 바뀌는 distinct event만
선택한다.

5.10 O_readiness_contact: 45D → 64D

각 줄별 압현 상태와 엄지 support를 같이 넣는다.

    per string press_quality       6D
    per string ready               6D
    per string wrong_press         6D
    per string sustain_valid       6D
    per string slip_speed_mps      6D
    active finger target distance  4D
    thumb geometry                 6D
    thumb force quality             1D
    chord_ready                     1D
    confidence                      1D
    dwell_fraction                  1D
    minimum_safety_margin           1D
    -----------------------------------
    total                          45D

이 block은 정책에 정답 label만 주는 것이 아니라, 현재 물리 상태가
이미 압현에 가까운지와 지속 가능한지를 알려준다.

5.11 O_phase: 12D → 32D

    prepare / press / hold / release / transition  one-hot 5D
    preparation_progress                            1D
    event_progress                                  1D
    time_to_press_s                                 1D
    time_to_release_s                               1D
    song phase sin/cos                              2D
    event_resolved                                  1D
    -----------------------------------------------
    total                                          12D

5.12 O_synchronizer: 2D → 8D

    release_enable
    timing_offset_s

Fret-v2 ABI에는 Synchronizer 입력 자리가 예약되어 있다. 그러나 현재
독립 Fret checkpoint는 reset 시 `(release_enable=1, timing_offset=0)`을
사용해 학습했다. 따라서 이 두 값을 runtime에서 갑자기 바꾸면
고정 정책에 out-of-distribution 입력이 된다. 초기 FullG0 통합에서는
source actor에는 `(1,0)`을 유지하고, timing supervisor가 별도 계약으로
사용하는 것이 안전하다.

5.13 O_history: 30D → 48D

직전 control step에서 EMA를 거쳐 실제로 실행된 `prev_action` 30D다.
raw actor output이 아닌 executed action을 넣는 이유는 action smoothing이
현재 actuator state의 일부이기 때문이다. 이 history가 있어야 단일
frame observation도 어느 정도 Markov state가 된다.
6. Fret-v2 신경망

6.1 실제 모델 파일

    tab2body/learning/fret_v2_model.py
        FretV2BlockNetwork
        FretV2ActorCritic

모델 architecture contract 이름은 다음과 같다.

    fret.block_encoder_mlp.v1

`tab2body/train_fret.py`는 observation contract가 v2이면
`fret_actor_critic_class()`를 통해 이 모델을 선택한다.

6.2 Actor 구조

    420D observation
        ↓ FRET_V2_BLOCK_SLICES로 11개 block 분리
    각 block별 Linear + ELU encoder
        ↓
    640D block feature concatenate
        ↓
    Linear 640 → 512 + ELU
        ↓
    Linear 512 → 256 + ELU
        ↓
    Linear 256 → 30
        ↓
    30D latent mean
        + learned 30D log_std
        ↓ Normal distribution sampling
        ↓ tanh
    normalized action [-1, 1]

Actor parameter 수는 다음과 같다.

    actor network       497,518
    learned log_std          30

6.3 Critic 구조

Critic은 Actor와 같은 11개 observation block encoder 구조를 사용하지만
파라미터를 공유하지 않는다.

    420D observation
        ↓ 11개 block encoder
    640D feature
        ↓ Linear 640 → 512 + ELU
        ↓ Linear 512 → 256 + ELU
        ↓ Linear 256 → 6
    six-channel value

Critic network parameter 수는 491,350개다. 따라서 모델 전체는
log_std를 포함해 약 988,898개 trainable parameter를 가진다.

Fret의 value가 6개인 이유는 reward도 6개 기타 줄 채널을 유지하기
때문이다. Actor는 PPO advantage를 계산할 때 현재 곡에서 실제로
감독되는 줄에 대한 reward/value channel을 중심으로 사용한다.

6.4 정책 분포

`tab2body/learning/models.py`의 `ActorCritic` API를 그대로 사용한다.

    observation
        → RunningMeanStd로 정규화
        → Actor latent mean과 log_std
        → diagonal Normal
        → tanh
        → [-1,1] action

학습 중에는 Normal에서 action을 sampling한다. 평가에서는
`deterministic=True`로 latent mean을 tanh한 action을 사용한다.

초기 mean은 현재 seated pose와 control range를 이용해 만든
`init_action`이다.

    init_action =
        (init_pose[ctrl_idx] - ctrl_mid)
        / (action_scale * ctrl_half)

즉, 초기 정책은 무작위 관절 자세가 아니라 humanoid의 초기 왼손 자세
근처에서 시작한다.


7. 30D action이 물리 action으로 바뀌는 과정

7.1 PPO에서 나온 raw action

한 rollout step에서 PPO는 현재 관측을 Actor에 넣는다.

    obs[t]      shape [N,420]
    raw_action  shape [N,30]

30개 값은 아직 관절 각도나 torque가 아니다. 각 값은 해당 control DOF의
허용 범위 안에서 어느 쪽으로 목표를 둘지를 나타내는 정규화 값이다.

7.2 curriculum action mask

`FretTask.apply_actions()`는 raw action을 바로 base controller에 넘기지
않는다. 먼저 `policy_action_mask()`로 현재 curriculum 단계에서 학습할
관절만 PPO action을 사용하도록 한다.

`isolated_press` v2의 기본은 30D 왼손 action authority를 계속 유지한다.
기존의 `isolated_press_lock_after_frames=60`은 준비 60 frame이 끝나자마자
shoulder·elbow를 잠겨, pinky가 굽히며 생기는 프렛 방향 오차를 팔로
보정하지 못하게 했다. 현재 기본값은 `0`, 즉 시간 기반 lock
비활성이다. 큰 proximal 우회는 action mask 대신 proximal motion cost,
reference posture, joint/safety gate로 제한한다. 양수 lock을 다시 쓰려면
고정 시간이 아니라 유효 압현 영역에 안정적으로 도달한 readiness latch를
별도 검증해야 한다.

integrated_press 단계에서는 `integrated_press_action_permissions()`가
stage phase에 따라 proximal arm과 손가락 action을 점진적으로 unlock한다.
goal_pair 단계에서는 선택적으로 현재 손가락/들어오는 손가락만 PPO
log-probability routing 대상에 넣을 수 있다.

중요한 점은 action mask가 반드시 물리적으로 손가락을 고정한다는 뜻은
아니다. mask가 꺼진 action은 `prev_action`을 재사용하고, hover/release와
같은 물리 후처리는 계속 유지된다.

7.3 인접 손가락 synergy

`adjacent_finger_action_synergy()`는 현재 press와 다음 move를 보호하면서
비활성 인접 손가락에 작은 flexion action을 전달한다.

    active target finger movement
        → neighbor driver delta 측정
        → follower_allowed 확인
        → 작은 induced flexion 계산
        → max induced delta로 제한

현재 설정의 개념적 범위는 다음과 같다.

    coefficients              (0.20, 0.30, 0.40)
    min driver delta          0.05 deg
    full driver delta         1.00 deg
    max induced delta         3.00 deg

이 보정은 새로운 독립 정책이 아니다. Actor가 낸 action에 작은 물리적
손가락 연동을 더하는 deterministic postprocess다. 활성 press 손가락이나
곧 이동해야 할 손가락은 follower로 사용하지 않는다.

7.4 EMA smoothing

`GuitarEnvBase.apply_actions()`가 finite 검사와 EMA를 수행한다.

    safe_action = finite(action).clamp(-1, 1)
    executed_action =
        action_alpha * previous_executed_action
        + (1 - action_alpha) * safe_action

현재 Fret 기본값은 다음과 같다.

    action_alpha = 0.5

따라서 새 정책 action의 절반과 직전 실행 action의 절반이 섞인다.
EMA 결과는 `prev_action`에 저장되며, 다음 observation의
`O_history`가 된다.

7.5 action을 관절 목표로 변환

각 DOF의 hard range를 `ctrl_lo`, `ctrl_hi`로 두고 다음처럼 변환한다.

    ctrl_mid  = (ctrl_lo + ctrl_hi) / 2
    ctrl_half = (ctrl_hi - ctrl_lo) / 2

    pd_target = ctrl_mid + action_scale * executed_action * ctrl_half
    pd_target = clamp(pd_target, ctrl_lo, ctrl_hi)

현재 `action_scale=1.0`이므로 action -1은 lower limit,
action +1은 upper limit에 대응한다. 실제 runtime에서는
`fret_human_joint_profile.json`으로 사람 관절의 hard limit을 더 좁혀
사용할 수 있다.

7.6 PD torque와 PhysX

`GuitarEnvBase.step_physics()`는 다음 torque를 적용한다.

    tau = kp * (pd_target - q)
    tau = clamp(tau, -tau_limit, tau_limit)

각 DOF의 damping은 Isaac Gym drive에서 함께 작동한다. 이후 PhysX가
60Hz 한 control step 안에서 4 substep을 계산한다.

`net_contact_force_tensor`는 네 substep impulse를 합산하지 않고
`CC_LAST_SUBSTEP`으로 마지막 substep의 힘만 읽는다. 종전 기본값인
`CC_ALL_SUBSTEPS`를 쓰면 마지막 geometry와 중간 solver impulse가 섞여
실제 수 N 수준의 엄지 지지가 수만 N으로 보이는 계측 착시가 발생했다.
overlap 복구 속도는 `max_depenetration_velocity=10.0 m/s`로 명시한다.

하체 Hip/Knee/Ankle/Toe는 다음 세 겹으로 고정된다.

    1. seated pose 근처로 hard pinch limit
    2. 높은 armature와 solver damping
    3. 매 step 초기 pose로 state reinject

따라서 현재 Fret 학습에서 하체 action을 policy가 사용하지 않는다.

7.7 history에 저장되는 action

`O_history`에 들어가는 값은 다음이 아니다.

    - actor가 Normal에서 처음 sampling한 raw action
    - clamp 이전의 비정상 값

실제로는 curriculum mask, synergy, finite fallback, EMA를 모두 통과해
PD에 사용된 `prev_action`이다. 이 구분이 없으면 policy가 자신이 실제로
움직인 값과 다른 값을 다음 입력에서 보게 된다.


8. 한 control step의 실제 실행 순서

`FretTask.step(actions)`의 순서를 하나씩 적으면 다음과 같다.

8.1 정책 호출

    obs[t] : [N,420]
        → FretV2ActorCritic.act()
        → raw_action[t] : [N,30]

PPO는 이 action의 log probability와 Critic의 six-channel value도 함께
저장한다.

8.2 action 후처리

    FretTask.apply_actions(raw_action)
        → policy_action_mask()
        → isolated/integrated/goal-pair routing
        → adjacent finger synergy
        → GuitarEnvBase.apply_actions()
        → finite clamp + EMA
        → 30D PD target

8.3 물리 진행

    FretTask.step_physics()
        → q와 pd_target으로 torque 계산
        → torque limit 적용
        → PhysX simulate, 4 substeps
        → DOF/body/contact tensor refresh
        → locked lower body reinject

8.4 현재 goal snapshot

물리 step 직후 task는 현재 `frame_idx`의 goal을 복사한다.
이때 `fret`, `finger`, `barre`, `finger_event`가 reward 계산의 기준이
된다. 준비 구간이면 preparation delay를 finger_event의 시간 field에
반영하지만, 실제 song frame cursor를 임의로 이동시키지는 않는다.

8.5 finger geometry 측정

`FretReward.compute()`는 다음 순서로 손끝과 프렛 geometry를 계산한다.

    1. LH finger chain sample points 계산
    2. 기타 local frame에서 string/fret cell 위치 계산
    3. 손가락 segment를 여러 sample로 나눔
    4. target fret cell 안의 longitudinal/lateral/normal 오차 측정
    5. 손끝 distal 및 전체 segment의 press depth 계산
    6. press hysteresis 상태 업데이트
    7. designated finger, wrong press, no press 판정

현재 Fret reward의 주요 geometry 상수는 다음과 같다.

    fret cell의 target approach fraction      0.20 부근
    fingertip target clearance                 0.0155 m
    press on depth                            0.0010 m
    press off depth                           0.0005 m
    fingertip pad radius                      0.0063 m

on/off depth를 다르게 두는 hysteresis는 경계에서 contact가 한 frame마다
켜졌다 꺼지는 현상을 줄인다.

8.6 압현 성공 판정

활성 target인 한 줄에 대해 다음 조건을 확인한다.

    press_mask
        fret > 0
    designated_pressed
        target finger가 cell을 실제로 누름
    wrong_press == false
        다른 높은 프렛이나 NO_PRESS 위반이 없음
    position_inside
        프렛 cell 길이 방향 정규화 위치가 0.1~0.9 내부

    physical_press = designated_pressed & ~wrong_press & press_mask
    press_success  = physical_press & position_inside

바레가 비활성인 현재 계약에서는 target finger의 distal press를
중심으로 평가한다. `barre=true` 확장 시에는 해당 finger segment 전체를
사용할 수 있지만, 현재 bundle은 `allow_barre=false`다.

8.7 hold와 sustain

순간적으로 한 frame 접촉한 것만 성공으로 보지 않기 위해
`update_press_hold_state()`가 연속 성공을 추적한다.

    press_hold_min_frames   = 6 frame
    press_hold_full_frames  = 12 frame

60Hz 기준으로 각각 약 100ms, 200ms다. 동일한 fret/finger 목표가
유지되고 press_success가 연속이면 streak가 증가한다. target이 바뀌거나
한 frame이라도 압현이 끊기면 dropout이 기록된다.

같은 목표를 계속 누르는 sustain event는 `PressSustainTracker`가 별도로
누적한다. 따라서 F1이 높아도 hold dropout이 많으면 실제 연주용
압현 정책으로는 충분하지 않다.

8.8 metric과 goal cursor 전진

현재 frame을 평가한 뒤 다음 값들을 누적한다.

    - true positive / false positive / false negative
    - 손가락별 press success와 target count
    - no_press correct와 no_press total
    - wrong press
    - chord ready와 hold quality
    - press dropout
    - thumb support/readiness

그 다음 `FretGoalSequence.advance(live)`가 준비 중이 아닌 environment의
goal cursor를 한 frame 전진시킨다. 정적 practice stage에서는
`practice_remaining`을 줄이며 동일 target을 반복한다.

8.9 safety 검사와 종료

reward 계산 뒤에는 penetration, wrist, palm-down, finger-back,
thumb overforce, nonfinite, velocity blowup 등을 검사한다.

    정상 종료
        마지막 goal frame을 완료

    실패 종료
        잘못된 압현이 설정된 frame 이상 지속
        기타 관통 또는 엄지 overforce
        wrist/palm/finger-back safety 위반
        NaN/Inf 또는 velocity blowup
        목표를 완료하지 못한 timeout

실패 종료에는 `failure_termination_penalty`가 적용된다. 기본값은
`-25.0`이다. 마지막 goal과 timeout이 같은 frame이면 정상 완료로
처리할 수 있지만, safety failure가 함께 있으면 실패가 우선한다.

8.10 다음 observation과 자동 reset

현재 물리 snapshot과 다음 goal cursor로 `compute_observations()`가
다음 420D를 만든다. done environment는 terminal observation을 먼저
반환한 뒤 `reset_idx()`로 다음 episode 상태를 준비한다.

reset에서는 다음을 수행한다.

    - seated initial pose로 q 복원
    - velocity 0으로 복원
    - 기타 root snapshot 복원
    - prev_action과 pd_target 재설정
    - goal cursor와 hold/safety tracker 초기화
    - 한 번의 held physics step으로 rigid-body observation 정착

FretTask는 reset 직후 body transform이 이전 episode에 남지 않도록
settled reset observation을 캐시한다.
9. Reward는 무엇을 학습시키는가

9.1 reward의 단위

FretTask는 `reward[N,6]` 형태로 줄별 reward channel을 반환하고,
`value_dim=6`인 Critic을 사용한다. 전체 평균 하나만 즉시 계산하지
않는 이유는 어떤 줄/손가락에서 압현이 실패했는지 보존하기 위해서다.

`PPOTrainer`는 해당 곡에서 실제로 `fret != 0`인 supervised string의
reward weight를 사용해 Actor advantage를 구성한다. 곡 전체에서
영원히 DONT_CARE인 줄은 Actor 학습 weight에서 제외된다.

9.2 접근과 압현 reward

`tab2body/env/rewards/fret.py`의 `FretReward.compute()`가 다음을
조합한다.

    approach distance reward
        손끝이 target fret cell에 가까워질수록 증가

    press acquisition
        press depth 진행과 실제 press_success 조합

    fine alignment reward
        longitudinal, lateral, normal 오차를 함께 평가

    position quality
        fret cell 안의 유효 위치를 평가

    arch quality
        MCP/PIP/DIP 굽힘과 손가락 arch 형태를 평가

    press hold quality
        6/12 frame 지속 압현을 평가

거리만 가까우면 성공으로 인정하지 않는 이유는 손끝이 프렛 옆에
도착하거나 줄을 누르지 않은 채 목표를 통과하는 해법을 막기 위해서다.

9.3 프렛 셀 안의 위치

프렛 셀 안 위치는 `fret_position_quality()`와
`dense_fret_position_quality()`로 계산한다. 단일·다중 압현 모두
정규화 위치 `0.1 <= u_fret <= 0.9`를 같은 유효 영역으로 쓴다.
이 영역 안에서는 특정 점, 중앙, 0.20 지점에 추가 점수를 주지 않는다.
영역 밖에서는 가장 가까운 경계로 향하는 연속 gradient를 남기지만,
`correct press`로는 인정하지 않는다. 0.20은 접촉 전 reach 단계에서
사용하는 명목 approach target일 수는 있어도 압현 성공의 최적점은 아니다.

normal alignment도 단계별로 다르다. `coarse_reach`, `fine_reach`,
`chord_reach`는 현 위 hover clearance를 목표로 한다. 실제 압현을 다루는
`isolated_press`, `integrated_press`, `chord_fine_reach` 및 후기 stage는
pad가 string plane 안으로 들어가도 정렬 보상이 떨어지지 않는
one-sided press-compatible normal 오차를 사용한다.

9.4 wrong press와 NO_PRESS

`wrong_press_mask()`는 실제로 눌린 fret cell과 현재 goal을 비교한다.

    - 목표 fret보다 높은 fret을 눌러 막으면 wrong
    - NO_PRESS 줄에 압현이 있으면 wrong
    - DONT_CARE 줄은 현재 frame의 supervised 대상이 아님

wrong press가 발생한 target channel은 positive core reward를 받지 못하고,
wrong press penalty와 avoidance shaping이 적용된다. 후기 stage에서는
wrong press streak가 일정 frame 이상이면 episode가 종료된다.

9.5 엄지 support reward

엄지는 단지 손가락 action 중 하나가 아니라 기타 neck 뒤쪽을 지지하는
구조로 취급한다. `tab2body/env/rewards/thumb.py`와
`FretReward`는 다음을 사용한다.

    thumb approach
        thumb pad가 neck support 영역에 가까운지

    thumb geometry
        dx, dy, gap, in_region

    thumb contact
        LH:thumb_pad의 contact force와 hysteresis

    thumb compression
        proxy 안으로 과도하게 파고들지 않는지

    thumb press readiness
        target finger가 가까울 때 support가 실제 압현을 돕는지

thumb reward가 너무 강하면 policy가 압현보다 엄지 고정만 학습할 수
있으므로 press quality와 gate로 결합한다. 과도한 force나 compression은
penalty와 termination 대상이다.

9.6 release/hover와 전환 reward

현재 목표가 끝난 손가락은 무조건 손에서 멀리 튕겨내지 않는다.
`released_finger_hover_reward()`는 다음을 유도한다.

    - fretboard 근처의 안전한 hover
    - 다음 목표로 이동할 때만 필요한 outward motion
    - 이미 성공한 손가락의 arch/posture 보존

다음 목표에 접근하는 reward는 현재 press를 보호하는 조건부로 적용된다.
현재 press를 무너뜨리고 다음 목표만 빨리 향하는 행동은 좋은 전환으로
인정하지 않는다.

9.7 regularization과 safety penalty

다음 항목은 압현 성공률을 높이는 보조 신호 또는 안전 제한이다.

    - wrist target/radius reward
    - joint limit near diagnostic/penalty
    - finger arch/coupling reward
    - action saturation regularization
    - slip penalty
    - finger-back soft penalty
    - guitar penetration soft penalty
    - proximal motion penalty
    - smoothness reward/penalty

모든 항목이 매 stage에서 동일한 세기로 켜지는 것은 아니다.
`cfg.py`의 reward config과 curriculum stage에 따라 mask와 weight가
달라진다.


10. Fret curriculum은 어떻게 진행되는가

Fret의 curriculum 구현은 다음 두 파일이 중심이다.

    tab2body/learning/curriculum.py
        FingertipApproachCurriculum과 promotion gate

    tab2body/train_fret.py
        iteration마다 env와 log_std schedule 적용

현재 stage 목록은 다음과 같다.

    coarse_reach
    fine_reach
    isolated_press
    integrated_press
    chord_reach
    chord_fine_reach
    static_chord
    frozen_context
    goal_pair
    transition_window
    coverage
    integration
    full_song

10.1 coarse_reach

먼 거리의 목표로부터 왼손을 기타 neck 쪽으로 이동시키는 단계다.
초기에는 상세 press precision보다 target 접근 방향과 wrist/arm 자세를
먼저 학습한다.

10.2 fine_reach

손끝이 올바른 fret cell과 string 위치에 더 정밀하게 접근하도록 한다.
finger arch와 fine alignment의 비중이 증가하고, action mask를 통해
먼저 목표 손가락과 proximal action을 중심으로 학습한다.

10.3 isolated_press

한 번에 하나의 source finger/string 목표를 집중해서 누른다.
현재 곡에서 synthetic fret/string을 만들지 않고, source song의 실제
press frame을 선택해 반복한다.

기본 `isolated_press_lock_after_frames=0`으로 시간 기반 proximal lock은
비활성이다. pinky 압현에서는 shoulder/elbow 보정이 실제로 필요했고,
60-frame lock이 준비 구간 직후의 성공 geometry를 깨뜨렸다. proximal 움직임은
유지하되 posture/motion/safety 보상으로 불필요한 우회를 제한한다.

10.4 integrated_press

개별 손가락 press를 전체 왼손 경로에 다시 넣는다. 처음에는
proximal/finger action을 제한하고, 일정 iteration 이후 단계적으로
unlock한다. 현재 press를 유지하면서 다음 목표로 이동하는 전환을
학습한다.

10.5 chord_reach와 chord_fine_reach

여러 줄을 동시에 눌러야 하는 source chord를 다룬다.

    chord_reach
        여러 손가락이 동시에 target 영역에 접근

    chord_fine_reach
        contact, fine alignment, depth, completion gate를 정밀 조정

다중 압현은 평균값 하나만 높아도 성공으로 보지 않고, 가장 약한
손가락의 bottleneck과 전체 completion을 함께 본다.

10.6 static_chord

짧은 chord transition이 아니라 최소 약 0.20초 이상 유지되는 source
chord를 static context로 반복한다. `practice_available_chord_finger_sets`
카탈로그에 없는 임의 조합은 만들지 않는다.

10.7 frozen_context

곡의 특정 압현 상태를 고정해 손가락별 약점을 확인한다. 일정 비율은
평가 cohort로 남겨 adaptation이 쉬운 표본만 좋아지는 것을 막고,
나머지는 실패 손가락에 집중하는 recovery sampler로 사용한다.

10.8 goal_pair

현재 목표와 다음 목표의 관계를 학습한다.

    retention
        이미 잘 누른 손가락을 유지

    mixed
        유지하는 손가락과 이동하는 손가락을 섞음

    full
        짧은 sequence와 일부 full-song 구간 포함

현재 press를 유지하면서 incoming finger를 준비해야 하므로,
단일 static press checkpoint를 실제 곡 전환에 연결하는 단계다.

10.9 transition_window

1.0, 1.5, 2.0, 3.0초 수준의 source timeline window에서 여러 goal
변화를 연속으로 다룬다. transition 수가 점점 증가하고, 현재 압현을
보존하면서 다음으로 이동하는지 평가한다.

10.10 coverage, integration, full_song

    coverage
        곡의 서로 다른 finger/press 구간을 충분히 경험

    integration
        곡의 여러 구간을 연속으로 연결

    full_song
        처음부터 끝까지 original 60Hz goal timeline 평가

이 단계들은 단순한 한 frame press 성공이 아니라 곡 전체에서
손가락별 망각, NO_PRESS 위반, sustain dropout, safety failure를 함께
확인한다.

10.11 promotion과 recovery

iteration 하나의 평균만으로 stage를 올리지 않는다. 일반적으로 다음을
확인한다.

    - stage 최소 iteration 수 충족
    - 손가락별 evidence episode 확보
    - press/F1, no_press, wrong_press, sustain, dropout gate
    - thumb readiness/support와 safety gate
    - 연속 promotion window 통과

설정의 기본 promotion success rate는 0.80, promotion window는 3개다.
chord나 bridge stage는 별도의 더 엄격한 F1, sustain, failure rate gate를
사용한다. 특정 손가락이 약해지면 해당 손가락을 집중 sampling하지만,
다른 손가락을 계속 유지하는 retention 표본도 남긴다.

10.12 exploration std schedule

`train_fret.py`의 `training_iteration_callback()`은 policy log_std를
stage별로 조정한다.

    thumb base exploration
        초기 0.05 수준을 유지하다가 target std로 ramp

    chord acquisition
        여러 손가락 flexion/lateral 탐색 floor를 일시적으로 높임

    precision schedule
        압현 정밀도가 올라갈수록 일반 finger std를 점진적으로 낮춤

    focus finger
        현재 약한 손가락의 std를 별도로 높임

이것은 checkpoint 가중치를 매번 새로 만드는 것이 아니라,
학습 중 `model.log_std`를 curriculum 상태에 맞춰 제한하는 방식이다.
11. PPO 학습 반복

11.1 rollout 수집

`tab2body/learning/ppo.py`의 `PPOTrainer.collect()`가 기본 horizon
32 control step을 모은다.

    for t in range(horizon=32):
        action, logp, value = model.act(obs)
        next_obs, reward, done, info = env.step(action)
        obs[t]       = action을 만든 420D observation
        actions[t]   = 30D policy action
        logp[t]      = action의 log probability
        values[t]    = 6D critic value
        rewards[t]   = [N,6] environment reward
        dones[t]     = episode 종료 여부
        obs          = next_obs

기본 1024 env를 사용하면 iteration 하나에 다음 transition이 쌓인다.

    1024 env × 32 horizon = 32,768 transitions

`collect()`는 action mask와 FretTask가 제공하는
`policy_teacher_action`, `policy_teacher_mask`도 함께 저장할 수 있다.

11.2 six-channel advantage

`PPOTrainer.advantages()`는 각 reward/value channel에 대해
gamma와 GAE lambda를 적용한다.

    gamma       = 0.99
    gae_lambda  = 0.95

그 뒤 Actor advantage를 만들 때 `actor_reward_weights`를 사용한다.
Fret policy는 6개 줄 reward를 모두 같은 비율로 무조건 평균하지 않고,
현재 song에서 `fret != 0`인 supervised string을 중심으로 weight를
정규화한다.

11.3 PPO update 설정

`tab2body/cfg.py`의 기본 PPO 설정은 다음과 같다.

    horizon                         32
    epochs                           5
    minibatch_size                4096
    clip_ratio                    0.2
    value_coef                     1.0
    entropy_coef                 0.001
    actor_learning_rate          5e-6
    critic_learning_rate         3e-4
    max_grad_norm                 1.0
    target_kl                    0.03
    action saturation weight     0.01
    action saturation threshold  0.80
    action teacher weight        0.15

1024 env 설정에서는 rollout 32,768개를 minibatch 4,096개씩 8개로
나누고, PPO epoch 5회 동안 업데이트한다.

11.4 action teacher 보조 loss

FretTask는 성공한 압현 자세를 `success pose/action cache`에 저장할 수
있다. 현재 상태가 충분한 quality를 보이면 해당 cache에서 proximal 또는
finger action teacher를 만든다.

    current observation
        → 성공 pose/action cache 조회
        → teacher_action, teacher_mask
        → deterministic mean action과 masked distance 계산
        → PPO loss에 action_teacher_weight만큼 추가

teacher는 모든 환경에서 항상 활성화되지 않는다. 실패한 자세를 teacher로
복사하지 않도록 minimum pose quality, thumb quality, stage 조건을 확인한다.
따라서 PPO policy loss를 대체하는 supervised controller가 아니라,
이미 발견한 안정적인 자세를 다시 찾기 위한 보조 신호다.

11.5 action saturation regularization

엄지 base action 등 특정 action이 -1/+1에 붙는 현상을 진단하고
regularization한다. 목적은 관절 limit에 붙어서 압현하는 편법을 줄이는
것이다. 단, 실제 task에서 필요한 hard limit 접근 자체를 금지하는 것은
아니다.

11.6 observation normalization

`RunningMeanStd`가 rollout observation의 평균과 분산을 관리한다.

    normalized_obs =
        clamp((obs - mean) / sqrt(var + 1e-8), -5, 5)

평균, 분산, count는 checkpoint의 model payload에 같이 저장된다.
새 observation contract나 다른 곡의 goal로 checkpoint를 재사용할 때
RMS만 복사하면 안 되고 observation manifest와 goal contract도 함께
검증해야 한다.


12. 평가 지표

12.1 압현 정확도

Fret 평가 결과는 단일 평균 점수보다 다음을 함께 본다.

    press precision / recall / F1
        supervised press frame에서 올바른 압현 비율

    per-finger press rate
        index, middle, ring, pinky 각각의 성공률

    no_press_accuracy
        -1로 표시된 release/open 구간을 누르지 않은 비율

    wrong_press_rate
        잘못된 프렛 또는 금지된 줄을 누른 비율

    target_distance
        목표 cell까지의 거리

    press_depth / position_quality
        줄 안쪽 depth와 fret cell 위치 quality

F1이 높아도 특정 손가락이 거의 등장하지 않는 곡이면 네 손가락
정책이 모두 학습됐다고 볼 수 없다. `train_fret.py`는 시작 시
finger coverage와 stable chord coverage를 출력한다.

12.2 지속성과 전환

    press_hold_acquired_rate
        최소 hold streak를 얻은 비율

    sustain_hold_rate
        sustain 구간에서 압현을 유지한 비율

    sustain_event_success_rate
        sustain event를 전체적으로 완료한 비율

    press_dropout_rate
        유지 중 압현이 끊긴 frame 비율

    chord_ready_rate
        모든 active finger가 함께 준비된 비율

    mean_chord_hold_quality
        코드 내 가장 약한 손가락을 반영한 hold 품질

12.3 엄지와 물리 안전

    thumb_press_readiness
    thumb_support_rate
    thumb_support_stable_6 / stable_12
    thumb_wrong_contact_rate
    thumb_force_quality
    thumb_overforce_termination_count
    max_guitar_penetration_m
    finger_back_termination_count
    wrist_safety_termination_count
    palm_down_termination_count
    velocity_blowup_termination_count
    nonfinite_termination_count
    joint-limit usage
    action saturation fraction

일부 capsule overlap나 naturalness 지표는 현재 calibration 전까지
diagnostic-only다. 결과를 논문에 사용할 때는 실제 pass/fail gate와
진단 지표를 구분해야 한다.

12.4 정상 성공과 실패 종료 분리

평가에서 다음은 서로 다른 상태다.

    goal_finished
        마지막 goal frame까지 도달

    episode_success
        goal_finished이고 safety/performance failure가 없음

    failure_termination
        timeout 전 미완료, wrong press streak, safety, NaN 등

따라서 단순히 episode가 끝났다는 사실만으로 Fret 성공이라고 부르면
안 된다.


13. Checkpoint와 호환성

13.1 저장 위치

기본 run layout은 다음 구조다.

    fret/training/runs/<run_name>/
        run_metadata.json
        logs/training.log
        logs/metrics.jsonl
        checkpoints/fret_000500.pt
        checkpoints/fret_001000.pt
        evaluations/
        videos/
        plots/

주기적인 checkpoint 간격은 기본 500 iteration이고, rollout video는
`video_interval` 기본 1000 iteration마다 요청된다.

13.2 checkpoint payload

`PPOTrainer.save()`는 다음을 저장한다.

    iteration
    global_step
    model
        actor block encoder와 fusion layer
        critic block encoder와 fusion layer
        log_std
        obs_rms.mean/var/count
    optimizer
    training_context
        curriculum stage, stage iteration, sampler, exploration schedule
    environment_state
        goal sampler, success pose cache, runtime state
    checkpoint_contract
        goal과 observation/action 의미론 계약

13.3 checkpoint contract

`tab2body/train_fret.py`의 `build_runtime_checkpoint_contract()`와
`tab2body/learning/checkpoint_contract.py`가 다음을 봉인한다.

    task = fret
    observation contract = fret.observation.v2
    observation dimension = 420
    action dimension = 30
    value dimension = 6
    observation manifest 전체 field 이름과 순서
    controlled_dof_names 전체와 순서
    action_scale = 1.0
    action_alpha = 0.5
    reset_soft_limit_fraction
    goal file SHA-256
    hand target file SHA-256
    guitar/humanoid asset fingerprint
    human hard-limit profile SHA-256
    implementation fingerprint
    raw reward weights와 reward safety config
    PPO config
    sim_hz = 60
    sim_substeps = 4
    physics_contact_collection = last_substep
    physics_max_depenetration_velocity = 10.0
    model architecture version
    policy distribution version

따라서 420D tensor를 넣을 수 있다는 이유만으로 다른 곡이나 다른
관절 순서의 checkpoint를 바로 사용하면 안 된다.

13.4 resume와 initialize-from

일반 resume:

    --checkpoint <path>

    - model weight 복원
    - optimizer 복원
    - RMS 복원
    - curriculum/environment state 복원
    - 같은 goal SHA와 semantic contract 요구

새 run의 policy initialization:

    --initialize-from <path>

    - policy actor/log_std/RMS를 warm-start
    - critic와 optimizer는 기본적으로 새로 시작
    - curriculum/environment state도 새 run 기준
    - `--initialize-optimizer`를 명시할 때만 호환 optimizer를 추가 사용

현재 구현은 Fret-v1 weight를 Fret-v2 block encoder에 직접 복사하는
것을 허용하지 않는다. observation ABI를 바꾸려면 별도의 transfer 또는
distillation 절차가 필요하다.

15. 실제 frame 하나를 예로 이해하기

02_Jazz1의 첫 frame은 다음과 같다.

    fret_goal   = [0, 0, 6, 0, 0, 0]
    finger_goal = [0, 0, 3, 0, 0, 0]
    hand_anchor = 4
    allowed     = [3, 8]

Isaac 순서에서 세 번째 값은 G string이다. 따라서 이 frame의 의미는
다음과 같다.

    "G string의 6번 프렛을 약지로 누른다."

나머지 줄의 값 0은 DONT_CARE다. 현재 frame에서 그 줄의 press 여부를
성공/실패로 사용하지 않는다.

정책이 이 frame에서 받는 입력은 다음과 같다.

    - 왼팔 30개 q/qdot
    - L_Thorax와 손목/손바닥의 기타 상대 pose/twist
    - 네 손가락 끝과 엄지의 기타 상대 geometry
    - 현재 G-string/fret6/약지 target encoding
    - wrist target과 allowed radius
    - next finger event와 keep/move/rest 정보
    - 현재 press quality, wrong press, thumb readiness, phase, prev action

Actor는 다음과 같은 30D 값을 낸다.

    - shoulder 3D 변화
    - elbow 3D 변화
    - wrist 3D 변화
    - thumb 5D 변화
    - index 4D 변화
    - middle 4D 변화
    - ring 4D 변화
    - pinky 4D 변화

여기서 약지 action이 손끝을 target cell로 이동시키고, 엄지 action이
neck 뒤쪽을 지지하며, wrist/arm action이 전체 손 위치를 맞춘다.
그 결과 손끝 sample이 G-string의 fret6 cell 안에 들어가고,
press depth가 on threshold를 넘고, wrong press가 없고,
6 frame 이상 연속 유지되면 해당 frame은 압현 성공으로 기록된다.

반대로 손끝이 가까워도 다음 상황이면 성공이 아니다.

    - 다른 프렛을 누름
    - NO_PRESS 줄을 누름
    - target cell 옆으로 벗어남
    - depth가 충분하지 않음
    - press가 한 frame만 생겼다가 바로 풀림
    - 기타 관통 또는 safety 종료가 발생함

이렇게 계산된 reward와 value target이 PPO update로 되돌아가며,
다음 iteration의 Actor가 같은 상태에서 더 나은 30D action을 내도록
parameter가 조정된다.


16. 현재 Fret 구조에서 꼭 기억할 점

    1. Fret은 raw audio policy가 아니다.
       학습 runtime은 이미 만들어진 60Hz fret goal을 읽는다.

    2. 420D는 단순 joint state가 아니다.
       현재 event, 다음 event, fret geometry, hold, thumb, phase,
       history가 함께 들어간다.

    3. 30D action은 torque가 아니다.
       mask → synergy → EMA → PD target → torque → PhysX 순서가 있다.

    4. 압현 성공은 위치 하나로 결정되지 않는다.
       designated finger, depth, fine alignment, wrong press,
       hold/sustain을 함께 본다.

    5. 엄지는 별도의 안정화 역할이 있다.
       엄지 support가 부족하면 손끝이 가까워도 지속 압현 품질이 낮아질 수 있다.

    6. Fret checkpoint는 곡·goal·관절 이름·observation manifest에 묶인다.
       다른 곡에 바로 일반화된다고 가정하지 않는다.

    7. 현재 checkpoint는 G0 fixed guitar에서 학습된다.
       G1/G2에서 기타가 움직이면 guitar-relative observation 경로는
       재사용할 수 있지만, 물리 안정화와 공동 fine-tuning 검증이 별도로 필요하다.
