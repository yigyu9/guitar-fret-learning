# 왼손 fret 압현 규칙 처리 현황

> **상태: 2026-07-22 HISTORICAL STATUS.** 완료 표시는 현재 Fret-v2 구현 상태를 뜻하지 않는다.

상세 수식과 임계값은 [전체 규칙 명세](FULL_RULE_SPEC.md)에 있다. 아래 표는 미팅용 요약이다.

## 규칙별 현황

| 규칙 | 핵심 내용 | 상태 | 처리 방식 |
|---|---|---|---|
| R1 | 지정 손가락으로 목표 줄·프렛 압현 | 구현 | 접근 30% + 실제 압현 50% + 위치 품질 20% |
| R2 | 접근점과 좋은 압현 영역 분리 | 구현 | 접근점 20%, 좋은 위치 10~30%, 넓은 성공 범위 허용 |
| R3 | PRESS / NO_PRESS / DONT_CARE | 구현 | 매 frame 모든 줄·프렛 상태 파생, 오압현 시 해당 줄 점수 0 |
| R4 | DONT_CARE도 안전 규칙 준수 | 구현 | 정확도에서는 제외하고 관통·과압·관절 안전은 유지 |
| R5 | release 이후 목표 상태 전환 | 구현 | 재타현은 PRESS 유지, 이동 공백은 NP, 마지막 뒤는 DC |
| R6 | 엄지의 넥 후면 지지 | 구현 | 후면 접근·접촉 보상, 과도한 힘은 감점·지속 시 종료 |
| R7 | 손목 작업영역 이탈 방지 | 종료 구현 | 기타 로컬 안전 박스 밖 3 frame이면 종료 |
| R8 | 손가락이 넥 뒤로 과도하게 넘어감 | 종료 구현 | 일반 손가락 구간이 `z<-50mm`에서 3 frame이면 종료 |
| R9 | 아치형 손가락 선호 | 보류 | 단음·코드·바레의 정상 각도가 달라 단일 임계값을 두지 않음 |
| R10 | 과속·떨림·release 튐 억제 | 보류 | 압현 성능에 직접 중요하지 않아 자연스러움 단계로 이동 |
| R11 | 하체와 비제어 관절 잠금 | 인프라 구현 | limit, armature, 매 step PD target 재주입 |
| R12 | 손가락→손목→팔꿈치→어깨 우선 | 구현 | 목표 근처에서만 상위 관절 움직임에 더 큰 비용 부여 |
| R13 | 손바닥 안쪽이 바닥을 향하지 않음 | 종료 구현 | palm inward normal의 world-z가 기준 아래로 3 frame이면 종료 |
| R14 | 손·팔의 기타 관통 금지 | 구현+종료 | 충돌 필터, signed depth, swept 검사; 심각한 관통 지속 시 종료 |
| R15 | 현재·다음 목표와 타이밍 관측 | 구현 | 3시점 75D + 손가락별 13D×4 + 진행률 = 128D |
| R16 | Protected·인접 줄 접촉 회피 | 보류 | 단일 압현은 R3으로 처리; dyad·코드 단계에서 접촉 감점 검토 |
| R17 | idle·에너지 최소화 | R12 통합 | 별도 전역 energy 보상 없이 REST 원칙만 R12에 포함 |
| R18 | 해제 손가락이 멀리 튀지 않음 | 약한 보상 | 실제 압현 성공 후 30mm 자유, 초과분만 전체 0.5% 감점 |
| R19 | 손목 중립각 선호 | R21 통합·보류 | hard limit만 적용, soft range는 실제 분포 확보 뒤 결정 |
| R20 | 같은 위치 재타현 유지 | 구현 | fingermapping이 event를 병합하고 환경은 PRESS를 계속 보상 |
| R21 | 관절 hard limit·soft range | 부분 구현 | hard limit 완료, 자연스러운 soft range는 데이터 확보 전까지 보류 |
| R22 | 손가락끼리 관통 금지 | 진단만 | 마디 capsule 간 최소 간격·침투 깊이 기록, 보상·종료 없음 |
| R23 | 압현 중 손끝 미끄러짐 억제 | 약한 감점 | 안정 압현 뒤 2mm 자유, 초과 접선 이동만 전체 0.5% 감점 |
| R24 | 비정상 지지·과압 금지 | 진단만 | 손·팔 접촉력, 관절 토크, limit 비율 기록 |
| R25 | 코드 사전 준비와 ChordReady | 보류 | 현재 단일 압현 단계에는 strike timing 채널이 부족함 |
| R26 | 한 곡 반복 학습 커리큘럼 | 구현 | random start 숙달 → 전체곡 통합 → frame 0 전체곡 |
| R27 | PRESS를 순간이 아닌 지속 성공으로 평가 | 진단+평가 | 이벤트 유지율 90%, 연속 이탈 3 frame 이하를 최종 gate로 사용 |
| R28 | 누른 채로 fret 이동 금지 | 진단만 | MOVE 중 3mm 초과 confirmed drag를 기록 |
| R29 | 시작 전 첫 운지 준비시간 | 구현 | 60 frame 동안 첫 goal 접근 허용, 이후 곡 시간 진행 |

## 공통 메커니즘

| 항목 | 상태 | 내용 |
|---|---|---|
| M1 all-correct | 구현 | 모든 PRESS·NO_PRESS가 맞을 때만 전체 보너스 |
| M2 실패 종료 벌점 | 구현 | 안전 실패 종료에만 보상 채널 `-25`, 정상 완주에는 미적용 |
| M3 press 검출 | 구현 | pad signed depth, 올바른 fret cell, 목표 줄, 최고 fret 우선, hysteresis |

## 상태별 요약

- **핵심 구현 완료**: 정확한 압현, P/NP/DC, release, 엄지 지지, 안전 종료, 미래 목표 관측, 커리큘럼, 준비시간
- **약하게 적용**: 해제 손가락 hover, 압현 중 미끄러짐, 상위 관절 움직임 비용
- **진단만 적용**: 손가락 상호 관통, 비정상 지지·과압, 누른 채 이동
- **보류**: 아치형 각도, 속도·jerk, 인접 줄 뮤트, 관절 soft range, 코드 사전 준비

보류의 공통 이유는 정상 자세 분포나 다중 압현 데이터가 아직 부족하기 때문이다. 근거 없이 강한 보상이나 종료 조건을 넣어 올바른 압현 학습을 방해하지 않도록 했다.
