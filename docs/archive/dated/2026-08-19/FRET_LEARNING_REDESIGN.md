# Fret 학습 실패 분석과 재설계

> **상태: HISTORICAL REDESIGN RECORD.** 현재 Fret-v2 계약과 최신 커리큘럼 상태는
> [`fret/README.md`](../../fret/README.md)를 따른다.

## 결론

최근 학습 실패의 주된 병목은 단일 손가락 압현 자체가 아니라, 이를 다중
손가락 코드로 이전하는 과정이었다. BN3의 두 최근 실행은 `integrated_press`
끝에서 압현 성공률 0.86~0.91을 기록했지만 `chord_reach` 진입 직후 0으로
떨어졌다. 이후 `chord_fine_reach`를 약 4,000 iteration 수행해도 회복하지
못했고, `static_chord` 후반 성공률도 0.07~0.14에 머물렀다. 특히 3번 손가락은
거의 0인 반면 4번만 약 0.39~0.48이어서 한 손가락에 치우친 해법이 굳었다.

과거 성공 실행은 같은 전환을 회복해 최종 압현 성공률 0.73~0.91에 도달했다.
체크포인트의 실제 정책 분산을 비교하면 성공 정책의 굽힘 축 표준편차는 대체로
0.08 전후였지만 최근 BN3 정책은 정밀 코드 단계에서 거의 모든 손가락 축이
0.025로 제한됐다. 아직 공동 자세를 찾지 못한 상태에서 탐색을 약 3분의 1로
줄인 것이 코드 단계 정체와 일치한다.

## 변경한 학습 구조

1. `chord_reach`, `chord_fine_reach`, `static_chord`를 정밀화 단계가 아니라
   습득 단계로 분리했다. 이 구간에서는 굽힘 축 0.060, 좌우 축 0.040의 탐색
   하한을 유지하고, 집중 학습 중인 손가락은 0.080까지 보장한다.
2. 탐색 분산 감소는 정적 코드 숙련 뒤 `frozen_context`부터 1,500 iteration에
   걸쳐 0.035까지 수행한다. 따라서 성공 자세를 찾기 전에 분산이 닫히지 않는다.
3. 단일 손가락 단계에서 실제로 성공한 손가락 자세와 action을 `chord_reach`부터
   계속 보상·지도 신호로 사용한다. 커리큘럼 단계가 바뀌어도 이미 익힌 압현
   자세를 목적함수에서 제거하지 않는다.
4. 활성 손가락별 성공 캐시에 저장된 팔·손목 action을 품질 가중 평균으로
   합성한다. 손가락별 action 범위 차이가 0.35를 넘는 축은 서로 충돌한다고
   보고 teacher mask에서 제외한다. 이 teacher는 실제 action을 대체하지 않고
   PPO actor의 학습 loss에만 적용된다.
5. 코드 압현 완성도가 0.80 이상이면 proximal teacher를 끈다. 초기 탐색에는
   중심을 제공하지만, 최종 자세는 환경의 접촉·유지 보상을 통해 자유롭게
   정밀화할 수 있다.
6. action teacher weight는 0.05에서 0.15로 높였다. 유효한 캐시와 합의된 축에만
   mask가 켜지므로 캐시가 없거나 충돌하는 상태에는 추가 loss가 생기지 않는다.
7. 엄격한 chord 승급 기준을 만족하지 못한 채 다음 단계로 강제 이동하지 않는다.
   최소 기하·성공률도 확보하지 못하면 같은 조합을 계속 연습하고, static chord
   실패 시 실패한 코드 조합만 최대 3회 복구 학습한 뒤 재평가한다.

## 새 학습의 판정 기준

단순 평균 reward보다 아래 지표를 우선한다.

- `integrated_press` 종료 시 모든 사용 손가락 press success 0.80 이상
- `chord_fine_reach`에서 각 코드 조합의 p90 거리 10 mm 이하, alignment 0.80 이상
- `static_chord`에서 각 손가락과 각 코드 조합 성공률 0.80 이상
- 후기 단계에서 no-press accuracy 0.99 이상, wrong-press rate 0.01 이하
- sustain hold 0.90 이상, press dropout 0.05 이하
- 어느 한 손가락도 전체 평균과 크게 분리되어 0에 수렴하지 않을 것

평균 reward가 오르더라도 위의 최소 손가락·최소 코드 조합 지표가 개선되지
않으면 성공으로 보지 않는다. 새 실행은 checkpoint/curriculum schema 46을
사용하며 기존 체크포인트와의 호환을 목표로 하지 않는다.

## 검증

- Fret 보상, PPO teacher loss, 탐색 스케줄, curriculum 및 goal-pair CPU 회귀
  검사를 통과했다.
- BN3에서 기본 curriculum과 강제 `chord_reach` 각각 8개 GPU 환경, 4 step,
  PPO 1 update smoke를 통과했다.
- 실제 성능 판정은 새 설정으로 처음부터 장기 학습한 실행에서 위 지표를
  stage별로 비교해야 한다. 기존 checkpoint를 재개하면 탐색 축소 이후 형성된
  편향이 남으므로 새 학습을 권장한다.
