# 현재 J 학습 코드 가독성 정리

사용자가 실제 학습 코드를 읽기 쉽게 정리해 달라고 요청했다. 기본 진입점의32파일(구현24개·초기화8개)을 검토하고, 읽기 어려운 training6개와 GPU 측정·보상·제어6개에 집중한다. 파일을 추가로 나누거나 학습 동작을 바꾸지 않는다.

## 작업 순서와 검증

1. 기존 소스·검사·해설·SHA를 보관하고 현재 기준을 고정한다. → 검증: 이전 결과 기준과 현재 원문 차이를 확인한다.
2. 한 줄의 복합문을 풀고 긴 인자·조건·사전을 펼친다. J 기본과 song 공유 기반의 경계, N/M/표면표본 축, 상태 수명과 단위를 한글로 설명한다. PPO·정책·수집·runner의 오해하기 쉬운 지역명만 정정한다. → 검증: 포맷 AST 동일, 지역명 변경은 역치환 AST/직접 수치 비교, 모델·관측·계약·난수·부동소수 연산 순서 보존.
3. 전체 CPU와 정책/PPO/수집 동등성, 새 GPU 학습·엄격 재개·평가를 확인하고 문서 링크·해설·소스 SHA를 갱신한다. → 검증: 새 실패0, 동결 SHA, 별도 change-reviewer 검수.

## 변경 범위

- `training/launch.py`, `finger_skill_runner.py`, `rollout.py`, `policy.py`, `ppo.py`, `training_log_io.py`
- `gpu/environment.py`, `finger_skill_environment.py`, `contact.py`, `control.py`, `finger_reward.py`, `episode_diagnostics.py`
- 나머지 현재 곡·compiler·공용 기하/제어·초기 입력·native 코드는 충분히 구분되어 있으므로 필요한 근거만 확인하고 유지한다.

## 유지 조건

- 보상9개·실패 비용·손목 종료·관측557/이벤트24/우선8·J33/오른손0·노출25%·PPO 수식/미니배치 순서·reset/commit/오류복구 의미를 유지한다.
- 공개 함수 인자·모델 attribute·checkpoint/state_dict·로그키·schema 문자열을 바꾸지 않는다. 동일한 수학식처럼 보여도 연산 순서나 기하 표본 계통을 통합하지 않는다.
- 중복처럼 보이는 표면/접촉 표본과 준비 자세 계산은 시점·목적이 달라 임의 캐시·삭제하지 않는다.
- 보관본과 과거 결과를 수정하지 않는다. 이전 checkpoint의 source pin을 현재 값으로 고치지 않는다.
