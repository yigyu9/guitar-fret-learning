# GPU 물리 실패 원인과 영상

사용자 요청: 기존에는 거의 없던 물리 실패의 이유를 확인하고 영상으로 남긴다. 전환 결과 원자료와 활성 학습 코드는 보존하며 진단·영상은 별도 결과로 만든다.

- [x] 기존 CPU/GPU 실행의 실패 분포·초기화·물리/제어 차이 확인 → 동일 입력·무행동 기준과 구분
- [x] CPU 기준/소수 GPU/1024 GPU 무행동·초기 정책의 실제240Hz 상태 수집 → 소스 SHA·시계·실패 이유·원본 몸체 자세 저장
- [x] 저장된 실제 자세를 원본 메시로 영상화 → 재물리/자세 보정 없이 재생, 실패 시점·속도 명시, 화면 확인
- [x] 독립 검수·원인/미확인 사항·num-envs 권고 정정 → 원자료·영상·실행 설명 연결

가정: 이번 영상은 새로운 재현 실행이며 과거 benchmark에 카메라가 없었으므로 당시 영상이라고 표현하지 않는다. GPU 환경 수·무행동/정책 동작을 구분해 원인 범위를 좁힌다. 원인이 밝혀지기 전 실패를 정상 탐색이나 하드웨어 한계로 단정하지 않는다.

결과: CPU/GPU2 무행동2초 실패0, GPU1024 무행동2초817환경/1781실패. 새GPU경로의안정성회귀까지확인했으며정확한물리/제어내부원인분리는남아있다. 생산코드수정없이영상·원자료를저장했고128안정학습권고를철회했다. 추가초기정책CUDAassert재현은실패로보존하고영상입력에서제외했다.
