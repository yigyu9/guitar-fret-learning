### 역할과 읽는 순서

입력 Python 경로 수집, 파일 SHA 계산, 공통 JSON 저장을 담당한다. 모델과 물리 환경에 직접 의존하지 않는다. NumPy는 실수 포맷 또는 자료형 변환에 실제로 필요할 때 함수 안에서 import한다. Isaac Gym을 Torch보다 먼저 불러와야 하는 시작 순서를 불필요한 최상위 import로 깨뜨리지 않으려는 구성이다.

처음에는 [digest:92](/home/ajou/yigyu/3/guitar_learning/training/training_log_io.py:92)와 [write:100](/home/ajou/yigyu/3/guitar_learning/training/training_log_io.py:100)를 읽고, 입력 검증에 관심이 있으면 소스 경로 수집 두 함수를 읽는다. JSON 숫자 표현이 왜 일정해야 하는지 보려면 `_float_token`과 `_Dragon4Encoder`를 읽으면 된다.

### `digest`: 여러 파일이 함께 쓰는 파일 해시

`digest(path)`는 파일을 한 번에 메모리로 읽지 않고 1MiB씩 읽어 SHA256 문자열을 반환한다. 100MiB 입력은 약 100블록을 읽는다. 문자열 경로와 Path 모두 받는다. 내용이 1바이트만 달라도 해시가 바뀌므로, 계산에 영향을 주지 않는 소스 주석 변경도 입력 봉인에는 다른 소스로 보인다.

현재 코드·곡·초기화 입력·checkpoint의 원문 식별에 사용한다. “수학적으로 같은 코드”인지 판단하는 도구가 아니라 **저장된 실제 바이트가 같은지** 확인하는 도구다. 파일이 없거나 읽을 수 없으면 오류를 숨기지 않는다. GPU 기하·역사 입력·악보 입력의 파일 SHA도 이 공용 함수를 별칭으로 가져와 중복 계산 구현을 줄였다.

### `active_source_paths`: 무엇을 미리 봉인하는가

[active_source_paths:79](/home/ajou/yigyu/3/guitar_learning/training/training_log_io.py:79)는 주어진 디렉토리를 재귀적으로 읽어 `.py` 경로 집합을 만든다. 이름이 `archive`인 디렉토리는 건너뛰고 디렉토리 심볼릭링크 안으로 들어가지 않는다. 단일 실행에서 실제 import한 파일만 세는 함수가 아니다. runner는 학습 패키지의 활성 Python 전체를 미리 SHA 입력에 포함한다.

이 때문에 직접 학습하지 않는 도구나 검사 파일을 실행 도중 편집해도 현재 pin 정책에서는 소스 변경으로 잡힐 수 있다. “기본 학습 구현 24개”와 `inputs_before.json`의 더 큰 봉인 목록은 서로 다른 범위다.

### `_float_token`, `_Dragon4Encoder`, `dump/dumps`: 실수의 JSON 표현

[_float_token:22](/home/ajou/yigyu/3/guitar_learning/training/training_log_io.py:22)은 float 하나를 JSON 숫자 문자열로 만든다. 유한하지 않은 값은 allow_nan=False이면 거부한다. 0과 -0의 부호를 보존하고, 절댓값 1e-4 미만 또는 1e16 이상은 과학 표기, 나머지는 위치 표기를 쓴다. NumPy의 unique float 표기로 저장·재읽기에서 원래 실수를 표현할 수 있도록 한다.

[_Dragon4Encoder:37](/home/ajou/yigyu/3/guitar_learning/training/training_log_io.py:37)는 이 포맷을 JSON 인코더에 연결한다. 일반 C 인코더가 사용자 실수 포맷을 건너뛰는 것을 피하려고 Python 측 `_make_iterencode`를 사용한다. [dump / dumps:49](/home/ajou/yigyu/3/guitar_learning/training/training_log_io.py:49)는 표준 json의 동명 함수처럼 사용하되 별도 cls를 지정하지 않았으면 이 인코더를 기본으로 넣는다. `dumps`는 문자열을 반환하고 `dump`는 열린 스트림에 쓴다.

SHA나 계약 검증에는 JSON 표현 차이가 영향을 줄 수 있고 로그의 NaN은 분석을 불명확하게 만든다. 그래서 숫자 저장 규칙을 한곳에 모은다. 이는 보상 정규화나 반올림으로 학습값을 조절하는 기능은 아니다.

### `write`: 새 JSON 결과를 한 번 저장한다

`write(path,value,compressed=False)`는 새 파일을 `xt` 모드로 열어 JSON과 마지막 개행을 쓴다. 이미 파일이 있으면 실패하므로 원결과를 조용히 덮어쓰지 않는다. NumPy 배열은 list로, NumPy 스칼라는 Python 스칼라로 바꾸며 다른 미지원 객체는 TypeError로 거부한다. compressed=True이면 gzip 텍스트 파일을 쓴다.

부모 디렉토리를 자동 생성하거나 매번 fsync를 강제하지 않는다. 디렉토리 생성과 중요한 저널/checkpoint의 디스크 동기화는 runner와 같은 파일 뒷부분의 전용 기록기가 담당한다.

### 먼저 구분할 다섯 개 카운터

[TransitionJournal:141](/home/ajou/yigyu/3/guitar_learning/training/training_log_io.py:141)은 “관측했다”, “썼다”, “디스크에 확정했다”, “학습했다”를 한 숫자로 합치지 않는다.

| 카운터 | 증가 조건 | 아직 의미하지 않는 것 |
| --- | --- | --- |
| sampled | write에 행 전달. 인코딩 실패도 포함 | 로그 저장 성공 |
| logged | JSON 인코딩과 gzip 쓰기 성공 | 디스크 동기화·PPO 성공 |
| durable | gzip 구성원을 닫고 flush/fsync 완료 | PPO 반영 |
| committed | PPO 성공 뒤 호출자가 commit 호출 | 저널이 PPO를 실행한다는 뜻은 아님 |
| discarded | 수집했으나 이번 학습에 미반영으로 확정 | 원 로그 삭제 |

`unresolved_sampled=sampled−committed−discarded`다. 종료 정리에서 이 값을 discard로 처리해 수집했지만 배운 것으로 확정하지 않은 자료를 분리한다. `logged_not_committed`는 logged−committed여서 실패 실행에서는 0이 아닐 수 있다.

raw 행의 reward가 길이 N 배열이면 한 행을 N개 전이로 센다. 결정행은 reward 배열 대신 discounted_reward 스칼라를 가지므로 한 행을 1개 결정으로 센다. 같은 클래스를 써도 두 저널의 카운터 단위가 다르다. N=128/H32/K1이면 raw 저널 32행=4096개 전이, 결정 저널 4096행=4096개 결정이다.

### `iter_transitions`: 검증된 로그 앞부분만 읽기

[iter_transitions:279](/home/ajou/yigyu/3/guitar_learning/training/training_log_io.py:279)는 gzip 구성원 단위로 CRC 검증을 마친 뒤 그 안의 JSON 행을 내보낸다. 1MiB 이상 중간 자료는 임시 파일로 넘길 수 있는 SpooledTemporaryFile을 써서 큰 로그를 한 번에 메모리에 올리지 않는다.

## 4. 보상 로그를 읽는 작은 사례

128환경/H32를 모아4096개 전이를 PPO에 반영했다고 하자. metrics의 reward_component_means.song_left_contact=0.002는 이 update의 **실제 전이당 최초 접촉 보상 평균**이다. 수집창의 항목합은 평균×4096으로 환산할 수 있다. 한 음의 최초 접촉 예산이나 전체 에피소드 누계와 같은 값은 아니다.

그 update에서 에피소드 3개가 끝났다면 mean_left_success_count는 그 3개 종료 에피소드의 달성음 평균이다. 나머지 125환경의 진행 중 성공은 이 분모에 들어가지 않는다. 종료가 없으면 None이며 0개 달성으로 대체하면 안 된다. 에피소드별 기회 수·scope·실패 이유를 함께 봐야 분모 변화로 평균이 바뀐 것인지 구분할 수 있다.

raw 로그 4096개 전이가 생겼지만 PPO가 실패했다면 sampled/logged/durable은4096이어도 committed는0이고 정리 뒤 discarded는4096일 수 있다. 이를 “4096개 전이를 학습했다”고 보고하면 틀린다. 모델의 optimizer update 수와 저널 commit, metrics 행을 함께 확인한다.

## 5. 이 파일을 바꿀 때 영향

로그를 줄이려면 정본과 참조 관계부터 확인한다. episodes.jsonl만 지우면 raw·metrics 참조를 복원할 수 없고 episode_metadata.json만 지우면 분리한 고정 필드를 복원할 수 없다. raw 행 수는 환경 전이 수가 아니므로 행 수만으로 학습량을 계산해서도 안 된다.

SHA나 strict 검사를 완화하면 이전 모델을 열기는 쉬워져도 어떤 코드·물리·보상으로 학습한 모델인지 보장하는 의미가 사라진다. 현재는 새 실행을 별도 출력에 만들고 원본을 보존한다. Python 파일의 설명문(docstring)이나 주석을 편집해도 소스 SHA가 바뀐다. 학습 중 Python 소스 수정과 기존 checkpoint 재개는 구분해야 한다. 현재 설명은 파일 통합과 가독성 정리를 마친 소스를 기준으로 한다. 이번 정리는 기존 수식·상태557/이벤트24/우선8·J33·K1·노출25% 일정을 유지하며 환경·정책·재개 schema도 바꾸지 않는다. 다만 소스 바이트가 달라져 source pin은 바뀐다. 변경 전 checkpoint의 입력 SHA를 현재 코드에 맞춰 고쳐 쓰지 않으며, 현재 소스의 새 실행과 동일 소스·계약의 엄격 재개를 구분한다.
