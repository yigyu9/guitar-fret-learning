# 접촉 후보, 손가락 대기 보상, 엄지 안내와 진단

[전체 읽기 안내](/home/ajou/yigyu/3/docs/2026-11-02/코드해설/README.md) · [해설한 소스 기준](/home/ajou/yigyu/3/docs/2026-11-02/코드해설/소스기준.json)

이 문서는 `gpu/contact.py`, `gpu/finger_reward.py`, `gpu/episode_diagnostics.py`를 해설한다. 앞의 두 파일은 입력 텐서로부터 기하·보상률을 반환하고, 세 번째는 실제 에피소드에서 무슨 일이 있었는지를 고정 크기 누적기로 기록한다. **세 파일 어느 것도 정책 행동·관절 target·native 상태를 직접 바꾸지 않는다.**

추가 통합으로 표면·압현면·손목 영역도 `contact.py` 앞부분에 들어왔다. 회전·상대속도 공통 함수는 `control.py` 앞부분에 있다. 위치를 옮겼을 뿐 함수의 수치 계산, 보상·접촉 판정과 물리 설정은 바꾸지 않았다.

## 용어를 먼저 고정한다

| 이름 | 코드에서의 뜻 |
| --- | --- |
| 표면 접근 | 지정된 손가락의 끝마디 안쪽 패드에서 유한 압현 목표 선분까지의 거리. 접촉 전에도 계산 |
| `positive` | 위치·높이·패드 방향·해당 끝마디 하중을 동시에 만족하는 기하/하중 후보 |
| `wrong` | 현재 기본 v2 규칙에서 실제로 관측한 담당 패드 오류 또는 타 손가락 높은 프렛 경합 |
| `candidate` | 환경에서 만든 `positive & ~wrong` |
| clean | 두 인접 물리 끝점의 candidate가 모두 True인 구간과 발음 시간창의 겹침 |
| 최초 접촉 | `press..end`의 연속 candidate 시간이 최대50ms 문턱까지 진전하는 것 |
| 압현 유지 | `onset..end`에서 clean을 얼마나 오래 유지했는지 |
| 압현 달성 | 한 번의 연속 clean이 음별 required를 넘어서 latch된 상태 |

몸체의 합력만으로 “어떤 물체와 어느 점에서 닿았는가”는 알 수 없다. 코드의 접촉은 이 한계를 보완하기 위한 원본 메시 표면·목표 기하·몸체 하중의 대리지표다. `clean`이라는 변수 이름도 실제 현 압력·진동·소리의 인증으로 확대하면 안 된다.

## 1. `gpu/contact.py`: 유효한 패드 표면과 목표 셀을 정의한다

### 길어진 파일을 구역별로 읽는 방법

한 파일에 목표 기하와 그 기하를 평가하는 접촉 판정을 모았다. 파일 위에서 아래로 다음 순서다.

| 구역 | 주요 함수·상수 | 먼저 이해할 내용 |
| --- | --- | --- |
| 전체 표면과 목표 선분 | `surface_target_geometry`, `finger_mesh_surface_samples` | 10개 마디 전체 표본과 최근접 유한 선분 |
| 원본 넥 압현면 | `_extract_plane`, `_validate_targets`, `load_press_surface`, `project_press_strings` | 봉인 자산 검증, 목표가 놓일 평면·셀 |
| 악보별 손목 영역 | `_load_frames`, `_lower_edges`, `load_wrist_region_track`, `measure_wrist_region` | 상자 로딩·보간과 영역 밖 오차 |
| 검지~소지 지정 패드 | `FINGERTIP_TRACKING_CONTRACT`, `_clip_polygon`, `_sample_patch`, `load_fingertip_pad`, `pad_target_geometry`, `pad_tracking_reward` | 안쪽 패치와 거리·방향·하중 조건 |
| 엄지 후면 안내 | `THUMB_SUPPORT_CONTRACT`, `load_thumb_support`, `_smoothstep`, `thumb_support_geometry` | 유한 뒷면에서 동일 표본의 위치·법선·하중 |
| 오압현 출처 | `WRONG_PRESS_CONTRACT`, `pad_contact_cells`, `wrong_press_sources` | 허용 셀과 타 손가락 경합 |

앞의 세 구역은 [물리 장면·좌표 기하 해설](/home/ajou/yigyu/3/docs/2026-11-02/코드해설/05_물리장면과제어.md)에 자세히 설명했다. 접촉 의미를 먼저 알고 싶으면 아래 `pad_target_geometry()`부터 읽고, 목표 선분·손목 범위가 어디에서 왔는지 궁금할 때 앞 구역으로 돌아가면 된다. 손목 스키마는 `WRIST_REGION_SCHEMA`이며 패드·엄지·오압현의 계약 상수와 이름을 구분한다.

### 패드 로딩: 손등 전체에서 아무 점이나 고르지 않는다

원문: [_sample_patch](/home/ajou/yigyu/3/guitar_learning/gpu/contact.py:416), [load_fingertip_pad](/home/ajou/yigyu/3/guitar_learning/gpu/contact.py:486).

`load_fingertip_pad()`는 검지·중지·약지·소지의 `LH:*3` 끝마디 binary STL을 읽는다. XML에 적힌 mesh scale, geom quaternion과 위치를 적용한 **실제 삼각형 위**에서 점을 만든다. 새 충돌 메시나 가상의 구형 손끝을 추가하지 않는다.

원본 네 손가락은 마디가 −y 방향으로 뻗고 +x 축 굽힘으로 −z 쪽을 향한다. 로더는 이 좌표 정의를 `source_finger_frame_contract()`로 먼저 확인한다. 그다음 `_sample_patch()`가 다음 패치만 남긴다.

```text
u = (mesh_ymax - point_y)/(mesh_ymax-mesh_ymin)
point_z <= 0
u >= 0.25인 안쪽 면 중 normal_z <= -0.25
또는 u >= 0.75인 끝부분 중 normal_y <= -0.4, normal_z <= 0
```

이는 이 모델의 굽힘 안쪽과 인접 끝부분을 구분하는 공학적 정의다. 실제 사람 피부/손톱의 해부학적 라벨을 추정한 것은 아니다. `_clip_polygon()`이 삼각형을 경계 평면으로 자르고, 잘린 다각형을 다시 삼각형으로 나눈다. 경계 밖 꼭짓점까지 통째로 남기는 방식이 아니다.

잘린 면적의 CDF를 128개 같은 면적 층으로 나눠 삼각형을 선택한다. 점의 무게중심 좌표는 무리수 수열로 결정하여 난수 상태를 소비하지 않는다. 점 위치·단위 바깥 법선 외에 원본 삼각형 번호·barycentric·패치 면적·표본 간격도 계약에 저장한다. 같은 입력 자산이면 같은 128점이 나온다.

반환형의 핵심은 `points_local[4,128,3]`, `normals_local[4,128,3]`, `valid[4,128]`다. 로컬은 끝마디 몸체 좌표다. 매 물리 시각의 환경이 현재 몸체 pose로 이 점들을 G 좌표로 변환한다. 유한 표본이므로 실제 표면의 모든 접촉을 빠짐없이 잡는다는 보장은 없다.

### `pad_target_geometry()`: 거리 선택과 접촉 판정은 분리한다

원문: [pad_target_geometry](/home/ajou/yigyu/3/guitar_learning/gpu/contact.py:554).

입력 `points/normals/velocities`는 `[N,4,P,3]`, valid는 `[4,P]`, 투영된 현 시작/끝은 `[N,6,3]`, 목표 프렛 low/high는 `[N,M]`, loaded는 `[N,4]`다. 현 인덱스는 0~5, 목표 손가락은 검지1~소지4다.

함수는 담당 손가락별로 목표를 모아 계산한다. 전체 N×M×모든 손가락×P×xyz 텐서를 만들지 않고 현재 손가락의 목표·표본 크기만 계산하여 대규모 병렬 환경의 임시 메모리를 줄인다.

목표 현 선분의 y범위를 실제 프렛 경계에서 양쪽2mm씩 안으로 줄인다. 각 표면점을 선분에 투영하고 유한 범위로 clamp해 최근접점을 찾는다. 거리 최소점은 **valid만 고려**하며 방향이나 하중이 나쁘다고 다른 점으로 바꾸지 않는다. 이 선택을 기준으로 `delta=목표점-패드점`, `distance`, `velocity=-선택 패드점의 기타 상대 실제속도`, `sample_index`, `normal_cos`, `signed_height`를 반환한다.

별도로 모든 valid 패드점에 아래를 검사한다.

| 조건 | 수치 |
| --- | --- |
| 목표현 평면 내 가로 거리 | ≤3mm |
| 패드점 y | 프렛 경계 안쪽2mm 범위 |
| 압현 평면의 signed 높이 | −1mm~+3mm |
| 패드 바깥 법선과 압현면 안쪽 방향 cosine | ≥0.1 |
| 담당 끝마디 하중 | native 합력 크기≥0.01N |

`position_geometry`는 위치만 만족하는 점이 하나 이상인지, `facing_geometry`는 그중 방향까지 만족하는 점이 있는지, `positive`는 방향까지 만족하고 그 몸체도 loaded인지다. 위치는 점A, 방향은 무관한 점B에서 가져와 합치지 않는다. 같은 점에서 위치와 방향을 만족해야 한다.

예를 들어 표면 최근접점이 1mm이고 법선이 손등 방향이면 거리는 여전히 작게 관측된다. 하지만 같은 담당 패드에 조건을 만족하는 다른 점이 없다면 positive는 False다. 반대로 최근접점과 별개의 패드점이 모든 접촉 조건을 만족할 수는 있다. “가장 가까운 점의 법선이 나쁘면 모든 접촉 실패”라는 판정도 아니다.

### 현재 기본의 접근 보상과 옛 tracking helper

원문: [pad_tracking_reward](/home/ajou/yigyu/3/guitar_learning/gpu/contact.py:645).

이 helper는 공유 `finger_tracking_reward()`의 선택기·거리식을 재사용하되 candidate 가산을 중립화하고 가까운 영역에서만 방향을 최대20% 줄인다. `tracking_weight`도 손가락마다 곱한다. velocity·action은 모양 검사에 쓰며 움직임 비용으로 쓰지 않는다.

공유 v22 `substep()`에서는 이 함수를 여전히 계산하지만, **현재 J 환경의 최종 9항에는 별도 `song_finger_tracking`이 없다**. 현재 목표 패드 접근은 `FingerSkillEnvironment._surface_potential()`의 PBRS다. 이 둘의 수식을 더해서 현재 접근 점수라고 설명하면 중복이다.

### 엄지 패드는 다른 네 손가락 좌표를 그대로 적용하지 않는다

원문: [THUMB_SUPPORT_CONTRACT](/home/ajou/yigyu/3/guitar_learning/gpu/contact.py:674), [load_thumb_support](/home/ajou/yigyu/3/guitar_learning/gpu/contact.py:692).

엄지 원본은 −x로 뻗고 +z로 굽힌다. 로더가 thumb2/3의 위치축·회전·힌지축을 검증하고, 좌표를 순환 회전 `canonical(x,y,z)=body(z,x,y)`하여 공유 패치 선택기를 쓴 뒤 다시 몸체 좌표로 돌린다. 그냥 검지의 −z 안쪽 조건을 엄지 STL에 그대로 적용하지 않는다.

후면 목표는 실제 face가 참조하는 **연주용 neck1 뒷면**의 유한 사다리꼴이다. 사용되지 않는 OBJ 정점이나 후면 평면이 다른 neck2 headstock 전이를 섞지 않는다. 실제 뒷면은 네 꼭짓점·두 y수준의 사다리꼴인지와 같은 평면인지 확인하고 자산 SHA를 계약에 기록한다.

### `thumb_support_geometry()`: 같은 한 점의 위치·방향·하중으로 보상률을 고른다

원문: [thumb_support_geometry](/home/ajou/yigyu/3/guitar_learning/gpu/contact.py:779).

입력은 현재 G 좌표의 엄지128점/법선 `[N,P,3]`, valid[P], 작업 중심 y[N], 뒷면 꼭짓점[4,3]·plane[4], 선택적 엄지 native 합력 `[N,3]`이다. `center_y`는 현재 손목 안내 상자의 Gy 중심에서 온다.

작업 중심±4cm를 실제 neck1 길이로 자른다. 그 높이에서 사다리꼴 좌우 경계를 보간한 뒤 넥 폭의 **중앙50%**만 목표로 쓴다. 이 유한 영역을 두 삼각형으로 만들고 각 엄지점의 최근접점·평면 signed gap·평면 내 영역 초과거리·방향 cosine을 계산한다.

기하 품질은 다음 네 요소의 곱이다.

```text
거리 품질 = (1 + max(gap-0.003,0)/0.02)^(-2)
침투 억제 = smoothstep((gap+0.001)/0.001)
방향 품질 = smoothstep(facing/0.8)
영역 품질 = (1 + region_excess/0.02)^(-2)
q = 거리 × 침투 억제 × 방향 × 영역
```

smoothstep은 입력을0~1로 자르고 `x²(3−2x)`를 반환한다. gap0~3mm가 거리 최고 구간이며 −1mm보다 깊으면 침투 억제로 품질0이다. 영역 밖이라도 갑자기0이 되기보다 2cm 척도로 부드럽게 약해진다. 패드가 후면을 바라보는 방향도 같은 선택점에서 검사한다.

엄지 접촉 candidate에는 더 좁은 조건을 쓴다: 같은 점의 gap −1~+0.5mm, 영역 excess≤1e−6m, facing≥0.1, 엄지3 native 합력의 **후면 바깥 법선 성분**≥0.01N. 단순 힘 크기가 아니라 `max(0,F_G·rear_normal)`이다. 합력을 생략하거나 비유한이면 접촉 가산은 꺼지고 기하만 계산한다.

```text
rate = 0.01/초 × q + 0.01/초 × q × contact_candidate
```

최고 품질 근접만이면 최대0.01/초, 같은 점의 접촉 대리지표까지 만족하면 최대0.02/초다. 하중이1N이라고0.01N보다 더 많은 가산을 주지 않는다. 과도한 누름을 보상으로 유도하지 않기 위한 binary 조건이다.

표본 선택은 최대 rate→최대 quality→유한 영역 최근접거리 순이며 완전 동률만 첫 표본이다. 가장 가까운 점 하나의 gap과 다른 점의 좋은 법선을 섞어 반환하지 않는다. 무효 표본은 유한한0과 valid=False로 반환한다. 반환값에는 선택점·법선·delta·signed_gap·normal_load·rate·contact_candidate가 함께 들어 있어 관측과 진단이 같은 증거를 읽는다.

엄지를 넥에 붙이는 상태 setter나 강제 스프링이 아니다. 정책이 팔·엄지 target을 움직여 좋은 기하를 만들도록 유도하는 작은 보상이다. 실제 기타 지지 분담이나 접촉쌍/압력을 측정했다는 뜻도 아니다.

### 현재 오압현 v2: 없는 접촉을 오압현으로 추정하지 않는다

원문: [WRONG_PRESS_CONTRACT](/home/ajou/yigyu/3/guitar_learning/gpu/contact.py:882), [pad_contact_cells](/home/ajou/yigyu/3/guitar_learning/gpu/contact.py:896), [wrong_press_sources](/home/ajou/yigyu/3/guitar_learning/gpu/contact.py:921).

`pad_contact_cells()`는 목표와 독립적으로 실제 담당 끝마디 패드가 어느 현·프렛셀에 닿은 후보인지를 분류한다. 압현면으로 현을 투영하고, 유일하게 가장 가까운 현인지, 프렛 안쪽2mm인지, 3mm 가로/−1~3mm 높이/방향/하중 조건을 검사한다. 현 사이 동률·프렛 경계처럼 애매한 점을 확정 오압현 셀로 만들지 않는다.

`wrong_press_sources()`는 목표별 `[N,M] wrong`과 몸체10개×원인3개의 `[N,M,10,3] flags`를 반환한다. 현재 원인은 다음 세 가지다.

| 원인 | 실제 기준 |
| --- | --- |
| `other_higher` | 다른 손가락(엄지 포함)의 loaded 전체2/3마디 표본이 목표현의 더 높은 확정 프렛에 있음. 담당 positive가 있어도 차단 |
| `own_wrong_fret` | 담당 손가락의 facing·loaded 끝마디 패드가 같은 현의 허용되지 않은 다른 프렛에 있음. 담당 positive가 없을 때만 |
| `own_wrong_string` | 담당 손가락 패드가 허용되지 않은 다른 현에 있음. 담당 positive가 없을 때만 |

현재는 **다른 손가락이 같은/낮은 프렛에 있는 것만으로 오압현을 주지 않는다**. 담당 올바른 패드가 있으면 그 손가락의 부수적인 다른 샘플 때문에 무효화하지 않는다. 또한 같은 담당 손가락의 동시에 발음 중인 선택 목표 셀은 `active_grid`에 넣어 허용한다. `scope`를 이용하므로 구간 밖 음을 임의로 수행해야 하는 것도 아니다.

예를 들어 검지 목표가2번현5프렛인데 중지가 같은현7프렛에 loaded되어 있으면 other_higher다. 중지가3프렛에 있는 것만으로는 이 규칙의 오압현이 아니다. 검지의 올바른 positive가 없고 검지 패드가3번현5프렛에 있다면 own_wrong_string이다. 검지가 어느 곳에도 loaded되지 않은 채 멀리 있으면 wrong이 아니라 missing으로 이어진다.

`active_grid`·`future_grid`는 현×프렛×손가락의 작은 격자다. 모든 목표×미래 목표 조합을 크게 만들지 않고 현재 허용 셀과 다음 준비 셀을 조회한다. 미래 음 준비와 겹친다는 `next_preparation`은 **진단 표지일 뿐 현재 경합 면제는 아니다**.

오압현 기하는 물리 양 끝점에서 계산하고 실제 감점 시간은 환경이 발음 겹침 구간에 사다리꼴 적분한다. 소스3개·몸체 여러 개가 동시에 True여도 `wrong = any()`라 같은 목표의 감점을 원인 수만큼 곱하지 않는다. 출처 시간끼리는 겹칠 수 있으므로 원인별 시간을 더해 총 wrong 시간을 만들면 안 된다.

### `finger_target_indices()`: 손가락마다 지금/다음 목표를 뽑는다

원문: [finger_target_indices](/home/ajou/yigyu/3/guitar_learning/gpu/finger_reward.py:23).

입력은 now[N]와 onset/end/press/finger[M], 선택적 mask[N,M]이다. 반환은 `indices long[N,4,2]`, `valid bool[N,4,2]`이며 invalid index는−1이다. 네 손가락 순서와 마지막 축 tracking/next는 관측 priority와 접근 보상이 공유한다.

tracking은 우선 자기 담당 중 현재 발음되는 음에서 end가 가장 이른 것을 고른다. 없으면 `press−2 <= now < end` 준비/진행 창에서 onset이 가장 이른 음을 고른다. next는 tracking과 다르면서 미래 onset인 음 중 가장 이른 것이다. 동률이면 원곡 순서다. 목표 배열을 수정하거나 달성한 음을 별도로 지우지 않는다.

이 때문에 여러 음이 같은 손가락에 몰려도 접근 potential에 그 손가락의 모든 음을 동시에 합하지 않는다. 반대로 손가락 4개가 각각 목표를 가지면 최대4개 tracking을 동시에 반영할 수 있다. 목표 없는 손가락은 valid=False라 접근에0이다.

`finger_tracking_reward()`는 이 선택기를 사용하는 옛 순수 보상률 함수다. 거리품질 `(1+d/0.04)^−2`, candidate 가산, 현재 곡 등장 손가락 분모를 가진다. `contact.pad_tracking_reward()`가 이를 조정하여 공유 v22에서 사용하지만 현재 최종9항에는 별도 tracking이 없다. 함수가 남아 있는 이유와 실제 최적화 사용을 구분한다.

### `finger_posture_reward()`: qpos를 그대로 MCP/PIP/DIP라고 부르지 않는다

원문: [finger_posture_reward](/home/ajou/yigyu/3/guitar_learning/gpu/finger_reward.py:122), [_verify_source_frames](/home/ajou/yigyu/3/guitar_learning/gpu/finger_reward.py:324), [source_finger_frame_contract](/home/ajou/yigyu/3/guitar_learning/gpu/finger_reward.py:352).

입력은 손바닥 quaternion[N,4], 손가락4×마디3의 quaternion[N,4,3,4]다. 각 child를 parent 기준으로 회전시킨 뒤 원본 전방 `(0,−1,0)` 벡터를 얻는다. 이를 굽힘축+x에 수직인 yz면에 투영하여 다음 실제 기하 굽힘각을 구한다.

```text
relative = inverse(parent_q) × child_q
direction = rotate(relative, [0,-1,0])
angle = atan2(-direction_z, -direction_y)
```

MCP는 palm→finger1, PIP는finger1→finger2, DIP는finger2→finger3다. native 구면관절 qpos의 한 열을 MCP각으로 이름만 바꾸지 않는다. 특히 MCP의 x/z 동시 회전은 기하 굽힘과 입력 x가 정확히 같지 않다.

quaternion이 비유한·0이거나 yz투영 길이가1e−6보다 작으면 해당 joint valid=False다. 한 손가락의 joint 하나라도 무효면 그 손가락 품질은0이다. 무효각0을 곧 잘 펴진 자세로 보상하지 않도록 한다.

이 함수는 옛 coordination/넓은 standby 품질도 반환하지만 현재 B 보상은 아래 함수가 재계산한다. 옛 coordination 식이 존재한다고 기본에서 관절 비율 제약을 강제하는 것은 아니다. `source_finger_frame_contract()`는 원본 XML의 palm/finger 체인·identity rest 회전·−y 오프셋·+x 굽힘축을 시작 시 검증하고 SHA를 기록한다. 특정 원본 손 모델용 식을 임의의 손 자산에 일반화하지 않는다.

### B는 도달해야 하는 관절 명령이 아니라 약한 허용대 선호다

원문: [B 준비 기준](/home/ajou/yigyu/3/guitar_learning/gpu/finger_reward.py:168), [finger_recovery_config](/home/ajou/yigyu/3/guitar_learning/gpu/finger_reward.py:181), [finger_preparation_reward](/home/ajou/yigyu/3/guitar_learning/gpu/finger_reward.py:282).

사용자가 고른 B의 입력 굽힘각은 아래와 같다. 단위는 degree다. spread는 준비 비교 자세의 MCP z입력이며 현재 reward에 별도 spread 목표를 강제하지 않는다.

| 손가락 | MCP 입력x | PIP | DIP | 비교자세 spread z |
| --- | ---: | ---: | ---: | ---: |
| 검지 | 25 | 35 | 12 | −14 |
| 중지 | 28 | 38 | 14 | −3 |
| 약지 | 31 | 41 | 16 | 3 |
| 소지 | 34 | 44 | 18 | 10 |

실제 비교 기준 `B_PREPARATION_ANGLES_DEGREES`의 MCP는 위 x/z 동시 회전을 같은 투영식으로 변환한 값이다. 표의 MCP 입력x 자체와 비교하지 않는다. PIP/DIP는 같은 값이다.

현재 기하각과 기준각 차이에서 ±15° 허용대 안은 품질1이다. 밖으로 나간 정도를30° 척도로 부드럽게 줄인다.

```text
outside_j = max(abs(actual_j-reference_j)-15°,0)
quality = 1 / (1 + Σ outside_j²/(30°)²)
per_finger_rate = standby_rate × gate × quality / 4
rate = 네 손가락 per_finger_rate 합
```

기본 `standby_rate=0.02/초`다. 한 손가락만 완전 gate1·품질1이면0.005/초이며 네 손가락 합이0.02/초다. reward는 양성 선호이지 B를 벗어났을 때 별도 음성 벌점이 아니다. 엄지는 이 prior에서 제외된다. 입력 텐서·관절 target·reset을 바꾸지 않아 압현 자체를 위한 제어 움직임을 강제하지 않는다.

`finger_recovery_config()`는 지원 옵션을 정확히 검사한다. 기본 standby0.02, shape0이다. 일부 전문 비교에서는 standby0.04 또는 shape0.004를 지원하지만 **현재 기본 CLI는 기본 계약을 제한**한다. “지원된다”와 “지금 활성이다”는 다르다.

### `finger_preparation_gate()`: 손가락별로 다른 쉬는 시간을 적용한다

원문: [finger_preparation_gate](/home/ajou/yigyu/3/guitar_learning/gpu/finger_reward.py:238).

시간창은 각 담당 손가락의 음만 본다. 자기 `press..end` 하나라도 진행 중이면 gate0이다. 이전 음 끝과 다음 press 사이의 gap에 따라 준비·회복을 다음처럼 정한다.

```text
amount = clamp((gap-0.25)/0.35,0,1)
lead = gap<0.6이면 0.4×gap, 그 밖에는0.35초
releasing = clamp((now-previous_end-0.05)/0.1,0,1)
preparing = clamp((next_press-now-lead)/0.1,0,1)
idle = amount × releasing × preparing    (active이면0)
tracking_weight = 1-idle
```

gap≤0.25초면 완전 대기 복귀를 요구하지 않고 바로 다음 압현을 준비한다. 중간 gap0.25~0.6초는 amount가0~1이라 부분 회복이며, 충분한 gap에서는 release 이후50ms 유예+100ms fade를 거쳐 대기를 켜고 다음press350ms 준비+100ms fade 전에 줄인다. 첫/마지막의 무한 간격에는 통상 lead0.35와amount1을 사용해 inf−inf를 피한다.

예를 들어 자기 음이5.0초에 끝나고 다음 press가6.0초면5.05부터 fade 시작,5.15 이후 완전 대기 가능,5.55부터 다음 준비 때문에 약해져5.65에는 gate0이다. 다른 손가락이 이 사이 압현 중이어도 자기 대기 gate가 같이0이 되지는 않는다.

현재 contact_veto와near_veto는 False다. 과거 잔여 candidate/wrong이나 단순 근접 때문에 음 사이 B 복귀가 영원히 차단되지 않도록 한 것이다. 다만 자기 관련 목표 거리의 비유한은 해당 손가락을 무효화한다. 빈 곡은 gate0으로 두어 “아무 할 일도 없는 곡” 자체로 보상을 만들지 않는다.

현재 관측의 standby_gate도 환경이 마지막 240Hz에 계산한 같은 gate를 읽는다. 관측을 호출할 때 타이머를 별도로 진행시키거나 판정을 새 기준으로 바꾸지 않는다. `tracking_weight=1-idle`은 대기 gate의 비유한 veto와는 별도로 score-only idle의 반대값이다.

### `LeftEpisodeDiagnostics`: 대기·각도·손목·엄지를 누적한다

원문: [LeftEpisodeDiagnostics](/home/ajou/yigyu/3/guitar_learning/gpu/episode_diagnostics.py:206), [physics](/home/ajou/yigyu/3/guitar_learning/gpu/episode_diagnostics.py:299), [thumb_physics](/home/ajou/yigyu/3/guitar_learning/gpu/episode_diagnostics.py:368), [control](/home/ajou/yigyu/3/guitar_learning/gpu/episode_diagnostics.py:415), [episode](/home/ajou/yigyu/3/guitar_learning/gpu/episode_diagnostics.py:429).

`reset(indices)`는 해당 행의 누적기·run·초기 품질 기준만 지운다. min은 +inf, max 일부는−inf로 초기화하고 실제 sample이 없는 통계는 종료 출력에서0/별도 분모로 표현한다. `set_reset_posture()`는 에피소드 t0의 유효 B 품질을 한 번 저장한다. H32의 시작마다 기준을 다시 잡지 않는다.

`physics()`는 매1/240초 다음을 누적한다.

* 손가락별 gate>0시간, gate 자체 적분, quality 적분, raw 대기 보상.
* active로 막힌 시간, fade 시간, 비유한거리·무효각 등의 제외 시간. 여러 flag는 겹칠 수 있다.
* gate>0 및gate==1 run의 횟수·길이·B밴드 점유. 0.5/1/3초 이상 run은 따로 집계한다.
* 실제 press 중과 B gate 가중 idle 중 MCP/PIP/DIP의 평균·최소·최대. 분모는 각 joint의 유효 가중 초다.
* 손목 박스 내부 시간과 축별 절대 초과오차의 평균·최대.
* 검지형/소지형/끝마디 과대 조합의 실제 기하 flag.

극단 조합은 `MCP<−20°, PIP>60°, DIP>60°`, `MCP>75°, PIP>75°, DIP<10°`, `DIP−PIP>50°`다. 플래그끼리는 겹칠 수 있고 anatomical 안전 인증이나 현재 종료 조건은 아니다. 여기서 extreme의 idle은 **자기 press..end 밖**이라는 뜻이며 B gate==1과 같지 않다.

`thumb_physics()`는 새 엄지 helper의 동일 선택점 자료를240Hz로 누적한다. valid/near/contact_candidate 시간, gap·facing·영역초과, 후면 normal load, native force 크기, 침투 방향 gap시간, raw 보상을 기록한다. near_geometry이지만normal load<0.01N인 `nearbutunloaded_s`는 “위치는 왔는데 접촉 가산이 안 되는가”를 구분한다. 힘 방향이 틀린지, 아예 하중이 없는지를 영상만 보는 것보다 구체적으로 확인할 수 있다.

4개 표본의 raw 보상을 임시 `tick_standby/tick_thumb`에도 모은 뒤 `control()`에서 완료tick 실패 여부와 계수를 적용한 weighted_reward를 누적한다. 실패tick의 양성을 실제 환경과 같이 억제한다. 현재 기본 approach계수는1이므로 최종 대기·엄지 항과 비교할 수 있다. 원시 보상률 적분과 실제 지급액을 섞지 않는다.

`episode()`는 표본 초와 endpoint 개수, 평균의 분모, evaluable 여부를 함께 반환한다. 예를 들어 gate_weighted_s가 거의0인데 raw reward가 작다면 자세가 나빠서라기보다 보상을 줄 시간이 없었을 수 있다. gate가 충분하고 quality도 높지만 actual이 거의 안 움직였다면 이미 B 허용대 안이었을 수 있다. 대기 reward가 있다는 사실만으로 능동 복귀가 검증되지는 않는다.

### `FingerRecoveryWindows`: 정책이 분모를 줄이지 못하게 고정 창을 쓴다

원문: [FingerRecoveryWindows](/home/ajou/yigyu/3/guitar_learning/gpu/episode_diagnostics.py:93).

원곡의 자기 press..end 합집합을 만들고 겹친 음을 합친 뒤 회복 진단창을 잡는다. 이전 음끝+0.05초 release+1.0초 임시 복귀 예산 이후부터 다음press−0.35초 전까지다. 처음은1.05초부터, 마지막은곡끝까지다. 길이0.5초 이상 창을80% B밴드 점유 평가에 사용한다.

분모는 미리 정한 창의 길이다. 실패로 일찍 종료했다고 관측한 짧은 부분만 분모로 줄여 점유율을 높이지 않는다. `coverage_fraction`, `complete_windows`, 미관측 창 수를 같이 남긴다. 안정적 밴드 진입은0.2초 연속으로 확인하고 legacy `return_within3s`는 **진단창 시작 이후3초**를 뜻한다. 음을 뗀 직후3초라는 뜻이 아니다. 1초 복귀 예산 역시 검증된 인간/로봇 최대 복귀시간 보장이 아닌 비교용 고정 값이다.

현재 finger-skill은 원래 전체곡용 recovery를 그대로 쓰지 않고 `LeftEpisodeDiagnostics(count,device)`로 일반 각도·손목·엄지 진단만 유지하고, 구간 교차 recovery는 아래 `SkillEpisodeDiagnostics`가 담당한다. 따라서 현재 결과에서 옛 클래스의 optional recovery가 항상 나와야 하는 것은 아니다.

### `decompose_pad_motion()`: 팔이 옮긴 점과 손가락 자체 움직임을 나눈다

원문: [PadMotion](/home/ajou/yigyu/3/guitar_learning/gpu/episode_diagnostics.py:530), [decompose_pad_motion](/home/ajou/yigyu/3/guitar_learning/gpu/episode_diagnostics.py:547).

이 함수는 매번 가장 가까운 점으로 바꾸지 않고 **같은 원본 패드 물질점128개**의 두 시각 월드 위치를 받는다. 이전 점을 이전 palm 로컬로 옮기고 새 palm pose로 운반한 가상점 `carried`를 만든다. 이전/현재 기타 pose를 이용해 모두 기타 물질좌표로 표현한다.

```text
total   = 현재 실제점_G - 이전 실제점_G
support = 새 palm으로 운반한 가상점_G - 이전 실제점_G
finger  = 현재 실제점_G - 새 palm으로 운반한 가상점_G
total = support + finger        (벡터 관계)
```

예를 들어 손가락 각도는 그대로이고 팔·손목만 움직였다면 대부분support로 나타난다. palm에 대해 손가락 마디가 움직이면finger 성분이 나온다. 기타 자체 이동도 상대좌표 변환에 들어간다.

벡터 합은 정확하지만 `|total|=|support|+|finger|`는 일반적으로 성립하지 않는다. 두 성분이 반대 방향이면 실제 총변위가 작아질 수 있다. 이 자료를 “성공의70%가 팔의 힘”처럼 원인·힘 분담 비율로 해석하면 안 된다. 기하 변위의 정의된 분해다.

`_pose_for_points()`는 점 차원에 맞게 pose를 broadcast하고 유한 pose·0이 아닌 quaternion을 검사한다. 분해 출력 `PadMotion`은 total/support/finger 텐서 세 개만 갖는 불변 dataclass다.

### `SkillEpisodeDiagnostics`: 구간 시계에 맞춘 현재 진단

원문: [SkillEpisodeDiagnostics](/home/ajou/yigyu/3/guitar_learning/gpu/episode_diagnostics.py:583), [reset](/home/ajou/yigyu/3/guitar_learning/gpu/episode_diagnostics.py:620), [_phases](/home/ajou/yigyu/3/guitar_learning/gpu/episode_diagnostics.py:666), [control](/home/ajou/yigyu/3/guitar_learning/gpu/episode_diagnostics.py:681), [episode](/home/ajou/yigyu/3/guitar_learning/gpu/episode_diagnostics.py:719).

생성자는 원곡에서 고정 recovery 창을 한 번 얻고 환경마다 구간 offset·duration·focus를 보관한다. `reset()`은 원곡 창과 **실제 재생 구간의 초기 준비3초 이후~끝**을 교차시켜 현재 분모를 만든다. 최초3초 준비와 원곡 중간 휴식의 회복을 같은 결과로 섞지 않는다.

`physics()`는240Hz로 첫3초 관측/유효/B밴드/gate/quality와 손가락별press시간, 교차 recovery창 관측/유효/밴드시간을 적분한다. `last_physics`로 실제 진행량을 제한하고 구간끝을 넘는 시간은 자른다.

`_phases()`는 완료60Hz 끝점에서 selected 음과 시계로 손가락별 단계를 분류한다. 처음local<3초는 initial_preparation, 그 밖에는 preparation·press·hold·release·idle다. 이 labels는 **진단용 phase**이며 B gate를 계산하는 실제 선호 시간창과 정확히 같은 정의가 아니다. preparation은press−2..press, release는end..end+0.15다. 겹치면 코드가 뒤에 적용하는hold 등이 우선한다.

`control()`은 각 끝점에서 같은128점을 분해하고 손가락별 평균 변위 길이를 phase별 누적한다. 같은 tick이 phase 경계를 가로질러도 현재 끝점 phase에 들어간다는 제한이 있다. 유효하지 않은 표본은0으로 처리하지만 평균 분모는128로 고정하고 `valid_sample_s`를 따로 남긴다. 따라서 invalid가 많은 결과의 path가 작다고 정지라고 단정하지 않는다.

최종 `finger_skill_diagnostics`에는 첫 준비의 네 손가락 품질, 구간별 고정 recovery창/coverage, physics_pressing_s, `[phase, finger, component]`의 path_m·관측초·유효표본초와 벡터 합 최대오차가 들어간다. “손이 가까이 왔는데 손가락이 거의 안 움직임”은 다음처럼 나눠 해석할 수 있다.

1. `motion`의hold/press에서 support path는 큰데finger path는 작은가: palm 상대 굽힘이 작았는지 확인한다.
2. 환경의left_finger_motion에서 target range도 작은가: 정책/누적 요청 쪽을 본다.
3. target range는 크고actual range가 작으며target−q RMS가 큰가: 추종·접촉·PD/한계 반응을 본다.
4. actual range는 큰데surface_min/geometry/facing/loaded가 안 되는가: 실제 올바른 패드의 방향·위치·하중을 본다.
5. B gate 시간과band 품질은 충분했는가: 대기 시간이 없었던 문제와 충분히 쉬어도 복귀하지 못한 문제를 나눈다.

이 진단들은 원인을 가르는 관측 근거이며, 하나의 값만으로 정책 실패의 인과를 확정하는 장치는 아니다.

## 이 세 파일의 권장 읽기 순서

먼저 `contact.pad_target_geometry()`로 지금 무엇을 올바른 접촉이라고 부르는지 읽고, `wrong_press_sources()`로 그 후보를 무효화하는 조건을 확인한다. 다음 `finger_target_indices()`와 `finger_preparation_gate/reward()`를 읽으면 목표·대기 전환의 시간 의미가 연결된다. 엄지는 `THUMB_SUPPORT_CONTRACT → load_thumb_support → thumb_support_geometry` 순서가 좋다. 마지막에 진단 클래스의 physics/control/episode를 읽으면 로그의 각 수치가 실제 보상·기하의 어느 단계에서 나왔는지 추적할 수 있다.
