# 압현 V5 학습 코드 해설

2026-11-04의 V5 전용 정리 기준이다. 실행 명령은 [학습 안내](../../../guitar_learning/README.md), 파일 역할을 먼저 찾으려면 [코드 지도](../../../guitar_learning/docs/CODE_STRUCTURE.md)를 본다. 아래 설명은 활성 구현의 책임과 데이터 흐름을 다룬다. 진행 중인 C1의 봉인 원문이나 이전 checkpoint에 새 설명을 소급 적용하지 않는다.

## 1. 한 번의 학습이 진행되는 순서

```text
등록 목표·초기 자세·입력 SHA 검사
    → GPU 장면 생성과 에피소드 reset
    → 신체 상태464 + 목표8×26 + 목표 유효 마스크
    → Actor에서 행동 표본, Critic에서 보상·비용 가치 예측
    → 직접 목표각 요청과 속도 제한
    → 1/240초 물리·측정 네 번
    → 1/60초 보상·종료·전이 확정
    → H개 정책 tick을 수집하면 PPO 갱신
    → 로그·checkpoint·노출량 commit
    → 살아 있는 환경은 같은 에피소드로 계속
```

`train.py`와 `training/launch.py`는 기본 명령을 V5로 연결한다. `tool/experiments/compact_press_v5.py`는 `configuration`, `build_settings`, `validate_settings`, `runtime`에서 V5 설정과 실제 정책·환경을 연결한다. `train`은 새 학습 또는 동일 계약의 재개, `evaluate`와 `render`는 저장본을 검사한 뒤 평가·영상을 실행한다. C1~C6는 `press_sequence.py`가 원본 압현 시각과 선택 C조합을 검증한 뒤 같은 V5 실행을 사용한다.

`training/finger_skill_runner.py`의 `run`과 `_train_phase`가 경험 수집→PPO→로그·저장→다음 수집을 운영한다. `ExposureSchedule`은 처음 계획한 전이 예산을 저장한다. 최초 예산의25%를 반영하면 이후 reset하는 환경부터 구간 대신 전체 목표를 선택한다. 재개하거나 업데이트 수를 추가해도 문턱을 다시 계산하지 않는다. 현재 성공률에 따라 자동으로 난도를 올리는 구조는 아니다.

### 목표26차원×8슬롯

목표 슬롯 순서는 검지 tracking/next, 중지 tracking/next, 약지 tracking/next, 소지 tracking/next다. tracking은 자기 담당의 현재 발음 또는 준비 중 목표, next는 그 다음 미래 목표다. 동률·시간창·유효 여부는 `gpu/finger_reward.py`의 `finger_target_indices`와 환경의 선택 마스크를 따른다. 목표가 없는 슬롯은 유효 마스크가False이고 인코딩 결과도0이다.

## 3. Actor와 Critic은 어떻게 계산하는가

`training/compact_press_v5.py`의 `CompactPressV5Policy`를 읽는다.

```text
Actor
    상태464/473 → MLP256→256 → 256
    목표26 → 공유 MLP64→64 → 64, 이를8슬롯에 적용
    256 + 8×64 = 768
    MLP768→512→256 → 선형 출력33
    학습 가능한33축 log_std → 정규분포 표본 → tanh

Critic
    독립 상태·목표 인코더: 같은 입력, 별도 매개변수
    결합768 → MLP256→256
    보상 가치1, 종료 비용 가치1
```

목표 인코더는 슬롯마다 별도 신경망8개를 만드는 대신 같은 가중치를 공유한다. 인코딩 뒤 슬롯 위치를 유지하여 연결하므로 손가락과 tracking/next를 구분한다. Attention이나 내부 기억 상태는 사용하지 않는다. 상태·목표에 포함된 유지시간·이전 행동·속도·다음 목표가 순차 동작에 필요한 맥락을 제공한다.

Actor는33개 학습 행동을 출력하지만 공용 제어 전달 배열은39칸이다. 마지막6칸은0이며 확률·우도·KL·entropy 계산에서 제외된다. 활성33축은 왼팔12, 엄지5, 검지~소지 각4다. 팔과 엄지17축의 초기 표준편차0.15, 나머지16축0.35를 각각 적용하고 이후 PPO가 `log_std`도 갱신한다. `size` 이름으로 V5 층 폭을 바꾸지 않는다.

`act`는 탐색 또는 평균 행동을 만들고, `evaluate`는 저장한 latent 행동의 현재 우도·entropy·가치를 다시 계산한다. tanh의 확률변환 보정을 포함한다. PPO가 학습하는 확률과 실제 수집한 행동의 정의를 일치시키는 부분이다.

## 4. 행동에서 실제 물리 움직임까지

`training/rollout.py`의 `GpuPool`·`DecisionCollector`, `gpu/control.py`의 `BatchedController`, `gpu/scene.py`를 순서대로 본다.

- LH21 손가락 행동0은 v9 준비 기준각, −1/+1은 native 하한/상한을 요청한다. 같은 행동을 반복해도 각도를 누적해서 더하지 않는다.
- 요청한 손가락 목표각은4rad/s의 변화율 제한을 거쳐 적용된다. 명령이 크더라도 실제 적용 목표는 작은 폭으로 움직일 수 있다.
- 관절의 실제각은 PD·힘 한계·접촉·관성의 결과다. 정책 목표각으로 실제 q를 덮어쓰지 않는다.
- 팔·손목과 하체 지지는 기존 유한 제어를 유지한다. root는 고정되지만 기타는 자유 강체다.
- 정책은60Hz, 물리는240Hz다. 각 정책 행동에서4회 물리 측정이 발생한다. 제어 목표·기타·마디 자세·접촉 tensor를 갱신하고 보상·종료·진단을 측정한다.

`GpuScene.reset`과 `prepared_reset_v1.py`는 에피소드 경계에서 검증된 준비 상태를 복원한다. 목표가 바뀌거나 H32가 끝났다는 이유로 순간이동·추가 reset을 하지 않는다. 서로 다른 환경의 종료는 그 행만 초기화한다.

## 5. 압현·오압현·준비의 의미

`gpu/contact.py`는 손등을 제외한 실제 distal 패드 표본과 같은 표면점의 위치·방향을 사용한다. 목표 프렛 셀·줄의 근접, 압현면 높이·패드 법선, 해당 distal 몸체 하중 조건을 함께 확인한다. 이는 기하·몸체 합력 기반 후보이며 개별 현과의 접촉쌍·압력·진동·음향 검출은 아니다.

`wrong_press_sources`는 담당하지 않은 손가락, 비허용 마디·위치, 같은 줄의 더 높은 프렛 간섭 등을 확인한다. 낮은 목표에 잘 닿았더라도 높은 프렛을 함께 누르면 실제 유효 음이 달라질 수 있으므로 clean에서 제외할 수 있다. 목표 후보와 clean 후보를 별도로 읽어야 한다.

손가락별 진행은 동시에 다를 수 있다. 검지가 압현 중이어도 중지는 다음 목표를 준비할 수 있다. 준비→표면 하강은 시간에 따른 부드러운 보간이며, 손목 준비 완료를 반드시 기다리는 세 개의 독립 제어기를 순차 실행하는 구조는 아니다. 준비 상태·정렬 여부는 진단으로 남기고 활성33축은 매 정책 tick 함께 출력한다.

B 대기 자세는 `gpu/finger_reward.py`와 V5의 실제 gate·품질 계산을 사용한다. 실제 기하각 기준 MCP±30°, PIP/DIP±10°의 허용대 밖에서 품질이 부드럽게 감소한다. 엄지를 제외한 자기 손가락별 쉬는 시간에 약하게 보상하며 자동 복귀 명령이나 필수 경유점이 아니다. 손가락 움직임·속도 비용은0이다.

## 6. 최종 보상9항과 종료 비용

현재 지급은 공용 부모의 중간 계산이 아니라 V5 최종 합성까지 확인한다. `gpu/finger_skill_environment.py`가 음별 예산·중복 방지·실패 정산을, `gpu/compact_press_v5.py`가 현재 접근·준비·유지 조건과 완료 평가를 정의한다.

| 보상 | 로그 키 | 지급 방법 |
| --- | --- | --- |
| 목표 패드 접근 | `song_left_approach` | 매 정책 전이의 γΦ다음−Φ현재. 거리·방향·정렬·준비 gate·음 가중치로 bounded potential 계산 |
| 최초 접촉 | `song_left_contact` | 최장 연속접촉 진행의 증가분에 음당0.25b 예산. 같은 진행에 재지급하지 않음 |
| 압현 유지 | `song_clean_hold` | 음 길이로 정규화한 clean 유지 적분, 음당1.0b 예산. 동시 구간은 개별과 모두 clean에 나누어 지급 |
| 압현 달성 | `song_left_success` | 필요한 연속 clean 문턱을 처음 넘으면 음당0.25b를 한 번 지급 |
| 오압현 | `song_wrong_press` | 발음 구간의 audible wrong 시간을 음 길이로 정규화, 음당0.15b 감점 예산 |
| 음 수행 부족 | `song_performance_deficit` | 누락 시간 증분을 감점하고 음 종료에 누락률·연속 유지 부족률의 최댓값까지 한 번 정산, 음당0.10b |
| 대기 자세 | `song_finger_standby` | 실제 쉬는 gate×자세 품질의 적분, 네 손가락 합계 최대0.02/초 |
| 엄지 안내 | `song_thumb_support` | 유한 넥 후면 영역의 간격·방향·영역 품질과 하중 후보의 약한 지속 보상 |
| 행동 변화 | `action_change` | LH21을 제외한 행동 변화 감점 |

b는 선택된 목표 수와 등장 손가락별 목표 수로 정하는 균형 가중치다. 표의 예산을 전체곡 성공 점수나 모든 음에서 항상 받는 양으로 해석하지 않는다. 접근은 bounded potential의 차이이며 양수·음수 모두 가능하다. 시간·목표 gate가 바뀌는 경우도 있으므로 접근 합계가 음수라는 이유만으로 손이 항상 멀어졌다고 판단하지 않는다.

보상 프로필은 네 가지다. `corrected`는 대기 gate의 반대값으로 접근을 조절하고 달성 문턱은 min(D,max(0.05,0.4D))다. `preparation`은 접근 계수를1−0.90×gate로 바꾸어 대기 중에도 노출 목표의 접근 신호를10% 남긴다. `full_hold`는 달성·수행 부족의 필요 유지시간을 D 전체로 바꾼다. `combined`는 두 변경을 함께 적용한다. 연속 유지 보상은 corrected에서도 음 전체 구간에 지급되며 문턱을 넘자마자 사라지지 않는다.

### 종료 조건

기타의 과도한 위치·회전 변화, 발 위치 변화·지지 상실 등 공용 물리 안전과 지지 제어 유효성은 `gpu/environment.py`의 계약을 따른다. 손목 영역 이탈은 다음처럼 추가한다.

- 에피소드 최초3초는 일반 손목 감시 유예다.
- 허용 영역 밖 초과거리3cm보다 크면 시간을 누적한다. 활성 상태에서2~3cm면 경과 시간을 초당1초 줄이고2cm 이내면 초기화한다.
- 일반 누적1.5초 또는 심각 초과거리10cm의 연속0.10초에서 실패한다. 측정은240Hz, 실제 종료는60Hz 제어 경계에서 확정한다.
- H32·목표 전환에서는 이 타이머를 지우지 않는다.

종료 비용은 실패 시 에피소드당 한 번 **5 + 남은 시간×2 + 아직 관측·정산하지 않은 음 감점 예산**이다. 물리·손목 실패가 함께 발생해도 중복 부과하지 않는다. 정상 지속 물리 비용은0이다. 실패 tick의 양성 지급 억제와 terminal potential 정산은 유지한다. 안전을 지키는 것과 압현 성공은 별도로 평가한다.

## 7. PPO가 경험을 어떻게 사용하는가

`DecisionCollector`가 `[H,N,...]`에 상태·목표·마스크·latent 행동·우도·보상·비용·종료·가치를 저장한다. K1이므로 매 tick 독립적인 새 결정을 내린다. H32는 수집 창0.533초이며 에피소드 전체 길이와 다르다. 끝나지 않은 환경의 창 마지막은 Critic으로 bootstrap하고 다음 수집에서 그대로 이어 간다.

`training/ppo.py`는 보상과 비용의 GAE·return을 계산하고 유효 결정을 minibatch로 섞어 Actor와 Critic을 갱신한다. PPO의 ratio·clip·KL 보호·rollback은 같은 확률 정의를 사용한다. 보상·비용을 결합한 advantage와 cost weight1을 사용하며 정상 물리 비용이0이어도 종료 비용은 학습에 반영된다.

현재 기본 설정의 핵심은 Actor 학습률3e−5, Critic3e−4, γ0.99, GAE λ0.98, minibatch4096, epoch2다. 정확한 실행값은 저장된 `settings.json`을 우선한다. 경험량은 H×N×업데이트 수다. 환경 수나 H를 바꾸면 한 갱신의 자료량·실제 노출량도 달라지므로 업데이트 수만으로 수렴 속도를 비교하지 않는다.

γ0.99의 효과는 60Hz 시간축에 걸쳐 적용된다. 긴 행동의 첫 준비가 나중 성공에 기여하는 학습에는 Critic 정확성과 GAE 길이가 중요하다. H32 밖의 보상을 전혀 못 본다는 뜻은 아니다. [현재 효율 분석](../../2026-11-09/압현_v5_학습효율분석_v1/README.md)은 초반 로그와 과거 목표 전환의 접촉 경험·가치 예측을 대조한다.

## 8. 저장·로그를 읽는 순서

`training/training_log_io.py`가 SHA·JSON·저널·에피소드 압축과 checkpoint 기록을, `portability.py`가 `project://` 식별자·설정 snapshot·입력 계약을 처리한다. `read_checkpoint`는 설정·source/asset SHA·identity를 먼저 확인하고 현재 V5 아키텍처와 비교한다. 새 소스에 맞춰 기존 pin을 고치는 재개는 하지 않는다.

| 출력 | 먼저 볼 내용 |
| --- | --- |
| `settings.json`, `training_contract.json`, `inputs_before.json` | 실제 학습 조건, 상태·목표·행동·보상·물리 계약, 소스·입력 근거 |
| `learning_metrics.jsonl` | 항목별 보상, 비용, 학습률·KL·entropy·가치 예측·시간·구간/전체 노출 |
| `episodes.jsonl`, `episode_metadata.json` | 종료 이유·음별 contact/clean/achieved·유지·해제·진단; 압축 메타데이터 복원 필요 |
| `finger_control_diagnostics.json`, 초기 대표 trace | 요청·적용·실제각, 속도 제한·관절 한계, 팔/손가락 변위, 대기·엄지·접촉 |
| `checkpoint_manifest.jsonl`, `final.pt` | 저장된 모델·옵티마이저·노출 일정·입력·lineage와 SHA |
| `report.json` | 실행 완료·출력 참조·종합 결과; completed는 연주 성공이 아님 |

에피소드 원문은 `iter_episode_rows()`로 읽어 고정 메타데이터와 가변 행을 합친다. 누적 진단을 여러 행에서 다시 합산하지 않는다. 수집(sampled), PPO 반영(committed), 디스크 기록(durable)을 구분한다. 초반 대표 환경600tick trace를 전체 환경·학습 전체의 통계로 확대하지 않는다.

제어 문제는 요청각이 충분히 변하는지→속도 제한 뒤 적용각이 변하는지→실제각이 따라오는지→패드 위치·방향·하중이 맞는지 순서로 나눠 본다. `decompose_pad_motion`은 palm이 운반한 움직임과 손가락 자체의 기하 변위를 분리하며 힘·성공의 인과 비율을 뜻하지 않는다.

## 9. 무엇을 성공이라고 부르는가

음별 설정 문턱의 달성 latch, 음 전체 길이의 연속 clean 유지, 동시 목표 전체 clean 구간 유지, 요구된 해제 완료를 구분한다. V5 `press_completion`의 완료는 선택 시간축을 안전하게 끝내고 전체 유지와 필요한 해제를 모두 만족해야 한다.

해제는 원래 음 끝부터0.1초 이내 목표 패드의 기하·방향·하중 후보가 True→False로 바뀌는 관측이다. 오압현만으로 clean이 꺼진 것은 새 해제가 아니다. 같은 줄·프렛·손가락의 연속 목표가 중간 해제를 요구하지 않으면 예외다. pending·실패 중단 상태를 성공으로 처리하지 않는다. 후보 소실은 물리적 완전 분리나 개별 현 압력0의 보증이 아니다.

현재 목표·보상·검증의 정의를 유지한 채 학습 효율을 비교한다. 다른 구조의 과거 성공 수나 지원된 초기 자세 성과를 현재 자유 압현·전곡·음향 성공으로 상속하지 않는다. V5 메타데이터의 이전 버전 이름은 로그·공유 수학의 식별자이며, 구버전 실행기가 남아 있다는 뜻은 아니다.
