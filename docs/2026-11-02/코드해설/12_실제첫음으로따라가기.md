# 실제 첫 음 하나로 전체 코드를 따라가기

[해설 목차](/home/ajou/yigyu/3/docs/2026-11-02/코드해설/README.md)

추상적인 설명을 실제 데이터와 연결하기 위한 예제다. 기본 곡 `05_BN2-131-B_solo`를 현재 `make_task(..., pre_roll_s=3., tail_s=.5)`로 읽어 확인했다. 여기서 음 하나만 골라 설명하는 것은 학습 대상을 단음으로 바꾼다는 뜻이 아니다. 현재는 J 전용 v3 환경에서67목표 전곡과 그 선택 구간을 학습한다. 정책은 v2 schema·557상태(공유 왼손552+잔여시간1+손목 종료 타이머4)를 받고, 지지17축과 연주 손가락16축을 모두 학습한다.

## 1. 파일에 있던 음이 `ScoreTarget`이 된다

[song/task.py의 make_task()](/home/ajou/yigyu/3/guitar_learning/song/task.py:298)는 원곡의 목표를 컴파일하고 정책 준비 시간3초를 더한다. 첫 목표의 실제 값은 다음과 같다.

| 필드 | 값 | 해석 |
| --- | --- | --- |
| `target_id` | `event-000000/string-2/note-0` | 원본 이벤트·현·매핑 음의 식별자 |
| `string` | `1` | 시뮬레이터의0기준 현 번호. ID의 string-2는1기준 표현 |
| `fret` | `7` | 7프렛 |
| `finger` | `3` | 약지. 검지1·중지2·약지3·소지4 |
| `direction` | `1` | 공통 목표 자료에서의 down 방향 |
| `source_onset_s` | `0.6385` | 원곡 시각의 음 시작 |
| `source_end_s` | `0.8707` | 원곡 시각의 목표 종료 |
| `press_s` | `3.5185` | 정책 시각에서 압현 준비 접촉을 평가하는 시작 |
| `onset_s` | `3.6385` | 정책 시각에서 audible 수행 구간 시작 |
| `end_s` | `3.8707` | 정책 시각에서 수행 구간 종료 |

`direction`이 있다고 현재 왼손 정책이 오른손을 타현한다는 뜻은 아니다. 같은 목표 자료를 양손·기존 경로도 공유하기 때문에 필드가 함께 있다. 기본 J 정책의 오른손6축 행동은0이다.

이 곡은 원본 이벤트66개를 목표 음67개로 확장한다. 이벤트와 음의 개수를 구분해야 한다. 전체 정책 시간은 음 마지막 종료만으로 결정하지 않고 원오디오29.3063945578초 + 준비3초 + 말미0.5초를60Hz 경계로 올려32.8166666667초,1969tick으로 만든다. 선택 구간의 로컬 길이는 전곡 길이와 별도로 구성한다.

## 2. GPU 환경은 Python 객체를 텐서 배열로 바꾼다

[TensorSongEnvironment 초기화](/home/ajou/yigyu/3/guitar_learning/gpu/environment.py:321)에서 `onset`, `end`, `press`, `string`, `fret`, `finger`를 목표 음 축으로 텐서화한다. 이 곡이면 각 일정 배열의 길이는67이다.

원장에는 환경 축도 붙는다. 예를 들어 `note['best_clean_streak'][환경번호, 0]`은 그 환경에서 **첫 목표**에 대해 지금까지 기록한 가장 긴 연속 clean 시간이다. `candidate[환경번호, 0]`은 현재 접촉 후보이고, `note['left'][환경번호, 0]`은 이미 압현 달성 문턱을 통과했는지를 나타내는 별도 값이다. 순간 후보가 true라고 달성도 즉시 true인 것은 아니다.

약지가 맡는 음의 균형 가중치도 계산한다. 이후 악구를 선택하면 선택된 음과 등장 손가락 기준으로 다시 균형을 맞춘다. 아래 수식의 `b`는 그때 그 목표의 가중치이며 항상1이라고 가정하면 안 된다. 목표를 선택하지 않은 환경에서는 첫 음의 보상·원장 집계 범위도 제한된다.

## 3. 정책에 “약지가 어디로 가야 하는지” 전달한다

약지의 우선 슬롯 두 개는 `ring_tracking`, `ring_next`다. [finger_target_indices()](/home/ajou/yigyu/3/guitar_learning/gpu/finger_reward.py:23)가 현재 시각·선택 범위에서 목표를 고른다. 이 예의 첫 음이 항상 tracking에 들어가는 것은 아니다. 현재 시각과 다른 관련 음에 따라 선택이 달라진다.

선택된 목표 토큰에는 onset/end/press까지 남은 시간, 현·프렛·손가락, 현재 수행/준비 여부, 접촉·연속 유지 이력, 패드 표면 오차와 상대 속도 등이24열로 들어간다. `mask`가 false인 슬롯의 숫자를 실제 목표로 해석하면 안 된다.

[FingerSkillPolicy.forward()](/home/ajou/yigyu/3/guitar_learning/training/policy.py:500)에서 약지 head는 전체 손가락 인코더 정보, 자기 우선 목표 표현, 약지의 관절·자세20개 입력을 이용해4축의 평균을 출력한다. [act()](/home/ajou/yigyu/3/guitar_learning/training/policy.py:549)는 평균에 독립 Gaussian 탐색을 더하고 tanh로 제한한 행동을 매60Hz tick 새로 만든다. R/F 동결·상관 탐색·여러 tick 행동 유지 분기는 없다. 목표가 약지라고 해서 환경이 정답 관절각을 이 출력에 넣어 주는 것은 아니다.

## 4. 그 행동이 약지의 실제 움직임이 된다

[BatchedController.targets()](/home/ajou/yigyu/3/guitar_learning/gpu/control.py:458)는 약지 행동을 누적 목표각으로 변환한다. 손가락이 이미 목표 쪽으로 움직이고 있다면 행동0이어도 현재 목표까지 물리 추종이 계속될 수 있다. 반대로 행동이 커도 접촉·힘 상한·관절 한계 때문에 실제 움직임이 작을 수 있다.

[GpuScene.step()](/home/ajou/yigyu/3/guitar_learning/gpu/scene.py:381)이 물리 상태를 진행한 뒤, 환경은 실제 약지 패드 표면을 기타 좌표계로 바꾸고 이 목표의 현·프렛 셀과 비교한다. 패드 중심 한 점만 가까운지를 보는 방식으로 읽으면 안 된다. 유효한 표면·방향·기하·하중을 함께 검사하며 실제 같은 선택점 기준의 속도를 사용한다.

기타도 자유 강체이므로 약지가 세계 좌표계에서 같은 위치에 있어도 기타가 움직이면 상대 오차가 달라진다. `delta`와 표면 거리를 기타 좌표계에서 읽는 이유다.

## 5. 접근·접촉·유지·달성을 차례로 구분한다

이 목표의 audible 길이 `D = end - onset`은0.2322초다. 현재 연속 clean 달성에 필요한 시간은 [required 계산](/home/ajou/yigyu/3/guitar_learning/gpu/environment.py:333)에 따라 다음과 같다.

```text
required = min(D, max(0.05초, 0.4 × D))
         = min(0.2322, max(0.05, 0.09288))
         = 0.09288초
```

이 값은 실제 측정이 아니라 목표로부터 계산한 문턱이다. 실제 판정은 물리·제어 샘플과 유효 구간 누적으로 이뤄진다. 전체0.2322초 중 여러 번 끊어진 접촉 시간을 단순 합해0.09288초를 넘는 것과 연속 clean 문턱을 넘는 것은 다르다.

| 시기·상태 | 코드에서의 의미 |
| --- | --- |
| 목표 준비 중 패드가 접근 | potential 변화로 목표 패드 접근 항에 반영. 같은 위치에서 매번 같은 거리 점수를 받는 방식과 다름 |
| `press..end`의 유효 접촉 | 현재·최장 접촉 streak를 갱신하고 최초 접촉 예산의 새 진행분 지급 |
| `onset..end`에서 clean 유지 | 이 음의 길이로 정규화한 압현 유지 보상 누적 |
| 연속 clean 문턱 통과 | 압현 달성 flag와 한 번의 보너스 |
| audible 동안 다른 압현/누락 | 오압현 시간, 음 수행 부족의 시간·예산에 반영 |
| 음 끝 | 미지급 부족분을 한 번 정산. 같은 미달성을 매 tick 재지급하지 않음 |

이 음의 최초 접촉 진행 문턱은 `min(0.05초, end-press)`이므로0.05초다. 반면 압현 달성 문턱은 위의0.09288초다. 두 문턱을 같은 “접촉 성공”으로 읽으면 최초 접촉은 있는데 달성이 없는 로그를 잘못 해석하게 된다.

현재 자식 환경의 접촉 예산은0.25b, 압현 유지 예산은1.0b, 달성 예산은0.25b다. 이 숫자는 **해당 보상의 예산**이며 매 tick마다 그 금액을 새로 지급하는 것이 아니다. 접근·대기·엄지·행동 변화와 별도 실패 비용은 이 표의 음별 세 항과 다른 방식으로 계산한다. 최종 계수는 [FingerSkillEnvironment._reward_components()](/home/ajou/yigyu/3/guitar_learning/gpu/finger_skill_environment.py:342)에서 확인한다.

## 6. 한 tick의 결과가 학습과 로그에 남는다

네 번의 물리 끝점이 모이면 `end_control()`이 이 환경의 `reward`와 `cost`를 반환한다. 보상은 이 첫 음만의 값이 아니라 같은 tick에 범위 안에서 평가된 목표·자세·행동 변화 등의 합이다. 이 합과 행동 확률·가치·종료 정보를 수집 버퍼에 넣는다.

H32가 끝나면 PPO가 버퍼를 사용한다. 그 update에 첫 음이 끝나지 않았다면 원장의 연속 접촉·지급 상태를 다음 수집으로 이어간다. 음이 끝났다고 반드시 에피소드 전체가 끝나는 것도 아니다.

실제로 끝난 에피소드에서 첫 음을 확인하려면 `left_note_ledger`의 `target_ids`와 `values`를 같은 인덱스로 읽는다. first index의 값이 언제나 모든 악구의 첫 선택 음이라는 뜻은 아니다. 선택 범위와 원본 목표 ID를 함께 확인한다. `learning_metrics.jsonl`의 항목 평균은 해당 update의 모든 환경·전이 평균이므로 첫 음 하나의 달성 여부를 거기서 바로 읽을 수는 없다.

이 예의 수치는 [실제 목표 예제.json](/home/ajou/yigyu/3/docs/2026-11-02/코드해설/실제목표예제.json)에 저장했다. 예제를 얻기 위해 곡 자료만 읽었고 물리 학습은 실행하지 않았다.


이 예의 목표·시간·보상 예산은 J 전용화 전후 동일하다. 다만 관측과 정책 schema가 바뀌었으므로 이전561상태나 구형557상태 R/F/J checkpoint를 새 실행에 불러오지는 않는다. 예제의 숫자가 같다는 사실과 checkpoint 호환은 별개의 조건이다.
