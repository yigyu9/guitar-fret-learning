# 패키지 초기화 파일 8개

[해설 목차](/home/ajou/yigyu/3/docs/2026-11-02/코드해설/README.md)

현재 정적 연결32개 중8개는 `__init__.py`다. 여덟 파일 모두 현재 한 줄의 설명문만 갖는다. 실행 함수·클래스·등록 코드·전역 학습 상태를 만들지 않는다. 구현24개와 파일 수를 따로 세는 이유다.

## `guitar_learning/__init__.py`

[소스](/home/ajou/yigyu/3/guitar_learning/__init__.py:1). 최상위 학습 패키지를 표시하고 자유 기타 학습 환경·측정 패키지라는 역할을 설명한다. `python -m guitar_learning.train`이 패키지를 해석하는 과정에 포함된다. 학습을 시작하는 코드는 이 파일이 아니라 `train.py`다.

## `guitar_learning/training/__init__.py`

[소스](/home/ajou/yigyu/3/guitar_learning/training/__init__.py:1). 실행·정책·PPO·수집·기록이 속한 패키지다. `training.launch` 등을 가져오면서 상위 패키지로 로드된다. 정책이나 Torch를 자동으로 import하지 않으므로, 실제 실행기에서 Isaac Gym을 먼저 가져오는 순서를 유지할 수 있다.

## `guitar_learning/gpu/__init__.py`

[소스](/home/ajou/yigyu/3/guitar_learning/gpu/__init__.py:1). GPU 환경·제어·보상의 패키지 경계를 표시한다. 이 파일을 읽었다고 GPU 시뮬레이터가 생성되지는 않는다. 실제 물리 장면은 `GpuScene.__init__()`에서 만든다.

## `guitar_learning/core/__init__.py`

[소스](/home/ajou/yigyu/3/guitar_learning/core/__init__.py:1). 공통 제어·기하 구성요소의 패키지다. GPU 기본 경로도 `core/control.py`의 행동 순서와 프로필, `core/geometry.py`의 공용 관측 정의 등을 사용하므로 포함된다. `core`를 import하는 것과 CPU 학습 환경을 실행하는 것은 별개다.

## `guitar_learning/runtime/__init__.py`

[소스](/home/ajou/yigyu/3/guitar_learning/runtime/__init__.py:1). 초기 자세 입력·네이티브 세션 계층의 패키지다. 기본 GPU 경로에서는 `prepared_reset_v1.py`의 복원 입력이 필요해 연결된다. CPU `PreparedSession`을 이 파일에서 만들거나 자동으로 실행하지 않는다.

## `guitar_learning/song/__init__.py`

[소스](/home/ajou/yigyu/3/guitar_learning/song/__init__.py:1). 전곡 일정·악구·단계 설정·안내 입력이 속한 패키지다. 이 파일은 곡을 읽거나 목표를 고르지 않는다. 실제 전곡 목표 생성은 `song/task.py`의 `make_task()`가 담당한다.

## `guitar_learning/score/__init__.py`

[소스](/home/ajou/yigyu/3/guitar_learning/score/__init__.py:1). 검토한 악보 번들을 컴파일하는 패키지다. 설명의 “표준 라이브러리만으로”는 악보 컴파일 계층의 성격이며, 학습 전체가 Torch·Isaac Gym 없이 실행된다는 의미가 아니다. XML·악보·타현 계획 로드는 하위 모듈 함수에서 시작한다.

## `guitar_learning/native/__init__.py`

[소스](/home/ajou/yigyu/3/guitar_learning/native/__init__.py:1). 프로젝트 내부로 옮긴 네이티브 구현의 패키지 경계다. 외부 구형 디렉토리를 다시 import하는 연결 파일이 아니다. 경로 해석·현재 내부 소스 검증은 `native/paths.py`에 있다.

## 코드를 읽을 때의 의미

이8개는 처음에 한 번 역할만 확인하고 주요 구현24개로 넘어가면 된다. Python은 하위 모듈을 가져올 때 상위 패키지의 초기화 파일을 실행하지만, 현재는 설명문 외 처리가 없다. 앞으로 이 파일들에 무거운 import나 전역 환경 생성을 추가하면 모든 하위 모듈의 import 순서와 실행 비용에 영향을 줄 수 있다. 지금의 단순한 상태가 곧 누락된 구현이라는 뜻은 아니다.

`native/lower_body_release_v1/__init__.py`는 다른 네이티브 구현이 사용하는 활성 패키지 파일이지만, 공용 pin 함수가 native/paths.py로 이동하여 기본 학습의 정적 경로에서는 제외됐다. 해당 파일을 삭제한 것은 아니다.
