이 문서는 `gpu/scene.py`, `gpu/control.py`와 `gpu/contact.py`의 공통 기하 구역을 해설한다. 순서대로 **실제 물리 장면의 소유자**, **정책 숫자를 유한한 인체 명령으로 바꾸는 제어기**, **관측·접촉에서 사용하는 목표 표면과 손목 영역**이다. 회전·상대속도 함수는 `control.py`, 표면 표본·압현면·손목 영역은 `contact.py`에 모였다. 학습 보상의 크기를 바꾸는 함수와 실제 움직임을 만드는 함수는 구분해 읽는다. 이번 통합은 배치를 바꾼 것이며 보상·제어 수식, 물리 설정과 제한값은 유지했다.

## 1. `gpu/scene.py`: 하나의 시뮬레이터 안에서 N개의 장면을 소유한다

원문: [GpuScene](/home/ajou/yigyu/3/guitar_learning/gpu/scene.py:31).

### 생성자에서 만드는 것

이 클래스가 Isaac Gym 객체, GPU native 버퍼, 환경별 human/guitar/chair actor, 물리 시계와 reset 권한을 소유한다. `N=1024`이면 시뮬레이터 1024개가 아니라 **시뮬레이터 하나 안의 환경 1024개**다. 서로 다른 환경끼리는 actor의 collision group으로 분리한다.

생성 순서는 다음과 같다.

1. CUDA 장치를 확인하고 `load_prepared_reset_contract()`로 합의한 035/v14 준비 상태·질량·제어·자산 정보를 읽는다.
2. `RigidGuitar`가 봉인된 복합 기타 자산의 SHA와 원래 논리 몸체 계약을 확인한다.
3. 왼손 실행이라면 손가락 사이의 선택적 충돌 필터를 만든다.
4. GPU PhysX를 240Hz로 만들고 지면을 추가한다.
5. 인체·복합 기타·의자를 읽고 환경마다 actor를 생성한다.
6. 질량·COM·관성, 충돌 속성, DOF 속성을 실제 native API에 넣고 읽어 확인한다.
7. native 상태·접촉·Jacobian 버퍼를 Torch CUDA view로 연결하고 최초 reset을 수행한다.

내부 입력의 경로 대응·출처 검증과 준비 상태 복원 공통 코드는 `native/paths.py`에 모였다. 장면이 사용하는 준비 계약의 공개 진입점은 계속 `runtime/prepared_reset_v1.py`다. 아래 넥 기하 로더의 `_sha`·`_wrist_sha` 별칭은 `training/training_log_io.py`의 공통 `digest()`를 사용한다. 이 저장 공통 함수 참조가 장면을 새로 만들거나 학습을 시작하는 것은 아니다.

핵심 물리 설정은 `dt=1/240`, substeps=1, 중력 `(0,0,-9.81)`, GPU pipeline=True, PhysX GPU=True, solver type1, 위치 반복4·속도 반복2, contact_offset2mm, rest_offset0이다. `CC_LAST_SUBSTEP`을 쓰지만 여기서 외부에 호출하는 물리 step 자체가 240Hz이며 내부 substep은 1이다. 정책 60Hz의 네 물리 표본을 하나로 생략하는 설정이 아니다.

장면은 인체 root 고정, 기타 root 자유, 기타 중력 활성인지 검사한다. 실제 기본은 기타를 고정하지 않는다. `diagnostic_guitar_mode='fixed'/'free'`는 별도 진단용이고 metadata에도 training_contract=False로 표시한다. 이 옵션을 기본 학습의 상태 고정으로 읽지 않는다.

### 105/97/8과 혼합 제어

native q 배열은 105개지만 lower<upper인 유효 가동축은 97개, lower==upper인 0범위축은 8개다. 인체 일부는 native POSITION drive 48축, 일부는 외부에서 유한 effort를 넣는 57축의 혼합 제어다. 제어기는 외부 effort를 POSITION 축·0범위축에 넣지 않아야 하며 `step()`이 이를 검사한다.

왼손 native PD 속성은 `default_profile()`의 검지~소지 stiffness12/damping1.5, 엄지 stiffness8/damping1.25로 적용한다. 이는 정책이 직접 토크를 출력한다는 뜻이 아니다. 기본 손가락 정책은 **요청 위치를 누적 갱신**하고 native drive가 실제 관절을 따라가게 한다. target과 actual q는 접촉·PD·물리 때문에 달라질 수 있다.

### 실제 기타 1몸체와 논리 기타 39몸체

원문: [RigidGuitar](/home/ajou/yigyu/3/guitar_learning/gpu/scene.py:466), [expand](/home/ajou/yigyu/3/guitar_learning/gpu/scene.py:501).

GPU native 기타는 하나의 강체에 89개의 충돌 형상을 합친 복합 자산이다. 예전 관측·악보는 nut/fret/string marker를 몸체 이름으로 찾으므로, 읽는 단계에서 이를 원래 39개 논리 몸체로 확장한다. **논리 fret/string marker는 별도의 물리 관절·줄 시뮬레이션이 아니다.**

`RigidGuitar.__init__()`는 manifest 자체의 고정 SHA, compound XML SHA, 원본 자산 SHA, 원래 body 이름·질량 속성·준비 root 일치를 검사한다. 속성이 비슷한 다른 기타를 조용히 대체하지 않는다.

`expand(native)`는 실제 기타 root의 위치·회전에 미리 저장한 각 논리 offset/회전을 적용한다. native 선형속도는 몸체 원점이 아닌 COM 속도이므로 논리 몸체마다 다음을 계산한다.

```text
p_logical = p_root + R_root × logical_offset
q_logical = q_root × logical_rotation
v_logical_COM = v_compound_COM + ω × (logical_COM - compound_COM)
```

물리 강체를 새로 만들거나 상태를 덮어쓰지 않고 관측 view만 구성한다. `_refresh()`의 접촉 합력도 실제 인체·기타 root·의자에만 복사한다. 나머지 논리 기타 marker의 force는 0이다. 따라서 특정 `G:string`의 force를 읽어서 줄별 압력을 계산하는 구조는 아니다.

### 왼손 손가락 간 충돌 필터

원문: [left_hand_collision_properties](/home/ajou/yigyu/3/guitar_learning/gpu/scene.py:543), [verify_external_filter_preservation](/home/ajou/yigyu/3/guitar_learning/gpu/scene.py:589).

native 규칙은 `(filterA & filterB) == 0`일 때 충돌 허용이다. 기존 15개 왼손 마디는 공통 filter128이어서 서로 겹치는 비트가 있었다. 코드는 엄지·검지·중지·약지·소지에 각각 20~24번 별도 비트를 배정한다. 같은 손가락 마디끼리는 같은 비트를 공유해 기존 제외를 유지하고, 서로 다른 손가락은 비트가 겹치지 않게 만든다.

단순히 15개를 전부 0으로 바꾸지 않는다. 원래 filter128로 손바닥·팔 등과 제외하던 다른 인체 형상에는 새 손가락 비트를 추가하여 그 제외 관계를 보존한다. 모든 human shape pair를 전후 비교해 **서로 다른 손가락 90쌍만 새로 활성화**됐는지 검사한다. 실제 기타·의자 필터와의 관계도 별도 비교한다. 충돌 메시·마찰·접촉 offset 자체를 바꾸는 함수가 아니다.

손가락 간 충돌이 켜져 있다고 기하학적 겹침이 절대 없어진다고 보장하지는 않는다. 유한 시간 스텝, solver, target drive와 실제 반응을 함께 보아야 한다.

### 상태를 읽는 `snapshot()`과 쓰는 `reset()/step()`

원문: [body_state](/home/ajou/yigyu/3/guitar_learning/gpu/scene.py:322), [snapshot](/home/ajou/yigyu/3/guitar_learning/gpu/scene.py:343), [reset](/home/ajou/yigyu/3/guitar_learning/gpu/scene.py:351), [step](/home/ajou/yigyu/3/guitar_learning/gpu/scene.py:381).

`snapshot()`은 q/qd/target, 확장한 몸체 상태, 합력, 환경별 물리 스텝, native Jacobian, reset body 표지를 사전으로 준다. 대부분 native 버퍼 view이므로 장기 보관할 불변 snapshot이라고 가정하면 안 된다. 이후 학습 수집기가 필요한 값을 복사한다.

`reset(indices)`만 에피소드 경계에서 실제 관절·기타 root 상태를 준비 상태로 쓴다. 고유한 유효 환경 인덱스인지 확인하고, human DOF와 자유 기타 root의 indexed setter를 호출한다. 인체 root·의자를 매 tick 옮기지 않는다. target과 effort를 초기화하고 해당 환경 물리 시계를 0으로 바꾼다. 동일 전역 물리 스텝에서 reset 호출을 여러 번 나누지 않도록 계약을 둔다.

reset 직후에는 native rigid body/Jacobian 갱신이 아직 첫 물리 스텝을 거치지 않았다. `body_state`는 해당 행에 준비 스냅샷을 제공하고 합력은 0으로 제공한다. 첫 `step()` 뒤 `_reset_mask`를 내리면 live native 값을 읽는다. 제어기도 reset 표지를 받아 이 순간에만 기하 Jacobian fallback을 쓴다.

`step(targets105,efforts105)`는 크기·장치·유한값·native 범위·effort cap·혼합 제어 소유권을 검사한다. 이후 position target과 effort를 제출하고 `simulate/fetch_results`를 한 번 실행해 실제 1/240초를 진행한다. 정상 진행 중에 q/root를 target 값으로 직접 덮어써 움직임을 만드는 코드는 없다.

Torch와 Gym은 서로 다른 CUDA 스트림을 사용한다. `step()`의 제출 전과 `_refresh()`의 읽기 전에 `torch.cuda.synchronize()`를 두어, 한쪽이 아직 쓰는 버퍼를 다른 쪽이 먼저 읽지 않게 한다. 이 동기화는 숫자 보상의 일부가 아니라 자료 일관성을 위한 경계다.

`diagnostics`는 실제 GPU/pipeline 설정, 시뮬레이터 수, native/logical 몸체 수, reset 횟수, 속성 readback 오차, 충돌 필터 적용 환경 수를 기록한다. `close()`는 simulator를 파괴하고 마지막 감사 JSON을 쓴다. 학습 실행 완료와 자원 정리를 모두 확인할 수 있게 하는 부분이다.

## 2. `gpu/control.py`: action 39개를 target105·effort105로 바꾼다

원문: [BatchedController](/home/ajou/yigyu/3/guitar_learning/gpu/control.py:176).

이 파일은 기타에 힘을 직접 주지 않는다. 인체 관절에만 유한한 target/effort를 만들며, 기타는 인체와의 실제 접촉·중력으로 움직인다. `_load_geometry()`와 `_load_support()`가 준비 입력에서 관절축·계층·질량 기하·발 밑면·가슴 capsule·기타 원본 삼각형·오른팔 지지 목표를 한 번 읽는다.

### 행동과 관절 이름의 대응

`ACTIVE_NAMES`의 39열을 native105 인덱스로 바꿔 `self.active`에 저장한다. 왼손 쪽 33축은 팔·손목과 LH21을 포함한다. `finger_actions`는 이 중 왼손 엄지와 네 손가락 21열이다. 나머지 관절은 prepared reference 및 유한 하체/지지 제어를 따른다.

관절 제한은 q의 실제 native lower/upper다. 손가락을 임의의 좁은 ±0.5rad 안에 가두는 대신 왼손 LH21에는 전체 native 범위를 제공한다. 그러나 가동범위를 쓸 수 있다는 것과 정책이 원하는 방향을 학습했다는 것은 별개다.

### `targets()`: 기본 손가락은 속도형 누적, 나머지는 기준 자세 오프셋

원문: [targets](/home/ajou/yigyu/3/guitar_learning/gpu/control.py:458).

먼저 모든 active action을 −1~1로 자른 뒤, 일반 축에 대해 준비 기준 `reference`에서 양·음 방향별 허용 폭을 곱해 requested 각도를 만든다. 일반 축은 alpha0.2 smoothing과 `rate/60` 최대 변화량을 적용한다.

그 후 기본 incremental LH21에 대해서는 일반 식을 덮어쓴다.

```text
finger_target_next = clamp(finger_target_previous + action×4/60,
                           native_lower, native_upper)
```

action=+1을 한 tick 주면 요청 target이 약 0.0667rad, 약 3.82° 증가한다. 0이면 이전 target 유지, −1이면 같은 속도로 반대 방향이다. 이미 상한에 닿은 뒤 +1을 계속 줘도 숨은 적분값을 더 쌓지 않는다. 저장하는 target 자체가 잘리므로 다음 tick −행동이면 즉시 안쪽으로 돌아설 수 있다. LH21 smoothing alpha는 1로 우회한다.

이 값은 **실제 q를 그만큼 회전시키라는 순간 상태 쓰기**가 아니다. native PD가 추종할 요청 위치를 바꾸는 것이다. 실제 움직임이 작은 원인은 action이 작거나, target이 native 한계에 있거나, 실제 물리가 추종하지 못하는 등으로 나뉜다.

지원되는 `position` 모드도 같은 파일에 남아 있다. 이 모드는 action0이 준비 reference로 돌아가는 요청이며 ±1이 native 끝 범위를 요청한다. 현재 기본 finger-skill은 incremental만 허용하므로 position의 자동 reference 복귀를 현재 행동0의 의미로 적용하면 안 된다. 어느 모드에도 자동 B 대기 자세 복귀는 없다. B는 보상의 약한 선호다.

마지막으로 `_foot_targets()`를 넣고 전체 rate/native clamp와 zero축 고정을 적용해 `self.target`을 갱신한다. target 메모리는 H32 경계에서 사라지지 않고 `reset(indices)`에서만 reference로 바뀐다.

### `_foot_targets()`: 발바닥이 지면에 남게 하는 유한한 기구학 요청

원문: [_lower_fk](/home/ajou/yigyu/3/guitar_learning/gpu/control.py:399), [_foot_targets](/home/ajou/yigyu/3/guitar_learning/gpu/control.py:422).

하체 FK로 네 발 지지면의 아래쪽 꼭짓점을 계산한다. 양쪽 Knee_x·Ankle_xyz·Toe_x의 총 10개 채널을 대상으로, 준비 reference±0.6rad와 native 안쪽 범위에서 DLS를 정확히 8번 반복한다.

잔차는 발밑 z를 지면 부근 −0.00025m에 맞추는 항에 2000, 발 몸체 원점 xy를 준비 위치에 남기는 항에 2의 가중치를 둔다. `JᵀJ+0.01I`를 풀고 1회 증분을 ±0.05rad로 제한한다. 이는 상체·손가락을 고정하는 IK가 아니라 발 지면 유지용이다. CPU의 SciPy least_squares와 동일 실행이라고 가정하지 않도록 제어 계약에 차이를 기록한다.

### `efforts()`: 중력·자세·지지를 합하고 마지막에 힘을 제한한다

원문: [efforts](/home/ajou/yigyu/3/guitar_learning/gpu/control.py:487).

각 물리 표본에서 다음을 계산한다.

1. 원본 축/계층의 기하 Jacobian과 native Jacobian을 준비한다. reset 직후 행만 기하값, 그 이후는 native 값을 선택한다.
2. COM 선형 Jacobian과 질량으로 인체 중력 보상 `9.81 Σ(m Jz)`를 구한다.
3. `kp×(target-q)-kd×qd` 자세 항을 만든다. 오른팔 일부 회전 그룹은 SO(3) 회전 오차로 바꾼다.
4. 오른팔 지지점의 월드 목표를 향하는 힘을 최대20N으로 제한하고 `JᵀF`로 허용 지지 관절에 넣는다.
5. 가슴 capsule과 기타 원본 삼각형의 최근접 관계로 가슴 근접 힘을 만들고 해당 몸통 관절에 넣는다.
6. 하체 16가동축은 기하 질량행렬과 implicit SO(3) PD로 별도 계산한 effort로 교체하고 hip bias를 더한다.
7. native effort cap으로 잘라 POSITION축·zero축 effort를 0으로 만든다.

`stable_pd()`의 수식은 다음과 같다. `dt=1/240`이고 M은 대칭화한 질량행렬이다.

```text
(M + diag(dt kd + dt² kp)) v_predict = M v + dt kp e
feedback = kp e - (kd+dt kp) v_predict
effort = gravity + feedback
```

중력을 예측 우변 안에 다시 넣지 않는다. 손가락에 이 하체 질량 PD를 그대로 적용하는 것도 아니다. 최종 POSITION축은 effort0이며 해당 native drive가 위치 요청을 수행한다.

가슴 근접 계산의 `source_capsule_witness()`는 삼각형 AABB 거리로 512개 후보를 고르고, 후보 거리로 누락 삼각형이 더 가까울 수 없음을 인증한다. 인증이 안 된 행만 전체 삼각형을 16환경 단위로 검사한다. 그 아래 `capsule_triangle_witness()`는 끝점·세 변·평면 교차를 모두 검사하고 `_point_triangle()`은 점의 투영이 삼각형 밖이면 변으로 제한한다. 단순히 가장 가까운 꼭짓점 하나를 고르는 함수가 아니다.

결과가 유한하지만 가슴 최근접 두 점이 같아 정상 방향을 정할 수 없는 경우에는 `normal_defined=False`다. 수집기는 해당 행을 control invalid로 표시하고 현재 tick 끝까지 마지막 유효 유한 effort만 사용한 뒤 종료한다. 비유한 또는 인증 실패를 정상 동작처럼 조용히 계속 쓰는 계약은 아니다. `diagnostics`의 chest gap/force, fallback 여부, finite/valid가 이 구분의 근거다.

### 손가락이 자유롭다는 표현의 범위

손가락 action21에는 보상상의 행동 변화 비용이 0이고 제어 smoothing도 우회하지만, **native 관절범위·4rad/s target 제한·PD·effort 상한·접촉 물리는 남아 있다**. “비용 없음”은 무제한 속도나 힘 또는 관절 무시를 뜻하지 않는다. 반대로 관절 분담 선호를 적용해 PIP/DIP를 강제로 연동하는 제어 결합도 이 기본 경로에는 없다.

## 3. `control.py`의 좌표 연산과 `contact.py`의 목표 기하

원문: [회전·상대속도 연산](/home/ajou/yigyu/3/guitar_learning/gpu/control.py:19), [목표 표면·압현면·손목 영역](/home/ajou/yigyu/3/guitar_learning/gpu/contact.py:1).

이전에 별도 `gpu/geometry.py`에 있던 함수들은 위 두 파일로 이동했고 옛 파일은 제거했다. `control.py` 앞부분의 회전·속도와 `contact.py`의 기하 측정은 매 스텝 사용하는 순수 Torch 연산이다. `contact.py`의 자산 로더는 시작 시 한 번 실행하는 CPU 검증이다. 같은 파일에 NumPy/SciPy 로더가 있다고 매 물리 스텝 상태를 CPU로 옮긴다는 뜻은 아니다.

### 회전·속도 도구

아래 여섯 함수는 모두 `gpu/control.py`의 맨 앞에 있다. `finger_reward.py`와 환경도 같은 구현을 가져와 사용한다. `control.py`가 접촉 판정 전체를 가져오지 않으므로 제어→보상→접촉으로 import가 되돌아오는 순환을 만들지 않는다.

| 함수 | 의미와 주의 |
| --- | --- |
| `conjugate(q)` | xyzw 단위 quaternion의 역회전에 해당하는 공액 |
| `multiply(a,b)` | 회전 합성. 순서가 바뀌면 다른 회전 |
| `apply(q,v)` | q를 정규화해 v를 회전. 선행 배치 차원 broadcast 허용 |
| `rotvec(q)` | quaternion 부호를 정리하고 shortest 회전벡터 rad로 변환. 작은 회전에서 수치 안정 처리 |
| `origin_velocity(state,com)` | native COM 속도에서 몸체 원점 속도로 변환 |
| `relative_point()` | 움직이는 기준 몸체의 병진·회전속도를 빼고 로컬 위치/속도를 반환 |

예를 들어 손과 기타가 월드에서 같은 속도로 평행 이동하면 기타 상대 점속도는 거의 0이어야 한다. `v_hand-v_guitar_COM`만 사용하면 기타의 회전과 COM 오프셋 때문에 오차가 남으므로 `ω×offset`까지 빼는 함수가 필요하다. 위치 13열 중 7:10은 COM 선형속도라는 계약을 계속 유지한다.

### 전체 메시 표본과 현재 패드 표본의 차이

이 절부터 손목 상자까지의 함수는 `gpu/contact.py`에 모였다. 다음 [접촉·손가락 보상 해설](/home/ajou/yigyu/3/docs/2026-11-02/코드해설/06_접촉과손가락보상.md)에서 같은 파일의 뒤쪽 패드·엄지·오압현 구역을 이어 읽는다.

원문: [finger_mesh_surface_samples](/home/ajou/yigyu/3/guitar_learning/gpu/contact.py:96), [surface_target_geometry](/home/ajou/yigyu/3/guitar_learning/gpu/contact.py:36).

`finger_mesh_surface_samples()`는 각 손가락 메시를 64개 구면방향+6개 좌표축 방향에서 바라본 지지 꼭짓점을 중복 제거해 저장한다. 손가락마다 표본 수가 달라 최대 길이로 padding하고 `valid`로 구분한다. 이 표본은 오압현의 타 손가락 경합, 엄지 옛 거리 진단 등에 현재도 쓰인다.

`surface_target_geometry()`는 10개 2/3마디 표본에서 유한 줄·프렛 선분까지의 최근접점을 구하는 공유 함수다. 현재 왼손 **양성 접촉과 접근 거리**는 더 엄격한 `contact.pad_target_geometry()`를 사용한다. 앞 함수가 존재한다고 손등 포함 전체 표면 중 아무 점이나 가까우면 양성 압현이라는 뜻은 아니다.

### 압현 평면을 원본 자산에서 얻는다

원문: [_extract_plane](/home/ajou/yigyu/3/guitar_learning/gpu/contact.py:146), [load_press_surface](/home/ajou/yigyu/3/guitar_learning/gpu/contact.py:211), [project_press_strings](/home/ajou/yigyu/3/guitar_learning/gpu/contact.py:241).

compound 자산의 물리 neck1/neck2 메시를 읽고 scale·geom 변환을 적용한다. ConvexHull의 가장 위쪽 면이 같은 평면인지 확인하고 그 평면을 압현 목표로 사용한다. 원래 virtual string 높이를 그대로 목표 삼아 넥 위에서 멈추는 대신, x/y는 유지하고 Gz를 연주면으로 내린 선분을 만든다.

각 목표의 프렛셀 양쪽에서 2mm씩 줄인 선분이 실제 finite string과 교차하는지, 양 끝점이 같은 원본 볼록 넥 껍질 안에 있는지 검사한다. 볼록성 때문에 양 끝점이 같은 껍질 안이면 그 사이도 안이다. 증명 대상은 원본 자산 기하이며 PhysX cooked 충돌면의 모든 세부나 실제 현 압력은 아니다.

`project_press_strings()`는 `[N,6,3]` 시작/끝점을 받아 plane의 `nx x+ny y+nz z+d=0`으로 z를 구한다. 기타 로컬 평면을 써서 움직이는 기타에도 같은 상대 목표를 유지한다. 물리 줄이나 넥 위치를 옮기는 함수는 아니다.

### 손목은 중심점이 아니라 허용 상자다

원문: [load_wrist_region_track](/home/ajou/yigyu/3/guitar_learning/gpu/contact.py:309), [measure_wrist_region](/home/ajou/yigyu/3/guitar_learning/gpu/contact.py:354).

로더는 bundle의 `training/hand_position_targets.json`과 manifest SHA를 확인한다. 시간은 60Hz 순차 frame인지, anchor/allowed_fret_range가 1~22 안인지 검사한다. 파일 속 옛 `wrist_pos_guitar`, `allowed_radius_m`, `offsets_m`를 현재 목표로 그대로 사용하지 않는다.

anchor 프렛셀 가운데 Gy에서 원본 넥의 최대 Gx 경계를 구한다. Gy 중심은 allowed_fret_range 전체의 바깥 셀 경계 중점으로 잡는다. 이 기준에서 다음 상자를 만든다.

```text
Gx: 원본 넥의 아래쪽 경계 + 1cm ~ +8cm       폭 7cm
Gy: 작업 프렛 범위 중심 -6cm ~ +6cm          폭 12cm
Gz: 압현면 -11cm ~ -2cm                     폭 9cm
```

축 이름은 화면의 위/아래와 같다고 가정하지 말고 기타 로컬 축으로 읽어야 한다. 실제 박스는 곡의 anchor/range에 따라 60Hz 시계열로 움직인다. `measure_wrist_region()`이 인접 시간의 lower/upper를 선형 보간하고 양끝 바깥은 clamp한다.

```text
nearest = clamp(actual_wrist, lower, upper)
delta = nearest - actual_wrist
```

상자 안은 어디든 delta0·ready=True다. 중심으로 끌어당기지 않고 회전도 자유여서 rotation error는 항상 0이다. 함수가 반환하는 옛 `position=-q/(1+q)`는 공유 v22의 보상 표현이고, 현재 J 환경은 이를 최종 보상에 더하지 않는다. **현재 학습에서는 같은 delta가 손목 종료 타이머와 관측·진단의 입력**이다. 상자 자체 크기와 그 밖에 추가로 허용하는 종료 여유3cm를 구분해야 한다.

### 이 세 파일을 읽는 순서

`scene.snapshot/reset/step`으로 실제 상태의 소유권을 먼저 확인하고, `control.targets`로 행동0·±1의 뜻을 이해한다. 이어 `control.efforts`의 중력·지지·힘 제한을 읽는다. 회전·속도 식이 막히면 `control.py` 앞부분으로 돌아온다. 마지막으로 `contact.py`의 표면·압현면·손목 로더와 `scene.py`의 RigidGuitar·충돌 필터 검증을 읽으면 준비 자산이 현재 목표와 물리에 어떻게 연결되는지 이해하기 쉽다.
