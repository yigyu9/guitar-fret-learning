# 약 8시간 자율 개선 계획

사용자 승인: 2026-11-01, 질문 없이 분석 → 개선 설계 → 구현 → 검증 → 충분한 비교 실험 → 기록까지 수행한다. 기존 실행을 훼손하지 않고 같은 GPU는 한 실험씩 사용한다.

## 판단과 가설

- 기존 최고800회는 평균128환경 AB107/128, 마지막1000회5/128이다. 다른 seed900회는0/128이고942회에KL보호로 중단됐다. 두 목표를 배우는 문제와 배운 성공을 보존하는 문제를 구분한다.
- 현재 H128 → 필요 시 초기분포 혼합 → 엄지21축의 독립 비교는 계속한다. 결과에 따라 구조 개선 가능성을 판단한다.
- 추가 실험은 성공 모델의 회귀를 직접 검사한다. 동일800회 모델의 **가중치만 명시 이전**하고 두 군 모두 새 Adam·새 RNG로 시작한다. strict resume라고 부르지 않는다.
- 대조군은 기존 actor LR3e-5·회복상한3e-5, 보수군은 초기 LR1e-5·회복상한1e-5다. LR 초기값/회복상한을 하나의 보수적 학습률 조건으로 정의한다. critic LR3e-4, KL0.02, retry3·기존하한7.5e-6, std·보상·GAE·물리·초기 자세·목표는 고정한다. LR하한 결함 교정과 보상 변경은 이 비교에 섞지 않는다.
- 조기KL실패는 해당 군의 실패로 보존하며 다음 독립 군은 진행한다. 비유한·소스·계약·정리 오류는 전체를 중단한다. 실패KL의 실제값·유한성을 새 로그에 기록한다.

## 순서와 검증

- [x] 원본 로그·보상·KL/std·구조 분석을 독립 검토한다.
- [x] 별도 wrapper 구현. 원본800 checkpoint는 원래 정책/PPO identity와 입력 SHA로 먼저 검증하고, 명시적 새 계약 아래 model-only 이전한다.
- [x] CPU 회귀 검사·별도 변경 검수. 최초19검사, 예산 호환성 수정 후21검사 통과, 독립 검수 완료. 기존488핀 및 실행 중인 continuation의 봉인 파일은 그대로 둔다.
- [ ] 기존 continuation 종료 뒤 GPU독점 실행. 먼저 4군(C0 seed7, C1 seed7, C0 seed17, C1 seed17)을 각100회씩 순차 학습한다. 50회 중간·100회 최종 평가를 기록한다. 시간 예산이 허용할 때만 균형 있게200회까지 늘린다.
- [ ] 평균32환경 중간 평가·평균128환경 최종 평가, 최종 확률32환경 평가. 모든 최초 에피소드·실패 포함. 평균AB, 음별/전체 유지, 정시 전환, 위치/방향/부하/오압현, 9보상, 손목/물리, KL/LR/std, 엄지 후보를 기록한다.
- [ ] 사전 기준으로 best/last를 별도 보존하고 실제 평균 정책 손/전신 영상을 저장한다. 선택 순위는 실패가 적은 모델에서 전체 유지→AB 달성→clean 시간이며, 최고 모델 선택에는32환경을 쓰고 선택 모델은128환경 재확인한다. 128확인 결과로 같은 데이터에 대한 반복 튜닝은 하지 않는다.
- [ ] 그래프·원장·실패 포함 결과·코드/모델 SHA·채택 여부·다음 실험을 문서로 정리하고 문서 링크·영상 재생 정보를 검증한다.

## 채택과 해석

일차 지표는 두 seed의 최종128환경 **결정적 AB/두 음 전체 유지/정시 전환**이다. 원래800회보다 안정적으로 보존하는지와 동일 model-only 대조군보다 나은지를 함께 본다. 기존 임시 목표90%를 유지하며 실패≤1%다. 2seed·한 손가락·한 전환의 비교이므로 다른 목표·여러 손가락·동시 압현·전곡 성공으로 일반화하지 않는다. 개선을 입증하지 못하면 실험 도구와 부정 결과를 보존하고 기본 학습 코드는 바꾸지 않는다.

## 시간과 저장

현재 비교의 초기 예상은17:48 KST, 추가 실험은 약40~70분이다. 약8시간 창을 기준으로 하되 실행 속도·분기에 따라 더 걸릴 수 있으며, 균형 잡힌 비교를 우선한다. GPU경합·반복적인 중복평가·원시로그 무단삭제는 하지 않는다. 상태는 이 디렉토리 README와 `runs/progress.json`, 결과는 `runs/RESULTS.md`에 남긴다.

체크리스트는 실행 준비 시점의 기록이다. 이후 실제 진행·완료·실패는 `runs_v2/progress.json`, `runs_v2/RESULTS.md`, `runs_v2/ANALYSIS.md`를 우선한다. 자율 감독은10:25 KST에 시작했고 native 검증 대기부터 추적한다.

GPU 사전 검사에서 모델 이전 비교가 노출 예산까지 동일하게 요구하여 학습 시작 전에 중단됐다. 실패 원본은 보존하고 `tools_v2`에서 두 계약 경로의 예산2필드만 model-only 호환성 비교에서 제외했다. 원래 모델의 전체 identity 검증과 새 모델의 strict resume는 완전 동일 계약을 요구한다. 실제 GPU 검증은 `validation_v2/preflight.json`을 따른다.

실제GPU 검증 완료: `validation_v2/preflight.json`의7개 작업이 모두 completed=true이며, 원800모델 SHA불변·기존감독재개·손/전신영상 양수길이를 확인했다. 대조군/보수군 새학습 및strictresume에서 입력변경/누락0이었다.
