# 정책 회귀와 KL 중단 분석

분석 범위는 `transition_diagnosis_v3/runs/study_v1`의 원본 학습·평가 기록이다. 현재 GPU 실험과 봉인된 소스는 수정하지 않았다. 아래 실험안은 원인 분리를 위한 제안이며, 실행 결과와 구분해야 한다.

## 핵심 판단

지금의 가장 강한 증거는 **확률적으로 실행한 정책의 학습 성적과 평균 행동으로 실행한 정책의 전환 성공률이 다르다**는 것이다. 학습률이나 탐색이 완전히 사라져 학습이 멈춘 상황으로 설명하기 어렵다. 값 함수가 폭주했다는 증거도 없다. 성공한 모델을 검증 기준으로 보존하고, 성공 주변의 정책 변화를 작게 유지하는 비교가 필요하다.

두 번째 문제는 942회 다음 갱신에서 KL 보호가 발생하면 전체 실험이 멈추고, 유효한 942회 상태도 저장하지 못하는 운영 구조다. KL 기준 자체를 완화할 이유는 없다. 거부된 갱신의 수치와 상태 복원을 기록하고, 안전하게 낮은 학습률로 재시도할 수 있게 해야 한다.

## 1. 800회에서 1000회로 갈 때 실제로 달라진 것

다음은 seed 7의 각 100회 구간 평균이다. 학습 중 행동은 확률적으로 샘플링된다. 표의 성공률은 해당 구간에서 종료된 유효 전곡 에피소드로 계산했다.

| 지표 | 701–800 | 801–900 | 901–1000 |
|---|---:|---:|---:|
| 배우 학습률 | 1.140e-5 | 1.499e-5 | 1.130e-5 |
| 수락된 최종 KL 평균 | 0.0042 | 0.0060 | 0.0059 |
| clip fraction 평균 | 0.042 | 0.074 | 0.073 |
| KL 재시도 총수 | 0 | 0 | 1 |
| 잠재 Gaussian entropy 평균 | -20.892 | -20.893 | -20.893 |
| reward value loss 평균 | 0.0106 | 0.0093 | 0.0095 |
| reward explained variance 평균 | 0.546 | 0.665 | 0.697 |
| 압현 유지 보상/결정 평균 | 0.00399 | 0.00376 | 0.00358 |
| 전체 보상/결정 평균 | -0.0043 | -0.0045 | -0.0048 |
| 학습 중 두 음 달성 | 237/448 (52.9%) | 295/448 (65.8%) | 239/447 (53.5%) |
| 학습 중 clean 시간 비율 평균 | 91.1% | 85.9% | 82.0% |

별도 고정 모델 mean 평가에서는 800회 107/128, 1000회 5/128이다. 학습 구간 성공률과 해당 구간 마지막 모델의 성공률은 같은 지표가 아니다. 전자는 학습 도중 계속 변한 정책을 샘플링한 결과이고, 후자는 정지한 마지막 정책의 평균 행동을 실행한 결과다.

관측으로 지지되는 해석:

- 800회 이후 압현 유지·clean 비율과 보상이 악화되었지만, 평균 행동 전환 성공은 훨씬 급격하게 무너졌다. 얇은 성공 영역 근처에서 행동 평균이 이동했을 가능성이 있다. 위치 판정 실패가 주원인이라는 평가 기록과 일치한다.
- 801–900 배우 학습률과 KL이 증가했다. 다만 이 변화가 회귀의 원인이라는 인과관계는 비교 실험 전에는 확정할 수 없다.
- entropy는 전체 1–100 구간 -20.887에서 901–1000 구간 -20.893으로 거의 같았다. 이 값은 16개 활성 축의 **잠재 Gaussian entropy**이며, tanh 행동 또는 실제 관절각의 entropy가 아니다. 이를 근거로 모든 관절의 탐색이 충분하다고 단정해서도 안 된다.
- 값 손실 감소와 explained variance 증가는 값 함수의 명백한 발산과 맞지 않는다. 그렇다고 장기 전환 credit assignment가 충분하다는 증명은 아니다.
- 평균 접근 보상은 약 -0.0103으로 유지된다. 다른 항보다 크다는 이유만으로 비중을 낮추면 안 된다. 음성 potential 차이, 각 시간대의 목표와 보상 정의를 함께 봐야 한다.

## 2. 942회 중단에서 아는 것과 모르는 것

seed 17은 942회까지 수락되었고 다음 갱신에서 `KLGuardError`를 기록했다. 마지막 수락 갱신은 LR 1.171875e-5, KL 0.0119743이었다. **이 KL은 실패한 시도의 KL이 아니다.** 실패 시도값이 원본 보고서에 직렬화되지 않아 초과량과 유한성을 확인할 수 없다.

901–942회 수락 구간은 KL 평균 0.0040, clip fraction 0.040, entropy -20.897, value loss 0.0101, explained variance 0.544였다. 수락 기록만으로 마지막 거부 시도의 원인을 재구성할 수 없다.

`PPOTrainer.update()`는 예외 시 정책, 두 Adam 상태, 비용 가중치, 갱신 수와 CPU/CUDA 난수 상태를 복원한다. `DecisionPPOTrainer`도 거부한 actor 단계의 가중치·Adam을 복원한 뒤 재시도한다. 이 원칙은 보존해야 한다. 원본 보고서에는 942회 복구 체크포인트가 없으므로 942회에서 재개했다고 기록하면 안 된다. 유효한 마지막 저장본은 900회다.

실험 설정에는 LR floor 7.5e-6, cap 3e-5, retry factor 0.5, retries 3이 들어 있다. 재시도 하한에 걸리면 더 작은 갱신을 시도하지 못할 수 있다. 이는 실패 시도별 LR/KL을 추가해야 정확히 확인할 수 있는 가설이다.

## 3. 개선 우선순위와 수치 실험안

### 우선 1: 실패 관측과 검증 기반 최고 모델 보존

알고리즘을 바꾸기 전에 운영과 관측을 개선한다.

- 매 거부 시도에서 update/epoch/minibatch/retry, 시도 LR, 실제 KL, 유한성, target KL, 복원 결과를 저장한다.
- 마지막 유효 갱신과 실패 직전 완료 횟수를 구분한다. 검증된 strict resume 경로가 없는 복구 파일은 재개 가능하다고 표시하지 않는다.
- 고정 검증을 50회 간격, mean 32환경으로 실시한다. 최고 후보와 마지막 모델은 mean 128환경으로 다시 평가한다.
- 순위는 `두 목표 전체 시간 유지 비율 → 두 목표 달성 비율 → B clean 시간 → 실패율`로 결정한다. 단순 reward 최댓값으로 선택하지 않는다.
- 초기 A만 성공하는 모델을 최고 모델로 뽑지 않도록 AB 공동 지표를 사용한다. 최고와 마지막 파일을 모두 보존한다.

이 작업 자체로 학습 성능이 좋아졌다고 주장하면 안 된다. 회귀를 관측하고 잘못된 최종 모델을 배포하는 것을 막는 개선이다.

### 우선 2: 성공 주변 보수적 미세조정 대조

현재 코드와 다른 조건을 유지한 채 배우 갱신만 비교한다. **검증 데이터로 고른 모델과 같은 데이터에 대한 성공을 일반화 성능으로 부르면 안 된다.**

| 조건 | 시작 | 배우 LR | 기타 |
|---|---|---|---|
| C0 대조 | seed7 800회 가중치만 이전 | 기존 자동 회복, cap 3e-5 | 기존 floor/clip/epochs/KL 유지 |
| C1 작은 갱신 | 같은 800회 가중치만 이전 | cap 1e-5 | floor 7.5e-6, clip .2, epochs 2, KL .02, std와 보상 유지 |

각 조건을 별도 난수 7/17로 100회씩 우선 실시하고, 시간 여유가 있으면 200회까지 늘린다. C0 seed7 → C1 seed7 → C0 seed17 → C1 seed17 순으로 먼저 모든 조건의 100회 결과를 확보한다. 50/100/150/200회 mean32 평가, 최고 및 마지막 mean128 평가를 실시한다.

이는 원800회 strict resume가 아닌 model-only 이전이다. 두 조건 모두 동일한 정책·값 함수 가중치와 learned log_std를 로드하고 Adam은 새로 시작한다. 원모델 identity/pins를 검증한 뒤 이전 출처를 기록하며, RNG 재시드 시점도 동일하게 한다. C1의 최초 배우 LR도 1e-5로 제한한다. 재시도 하한이나 KL허용치를 동시에 바꾸지 않는다. 같은 원본 정책에서 갈라진 결과는 독립적인 처음부터 학습 seed와 구분한다.

핵심 지표는 추가 200회 후 성적뿐 아니라 `검증 최고점 대비 마지막 손실`, 학습 중 AB 성공, mean/sample 차이, B 위치 거부 비율이다. C1이 단순 정지에 가까워 성능을 유지하기만 하면 새로운 동작 학습 개선으로 해석하지 않는다. 다른 seed의 900회 실패 모델에서 각 조건 100회 복구 여부를 추가 검사하면 보존과 신규 학습을 분리할 수 있다.

### 우선 3: 긴 전환의 credit assignment 분리

이미 진행 중인 H128 대조를 먼저 본다. H32는 수집 길이 0.533초로 휴지 0.75초보다 짧다. gamma .99, lambda .98의 직접 GAE 잔차 전달 계수는 32틱에서 약 .380, 45틱에서 .256, 128틱에서 .0208이다. H128이 더 멀리 수집하지만 할인 자체가 강하다는 점은 남는다. 값 bootstrap이 있으므로 이것만으로 장기 학습이 불가능하다는 뜻은 아니다.

H128이 안정적으로 개선하지 못하면 후속 가설로 gamma만 .99→.995로 바꾸는 별도 조건을 제안한다. 단 접근 potential shaping에 별도 gamma .99 설정이 있으므로, 그 일관성과 보상 성격을 먼저 확인해야 한다. 이것은 이번 8시간 필수 실행 조건이 아니다. lambda .98, 나머지 보상·학습률·초기분포·표준편차는 고정한다. baseline H128과 동일한 2,048,000 물리 전이(64환경×128틱×250회), 2 seeds로 비교한다. gamma와 lambda를 동시에 바꾸지 않는다. 이 조건은 현재 H/I/T 실행 시간과 GPU 여유를 확인한 뒤 우선순위를 정한다.

## 하지 않을 해석

- 800회 성공은 이 특정 중지·3번줄·6→7프렛 시퀀스에서 전환 가능한 정책이 있음을 뜻한다. 다른 손가락, 다른 프렛, 동시 압현에 대한 검증은 아니다.
- 전체 L 조건은 엄지 활성 축을 제외한다. 엄지 접촉 부재는 T 조건 결과와 분리해야 한다.
- KL 보호를 없애거나 허용치를 키워 실험 완주만 시키는 것은 개선 검증이 아니다.
- 보상, 학습률, std, 초기분포를 동시에 바꾸면 무엇이 효과가 있었는지 확인할 수 없다.
