# 전환 학습의 자율 분석·개선

> **17시대 복구:** 11:53 선행 비교는 음 종료 후 후보를 모순 성공으로 본 분석기 오류로 중단됐고 후속 학습률 비교는 미시작이었다. 원본 실패 기록을 보존하고 분석기6검사·독립 검수 후 학습률 비교를 우선 재개했다. 현재 유효 실행은 `runs_recovery`이며 H17·I·T는 아직 미실행이다.

사용자 부재 약8시간 동안 기존 비교를 계속하고, 성공 정책이 후속 학습에서 무너지는 현상을 별도 비교한다. 원본 실행과 생산 기본 구현의 봉인 파일은 바꾸지 않는다.

먼저 진행하던 H128·초기분포·엄지 비교는 [기존 후속 실행](../../압현성공/experiments/transition_diagnosis_v3/runs/continuation_v1/진행상황.md)을 따른다. 그 GPU 반환 뒤 새 비교를 순차 시작한다. 초기 예상상 추가 비교의 완료는18:30~19:00 KST 부근이며 실제 실행 속도·분기·오류에 따라 갱신한다.

새 비교는 최고800회 모델을 원래 소스·정책·PPO identity로 검증한 뒤 **가중치만 이전**한다. 두 군 모두 새 Adam·새 난수로 시작하며, 원800회의 strict resume나 같은 난수 궤적 재현으로 부르지 않는다. 기존 학습률3e-5 상한과 보수적1e-5 상한을 비교하고, 나머지 조건은 유지한다. 두 난수에서 각100회 추가 학습을 우선 확보하며, 시간이 남으면 균형 있게 늘린다.

실패·비유한 값·입력 변경을 숨기거나 성공한 환경만 분모로 집계하지 않는다. 32환경 평균 평가로 최고 모델을 선택하고128환경 확인·확률32환경 평가·실제 정책 손/전신 영상을 남긴다. 결과가 부족하면 개선을 확정하거나 생산 기본값을 자동 교체하지 않는다. 한 손가락·한 전환의 결과와 전곡·동시 압현을 구분한다.

현재 유효 실행은 `tools_v2`와 `runs_v2`다. 첫 `tools`/`runs`/`validation`은 모델 이전 호환성 검사에서 노출 예산 차이를 발견한 실패 기록으로 보존했다. 새 버전은 가중치 이전 비교에서만 명시한 예산 필드를 제외하며, 저장 계약·strict resume는 그대로 유지한다. CPU21검사와 독립 검수를 통과했고 실제 GPU7검사 후 기존 비교 종료를 기다린다.

실제 GPU 사전검증7개를 모두 통과했다. [검증 원장](validation_v2/preflight.json). 기존 감독은 재개됐고 새 감독은 선행 비교의 GPU 반환을 기다린다. 이 사전검사는 구현 실행 검증이며 개선 성과의 증거가 아니다.
