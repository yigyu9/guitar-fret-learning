# 단일 압현 검증 범위와 진행 순서

현재 기타의 검사 범위는 **6줄 × 1~22프렛 × 검지·중지·약지·소지 = 528조합**이다. 528조합을 시험하거나 성공시킨 상태가 아니다. 이 문서는 검사해야 할 전체 범위와 판정 방법을 정의한다.

## 코드와 자산에서 확인한 범위

| 항목 | 현행 범위 | 근거 |
|---|---|---|
| 기타 줄 | 6줄, 내부 목표 인덱스0~5 | `guitar_learning/song/task.py:77`, `guitar_learning/gpu/contact.py:215` |
| 압현 프렛 | 1~22 | `guitar_learning/gpu/contact.py:217`, `guitar_learning/core/geometry.py:73` |
| 담당 손가락 | 검지1·중지2·약지3·소지4 | `guitar_learning/song/task.py:78` |
| 개방현 | 0프렛·담당 손가락0 | `guitar_learning/song/task.py:78`; `guitar_learning/core/geometry.py:86`은 압현 목표를 만들지 않음 |
| 엄지 | 압현 담당 손가락 목록에서 제외 | 후면 안내·지지와 검지~소지 압현 수행은 별도 항목 |
| 준비 자세 | 인체105축 | `load_gpu_prepared_reset_contract('left')` CPU 입력 확인 |

2026-11-02에 기존 `load_press_surface`를 CPU에서 호출하여 132셀의 원본 연주면 기하를 확인했다. 264개 셀 양끝점 전부 원본 연주면 hull 안에 있고 평면 잔차는0이었다. **이것은 목표 셀 기하가 존재한다는 확인이며, 인체 도달 가능성·실제 접촉·정책 학습 성공의 확인이 아니다.** GPU·학습은 이 범위 확인에서 실행하지 않았다.

현재 코드가 허용하고 실제 연주면이 존재하는 1~22프렛만 검사한다. 23프렛 이상으로 늘리거나 압현 성공 기준을 완화하지 않는다. 코드의 `string`과 사용자가 부르는 줄 번호의 변환은 각 번들의 기존 표준 번호 규칙을 따라 명시하며, 두 번호를 혼용하지 않는다.

## 먼저 수행할 단독 비교

첫 작업은 **중지·기존 표준3번줄·8프렛 단독 목표에서 초기 bias cap0.9만 바꾼 비교**다. 전체528조합 검사와 분리한다.

- 기존 B 단독 목표 조건과 같은 A6 초기 reset, 준비시간, 음 유지시간, 모델, 환경 수, 학습량, 난수 seed를 유지한다.
- 포화된 초기 정책 bias만 normalized action±0.9로 제한한다. 실제 reset 상태·decoder·행동 범위·보상·PD·탐색 std는 유지한다.
- 학습 중 latent mean을 계속 제한하지 않는다. 새로운 조건은 새 모델로 학습하며 과거 체크포인트를 변경된 계약에 암묵 재개하지 않는다.
- 압현 달성뿐 아니라 B 목표의 올바른 연속 유지, 최초 접촉 시점, 패드 거리·높이·방향, 손목 안내 이탈, 실제 관절 추종, 행동·latent 포화를 같은 기준으로 비교한다.
- 성공 여부와 무관하게 결과를 기록하고, 성공 경험이 없으면 원인 분석 없이 528조합으로 확대하지 않는다.

## 초기 자세는 별도 검증 대상

현재 A6 정렬 초기 자세는 6프렛에 유리한 출발점이다. 모든 프렛을 골고루 검사할 **중립 초기화로 인정하지 않는다.** A6에서 특정 높은·낮은 프렛으로 실패했다고 그 목표가 물리적으로 불가능하다고 결론 내리지 않는다.

전체 범위를 학습시키기 전에는 손목의 초기 위치·방향을 골고루 제공하는 분포를 별도로 검증해야 한다. 선택한 초기 상태는 모두 원래 관절·물리·기타 지지 조건을 유지하며 에피소드 reset에서만 적용한다. 목표 전환 도중 상태를 덮어쓰지 않는다. 최초부터 압현된 자세를 성공으로 집계하지 않도록 대상 손가락 패드와 목표면의 이격·초기 접촉도 기록한다.

`초기 자세 고정 조건`과 `초기 분포 변경 조건`은 같은 실험 결과로 합치지 않는다. 목표에 맞춘 초기 정렬을 제공한 검사도 별도 조건명으로 기록한다. 분포의 구체 범위는 원본 기하·기존 관절 범위·물리 지지 확인 후 결정한다.

## 단계별 검사 행렬

| 단계 | 목표 조합 | 확인 목적 | 다음 단계 조건 |
|---|---|---|---|
| 0 | 중지·기존3번줄·8프렛 단독 | 초기 cap0.9 변경의 효과 | 동일 기준의 유효 학습·평가와 실패 원인 기록 |
| 1 | 4손가락 × 6줄 × 대표 프렛1·6·12·17·22 =120조합 | 낮은·중간·높은 프렛과 양 끝 줄에서의 편향·도달 문제 탐색 | 실패를 기하/제어/학습으로 분류하고 초기 분포의 편향 점검 |
| 2 | 4손가락 × 6줄 × 1~22프렛 =528조합 | 누락 없는 단일 압현 수행 확인 | 528행 각각의 검사 상태와 유효 평가 근거 확보 |
| 3 | 성공한 단일 목표 사이 전환, 이후 손가락 변경·동시 압현 | 단일 성공을 바탕으로 다음 난이도 진행 | 단일 성공과 전환 성공을 별도 판정 |

대표120조합이 모두 가능한 것으로 가정하지 않는다. 2단계에서는 이미 완료한 동일 조건의 대표 행은 근거를 재사용할 수 있으나, 초기 분포나 제어 계약이 바뀌면 변경 조건에서 재검사한다. 목표를 섞어 학습해도 평가와 결과 행렬은528조합별로 분리한다. 각 목표마다 별도 정책을 학습시킨 결과와 하나의 공용 정책이 여러 목표를 수행한 결과도 구분한다.

## 528행에 기록할 최소 항목과 판정

각 행의 키는 `손가락 × 줄 × 프렛 × 초기 조건 × 제어/학습 조건`으로 한다.

| 기록 | 구분할 사실 |
|---|---|
| 기하와 FK | 목표 셀 존재, 동일 패드 표본의 셀·줄·높이·방향, 비목표 간섭, 관절 범위·고정 축 조건 |
| 정책 명령 | 실제 decoder 행동 범위, 초기 bias, 포화, 요청각·적용각·실제각 차이 |
| native 참조 | 같은 초기 상태에서 유한 제어·PD·자유 기타 물리로 도달했는지; 정책 성공과 분리 |
| 학습과 평가 | 학습 예산·seed·원본 SHA, 독립 평가 횟수, 최초 접촉, 현행 압현 달성, 연속 유지·전체 유지 비율, 오압현 |
| 안전·초기 조건 | 물리/손목 종료, 초기 접촉, 기타 이탈, 조기 종료와 유효 관측 시간 |

행 상태는 `미검사`, `기하 확인`, `정책 범위 확인`, `native 참조 성공`, `정책 평가 성공`, `정책 평가 실패`, `실행 무효`로 구분한다. 기하 탐색 실패는 불가능의 증명이 아니고, 일부 에피소드의 성공은 안정적 성공률의 증명이 아니다. 단일 압현 성공은 기존 올바른 압현·오압현 veto·연속 유지·시간 조건으로 판정하며, 무효 run이나 조기 종료를 성공 분모에서 임의 제거하지 않는다. 추가로 음 전체 유지와 성공률을 보고하여 달성 기준만 통과한 짧은 접촉을 구분한다.

계산 자원을 쓰기 전 기하·명령 범위를 점검하고, 기존 GPU 연구와 겹치지 않도록 실행한다. 현재 문서 작성은 범위 조사이며 위 단계의 학습·실험을 완료했다는 뜻이 아니다.

## 최종 정책의 목표

최종 목표는528개의개별전용모델을모으는것이아니라, 손가락·줄·프렛 목표를입력받는단일압현정책의검증범위를528조합으로채우는것이다. 현재B8전용짧은비교는초기화문제를분리하는진단이다. 단독진단성공과목표조건부공통정책의전체범위성공은구분하며, 손가락전환/동시압현/곡학습은그다음단계다.
