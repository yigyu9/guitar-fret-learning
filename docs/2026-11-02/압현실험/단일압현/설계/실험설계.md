## 2. 대조와 초기 상태

과거 대표4목표는 large64/H32/100회=204,800전이에서 고정 정책32/32 성공, 학습 약497~504초였다. natural_press E4 중지 단음도100회 약518초·32/32였다. 모델 저장은0/100회뿐이므로100회가 정확한 수렴 경계라는 증거는 없다. 과거 2.5초 음 길이/연속1초와 이번1.5초/연속.6초는 별도 기준이다. 검지는 확률적 학습 중 달성0이면서 고정 정책32/32였으므로 학습 중 달성0만으로 중단하지 않는다.

목표에 맞춘 손목지원 초기 상태를 새로 만든다. 기존 v9 전신·하체 지지를 바탕으로 필요한 왼팔/손목 정렬을 계산하고, 초기 손가락은 대기 후보에서 시작하며 담당 패드는 목표 표면 위8~12mm를 첫 후보로 한다. 이 수치는 검사할 후보이며 모든 목표에서 확보됐다고 가정하지 않는다. 엄지 및 비담당 손가락의 초기 간섭도 확인한다.

초기화 검사는 실제 q/body FK 일치·native 범위·목표 손가락의 기존 압현 없음·초기 오압현 없음·기타/하체 안정성·3초 유지 후 기하를 포함한다. 초기부터 눌린 자세로 성공을 만들지 않는다. 실패하면 조합당 최대3분의 첫 탐색 예산에서 후보를 바꾸고, 미확보면 initial_unresolved로 남겨 다음 조합을 진행한다. 잘못된 초기 상태에서100회 학습을 낭비하지 않는다. 전체 초기 준비 예산은 약1시간으로 제한하며 남은 미확보 조합은 재검사 시간에 다시 다룬다. 탐색 미발견은 물리적으로 불가능하다는 뜻이 아니다.

목표 손목은 기존 유한 PD로 유지한다. 무한 고정·q 매 tick 덮어쓰기·추가 기타 지지력은 사용하지 않는다. 기타는 자유 강체·중력ON·스트랩OFF, root/하체 제어·질량·충돌·힘 상한은 기존과 같다. 목표 손가락4축만 학습하고 나머지 관절은 검증한 유한 유지 명령을 사용한다. 엄지 지지 학습은 이번 범위에 추가하지 않는다.

## 4. 전체를 순환하는 평가 일정

한 조합만100회까지 끝내지 않고 초기 검증이 된18개를25회씩 순환한다. 프렛/손가락이 편중되지 않게 순서를 분산하고 실행 순서를 시작 때 고정·기록한다. 모든 조합의 첫 결과를 먼저 확보한 뒤 미해결 조합을50→75→100회로 보낸다. 초기 미확보도18행에 남긴다.

각 경계에서 탐색 잡음 없는 고정 정책의 첫16개 에피소드를 평가한다. 종료·실패도 분모에 포함한다. 빠른 후보 기준은 다음을 모두 만족하는 것이다.

- 연속.6초 압현 달성≥15/16.
- 음 구간 평균 clean 비율≥90% (평균1.35초 이상).
- 물리 또는 손목 종료0.
- 평균 오압현 시간≤.05초.

후보가 다음25회 경계에서도 통과하면 그 모델을32개 첫 에피소드로 확인한다. 확인 기준은 달성≥31/32, 평균 clean≥90%, 물리/손목 종료0, 평균 오압현≤.05초다. 예를 들어25·50회가 통과하면50회에서 확인 후 중단한다. 100회에서 처음 후보가 되면 같은 모델의 독립 프로세스32개 평가로 재확인한다. 한 경계만 통과하고 다음 경계에서 퇴보하면 통과했던 모델도 별도32개 확인 후보로 보존한다. 동일 초기 반복의 평가이지 독립 학습 seed32개가 아니다.

25회 성과가0이어도 학습 중 확률적 기록만으로 탈락시키지 않는다.100회 예산 내 고정 평가 미통과는 budget_unresolved다. best 모델은 달성률→clean→낮은 오압현→낮은 종료율 순서로 선택하고 동률이면 더 이른 모델을 선택한다. 평균 보상만으로 선택하지 않는다. 평균 clean90%는 전구간 유지 성공률90%와 다르므로 둘 다 원시 지표로 보고한다.

예산이 부족하면 모든 조합25회·평가를 먼저 끝내고 남은 시간에 다음 경계를 공정하게 배정한다. 제시간에 실행하지 못한 조합은 not_run으로 표시한다. 실패하거나 미실행인 조합을 분모에서 지우지 않는다.

## 5. 8시간 일정과 자원 선택

시간 원점T0는 검증을 끝내고 사용자가 확인 가능한 실행 상태에 started_at을 기록한 감독 실행 시작이다. 감독 실행 내 초기 목표 준비·학습·평가·영상·정리를 모두8시간에 포함한다. 사전 도구 구현/소규모 검증 시간은 별도 공개하며, 완료되지 않은 구현을8시간 연구가 진행 중이라고 표시하지 않는다.

| T0 이후 | 우선 작업 |
| --- | --- |
| 0~1시간 | 초기화18개 확인, 작은 학습·strict 재개·평가·렌더 및 자원 점검 |
| 1~6시간 | 25/50/75/100회 순환 학습·평가·통과 조합 중단 |
| 6~7시간 | 미확보 초기화·실패 대표 재검사, 필요한 경우 seed17 확인 |
| 7~8시간 | 조합별 영상 완성,18행 집계·그래프·분석·검수 |

위 시간은 목표 배분이다. 실제 속도에 따라 업데이트하며 마지막 영상 예산은 확보한다. 6시간 이후 새 대규모 조건을 추가하지 않고,7시간 이후 새 학습을 시작하지 않는다. 8시간은 최소 연속 학습 시간이 아니라 전체 연구의 최대 시간 예산이다. 모두 조기 통과하면 남는 시간은 두 번째 seed/실패 진단에 쓰며 의미 없이 성공 모델을 계속 갱신하지 않는다.

기존64환경을 기본으로 한다.128/256환경은 짧은 기술 측정 후보이며 표본 처리량뿐 아니라 성공까지 걸린 시간·물리 실패·메모리를 확인해 채택한다. 매 조합에 환경 수 실험을 반복하지 않는다. 새로운 환경 수에 수렴 근거가 없으면64를 유지한다. 총 경험만 맞춰64환경100회를1024환경6회로 줄이지 않는다.

2조합 병행은 단독 기준과 작은 시험에서 총 완료시간·메모리·오류율이 개선될 때만 도입한다. 같은GPU의 다중물리 버퍼 사용이 미검증이면 단일 작업 큐를 유지한다. GPU100% 표시 자체를 목표로 하지 않는다. 영상 렌더는 GPU 학습과 겹치지 않는다. CPU 분석·결과표 갱신은 학습과 독립이면 함께 진행한다. 측정되지 않은 병행 가속을8시간 성공 보장에 넣지 않는다.

## 6. 중간 종료 방지와 복구: 구현 필수 조건

기존 run()은 실패 job의 자동 재사용을 거부하고 상위 단일 예외 처리로 전체 연구가 끝날 수 있었다. 그 보호를 제거하는 대신 새 감독기가 실패 시도를 보존하고 새 attempt 디렉토리로 재시도한다. 아래는 실행 전 구현·검증해야 할 요구사항이다.

1. 채팅/터미널과 독립된 감독 프로세스. 가능하면 user service로 관리하고 불가하면 독립 세션+별도 감시 프로세스를 사용한다. 감독기 PID·자식 PID·시작시각·명령·종료시각·heartbeat를 기록한다. 시작 도구 호출이 끝나도 감독기가 실제 살아 있고 학습 지표가 증가하는지 재확인한다. 절전 차단은 사용 가능한 방식으로 설정하고 확인한다. 재부팅/정전까지 방지한다고 약속하지 않는다.
2. 감독기는30초마다 상태를 갱신한다. 로그·학습 update·CPU/GPU 상태 등에서 진행을 확인하며 파일 크기만으로 성공 판정하지 않는다. 시작 준비와 실제 학습을 구분한다. 최초 시작5분/정상 학습 중 마지막 진행5분 초과 시 진단 후 관리하는 자식 프로세스 그룹만 종료한다. 상한은 파일럿 실측에 맞게 확정한다.
3. job은 pending/running/completed/retry_pending/blocked/budget_unresolved로 기록한다. 상태는 임시 파일 작성 후 원자적 교체, 완료는 보고서·모델·입력 SHA·실제 update 수를 검증한 뒤 확정한다. 결과에 오류가 난 학습을 완료로 표시하지 않는다.
4. 정상 복구본을 최대10회 간격, 평가용은25회 경계에 저장한다. 정책·optimizer·LR 일정·난수·계약을 검증한 정상 저장본만 재개한다. 중간 로그상 update 수가 더 높아도 checkpoint가 없으면 그 지점에서 재개했다고 기록하지 않는다. episode 상태 미복원 여부와 재개로 reset되는 범위도 계약에 명시한다. 복구 저장 비용을 포함해 파일럿 속도를 측정한다.
5. 일시적 자원/프로세스 오류는 최대2회, GPU 자식 정리·자원 반환·입력 무결성 확인 뒤 새 attempt로 재시도한다. 손상 파일을 덮어쓰지 않는다. 재개 불가시 fresh 재시작을 별도 seed/attempt로 명시하며 자동으로 다른 결과와 합치지 않는다.
