# 공통 출발에서 이동하는 단일 압현 재실험

기존 초기 자세 미확보9조합의 재실험이다. 대표3조합에서 기존 즉시배치(A), 공통 출발 이동(B), 이동과 실제 손목 피드백(C)을 비교한다. 준비가 실제 물리를 통과한 조합만 손가락 압현 학습으로 연결한다.

현재: 준비 실패9조합의 재검사·영상9개, 중지1번줄12프렛 large64/H32 100업데이트 학습·고정32평가·대표영상 저장 완료. 준비32/32 통과, 학습 정책 압현0/32. 별도의 알려진 손가락 각도 진단은 현행 물리 압현 기준1/1을 만족했다. [최종결과](분석/최종결과.md)에서 학습과 진단 결과를 구분한다.

프렛 운영 후보는 1~14, 경계 검증은 15~16, 보류는 17~22다. 이는 모든 손가락의 물리 가능 범위를 인증한 값이 아니며 각 조합의 실제 준비 검사를 별도로 요구한다.

- `설계/`: 대상과 비교 조건
- `tools/`: 새 버전 생성·실행·검증 도구
- `로그/`: 원시 물리 기록과 실행 상태
- `분석/`: 비교표·실패 원인·평가 결과
- `video/`: 조합별 대표 영상만 저장

이동은 팔의 유한 보조 제어이며 팔 정책 학습 성공을 뜻하지 않는다. 준비 실패도 전체 결과에 포함하고, 학습 전 준비 성공과 실제 손가락 압현 성공을 구분한다.

현재 학습 원장은 `로그/learning100_eval_render_v4/state.json`, 준비 재검사는 `로그/retry_failed_C/state.json`, 대표 비교는 `로그/representative_ABC/state.json`에 있다. CPU 검사는 손·손목 대 전체 기타의 표본 분리 검사이며 전완·어깨·몸통 무충돌 인증이 아니다. native 준비 통과도 목표 접촉/오압현과 기존 물리 보호 기준의 통과이며 모든 접촉쌍 부재를 의미하지 않는다.

현재 학습·평가·영상의 실행기는 `tools/learning_runtime_v4.py`다. 이전 버전은 실패 원인과 검증의 원문으로 보존하며 신규 학습에 사용하지 않는다. `tools/transport_runtime.py`는 현행 운반 보조 함수로 재사용한다.
