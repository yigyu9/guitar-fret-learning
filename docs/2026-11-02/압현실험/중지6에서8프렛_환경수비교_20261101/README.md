# 중지 3번줄 6→8프렛 전환

256·512·1024환경의 GPU 처리량과 안정성을 같은 경험량으로 비교하고, 적격 조건 중 가장 빠른 설정에서 새로운 6→8 정책을 두 난수로 학습한다. 보상·제어·탐색·학습률은 함께 변경하지 않는다. 기존 6→7 모델과 생산 코드는 보존한다.

## 어디서 확인하나

- [승인된 계획과 체크리스트](PLAN.md)
- [환경 수 비교 진행·결과](benchmark/RESULTS.md): 기존 6→7 workload의 처리량 비교이며 6→8 압현 성능이 아니다.
- [독립 코드 검수](REVIEW.md): CPU 33개 검사와 KL 분기 8개 검사 통과. 실제 물리 성공은 별도로 확인한다.
- [실제 GPU 실행 검증](GPU검증.md): large·1024 학습·저장·재개·평가·영상 통과 후 두 난수의 본 실험을 시작했다.
- [참조 검증 기록](참조검증기록.md): 실행 설정 오류와 B 초기 접촉 지연을 구분하고 기준을 유지한다.
- `validation/`: 참조 경로의 실제 물리 검증. 최초 v1은 환경 생성 설정 오류로 물리 실행 전에 중단했다. 당시 원문·소스 스냅샷은 보존했다.
- `learning_v1/진행상황.md`: 참조와 환경 수 비교를 통과한 뒤 시작하는 실제 학습·평가의 자동 갱신 상태.
- `동영상/`: 실제 학습 정책의 손 확대·전신 MP4만 저장. 참조 경로의 성공을 정책 성과로 표시하지 않는다.
- 공개 영상은 실험 완료·봉인 검증 후 실제 촬영의 압현 결과와 반복 평가를 기준으로 대표 손 확대·전신 한 쌍만 남긴다. 별도 CPU 감시기가 동결된 학습 코드를 수정하지 않고 완료 후 정리한다. 원본 렌더는 검증 자료로 보존하며, [정리 상태](../../../maintenance/video_selection_20261101/active_video_cleanup.md)를 따로 기록한다.
- `tools/`: 이 실험만의 목표 준비·참조 검증·실행·분석 도구. 생성 과정과 로그는 영상 디렉토리에 섞지 않는다.

## 결과 해석

매번 A6을 3.00–4.50초에, B8을 5.25–6.75초에 누른다. 휴지 0.75초이며 실제 초기 상태는 기존 A6 기준과 같다. 0.6초 연속 압현 달성과 각 음 전체 1.5초 유지, 이전 음 말미 유지와 다음 음 정시 시작은 서로 다른 지표다. 물리·손목 종료를 평가 분모에서 빼지 않는다.

학습 비교는 반복 수 대신 실제 경험 수로 보고한다. 환경 수가 커지면 한 번의 수집량과 최적화 횟수도 달라진다. 처리량 개선을 같은 비율의 수렴 개선으로 해석하지 않는다. 평균 정책과 탐색을 포함한 정책을 구분하며, 반복 평가에 따른 변동도 기록한다.
