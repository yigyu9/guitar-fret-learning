# 실제 물리 참조 검증

정책 학습과 구분한 사전 검사다. 초기 상태 이후 상태를 덮어쓰지 않고, 자유 기타·중력·기존 유한 제어와 접촉 판정을 그대로 사용한다.

## v1: 생성 설정 오류

진단의 노출 일정 2/1이 현행 생성 계약에 맞지 않아 물리 실행 전에 중단했다. 4/1 계약으로 수정하고 CPU 회귀 검사를 추가했다. 실패 로그와 수정 전 소스·SHA는 `validation/reference_native_v1/`에 보존한다. 물리 도달 불가능의 증거가 아니다.

## v2: 시작 직후 한 물리 구간의 접촉 지연

- A6: 전체 1.5초 clean, 최초 clean 3.004167초.
- B8: clean 1.495833초, 최초 clean 5.258333초. 전체 1.5초·시작 지연 1/240초 이내 기준은 미통과.
- 물리·손목 실패 없음. 상태 중간 재설정 없음. 소스 불변·장면 정리·유한 상태·물리 clock 검증 통과.
- 5.250000초: B 위치·방향 조건은 참이지만 하중 조건은 거짓. 패드 높이 약 1.002mm.
- 5.254167초: 하중·후보 접촉이 처음 참. 이전·현재 후보를 함께 요구하므로 최초 지속 clean은 다음 물리 시점이다.

`native_verified=true`는 약한 90% 유지 검사만 통과했다는 뜻이다. `accepted=false`이므로 자동 실행기는 본 학습을 시작하지 않고 종료했다. 이를 성공으로 바꾸거나 기준을 완화하지 않는다.

## 다음 단독 확인

목표·시간표·휴지 0.75초·후보 관절각·초기 상태·제어·물리·성공 기준을 유지한다. 참조의 이동을 0.55→0.45초로 하고 안착을 0.20→0.30초로 바꿔 B 요청각 도착을 5.05→4.95초로 앞당긴다. 기존 코드와 v2 원문은 보존하며 새 `settle030` 파일·`validation/reference_native_v3/`를 사용한다.

연속 최대 요청 속도는 팔 0.450rad/s, 중지 1.692rad/s로 기존 3/4rad/s 제한 이내다. 안착 시간 부족이라는 해석은 새 물리 결과로 확인해야 하며, 이 참조 경로 변경은 정책 보상·학습 구조 변경이 아니다.

## v3: 엄격한 참조 기준 통과

0.30초 안착 경로에서 A6·B8 모두 clean 1.5초, 최초 clean은 각각 3.004167·5.254167초로 시작 후 한 물리 tick 이내다. 물리·손목 실패 없이 `accepted=true`, 소스 불변·clock·장면 정리·유한 상태 검사를 통과했다. 이전 실패를 덮어쓰지 않았다.

관측된 경로에서는 안착 시간을 추가한 변경으로 시작 지연을 해결했다. 임의의 경로·난수·환경 수에 대한 일반화나 정책 학습 성공을 증명한 결과는 아니다. 원문은 `validation/reference_native_v3/report.json`, 실제 상태·접촉 기록은 같은 디렉토리의 `trace240.npz`다.
