## 손가락 미동작 해석 독립 대조

사용자의 "손목 단계 미통과로 움직이지 않는가" 질문에 따라 원시 NPZ·1320행240Hz trace·initial/final checkpoint·정책/제어 코드를 CPU로 재확인했다. CUDA는 초기화하지 않았다.

- J33은 지지17축과 손가락16축을 공동 출력한다. `finger_skill_environment.py`의 현행 계약은 순차 phase/music-stage gate가 없음을 명시하며, `gpu/control.py:446` 이후는 행동을 기준각 오프셋으로 직접 변환한다. `training/policy.py:549` 이후의 결정론적 경로는 탐색 noise 없이 평균 latent의tanh를 사용한다.
- native 평가가330tick·5.5초 `timeline_complete`이고 손목 영역 내 비율1.0이다. 저장된60Hz 손목 active/누적위반/severe위반 값은 모두0이며 압현 창 관측은1.5초다. 손목 단계를 기다리며 에피소드가 멈춘 상황이 아니다.
- 검지/중지4축의 정규화 행동 최대 절댓값은각0.00203728/0.00359681이다. 실제 각도 peak-to-peak의 축별 최댓값은 전체0.131411°/0.105082°, 공통 창0.0388245°/0.0223211°다. 창 내 축별 target-q RMS의 최대는0.0066267°/0.0066765°로 작다. 기록은 큰 굽힘 명령이 구동기에서 막혔다는 설명보다 작은 정책 출력과 작은 실제 움직임에 부합한다.
- trace의 올바른 env0 episode identity는 episode report에 기록된1이며1320행이다. 해당 공통 창의 목표 표면 거리는 검지53.160~53.444mm, 중지53.238~53.619mm로, 압현 위치에 접근하지 못했다.
- initial/final checkpoint를 CPU에서 직접 읽어 update0→20과 검지/중지 최종 출력층의 초기0→변경True를 확인했다. 최종 weight/bias 최대 절댓값은각0.000638407/0.000613504이며 finger std는0.0497676~0.0498197이다. 학습 업데이트 자체가 실행되지 않은 상태는 아니다. 영상은 탐색 noise를 제외한 최종 평균 정책의1회 실행이다.

확인 가능한 직접 설명은 "짧은 pilot의 학습된 평균 행동이 거의0이어서 미세하게만 움직였다"다. 보상 구조·학습량·탐색 분산 중 무엇이 이를 유발했는지는 이 기록만으로 인과 확정할 수 없다. "미학습"을 업데이트0이라는 뜻으로 쓰지 않고 "압현 동작을 아직 습득하지 못한20업데이트 pilot"으로 설명하는 것이 정확하다. 소스·모델·기존 실행 상태는 변경하지 않았다.
