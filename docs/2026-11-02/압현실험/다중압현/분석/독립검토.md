## 1차 판정: 수정 권장

### Critical

### Warning

1. `도구/common_pose.py:42` — 실제 도착 입력은 q/state 일치와 몸체 개수만 확인하며 case·관절/몸체 이름 순서·출처·물리 단계 identity를 검증하지 않는다. `case_id='wrong_case'`, 빈 `joint_names/human_body_names`, 첫 두 몸체 상태 교환을 넣어도 수용하며 FK 재현 오차는 약 `3.1e-16 m`다. 재보정 FK는 주어진 상태를 기준으로 만들기 때문에 작은 재현 오차로 입력 정합성을 증명할 수 없다. 실제 도착 입력 schema와 case·이름 배열·source SHA·scene/step을 검증하고 거부 회귀검사를 추가해야 한다. 단위 quaternion 검증도 필요하다(2배 quaternion을 자동 정규화해 수용함).
2. `도구/common_pose.py:167`, `도구/common_pose.py:195` — `pins.update(imported_pins())`는 이미 고정한 기대 SHA를 현재 SHA로 덮는다. 새 도구가 실행 중 바뀌어도 마지막 검증이 새 값으로 통과할 수 있다. 처음 본 경로만 추가하고 기존 기대값은 유지한 뒤 비교해야 한다. 활성 프로젝트·봉인 입력은 별도 `protected` 검증이 있으나 새 연구 도구는 이 경로에 해당한다.

### Suggestion

## 확인된 사항

- 단일 성공은 `single_evidence` 참고 정보이며 새 사례·탐색 결과의 `native_verified=False`를 유지한다.
- 두 목표 잔차는 같은 q105에서 평가한다. 준비→압현에서 팔12축이 동일하고 미배정 관절은 유지한다. 실제 도착 경로는 담당 손가락8축만 최적화한다.
- 240Hz 연속 끝점 검증과 두 끝점의 두 목표 clean 교집합 적분을 사용한다. 개별 달성 latch가 서로 다른 시간에 생겨도 전체 성공으로 상속하지 않는다. 잘린 기록·누락·중복·비유한 입력을 거부하고 유지율 분모1.5초를 보존한다.
- 활성 환경 합성 검사는 허용된 다른 손가락을 오압현으로 보지 않는 경우와 같은 줄 서로 다른 프렛 거부를 검사한다. 활성 환경 원장의 개별 latch는 동시 유지 증명이 아니므로 별도 측정기가 필요하다.
- CPU 도구는 Isaac Gym 장면을 생성하지 않는다. 구현의 `physical_success_certified=False`와 기하 후보의 `native_verified=False`로 합성·기하·실제 물리 근거를 구분한다.
- `inputs.py verify` 결과 보호 대상193파일 SHA가 모두 일치했다. 실행 중 단일 상태/출력을 고정하지 않고 사본을 읽는 구조다.
