## 확인한 사항

- 사용자 승인 문서는 작은 병행 시험 후 영향 확인을 조건으로 확대하며 기존 single 보존을 유지한다. 이 리뷰는 병행 자체를 이전 금지 조건으로 거부하지 않고 새 승인 범위의 조건부 실행을 검토했다.
- 자원 gate는 GPU UUID·유한한 여유4GiB·최대1개의 기존 single native process만 허용한다. 정확한 script 위치·geometry/out/case 옵션·프로세스 시작 tick을 검사하며 GPU/PID/state를 다시 읽어 관측된 교체·PID 재사용을 차단한다. 외부 script의 단순 인자에 single 경로가 들어간 경우는 허용하지 않는다.
- 병행 native job은 v2의 공식 trainer/evaluator·metadata·체크포인트 SHA/부모 identity·설정 digest 검증을 유지하고 새 승인/gate만 추가한다. 부모 보상·PD·물리·동시240Hz 측정 로직을 바꾸는 diff는 없다.
- 새 child는 별도 session/process group으로 생성한다. 감시의 실패 종료 경로는 이 child의 group만 대상으로 하며 기존 single PID를 종료하는 코드는 없다. 실행 중 메모리2GiB하한·GPU 조회 실패·새 single 검사 오류·비교 가능한 완료 건의 지연을 감시한다.
- 영향 검사에서 목표 난도·CPU 비용·부분 시간 겹침이 혼입될 수 있음을 명시하고 준비 실패를 소요시간 비교에서 제외한다. 이는 인과 효과의 증명이 아니다.
- 신규22 CPU검사를 독립 실행해 전부 통과했다(약0.02초). 기존 봉인 v1의548개, v2의553개 pin도 다시 검증해 일치했다. 이22검사에는 위 두 단계/재개 반례가 아직 포함되지 않았다.

최종 병행 manifest 생성기는 아직 부모 작업자가 작성 중이다. 새 원장·pilot 예산·정식 학습 분모·출력 경로·정적 설정·pin은 생성기와 실제 봉인 후 별도 재검토가 필요하다. 실제 GPU 병행 영향 및 native 연결은 아직 검증하지 않았다.
