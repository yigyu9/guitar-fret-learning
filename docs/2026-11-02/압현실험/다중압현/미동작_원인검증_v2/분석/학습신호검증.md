# 손가락 미동작: 학습 신호와 탐색 검증

2026-11-02. 완료된 `pilot_env2/J`와 그 `final.pt`로 촬영한 실제 native 기록을 CPU에서 읽었다. 활성 코드·보상·PD·힘 상한·관절 범위·모델·큐를 변경하거나 GPU를 사용하지 않았다.

현재 영상에서 손가락이 거의 움직이지 않는 직접적인 이유는 **학습 후 결정론적 정책의 명령 자체가 매우 작기 때문**이다. 학습 중에는 더 큰 무작위 명령과 실제 관절 움직임이 있었다. 따라서 “손가락 명령이 전달되지 않았다”, “학습 업데이트가 실행되지 않았다”는 설명은 이 기록과 맞지 않는다. 다만 작은 평균 명령이 남은 원인을 학습량·탐색·준비 보상 중 하나로 확정할 자료는 부족하다.

## 확인한 사실

### 학습은 실행됐지만 작은 파일럿이다

- 20 업데이트 × 2 환경 × 32 제어 tick = 1,280 transition. 환경당 640 tick, 실제 물리 시간 10.667초다. 경과시간은 120.173초다.
- 완료 에피소드는 총 2개로 각 환경에서 321 tick/5.35초짜리 첫 에피소드 하나씩이다. 각 환경의 다음 319 tick도 PPO에 들어갔지만 완료 에피소드가 아니다. 완료 에피소드 수만 세어 이 후반 학습을 누락해서는 안 된다.
- 각 업데이트의 actor minibatch 2회, 총 **40회 수락**, 거부 0회, KL 재시도 0회다. analytic KL 범위는 0.0002604–0.0040221로 설정 상한 0.02보다 작다. actor 학습률은 기본 `3e-5`, value 학습률은 `3e-4`, epoch 2, 최대 gradient norm 0.5다. 기록된 clip 전 actor gradient norm은 15.21–24.78이다.
- 체크포인트 업데이트 수는 initial 0, final 20이다. 검지·중지 마지막 출력층은 초기 0에서 실제 변경됐다. 파라미터 변화 L2는 각각 0.004550, 0.005395다. 모든 gradient가 각 손가락에서 유효한 압현 방향이었다는 증거는 아니다.

### 접촉 성공 신호는 발견되지 않았다

완료 에피소드 두 개에서 각 목표의 contact time·clean time·달성은 모두 0이었다. 20 업데이트 전체의 `song_left_contact`, `song_clean_hold`, `song_left_success` 합계도 0이다. PPO의 입력 신호 전체가 0이었던 것은 아니다. 접근 potential, 수행 부족, 대기 자세, 엄지 보상은 존재했다.

`reward_component_means × 해당 transitions`의 합계는 접근 −1.8063, 수행 부족 −0.8000, 대기 +0.3271, 엄지 +0.03047이다. 접근 보상은 할인 potential 차이와 종료 시 `nextPhi=0` 정산이므로, 이 합계가 음수라는 이유만으로 손가락이 목표에서 멀어졌다고 해석하면 안 된다.

240Hz 학습 trace는 환경 0의 최초 600 제어 tick, 2,400 표본까지만 있다. 이 범위의 최소 패드 목표 거리는 검지 46.795mm, 중지 47.460mm이고 후보 표본은 모두 0이다. 목표와 상당한 거리가 남았다는 측정이지, 유한 탐색으로 물리적 불가능을 입증한 것은 아니다.

### 무작위 탐색과 영상의 평균 정책을 구분해야 한다

정책은 J33의 33축 공동 likelihood를 쓰며 각 축 독립 Gaussian, K1이다. 16 손가락 축의 최종 latent 표준편차는 약 0.04977–0.04982로 초기 0.049787과 거의 같다. 위치 codec은 준비 기준각 주변의 절대 목표를 요청한다. 매 tick의 무작위 행동을 관절각 증분으로 누적하지 않는다. 정책이 상태를 이용해 일관된 명령을 학습하는 것은 가능하지만, 현재 잡음 자체가 장시간 같은 방향의 굽힘을 보장하지 않는다.

| 기록 | 검지 | 중지 |
|---|---:|---:|
| 학습 행동 표준편차, 4축 범위 | 0.04786–0.05237 | 0.04794–0.05114 |
| 학습 행동 lag-1 상관, 4축 범위 | −0.0549–0.0744 | −0.0592–0.0642 |
| 학습 행동 인접 부호 반전 비율 | 46.7–51.5% | 49.0–50.3% |
| 학습 요청각 표준편차, 4축 범위 | 0.0260–0.0550rad | 0.0199–0.0561rad |
| 학습 실제각 표준편차, 4축 범위 | 0.00610–0.01403rad | 0.00494–0.01465rad |
| 실제 영상 결정론적 행동 최대 절댓값 | 0.002037 | 0.003597 |
| 실제 영상 실제각 최대 peak-to-peak | 0.1314도 | 0.1051도 |

상관과 반전은 240Hz의 같은 명령 4표본을 반복 계산하지 않고 **제어 tick당 한 표본, reset 사이를 제외한 598쌍**으로 계산했다. 학습 실제각 변동이 요청각 변동보다 작다는 것은 관측 사실이다. 속도 제한과 native 관절 응답이 각각 얼마나 기여했는지는 별도 진단 없이는 나눌 수 없다.

영상은 같은 final 체크포인트 SHA를 확인한 뒤 각 60Hz에서 `tanh(mean)`만 재계산한 결정론적 실행이다. 검지 행동 평균은 축별 약 −0.001625, −0.000409, −0.000094, −0.001220이고, 중지는 −0.000189, −0.000163, +0.002480, −0.001930이다. 학습 중 표준편차 0.05의 잡음이 사라지면 작은 평균만 남아 영상에서 거의 정지한 것처럼 보이는 결과와 맞는다.

마지막 출력층의 최대 파라미터 절댓값 0.000638/0.000614를 정책 평균으로 오인해서는 안 된다. 이 값은 가중치 하나의 크기다. 전체 출력층의 Tanh 입력 경계로 계산한 모든 입력에 대한 latent 절댓값 상한도 JSON에 따로 기록했고, 실제 영상의 명령은 그 상한보다 훨씬 작다.

native trace 파일에는 전체 1,408 표본 중 선택한 첫 촬영 에피소드 1의 1,320 표본과 다음 에피소드 88 표본이 함께 있다. 60Hz 자세 저장 330개는 첫 에피소드만 해당한다. `capture_metadata.training_updates=0`은 촬영 도중 업데이트가 없다는 의미이며, 읽어 온 final 모델이 미학습이라는 뜻이 아니다.

## 초기 목표 관측과 준비 보상의 시간창

실제 컴파일 목표의 `press_s`는 둘 다 **3.0초**, `onset_s`는 3.24/3.30초다. 프렛은 둘 다 6, 배정은 검지 3번 줄과 중지 2번 줄이다. onset에서 준비 시작을 역산하면 잘못된 결과가 나온다.

일반 event lookahead는 **4초**여서 두 목표가 초기 관측부터 일반 event 문맥에 들어간다. `finger_control_trace.targets.target_present`는 자기 손가락의 우선순위 tracking 슬롯을 가리킨다. 이것이 초기 false인 사실만으로 정책이 목표를 전혀 못 봤다고 주장할 수 없다.

| 악보 시각 | 일반 event 목표 | 자기 tracking 목표 | 담당 손가락 standby gate | 접근 가중치 |
|---|---|---|---:|---:|
| 0–1.0초 직전 | 있음 | 없음 | 1 | 0 |
| 1.0–2.55초 | 있음 | 있음 | 1 | 0 |
| 2.60초 | 있음 | 있음 | 0.5 | 0.5 |
| 2.65초 이후, 압현 중 | 있음 | 있음 | 0 | 1 |

따라서 초기 목표 관측 결함이 확인된 것이 아니라, **자기 목표 노출 이후에도 약 1.55초간 접근 potential 가중치는 0이고 대기 자세 보상이 유지되는 시간차**가 확인됐다. 초기 준비 동작 학습을 늦출 수 있는 후보지만, 현재 한 파일럿으로 실패 원인이라고 확정할 수 없다. 담당하지 않은 두 손가락의 대기 보상도 계속 있으므로 총 대기 보상을 전부 담당 손가락의 억제로 해석하면 안 된다.

## 개선을 검증할 다음 비교

1. 먼저 동일 물리·PD·힘·범위에서 명시한 부드러운 굽힘 trajectory로 충분한 요청각에 실제 관절이 응답하는지 확인한다. 현재 평균 정책의 작은 요청과 구동 실패를 구별한다. 이 진단은 학습 정책의 성공이 아니다.
2. 현재 K1·동일 std·같은 초기 상태를 대조군으로 유지하고, 충분한 공통 탐색 방향과 유지시간을 주는 **별도 조건**을 비교한다. 새로운 시간 상관 탐색은 likelihood·수집 계약이 달라지므로 기존 checkpoint를 암묵 재개하거나 K1 결과와 동등하게 취급하지 않는다. 표준편차만 올리는 것은 더 큰 고주파 흔들림이 될 수도 있다.
3. 기존 활성 `FingerSkillEnvironment.natural_preparation.v3` E0–E4 hook으로 준비 신호를 분리 검증할 수 있다. E1은 초기 자기 목표 관측, E2는 초기 담당 손가락 대기 보상 해제, E3은 hover 접근 potential, E4는 결합이다. E2 단독은 기존 관측과 접근 가중치를 앞당기지 않는다. `PairEnvironment`의 별도 subclass에 class attribute를 설정하고 **새 조건·새 계약·새 출력·fresh 학습**으로 비교하면 활성 코드 변경이 필요 없다. 아직 이 비교를 학습하거나 기존 결과에 성공을 상속하지 않았다.
4. 학습량은 같은 수의 전체 에피소드·동일 노출 예산·여러 seed에서 비교한다. 현재 환경당 약 두 에피소드의 짧은 예산은 일반적 학습 가능성을 판정하기에 부족하다. 예산을 늘리기만 하면 해결된다는 인과 결론도 성립하지 않는다. 접촉 후보 발견률, 동시 clean, 평균 정책 명령 크기, 실제 굽힘과 이동 경로를 중간 판정 지표로 삼는다.

동일한 명령 표준편차를 갖는 절대 목표를 1차 저역통과 수학 모형에 넣은 작은 비교도 저장했다. 가정한 시정수 0.10초에서 K1 응답 표준편차 0.01460, 16 tick 유지 조건 0.04006이다. 시간 상관이 응답에 영향을 줄 수 있다는 예시이며, 시정수를 native에 맞춘 결과나 물리 압현 성공을 뜻하지 않는다.

## 재현과 검증

최종 수치·읽은 원시 파일 SHA·명령은 `../로그/learning_signal/verified_v2/report.json`과 `invocation.json`에 저장했다. 앞선 `report.json`, `final/`, `verified/`는 이 작업 중 단계별 산출물이며 최종 해석에는 `verified_v2`를 사용한다.

```bash
python -B docs/2026-11-02/압현실험/다중압현/미동작_원인검증_v2/도구/learning_signal_audit.py --out docs/2026-11-02/압현실험/다중압현/미동작_원인검증_v2/로그/learning_signal/새결과경로
python -B -m unittest discover -s docs/2026-11-02/압현실험/다중압현/미동작_원인검증_v2/도구/tests -p test_learning_signal_audit.py -v
python -B -m unittest guitar_learning.tests.test_natural_preparation -v
```

새 검사 3개 및 기존 natural preparation 검사 12개가 통과했다. 신규 코드는 독립 검토 대상이다. 이 문서의 학습 신호 분석과 수학 모형만으로 압현의 물리 가능성·현 압력·음향 성공을 주장하지 않는다.
