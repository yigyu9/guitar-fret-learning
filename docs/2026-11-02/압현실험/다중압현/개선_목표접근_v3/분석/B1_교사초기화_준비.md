# B1: 실제 동시 압현 교사를 이용한 새 actor 초기화

2026-11-02. `goal_nominal_v1`의 실제 native 경로가 공통 음 구간 1.5초 전체에서 동시 clean·안전·오압현 없음·두 개별 달성을 만족했다. 이 경로만 B1의 교사 후보로 사용한다. 학습 정책의 성공을 미리 상속하지 않는다.

## 코드와 실행 전제

`도구/teacher_bootstrap.py`는 원시 report/guard/episode/metadata/settings/teacher observations/poses와 원 진단 manifest·소스·모델 SHA를 검증한다. report의 `teacher_eligible=true` 하나에 의존하지 않고 두 목표 동시 clean 누적·최장 구간·관측이 각각 1.5초인지, 오압현/unsafe가 0인지, 개별 둘 다 달성했는지, 전체 330 제어 tick/1,320 physics tick이 연속인지, 중간 상태 주입이 없었는지 확인한다. 부분 실패·개별 latch만 성공·기하 후보·다른 target ID는 거부한다.

330행 전체를 사용한다. 각 행은 행동 전 `state557/events64×24/priority8×24/masks`와 실행한 `action39`이다. poses는 같은 행동의 네 substep 후 상태이므로 관측으로 바꿔 넣지 않는다. action과 poses action의 정확한 일치, 관측의 pre-action 시계, 연속적인 pose 시계와 유한성을 검사한다. MP4는 BC 입력이 아니므로 파일 이동과 관계없이 사용하지 않는다.

원 pilot 체크포인트는 native 진단에서 동일성이 확인된 **전체 E0 계약과 아키텍처를 읽는 데만** 사용한다. 가중치·가치함수·PPO optimizer·RNG는 가져오지 않는다. 새 `FingerSkillPolicy`를 seed7로 처음부터 만들고 std·critic은 fresh 상태를 유지한다. E4 초기화를 암묵적으로 적용하지 않는다.

## 명시적인 계약 투영

source 전체 계약을 복사하고 다음 두 필드만 변경한다. 물리·PD·관절·힘·codec·관측·task·target·접촉·보상·종료·동시 성공 정의는 그대로다.

| 계약 필드 | 원 native 교사 계약 | B1 새 예산 계약 |
|---|---:|---:|
| `task.finger_skill.planned_transitions` | 1,280 | 204,800 |
| `task.finger_skill.full_song_after` | 320 | 51,200 |

이는 PPO resume 호환성 완화가 아니다. 새 actor 초기화 산출물 schema는 `multi_press.teacher_actor_initialization.v1`이고 전체 source/target 계약·두 필드 투영·교사/봉인 계획 계보를 기록한다. 원 모델로 trainer resume를 호출하지 않는다. 실제 native 평가 pool의 `portable(pool.contract)`가 이 **전체 target 계약과 정확히 같아야** actor를 넣을 수 있다.

## 고정 CPU 학습 예산

- medium 모델, seed7, CPU 1스레드.
- 400 minibatch step × 64행 = 25,600 sample visit, 매번 복원 추출.
- Actor Adam 학습률 0.001.
- 원 active33축의 `tanh(mean)`와 실제 teacher action의 평균 제곱 오차를 최소화한다. 6개 비활성 오른손 행동은 이 목표에서 제외한다.
- support/finger actor 파라미터만 학습한다. std·critic·buffer가 초기값과 byte 단위로 같은지 종료 시 검사한다.
- 40 step마다 전체 330행의 active33 RMSE, 담당8축 RMSE/최대오차/축별 오차를 기록한다. 이는 **동일 교사 관측에 대한 적합 오차**이며 holdout이나 실제 폐루프 성공률이 아니다.

최종 파일에는 actor 파라미터만 저장한다. `load_actor_artifact(policy, path, expected_contract, expected_sha256)`는 결과 보고서의 artifact SHA, 전체 계약·architecture·actor keyset, 원시 교사 pins와 봉인 계획 SHA를 확인한 후 actor만 복사한다. std·critic·PPO optimizer·RNG는 복사하지 않는다.

## CPU 검증과 다음 명령

새 검증 7개는 실제 raw teacher 자격/330행 정렬, 두 계약 필드만 변경, E4 거부, 부분 경로·개별 성공의 거짓 양성 거부, actor 한 step에서 std/critic 불변, actor artifact 왕복 후 불변·전체 계약/모델 SHA 불일치 거부를 확인했다. 400 step의 실제 bootstrap은 독립 검토와 봉인 후 root가 실행한다. 지금 저장한 `설계/B1/bootstrap_plan_draft.json`은 `sealed=false`인 초안이다. 최종 봉인 시 현재 소스에서 `build_plan()`을 다시 호출해야 한다.

```bash
python -B -m unittest discover -s docs/2026-11-02/압현실험/다중압현/개선_목표접근_v3/도구/tests -p test_teacher_bootstrap.py -v
python -B docs/2026-11-02/압현실험/다중압현/개선_목표접근_v3/도구/teacher_bootstrap.py --plan docs/2026-11-02/압현실험/다중압현/개선_목표접근_v3/입력/B1_bootstrap_plan_v1.json --out docs/2026-11-02/압현실험/다중압현/개선_목표접근_v3/로그/B1_cpu_bootstrap_v1
```

BC 후에는 같은 모델을 실제 물리에서 결정론적으로 실행해 동시 clean과 관절·손목 경로를 다시 측정해야 한다. 한 경로의 관측 분포 밖으로 나가면 작은 모방 오차도 누적될 수 있다. B1은 E0이고 B2는 E4이므로 서로 다른 조건으로 남긴다. 접촉 성공은 현재 하중·표면 기하 기준이며 현 압력·음향 성공과 구분한다.

## 후속 실제 실행 완료

독립 검토 후 634개 pin의 계획을 봉인하고 400 step CPU 학습을 완료했다. 이어 639개 pin의 별도 실제 평가에서 새 정책만으로 1.5초 동시 clean·오압현0·안전 이탈0을 재현했다. [CPU 결과](B1_CPU학습결과.md), [실제 개선 결과·영상·한계](개선결과.md), [현재 실행 상태·다음 명령](실행현황_다음명령.md)을 따른다. 이는 한 과제의 첫 결정론적 검사이며 일반화나 PPO 학습 성공을 뜻하지 않는다.
