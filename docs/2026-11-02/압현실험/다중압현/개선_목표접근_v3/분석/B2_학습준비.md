# B2 E4 학습 준비

2026-11-02. 검지·중지, 인접한 3/2번 줄의 6/6프렛 한 과제만 준비했다. GPU 학습·평가·시뮬레이터는 아직 실행하지 않았다. `설계/B2/training_manifest_draft.json`은 `executable=false`, 내부 candidate는 `sealed=false`여서 실행기가 거부한다. 다른 신규 진단 코드까지 독립 검토한 뒤 root가 전체 소스 SHA를 다시 확인하고 별도 실행 manifest를 봉인한다.

## 조건과 비교

`ImprovedPairEnvironment(PairEnvironment)`는 기존 공식 `natural_preparation.v3/E4` class attribute만 설정한다. 초기부터 자기 목표 관측을 제공하고, 담당 손가락의 초기 대기 보상을 해제하며, 목표 위 hover 영역 접근 potential을 사용한다. 기존 J33/K1 정책·PPO·native PD·힘 상한·관절 범위·접촉·오압현·안전·동시 clean 판정은 상속한다. 관측 차원은 557, 행동 차원은 39이고 실제 학습 likelihood는 기존 J33이다. 보상·관측의 E4 차이는 새 condition과 checkpoint 계약에 명시한다.

조건은 B2/fresh/teacher 없음이다. 초기 model/Adam/RNG를 과거 checkpoint에서 가져오거나 재개하지 않는다. 검증되지 않은 기하·trajectory를 교사로 사용하지 않는다. B1은 실제 경로의 native 동시 clean 검증 후 별도 조건으로 구현해야 하며 이 코드에는 없다.

| 항목 | B2 E4 |
|---|---:|
| 과제 | index_middle_same, 검지·중지 6/6프렛 |
| 학습 환경/수집 길이/업데이트 | 64 / H32 / 100 |
| seed / 네트워크 | 7 / medium |
| 학습 transition | 204,800 |
| 환경당 제어 tick / 물리 시간 | 3,200 / 53.33초 |

| 공통 음 구간 | 악보 시각 [3.30,4.80]초 |

비교 기준선 B0는 기존 정식 6과제 큐의 `index_middle_same_train`과 평가를 사용한다. 64환경/H32/100/seed7·fresh와 같은 조건이며 E4 준비 신호만 바뀐다. 과거 2환경/20업데이트 pilot과의 성능 차이를 E4의 인과 효과로 해석하지 않는다. 한 seed·한 과제의 결과는 초기 검증이다.

## 실행과 보호

- 실행 전 원래 336검사 완료, 원래 정식 6과제 train/evaluate 총 12작업의 완료·report SHA, GPU UUID와 유휴 상태를 모두 검사한다.
- `runtime()`는 공식 `GpuPool.environment_class_override`와 기존 `_pins` 확장만 연결한다. 원래 trainer의 strict metadata·source·architecture·checkpoint 검증은 그대로 호출한다.
- 평가 checkpoint는 새 B2 train 출력의 `J/final.pt`로 한정하고, metadata 설정 digest·E4 architecture 계약·앞선 완료 보고서의 checkpoint SHA가 모두 맞아야 한다. 기존 B0·pilot checkpoint를 바꿔 넣으면 거부한다.
- 출력이 이미 있으면 자동 재시도·암묵 재개를 거부한다. 평가 분모가 정확히 32가 아니거나 학습 예산 100업데이트/204,800 transition이 아니면 성공 보고서를 만들지 않는다.
- 기존 readonly bundle과 기존 sealed source는 새 manifest가 원래 모든 SHA pin을 계승한다. 새 소스와 실행 manifest도 checkpoint 입력 pin에 추가한다.

root coordinator가 봉인한 `설계/training_manifest.json`을 사용할 다음 명령은 다음과 같다. 아래 명령은 아직 실행하지 않았다. native wrapper와 GPU UUID 환경 설정은 coordinator가 기존 방식으로 제공해야 한다.


새 검사 4개가 통과했다(0.540초). 동일 예산과 기존 설정 비교에서 `experiment.improvement`만 다름, E4 초기 목표·대기 해제·접근 신호의 실제 차이, action/native/safety 계약 동일성과 물리 메서드 상속, B0·다른 설정·다른 parent SHA·다른 checkpoint 경로 거부, 기존 큐 미완료 시 GPU 조회 전 대기를 확인했다.
