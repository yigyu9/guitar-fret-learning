## 검수 범위와 근거

- `tools/study.py`의 L→D0→조건부 H/I→T→대표 영상 경로, `runtime.py`, `initial_mix.py`, `preflight_initial_mix_v2.py`를 확인했다. 관리 상태 `runs/study_v1/progress.json`의 소스·입력 488개를 현재 SHA와 대조했으며 불일치가 없었다.
- L은 seed 7·17 각각 large/64환경/H32로 새로 시작해 100회씩 strict 재개하며 1,000회까지 진행한다. 누적 업데이트 수를 각 블록 보고서로 검증한다. D0는 같은 300회 모델의 실행 방식만 비교한다. H128은 250회로 H32 1,000회와 수집 전이 수가 같으며, I는 B reset 검증이 승인된 경우에만 실행한다. T는 별도 새 정책으로 엄지 제어 축만 허용한다.
- 평가는 환경별 최초 에피소드와 실패를 분모에 포함한다. 32환경 중간 평가와 128환경 최종 평가를 구분하며, 보고서·원장·환경 ID·lifecycle을 교차 확인한다. I 평가에서 `started_from_B`가 하나라도 true이면 결과를 거부한다.
- 동일 물리 tick의 학습↔평가 전환과 부분 reset은 행별 모드를 확인해 초기화 캐시를 무효화한다. 전체/부분 reset 회귀 검사 2개와 기존 runtime 검사 10개가 통과했다.
- 실행은 출력 디렉토리와 로그를 덮어쓰지 않으며, 단일 관리 lock·GPU 점유 검사·최소 여유 공간·소스 변경 검사·작업별 시간 상한을 사용한다. 자식은 독립 프로세스 그룹에서 실행하고, 중단 시 SIGTERM 이후 시간 초과하면 SIGKILL 후 회수한다. 불완전 결과는 자동으로 성공 처리하거나 재사용하지 않는다.
