# 손가락 탐색·학습률·순차 제어 비교 계획

사용자 요청에 따라 수치 계획을 먼저 고정하고 기준군부터 순차 실행한다. 기존 16목표 학습과 생산 코드·원본 checkpoint는 보존한다. 새 실험은 현재 소스·자산·가상 곡을 실제 복사한 runtime 사본에서만 실행한다.

## 공통 조건

| 항목 | 고정값 |
| --- | --- |
| 모델·환경 | large, 실제 GPU PhysX, 64환경, H32, J33 |
| 조건당 학습 | 목표별 fresh 100업데이트, 204,800전이 |
| 목표 | 검지 3줄4프렛 / 중지 3줄6프렛 / 약지 2줄7프렛 / 소지 3줄9프렛 |
| 학습 seed | 1차 7, 후보 확인 17 |
| 에피소드 | v9 reset, 준비3초, 목표3.0~5.5초, 말미0.5초, 총6초 |
| 달성 기준 | 기존 clean 연속1초, 접촉·오압현 판정 변경 없음 |
| 물리·보상 | 물리240Hz/정책60Hz, 기존9보상·PD·힘·속도한계·종료·비용 유지 |
| 평가 | 초기와 최종 각각 결정적32환경의 첫 에피소드, 실패 포함 |
| 저장 | initial/final만, 주기저장간격1000>학습100회 |
| 실행 | 같은 GPU에서 한 번에 한 실험, CPU 스레드1, 연구 소스·입력 SHA 고정 |

4목표는 새 결과를 보기 전에 고정했다. 이전 조사에서 접촉 경험이 있었던 검지·중지·약지 각1개와 접촉이 없었던 소지1개를 고른 병목 탐색용 표본이며, 전체16목표의 무작위 대표 표본은 아니다. 실제 달성 일반화는 후속 확장에서 확인한다.

## 실험 조건

| 순서 | 조건 | 비엄지16축 latent std | 학습률 | 동작 구조 |
| --- | --- | --- | --- | --- |
| 0 | baseline | 기존 exp(-3)≈0.049787, 기존 clamp | 기존 | 전체33축 동시 |
| 1 | exploration | 초기0.15, 하한0.10 | 기존 | 전체33축 동시 |
| 2 | lr | 기존 | 아래 보정 | 전체33축 동시 |
| 3 | combined | 초기0.15, 하한0.10 | 아래 보정 | 전체33축 동시 |
| 4 | sequential | 초기0.15, 하한0.10 | 아래 보정 | 아래 관측 기반 순차 게이트 |

표준편차는 Gaussian latent의 수치이며 관절각·속도나 tanh 행동의 정확한 표준편차가 아니다. 지지17축(팔·손목·엄지)은 모두 기존 초기 std≈0.049787을 유지한다. 탐색 시간 상관성은 이번 비교에서 바꾸지 않는다. 독립 탐색 확대만으로 부족하면 별도 후속 요인으로 분리한다.

## 학습률 보정의 수치

- 초기 actor 3e-5, critic 3e-4, target KL 0.02, 최대 재시도3회는 유지한다.
- 기준군의 재시도 계수0.25 대신0.5를 사용한다. 같은 snapshot에서 재시도하므로 연속 시도에는 0.5^(retry+1)을 적용한다.
- actor LR 하한은7.5e-6이다. 하한에서도 KL 안전 검사를 통과하지 못하면 해당 실행을 실패로 기록하며 검사를 완화하지 않는다.
- 재시도0이고 최종 analytic KL<0.005인 갱신이10회 연속이면 다음 갱신의 LR을1.25배 올린다. 상한은3e-5다.
- 재시도 또는 불안정 갱신에서 연속 안정 횟수를0으로 한다. 횟수는 Adam param group에 저장한다.
- 해당 갱신에 사용한 LR과 다음 갱신에 적용할 LR, 회복 여부·사유를 구분해 기록한다.

## 순차 구조의 수치와 의미

원래 곡 시계와3초 준비/2.5초 압현 창을 유지한다. 교사 궤적·기타 고정·상태 덮어쓰기 없이 현재 관측으로 매 tick 단계를 결정한다.

1. 손목 이동: 안내 영역 밖 추가 초과가 각 축10mm 이하가 아니면 목표 손가락4축의 실행 행동은0(v9 기준 요청)으로 두고 팔·손목·엄지와 비목표 손가락은 학습 정책대로 움직인다.
2. 정렬: 손목 조건은 만족하지만 패드 정렬 조건이 부족하면 목표 MCP 굽힘/벌림2축을 허용하고 PIP/DIP2축은 행동0으로 둔다.
3. 굽힘: 손목 조건에 더해 목표 패드 오차의 실제 압현면 접선 성분≤8mm, 표면 signed height −1~+30mm, 법선 cosine≥0.1이면 목표 손가락4축을 모두 허용한다. 팔·손목의 미세 보정도 계속 허용한다.

이 조건은 실제 접촉 성공 조건(줄 거리3mm/높이−1~+3mm 등)을 완화하는 것이 아니라 굽힘을 시작할 준비 범위다. 단계를 강제로 성공 처리하거나 시간 초과로 건너뛰지 않는다. 조건을 벗어나면 이전 단계로 돌아가므로 래치·숨겨진 상태는 없다. 활성 목표가 없는 손가락은 기본 정책과 대기 보상을 그대로 사용한다.

정렬은 같은 토큰에 기록된 패드 오차·법선·높이를 사용한다. 접선 축은 실제 압현면 법선으로 정의하며 기타좌표 XY라고 임의 가정하지 않는다. 샘플/척도/프레임이 맞는지 CPU와 실제 GPU smoke에서 확인한다.

연구 정책은 raw latent Gaussian을 표본화한 뒤 결정 변환 T(관측,tanh(latent))를 실제 행동에 적용한다. PPO logp/KL은 raw latent 기준이며 실행 행동을 원래 Gaussian 표본인 것처럼 대체하지 않는다. 미사용 latent도 likelihood에 남는 분산 한계는 기록한다. 학습·평가·렌더 모두 같은 변환을 사용한다.

## 진행 순서와 비교

- [ ] CPU: 기준군 출력 동등성, 탐색 분리, LR 하한·복구·rollback 상태, 순차 변환·확률 일치 확인
- [ ] GPU smoke: 5조건 각각 최소2업데이트/8환경, 초기·최종 저장 및 평가·렌더 연결 확인
- [ ] seed7: baseline 4목표 → exploration 4목표 → lr 4목표 → combined 4목표 → sequential 4목표
- [ ] 후보 선택: 아래 기준을 통과한 조건 중 사전 순위가 가장 높은 한 조건만 baseline과 함께 seed17의4목표를 같은 예산으로 재학습
- [ ] 재확인: seed17에서도 기준을 통과한 후보 중 가장 좋은 조건만 나머지12목표를 seed7로 확장
- [ ] 조건별 요약·수치·성공 및 실패 영상·최종 추천 기록

성공 후보는 같은 seed의 baseline 대비128평가 중 달성 에피소드가8개 이상 늘고, 물리/손목 실패 합집합이 baseline+4개 이하인 조건이다. 예비 접촉 후보는 달성 기준을 못 넘더라도 연속 clean≥0.1초 에피소드가16개 이상 늘고 최소 패드 거리 중앙값이10mm 이상 줄며 같은 안전 조건을 만족한 조건이다. 두 종류는 별도로 표시하고 예비 접촉을 압현 달성으로 부르지 않는다.

후보 순위는 안전 조건 통과 후 달성 수 → clean≥0.1초 수 → 평균 최장 clean → 최소 거리 중앙값이 작은 순이다. 새 seed 검증을 통과하지 못하면 채택 보류로 기록한다. 예비 접촉 후보의 확장도 추가 진단이며 완성된 학습 구조의 채택이 아니다. 같은 seed의 병렬환경은 독립 학습 seed 반복이 아니므로 통계적 유의성·일반화를 주장하지 않는다.

기준군 실패·입력 SHA 변경·집계 무결성 실패는 연구를 중단한다. 개별 실험 실행 오류는 실패로 기록하고 입력 무결성이 유지되면 다음 조건을 진행한다. 성과가0이라는 이유로 실패 로그를 숨기거나 무한 연장하지 않는다. 학습기 자체의 물리·자원 보호는 유지한다.

## 시간·저장·산출물

첫20실행은 기존 실측 기준 약3~4시간, seed17 확인8실행은 약1~2시간 추가, 남은12목표 확장은 약2시간 추가로 예상한다. GPU 실제 처리속도에 따라 진행표에서 추정치를 갱신한다. 기존 기준 결과는 문맥으로만 사용하며 이번 baseline은 같은 사본과 도구로 새로 실행한다.

`runs/<조건>_<목표>_s<seed>/`에 모델·로그·초기/최종 평가를 저장한다. `analysis/`에 조건별 표·기계 판독JSON·추천 근거, `video/`에는 실제 정책MP4만 저장한다. 렌더 원시자료는 `rendering/`에 남긴다. 실패 사례도 영상의 실제 달성 여부를 별도로 표시한다. 예상 추가 공간은 검증까지 약8~12GiB이며 디스크 여유와 GPU/RAM 하한을 감시한다. 생산 기본값은 자동으로 바꾸지 않는다.

사전 검증 경로 보정: 연구 사본이 원 프로젝트 하위인 경우 내부 경로를 두 번 재배치하는 문제는 연구 모듈의 실행 문맥에서만 공통 경로 어댑터로 처리한다. 기존 native 소스·provenance와 물리·제어·입력 바이트는 유지한다. 최초 실패와 이전 봉인은 preflight_failures/attempt01에 보존한다.
