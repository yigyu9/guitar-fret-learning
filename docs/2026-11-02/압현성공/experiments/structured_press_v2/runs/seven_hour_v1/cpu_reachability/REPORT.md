# 고정 팔에서 손가락 네 축의 CPU 기하 도달 진단

결론: 현재 채택된 A 초기 자세에서 팔·기타를 고정해도 중지·약지·소지 모두 목표 셀의 안쪽 끝마디 패드를 압현면 0~1mm에 놓는 관절각을 찾았다. 따라서 이 세 목표에서 ‘고정 팔이면 손가락 네 축으로 목표 근처에 도달할 수 없다’는 가설은 이번 소스 FK 모델과 후보에 대해서는 지지되지 않는다. **충돌·힘·clean 유지·학습 성공을 입증한 결과는 아니다.** 중지는 별도로 실제 A 학습 32/32 성공이 이미 보고되어 이 CPU 결과보다 강한 실제 근거가 있다.

## 방법과 보존

- 봉인된 현재 runtime의 `load_gpu_prepared_reset_contract('left')`, `full_fk`, 실제 `load_fingertip_pad`와 현·프렛 셀 기하를 읽었다.
- 실제 채택 catalog의 목표별 `q105`를 시작점으로 사용했다. 팔·몸통·하체·root·기타·다른 손가락은 고정하고 해당 손가락 MCP 굽힘/벌림·PIP·DIP 네 축만 native 전체 범위에서 변경했다.
- 프렛 경계 양쪽 2mm 안쪽 유한 현 선분, 같은 표본의 방향 cosine≥0.1, 현 접선 거리≤3mm를 사용했다. 명목 높이 0.5mm를 요청하고 최종 높이 0~1mm를 확인했다.
- 각 목표 12개 시작점, 시작점당 최대 100회 함수 평가의 CPU least-squares를 수행했다. 작은 관절 변화와 native 경계 5° 이내 회피는 후보 선택용 진단 선호이며 학습 보상·제어에는 추가하지 않았다.
- 공식 `pad_target_geometry`도 CPU에서 다시 실행했다. 하중을 만들어 넣지 않고 `loaded=False`를 유지했으므로 최종 `facing_geometry=True`, `positive=False`다.
- 단일 CPU thread, GPU 노출 차단, GPU API 실행 없음. 목표별 약 1.7~1.9초가 걸렸다.
- 실행 전·후 봉인 runtime **3,148개 파일의 SHA가 모두 동일**, 변경 0개다. source seal SHA는 `274ad7e09a1c79e89652ff3c211c9f83e4bbd26e7471be71e0351e31a3bdde08`이다.
- 기존 파일은 덮어쓰지 않았다. 진단 script/result/report만 이 디렉토리에 새로 저장했다. 후보를 runtime catalog나 학습 정책에 반영하지 않았다.

## 선택한 관절각과 필요한 변화

단위는 도이며 열 순서는 MCP 굽힘 / MCP 벌림 / PIP / DIP다.

| 목표 | 선택 관절각 | 초기 v9 손가락 각에서의 변화 |
|---|---|---|
| 중지 | 37.15 / 14.59 / 59.42 / 26.35 | +10.69 / −2.41 / +0.69 / −0.13 |
| 약지 | 30.22 / 14.48 / 74.43 / 33.13 | +3.20 / −4.03 / +12.19 / +8.09 |
| 소지 | 37.99 / 23.17 / 56.14 / 20.14 | +4.78 / +0.57 / +5.31 / +2.76 |

세 후보 모두 native 경계 5° 이내 관절이 0개다. 약지 PIP는 74.43°로 상한 90°까지 15.57° 남아 있다. 소지 벌림은 23.17°로 실제 상한 40°까지 약 16.83° 남아 있다. 이 후보에서는 마지막 관절만 극단적으로 굽혀야 접촉 기하가 만들어지는 상황은 아니다. 약지는 PIP·DIP를 함께 움직이는 변화가 중지·소지보다 상대적으로 크다.

## 초기 실제 q와 팔 유지 목표의 구분

세 목표 모두 catalog의 초기 팔 12축 `q105`와 `hold_target105`의 차이는 **정확히 0rad**다. 따라서 초기 정적 FK에서 ‘실제 팔 q를 고정’하는 경우와 ‘팔 유지 목표 각을 적용했다고 가정’하는 경우는 같은 팔 각이다. 별도 고정 팔 목표 해를 반복 계산할 필요가 없었다.

그러나 전체 105축은 동일하지 않다. 최대 차이는 오른쪽 무릎 약 3.0449°, 오른쪽 발목 약 −2.4894°이며 원래 준비 자세의 실제 q와 제어 목표의 차이다. 이번 진단은 이들 값을 목표로 바꾸지 않고 초기 실제 q 그대로 고정했다. 실제 A에서는 하체·몸통의 유한 제어와 기타 운동, 팔 추종 오차가 계속 존재한다. CPU 정적 후보가 그 동적 오차를 제거하거나 보장하지 않는다.

## 학습 실패가 발생했을 때의 해석

1. 현재 source FK에서 손가락 네 축의 정적 기하 해가 존재한다는 점과 실제 물리 압현 가능성은 구분한다.
2. 약지·소지 A가 실패하면 먼저 정책이 위 정도의 MCP/PIP/DIP 변화를 실제로 요청했는지, 추종했는지 확인한다. 요청 자체가 작다면 탐색·학습 문제의 근거가 강해진다.
3. 비슷한 변화를 요청했는데 표면이 도달하지 못하거나 candidate만 생기고 clean이 안 되면 기타 이동, 힘·마찰, 다른 손가락 충돌·오압현, 손목/팔 실제 추종과 접촉 측정을 확인한다.
4. 위 후보는 다른 손가락·엄지와의 충돌, 하중, 현 압력, 오압현 없음, 연속 1초 유지, 안전 종료를 검증하지 않았다. 이 수치를 정책 teacher나 새 초기 자세로 바로 적용하지 않는다.

## 산출물

- `run.py`: 현재 봉인 runtime을 읽는 CPU 전용 진단.
- `run_v1.log`: 실행 결과.
- `results_v1/{middle,ring,pinky}.json`: 모든 시작점의 최적화 결과, 선택 q105, 관절 범위, 초기 q와 유지 목표 차이, 공식 CPU 기하 판정.
- `results_v1/summary.json`: 전·후 source seal 검증과 요약.
