# A 학습 모델의 free_v9 재생에서 정지·펴짐이 가능한 소스 근거

검사 범위는 봉인된 structured_press_v2/runtime의 원문과 저장된 A 모델 가중치이다. GPU 재실행·정책 변경·봉인 파일 수정은 하지 않았다. 영상의 특정 프레임에서 실제로 어떤 원인이 우세했는지는 관측/행동 궤적 대조 없이는 확정하지 않는다.

## 가장 강한 근거: A 모델의 팔 출력은 학습된 접근 궤적이 아니다

`training/policy.py:476`에서 support_head의 weight/bias를0으로 초기화한다. `tool/experiments/structured_press.py:138`에서 팔·엄지의 support bias를 해당 목표의 기하 IK hold 각으로 바꾸고,145행에서 A의 support encoder/head/log_std를 동결한다. A의 활성 행동은 목표 손가락4축뿐이다(47행). 추가 actor_extra의 팔 출력도 active_mask에 가려져 학습되지 않는다.

실제 CPU 텐서 확인 결과는 다음과 같다. 중지·약지·소지는 A200을0업데이트로 free_v9로 옮긴 저장본이며 검지는 원본 A100이다.

| 모델 | support_head.weight 최대 절댓값 | actor_extra 마지막층 팔12행 weight/bias 최대 절댓값 | 목표 손가락 마지막 head weight 최대 절댓값 |
|---|---:|---:|---:|
| 검지 A100 | 0 | 0 / 0 | 0.0040712049 |
| 중지 A200→free | 0 | 0 / 0 | 0.0052443021 |
| 약지 A200→free | 0 | 0 / 0 | 0.0047196732 |
| 소지 A200→free | 0 | 0 / 0 | 0.0042705284 |

따라서 이 네 A 모델의 **팔 latent mean은 관측과 무관한 고정 IK bias**이다. actor_extra의 공유 은닉층이 학습되었어도 마지막 팔 출력행이0이면 그 경로로 팔 명령을 바꾸지 못한다. support log_std도 동결되므로 기존 deterministic 및 요청각 기댓값 재생에서 팔의 요청각은 고정값이다. 확률 재생에서는 고정 분포의 표본만 달라진다.

즉, v9의 초기 팔이 고정 IK 목표로 이동하고 제어기/물리에서 수렴하면 영상상 손목 이동 후 멈춤이 나타날 수 있다. 이것을 학습된 ‘손목 이동 완료→정렬 대기’ 행동이라고 해석하면 안 된다. A가 학습한 주된 함수는 정렬된 팔을 전제로 한 목표 손가락의 압현 함수이다.

확인한 저장본:

- `structured_press_v2/runs/index_s3_f4_A_v1/train_100/J/final.pt`
- `seven_hour_v1/model_only/middle_free_v9/J/final.pt`
- `seven_hour_v1/model_only/ring_free_v9/J/final.pt`
- `seven_hour_v1/model_only/pinky_free_v9/J/final.pt`

## move/align/press는 기하 관측 단계이며 고정 시간표가 아니다

`structured_press.py:280`의 readiness:

- 손목 안내 영역의 각축 초과량이10mm 이하.
- 목표 패드와 표면 접선 XY 오차가10mm 이하.
- 목표 패드 signed height가2~20mm.
- 패드 방향 cos가0.1 이상.

290행의 단계 갱신은 실제60Hz 끝점에서 다음처럼 동작한다.

1. 손목 조건이 연속0.10초 만족하면 align, 그 전에는 move이다.
2. 네 조건을 모두 연속0.10초 만족하거나 clean candidate가 생기면 press이다.
3. 기존 press는 손목 각축 최대 초과량30mm 이하이면 유지한다. 이를 벗어나면 현재 조건으로 move/align에 돌아갈 수 있다.
4. 단계가 바뀌면 phase_elapsed와 transition_elapsed가0으로 바뀐다. 후자는0.20초까지 증가한다.

move와 align의 전체 길이는 고정되어 있지 않다. 실제 시각은 해당 영상의 readiness/phase 궤적을 읽어야 한다. press 진입 시 바꾸는 hold_action은 **팔12축**이며 손가락 목표각을 재초기화하지 않는다(309행).

## free_v9에서는 손가락도 팔도 단계별 잠금이 없다

`StructuredPool.step`, structured_press.py:453에서 active_mask를 적용한다. free_v9는 첫 tick부터33축이 활성이고 목표 손가락의 MCP_x/MCP_z/PIP/DIP4축도 항상 실행 가능하다. move/align 중 목표 손가락을0으로 막거나 press까지 기다리게 하는 게이트가 없다.

458행의 팔 hold/latch·±0.05 correction·0.20초 전환 blend는 **free_v9가 아닌 경우에만** 실행한다. free_v9에는 적용되지 않는다. hold_action과 단계·타이머는 여전히601열 관측에 들어간다(322행). 따라서 학습된 손가락 네트워크가 이 정보 변화에 반응할 가능성은 있지만, 그것은 신경망의 출력 변화이지 강제 제어 순서가 아니다.

## 3초 경계에 손가락 각도를 다시 설정하는 코드는 없다

한 음은 원곡0~2.5초에 pre_roll3초가 더해져 실제 local3~5.5초이다(`song/task.py:343`, 해당 bundle의 t_press0/t_release2.5). 전체 재생은 tail0.5초를 더한6초이다. `_local_time`은 실제 물리 tick/240이며 손목 안내 시간은 이 단일 목표에서 초기 준비 구간에도 같은 목표를 가리킨다.

3초에는 음의 audible/press 구간이 시작하고 손목 안전 종료 판정이 활성화된다(`gpu/finger_skill_environment.py:296`). 준비 남은 시간 관측도0이 된다(358행). 그러나 controller.target/reference를 덮어쓰거나 손가락 관절을 순간 reset하는 분기는 없다. structured motion_phase도3초를 직접 읽어 전환하지 않는다.

관측상 목표 tracking token은 press−2=1초부터 유효하다(`gpu/finger_reward.py:41`). 3초에는 음 이벤트 상태가 바뀌므로 네트워크 입력은 달라진다. 입력의 phase one-hot/hold latch는 기하 조건에 따라 다른 시각에도 바뀔 수 있다.

네 영상의 `renders/{index_A100_free_v9,middle_A200_free_v9,ring_A200_free_v9,pinky_A200_free_v9}/scene/finger_control_trace.jsonl.gz`에서 env0/episode1을 직접 읽었고, **네 손가락 모두 처음 target_present=True인 기록은 정확히1.0초**였다. 따라서 첫1초의 손가락 출력은 자신의 유효 tracking token이 없는 입력에서 나온다. 일반 lookahead event와 손목 안내 등 다른 정보까지 모두 없다는 뜻은 아니다. 1초 부근의 phase 변화가 함께 관측되면 token 등장과 phase 효과를 이 영상만으로 분리할 수 없다.

## 목표 손가락도 초반에는 약한 대기 보상을 받는다

`gpu/finger_reward.py:238`의 대기 gate는 손가락별로 계산한다. 첫 단일 음에서 next_press=3초, lead0.35초, fade0.10초이므로 목표 손가락은 다음 스케줄이다.

| 실제 local 시각 | 목표 손가락 대기 gate | 목표 패드 접근 potential의 tracking weight |
|---|---:|---:|
| 0~2.55초 | 1 | 0 |
| 2.55~2.65초 | 1→0 선형 감소 | 0→1 증가 |
| 2.65~5.5초 | 0 | 1 |
| 음 종료 후5.5~5.55초 | 0(해제 유예) | 이후 목표 선택 유효 범위에 따름 |
| 5.55~5.65초 | 0→1 | 음 종료 뒤 tracking 목표는 무효 |

접촉/근접이 대기 gate를 추가로 차단하지 않는다. 단, 관련 거리의 비유한 값은 해당 손가락 보상을 무효화한다. 위 tracking은 현재 J의 접근 potential에 실제로 곱해진다(`gpu/finger_skill_environment.py:283`). 목표 token이1초부터 보여도 목표 패드 접근 보상의 가중치는2.55초 전까지0이다.

대기 보상은 최대0.02/s를 네 손가락 고정 분모로 나눈 약한 양의 권고다. 목표 손가락 한 개의 최대값은0.005/s이다. 뿌리/MCP 굽힘은 기준 주변±30도, PIP/DIP는±15도의 넓은 허용대를 사용한다. 측정 굽힘 자세만 보상하며 spread(MCP_z) 목표, 관절 강제 target, 이동 비용은 아니다(`finger_reward.py:201`,282행). 목표 손가락은2.65~5.5초 압현 준비·수행 구간에는 이 대기 보상을 전혀 받지 않는다.

실제 순수 gate 함수를 CPU에서 호출한 값은 t=0/0.5/1/2/2.5초 모두 idle1·tracking0, t=2.6초 idle0.5·tracking0.5, t=2.65/3초 idle0·tracking1이다(경계 부동소수 오차는 반올림). 다른 비목표 세 손가락은 자신의 배정 음이 없어 idle1이다. 대기 보상은 감점이 아니며 gate1이라고 관절을 대기 각으로 강제하지 않는다.

### B 중심각과 실제 초기 reference의 수치 비교

아래 MCP는 native MCP_x 값 자체가 아니라 실제 보상과 같은 Exp([x,0,z]) 전방 벡터에서 계산한 기하 굽힘각이다. PIP/DIP는 native 굽힘각이다. reference는 catalog의 실제 prepared reference105이며 첫 물리 적분 뒤 q와는 약간 다를 수 있다.

| 손가락 | 초기 MCP/PIP/DIP(도) | B 중심 MCP/PIP/DIP(도) | 초기 reference의 밴드 밖 항목 |
|---|---|---|---|
| 검지 | 28.629 / 47.596 / 14.149 | 25.490 / 35 / 12 | 없음 |
| 중지 | 27.232 / 58.729 / 26.487 | 28.024 / 38 / 14 | PIP가 상한53도보다5.729도 더 굽혀짐 |
| 약지 | 27.955 / 62.239 / 25.044 | 31.027 / 41 / 16 | PIP가 상한56도보다6.239도 더 굽혀짐 |
| 소지 | 34.915 / 50.824 / 17.385 | 34.325 / 44 / 18 | 없음 |

허용대 안에서는 중심에 가까워져도 추가 보상이 없다. **네 손가락의 초기 MCP는 이미 넓은 대기 밴드 안이므로 B가 큰 MCP 펴짐을 권장한다고 말할 근거가 없다.** 중지·약지 PIP는 각각 약5.7도/6.2도만 펴도 초기 밴드 밖 오차가 없어진다. 그보다 더 펴는 것이 대기 보상에서 더 좋지는 않다.

첫 native240Hz 기록(t=0.004167초)의 실제 요청값도 확인했다.

| 손가락 | 요청 MCP_x/MCP_z/PIP/DIP(도) |
|---|---|
| 검지 | 14.885 / 13.257 / 36.929 / 18.460 |
| 중지 | 2.110 / 17.497 / 32.913 / 27.542 |
| 약지 | 10.257 / 18.779 / 36.585 / 22.015 |
| 소지 | 39.671 / 26.425 / 64.370 / 31.283 |

중지의 큰 MCP_x 펴짐 요청도 기하 MCP로 환산하면 B의 넓은 밴드 안에 머무른다. 중지 PIP32.913도는 B 밴드23~53도 안이다. B가 초기 PIP58.729도보다 이쪽을 선호할 수는 있지만32.913도를 특별히 선호하지 않는다. 반대로 소지는 초기 PIP50.824도가 이미 B 밴드29~59도 안인데64.370도로 더 굽히는 요청을 내므로 대기 보상을 개선하는 방향도 아니다. 따라서 네 영상 전체를 ‘대기 보상이 손가락을 펴게 강제한 결과’라고 묶을 수 없다. 목표 token 부재·학습된 시간/상태 함수·phase 입력이 함께 있는 상황에서 나온 정책 출력이라는 수준이 현재 근거에 맞는다.

따라서 영상에서 손목이 먼저 도착한 뒤 초반 대기 자세를 유지하다가 약2.55~2.65초 이후 손가락이 바뀌는 현상은 **현재 대기/접근 보상의 시간 분배와 정합하는 설명**이다. 다만 이것만으로 실제 펼침·벌림의 방향을 결정했다고 입증하지는 못한다. spread를 특정 방향으로 벌리라는 대기 보상은 없고, J의 과거 finger_shape 및 독립 tracking reward는 꺼져 있다(`finger_skill_environment.py:116`).

## 직접각 제어가 움직임을 만드는 방식

`gpu/control.py:446`: action은 현재 관절각에 누적되는 값이 아니라 고정 prepared reference와 양/음 관절 여유 범위를 이용한 직접 목표각이다. LH21은 smoothing alpha1, 속도제한4rad/s, 팔 등은 alpha0.2와 각자 속도제한을 적용한다(206행). 매 tick 목표각에 다가가며 실제 관절은 PD·관성·접촉의 영향을 받는다. action0은 현재 자세 유지나 B 대기 자세 고정이 아니라 prepared reference 복귀 요청이다.

따라서 목표 손가락 출력이 작아져 reference 쪽으로 이동하면 펼쳐져 보일 수 있고, MCP_z도 학습 가능한4축 중 하나여서 벌어질 수 있다. 이 동작에 대해 별도의 손가락 이동 비용은 없다. 비용이 없어도 정책이 곧바로 최소 움직임/자연스러운 움직임을 배우는 것은 아니다.

제어기의 DLS는 `gpu/control.py:197`의 좌우 무릎·발목·발가락10채널만 수정한다(410행). 팔12축 target을 직접 수정하지 않는다. 다만 고정 policy mean이라고 적용 target이나 실제 손목 위치까지 고정이라는 뜻은 아니다. 초기에는 smoothing/rate limit 때문에 applied target이 계속 움직이고, 이후에도 PD 추종 오차·접촉·몸통/기타의 움직임으로 실제 관절과 기타 기준 손목 위치가 변할 수 있다. 팔 정책 요청이 일정한 사실과 물리 손목 정지 여부를 구별한다.

## 확인된 사실과 남은 가설

**확인됨:** A 팔 mean은 고정 IK, free에서는 단계별 제어 잠금 없음, 목표 손가락도 초반2.55초까지 약한 대기 권고/접근 가중치0,2.65초부터 압현 준비 보상 활성,3초 관절 재초기화 없음, A의 aligned 시작에서 v9 시작으로 바뀌는 초기 분포 차이 존재.

**아직 미입증:** 특정 프레임의 펼침이 대기 prior, phase 관측 전환, 직접각 decoder, 실제 PD/접촉 중 어느 요인의 결과인지. A는 이미 정렬된 팔/상태에서 학습했고 free 재생은 팔이 이동하는 동안 손가락 위치·접촉·관측이 달라진다. 목표 손가락 함수가 그 낯선 구간에서 내놓는 출력일 수 있다. 자연스러운 영상만으로 이상 동작 또는 단일 원인을 확정하지 않는다.

판별하려면 해당 영상과 같은 저장본/배포 규칙에서 local time, 실제 phase/readiness, 대기 gate/tracking weight, 목표4축의 latent mean→요청각→실제 적용 target→실제 q를 같은 시각에 대조해야 한다. 추가 반사실 실험 없이 원인을 확정하거나 보상·제어를 바로 바꾸지 않는다.
