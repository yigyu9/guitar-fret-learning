# full33 fresh100 → 200의 성과 붕괴 분석

결론: **200 정책은 접촉을 못 찾고 가만히 있는 것이 아니라, 하중이 있는 검지 패드를 목표와 다른 현에 놓아 음 전체가 own_wrong_string으로 판정됐다.** 100final→200initial의 모델·Adam·RNG는 완전히 같아 현재 CPU 검사에서는 잘못된 재개 증거가 없다. 추가 학습 중 바뀐 정책과 그에 따른 기하 전략 변화로 보는 근거가 강하다.

최고 모델100은 보존한다. 아래 분석은 원래 성공·접촉 기준을 바꾸지 않았고 GPU 실행이나 봉인 코드 변경 없이 원시 완료 에피소드와 env0 trace를 읽었다.

## 1. 먼저 재개가 정확했는가

다음 두 파일을 CPU로 읽어 재귀적으로 비교했다.

- `index_full33_seed7_v1/100/train/J/final.pt`
- `index_full33_seed7_v1/200/train/J/initial.pt`

| 항목 | 결과 |
|---|---|
| 전체 model tensor·buffer | 완전히 동일 |
| architecture/control/config identity | 완전히 동일 |
| actor Adam state·parameter groups | 완전히 동일 |
| value Adam state·parameter groups | 완전히 동일 |
| 누적 updates | 모두100 |
| cost weight | 동일 |
| Torch CPU RNG | 완전히 동일 |
| CUDA RNG 전체 목록 | 완전히 동일 |
| NumPy RNG | 완전히 동일 |
| Python RNG | 완전히 동일 |
| curriculum/exposure | 완전히 동일 |
| sampler | 완전히 동일 |

각 비교의 다른 경로 목록은 모두 비어 있다. 실제 원본 SHA와 상세 비교는 `FULL33_COLLAPSE_ANALYSIS.json`에 기록했다.

이것은 모델/최적화/RNG의 정확한 재개 증거다. 살아 있는 물리 에피소드의 중간 상태까지 이어 재생했다는 의미는 아니다. 원래 resume 계약은 `J model/Adam/RNG/exposure/sampler; fresh prepared episodes`로, 새 준비 에피소드에서 시작한다.

100·200 평가 모두 stage=free_v9, 같은 v9 초기화 분포·같은 geometry SHA·같은 목표3줄4프렛을 사용했다. 다만 이 일반 평가에는 paired_B처럼 실제 reset q/body/hold의 환경별 SHA 감사가 저장되지 않았다. **초기화 설정의 일치와 실제 초기 tensor의 직접 페어 검증은 구분한다.** 예정된 200initial GPU 재평가에서100 성과가 재현되면 모델/초기화 경로가 이어졌다는 추가 증거가 된다. 그 재평가가 실패하면 동일 가중치의 실제 reset/동역학·평가 경로를 추가 확인해야 한다.

## 2. 32개 실제 완료 에피소드에서 무엇이 바뀌었나

목표 음은3.0~5.5초, 2.5초다.

| 평균 지표 | 100 | 200 |
|---|---:|---:|
| 안전 달성 | 32/32 | 0/32 |
| 물리/손목 실패 | 0/0 | 0/0 |
| clean | 2.5초 | 0초 |
| 최장 연속 clean | 2.5초 | 0초 |
| wrong | 0초 | **2.5초** |
| missing | 0초 | **0초** |
| target 위치 기하 유효 | 2.5초 | 0초 |
| target 위치+법선 유효 | 2.5초 | 0초 |
| 담당 패드의 target loaded 판정 | 2.5초 | 0초 |
| 담당 distal body의 하중 | 2.5초 | **2.5초** |
| own_wrong_string | 0초 | **2.5초** |
| own_wrong_fret / other_higher | 0 / 0초 | 0 / 0초 |

이 패턴은32개 모두 같았다. wrong source의 body는 `human/LH:index3`, 잘못 누른 위치의 fret 범위는4~4였다. 프렛을 잘못 고른 것이 아니라 같은4프렛의 다른 현 판정이다. 기록에는 어느 다른 현인지는 남아 있지 않으므로 ‘정확히 몇 번 현으로 옮겨갔다’고 단정하지 않는다.

200은 담당 body가 계속 하중을 받았으나 목표 현 기하는 한 번도 만족하지 못했다. 방향이 추가로 veto한 문제도 아니다. 위치 기하가0이고 env0 최근접 패드 법선cos는 약0.72~0.76으로 문턱0.1보다 충분히 높았다. 따라서 고립된 힘 부족이나 법선 뒤집힘보다 **목표 현 정렬의 이탈**이 더 직접적인 실패 설명이다.

두 정책 모두1~5.5초의 near_time은4.5초 전체다. ‘1cm 근처’라는 넓은 접근 지표는 성공 정책과 잘못된 현을 누르는 정책을 구분하지 못했다. 평균 최소 목표 거리는100 약0.541mm에서200 약5.423mm로 늘었다. 전체 음 창에서 target geometry가0이라는 원장 결과와 일치한다.

이 wrong 판정은 현행 source pad·가상 현/프렛·body 합력 대리지표다. 개별 네이티브 접촉쌍이나 실제 줄 압력·소리를 검증한 결과로 확대하지 않는다.

## 3. 실제 env0 기록

이는 저장된 첫 env0 에피소드의240Hz trace다. 다른31개 시각을 이 값으로 대신하지 않는다.

| env0 시점 | 100 목표 거리 | 200 목표 거리 | 200 하중/기하 |
|---|---:|---:|---|
| 2.5초 | 0.715mm | 5.822mm | loaded=true, geometry=false |
| 3.0초 | 0.663mm | 5.739mm | loaded=true, geometry=false |
| 3.5초 | 0.591mm | 5.623mm | loaded=true, geometry=false |
| 5.0초 | 0.548mm | 5.490mm | loaded=true, geometry=false |

100은 trace가 목표를 보여주는1초 시점부터 candidate=true였다. 200은 기록된 첫 에피소드 전체에서 target candidate가 한 번도 나타나지 않았다. 200의 실패는 음 시작이 조금 늦어진 것과 다르다. 가까운 다른 현 쪽 기하에 하중이 계속 걸린 채 목표를 회복하지 못했다.

검지의 실제 각도는3초에100 MCP30.33°/PIP48.31°, 200 MCP31.17°/PIP48.45°였다. 큰 손가락 자세 붕괴가 아니다. 비슷한 초기 손 모양에 약간 다른 관절·팔 배치가 조합된 결과로 보인다.

## 4. 자세·제어에서 확인한 차이

| 검지 평균 실제 이동폭 | 100 | 200 |
|---|---:|---:|
| MCP 굽힘 | 3.61° | 4.54° |
| MCP 벌림 | 1.06° | 1.70° |
| PIP | 1.27° | 1.50° |
| DIP | 3.40° | 3.03° |

목표/실제 native 한계 체류는 모두0이었다. 관절을 극단으로 꺾거나 손가락이 전혀 움직이지 않는 붕괴와는 다르다. MCP/PIP의 추종 RMS도100 약1.02/0.48°에서200 약1.33/0.64°로 늘었지만, 목표 현 자체의 기하 실패를 이것만으로 설명할 수는 없다.

마지막 실제 손목 기타 좌표 평균의 200−100 차이는 약 **(+3.92, −5.28, +1.05)mm**다. 몇 mm 수준의 상대 자세 변화와 손가락 벌림 변화가 엄격한 현 구분을 넘겼을 가능성이 있다. 하지만 마지막 손목 위치만으로 음 전체의 이동 경로·접촉 위치·팔의 힘 기여율을 계산할 수는 없다. full100/full200 native pose/video 비교가 필요한 이유다.

손목 안내 영역의 내부 비율은100 약0.56%, 200 약0.07%였으며 손목 종료는 없었다. 넓은 안내 영역/종료 허용 오차와 좁은 목표 현 판정은 서로 다른 기준이다. 이번 실패를 손목 종료가 너무 빨라 배울 기회가 없었다는 설명으로 바꿀 근거는 없다.

## 5. 왜 추가 학습에서 이런 방향으로 이동했나

직접 확인한 결과는 ‘target contact 유지에서 wrong string contact 유지로 정책의 평균 실행이 이동했다’는 것이다. 그 갱신 원인은 아직 가설이다.

- 평균 정책은100에서 성공했지만 확률적 학습에서는 같은 성공이 충분히 자주 나타나지 않았을 수 있다. 이미 진행한 탐색 잡음 민감도와 연결되는 가설이지만, 이 비교만으로 원인을 확정하지 않는다.
- 팔·손가락이 모두 활성인 중복 자유도에서 작은 자세 변화가 target 경계 밖으로 이동했을 수 있다. 전체 팔 정렬의 기반은 여전히 초기 IK bias지만, 그 위의 학습된 보정과 finger 출력이 추가100회 동안 함께 변했다.
- 국소적인 PPO 갱신 제한은100회 누적 후 목표 기하를 보존한다는 보장이 아니다. 정확한 재개와 최종 성능 보존도 다른 문제다.

평균 평가의 총보상은100 약−0.0668에서200 약−1.5319로 나빠졌다. 200의 접근 항은−1.6733→−1.3891로 좋아졌지만 최초 접촉0.25·유지1.0·달성0.25를 잃고 오압현−0.15·부족−0.10이 생겼다. **전체 보상 기준으로도 성공보다 이 잘못된 현 동작이 더 좋은 최적해라는 증거는 없다.** 평균 평가가 나빠졌는데 확률적 PPO 학습이 그 평균을 보존하지 못한 이유를 구분해야 한다.

## 다음 확인의 우선순위

1. 200initial을 원래 GPU 평가 경로로 재평가한다. CPU상100final과 모델/Adam/RNG가 같으므로100 성과 재현 여부가 재개/평가 의심을 더 줄여 준다.
2. 최고100과 마지막200의 실제 영상을 모두 보존한다. 성공 영상만으로 추가 학습이 유지됐다고 표현하지 않는다.
3. raw pose가 생기면 목표 패드/현의 signed height·lateral·fret 여유와 손바닥 기준 패드 이동을 비교한다. 같은 프렛에서 어느 현으로 판정되는지 실제 동일 표본 좌표를 기록한다.
4. 이후 변경은 예정된 잡음 감소 비교 결과를 먼저 본다. wrong string을 사후 예외 처리하거나 lateral 문턱을 늘려 성공으로 만들지 않는다.

checkpoint 최고 성과100을 계속 보존하고200은 마지막 모델/실패 분석용으로 구분하는 것이 현재 적절하다.

## 파일

- `FULL33_COLLAPSE_ANALYSIS.json`: 원본 SHA, 재개 재귀 검증,32개 통계, 실제 env0 표본.
- `index_full33_seed7_v1/{100,200}/evaluate_final`: 원시 완료 에피소드·메타데이터·240Hz trace.
- `index_full33_seed7_v1/100/train/J/final.pt`와 `200/train/J/initial.pt`: 재개 동일성 검증 원문.

새 GPU 작업·runtime·catalog·학습 기준 변경 없이 읽기 분석만 수행했다.
