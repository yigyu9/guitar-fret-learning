# 네 손가락의 실제 움직임과 소지 B0 취약성

2026-10-31. GPU 추가 실행 없이 이미 완료한 실제 Isaac Gym 영상·관절/몸체 기록·평가 원시 로그를 분석했다. 봉인 runtime 3,148개 SHA 대조 결과 변경 0개다. 원시 입력 SHA와 수치 전체는 `OTHER_FINGER_MOVEMENT_ANALYSIS.json`에 저장했다.

네 A 유래 정책은 목표 손가락을 실제로 굽힌다. 소지도 MCP·PIP·DIP를 함께 움직인다. 이번 네 영상에서 마지막 관절만 한계까지 꺾인 형태는 수치로 확인되지 않았다. 다만 다른 손가락은 거의 고정되어 있으며, 팔의 목표는 미리 계산한 IK 정렬값이다. 따라서 ‘네 손가락의 자연스러운 협응과 목표별 팔 이동을 학습했다’는 결론으로 확대할 수 없다. 소지 B0의 5개 실패는 힘 부족이나 물리 이탈이 아니라 자기 소지의 다른 줄 오압현이다.

## 실제 목표 손가락 변화

검지는 A100, 나머지는 A200의 `free_v9` 평균 정책 영상이다. 각 1개 환경의 0.0167~6초 360프레임이다. 해당 영상의 음 구간은 3~5.5초이며 모두 압현 유지 2.5초/2.5초, 오압현 0초다. 별도의 32환경 평가 성공과 이 1환경 상세 궤적을 구분한다.

| 목표 손가락 | 실제 전체 구간 변화폭 MCP 굽힘 / 벌림 / PIP / DIP (°) | 3.5초 실제 각 (°) | 초기→3.5초 MCP / PIP / DIP 변화 (°) |
|---|---|---|---|
| 검지 | 26.10 / 1.81 / 21.55 / 5.34 | 38.77 / 11.53 / 56.45 / 13.40 | +10.58 / +8.86 / −0.75 |
| 중지 | 45.55 / 5.40 / 39.49 / 2.07 | 47.73 / 12.01 / 72.28 / 25.71 | +21.27 / +13.55 / −0.77 |
| 약지 | 30.12 / 5.50 / 36.50 / 10.17 | 40.51 / 13.04 / 73.33 / 31.80 | +13.49 / +11.09 / +6.76 |
| 소지 | 8.08 / 4.07 / 15.82 / 15.44 | 40.97 / 26.92 / 66.33 / 32.82 | +7.76 / +15.51 / +15.43 |

전체 변화폭은 최대−최소이며 초기→압현 변화와 같지 않다. 특히 검지·중지·약지의 전체 변화폭에는 준비 중 펴졌다가 다시 굽히는 움직임도 포함된다. 타 손가락의 모든 축 중 최대 변화폭은 검지 영상 0.332°, 중지 영상 0.337°, 약지 영상 0.227°, 소지 영상 0.0079°다. 비목표 손가락에 자연스러운 연속 협응이 나타난 결과로 해석하면 안 된다. A에서 비목표 출력은 학습하지 않았고 이 평균 정책에서는 초기 기준 부근에 머문다.

이 네 영상에서 팔 12축 정책 출력의 시간 변화폭은 모두 정확히 0이다. 실제 팔·손목은 유한 PD 제어와 접촉 반작용으로 움직이지만, 이것은 관측에 따라 새 팔 교정 명령을 학습한 근거가 아니다. 미리 계산한 IK 팔 bias는 유지된다. `free_v9`는 지원 단계 제한을 해제한 실행이지 사전 정렬 정보를 제거한 실험이 아니다. 검지의 동시 동작·접촉 후 손목 이동은 별도 `TIMING_ANALYSIS.md`에 정량화했다. 다른 세 영상에 그 시간 순서를 그대로 대입하지 않는다.

## 실제 관절 한계와 어색함의 구분

실제 catalog의 MCP 벌림 한계는 검지 [−30,30]°, 중지·약지 [−20,20]°, 소지 [−20,40]°다. 네 영상의 공식 손가락 native 한계 점유율과 바깥 방향 명령 비율은 모두 0이다. 목표 관절의 전 구간 최소 경계 여유는 MCP 굽힘/벌림/PIP/DIP 순으로 다음과 같다.

| 목표 | 최소 여유 (°) |
|---|---|
| 검지 | 48.82 / 16.96 / 31.45 / 18.30 |
| 중지 | 41.46 / 2.59 / 17.22 / 30.69 |
| 약지 | 48.68 / 1.47 / 16.37 / 27.12 |
| 소지 | 48.35 / 13.00 / 23.01 / 22.73 |

중지·약지 벌림은 경계 5° 이내인 프레임이 각각 44.44%, 49.72%다. 그러나 v9 초기 각부터 각각 17.00°, 18.52°로 상한 20° 근처이며 3.5초에는 12.01°, 13.04°로 여유가 커진다. 이 수치만으로 학습이 관절을 극단으로 밀었다고 볼 수 없다. 반대로 native 범위 안이라는 사실만으로 사람처럼 자연스럽다고 보장되지도 않는다.

이전 `cpu_reachability/REPORT.md`의 소지 벌림 상한 30°는 설명 오류였다. 실제 상한 40°, 정적 후보 23.17°의 여유 16.83°로 해당 비봉인 보고서만 정정했다. 원래 solver는 실제 손가락별 catalog bounds를 사용했으므로 CPU 후보·최적화 결과·도달성 결론에는 영향이 없다. frozen runtime과 원시 결과는 보존했다.

## 소지가 약지 뒤로 보이는 영상

`renders/pinky_A200_free_v9/hand.mp4` 3.5초 실제 프레임을 확인했다. 시점에서 보라색 소지가 주황색 약지 뒤로 보이지만 투영 겹침은 충돌 증거가 아니다. 같은 프레임의 약지 끝마디와 소지 끝마디 몸체 중심은 34.93mm, 사용한 안쪽 distal 패드 표본 간 최소 거리는 22.37mm다. 이는 전체 메시 사이 최단 거리가 아니다.

전체 6초에서 약지 중간·끝마디의 기록된 순 접촉력은 0N이다. 소지 끝마디는 3.5초 2.71N, 전 구간 최대 7.58N이다. 기록된 근거는 해당 순간의 약지·소지 충돌을 뒷받침하지 않는다. 접촉 pair와 전체 메시 간격이 없으므로 순힘 0과 일부 표본만으로 모든 관통·충돌 부재를 증명하지는 못한다. 추가 확인이 필요하면 실제 pair ID 또는 전체 메시 최소 간격이 필요하며, 영상만 보고 충돌 보상을 수정할 단계는 아니다.

## 엄지 지지는 아직 입증되지 않음

네 영상 모두 엄지 뒤쪽 접촉 candidate 시간 0, near geometry 시간 0, rear normal load 0, 엄지 끝마디 순힘 0이다. 평균 rear signed gap은 검지 61.7mm, 중지 45.8mm, 약지 55.5mm, 소지 35.5mm다. 최소 gap도 각각 12.95/12.93/12.97/16.73mm다. 작은 엄지 안내 점수는 기하 거리 품질에서 발생하며 접촉의 증거가 아니다. 엄지를 학습하지 않은 A 유래 평균 정책이므로 이번 손가락 성공을 엄지 넥 지지 성공으로 해석하면 안 된다.

원본 `model_only/pinky_B0_evaluate/report.json`은 completed=true, 32환경 중 성공 27개다. 중지·약지 B0는 각각 32/32다. 소지 실패 환경은 3, 5, 7, 19, 28이며 모두 다음과 같다.

| 진단 | 실패 5개 각각 |

즉 하중은 만들지만 유효 안쪽 목표 패드가 목표 3번 줄 조건을 만족하지 못하고 다른 줄을 누른다. 원시 wrong source는 발생 줄 번호를 저장하지 않아 어느 다른 줄인지는 단정할 수 없다. 기존 full distal proxy는 target 2.5초로 보이지만 `rejected_target_time`도 2.5초다. 거친 전체 메시 근접과 지정된 유효 패드의 압현 성공을 혼동하면 안 된다.

현재 준비 통과 기준과 손목 영역은 최종 정확한 줄 압현을 보장하지 않는다. 이것이 소지 B 학습을 분리해 시험할 직접 근거다. 반면 이 B0 평가에는 각 실패의 실제 reset q/선택 variant를 짝지은 기록이 없어 특정 perturbation 때문이라고 연결할 수 없다. B0와 free_v9의 초기 분포·지원 조건도 달라 free_v9 성공32/32에서 동일 조건으로 성능이 떨어졌다는 비교는 아니다.

다음 대조는 동일한 실제 초기 q/hold·seed를 고정한 B0와 B 학습 정책을 먼저 비교하는 것이 적절하다. 오압현 2.5초가 줄고 유효 target geometry와 clean이 늘어나는지 함께 본다. 가장 필요한 추가 진단은 각 episode의 실제 reset q/hold·variant ID와, wrong source의 실제 줄 번호다. 기존 실패들은 종료/보상 분류가 이미 명확하므로 물리 실패 강화나 무접촉 종료 변경을 먼저 할 근거는 약하다.
