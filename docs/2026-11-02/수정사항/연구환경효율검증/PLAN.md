# 비교 연구 종료 후 연구 환경 효율 검증

사용자 승인: 진행 중인 연구가 끝난 뒤, 테스트로 문제가 없는 범위에서 효율적인 연구 환경을 설정한다.

- [x] 현재 GPU/CPU와 최근 30회 수집·갱신 시간 확인
- [x] 원연구·봉인 도구를 수정하지 않는 별도 후속 실행기 준비
- [x] 종료/실패 게이트·비유한 거부·스레드 대체 검사 및 독립 검수 통과
- [x] 대기 프로세스 시작, waiting_for_study 상태 확인
- [ ] 원연구 정상 완료 및 조정 프로세스 종료 확인. 실패하면 GPU 실험을 시작하지 않고 사유 기록
- [ ] 고정 입력·코드 봉인 및 CPU 검사 확인
- [ ] CPU 연산 스레드 1/2/4 비교: large/1024/H32, 각 16업데이트, seed7/17. 순서는 1→2→4 / 4→2→1
- [ ] 각 실행 strict 전곡 128환경 평가, 실패·비유한·저장/복원 검사
- [ ] 워밍업 4회 제외 수집+갱신 시간 비교. 두 seed 모두 5% 이상 빠르고 같은 seed 기준군과 평가 수치가 일치하는 후보만 채택
- [ ] 새 연구용 환경 설정·결과 작성. 미통과하면 기존 스레드1 유지

현재 연구의 원래 코드 SHA·입력·도구를 그대로 사용한다. 보상·제어·환경 수·물리·모델·H32는 바꾸지 않는다. 최종 연구에서 확인된 추천 요인이 있으면 모든 속도 조건에 동일 적용하며, 없으면 모두 OFF다. 이 검증은 장기 학습 품질의 증명이 아니다. 환경 수 증가·동시 GPU 실행·로그 내용 변경·동기화 제거는 이번 자동 채택 범위에 포함하지 않는다.

추적: status.json / RESULTS.md. 실행은 현재 연구 완료를 기다리는 독립 프로세스에서 수행한다. 컴퓨터 종료나 프로세스 강제 종료 뒤 자동 재시작은 제공하지 않는다.

Torch 실행기의 내부 스레드1 고정은 별도 thread_runtime.py가 후속 프로세스 안에서만 명시적으로 대체한다. 실제 torch.get_num_threads()를 확인해 로그에 기록한다. 원래 소스나 봉인은 수정하지 않는다. 채택 설정을 사용할 때도 환경 변수와 이 래퍼를 함께 사용해야 한다.
