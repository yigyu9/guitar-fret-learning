# 왼손 개선 개별·조합 비교 연구

사용자가 한 조건씩 바꾸고 유효한 변경의 조합을 짧게 학습·분석해 반영하도록 승인했다. 모든 제안을 한꺼번에 기본 학습으로 적용하지 않는다.

- [x] 현재 코드·원문 SHA 보관 및 GPU/용량 확인
- [x] 기본 동작을 유지하는 연구 전용 옵션·제어군 구현, CPU 동등성 검사
- [x] 각 조건 짧은 GPU 작동·엄격 저장/평가 검증
- [ ] 고정 비교: large/1024환경/H32/seed7, 각200업데이트, 전곡128환경 결정적 평가
- [ ] 기준 + 학습률(L) + 탐색(E) + 정규화(N) + 준비시간(P) + 근접기하(G) 각 단독 비교
- [ ] 유효 후보만 순차 조합, 동일 조건 확인
- [ ] 다른 seed에서 기준과 선택 조합을 확인한 뒤 채택 여부 결정
- [ ] 보고서·추천 설정·실험 근거·독립 검수 갱신

성공 지표: 실패 환경을 포함한 전곡 평균 달성 음을1순위, 최초 접촉·약지/소지 성과를2순위로 본다. 종료율과 실제 관절 동작도 확인한다. 단일 seed의 미세 향상은 확정하지 않는다. 학습 총 보상만으로 승자를 고르지 않는다.

초기 선별은200회(약1시간/조건 예상), 학습 노출 일정은 모든 조건에서200회 예산의25%로 동일하게 둔다. 첫50회 구간 후 reset부터 전곡으로 넘어간다. 8시간 실행의 절대 점수와는 다른 학습 예산이므로 같은 연구 안의 기준군과 비교한다. 학습률 감소·회복이 발동하지 않으면 해당 요인의 효과는 미관측으로 표시하고 더 긴 확인이 필요하다.

기준도 연구용 동일 클래스·소스·진단을 사용하되 모든 변경을 OFF로 두며, 기존 계산과 동등성을 검사한다. CPU/오른손·기본 학습 설정·물리·실패 문턱·최초 접촉 판정은 유지한다. 연구 클래스·설정은 별도 계약으로 봉인하고 과거 checkpoint 검증을 완화하지 않는다.

기본 코드의 변경은 우선 PPO의 기존 학습률 재시도 연산을 동작 동일한 override 지점으로 추출하는 것만 허용한다. 나머지는 연구 도구에서 격리한다. 확정 전 기본 학습을 새 설정으로 바꾸지 않는다.

추가 사전 지정 조합은 L+E와P+G다. 단독에서 개선이 없어도 상호작용을 확인한다. 활성 소스뿐 아니라 연구 실행·보고 도구 SHA도 봉인한다.
