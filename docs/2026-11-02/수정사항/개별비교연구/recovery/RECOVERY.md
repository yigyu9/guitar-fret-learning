# 원래 연구 복구와 격리 실행

원연구에서 완료된 기준군·L·E·N 네 조건은 보존하고, 소스 봉인 검증에 실패한 P 실행은 무효로 유지한다. P는새출력 `preparation_s7_r2`에서 같은200업데이트로 다시 수행한다. 원래 실패 실행이나 checkpoint를 성공으로 재분류하지 않는다.

## 원래 조건 복원

- 활성 Python287개의 바이트를 원연구 SHA에 맞춰 `frozen/guitar_learning`에 복원했다.
- 자산3개의 원문도 기준군 SHA와 일치하는 보관본에서 복구했다. [자산 출처](asset_recovery.json).
- PPO는 변경 전 원문과 당시 override 추출을 재구성한 뒤 원봉인 SHA와 완전히 일치함을 확인했다. 근사 구현이 아니다.
- 기준군 입력432개 및 완료 네 조건의 입력 봉인을 대조했다. 외부 준비 입력3개 등 패키지 밖 입력16개도 별도 복사했다.
- 현재 프로젝트의 코드·자산은 덮어쓰거나 되돌리지 않았다.

## 실행 격리

연구 자식 프로세스에서만 읽기 전용 복원본을 원래 절대 경로에 연결한다. 따라서 기존 체크포인트의 코드·자산 SHA와 계약을 그대로 검증할 수 있다. 호스트의 새 코드 편집은 원연구의 Python 사본에 반영되지 않는다. 소스 검증이나 strict load를 완화하지 않는다.

GPU 장치·proc/sysfs를 제공하고, 임시 캐시는연구 디렉토리로 분리한다. UTF-8 로케일을 명시한다. 격리 설정 시행착오의 로그는v1~v5로 보존하며 이들은 연구 성능 데이터가 아니다. 실제 GPU 검증 완료 여부는 `verification_recovery.json`을 따른다.

매 단계 전후 복원된 Python·원 입력·복구 도구 SHA를 검사한다. host에서도 복원본 자체를 수정하면 감지·중단한다. 연구 실행 중 frozen과복구 도구를 수정하지 않는다.

## 이어서 실행할 순서

1. 완료된 네 조건을 재사용한다.
2. P를새로학습·평가한다.
3. G, L+E, P+G를순차 수행한다.
4. 유효 후보가 있으면 원계획대로 추가 조합과seed17 기준/선택 비교를 수행한다.
5. 조건별 분석·그래프·최종 선택을 자동 기록한다.

원계획의 예산·선별 기준은 바꾸지 않는다. 기본 학습 설정도 임의로 바꾸지 않는다.
