# 네 손가락의 원목표·현재 계약·대조 근거 연결

기존 승인된 실패 진단 원범위를 실제로 넓히기 위한 CPU 준비다. 새 GPU/NN/학습/정책 load는 하지 않는다. V7 잡음 진단과 독립적으로 진행한다.

1. 원계획이 사전에 선정한24개 목표를 원순서로 보존한다. target/candidate 식별자와 원곡source index를 분리한다. 네 손가락의 이후 scripted positive 후보를 해당목표/곡/조건에 매핑하되 모르면 미확인으로 남긴다.
2. 각 항목에 초기자세·기타고정/자유·활성축·관측557 여부·제어방식·effort/PD·지원teacher·zero/random·실제positive/negative·음길이·분모·학습seed를 근거파일/필드와 함께 기록한다. 진단0.25Nm를 생산기본 힘상한으로 오인하지 않는다.
3. 현재 생산 계약과 과거/진단 계약을 비교해 동일/차이/재검증필요를 명시한다. 서로 다른조건의 일부성공을 합쳐 한조건의4손가락 성공으로 만들지 않는다. 소지zero4/4 같은 지원제어 confound를 표기한다.
4. 원단계2의 loaded-facing negative 및 각손가락 대응negative, 엄지자유해제/학습부하 미완료를 정확히 남긴다. 문턱이나 도달조건을 완화하지 않는다.
5. manifest.json·README.md 두 산출물에 기존입력SHA/근거포인터를 기록한다. mutable 상위status/README를 실행 의존성으로 새로 봉인하지 않고 필요한근거는 원결과/계약파일 또는 읽은시점값으로 남긴다. 새 일회성 분석Python파일을 추가하지 않는다.
6. 비작성자의 근거 대조를 받은 뒤 약지/다른seed와 누락negative의 다음 유한 GPU 준비 범위를 결정한다. positive부재 손가락의 장기학습·전체grid 자동실행은 하지 않는다.

성공 기준: 원24항목의 누락/중복0, 후보ID/sourceindex혼동0, 네손가락별 적어도1개positive의 조건·대조·실패분모를 찾거나 미확인으로 명시, 현재와다른조건의성공상속0. 원80%달성/70%clean/10%wrong/5%실패·연속2평가 기준은 유지하며, 이 manifest 작성이 물리/RL 성공을 뜻하지 않는다.
