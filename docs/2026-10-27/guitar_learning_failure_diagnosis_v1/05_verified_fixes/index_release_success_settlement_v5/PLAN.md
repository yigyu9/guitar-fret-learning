# A 달성 보상의 해제 조건 정렬: 단일 비교 V5

V4에서는 압현 최고200회123/128에도 압현+해제 동시 성공33/128이었다. 마지막300회는 A달성0이며 총보상도 감소했다. 해제 조건 불일치는 확인됐지만 마지막 퇴행의 단독 원인은 확정하지 않는다.

사용자가 승인한 보상·전환 개선 단계의 후속 단일 비교다. 기존 실행 입력과 활성 학습 코드는 보존하고 이 진단 디렉토리에서만 구현한다.

1. A(source4)의 기존 압현 달성 예산0.25만 유보한다. 원래 달성 latch와 해제 latch가 모두 참인 경우 원해제100ms 창의 마지막 시점까지 기존 해제 판정을 먼저 갱신한 뒤, now >= end + 0.1인 첫240Hz시점에 한 번 지급한다. 정확한 마감시각에 발생한 기존 유효 해제도 포함한다. B7/B8·다른8항·총양의예산 상한·달성/해제/접촉 판정·실패 처리·물리는 유지한다. 실패 제어구간에서는 기존 양의 보상 억제를 따른다. 조기해제만으로 지급하지 않는다.
2. 원 V4 학습 코드를 재사용하되 새 명시적 계약/스키마로 fresh seed7 fit1000과 PPO300을 실행한다. 과거checkpoint 호환 검사를 완화하지 않는다. fresh/fit 가중치가 원 V4와 같음을 확인해 보상 외 초기 차이를 배제한다. 원자료 수집을 반복하거나 선택 교사를 NN 평가에 혼합하지 않는다.
3. 실제 Python3.8 CPU에서 유보·정산·중복지급·끝경계·부분reset·실패억제와 B불변을 검사하고 독립 검수를 받는다. 입력 봉인 후 GPU 직렬로 fit→초기 고정/확률128→PPO300→50간격 고정128/최종확률128을 수행한다. 학습과 평가의 A 지급 원장을 남긴다.
4. 원128전체·384음 분모에서 all3, achieved_AND_released, A clean/streak, release,9보상·실패를 V4와 비교한다. 평가 점수와 무관하게 마지막300 영상 저장·분석·독립 검수한다. 전곡/자유 기타/다른손가락 성공으로 대체하지 않는다.

- [ ] 최소 구현과 CPU 검증
- [ ] 독립 검수·입력 봉인
- [ ] 동일 초기 모델의 fit 및 실제128 사전 평가
- [ ] PPO300과 일곱 후속 평가
- [ ] 결과 비교·마지막 영상·독립 검수

이 문서는 실행 입력 봉인 후 수정하지 않으며 완료 상태는 상위 계획/status에서 갱신한다. 이 변경이 후반 망각도 해결한다는 주장은 실제 결과가 나오기 전에는 하지 않는다.
