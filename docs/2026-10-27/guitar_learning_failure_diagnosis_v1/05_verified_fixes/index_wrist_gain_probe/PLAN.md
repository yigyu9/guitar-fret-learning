# 검지 손목 보정 속도 단일 비교

## 근거와 승인 범위

기존 12단계 사전검사는 root 실제 종료0으로 완료됐다. 검지 reference0/4이며 env0의 음 중 패드 위치 gate가 충족되지 않았다. 손목 위치 오차는2초6.79mm→2.5초44.58mm→2.75초16.51mm→3초43.55mm로 재증가했다. 보정 누적과 요청-실제 관절 오차도 증가했다. 이들은 현재 raw의 후속 분석으로 독립 검수를 진행 중이며 단일 원인의 증명은 아니다.

이미 승인된 실패 진단·필요 개선 범위에서, 먼저 피드백 속도 하나를 바꾼 분리 검사를 준비한다. 생산 소스·원래 입력·구버전 결과를 수정하지 않는다. 기준 자세 재선정, 준비시간 증가, 관절 범위/PD/힘/접촉 문턱 변경을 섞지 않는다.

## 한 가지 제어 차이

- 원래 arm-only 손목 보정 한 tick 최대0.5도(30도/초)를0.1도(6도/초)로 낮춘다.
- 제어 schema/설명은 별도 진단 버전을 명시한다. schema 및 해당 속도 메타데이터 외에 다른 수치·수식은 동일하다.
- 기존2초 ramp·3초 onset·고정 기타·검지row1 teacher/reference·나머지B/엄지035·native arm alpha0.2·손가락 incremental·native 범위/속도·9보상·종료는 유지한다.
- 원래 0.5도 조건은 이미 완료한 index_initial/reference/zero/random 원자료를 재사용한다.0.1도 조건의 결과를 본 뒤 다른 gain을 추가하지 않는다.

## 실행과 검증

1. 새 docs wrapper에서만 WRIST_CONTROL 상수를 명시적으로 설정하고 현재 runner/CLI를 재사용한다. 실제 wrapper·계획·검사를 입력에 봉인한다. 기존 source contract를 완화하지 않는다. 현재 기본값으로 새 저장본을 읽는 strict load는 거부돼야 한다.
2. large·4환경·H32·seed7·train1은 initial.pt 생성만 한다. 기존 initial과 초기 정책73텐서의 동일성을 확인하고 optimizer 업데이트 전 저장본만 평가한다.
3. 같은 initial.pt의 reference/zero/random 각4첫시도를 평가한다. 실패도 분모에 남긴다. 원래 시간/목표/판정은 유지한다.
4. CPU 검사와 독립 변경 검수·입력 봉인이 끝나면 root만 GPU에서4단계를 직렬 실행한다. 실제 종료코드·12기존/4신규 장면종료·입력불변·분모를 확인한다.
5. 음 중 달성/clean/wrong와 손목 위치·회전 오차, correction 누적·request/actual/native submitted target·범위 체류를 비교한다. env0 60Hz와 전체4시도240Hz 음악 원장을 구분한다. force는 body resultant로만 보고한다.

작은 native reference 통과 목표는 기존 달성≥80%·clean≥70%·wrong≤10%·물리실패≤5%다.4시도는 일반 성능 검증이 아니며 RL 성과로 보고하지 않는다. 손목 오차·누적이 줄어도 압현을 잃으면 개선으로 채택하지 않는다. 실패 시 기준을 완화하거나 추가 gain 탐색으로 이어가지 않고 원인을 재분류한다.
