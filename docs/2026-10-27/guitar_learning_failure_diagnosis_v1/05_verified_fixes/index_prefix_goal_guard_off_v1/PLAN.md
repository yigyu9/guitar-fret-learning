# 절대 목표각과 DIP 보호의 결합: frozen model 비교

2026-10-28. 후보std precheck는 평균 전체126/128·A해제73/128, 확률전체10/128·해제118/128·실패0이다. 확률해제118중77은 A미달성이다. 기존354×128 기록의 연속eligible 동일goal 구간에서 확률 DIP목표 누적변화 중앙−.6135도/최소−3.7011도이고 양의변화는0이다. 이는 양의닫기증분차단과 음수통과의 구현에 맞는 관찰이며 성과후퇴의 단독원인 증명은 아니다.

원보호는 incremental 정책의 접촉후 계속닫기와 극단DIP 자세를 줄였지만, absolute goal의 양방향잡음에서는 이전목표보다 낮은 값만 받아들이는 편향이 생길 수 있다. 복잡한 새접촉기억/관절범위/계수를 추가하기 전에 **DIP 추가양증분 보호만 끄는 실행 개입**으로 분리한다. 기본학습에 채택하는 작업은 아니다.

## 1. 최소 CPU 준비·독립검수

- 원precheck의 모델70e/후보std/원fullstrict→std4개입→seed7/actual sampling/GoalPool변환1회/원evaluator를 재사용한다. 새fit/PPO/저장모델·보상/관측/시간표 변경은0이다.
- 기존 보호의 passthrough 경로를 가능한 한 재사용한다. 다른104열·bounds/4rad/s/PD/0.25Nm/105/90쌍·손목안내·비선택B/엄지035를 유지한다. 손가락간 충돌이나 물리·손목 종료를 끄지 않는다.
- 원계약/원모델 full strict 검증은 유지하고 별도 실행개입에 DIP보호 off를 명시한다. 원guard-on metadata/report를 실제guard-off인 것처럼 덮어쓰지 않는다. 체크포인트는 동일한 원파일이며 수정하지 않는다.
- CPU 고정snapshot에서 on/off 차이가 DIP제출열뿐임, off의 raw/final 목표 일치와 범위/속도 준수, 원before/after 실제콜백·모드/RNG·오류/alias·출력보호를 최소검증한다. 기존on의 would-block과 실제off blocked0은 별도로 명명한다.
- 준비에는 기존precheck 실제분석 독립PASS를 gate로 요구한다. 원source/봉인/실제결과는 동결하며 runtime입력에 mutable 진행문서나 새analysis 소스를 넣지 않는다.

## 2. root 직렬 native: off 평균128→off 확률128

기존on 두조건은 재실행하지 않는다. 새출력 각128첫시도/원384음을 사용한다. 정확두명령을게시하고 CPU/독립검수·최종봉인 후 root만 직렬 실행한다. 조건별 seed7과 동일원초기상태를 유지하며 추가조건/계수탐색/실행재시도는 자동으로 하지 않는다.

실제모드/RNG·모델불변·변환1회·원파일불변·수정범위와 native상한/close를 확인한다. 전체 음악·해제와 A달성/해제 교차·9항·bounded4관측/env0·DIP목표/실제각/힘·현재후보/차단기록을 남긴다. off에서 극단DIP/부하가 재발하는지도 함께 본다.

## 3. 실제분석·독립검수와 판단

각조건 원90% 음악/해제/AND 기준을 유지한다. on/off는 frozen policy의 closed-loop 실행개입이며 이후관측/NN출력이 달라질 수 있어 동일액션의 물리대조로 부르지 않는다. on/off의 보호차이와 목표감소패턴·후보이탈/clean연속변화를 함께 보되, 기록되지 않은240Hz 사건/다른손가락/자유기타/J33/67음·자연스러움으로 확대하지 않는다.

보호off가 개선돼도 기본삭제나 장기PPO는 별도판단이다. 기존보호가 incremental에서 줄인 극단자세의 근거를 지우지 않는다. 미개선이면 새계수/예산을 자동확장하지 않는다. 보상유보안도 이 비교에 섞지 않는다.
