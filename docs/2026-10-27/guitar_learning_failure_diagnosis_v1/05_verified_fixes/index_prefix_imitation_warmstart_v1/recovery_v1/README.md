# 원수집 자료의 제한적 후속 사용

원 collect 프로세스는 exit1이고 imitation_report.completed=false이다. 이 값은 바꾸지 않는다. 원 native diagnostic은 completed/closed/source unchanged이고128첫시도/384음·각음/all3/A release128/128·실패0이다. 원 observer의 생성되지 않은 `NN_constructors` 키를 default 없이 읽은 `None==0`만 false였음을 별도 CPU/독립검수로 확인한다. NN미생성은 저장 runtime counter0이 아닌 동결 source noNN provider 경로에 근거한다.

`collection_recovery.json`은 위 정확한 한 오류·원 launcher/report/source SHA·dataset SHA00bfe7…·4×354의 관측/clock/요청/목표·원128 acceptance를 묶은 새 자료수용 기록이다. 다른false/missingcheck/source변경/오염이면 거부한다. 원 수집과 실패 보고서를 고치거나 재수집하지 않는다.

원 fit/NN-evaluate 함수를 그대로 호출하고 gate/output/metadata schema/descriptor 네 binding만 실행 중 연결·finally복원한다. collect는 원 폴더만 읽고 새 출력은 이 폴더의 runs/fit 및 runs/evaluate뿐이다. 원 함수의 exclusive mkdir/dev-inode 소유검사·source/모델 strictload·105/cap/90쌍/원 currentgoal guard·PPOempty0를 그대로 쓴다. 후속 wrapper는 별도 raw파일을 덮어쓰지 않으며 복원 여부를 root가 보존하는 stdout 로그에 기록하고 오류면 원 실패를 유지한다.

새 metadata schema는 `diagnostic.index_prefix_imitation_initialization.recovery.v1`, actual_initialization에는 새 수용기록 SHA와 원 exit1/reportfalse/nativecompletedtrue를 명시한다. 원 policy architecture/environment identity와1000×192·6구간·Adam/std/73모델 불변검사는 유지한다. collect 실행 명령은 없고100PPO도 구현하지 않는다.

CPU prepare/독립검수 후 root만 `cpu_inputs/commands.json`의 fit→evaluate 두 명령을 GPU직렬로 실행한다. fit은 장면이 없고 evaluate만 새128scene이다. 원보고서 false를 성공으로 정정한 것이 아니며 NN성과·닫힌 루프재현·자연성은 아직 미검증이다.
