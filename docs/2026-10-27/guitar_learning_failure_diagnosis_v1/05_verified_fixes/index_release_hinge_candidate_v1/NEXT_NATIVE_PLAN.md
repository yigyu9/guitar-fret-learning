# 다음 실제 검증: 해제 목표2축만 변경

현재CPU의 조건부기하 통과는 실제 개선이 아니다. 기존 전체 실패진단 계획의 순서를 유지한다. 외장 원입력3개가 다시 읽히고 원SHA와 일치해야 실제 실행을 준비할 수 있다. 원source/checkpoint 검증을 완화하거나 다른 준비자세로 대체하지 않는다.

1. **기준 입력과 실행 경로 확인**: 원prepared/initial_values/inputs_before의 원SHA 재검증. 현행코드의 별도 fresh 무신경망 진단으로 원3음[4,7,8]·기타고정·128환경·seed7·60Hz/240Hz·035reset·유한손목v3·다른손가락B·엄지035·비엄지0.25Nm·90선별충돌쌍을 명시한다. 과거 checkpoint/source pin을 현행으로 고치거나 과거성과를 새실행에 상속하지 않는다. 현재통합소스와 당시 자료의 차이는 새실행 계약과 source SHA로 공개한다.
2. **기준 동작 한 번 검증**: 원A→N→B7/B8 참고 목표를 기존 유한 action 경로로 실행한다. 원장·음별달성/유지/오압현·A 달성/해제교차·실패 포함128분모를 기록한다. 새로운 baseline이 원reference의 핵심성과와 다르면 후보와의 인과 비교를 중지하고 경로차이를 먼저 설명한다. 비교를 맞추려 임계값·물리·타임라인을 바꾸지 않는다.
3. **단일 해제 후보 한 번 비교**: N 유지구간과 기존100ms 열기/120ms 닫기 보간에만 PIP40°/DIP10°를 사용한다. MCP2 N목표·A/B7/B8 접촉목표·팔/손목이동·속도/한계·DIP보호·보상·정상/조기종료는 그대로다. 준비기간과 최초압현에는 후보를 넣지 않는다. 실제q/target을 덮어쓰지 않고 원codec에서 요청을 생성한다. static추정과 실제index1회전/팔변화·추종lag를 분리한다.
4. **실제 여유와 후속 판정**: 사전 env0..3의 제한된60Hz 창에서 원index3 안쪽128점 signedheight/유한셀거리/원candidate·부하·해제latch를 측정한다. 실패endpoint·원오류·장면close·source전후를 보존한다. 후보의5mm는 별도기하설계 진단이며 원음악/해제기준90%를 바꾸지 않는다. 실제reference의 음악·해제·AND 기준을 통과한 뒤 같은 기존잡음조건에서 추가 한 번 실행해 최초압현 취약성이 남는지 따로 확인한다. 새로운std/grid/K/상관/보상/PPO/지도학습을 함께 넣지 않는다.

실제기하·음악·해제 개선이 확인되면 새관측/목표 단위에 대한 소스·계약을 명시하고 짧은NN/PPO진입을 별도로 정한다. 미충족이면 단일실패 gate를 근거로 다음 원인을 좁힌다. 고정기타 조건을 통과해도 자유기타/J33·다른손가락/seed·원67음·자연스러움의 원목표는 남는다. 이후 평가·실제 영상·문서화를 끝내야 전체목표 완료다.

현재 상태: CPU기하 후보만 완료, 새native/학습0. 외장마운트 EIO로 원입력 재검증이 불가능하여 실제 실행은 시작하지 않았다. 이 파일은 다음 실행의 범위 메모이며 실행 가능한 producer/사전검수/새계약을 대신하지 않는다.
