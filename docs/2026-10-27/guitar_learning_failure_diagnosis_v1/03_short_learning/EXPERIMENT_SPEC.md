# 짧은 과제 비교의 사전 조건

정책 학습 결과를 보기 전에 정한 조건이다. GPU 사전검사를 통과한 뒤에만 본 비교를 시작한다.

## 과제와 진입 기준

- 원곡의 중지 목표 row8 (`event-000052/string-3/note-53`)을 먼저 사용한다. 실제 정적 접촉에서 손목 조건을 만족하고, 선택된 표본의 말단 몸체 합력이1.59N인 팔 목표를 사용한다. 그때 진단 제어가 중지4축도 바꿨다는 점은 별도 기록했다.
- 원곡 onset을 local3초에 맞춘 단일 목표다. 원래 press→onset 간격, 음 길이와 연속 달성 문턱은 보존한다. 자유 기타 전곡 성과로 확대하지 않는다.
- 기타 고정, 팔12축은 봉인한 유한 목표까지3초 ramp 후 유지, 엄지는035 기준, 다른 손가락은 B를 유한 제어로 유지한다. 학습 손가락4축에는 정책 행동만 제출한다.
- `reference` 대조만 학습 손가락에 봉인한 접촉 목표각을3초 ramp로 요청한다. 이는 실제 도달 가능성 검증이며 정책 성과가 아니다. `zero`·초기 확률 정책·학습 정책과 분리한다.
- 같은 조건의 실제 악보 시계에서 reference가 candidate→clean→달성을 확보하고 손목/물리 종료가 없어야 학습 비교에 진입한다. 실패하면 원인을 확인하며, row9를 사전 지정 대안으로 검사한다. 대안도 실패하면 도달 경로를 먼저 개선하고300회 비교를 시작하지 않는다.
- 정책 likelihood·부분 reset·소스 봉인·저장/동일 계약 로드 검사와 PPO1회 smoke를 먼저 통과해야 한다. 진단 체크포인트를 기본 학습으로 읽거나 구버전 체크포인트를 이전하지 않는다.

## 제어 비교

- 두 조건은 `incremental`과 `position`이다. native 범위·속도·힘/PD·보상9항·실패 cost·종료 조건·원곡 목표·teacher 목표·PPO 설정을 동일하게 둔다.
- 중지4축의 prepared 기준에서, native 한계와4rad/s 상한을 적용한 첫 tick 목표각 변화 pooled RMS를0.570069도로 맞췄다. initial latent std는 incremental0.1711710544767014, position0.01이다. 사전 난수100000개/seed123을 사용했다. [계산](exploration_calibration.json)
- 축별 RMS와 장기 누적은 동일하지 않다. GPU 사전검사에서 실제 target/q 변화를 따로 확인한다. 학습 성공률을 보고 초기 std를 조정하지 않는다.
- 본 비교는 large·128환경·H32·K1·300업데이트·조건별1,228,800전이다. seed7/17로 비교하고, 채택 후보가 생기면 seed27로 확인한다. 초기/최종 및50회 간격 모델을 보존하며 같은 경로를 덮어쓰지 않는다.
- 매50회 동일 조건의 별도 고정 평가를 시행한다. 원래 계획 기준은 달성률80% 이상·평균 clean70% 이상·audible wrong10% 이하·물리 실패5% 이하를 연속2회 확인하는 것이다. 손목 실패와 총 실패도 함께 보고한다. 실패 에피소드를 분모에서 제외하지 않는다.
- 사전검사 실패나 비유한 값·계약/시계 불일치·학습 중 소스 변경 때 즉시 중단하고 원인을 수정한다. 성과 기준 미달을 이유로 예산을 연장하거나 통과 기준을 낮추지 않는다.

## 기록

항목별 보상, 실패 cost, 달성/clean/wrong/부족, 종료 사유, 실제/목표 관절각·한계 체류·추종 오차와 지정 평가 env0의 행동/목표/실제 자세를 저장한다. 모든 환경의240Hz 전체 원장은 저장하지 않는다. reference가 만든 접촉, 초기 우연 접촉과 학습 후 성과를 나눠 보고한다.


## v2 실제 실행 조건 보정 (첫300회 학습 전)

위의 고정 팔 목표각 조건(v1)은 두 목표 reference에서0/4달성이어서 채택하지 않았다. 원자료와 v1 소스는 보존했다. v2는 실제 접촉 순간의 손목 위치·방향을 기타 좌표에서 고정하고, 팔12축만 native Jacobian 피드백으로 유한 제어한다. 선정 손가락·패드 오차는 팔 안내에 사용하지 않는다. 팔 feedforward와 reference 손가락 ramp는2초, audible onset은 기존3초다. 모든 준비 전이를 수집하며 보상·종료·PD·힘·native 범위는 바꾸지 않았다. 팔 요청은 기존3rad/s, LH21은 기존4rad/s이고, 추가 팔 보정은 tick당±0.5도다.

4환경 사전검사 결과는 두 제어 방식 모두 reference3/4달성·clean75%·wrong25%, 출력0/무작위0/4달성이며 물리·손목 실패는0이다. reference의 남은 오압현과 손목 추종 오차는 해결됐다고 보고하지 않는다. 이는 해당 중지 과제의 정책 비교 진입 근거이고,80%의 학습 채택 기준을 통과했다는 의미는 아니다. [사전검사 요약](precheck_wrist_pose_summary.json)

첫 본 비교는 동일 중지 row8/large128/H32/300회/seed7 incremental이다. GPU 검사 중 발생한 호스트 CPU14 응답 지연을 피해 이후 본 비교의 양 조건에는 CPU0~13을 동일하게 지정하고 KMP affinity를 비활성화한다. 물리 엔진·학습 설정 변경은 아니다. 실행 초기 PATH 누락으로 생긴 Ninja 오류는 학습0회에서 중단됐으며 실패 자료를 보존한 새 retry1 출력에서 재시작했다. 결과에 따라 초기 std나 목표를 바꾸지 않는다.
