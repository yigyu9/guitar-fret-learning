## 3.1 손가락별 균형 계수

전체 목표 수를 M, 곡에 등장하는 손가락 수를 F, 손가락 f의 목표 수를 n_f라고 하면 그 손가락에 배정된 음의 계수는 다음과 같다.

~~~text
b_i = M / (F × n_f)
~~~

기본곡 M=67, F=4다.

| 손가락 | 목표 수 | 음 하나의 b |
| --- | ---: | ---: |
| 검지 | 25 | 0.670000 |
| 중지 | 18 | 0.930556 |
| 약지 | 12 | 1.395833 |
| 소지 | 12 | 1.395833 |

각 손가락의 모든 b를 합하면 똑같이 16.75다. 음이 많은 검지가 양성 보상의 총 기회를 독점하지 않도록 한 설계다. 실제 학습 성과의 균형을 보장하지는 않는다.

v15의적용대상은 **접근potential・최초접촉・압현 유지・음별달성및wrong/missing/missed감점**이다. wrong/missing에는추가로음길이D정규화,missed에는최장연속clean부족률을적용한다. 모든자세항에일괄적용하는계수는아니다. 추종은 별도의 “등장 손가락 수로 평균”하는 방식을 사용한다.

## 3.2 손목 영역 안내: song_wrist_position

v9부터 유지하는 GPU 왼손 손목 안내는 한 점이나 초기 손목 회전을 따라가지 않는다. 악보 hand_position_targets의 작업 범위 `allowed_fret_range`와 `anchor_fret`를 읽어 다음 기타 상대 3D 영역을 만든다.

| 축 | 기준 | 경계 |
| --- | --- | --- |
| Gy·넥 길이 | allowed_fret_range 양끝 프렛 셀의 실제 바깥 경계 중점 | 중심 ±6cm |
| Gx·높이 | anchor 프렛 셀 중심에서 source neck hull과 지판면이 만나는 아래 테두리 | 아래로 +1~8cm |
| Gz·깊이 | source neck 지판 압현면 | Gz 기준 −11~−2cm, 지판 뒤2~11cm |

길이 기준은 활성 음 하나의 프렛이나 anchor 프렛 와이어가 아니라 작업 프렛 묶음의 실제 셀 범위 중심이다. 높이 기준의 아래 테두리는 1번 현 쪽 넥 외곽이다. 축은 화면 방향이나 world 축이 아니라 기타 G 프레임이므로 영역은 기타와 함께 움직이고 회전한다. 초기 손목 위치를 영역 중심으로 다시 사용하지 않는다. 이 직육면체는 안내용 실험 범위이며 모든 꼭짓점의 손가락 도달성·자연스러운 압현을 인증하지 않는다.

원곡 악보 시각은 환경 시각에서 정책 준비3초를 뺀다. 원곡60Hz 트랙으로 만든 각 경계(lower/upper)를 선형 보간하고 시작 전·끝 뒤에는 양끝 값을 유지한다. 범위나 anchor가 바뀌는 구간도 경계를 보간해 이동한다.

~~~text
w = 실제 손목의 기타 상대 위치 [Gx,Gy,Gz]
e = clamp(w, lower, upper) − w          # 축별 최근접 영역점까지 벡터
q = Σ (e / [0.02, 0.03, 0.03])²         # m, 높이/넥 길이/깊이
원시 rate = −q / (1+q)
R_wrist += 원시 rate / 240               # 모든 물리 표본에서 한 번
최종 손목 항 = 단계 w_wrist × R_wrist
~~~

**안·경계는0이고 밖만 감점한다.** 안에서 중심에 더 가까워져도 추가 보상을 주지 않는다. 원시 rate는 유한한 초과 거리에서 −1보다 크고0 이하인 벌점이며 초과 거리에 따라 매끄럽게 증가한다. 정책 준비3초와 음 사이·곡 말미를 포함해 전240Hz 표본에 적용한다. 과거 준비~음 끝 창(reach window) 제한은 제거한다.

단계0/1/2의 기존 wrist 계수0.2/0.1/0.05는 유지한다. 단계0에서 높이만1cm 초과하면 q=0.25, 최종 rate=−0.04/초다. 넥 길이 또는 깊이만3cm 초과하면 q=1, −0.10/초다. 여러 축 초과는 q에 함께 더한다. 손목 항은 safety cost가 아니라 signed reward의 기존 song_wrist_position에 기록된다.

관측 위치 안내3열은 최근접 영역점−손목 벡터이며 안에서는0이다. orientation 안내3열은0으로 두고 초기 회전을 강요하지 않는다. 손목 안내의 기존 정규화·열 순서를 유지하며 전체 상태는 엄지8열을 더한552이다. **ready는 경계를 포함한 영역 진입**이며 회전 조건은 없다. 이 ready는 압현 허용이나 GPU 단계 진급 gate가 아니다. 손목 항은 v10 패드 접근/positive와 별개이며 contact_done의연속시간/clean_streak의압현 달성 문턱과 기존 손가락/팔 제어·물리는 유지한다.

CPU 왼손과 오른손에는 이 영역을 자동 적용하지 않는다. 현재 v22는 충돌·보상·552관측 계약이 바뀌므로 v21 이하 checkpoint의 strict resume를 거부한다. 새v22 또는 동일v22 전체 계약끼리만 복원한다. [현행 검증](/home/ajou/yigyu/3/docs/2026-10-26/guitar_learning_hand_contact_v22/README.md)을 따르며 이전 장기 학습·v20 구동검사를 새 성과로 상속하지 않는다.

근거: [영역 생성·거리·감점](/home/ajou/yigyu/3/guitar_learning/gpu/geometry.py), [관측·240Hz 적분](/home/ajou/yigyu/3/guitar_learning/gpu/environment.py), [구현·검증 현황](/home/ajou/yigyu/3/docs/2026-10-23/guitar_learning_wrist_region_v1/README.md).

## 3.3 손끝 표면 접근: song_left_approach

지정 finger3 패드의 유한 거리만 potential에 사용하며 법선·하중 조건으로 gate하지 않는다. 공통 선택기로 손가락별 현재 audible 음을 우선하고 없으면 준비 창 안의 다음 음을 선택한다. 유효 tracking slot0만 최대 4개 사용한다. 이미 달성한 음도 현재 선택 규칙에 해당하면 포함하며, 모든 활성 음을 동시에 합산하지 않는다.

~~~text
selected = 손가락별 유효 tracking slot0, 최대 4음
Φ(s,t) = Σ_selected b_i × exp(−surface_distance_i / 0.03)
R_approach = γ × Φ(next) − Φ(current)
γ = PPO reward gamma = 0.99
~~~

한 정책 tick 시작과 끝의 potential을 비교한다. 단계 가중치는 모든 단계에서 1이다. 진짜 곡 종료·물리 실패에서는 next Φ를 0으로 한다. H32 수집 경계나 목표 선택 변화 때문에 항을 생략하거나 상태를 초기화하지 않는다.

### 수치 예시

어떤 음 하나의 b=1이고 준비 창이 유지된다고 가정한다.

| 거리 변화 | 이전 Φ | 다음 Φ | 해당 음의 접근 보상 |
| --- | ---: | ---: | ---: |
| 30mm → 20mm | 약 0.3679 | 약 0.5134 | 약 +0.1404 |
| 20mm → 20mm | 약 0.5134 | 약 0.5134 | 약 −0.00513 |
| 창 종료로 다음 potential 0 | A | 0 | −A |

따라서 “가까이 있으면 매 순간 양의 접근 보상”이라는 설명은 틀리다. 고정된 potential에서는 할인 때문에 작은 음수가 생긴다. 창 진입·종료로 값이 바뀌는 효과도 포함된다.

할인 누적합에서 중간 potential이 상쇄되고, 같은 초기 상태와 terminal Φ=0이면 이 항은 초기 potential에 따른 상수로 정리된다. 이는 보상 shaping의 구조적 성질이다. 함수 근사·짧은 수집·변하는 정책 아래에서 학습 효율이나 수렴이 보장된다는 뜻은 아니다. 7장에서 시간 범위를 설명한다.

근거: [potential](/home/ajou/yigyu/3/guitar_learning/gpu/environment.py), [차이·terminal 처리](/home/ajou/yigyu/3/guitar_learning/gpu/environment.py).

## 3.4 최초 접촉: song_left_contact

각 음의 p~e 안에서 `both=candidate(previous) AND candidate(now)`인 유효 구간을 `contact_streak`에 연속 적분한다. 후보가 끊기거나 창 밖이면 현재 streak는0이지만, 최장값 `best_contact_streak`는 그 음의 에피소드 동안 보존한다. GPU왼손은 end<=press 목표를 초기화에서 거부한다. 짧은 양수 창에는 기존 min 문턱을 쓴다.

~~~text
tau = min(0.05초, e−p)
유효 both AND press_dt>0이면 current += press_dt, 아니면 current = 0
best_new = max(best_old, current)
progress_old = min(best_old / tau, 1)
progress_new = min(best_new / tau, 1)
원시 최초접촉 증가분 = 0.5 × b_i × (progress_new − progress_old)
contact_done |= (current >= tau)
~~~

v19는 기존의 문턱 도달 시 이진 보너스를 이 증가분으로 대체한다. 이진 보너스를 추가로 주지 않는다. b=1·tau=50ms라면 최장 접촉20→40→50ms에서 원시 예산 누적은0.2→0.4→0.5다. 20ms 접촉을 여러 번 반복해도 최장값이 늘지 않아 추가 예산은0이다. 20ms→끊김→30ms라면 누적 contact_time은50ms여도 최장은30ms·예산 진행률0.6이며 contact_done은 거짓이다. 한 번의 연속50ms를 만들어야 완료다.

음별 원시 예산 상한은0.5b로 유지한다. `contact_progress`는 **소진한 원시 보상 예산의 진행률**이며 실제 받은 금액이 아니다. 기존 실패tick 양성 억제를 유지하므로 실패tick에서 best가 늘어도 실제 양성보상은0이고 그 예산을 다시 지급하지 않는다. 최종 보상은 단계 contact 가중치0.5→1→1을 적용하며, 접촉 도중 단계가 바뀌면 분할값의 가중합이 이전 이진 지급액과 같다는 보장은 없다. 실제 지급 결과는 `reward_components.song_left_contact`로 확인한다.

준비 p~o에서도 접촉을 확보할 수 있다. 별도 시점별 가산이나 초당 접촉 보상은 없다. H32 경계에서 current·best·progress를 초기화하지 않고 종료환경의 선택행만 reset한다. 누적 contact_time은 진단용, audible clean 누적은 유지보상용, onset~end clean_streak는 음별 달성용이다. CPU왼손·오른손은 기존 경로를 유지한다.

근거: [원장·진행·보상·관측](/home/ajou/yigyu/3/guitar_learning/gpu/environment.py), [구현·검증](/home/ajou/yigyu/3/docs/2026-10-25/guitar_learning_press_acquisition_v1/README.md).

## 3.5 압현 유지: song_clean_hold

onset~end의 실제 clean 증가량을 음 길이로 나눈다.

~~~text
D_i = e_i−o_i
원시 증가 보상 = 2 × b_i × clean_dt_i / D_i
~~~

음이 짧든 길든 전체 audible 구간을 clean으로 유지했을 때 원시 총량의 이론상 상한은 2b다. 같은 clean 10ms라도 짧은 음에서는 더 큰 비율이 된다.

음별 성공 문턱을 이미 넘었어도 end까지 계속 지급한다. 40%만 채운 다음 손가락을 떼면 그 뒤의 유지 보상은 얻지 못하고 누락·오압현 감점이 남는다. 다만 left 플래그 자체를 취소하지는 않는다.

최종 timing 가중치는 0.5→1→2다. 예를 들어 D=0.5초, b=1, clean 총량=0.2초이면 원시 유지 보상은 0.8이다. 단계 0/1/2에서는 각각 0.4/0.8/1.6이다.

근거: [유지 보상](/home/ajou/yigyu/3/guitar_learning/gpu/environment.py).

## 3.6 압현 달성: song_left_success

GPU왼손 초기화는 `end<=onset`인0음길이 목표를 ValueError로 거부해0문턱 무접촉달성·유지보상/이벤트의0분모를 방지한다. 기존양수D와짧은음의min문턱은영향없고CPU왼손·오른손·공유ScoreTask는유지한다.

v12는onset~end안의연속clean_streak가required문턱을처음채울때기존보너스를지급한다. clean_streak는both인양수audible구간을이어더하고끊김·창밖에서0으로돌아간다. 누적clean은진단·유지보상용으로보존한다.

~~~text
required = min(D, max(0.05초, left_fraction × D))
확인한 left_fraction = 0.4
현재 clean_streak >= required 를 최초충족할 때만 지급
원시 달성 보상 = 0.5 × b_i, 음마다 한 번
최종 timing 가중치 = 0.5→1→2
~~~

“해당 음의 40% 유지”와 “곡 전체의 40% 음 달성”은 다르다. 여기서는각음의onset이후연속유지시간기준이다. 40%는학습용중간달성이며음끝까지완전유지했다는조건이아니다. 달성이후떨어져streak가0으로돌아가도left는유지되고보너스를다시주지않는다. 예를들어D=.5초일때100ms→끊김→100ms는유지보상은받지만.2초연속을만들지못해달성보너스는없다. contact_done과 left는 서로 다른 사건이라 같은 음에서 최초 접촉 보상과 음별 달성 보상을 각각 얻을 수 있다.

근거: [required·clean_streak·달성사건](/home/ajou/yigyu/3/guitar_learning/gpu/environment.py), [이번구현·검증](/home/ajou/yigyu/3/docs/2026-10-23/guitar_learning_continuous_clean_v1/README.md).

## 3.7 한 음의 계산 예

D=0.5초, b=1인 가상의 음을 생각한다. p~e 안에서 유효 접촉을 충분히 얻고, audible 전체 0.5초를 clean으로 유지했으며 실패하지 않았다고 가정한다. 아래는 접촉·유지·달성 세 항만 합친 값이다.

| 단계 | 최초 접촉 | 전체 압현 유지 | 달성 | 합 |
| --- | ---: | ---: | ---: | ---: |
| 0 | 0.25 | 1.0 | 0.25 | 1.5 |
| 1 | 0.5 | 2.0 | 0.5 | 3.0 |
| 2 | 0.5 | 4.0 | 1.0 | 5.5 |

여기에 손목·접근·추종·자세·감점과 별도 cost가 더해진다. 실제 b는 손가락마다 다르고 단계도 0.1 단위로 보간된다. 이 표는 같은 단계가 유지되고 접촉 예산을 끝까지 채운 이상적 예다. 실측 점수나 전체 보상의 상한이 아니다.

67음에서 Σb=67이므로 이 세 항만의 이상적 이론상 합은 단계 0/1/2에서 각각 100.5/201/368.5다. 이 값과 연속률 보상의 장기 누적량을 비교할 때는 반드시 같은 기간과 단계, 실제 발생 빈도를 맞추어야 한다.

## 3.8 별도 v24에 적용할 때의 차이

위 수식·67음 균형계수·세 항의 이론상 합은 기본 song 경로를 기준으로 했다. v24의 F/J는 같은 측정과 보상식을 재사용하되 선택한 원곡 음만 대상으로 한다. 균형계수도 `선택 음 수 / (선택 음에 등장하는 손가락 수 × 해당 손가락의 선택 음 수)`로 다시 계산한다. 부분곡에 전체곡의 M=67·손가락별25/18/12/12를 그대로 대입하지 않는다. 추종의 등장 손가락 분모도 선택 범위를 따른다.

R은 최종 reward에서 손목·엄지·행동변화·실패 항만 남긴다. 접근potential·최초접촉·유지·달성은 측정되더라도 R의 최종 보상으로 지급되지 않는다. 따라서 이 장의 접근·접촉·유지 예산을 R의 보상 크기로 비교하면 안 된다. F/J도 기본 song의 성과를 상속하지 않으며 부분곡·전곡 성과를 따로 평가한다.
