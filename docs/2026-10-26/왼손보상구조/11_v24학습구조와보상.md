# 11. v24 학습 구조와 보상

확인일: **2026-10-26**. 이 장은 `--learning-family finger-skill-v24`로 선택하는 GPU 왼손 경로를 설명한다. 옵션을 생략한 기본값은 여전히 `song`이다. [전체 목차](README.md) · [기본 song 보상 요약](00_보상구조요약.md).

## 11.1 무엇을 나누어 학습하는가

기본 song은 같은 정책으로 원곡 전체를 진행하면서 음악 stage0/1/2의 가중치를 바꾼다. v24는 팔·손목·엄지와 네 손가락의 정책을 분리하고, 별도 R/F/J 단계를 사용한다. J도 왼손 전체의 학습이며 양손 협응 학습을 뜻하지 않는다.

| 단계 | 학습하는 정책 | 다른 정책의 동작 | 자동 실행의 과제 |
| --- | --- | --- | --- |
| R: 지지 준비 | 팔·손목12축+엄지5축, 총17축 | 네 손가락은 초기 결정론적 명령 | 원곡의 연속 구간 |
| F: 손가락 획득 | 검지·중지·약지·소지 각4축, 총16축 | support 정책을 동결하고60Hz로 다시 계산 | 원곡의 연속 구간 |
| J: 전곡 결합 | 왼손33축 | 비활성 오른손6축의 행동은0 | 원곡67음 전체 |

F의 팔과 손목은 물리적으로 고정되지 않는다. 동결한 정책의 명령과 기존 물리 시뮬레이션에 따라 움직인다. support/finger는 인코더·출력부·표준편차와 optimizer 대상을 분리하며, 비활성 정책의 파라미터는 갱신 대상에서 제외한다.

관측은 기본552상태에 R/F/J 표시3열·계획한 결정 길이1열·남은 로컬 시간1열을 더한 **557상태**다. 제어는 `incremental`만 허용한다. 전체 native 가동범위·4rad/s·PD·힘 상한·035/v14 준비 상태·자유 기타 조건은 유지한다.

## 11.2 단계마다 어떤 보상을 쓰는가

| 단계 | 최종 reward에 남기는 항 | 안전 cost |
| --- | --- | --- |
| R | 손목 영역·엄지 안내·행동 변화·물리 실패 항 | 기존 안전 비용을 별도로 유지 |
| F/J | 선택한 원곡 목표의 접근·접촉·유지·달성·wrong/missing/missed·약한 B 등 기존 기반 항 | 기존 기준을 유지하고 남은 길이는 실제 로컬 구간으로 계산 |

R은 음악 측정을 중단하는 것이 아니라, 최종 보상 성분에서 위 네 항 외의 값을0으로 만든다. F/J의 첫 구조 비교는 음악 그룹 비중을 **손목0.2·접촉0.5·유지/달성0.5·접근1**로 고정한다. 기본 song의 최근256곡 stage 자동 진급은 적용하지 않는다. 음 감점의 기존 별도 계수도 이 양성 그룹 계수와 구분한다.

손가락 움직임 비용0, 약한 idle B, 기존 접촉·clean 문턱은 유지한다. 새 움직임 보너스나 강제 B 복귀 제어를 추가한 구조가 아니다.

## 11.3 원곡 일부를 쓰는 방법

원곡의 음 ID·press/onset/end 시각을 유지한 연속 구간을 만든다. 로컬 물리 시간과 원곡 악보 시간을 구분하며, 구간을 고르는 일은 에피소드 reset 때 수행한다. 진행 중인 음을 임의로 자르거나 별도 단음 정답을 만들지 않는다.

현재 기본 곡의20개 겹침 묶음에서24개 view를 만든다. 경계가60Hz에 안전하게 맞지 않는15음 묶음은17음까지 확장된다. reset의 손가락 bucket은 균등 순환한다. 선택 mask를 관측·접촉 판정·보상·감점·추종·성공 분모에 함께 적용한다.

손가락 균형 계수는 선택된 구간에서 다시 계산한다.

~~~text
b_f = M_selected / (present_fingers_selected × own_note_count_selected)
~~~

원곡67을 부분 구간의 분자에 그대로 사용하지 않으며, 선택하지 않은 음을 missing으로 세지 않는다. B 보호에는 선택 음과 손가락별 첫 후속 원곡 음을 반영해 인위적인 구간 말미 휴식 보상을 막는다. 준비3초의 B 체류는 원곡의 실제 회복창 성과와 따로 집계한다.

근거: [원곡 구간 구성](/home/ajou/yigyu/3/guitar_learning/song/finger_phrases.py), [선택 범위·재균형](/home/ajou/yigyu/3/guitar_learning/gpu/finger_skill_environment.py:89).

## 11.4 R→F→J는 어떤 기준으로 진행하는가

| 전환 | 독립 고정 평가의 기준 |
| --- | --- |
| R→F | 안전 종료 비율90% 이상, 실패도 포함한 손목 영역 체류 평균80% 이상 |
| F→J | 안전 종료90% 이상, 네 손가락마다 목표 기회64음 이상 및 달성률20% 이상 |
| J 종료 | 명시된 학습 예산으로 종료하며 숨은 숙련 gate를 두지 않음 |

평가는 실패한 구간도 분모에 포함한다. 학습 중인 정책의 수집 평균과 고정 평가를 섞지 않는다. 예산이 소진됐는데 기준을 충족하지 못하면 `stalled`를 기록하고 종료하며 문턱을 자동으로 낮추지 않는다.

동일 단계의 strict resume는 모델·Adam·난수·curriculum·구간 sampler를 복원하고 새 준비 에피소드에서 시작한다. R→F→J의 transfer는 commit 후 실행을 마감하고 Actor만 이전하는 절차다. critic과 optimizer는 새로 만들며, 기본v22/v23 저장본을 암묵적으로 이어 쓰지 않는다.

## 11.5 결정 길이와 PPO

기본은 매60Hz 새 행동을 결정하고 물리는240Hz로 진행한다. 명시적인 F 비교에서만 최대3/6tick 동안 샘플링한 손가락 행동을 유지할 수 있다. support는 그동안에도60Hz로 결정론적으로 다시 계산한다. 원곡 음 경계에서는 유지 길이를 줄이므로 최대3tick 옵션이어도 실제 결정은1·2·3tick으로 나뉜다.

한 결정의 실제 지속시간을 d라고 할 때 다음을 사용한다.

~~~text
decision_reward = Σ[k=0..d−1] gamma^k × raw_reward[t+k]
bootstrap_discount = gamma^d
GAE_trace_discount = (gamma × lambda)^d
~~~

다음 가치에는 다음 결정의 계획 길이를 제공한다. 환경별 길이가 달라 생긴 padding은 최적화·KL·진단에서 제외한다. 상관 탐색 옵션도3축의 완전한 분포이며 손가락 자유도를 축소하는 방식이 아니다.

`transitions.jsonl.gz`는 원시60Hz 전이, `decisions.jsonl.gz`는 샘플링한 결정의 기록이다. 새 경로의 `mean_reward/mean_cost`는 할인된 결정 합의 평균이므로 기본 경로의 raw tick 평균과 직접 비교하지 않는다. 원시 전이·결정 수·실제 최적화량을 함께 확인한다.

## 11.6 실제로 검증된 범위와 남은 한계

기존 자료에는495개 소스 봉인,54모듈525개 CPU 검사와 다음 짧은 GPU 검증이 있다. 이번 문서 갱신에서 이 실험을 재실행하지 않았다.

| 기록 | 원시 전이 | 결정 수 | 확인된 종료 |
| --- | ---: | ---: | --- |
| F 1024환경 구동 |65,536 |65,536 |완료 에피소드0 |
| F 동일 단계 재개 |32,768 |32,768 |완료 에피소드0 |
| 상관 탐색 F3 |32,768 |12,389 |46개 종료 중 물리 실패3개 |
| R 구동 |8,192 |8,192 |완료 에피소드0 |
| J 구동 |8,192 |8,192 |완료 에피소드0 |

별도의 R 독립 평가는4개 구간에서 안전4/4·손목 체류61.366959%였다. 손목80% 기준을 충족하지 못해 `ready=false`이고, 그 단기 검증 예산에서는 `stalled=true`였다. 이후의 명시적 진단 Actor 이전 검사가 통과했다는 사실은 자동 준비 기준을 넘었다는 뜻이 아니다.

고정128개 패드점의 팔/기타 상대 변위와 손가락 내부 변위를 분해해 기록한다. 이는 기하학적 이동이며 실제 압현 힘의 인과 기여율이 아니다. 단기 구동·동결·복원·확률 계산 검증은 자동 R→F→J 전체 성공, 장기 수렴, 자연스러움, 실제 압력·음향의 인증과 구분한다.
