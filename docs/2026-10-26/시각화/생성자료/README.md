# 초기 자세 고정 곡 목표와 손목 안내

현재 기본곡 `05_BN2-131-B_solo`의 67개 목표를 초기035/v14 자세 위에서 확인한다. 휴머노이드·기타·의자와 실제 손목은 같은 초기 몸체 변환을 유지한다. 곡 시각과 안내 표시만 바뀌며 정책·학습·물리 적분은 실행하지 않는다.

## 표시 내용

- 프렛 영역은 너트~1프렛, 1~2프렛처럼 **이전 경계부터 해당 프렛까지**다. 색칠한 폭은 실제 여섯 현이 차지하는 연주 영역이다. 22개 영역을 모두 표시하고 숫자는 해당 영역의 프렛 번호다.
- 주황색은 `onset≤시각<end`인 현재 발음 목표다. 목표 프렛 영역과 지정 현의 목표 선분을 강조한다.
- 준비 표시는 현행 공통 선택기의 손가락별 tracking slot0 중 아직 audible이 아닌 목표다. 현재 audible 목표와 중복 표시하지 않는다. 준비 창은 `press−2≤시각<end`다.
- 목표 선분은 현재 학습의 넥 압현면 Gz≈9.3mm와 프렛 셀 안쪽2mm를 사용한다. 지점 하나로 압현 목표를 바꾸지 않는다.
- 자홍색 십자는 현행 손목 안내 중심이다. 흰 작은 원은 고정된 실제 손목이고 연결선은 두 위치의 차이다. 손목이 십자로 실제 이동하는 영상이 아니다.

손목 안내는 곡의 `anchor_fret`를 보간한 뒤 **초기 실제 손목 x/z를 유지하고, anchor와 기준5프렛 사이의 y 차이만 더한다.** 따라서 현재 목표음의 프렛 번호와 anchor는 다를 수 있고, 손목 중심이 해당 프렛의 정중앙에 있어야 한다는 의미도 아니다. 손목 초기 기준은 기타 좌표로 약 `[0.064541, −0.047197, −0.065471]m`다.

## 실행과 검증

프로젝트 루트에서 새 출력 경로를 지정한다. 소프트웨어 렌더러를 사용하고 CUDA는 비활성화한다.

```bash
CUDA_VISIBLE_DEVICES='' OMP_NUM_THREADS=1 PYTHONDONTWRITEBYTECODE=1 \
  /home/ajou/miniconda3/envs/rl38/bin/python -B \
  /home/ajou/yigyu/3/docs/2026-10-26/시각화/생성자료/render.py \
  --song 05_BN2-131-B_solo \
  --out /home/ajou/yigyu/3/runs/fixed_song_guides_new
```

현재 GPU 환경의 `_wrist_guide`를 CPU의 불변 장면에 직접 적용하고 별도 보간 공식과 비교했다. 최대 차이는 약1.67×10⁻⁸m다. 목표 선택은 현행 `finger_target_indices`, 프레스 평면은 `load_press_surface`를 사용한다. 몸체106개 위치 오차0·회전 오차약5.09×10⁻¹⁶rad, 시각모델의 nq/nv/time 모두0을 확인했다.

8개 CPU 검사로 곡 전체·프렛 경계·지정 현·안쪽 여유·손목 x/z 불변·음 시작/끝 경계·준비 목표·입력 SHA를 확인했다. 독립 검수의 재생 루프/스크러빙 검사와 영상 전체 디코딩도 통과했다. 이 세션에는 연결 가능한 브라우저가 없어 실제 브라우저 화면에서의 클릭 검사는 수행하지 못했고, 스크립트 모의 DOM 검사와 네이티브 렌더 이미지 검토로 확인했다.

기존 학습 Python438개와 이전 결과 봉인은 변경하지 않았다. 검증 기록은 [verification.json](/home/ajou/yigyu/3/docs/2026-10-26/시각화/생성자료/verification.json), [독립 검수](/home/ajou/yigyu/3/docs/2026-10-26/시각화/생성자료/independent_review.json), [CPU 검사 로그](/home/ajou/yigyu/3/docs/2026-10-26/시각화/생성자료/cpu_tests.log)를 따른다.

## 현재 파일 배치

상위 시각화 디렉토리에는 시점 조절 보기·전곡 영상·대표 이미지 결과물만 두었다. 생성 코드·템플릿·배경·좌표·검증 기록은 생성자료에 모았다. 이동 전 원문과 경로 대응은 relocation.json에 보존했다. 생성 코드는 새 출력 경로로 재실행하며, 기존 결과 경로를 덮어쓰지 않는다.

## 카메라 상하 방향 수정

초기 넥 카메라는 화면 위쪽이 세계 아래쪽을 향해 거꾸로 보였다. 카메라의 시선과 위치를 유지하고 roll만180도 바꿨다. 현재 화면은 세계 위 방향과 내적+0.992597로 바로 서며, 위가6현·아래가1현, 너트는오른쪽이다. 프렛 번호와 목표·손목 표시를 새 카메라로 다시 투영했다.

몸체106개의 초기 변환·곡시간·목표의 실제 기타좌표·손목 안내의 실제 기타좌표는 동일하다. 수정 전 결과 전체는 상하반전수정전.tar.gz에 보존했다. creation/relocation 기록은 각 생성·이동 당시 이력이며, 현재 카메라 검증은 upright_verification.json과 현재 result_manifest.json을 따른다.
