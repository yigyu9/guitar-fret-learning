# 손가락 관절 편중·대기 구간 진단

사용자의 마지막 관절 편중·대기 시간 부족 가설을 최종 v19 정책으로 확인했다. **검지는 대기가 충분히 길어도 PIP를 펴고 DIP를 굽히는 명령을 계속 내며, 압현 중에도 같은 배치를 사용한다.** 대기 길이만의 문제는 아니며, 대기 복귀를 학습하지 못한 정책과 압현 중 관절 분담을 평가하지 않는 목적함수를 구분해야 한다. 학습 원문·원래 결과를 보존했고 보상·제어·PD·관절 한계·성공 기준을 바꾸지 않았다. [작업 계획](/home/ajou/yigyu/3/docs/plans/guitar_learning_finger_diagnosis_20261025.md).

## 판정

| 확인할 가설 | 근거와 판정 |
| --- | --- |
| 대기가 너무 짧아 돌아오지 못함 | 짧은 조각은 존재한다. 그러나 새env0 검지 대기 가능 시간9.258초의92.9%는0.5초 이상 연속 구간이다. 마지막5.879초는full gate1·본인 추종0인데도 PIP≈0°/DIP≈90°가100%다. **단독 설명으로 부적절하다.** |
| 추종 보상이 대기와 동시에 경쟁해서만 생김 | 새env0 검지 B가능9.258초 중 본인추종과 동시인 것은0.658초다. 본인추종이 없는8.600초에도 해당 패턴이79.7%다. 소지는B가능19.792초 전부 본인추종0인데 B품질0.101이다. **동시 추종만으로 설명되지 않는다.** 전체 문맥·미래 보상의 영향까지 배제한 것은 아니다. |
| 보상 gate 자체가 전부 꺼짐 | 실제240Hz gate·품질·받은 보상의 적분이 기존 episode 진단과 일치한다. 초기 검지1.75초와 마지막5.879초의full gate1을 직접 확인했다. **대기 보상은 동작한다.** |
| 관절이 물리적으로 명령을 따르지 못함 | 원본1024곡 검지 PIP/DIP 목표−실제 RMS0.835°/0.823°이며 지속 명령 자체가 하한/상한 방향이다. **이 두 관절의 편중을 제어 추종 불량으로 설명할 근거가 약하다.** 모든 손가락·모든 접촉의 물리 문제를 배제하지 않는다. |
| 압현 중 DIP 편중을 바로잡는 신호가 없음 | 실제 보상의coordination0, B는압현 준비/접촉 근처에서제외된다. 말단패드 거리 추종은 관절 분담을 직접 평가하지 않는다. **코드로 확인한 설계상 공백이다.** |
| 관측 idle과 실제 B gate의 불일치 | 관측은2초/.25fade, B는.35초/.15fade로 다르다. 다만 실제 B가능·관측idle0은 새env0 검지0.658초/중지0.004초/약지0.696초/소지0이다. **불일치는 사실이나 주원인이라고 단정할 수 없다.** |

직접 관측한 문제는 **한계 방향으로 편향된 정책 명령과, 긴 대기에서도 복귀하지 않는 행동**이다. B는 손가락당 최대0.0025/초의 양성 권고이고 자동 복귀 제어는 아니다. 현재의 신호로 자연스러운 복귀가 학습되지 않았다는 점은 확인했지만, 계수·품질곡선·입력·탐색·미래 보상의 기여도는 분리 비교 학습 없이 정확히 나눌 수 없다. 단순 보상 총량 비율만으로 학습 원인을 확정하지 않는다.

후속 개선의 우선순위는 대기 시간을 일괄 늘리는 것보다, **실제 대기 자격에서 B 방향 복귀가 학습되도록 신호를 설계하고, 압현 중 관절 분담 문제를 별도로 다루는 것**이다. 손가락 움직임 비용0·전체 가동범위는 유지할 수 있다. 압현에 영향을 주지 않는다는 보장은 별도 비교로 검증해야 하며 이번에는 보상을 바꾸거나 재학습하지 않았다.

## 기존 자료에서 확인한 내용

[기존1,024곡 분석](existing_analysis.md)은 실제240Hz 진단과60Hz 명령 통계를 사용한다. 저장된8환경 자세는60Hz에서 별도로 재구성했다.

- 검지 PIP 신전명령95.16%·DIP 굽힘명령100%. 목표−실제 RMS0.835°/0.823°로 관절이 명령을 대체로 따라간다.
- 안전 완주곡에서 검지의 대기 보상 gate 가중 시간은 평균9.00초지만 해당 구간 B 품질은0.139다. 소지는19.64초·품질0.112다.
- 저장한8환경 모두 검지의 PIP≤10°·DIP≥60° 진단 패턴이 전체60Hz 표본의94% 이상이며, 본인의 마지막 음 이후 약5.88초에서도100%다. 따라서 대기 시간 부족만으로 설명할 수 없다.

[목적함수 점검](objective_audit.md)에서 압현 중 관절 분담 보상0, 근거리 추종과 대기 보상의 제외 조건, 실제 B gate와 정책 관측 idle의 차이를 확인했다. 단일 보상항의 인과 기여를 분리 실험 없이 확정하지 않는다.

## 추가 진단의 범위

기존 기록은 실제 B 가능 시간의 총합은 있지만 연속 구간 길이가 없다. `support/trace_policy.py`는 같은 최종 체크포인트·1024환경·seed·035/v14로 고정 정책을 실행하고, 원래 helper의 결과를 반환하기 전에 변경하지 않고 복사한다. 실제240Hz B gate·품질·차단 원인·각도·관절/명령·추종 선택/품질·목표별 거리·candidate/wrong을 사전 지정env0..7의 첫곡에만 보관한다. PPO/단계 갱신과 자세 개입은 없다.

같은1024환경의 고정 정책 진단을 정상 완료했고 사전 지정8환경의 첫곡을 각7876개240Hz 표본으로 저장했다. [실제 연속 구간 분석](trace_analysis.md)·[수치와 적분 검사](trace_analysis.json)·[실제 gate/각도 그림](trace_angles.png)·[관찰 실행 보고서](trace_observed_report.json)를 제공한다.

env0 검지의 실제 대기 구간은35개, 중앙길이는16.7ms지만0.5초 이상3개 구간에8.600초(전체 대기 가능 시간의92.9%)가 들어 있다. 구간 개수의 중앙값만 보고 대부분의 대기가 짧다고 해석하면 안 된다. 사전 지정8환경을 시간으로 합산해도 검지92.3%·중지90.1%·약지97.6%·소지100%가0.5초 이상 구간에 속한다. 이 초 단위 값은 gate>0의 실제 표본 시간이며 위 기존 분석의fade 가중 시간과 구분한다.

초기 검지는 본인 관련 목표가 없고B gate1·본인추종0인1.75초 동안 실제 MCP/PIP/DIP가42.89/51.85/20.75°에서−29.32/0.68/55.34°로 바뀌었다. 처음부터 B를 향해 이동한 것이 아니다. 중지는 같은 초기 조건의 B품질이0.567→1.0으로 올라갔으므로 모든 손가락의 대기 동작이 같은 방식으로 실패한 것도 아니다.

**반복 실행을 원래 영상과 섞지 않는다.** 원래1024평가는 평균21.0391음·안전887·env0 26음이며 새관찰1024평가는 평균21.3662음·안전908·env0 30음이다. 같은정책·입력 계약이지만 반복궤적은 달랐다. 새env0의 원본 대비 실제q RMS차이는약0.395°이며 같은 프레임 몸체 위치의 최대차이도약2.59cm다. 관찰 복사에 따른 수치적 실행 순서 영향과GPU실행의 비결정성을 분리 검증한 것은 아니다. 새기록은 원래 영상의 비트 단위 재생이 아니라 같은조건의 추가 진단이다. 두 기록 모두 검지 편중과 마지막 긴 대기에서 미복귀가 나타난다.

## 도구

- `support/analyze_existing.py`: 기존 평가 집계와8환경 자세 진단.
- `support/trace_policy.py`: 현재 helper에 대한 프로세스 내 관찰 wrapper, 원래 함수 결과와 제어 결정을 유지.
- `support/analyze_trace.py`: 추가240Hz 기록의 연속 대기·패턴·추종/B 동시성 및 원래 진단 적분 대조.
- `support/test_*.py`: 관찰 복사·경계·기존 집계·독립 회전 재구성·분석 수학 검증.

새 GPU 평가는 물리 실행의 수치적 차이가 생길 수 있어 기존 영상의 비트 단위 재현으로 가정하지 않는다. 원래8환경 캡처와 수치 차이를 함께 보고한다. 이 진단에서 말하는 각도/접촉 후보는 해부학적 정상범위·현 압력·음향 인증이 아니다.
